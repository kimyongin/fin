# 활동·할 일·회고

## 제목·요약·본문 작성

신규 할 일과 기록은 제목, 요약, 상세 Markdown 본문을 모두 채운다. 제목은 최대 100자, 요약은 최대 300자, 본문은 최대 25,000자다. 글자 수는 UTF-8 bytes나 토큰 수가 아닌 Unicode 코드 포인트 기준이다. 한글 한 음절은 1자이며 결합 이모지는 여러 자일 수 있다. 공백·null은 필수값을 대신하지 않는다. `save_general_task`는 본문을 `trigger_text`, 기록은 `body`로 받는다. 제목·요약은 별도 파라미터로 보내고 본문에 frontmatter를 중복하지 않는다. 선택 태그·종목·일정은 현재 schema의 생략/해제 계약을 따른다.

목록은 제목·요약·기존 메타데이터만 보여 준다. 의미 검색은 **제목과 요약만** 합쳐 분할 없이 한 번 임베딩한다. 본문 키워드 검색은 유지되지만 본문에만 있는 개념이 의미 검색으로 회수된다고 가정하지 않는다. 요약이 없는 기존 자료는 제목만 의미 검색하며 임의로 자동 요약하지 않는다. 긴 기존 상단이 입력 한도를 넘으면 키워드 검색은 유지되고 의미 색인에서 제외된다. 기존 초과 필드 그대로의 편집은 허용하지만 바꾼 필드는 새 상한에 맞춘다.

제목에는 핵심 대상과 문제·행동·결과를 드러낸다. 할 일은 대상과 할 작업, 기록은 대상/주제와 확인한 결과나 판단을 기본으로 한다. `오늘 조사`, `점검 완료`, `중요한 내용` 같은 제목은 대상을 구별할 수 있게 고친다. 실제 자료와 사용자의 표현에 근거한 이름을 쓰며 무관한 키워드를 늘리지 않는다.

요약은 보통 1~3문장으로, 대화 없이 읽어도 이해되게 쓴다. 할 일에는 목적·대상·기대 결과, 기록에는 핵심 결과·이유·중요한 한계를 담는다. 이론의 적용 조건, 뉴스의 사건·중요성, 결정의 선택·이유·재검토 조건 중 실제 자료에 있는 내용을 우선한다. 무관한 조건이나 수치를 만들지 않는다. `그것`, `위 내용`, `지난번과 같다`를 단독 설명으로 쓰지 않는다. 핵심 개념·대상·중요 조건을 자연스럽게 표현하고 자세한 절차·표·URL·긴 인용은 본문에 둔다.

부정·조건·불확실성·판단 주체를 보존한다. `매수를 검토했으나 보류`를 `매수 결정`으로 줄이거나 AI 제안을 사용자 채택으로 바꾸지 않는다. 검색 점수로 찬반이나 결정 상태를 판정하지 않는다.

| 구분 | 부족한 작성 | 권장 합성 예시 |
| --- | --- | --- |
| 할 일 제목 | 다음 점검 | 대출 만기 전 현금 확보와 장기채 보유 점검 |
| 할 일 요약 | 상황을 보고 판단한다 | 대출 만기까지 필요한 현금과 장기채 보유 비중을 확인한다. 상환 재원 부족 여부를 계산하고 매도 필요성과 판단 근거를 기록한다. |
| 기록 제목 | 장기채 검토 완료 | 대출 조건 미확정으로 장기채 추가 매수 보류 |
| 기록 요약 | 나중에 재확인 | 장기채 추가 매수를 보류했다. 대출 조건이 확정되지 않아 상환에 필요한 현금을 판단하기 어렵기 때문이다. 조건 확정 후 현금 여력과 추가 매수 여부를 다시 검토한다. |

이 예시는 실제 사용자 판단이 아니다. 자료에 없는 만기·현금 부족·매수 의사를 예시에서 복사하지 않는다.

저장 전에 제목·요약만 읽고 대상·주제·목적 또는 결과를 식별할 수 있는지 확인한다. 본문과 비교해 중요한 부정·조건·미확인 범위가 빠지지 않았는지, 사용자가 나중에 할 자연스러운 질문 1~2개의 의미가 담겼는지 검토한다. 질문은 별도 필드로 저장하거나 매 저장마다 임베딩 호출하지 않는다. 본문 수정으로 요약이 부정확해지면 같은 저장에서 요약도 고친다. 스타일만 바뀐 본문에는 요약 재작성을 강제하지 않는다.

사용자의 저장 요청이나 보여준 초안 동의 범위 안에서 한 번 저장하고 상세를 재조회해 제목·요약·본문·태그·참조를 확인한다. 검수 때문에 매번 추가 승인을 요구하지 않는다. 저장 성공과 색인 대기/실패를 구별하고, 재조회 실패 때문에 성공한 완료나 금융 쓰기를 반복하지 않는다.

완료에는 `transition_general_task`의 `result_title`, `result_summary`, `result`(본문)을 실제 수행 결과로 모두 채운다. 할 일의 목적 요약을 완료 결과로 복사하지 않는다. 결과 누락 시 완료 상태와 기록이 모두 저장되지 않는다. reopen/cancel에는 수행 결과를 강제하지 않으며 이유는 해당 계약을 따른다.

## 미래 행동과 수행 기록

할 일은 미래 의도이고 활동은 수행·관찰·판단의 내용이다. AI 검토안인지 사용자 결정인지 본문으로 구분하며 별도 내부 종류나 상태를 만들지 않는다. 현재 활동을 수정/삭제해도 원래 자산 변경이나 할 일 완료가 되돌아가지 않는다.

미래 행동을 기억해 달라는 요청에는 `list_general_tasks`와 `get_general_task`로 중복/현재값을 확인한 뒤 `save_general_task`를 쓴다. 반복은 요청된 경우에만 none/daily/weekly와 시간대·현지 시각을 정한다. 주간 요일은 도구 schema를 따른다. 수정에서 tag_ids 생략은 보존, 빈 배열은 해제이므로 구분한다.

“할 일 확인하고 진행해”에는 `list_due_general_tasks`의 next_offset이 끝날 때까지 읽고 해당 할 일을 확인한다. 도래 목록 조회 자체가 작업 실행·금융 변경 승인은 아니다. 실제 작업이 성공하면 반환된 회차·버전으로 `transition_general_task`의 complete를 호출해 결과를 기록한다. 실패·증거 부족·승인 대기이면 완료 처리하지 않는다. 완료가 만든 연결 활동을 수동으로 다시 저장하지 않는다.

reopen은 잘못된 완료를 바로잡고 cancel은 미래 반복을 끝낸다. 전체 할 일 삭제는 `delete_general_task`로 현재 버전을 확인해 수행하며 과거 기록은 남고 연결이 해제된다. 반복을 끝내려는 요청과 과거 수행을 지우려는 요청을 혼동하지 않는다.

## 활동 편집과 태그

사용자가 기록하려는 수행/판단에 일치하는 완료 대상 할 일이 없으면 `record_manual_activity`로 저장하고 `get_activity`로 읽는다. 미래 약속을 완료된 활동으로 저장하지 않는다. task_id나 시장 instrument_ticker는 탐색용 참조이며 할 일 완료나 금융 실행의 증거가 아니다. 미등록 시장 티커도 지원하며 현금·평가형 자산 맥락은 본문/태그로 표현한다.

정정에는 현재 `get_activity` 본문·버전을 읽고 `update_activity`로 승인된 필드만 바꾼다. 자동 활동도 본문을 정정할 수 있지만 원래 자산/할 일 값을 바꾸지 않는다. 필드와 지정 태그는 함께 저장하며 tag_ids 생략과 빈 배열을 구분한다. 삭제는 요청한 대상을 읽은 뒤 `delete_activity`를 쓴다.

태그를 지정할 때는 `list_activity_tags`로 실제 ID를 확인하고 기존 이름을 재사용한다. 태그만 바꾸는 요청에는 `set_activity_tags` 또는 `set_general_task_tags`를 사용할 수 있다. 활동 태그는 검색에 사용하며 공유 범위·목표 배분을 바꾸지 않는다. 검색의 실제 방식·페이지·필터 의미는 `search_activities` 설명을 따른다. 검색 누락을 기록 부재로 단정하지 않는다.

금융·원칙·할 일 변경이 만든 자동 기록과 같은 사실을 수동 기록으로 중복하지 않는다. 독립적인 추가 판단 이유를 보완하려면 해당 대상과 승인 범위를 명확히 한다. 기록 저장 동의는 별도 원칙/목표 변경 권한이 아니다.

## 기간 회고

일·주·월 회고에는 시작/끝 날짜와 시간대를 정하고 `get_activity_report_context`의 next_cursor가 끝날 때까지 원본을 읽는다. 이전 회고도 결과에 섞일 수 있으므로 요약을 또 하나의 실제 사건으로 세지 않는다. 주간 회고를 저장된 일일 요약만으로 구성하지 않는다.

실제 변경·체결·완료와 그 이유를 구분한다. 이유는 당시 기록에 있을 때만 설명한다. current_open_tasks는 요청 시점의 현재 할 일이며 과거 기간 말일의 상태가 아니다. 일부 페이지 실패 시 전체를 읽은 완성본이라고 보고하지 않는다.

같은 기간의 기존 회고를 검색해 읽고 자동 덮어쓰지 않는다. 요청이나 보여준 초안 동의 후 기간·출처·확인한 사실·해석·불확실성을 일반 활동 하나로 저장한다. 새 회고 테이블이나 자동 생성 일정을 만들지 않는다. Portfolio 자체가 예약 시각에 LLM 보고서를 만든다고 설명하지 않는다.
