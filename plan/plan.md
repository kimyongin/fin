# UI PRD §1 UX 원칙 강화 + §7·§8 톤 일관화

## Context

`PRD_PORTFOLIO_UI.md`의 §1 "UX 설계 원칙"은 11개의 짧은 bullet로 페이지 전략·layout·시각·반응형·안전 원칙이 한 리스트에 섞여 있다. 신규 기능을 추가할 때 이 원칙을 PR 리뷰의 체크리스트처럼 쓰려면 다음이 부족하다:

- **Why가 없다** — 규칙은 있지만 "왜 이렇게 정했는가"가 빠져 있어, 엣지 케이스에서 규칙을 굽힐지 지킬지 판단 근거가 약하다.
- **위반 예가 없다** — "안 하기로 한 것"이 명시되지 않아 동일 의도의 다른 패턴(예: 4-메트릭 그리드, 모달, 카드 내 수정 버튼)이 다시 들어올 위험이 있다.
- **결이 다른 원칙이 같은 단위로 나열** — "한 페이지 = 한 가지 일"(전략)과 "그림자는 모바일 drawer 슬라이드에만"(시각 디테일)이 같은 무게로 섞임.

목표: §1을 **6–8개 핵심 원칙**으로 압축하고, 각 원칙마다 `규칙 한 줄 → Why → Do · Don't 예시 한 쌍`으로 구성한다. 예시는 mock(`index-v2.html`)의 실제 구현을 인용해 추상적 원칙이 아닌 운영 가능한 가이드로 만든다. §7(Drawer Form 동작), §8(시각 토큰)도 §1과 일관된 "규칙 + Why + Do/Don't" 톤으로 정렬한다.

비목표: 새 원칙을 만들지 않는다. 현재 mock·PRD에 이미 녹아 있는 의사결정을 명문화할 뿐이다.

## §1 재구성 — 8개 핵심 원칙

각 원칙: `### N. 규칙 한 줄` 헤더 + `**Why:**` 1–2문장 + `**Do:**` mock 인용 + `**Don't:**` 흔히 빠질 수 있는 안티패턴.

### 1. 한 페이지 = 한 가지 질문에만 답한다
- **Why:** 한 화면이 여러 의도(`보기`/`편집`/`설정`/`분석`)를 동시에 떠안으면 navigation·hero·탭 구조가 흔들리고 사용자는 "지금 어디서 무엇을 해야 하는지" 추적해야 한다.
- **Do:** 자산 = "내 자산이 지금 얼마이고 무엇이 움직이나", 분석 = "오늘 시장 해석과 결정", 자료 = "데이터가 깨끗한가".
- **Don't:** 자산 페이지에 가격 동기화 버튼·계좌 관리 overlay·종목 마스터 편집을 한꺼번에 끼워 넣기. 이는 자료 페이지의 책임이다.

### 2. Hero strip은 단일 1차 메트릭 + 한 줄 보조
- **Why:** 4–6개 메트릭 카드 그리드는 "이 중 무엇이 1차인지" 판단을 사용자에게 미루게 한다. 페이지마다 답해야 할 핵심 숫자 1개를 골라 시선의 출발점을 고정한다.
- **Do:** 자산 hero `₩54,344,000 · +₩2,544,000 +4.9%` / 분석 hero `2026-05-07 · 회복 국면 · 뉴스 28건` / 자료 hero `17 / 18 동기화 완료`.
- **Don't:** hero에 KPI 4–6개를 카드 그리드로 펼치기. hero에 액션 버튼(거래 추가, 동기화)을 두기 — 액션은 각 탭의 FAB로.

### 3. 상단 전체폭 탭, 한 탭 = 한 master 리스트
- **Why:** 페이지 안에서 큰 모드 전환은 좌측 nav가 아닌 hero 아래 segmented control로 표현한다. 동일 페이지에서 객체군이 다르면 탭으로 분리한다(보유 종목/계좌/거래는 다른 master 객체).
- **Do:** 자산 `계좌 / 종목 / 거래`, 분석 `리포트 / 리밸런싱`, 자료 `환율 / 종목 / 태그`. 모든 탭이 동일한 hero를 공유한다.
- **Don't:** 한 탭 안에 두 개 master 리스트를 좌우로 나열(워크벤치형 3-패널), 탭 폭 가변(컨텐츠에 맞춰 내용 좁아지기), 탭 안에서 또 sub-tab 한 단계 더 파기.

### 4. 마스터 카드는 표시 전용, 편집은 drawer form
- **Why:** 카드 안에 `수정`/`삭제` 버튼을 두면 의도치 않은 활성화·다중 모달 stack·모바일 터치 면적 충돌이 생긴다. 단일 진입점(카드 클릭 → drawer)이 카드 그리드를 깨끗하게 유지하고 키보드 탐색을 단순화한다.
- **Do:** 카드는 `tabindex="0"` + `data-drawer="..."`만. drawer form은 `view / edit / create` 모드로 같은 form을 재사용. 저장·삭제·다운로드는 drawer 우하단 sticky footer.
- **Don't:** 카드 row2 끝에 `수정` ghost 버튼 / 모달 중앙 dialog를 다시 띄우기 / 같은 모델에 view·edit 화면을 따로 그리기.

### 5. 생성은 FAB + draft 카드 패턴
- **Why:** "추가" 액션을 hero·카드 내부·툴바·모달이 각자 들고 있으면 사용자가 어디를 눌러야 할지 학습 비용이 든다. 우하단 floating action button → 빈 draft 카드 + create-mode drawer 한 흐름으로 통일한다.
- **Do:** 자산 거래 탭 `+` FAB → 빈 `trade-new-draft` 카드가 리스트 최상단 삽입 + drawer 자동 오픈. 자료 환율 탭은 secondary `↻` FAB(동기화) + primary `+` FAB(누락 보완) 두 단계로 분리.
- **Don't:** hero에 `+ 거래 추가` 버튼 / 카드 그리드 마지막에 점선 `+` 슬롯(데이터가 늘면 멀어진다) / 모달로 `거래 추가` 폼 띄우기.

### 6. 로그성 데이터(거래·가격)는 최근 N + 그룹 + 필터 + 더 보기
- **Why:** 거래·가격 기록은 운영 시간에 비례해 무한 증가한다. "전체 카드 나열"은 메모리·스크롤·지각 비용을 모두 폭증시킨다. 명시적 페이지네이션과 그룹 헤더·필터로 사용자가 탐색 범위를 통제하게 한다.
- **Do:** 거래 탭 `최근 30건 · 최신순` + 월별 group head + `이전 거래 더 보기` 버튼. 보유 종목 drawer 거래 기록은 5건만 + `전체 거래 보기` CTA. 가격 기록은 종목별 `price-history-{slug}` drawer로 분리하고 기간·source·오류만 pill 필터.
- **Don't:** 한 화면에 거래 전체 무한 스크롤 / 종목 drawer 안에 그 종목의 모든 과거 거래를 다 풀어 놓기 / 자동 로드 무한 스크롤(사용자 의도 없는 fetch).

### 7. 형제 항목 탐색은 drawer가 책임진다
- **Why:** 우측 detail 패널은 항상 한 항목만 보여준다. 사용자가 "다음 종목, 다음 리포트"를 보려고 매번 마스터 카드로 돌아가게 하면 흐름이 끊긴다. drawer 헤더에 prev/next + `1/N`을 두고 키/스와이프로 형제 이동을 흡수한다.
- **Do:** 보유 종목·리포트·리밸런싱·종목 마스터·계좌·거래 모두 `drawerSiblings`에 정렬 규칙 등록. 데스크탑 ←/→, 모바일 가로 스와이프 60px+, 120ms 페이드 후 교체.
- **Don't:** drawer 안에 "다음 항목 검색" 셀렉트 / 카드를 닫고 다음 카드를 다시 눌러야 이동 / 형제 정의 없이 임의 순서로 이동.

### 8. 시각 절제 + 상태·위험 표면화
- **Why:** 다크 팔레트는 색상 1개만 강조해도 시선이 거기에 묶인다. 액센트(주황)를 여러 곳에 쓰면 진짜 1차 CTA가 묻힌다. 동시에 로딩·실패·확인 같은 시스템 상태를 별도 화면으로 빼면 사용자가 흐름을 잃는다.
- **Do:** 액센트는 `primary CTA` + 첫 번째 차트 segment에만. 채색 배지는 `success/warning/danger/neutral` 4종 + outline 칩. 로딩/빈/오류/저장/동기화 결과는 해당 섹션 안에서 inline 표시. 삭제·매도 초과·결정 변경은 drawer-local inline 확인 행으로 처리.
- **Don't:** 카드 hover에 액센트 배경 / 임의 hex로 `info-2`, `success-strong` 변형 배지 추가 / 토스트나 풀스크린 모달로 저장 결과·삭제 확인을 띄우기 / 가로 스크롤로 추가 정보를 숨기기.

> 8개 원칙은 PR 리뷰 체크리스트로 사용한다. 신규 기능은 각 원칙별 Do 패턴 중 하나에 매핑되어야 하고, Don't 패턴이 등장하면 설계를 재검토한다.

## §7 Drawer Form 동작 — 톤 일관화

§7은 detail 명세이므로 §1과 같은 Do/Don't 형식 대신, **§1 원칙 4·5·6·7로의 역참조 + footer 모드 표 + 형제 탐색 표**로 정돈한다. 변경 포인트:

- 첫 줄에 "§1 원칙 4(마스터 카드 표시 전용), 5(FAB+draft), 7(형제 탐색)의 구현 명세"라는 lead-in 한 줄.
- 기존 산문 6개 bullet → **2개 표 + 4개 짧은 규칙 bullet**로 재구성:
  - **표 1**: drawer 위치 (데스크탑 ≥901px / 모바일 ≤900px) — 표시 위치, 닫기, 진입 트리거.
  - **표 2**: footer 버튼 모드 (`view` / `edit` / `create` / `delete-confirm`) — 이미 추가된 내용을 표 형식으로.
  - 4개 규칙: 카드 내부 액션 금지, draft 진입 흐름, `data-readonly="true"` 동작, 형제 탐색 키 매핑.
- 마지막에 **형제 탐색 정렬 규칙 표** (객체별 정렬 기준).

## §8 시각 토큰 — 톤 일관화

§8도 토큰 나열에 그치지 않고 **사용 규칙 + Do/Don't**를 짧게 첨부한다.

- 기존 토큰 표는 유지.
- 토큰 표 아래 `### 사용 규칙` 소제목 신설 + 4개 짧은 bullet:
  - **액센트(`--accent`)** — Do: primary CTA(거래 추가 FAB, 첫 번째 차트 segment). Don't: 카드 hover 배경, focus ring, 보조 배지.
  - **채색 배지** — Do: `success/warning/danger/neutral` 4종 + outline 칩. Don't: 임의 hex 추가, 같은 의미의 다른 단계(`success-strong`, `info-2`).
  - **그림자** — Do: 모바일 drawer 슬라이드, FAB. Don't: 카드 그림자, 호버 lift, 데스크탑 drawer.
  - **차트 segment 6단** — Do: `accent → info → success → purple → warning → slate` 고정 순서. Don't: 종목 수에 따라 색 추가, 사용자 태그 색을 차트에 사용.
