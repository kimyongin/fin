# Portfolio 화면 재설계 v1~v3 — 과거 검토 자료

> 2026-09-20: 현재 설계는 [제품 재정리](./product-reorganization.md)와 [디자인 원칙](./PRINCIPLES.md)을 따른다. 아래 내용과 클릭 시안은 검토 이력이며 구현 명세가 아니다. v3 자산 전면 재설계와 밝은 테마는 채택하지 않는다. 다음 시안은 기존 React 자산 흐름과 테마를 기반으로 새 책임을 통합한다.

## 개정 v3 — 모바일 우선 반응형

당시 공통 설계 기준에 따라 만든 세 번째 클릭 시안은 [prototype-v3.html](./prototype-v3.html)이다. 현재 승인된 구현안은 아니다.
v1/v2는 비교용으로 유지한다. v3는 오늘의 결론을 먼저, 자산 배분은 접을 수 있는 카테고리 카드로 제공한다.
계좌별·종목별 조회, 필터, 표 편집은 유지한다. 일반 조회의 모바일 표는 카드로 전환하고, 편집 모드만 가로 스크롤을 허용한다.
상세 내 이전 화면으로 돌아가기와 닫기, 목록의 필터/위치 유지, 기록의 시점과 상태 구분을 검토한다.
시안에서는 대표 흐름만 가상 데이터로 제공한다. 운영 앱 변경이나 DB 쓰기는 없다.

### v3 검증 기록 (2026-09-20)

- Playwright Chromium: 360 / 390 / 768 / 1024 / 1440px의 5개 주 화면에서 가로 넘침 및 JS 오류 없음.
- 같은 너비에서 카테고리·보유·브리핑·판단·질문·실행·원칙 편집 등의 대표 상세 10종에서 가로 넘침 없음.
- 모바일 계좌 필터 → 카테고리 펼침 → 보유 상세 → 판단 → 이전 상세 → Escape 닫기 후 필터 유지 확인.
- 모바일 표 편집으로 수량 변경 후 가상 보유 데이터 갱신 확인. 계좌별/종목별 펼친 목록, 분석 상태 4종, 평가액 0에서 NaN/Infinity가 없는지 확인.
- 390px 모바일 오늘/자산 및 1440px PC 오늘 화면의 스크린샷 검토.
- 아직 실기기 Safari/Android, 스크린리더, 모든 색 대비, 매우 긴 사용자 데이터는 검증하지 않았다. 운영 UI 적용 시 공통 체크리스트로 별도 검증한다.
- 모든 동작은 메모리 안의 가상 데이터다. 카테고리·태그 편집/대량 붙여넣기/실제 잔고 등록은 안내 단계이며, 체결 예시는 기본 보유값에서만 시험한다.

## 改訂 v2 — 기존 자산 배분 중심 구조 보존
prototype-v2.html은 자산 배분 구조를 복원한 이전 시안이다. prototype.html은 비교용 첫 시안으로 남긴다.
- 기존 카테고리 / 계좌별 / 종목별 / 표 편집을 자산 하위 화면에 보존한다.
- 자산 상단에 전체 계좌 통합 평가액과 카테고리별 현재·목표·차이를 표시한다. 필터는 아래 보유 목록만 바꾸며 분모를 몰래 변경하지 않는다.
- 동일 종목의 복수 계좌 보유, 카테고리/계좌 복합 필터, 표 수량·평균가 편집 후 가상 평가액 갱신을 시험할 수 있다.
- 오늘에도 자산 배분 요약을 연결한다. 원칙은 목표를 관리하고 자산은 현재값과의 비교를 제공한다.
- 시안은 배분 카테고리와 종목이 단일 연결된 예시다. 실제 다중 태그 중복 합산 규칙은 별도 검증하고 기존 기능을 보존한다.
- 카테고리·태그 관리의 생성/변경, 목표 편집, 스프레드시트 대량 붙여넣기는 기존 기능 보존 대상으로 명시하며 이번 시안에서 완전 구현하지 않는다.
- 가상 데이터: 3계좌, 4종 자산, 총 600만원. 원칙·판단·실행 패널은 기존 대표 흐름과 연결한다. 실제 데이터 변경 없음.

## 목표
출근길 약 1분 안에 중요한 변화와 오늘 확인할 일을 파악한다. ChatGPT에서 요청해 조사·저장하고, 앱에서 결과를 읽고 판단·할 일·잔고를 관리한다. 자동 분석은 현재 범위 밖이다.

## 탐색 구조
주 메뉴는 오늘 / 자산 / 판단·할 일 / 투자 원칙이다. 데스크톱은 좌측 내비게이션, 모바일은 하단 4개 메뉴를 사용한다. 판단과 할 일은 한 화면의 탭으로 전환하고, 자료·설정·활동 기록·사용 안내는 보조 메뉴에 둔다.

| 화면 | 첫 화면의 질문 | 주요 내용과 동작 |
| --- | --- | --- |
| 오늘 | 마지막 점검 이후 무엇이 바뀌었나? | 분석 날짜, 한 줄 결론, 중요 변화 최대 3개, 판단할 항목, 열린 질문, 새 점검 문구 복사 |
| 자산 | 무엇을 왜 보유하고 있나? | 종목별 수량/평균가, 계좌별 내역, 실제 잔고 확인 범위, 보유 이유, 관련 판단과 할 일 |
| 판단·할 일 | 왜 결정했고 무엇을 확인하거나 실행할 차례인가? | 판단/할 일 탭, 제안·채택·대체됨, 조사·실행 상태, 관련 판단·과제·근거 연결 |
| 투자 원칙 | 어떤 기준으로 투자하나? | 목적/성향, 운용 계획과 상세 원칙 편집, 버전 이력; 현재 비중 계산은 자산의 목표 비교에서 제공 |

뉴스는 오늘의 변화와 판단의 근거에서 조회하고, 전체 저장 자료는 판단 화면의 자료 진입점으로 제공한다. 활동 기록은 사용자 판단 기록과 구분한다. 기존 뉴스/전략/활동 데이터와 URL은 구현 시 보존하거나 새 위치로 안내한다.

## 상세 화면과 연결
데스크톱은 우측 상세 패널, 모바일은 전체 높이 상세 패널을 사용한다. 닫기/뒤로 가기로 목록 필터와 위치를 보존한다. 원칙 → 판단 → 할 일 → 체결 및 보유 이유의 연결은 ID로 제공한다. 시안은 대표 연결만 가상 데이터로 보여준다.

## 상태와 책임
- 분석 없음: 초기 잔고 등록과 점검 시작 안내. 최근 분석: 날짜를 그대로 표시. 부분 조사: 미확인 범위 공개. 변화 없음: 조사 범위 안에서 추가 행동 없음으로 표시.
- 분석 작성, 사용자 열람, 실제 잔고 확인, 가격 갱신 시각은 독립적으로 표시한다. ChatGPT 열람은 미상이 가능하다.
- 의견 채택은 사용자 판단만 변경한다. 계획을 취소하거나 완료 처리하는 것만으로 잔고를 변경하지 않는다.
- 실행할 일은 체결 연결로 진행도를 계산한다. 원장 입력·취소·보정은 #37/#38의 미리보기 계약을 사용한다.
- 기준 입력은 선택 사항. 빈 데이터가 있으면 개인화 한계를 밝히고 첫 점검을 막지 않는다.
- ChatGPT 시작 문구는 “오늘 내 포트폴리오 점검하고 저장해줘”. 복사 후 사용자가 연결된 ChatGPT에서 보낸다. 검증되지 않은 자동 전송 링크를 만들지 않는다.

## 시안 범위
prototype.html은 네트워크/DB 연결 없는 클릭 가능한 과거 가상 시안이다. 실제 종목/뉴스/원칙이 아니며 페이지를 새로고침하면 초기화된다. 현재 React 구현의 4개 주 메뉴와 책임 분리가 우선하며, 시안은 오늘 상태와 상세 연결을 검토한 이력으로만 사용한다.

## 화면별 구현 연결
- #36: 탐색 구조, 오늘과 상세 패널, 상태 표시. 원칙 편집 기능은 #43, 체결/보정은 #37/#38을 연결한다.
- #34/#35/#44: 원칙/판단/질문/실행/체결 관계와 상태를 화면에 제공한다.
- #41/#42: 종목별 보유 이유와 실제 잔고 확인을 자산 상세에서 제공한다.
- #39: 390px 모바일에서 주요 내용을 읽을 수 있는지, 키보드 포커스/상세 닫기/페이지 넘침/상태 오해 여부를 검증한다.

## 시각 방향
밝은 종이색 배경, 짙은 녹색 강조, 큰 요약 문장과 여백을 사용한다. 정보 밀도는 자산 표에 집중하고 오늘 화면은 짧게 유지한다. 이 색상은 제안이며 기존 어두운 테마를 폐기하는 결정은 아니다. 색상 외에 텍스트 상태도 함께 제공한다.
