기본 본문은 16px 수준, 보조 정보는 12px 이상, 조작 영역은 최소 44px이다. 핵심 CTA는 주황색 하나, 보기 선택은 선택 상태 표현, 일반 조회/새로고침은 보조 스타일로 구분한다. 삭제는 위험 스타일과 영향 설명을 사용한다.

기존 앱 외곽 폭 max-w-6xl과 좌우 padding 16px/24px을 유지한다. 네 개의 주 탐색은 모든 화면 폭에서 하단 고정 위치를 유지하고 본문은 그 높이와 safe-area만큼 여백을 둔다. 상세 drawer는 1024px 이상에서 적용해 중간 폭은 전체 높이 상세로 유지한다. 정확한 drawer 폭은 기본 40rem/max-width 100%로 시작하고 긴 내용으로 검증한다.

## 모달·드로어·전체 화면 편집

최신 공통 동작은 [#123](../tickets/ui-16-modal-inline-edit.md)이다. 편집 가능한 현재 대상은 상세에서 직접 입력하고 한 번 저장한다. 아래 읽기/편집 왕복 표현 중 충돌 부분은 모달 가이드의 직접 편집 규칙으로 대체한다. 과거 이력/권한 없는 대상은 읽기 전용이며 전수 적용은 아직 구현 전이다.

현재 공통 기준은 [모달 디자인 가이드](./modal-guidelines.md)다. 입력·라벨·버튼·간격은 계좌/보유 추가 폼에 맞추고 용도별 모달/드로어 예외는 가이드에 따른다. 기존 전체 화면의 적용 완료 여부는 #117에서 점검한다.

- 공통 surface는 제목/닫기 및 상세 뒤로가기, 스크롤 본문, 선택적 footer를 별도 영역으로 가진다. header/footer는 본문 스크롤 밖에 남는다. 긴 제목은 줄바꿈하고 닫기 버튼을 밀어내지 않는다.
- 브리핑/판단/할 일처럼 긴 조회 상세는 PC 오른쪽 modal drawer, 모바일 전체 높이. 짧은 편집은 PC 중앙 modal, 모바일 전체 높이를 기본으로 한다. 동일 shell의 variant를 재사용하고 서로 다른 focus trap 구현을 만들지 않는다.
- 100dvh 및 safe-area를 고려한다. footer는 마지막 입력/오류를 가리지 않으며 가상 키보드에서도 입력과 저장에 도달할 수 있어야 한다. 모든 화면 폭의 하단 탐색은 overlay 아래에서 inert 처리한다.
- 저장 버튼은 오른쪽, 취소는 그 앞. 모바일은 두 버튼을 같은 행에 충분한 폭으로 제공한다. 위험 행동은 저장과 떨어진 별도 영역. 닫기와 취소의 문구는 읽기/편집 의도에 맞춘다.
- dirty 상태에서 닫기/X/Escape/배경 클릭/뒤로가기로 나갈 때 현재 surface 안에서 계속 편집/변경 버리기 선택을 제공한다. 기본 배경 클릭은 닫지 않는다. 최상위 surface만 키보드 닫기를 처리한다.
- 저장 중에는 닫기와 중복 저장을 막고 진행 상태를 알린다. 실패는 draft를 보존한다. 서버 저장 성공 후 재조회 실패는 저장 실패와 구분하며 재저장하지 않고 새로고침을 재시도한다. 기존 금융 멱등성 계약을 보존한다.
- 뒤로가기는 연결 상세의 이전 항목을 먼저 복원하고, 목록으로 돌아갈 때 필터·선택·스크롤을 복원한다. resize 때 draft/선택을 재생성하지 않는다. 새 router는 선행조건이 아니다.
- 표 전체 화면은 제목·종료, 필터·표 본문, 개수·오류·롤백·저장을 같은 surface에 포함한다. 전체 화면 종료는 inline 편집으로 돌아가는 것으로 draft를 유지한다. dirty 경고는 편집 자체를 떠날 때만 적용한다.
- 레이어 순서는 일반 본문 < 탐색 < 전체 화면/모달/드로어. 포털 또는 검증된 배치로 부모 stacking context 충돌을 방지하고 본문과 overlay의 이중 스크롤을 방지한다.

## 구현 경계와 검증

기존 AppHeader/ModalShell/ModalActions부터 확장한다. PageLayout, ViewTabs, FilterBar, Section, 상태 표현은 구체적인 두 소비자에서 필요한 props만 추출한다. 데이터 fetching/금융 계산/권한 판단은 UI primitive에 넣지 않는다. 새 UI 라이브러리·범용 폼 엔진은 필수 범위가 아니다.

각 티켓은 360/390/768/1024/1440px, 소유자/공유, 긴 이름/빈값/필터 없음/오류, 키보드와 모달 복귀를 기록한다. 자동 viewport 검증과 실제 모바일 키보드 검증은 구분한다. 안전한 fixture/격리 환경을 사용하며 로컬 URL이라는 이유로 운영 데이터에 테스트 기록을 저장하지 않는다.

이번 범위는 표현/상호작용 개선이다. API·DB·MCP·공유 권한·원가 계산은 변경하지 않는다. 새 쓰기 기능이나 자동 분석을 추가하지 않는다. 구현 완료 보고에는 화면별 적용 여부와 미검증 항목을 남긴다.
