# 화면 구조 규칙

2026-09-21 · 합의된 구현 기준 / 로컬 적용 완료. 자동 viewport 검증 결과와 남은 실기기 항목은 아래 구현 현황을 따른다. 제품 책임은 PRD와 product-reorganization.md, 공통 디자인 원칙은 PRINCIPLES.md가 원본이다.

## 페이지 공통 구조

| 영역 | 계약 |
| --- | --- |
| 앱 헤더 | 페이지 h1, 포트폴리오 문맥, 보조 메뉴. 페이지가 동일 제목을 반복하지 않는다. 공유 읽기 문맥을 유지한다. |
| 페이지 시작 | 헤더 아래 간격 24px을 공통 레이아웃에서 소유한다. feature root의 추가 mt-8을 제거한다. 기본 섹션 간격 20px, 목록 간격 12px. |
| 페이지 도구 | 보기 전환, 필요한 대표 행동, 필터·검색 순서. 데스크톱은 보기 전환과 행동을 같은 행에 둘 수 있고 모바일은 자연스럽게 줄바꿈한다. |
| 보기 전환 | 자산 4개 보기와 판단/할 일은 같은 segmented 스타일. 활성 표시와 키보드 탐색을 제공한다. 탭 ARIA를 쓰면 연결 panel·방향키·Home/End까지 구현한다. |
| 필터 | 목록 범위를 좁히는 칩/select/search. 보기 탭과 시각적으로 구분하고 레이블·선택 상태·빈 결과·조건 해제를 제공한다. 필터는 현재 목록에만 영향을 준다. |
| 본문 | 섹션 제목·요약·목록/표. 공통 Section은 선택적으로 사용하며 모든 콘텐츠를 카드로 감싸지 않는다. 카드 padding은 모바일 16px/PC 24px, 기본 카드 radius 16px. |
| 상태 | 최초 loading, 빈 데이터, 필터 결과 없음, 오류, 추가 로딩을 구분한다. 재조회 실패 시 남은 데이터가 최신인 것처럼 보이지 않게 한다. 오류는 해당 영역 가까이에 dark theme 톤으로 표시한다. |
| 하단 | 목록의 더 보기와 개수는 결과 아래. 조회 페이지에는 빈 푸터가 없다. 편집 액션은 편집 영역 하단에 유지한다. |

기본 본문은 16px 수준, 보조 정보는 12px 이상, 조작 영역은 최소 44px이다. 핵심 CTA는 주황색 하나, 보기 선택은 선택 상태 표현, 일반 조회/새로고침은 보조 스타일로 구분한다. 삭제는 위험 스타일과 영향 설명을 사용한다.

기존 앱 외곽 폭 max-w-6xl과 좌우 padding 16px/24px을 유지한다. 네 개의 주 탐색은 모든 화면 폭에서 하단 고정 위치를 유지하고 본문은 그 높이와 safe-area만큼 여백을 둔다. 상세 drawer는 1024px 이상에서 적용해 중간 폭은 전체 높이 상세로 유지한다. 정확한 drawer 폭은 기본 40rem/max-width 100%로 시작하고 긴 내용으로 검증한다.

## 화면별 적용

| 화면 | 상단과 본문 구성 | 유지할 특성 |
| --- | --- | --- |
| 오늘 | 마지막 분석 날짜·상태·결론 → 변화/연결 과제 → 확인 상태·이력. 새 점검 문구 복사는 눈에 띄는 한 곳 | 실시간 분석처럼 표시하지 않음. 불필요한 필터는 추가하지 않음 |
| 자산 | 4개 보기와 목표 비교 → 현재 보기에 필요한 필터/추가 → 품질 안내 → 기존 자산 본문 | 다중 계좌·태그/버킷 구분·수량/평균가/비중·표 편집 |
| 판단·할 일 | 보기 전환 → 상태 필터 → 목록 → 더 보기 | 큰 반복 소개를 짧은 안내로 축소. 연결 상세 왕복·목록 위치 보존 |
| 투자 원칙 | 개인 기준·운용 원칙·계획 섹션과 각 편집 진입 | 저장 단위가 다른 설정을 단일 전체 저장으로 합치지 않음 |
| 배분 점검 | 자산으로 돌아가기 → 품질/분모 → 비교와 계산 | 조회용 계산과 원칙 편집 책임 분리 |
| 자료/활동 | 필터 또는 개수·보조 행동 → 목록/타임라인 | 자료 추가·수정·삭제, 활동 전후 값 유지 |
| 설정/가이드 | 섹션별 제목·설명·대상 행동 | 가이드의 설명형 구성 허용. 기능별 저장/권한 유지 |

## 모달·드로어·전체 화면 편집

- 공통 surface는 제목/닫기 및 상세 뒤로가기, 스크롤 본문, 선택적 footer를 별도 영역으로 가진다. header/footer는 본문 스크롤 밖에 남는다. 긴 제목은 줄바꿈하고 닫기 버튼을 밀어내지 않는다.
- 브리핑/판단/할 일처럼 긴 조회 상세는 PC 오른쪽 modal drawer, 모바일 전체 높이. 짧은 편집은 PC 중앙 modal, 모바일 전체 높이를 기본으로 한다. 동일 shell의 variant를 재사용하고 서로 다른 focus trap 구현을 만들지 않는다.
- 100dvh 및 safe-area를 고려한다. footer는 마지막 입력/오류를 가리지 않으며 가상 키보드에서도 입력과 저장에 도달할 수 있어야 한다. 모든 화면 폭의 하단 탐색은 overlay 아래에서 inert 처리한다.
- 저장 버튼은 오른쪽, 취소는 그 앞. 모바일은 두 버튼을 같은 행에 충분한 폭으로 제공한다. 위험 행동은 저장과 떨어진 별도 영역. 닫기와 취소의 문구는 읽기/편집 의도에 맞춘다.
- dirty 상태에서 닫기/X/Escape/배경 클릭/뒤로가기로 나갈 때 현재 surface 안에서 계속 편집/변경 버리기 선택을 제공한다. 기본 배경 클릭은 닫지 않는다. 최상위 surface만 키보드 닫기를 처리한다.
- 저장 중에는 닫기와 중복 저장을 막고 진행 상태를 알린다. 실패는 draft를 보존한다. 서버 저장 성공 후 재조회 실패는 저장 실패와 구분하며 재저장하지 않고 새로고침을 재시도한다. 기존 금융 멱등성 계약을 보존한다.
- 뒤로가기는 연결 상세의 이전 항목을 먼저 복원하고, 목록으로 돌아갈 때 필터·선택·스크롤을 복원한다. resize 때 draft/선택을 재생성하지 않는다. 새 router는 선행조건이 아니다.
- 표 전체 화면은 제목·종료, 필터·표 본문, 개수·오류·롤백·저장을 같은 surface에 포함한다. 전체 화면 종료는 inline 편집으로 돌아가는 것으로 draft를 유지한다. dirty 경고는 편집 자체를 떠날 때만 적용한다.
- 레이어 순서는 일반 본문 < 탐색 < 전체 화면/모달/드로어. 포털 또는 검증된 배치로 부모 stacking context 충돌을 방지하고 본문과 overlay의 이중 스크롤을 방지한다.

## 구현 경계와 검증

기존 AppHeader/ModalShell/ModalActions부터 확장한다. PageLayout, ViewTabs, FilterBar, Section, 상태 표현은 구체적인 두 소비자에서 필요한 props만 추출한다. 데이터 fetching/금융 계산/권한 판단은 UI primitive에 넣지 않는다. 새 UI 라이브러리·범용 폼 엔진은 필수 범위가 아니다.

각 티켓은 360/390/768/1024/1440px, 소유자/공유, 긴 이름/빈값/필터 없음/오류, 키보드와 모달 복귀를 기록한다. 자동 viewport 검증과 실제 모바일 키보드 검증은 구분한다. 안전한 fixture/격리 환경을 사용하며 로컬 URL이라는 이유로 운영 데이터에 테스트 기록을 저장하지 않는다.

이번 범위는 표현/상호작용 개선이다. API·DB·MCP·공유 권한·원가 계산은 변경하지 않는다. 새 쓰기 기능이나 자동 분석을 추가하지 않는다. 구현 완료 보고에는 화면별 적용 여부와 미검증 항목을 남긴다.

## 구현 현황과 예외

| 범위 | 적용 결과 | 검증 |
| --- | --- | --- |
| 판단·할 일 / 자산 | 공통 `ViewTabs`, `FilterChips`, `PageToolbar`, 연결 tabpanel과 44px 조작 영역 | 탭 Arrow/Home/End, 기존 보기·필터·공유 E2E |
| 읽기 상세 | 판단·할 일·브리핑에 모바일 전체 높이/PC 오른쪽 drawer와 내부 상세 뒤로가기 | focus/inert/Escape/연결 상세 E2E |
| 편집 surface | 계좌·종목·보유·태그·뉴스에 고정 footer, pending 차단, dirty 확인, dark 오류 | 닫기/계속 편집/버리기와 draft 유지 E2E |
| 표 편집 | 필터·표·상태·오류·롤백·저장을 전체 화면 shell에 통합하고 inline draft 공유 | 확대/수정/축소 draft와 5개 viewport E2E |
| 나머지 페이지 | feature 중복 상단 여백 제거, 주요 action 44px, dark 오류 표현 | 9개 목적지의 360/390/768/1024/1440px 가로 넘침 검사 |

자동 검증은 Vitest 80개, DB 278개, OAuth MCP 계약, Chromium E2E 28개, production build, encoding과 diff 검사를 사용한다. 실제 모바일 가상 키보드·iOS safe-area·실기기 스크린리더는 아직 확인하지 않았다.

상세 surface는 같은 URL의 browser history entry를 사용해 뒤로가기로 닫히며, 앱 내부 연결 상세는 별도 stack으로 이전 기록을 복원한다. 자산 편집 쓰기 성공 뒤 재조회만 실패하면 편집창을 닫고 전역 안내를 표시하여 동일 쓰기를 다시 저장하도록 유도하지 않는다.
