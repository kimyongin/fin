# 태그 디자인·사용성 가이드

2026-09-24 · Astra 설계, Sol 로컬 구현. 검증 범위는 [태그 UX 티켓](../tickets/ui-20-tag-chip-guidelines.md).

2026-09-26 후속 적용: [활동 태그 검색 입력 제거](../tickets/ui-30-activity-tags-without-search.md). 활동의 추가/기록/할 일 상세와 태그 관리에는 이름 검색 없이 칩 목록을 바로 표시한다. 활동 목록을 태그로 필터링하는 기능과 자산 태그 관리의 검색은 유지한다. 로컬 검증 범위는 해당 티켓에 기록한다.

상위 기준은 [디자인 원칙](./PRINCIPLES.md), 모달의 계층·저장·접근성은 [모달 가이드](./modal-guidelines.md)를 따른다. 이 문서는 모든 태그의 표시·선택·관리 표현의 정본이다. 글자 크기·굵기·줄간격은 [타이포그래피 가이드](./typography-guidelines.md)를 참조하며 주 대상 이름은 `item-title`, 조작 칩은 `action`, 보조 텍스트/읽기 칩은 `meta`다. 이 후속 글자 규칙의 전 영역 적용은 별도 구현 티켓에서 진행한다.

## 목적과 구분

태그를 한눈에 읽고, 누르면 무슨 일이 생기는지 예상할 수 있게 한다. 자산 태그와 활동 태그는 같은 디자인을 쓰되 기존 데이터와 사용 목적은 유지한다. 자산 대표 태그는 하나, 활동 연결은 여러 개이며 검색의 OR/모두 포함 조건도 유지한다.

| 용도 | 표시와 동작 | 저장 |
| --- | --- | --- |
| 주된 대상 | 배분 행에서는 태그명이 일반 텍스트 제목. 작은 칩으로 축소하지 않음 | 없음 |
| 보조 정보 | 자산 목록에서는 종목 코드 옆 일반 보조 텍스트. 활동의 복수 태그 등은 작은 읽기 전용 칩 | 없음 |
| 선택·필터 | 누를 수 있는 칩. 선택 상태는 테두리·배경색으로 알리고 버튼의 `aria-pressed`를 유지 | 상세의 저장 또는 검색 실행에 포함 |
| 태그 관리 | 칩을 누르면 같은 관리창에서 해당 이름을 직접 편집. 영역 라벨은 `편집할 태그` | 현재 태그 하나만 명시적으로 저장 |

관리 칩 선택을 기록에 붙이는 동작처럼 표현하지 않는다. 일반 읽기 칩을 눌러 임의로 필터를 바꾸지도 않는다. 선택 칩 안에 체크 표시나 그 빈자리를 두지 않는다.

## 모양·배치

- 선택·필터·관리 및 활동의 읽기 칩은 고정 10px 모서리 반경(`rounded-[10px]`)을 쓴다. 글자 수나 줄바꿈으로 높이·너비가 달라져도 곡률은 바뀌지 않는다. 너비는 내용만큼 사용하고 왼쪽에서 오른쪽으로 `flex-wrap` 배치하며 넘치면 다음 줄로 이어진다. 태그마다 전체 너비 행을 배정하거나 가로 스크롤을 요구하지 않는다. 자산 보조 텍스트·배분 제목까지 칩을 강제하지 않는다.
- 칩 사이 간격은 가로·세로 8px, 좌우 여백 12px을 기본으로 한다. 읽기용은 타이포그래피 `meta`·최소 28px 높이, 조작용은 `action`·최소 44×44px 조작 영역이다. 여러 줄이면 높이가 늘어나며 조밀하게 만들기 위해 터치 영역을 줄이지 않는다.
- 기존 surface/line/ink/accent 변수 사용. 기본은 중립 테두리와 배경, 선택은 accent 테두리·옅은 배경으로 구분한다. 선택 전후 텍스트는 칩 가운데에 놓고 체크 아이콘 공간을 예약하지 않는다. 임의 태그별 색상·색상 편집 기능을 추가하지 않는다.
- 긴 이름은 컨테이너 최대 너비 안에서 줄바꿈한다. 관리·선택에서 말줄임/hover tooltip만으로 전체 이름을 제공하지 않는다. 읽기 칩도 기본은 전체 이름을 제공한다.
- 빈 태그의 읽기 표시는 `태그 없음` 일반 보조 문구 또는 문맥상 생략한다. 자산 조회의 `태그 없음` 칩은 [상단 카드 가이드](./page-panel-guidelines.md)의 미분류 필터이며 실제 태그로 저장하지 않는다. 상세에서 가짜 태그를 선택·저장하게 만들지 않는다.
- 태그 ID를 key/선택 기준으로 유지하고 선택 시 순서를 재배열하지 않는다. 선택 태그를 두 목록에 중복 나열하지 않는다. 검색이 있는 자산 관리창은 검색어 변경으로 편집 초안을 초기화하지 않는다.
- 배분의 현재/목표/차이 행은 태그명을 제목으로 강조하고 숫자·입력을 하위 정보로 정렬한다. 자산 목록의 태그는 코드와 같은 보조 텍스트다. 표 편집의 셀 편집기는 표 조작을 위해 기존 select를 유지한다. #129/#130의 후속 설계이며 실제 적용 전이다.

## 선택 영역의 고정 간격 — 2026-09-26 후속 설계

[#143](../tickets/ui-32-stable-tag-selection-spacing.md)이 #141의 라벨 옆 선택 개수·초기화 표현을 대체한다. 로컬 구현 기준이다.

- 자산 단일 선택·활동 다중 선택·활동 태그 필터 모두 시각 라벨 아래 첫 칩 영역까지 8px을 확보한다. legend에 grid gap만 선언해서 실제 간격을 보장했다고 판단하지 않는다.
- 라벨 행은 선택 여부에 따라 높이가 바뀌지 않는다. `선택 N개`를 제거하고 각 칩의 테두리·배경 강조로 선택 상태를 읽는다. 2026-09-26 사용자 후속 결정에 따라 체크 표시와 미선택 상태의 빈 아이콘 자리는 모두 제거한다.
- 선택이 있으면 `선택 해제`를 전체 칩 뒤의 보조 텍스트 버튼으로 둔다. 단일은 하나, 다중은 모두 비운다. 최소 44px 조작 영역을 유지하고 좁은 화면에서는 마지막 줄로 넘어갈 수 있다. 라벨/첫 칩 행을 밀어내지 않는다.
- 선택/해제 시 칩 순서와 가능한 한 위치를 유지한다. 선택 개수나 해제 버튼 때문에 별도 상단 행이 생기지 않게 한다. 선택 전후 칩 너비와 실제 줄바꿈을 비교해 확인한다.
- fieldset/legend 또는 동등한 접근성 그룹 이름과 aria-pressed는 보존한다. 필터의 모두 포함 옵션은 칩 아래에서 기존 의미를 유지한다.
- 360/390/768/1024/1440px에서 선택 전/후/전체 해제의 실제 간격·첫 칩 좌표와 긴 태그 줄바꿈을 함께 검증한다. 정지 화면 한 장만으로 완료 처리하지 않는다.

## 관리창의 흐름

배분·활동 페이지의 `태그 관리`에서 같은 구조의 1차 모달을 연다. 관리창의 첫 목적은 기존 태그 탐색이다. 처음부터 새 태그가 선택되거나 빈 생성 폼이 열리지 않는다.

1. 활동 관리창은 검색 입력 없이 `편집할 태그` 목록부터 시작한다. 자산 관리창의 기존 `태그 검색`은 유지하며 검색어를 저장할 이름으로 자동 취급하지 않는다. 공통 관리창은 검색 사용 여부만 명시적으로 받으며 제목·정렬 필드 유무로 추론하지 않는다.
2. 아래 `편집할 태그` 영역에 칩들을 가로로 배치한다. 짧은 안내 `태그를 누르면 이름을 수정할 수 있습니다`로 클릭 결과를 알린다. 목록 다음에 보조 `+ 새 태그` 버튼을 둔다.
3. 칩 또는 `+ 새 태그`를 누르면 목록과 버튼 아래에 작은 인라인 편집 영역 하나를 표시하고 태그명 입력으로 초점을 옮겨 스크롤한다. 각각 `태그 수정 · 기존 이름`, `새 태그 추가`로 목적을 표시한다. 칩은 그대로 보여 다른 대상으로 이동할 수 있다.
4. 태그명은 바로 편집 가능하다. 자산 태그의 기존 정렬 순서는 같은 영역에 유지하되 칩마다 순서 숫자를 반복하지 않는다. 활동에는 정렬 필드를 추가하지 않는다. 별도 수정 버튼/편집 모달/접기 조작은 없다.
5. 미선택 상태의 footer는 `닫기`만, 추가/수정 중에는 `닫기 / 추가` 또는 `닫기 / 저장`이다. 입력 영역에 현재 대상 하나만 저장됨을 드러낸다. 삭제는 선택한 태그의 편집 영역에 보조 위험 버튼으로 둔다. 각 칩 안에 작은 삭제·편집 버튼을 넣지 않는다.
6. 성공하면 관리창과 방금 저장한 대상의 편집 영역을 유지한다. 성공 안내로 `추가됨`/`저장됨`을 표시하고 기준값을 갱신한다. 자산 관리에서 수정된 칩이 검색 결과에서 사라져도 저장된 이름과 결과는 편집 영역에서 확인 가능하다.
7. 다른 태그/새 태그/닫기는 기존 미저장 보호를 사용한다. 삭제와 변경 버리기만 2차 확인을 사용한다. 삭제 성공은 선택을 해제하며 새 태그 폼을 자동으로 열지 않는다.

이 관리창은 사전의 여러 대상을 탐색하는 용도이므로 초기 미선택을 허용한다. 선택한 대상은 바로 편집하며 그 속성을 한 번에 저장하는 모달 원칙을 유지한다. 한 번에 하나의 초안만 두고 자동 저장·다중 태그 일괄 저장은 도입하지 않는다.

목록은 관리창 본문과 함께 스크롤한다. 기본 192px 높이 제한과 중첩 스크롤을 제거한다. 활동 목록은 전체 칩을 줄바꿈하며 접기·더 보기·태그 개수에 따른 숨김을 추가하지 않는다. 자산 관리에는 기존 검색이 있다. footer는 공통 shell에 고정하고 화면 높이가 짧으면 본문 스크롤로 입력/오류에 접근한다.

## 선택과 관리의 경계

- 활동 추가·기록/할 일 상세는 검색 없이 칩 다중 선택을 제공한다. 자산 대표 태그는 같은 칩으로 단일 선택하며 `선택 해제`로 없음 상태를 만든다. 활동 목록의 태그 필터는 별개이며 기존 OR/모두 포함 의미를 유지한다.
- 선택/해제는 부모 초안만 변경한다. 태그 생성/이름 변경/삭제는 페이지의 관리창에서만 한다. 상세 위에 태그 관리 모달을 쌓지 않는다.
- 선택/검색 영역에는 체크박스 테두리를 반복하지 않는다. 버튼 `aria-pressed`, 키보드 Enter/Space, 명확한 focus ring을 제공한다. 관리의 현재 편집 대상도 상태와 입력 영역 연결을 접근성 이름/설명으로 알린다.
- 목록 로딩/실패/빈 목록을 구별하며, 검색 결과 없음은 검색이 있는 자산 관리에만 해당한다. 공유 읽기 전용 화면에서는 허용된 데이터의 조회 필터를 사용할 수 있으나 대상 태그 연결 수정·관리 동작은 제공하지 않는다.
- 이름 변경은 ID를 유지해 목록·상세·검색에 반영한다. 삭제는 현재 서버의 영향과 거부 조건을 그대로 알린다. 배분 목표가 있어 삭제가 거부되는 경우 오류와 초안을 유지한다. 다른 데이터/목표 초안은 보존한다.

## 공통 구현과 유지 관리

첫 관리창 슬라이스에서 실제 소비하는 `TagChip`과 줄바꿈 배치의 최소 표현만 추출한다. 표시용 span과 조작용 button을 구분하고 버튼 안에 버튼을 넣지 않는다. `TagManagerModal`은 두 관리창이 재사용하고 조회·권한·저장·재조회는 기존 기능에 둔다. 범용 CRUD/선택 엔진이나 새 저장소는 만들지 않는다.

모든 신규/수정 태그 UI는 이 가이드를 확인한다. 앱 내 적용표를 구현 티켓에서 관리하며 남은 위치와 예외를 명시한다. 가이드를 먼저 갱신하고 공통 표현·소비자·검증을 함께 바꾸는 것을 변경 완료 조건으로 한다. 값이나 검색 의미가 바뀌지 않는 이번 작업은 DB/MCP 계약 변경이 필요 없다.

검증은 360/390/768/1024/1440px에서 한다. 0/1/30개 태그, 50자 이름·공백 없는 이름, 줄바꿈, 키보드, 선택/해제, 자산 관리 검색, 활동 목록의 태그 조회, 추가/수정/삭제, 미저장 전환, 오류·재시도를 확인한다. 활동의 검색 query/결과 없음 분기는 퇴역한다. 실제 모바일 키보드·스크린리더 검증 여부는 별도로 기록한다. 가이드 작성은 구현·실사용 검증 완료를 뜻하지 않는다.
