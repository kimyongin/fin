# Portfolio 제품 재정리: 목적에 맞춘 유지와 재구성

## 최신 화면 배치 결정 — 자산 관리 기능 이동 (2026-09-23, 구현 전)

[#112](../tickets/ui-05-asset-management-placement.md)에 따라 가격 갱신·종목 태그 관리는 설정에서 자산으로, 운용 전략 생성/편집은 원칙에서 자산의 배분 점검으로 이동했다. 운용 전략은 화면에서 `배분 설정`이라고 표시한다. 목표/현재 비중 확인과 설정 편집을 같은 흐름에 둔다. 원칙은 독립된 하단 탭으로 유지하며 서술형 기준·운영 규칙과 과거 원칙 조회를 제공한다.

기존 자산 네 보기, 계산, 저장 및 공유 권한은 유지한다. 이 결정은 아래 과거 기획의 원칙 내 운용 계획 편집 배치를 대체한다. 저장 구조는 ADR-0008 및 현재 PRD가 우선하며 아래 이전 개발 기준은 이력이다. 로컬 UI에 반영했으며 운영 배포는 별개다.

## 현재 개발 기준 — 활동·결과·태그·검색 (2026-09-23)

[새 설계](../design/activity-simplification.md)와 [ADR-0007](../adr/0007-activity-results-and-search.md)을 먼저 읽는다. 사용자에게 활동 하나로 할 일·한 일·결론을 제공한다. 판단 모아보기 탭과 등록 경로별 라벨을 제거하고 다중 활동 태그 및 조건·키워드·유사도 검색을 제공하는 계획이다. 물리적 판단 테이블 통합 여부는 #80에서 결정한다.

티켓 #80 계약 → #81 활동/결과 수직 통합 → #82 태그/기본 검색 → #83 하이브리드 검색. #84 문맥/MCP 가이드는 각 slice와 함께, #85 전환/검증은 첫 slice부터 진행한다. **현재는 티켓 작성 완료·구현 전**이다. #75~#79 기반과 미검증 게이트는 보존하며 아래 이전 기준과 충돌하면 이 절을 우선한다. 검색용 임베딩의 비용/실행 방식은 #83에서 검증하며 뉴스 조사·의견 생성은 ChatGPT가 담당한다.


## 현재 개발 기준 — 태스크・자동 행동 이벤트 (2026-09-22)

[설계](../design/tasks-and-events.md)와 [ADR-0006](../adr/0006-tasks-and-action-events.md)이 우선한다. 내부 태스크/이벤트는 분리하고 사용자에게는 예정된 행동과 수행한 행동을 하나의 목록으로 제공한다. 값 수정은 자동 이벤트, 태스크 완료는 연결 이벤트, 매일 반복은 회차별 유효 완료 이벤트로 기록한다. 영구 번들은 제거 방향이며 날짜별 표시와 요청 기반 일/주/월 리포트를 제공한다.

구현 순서: #75 자동 이벤트/일반 태스크 → #76 매일 반복 → #77 통합 목록 → #78 기간 리포트 → #79 전환/가이드/검증. 명세와 로컬 구현 결과는 docs/tickets/action-timeline-01~05에 있다. 운영 배포와 실제 ChatGPT 평가는 별도 게이트다.

#69/#70 메모/운영 규칙은 유지한다. #71~#74는 로컬 구현/검증 이력을 보존하되 해당 후속 작업은 #75~#79로 대체한다. 기존 migration과 로컬 기록을 삭제하지 않는다. 운영 배포/사람 평가 완료를 뜻하지 않는다.

## 이전 개발 기준 — ToDo·원칙 통합 (대체된 설계 이력)
설계/티켓 작성 완료, 구현 전. [공통 설계](./todo-principles-integration.md)와 [ADR-0005](../adr/0005-todo-bundles-and-operating-rules.md)를 먼저 읽는다.
신규 순서: #69 기존 메모/확인 메모 → #70 원칙의 데이터 관리 규칙 → #71 ToDo 묶음 → #72 탐색/판단/활동 통합 → #73 오늘/MCP 연결 → #74 검증. 각 티켓은 docs/tickets/todo-principles-01~06 로컬 명세에 대응한다.
주 메뉴는 오늘/자산/ToDo/원칙으로 변경 예정이며 기존 대상 메모・조사/실행・판단・금융/활동 원본을 유지한다. 규칙은 독립 저장하고 관련 작업에서 조회하며, ToDo는 여러 작업을 한 묶음으로 기록한다.
아래 과거 메뉴·구현 전 표기·작업 순서는 작성 당시 이력이다. 충돌하는 범위에서는 이번 설계를 적용한다. 기존 미완료 검증은 자동 완료 처리하지 않는다.
GitHub 대조: #66/#68 closed, #67 실제 모델 평가 open. 피드백 기능은 구현되어 있으므로 아래 '아직 미구현'을 새 구현 지시로 읽지 않는다. 운영/평가 상태는 개별 최신 티켓을 확인한다.

결정일: 2026-09-20 · 구현 전 설계 기준

새 세션은 [START-HERE](../START-HERE.md)부터 읽는다. 제품 목적은 [PRD](../prd/portfolio.md), 선택 이유와 책임 경계는 [ADR-0001](../adr/0001-mcp-first-product-boundaries.md)에 기록한다. 이 문서는 기능별 재구성과 구현 책임의 상세 원본이다.

## 목적과 판단 기준

내 자산의 현재 상태와 투자 기준을 바탕으로 마지막 점검 이후 무엇이 달라졌고 무엇을 판단해야 하는지 파악하며, 판단과 실행을 다음 점검으로 이어간다.
ChatGPT는 조사·해석·설명을, Portfolio는 기억·계산·검증을 담당한다. 분석은 사용자 요청으로 시작하며 자동 생성하지 않는다.

기존 기능의 존재 자체를 보존 이유로 삼지 않는다. 사용자에게 유용한 흐름·데이터·계산의 의미는 살리고, 목적이 겹치는 화면과 책임은 재구성한다.
기능 유지와 화면 위치 유지는 다르다. 승인된 재배치와 표현 변경은 허용하되 조용한 데이터 삭제·권한 확대·기능 누락은 금지한다.

## 목표 정보 구조

- 주 탐색: 오늘 / 자산 / 활동 / 원칙. 모바일과 PC 모두 하단 4개 메뉴를 유지해 화면 폭이 바뀌어도 조작 위치가 달라지지 않게 한다. 활동 안에서 할 일·한 일과 판단을 전환한다.
- 자산: 기존 태그 기준 / 계좌 기준 / 종목 기준 / 표 편집 유지. 기본 전체 접힘이나 v3 카드로 전면 교체하지 않는다.
- 자산의 ‘목표와 비교’ → 배분 점검: 전략 버킷의 현재/목표/차이, 적립금 배분, 규칙 기반 조정 후보. 별도 최상위 메뉴를 늘리지 않는다.
- 투자 원칙: 선택적 개인 기준 + 기존 상세 원칙 + 운용 계획 편집. 모드별 목표·적립금·리밸런싱 계산 결과는 자산의 ‘목표와 비교’에만 배치한다.
- 판단/브리핑 → 연결 근거 → 자료 보관함. 모든 뉴스의 수동 분류·저장을 일일 필수 작업으로 만들지 않는다.
- 활동 내역·자료 보관함·설정·가이드는 보조 진입점. 기존 URL은 대응 화면으로 안내하고 공유 포트폴리오 문맥을 보존한다.
- 기존 어두운 테마·강조색·공통 컴포넌트를 기반으로 새로운 화면을 통합한다. 기능별로 전혀 다른 앱처럼 만들지 않는다.

## 데이터와 계산의 경계

- 현행 UI는 종목당 태그 하나를 사용하고 전략 버킷이 여러 태그를 묶는다. 태그와 목표 버킷을 동일 객체로 합치지 않는다. DB 제약은 구현 시 별도 확인한다.
- 화면·MCP에 동일한 평가·집계 계약을 적용한다. 시장형/평가형/현금성, 외화, 복수 계좌, 미분류·버킷 미연결 자산을 다룬다.
- 시세 없음에 평균가를 쓰는 처리와 환율 없음에 0을 반환하는 기존 처리는 명시적인 품질 상태로 구분한다. 최종 누락값/분모 정책은 #32에서 확정하고 #34에서 구현, #36/#43에서 표시한다. 누락을 실제 0원으로 설명하지 않는다.
- 배분 계산은 공통 로직으로 검증한다. Portfolio의 규칙 계산 / ChatGPT 의견 / 사용자가 채택한 결정 / 실제 체결을 별개로 둔다. 후보 계산만으로 결정·할 일·체결을 만들지 않는다.
- 기준점·거래·보정 계약은 #32/#37/#38, 원칙 버전은 #43, 판단·조사 관계는 #44/#35가 담당한다. 동일 저장 원본을 중복 구현하지 않는다.

## 입력과 권한

- 초기·대량 등록은 기존 표 편집을 활용한다. 붙여넣기·검색·필터·이전 값·행 취소·전체 롤백·전체 화면·CSV 흐름을 유지한다.
- 보정은 현재 상태를 바꾸고, 체결 기록은 실제 매매를 기록한다. 메모/태그만 수정하거나 변경 없는 행을 다시 저장했다고 잔고 기준점을 새로 만들지 않는다.
- 잔고 확인은 사용자가 증권사와 비교한 범위만 기록한다. 보정·체결·브리핑만으로 확인을 추정하지 않는다.
- 현재 공유 전략에 원칙이 표시되는 경로와 신규 개인 기준의 비공개 요구를 필드별로 정리한다. 기존 공유는 명시적 정책 없이 변경하지 않고 새 민감정보는 자동 공개하지 않는다.
- 소유자·친구 보기·OAuth MCP·기존 토큰 MCP의 권한을 함께 검증한다. UI 숨김만으로 보호하지 않는다.
- 후속 확정 정책: [ADR-0002](../adr/0002-cost-basis-reconciliation-and-sharing.md)의 수수료 제외 평균가·보정 이전 정정의 현재값 유지, [ADR-0003](../adr/0003-extensible-feature-sharing.md)의 기능별 선택 공유를 적용한다. 기본 비공개는 영구 공유 금지가 아니며 새 기능은 자동 공개하지 않는다.

## 티켓 실행 순서와 경계

1. #32에서 기존 기능 대응표·계산/입력 정책을 확정하고 #33에서 OAuth 계약을 검증한다.
2. #44의 관계 계약과 #43의 원칙 버전 계약을 맞춘다. #41/#42는 optional 필드와 버전 참조를 먼저 합의한다.
3. #35-A 공통 스키마/저장 기반 → #34 읽기 문맥과 #35-B 쓰기/조회 → #35-C 재시도·동시성 검증. #34 완료를 스키마 생성의 선행 조건으로 두지 않는다.
4. #43 원칙·운용 계획 재구성과 계산 계약 → #36-A 탐색/기존 화면 연결, #36-B 오늘·판단·할 일, #36-C 자료·활동 재배치/온보딩. UI 골격은 합의된 계약과 fixture로 먼저 진행할 수 있다.
5. #37 매매 → #38 기존 편집과 보정 통합. #41/#42 및 각 화면의 최종 연동을 검증한다.
6. #39 읽기 파일럿은 실제 점검·저장·재열람이 가능해지면 시작한다. 전체 완료는 필수 연동·기존 흐름 회귀·실제 5일 관찰 후 판단한다.

작업 단위는 기존 티켓 안에서 나눈다. 기존 번호를 폐기하거나 중복 시스템 티켓을 만들지 않는다. 상세 계약에 없는 선택은 구현자가 임의로 결정하지 않고 해당 계약 티켓에 기록한다.

## 인수와 문서 우선순위
