# 목록의 읽기·편집·모바일 조작

2026-09-28 · 승인된 설계와 구현 기준. 화면별 적용 및 남은 검증은 [구현 티켓](../tickets/ui-35-list-reading-and-mobile-interaction.md)에서 관리한다.

## 공통 규칙

- 데이터 목록의 행·제목·본문 전체에 상세/편집 클릭을 연결하지 않는다. 내용은 스크롤·선택·복사 영역이며, 제목 바로 옆의 명시적인 아이콘 버튼으로 연다. PC도 동일하다.
- 읽기는 문서 아이콘, 편집은 연필 아이콘을 공통으로 쓴다. 둘 다 있으면 읽기 → 편집 순서다. 기존 아이콘 시스템을 재사용하고 시각 크기는 약 20px, 실제 터치 영역은 최소 44×44 CSS px로 한다. 두 누름 영역은 간격 없이 맞닿고, 아이콘 그림만 안쪽으로 조금 모아 시각적 간격을 줄인다. focus 스타일은 유지한다.
- 버튼은 대상 이름을 포함한 접근성 이름과 키보드 초점을 제공한다. hover/focus 설명을 제공하되 tooltip 없이도 모바일에서 기능을 알아볼 수 있어야 한다. 아이콘에는 중복 낭독이 없도록 한다.
- 화면에서 이미 본문 전체를 읽거나 목표값을 직접 입력하는 경우 불필요한 읽기/편집 모달을 추가하지 않는다. 적용표에 직접 입력·인라인 본문 등의 이유를 기록한다. 메뉴·태그 선택·자동완성·프로필 전환·접기/펼치기는 데이터 상세 열기와 다른 조작이며 기존 선택 기능을 유지한다.
- 완료·이번 완료·중단·삭제·저장·확인은 읽기/편집과 다른 행동이다. 이번 변경으로 모두 아이콘화하지 않는다. 특히 반복 회차 완료와 반복 중단을 합치지 않는다.
- 공유 조회에는 허용된 읽기만 노출한다. 버튼 숨김으로 서버 권한 검증을 대신하지 않는다.

## 읽기와 편집 모달

- 활동의 할 일·기록은 읽기 버튼으로 읽기 전용 마크다운 본문을, 편집 버튼으로 기존 원문 편집 폼을 연다. 읽기는 초안 생성·저장·완료를 실행하지 않는다. 목록 미리보기는 서식을 정리한 짧은 일반 텍스트다.
- 읽기 안의 연필 버튼은 같은 1차 모달을 편집 화면으로 전환한다. 편집 모달을 그 위에 겹치지 않는다. 저장 성공/변경 없이 취소/폐기 확인 후에는 원래 읽기로 복귀하고, 목록에서 직접 편집했다면 목록으로 복귀한다. 닫힌 읽기 화면 위에 뒤늦은 조회가 열리지 않게 한다.
- 관련 할 일/기록은 기존 허용 범위에서 읽되, 새 중첩 상세를 만들지 않는다. 검색 맥락 확장과 관련 추천은 별도 티켓 범위다.
- 읽기·편집 모두 기존 ModalShell과 모바일 전체 화면/넓은 화면 중앙 모달 규칙을 따른다. 2차 모달은 기존 의사 확인만 허용한다. 목록 필터·페이지·스크롤과 호출 아이콘의 초점을 복원한다.
- 마크다운은 공통 MarkdownContent를 통해 제목, 문단, 중첩 목록, 강조, 인용, 링크, 코드, 표를 안전하게 표시한다. 원문 저장 형식을 바꾸지 않는다. raw HTML과 실행 가능한 URL은 실행하지 않는다. 이미지 문법은 자동 외부 로딩 없이 안전한 링크/대체 텍스트로 표현한다. 새 에디터나 서버 변환은 필요 없다.

## 폭과 터치

- 내용 열은 줄어들 수 있게 하고 긴 제목·URL·티커·태그는 줄바꿈한다. 읽기·편집 버튼은 제목 바로 옆에 두고, 좁으면 제목과 함께 자연스럽게 다음 줄로 감싼다. 버튼 때문에 숫자나 제목이 잘리지 않게 한다.
- 일반 페이지·행·모달 전체의 가로 넘침은 허용하지 않는다. 넓은 마크다운 표와 코드 블록, 기존 표 편집만 자신의 내부에서 가로 스크롤한다. 전역 overflow 숨김이나 글자 축소로 문제를 가리지 않는다.
- 브라우저의 기본 click과 세로 스크롤을 우선 사용한다. pointerdown/touchend만으로 열지 않는다. 버튼 위에서 시작한 스크롤·pointercancel도 실행되지 않는지 재현한다. 기본 동작으로 해결되지 않는 경로에만 최소 이동 판정을 추가하며 앱 전체 제스처 엔진은 만들지 않는다.
- 긴 누르기·두 번 누르기·스와이프를 읽기/편집의 필수 진입으로 사용하지 않는다.

타이포그래피·태그·모달의 세부 수치는 기존 가이드가 정본이다. 모든 도달 가능한 목록의 적용/예외와 실제 검증을 티켓에 남겨야 전수 적용으로 판단한다.
