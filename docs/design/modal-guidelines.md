# 모달 디자인 가이드

2026-09-24 · 모든 모달에 적용하는 공통 기준. 계좌 추가·보유 추가의 실제 폼 디자인을 기준으로 정했다. 같은 대상의 상세에서 직접 편집·단일 저장하는 규칙을 추가했다. #117은 기존 스타일 적용 이력이며 새 규칙의 전수 적용은 [공통 직접 편집 티켓](../tickets/ui-16-modal-inline-edit.md)에서 관리한다. 기존 모든 모달의 적용 완료를 의미하지 않는다.

상위 원칙은 [PRINCIPLES](./PRINCIPLES.md), 모달의 상세 시각·배치 규칙은 이 문서가 원본이다. 과거 screen-structure/component-system의 일괄 드로어 요구보다 아래 용도별 기준을 우선한다.

글자 크기·굵기·줄간격은 [타이포그래피 가이드](./typography-guidelines.md)가 정본이다. 1차/2차 제목은 `dialog-title`, 입력 라벨은 `label`, 입력값은 `input`, 긴 읽기 내용은 `body`, 조작은 `action`으로 통일한다. 아래 규칙은 문서 계약이며 [전 영역 적용 티켓](../tickets/ui-24-typography-consistency.md)의 코드 검증 전이다.

## 모달 계층과 확인 단계

다음은 공통 `ModalShell`과 확인 계층의 구현 표준이다. 적용 범위와 검증은 [#126 모달 계층 통일 티켓](../tickets/ui-18-modal-hierarchy.md)에서 관리한다.

| 계층 | 역할 | 허용하는 내용 |
| --- | --- | --- |
| 0 · 페이지 | 탐색·목록 | 모달을 여는 시작점. 모달이 열리면 조작 불가 |
| 1 · 대상 모달 | 한 대상의 조회·직접 편집 | 필드·검증 오류·저장/닫기·독립 행동 진입. 현재 초안과 스크롤을 소유 |
| 2 · 확인 모달 | 짧은 단일 결정 | 미저장 닫기, 삭제/종료, 금융값 확정처럼 결과를 다시 확인해야 하는 행동 |

- **2차 모달은 사용자 의사 확인 전용이다.** 이미 1차 화면에서 정한 변경을 실행할지/버릴지 결정한다. 대상 속성 편집, 태그 추가·이름 변경, 목록 탐색·선택을 2차 모달로 설계하지 않는다. 이름을 ‘확인’으로 붙여 일반 편집 폼을 넣는 것도 금지한다.
- 해당 확정에 부수되는 짧은 선택적 변경 사유는 예외로 허용한다. 사유만 받아도 실행할 변경이 이미 확정되어 있어야 하며, 수량·가격·태그 등 변경값은 1차 화면에서 수정한다. 확인 취소 후 다시 돌아오면 입력한 사유를 보존하되 실제 쓰기는 최종 확정에서만 한다.
- 태그 관리의 최신 표현은 [태그 가이드](./tag-guidelines.md)와 [#128](../tickets/ui-20-tag-chip-guidelines.md)를 따른다. 배분/활동 페이지에서 각각 1차 태그 관리창을 열고 타원형 칩 목록·추가·선택한 태그 편집을 같은 본문에서 제공한다. 초기 미선택은 사전 탐색 상태이며 선택한 대상은 바로 편집한다. 관리창을 닫고 별도 편집창을 다시 여는 우회도 피한다. 삭제/미저장 폐기만 2차 확인을 쓴다. #127의 저장 계약은 유지하며 새 표현은 아직 구현 전이다.
- 동시에 활성화되는 대화상자는 하나다. 2단계는 1단계 위에 표시하되 1단계는 화면·초안·스크롤 위치를 유지하고 `inert`가 된다. 2단계를 닫으면 호출 지점으로 초점이 돌아가고 입력값은 그대로다. DOM에 두 대화상자가 남더라도 접근성 트리와 키보드에서는 최상위 하나만 활성화한다.
- 3단계 모달은 만들지 않는다. 확인 중 다른 결정이 필요하면 현재 2단계에서 선택지를 합치거나 1단계로 돌아간다. 확인을 여러 번 연속 요구하지 않는다. 예를 들어 미저장 자산을 삭제할 때는 한 확인창에서 ‘미저장 변경을 버리고 삭제’를 명시한다.
- 단순 입력 오류·성공 알림·필터·선택·도움말은 1단계의 해당 위치에 표시한다. 푸터 높이를 늘려 삭제/미저장 확인을 끼워 넣거나 버튼 이름만 ‘삭제 확인’으로 바꾸지 않는다.
- 2단계는 휴대폰에서도 내용 크기의 중앙 확인창이다. 본문이 길거나 키보드가 열리면 2단계 내부만 스크롤하며 1단계의 고정 footer·입력값은 움직이거나 사라지지 않는다. 긴 편집·대상 탐색은 2단계에 넣지 않고 1단계의 영역/전환으로 처리한다.
- 2단계는 짧은 제목, 대상·영향 설명, `취소`와 구체적인 실행 버튼을 사용한다. 위험한 삭제·버리기는 위험 색, 저장 확정은 강조색이다. 실패 메시지는 2단계에 남기고 재시도할 수 있게 한다. 처리 중에는 모든 닫기·중복 실행을 막는다.
- Escape와 2단계 X는 취소하여 1단계로 돌아간다. 1단계 X/푸터 닫기/Escape/뒤로가기는 동일한 미저장 보호를 거친다. 미저장 확인의 `계속 편집`은 초안을 유지하고 `변경 버리기`만 1단계를 닫는다. 배경 클릭으로 단계를 건너뛰거나 초안을 버리지 않는다.
- 공통 `ModalShell`과 그 위에 portal로 표시하는 얇은 `ConfirmDialog`를 사용한다. 기능별 코드는 어떤 행동을 확인할지, 실제 저장·삭제, 오류를 담당한다. 2단계 전용 overlay·포커스 트랩을 기능마다 다시 만들거나 범용 저장 엔진을 도입하지 않는다.

## 1. 참조와 공통 구현

2026-09-26 승인된 후속 디자인: [필드 통일 티켓](../tickets/ui-29-modal-field-consistency.md)과 [승인 시안](./assets/modal-field-preview-20260926.png)을 따른다. 짧은 속성은 편집 여부와 관계없이 같은 `라벨 → 필드` 구조로 표시한다. 읽기 전용도 같은 크기와 정렬을 사용하며 배경·잠금 표시로 구별한다. 아래 3절이 구체적인 기준이며 활성 모달에 로컬 적용했다. 실제 검증 범위는 티켓에 기록한다.

자산 [#139](../tickets/ui-28-instrument-registration-and-quote-display.md)의 종목 등록·0보유 흐름과 시세 쓰기 금지는 유지한다. 현재가/기준일의 일반 텍스트 표현만 새 읽기 전용 필드로 대체한다. 상세 헤더는 종목명·닫기, 본문은 종목명/티커 → 통화/종류 → 현재가/기준일 → 태그/메모 → 계좌별 보유 순서다. 가격 입력을 다시 허용하는 변경이 아니다.

기록 추가/상세의 후속 설계는 [#125](../tickets/activity-16-record-editor-simplification.md)다. 태그 선택·관련 종목·관련 할 일은 접기 없이 한 곳에서 편집하고, 연결 검색은 같은 폼의 결과 목록에서 바로 선택한다. [태그 관리 통일](../tickets/ui-19-tag-management-consistency.md)에 따라 태그 자체의 추가·이름 변경·삭제는 활동 페이지의 관리창으로 분리한다. 선택한 태그 연결은 여전히 기록/할 일 본문과 함께 저장한다. 별도 선택 모달이나 읽기/편집 중복 영역을 추가하지 않는다.

자산 상세의 최신 후속 설계는 [#124](../tickets/ui-17-asset-detail-simplification.md)다. 아래 일반적인 접기 허용과 달리 자산 상세의 가격·보유·메모는 접지 않는다. 보유값 저장 직전의 작은 사유 확인창을 예외로 허용하며 배경 상세를 비활성화하고 초안을 보존한다. 활성 dialog/포커스 트랩은 하나로 유지한다. 이 예외는 다른 기능에 확인창이나 필수 사유 입력을 추가하라는 지시가 아니다. 현재는 설계이며 구현 전이다.

### 상세는 그 대상의 편집 공간이다

- 편집 권한이 있는 현재 대상의 상세는 그 안에서 수정 가능한 모든 속성을 바로 편집한다. ‘수정’ 버튼으로 별도 편집 모드에 진입하거나 속성별 모달을 새로 여는 단계를 기본으로 두지 않는다. 드문 입력은 같은 본문에서 펼칠 수 있다.
- 같은 대상의 제목·본문·일정·선택 태그·메모 등 일반 속성은 하나의 초안으로 관리하고 하단 `저장` 하나로 함께 반영한다. 태그 선택만 따로 저장하거나 blur 시 일부 필드를 먼저 저장하지 않는다.
- 사용자에게 한 번의 저장으로 보이는 변경은 서버에서도 한 단위로 성공/실패해야 한다. 실제 저장소가 여러 개인 경우 해당 기능의 목적별 원자 저장 계약을 마련한다. 브라우저에서 독립 쓰기를 순차 호출하는 것으로 완료 처리하지 않는다.
- 저장 후 현재 모달을 유지하고 저장된 값으로 초안 기준을 갱신한다. 등록 성공은 기존 목록으로 돌아갈 수 있다. 닫기는 모달 종료이며 변경이 있으면 공통 미저장 확인을 거친다. 별도의 읽기 모드로 돌아가기 위한 ‘편집 취소’ 단계는 만들지 않는다.
- 매매 확정·할 일 완료·삭제·반복 종료처럼 실제 의미가 다른 행동은 일반 속성 저장과 구별한다. 미리보기는 업무 입력의 일부로 1단계에 두고, 짧은 최종 확인만 위 계층 2에 둔다. 미저장 초안과 충돌하는 삭제는 버려질 변경과 삭제 영향을 한 번에 알리며, 먼저 저장하려면 1단계로 돌아간다.
- 공유 조회, 권한 없는 대상, 과거 원칙 본문, 계산 결과는 실제 권한을 유지한다. 짧은 속성의 읽기 전용 필드와 긴 본문·설명의 표시를 아래 3절에 따라 구분하고, 조회 전용 모달에는 저장 버튼을 추가하지 않는다. 필드 모양을 통일해도 편집 권한이나 서버 쓰기 계약은 바뀌지 않는다.
- 대상 선택이나 참조 대상 탐색으로 다른 대상을 열어야 하면 같은 shell 안에서 전환하며 기존 초안·복귀 경로를 보존한다. 다른 대상의 사전 관리(태그 이름/삭제 등)를 현재 대상의 태그 선택 저장과 혼동하지 않는다. 추가 dialog를 쌓는 대신 인라인 영역이나 동일 shell 단계를 사용한다.
- 이 규칙은 자산에 한정되지 않는다. 활동·할 일·원칙·계좌·보유·태그 등 도달 가능한 모든 모달에 적용하고, 읽기 전용/업무상 별도 행동은 이유를 적용표에 기록한다. 공통 shell은 표현·접근성만 담당하며 도메인 저장을 대신하는 범용 엔진은 만들지 않는다.

- 현재 폼 참조: `EditorModals.jsx`의 AccountEditorModal·InstrumentEditorModal과 `AssetDetailModal.jsx`. 독립 HoldingEditorModal은 #139에서 제거했다. 새 시각 기준은 승인 시안과 아래 3절이다.
- 공통 틀: `src/components/ModalShell.jsx`. 제목/닫기, 스크롤 본문, 필요할 때 footer의 세 영역을 사용한다.
- 공통 액션: `src/components/ModalActions.jsx`. 등록/편집에 재사용하며 실제 의미에 필요한 최소 옵션만 보완한다.
- 기능은 입력·오류·저장 상태를 담당하고, shell이 폭·배경·초점·스크롤·닫기 규칙을 담당한다. 기능마다 별도 overlay/focus trap을 만들지 않는다.
- 참조 코드도 이 가이드의 검증 대상이다. 참조에 있다는 이유만으로 접근성이나 오류 처리 문제까지 복제하지 않는다. 범용 폼 엔진은 도입하지 않는다.

## 2. 크기와 구조

| 용도 | 작은 화면 | 넓은 화면 |
| --- | --- | --- |
| 등록·수정·활동/기록/할 일 상세·태그 관리 | 640px 미만 전체 화면 | 중앙 모달, 최대 42rem(기존 max-w-2xl), 바깥 여백 확보 |
| 2차 의사 확인 | 내용 크기의 중앙 창, 바깥 여백 16px | 내용 크기의 중앙 창, 최대 32rem |
| 긴 조회 전용 상세 | 1024px 미만 전체 높이 | 오른쪽 드로어 최대 40rem 사용 가능. 해당 화면에 선택 이유를 기록 |
| 표 편집 | 전체 화면 | 전체 화면. 여러 열 편집을 위한 명시적 예외 |

- 헤더는 명확한 제목 하나와 44px 닫기 버튼. 필요한 설명만 한두 줄로 두고 본문에 같은 제목을 반복하지 않는다.
- 본문 좌우 여백은 모바일 16px, PC 24px. 폼 필드 사이는 16px, 의미가 다른 섹션 사이는 24px을 기본으로 한다.
- 높이는 화면 안으로 제한하고 본문만 스크롤한다. 헤더와 footer는 입력/오류를 가리지 않으며 safe-area와 모바일 키보드를 고려한다.
- 좁은 화면은 한 열. 날짜·종류처럼 짧고 관련된 항목만 공간이 충분할 때 두 열로 배치한다. 제목·설명·메모는 전체 폭이다.
- 조회 전용 모달에 빈 footer나 저장 버튼을 만들지 않는다. 읽기 전용 필드는 비활성 처리로 흐리게 만들지 않으며 본문 선택·복사를 지원한다.

## 3. 폼과 읽기 본문

| 요소 | 기준 |
| --- | --- |
| 필드 라벨 | 타이포그래피 `label`, muted-ink, 입력과 8px 간격. 한국어 긴 라벨에 과도한 자간을 주지 않음 |

| textarea | 동일 배경/테두리/여백, 기본 약 3줄. 용도에 맞게 조정하며 입력을 잘라 숨기지 않음 |
| 입력 초점 | accent 테두리와 식별 가능한 키보드 focus 표시. outline 제거 시 대체 표시 필수 |
| 읽기 본문 | 짧은 속성은 공통 읽기 전용 필드. 긴 원칙/기록 본문·안내·확인 설명은 텍스트/마크다운으로 표시. 모든 문장을 입력칸이나 중첩 카드로 만들지 않음 |
| 보조 안내 | 해당 입력 가까이, 짧은 문장. placeholder를 라벨 대신 사용하지 않음 |
| 오류 | 해당 필드/섹션 가까이, 공통 rounded-2xl 오류 박스 또는 필드 메시지. 오류 의미를 글자로 표시 |

글자·배경·테두리는 기존 CSS 색 변수와 어두운 테마를 쓴다. 입력은 PC/모바일 모두 타이포그래피 `input`, 도움말/오류는 `secondary`를 사용하고 글자를 줄여 공간 문제를 해결하지 않는다. 확인창의 대상·영향 설명은 `body`다.

### 3.1 같은 속성은 같은 필드로 표시한다

- `라벨 → 값 → 필요한 도움말/오류` 순서를 고정한다. 라벨은 14/20·600, 값은 16/24·400이며 입력과 읽기 전용의 글자 크기는 같다. 라벨과 필드는 8px, 필드 묶음 사이는 16px, 섹션 사이는 24px다. 실제 수치의 정본은 타이포그래피 가이드다.
- 편집 가능: 일반 input/select/textarea, 초점은 기존 accent 표시. 읽기 전용: 동일 테두리·높이·여백에 약간 구분되는 중립 배경과 오른쪽 작은 잠금 아이콘. 색상은 공통 스타일에서 한 번 정의하고 페이지별로 다르게 만들지 않는다. 값의 대비를 낮추거나 전체 opacity로 흐리게 하지 않는다.
- 변경 불가 scalar는 가능하면 실제 `readOnly` 텍스트 input을 사용해 선택·복사와 접근성 읽기 전용 상태를 제공한다. select에는 readOnly가 없으므로 고정된 선택값은 읽기 전용 텍스트 필드로 표시한다. 고정 날짜도 텍스트로 보여 달력 버튼이 나타나지 않게 한다. 잠금은 별도 클릭 대상이 아니며 중복 낭독을 피한다.
- 처리 중 `disabled`는 일시적 조작 차단이다. 영구 읽기 전용과 구별하며, 로딩/저장 중 잠금 아이콘이 새로 붙었다 사라지지 않는다. 읽기 전용 값은 dirty 계산·저장 payload에 추가하지 않는다.
- 라벨은 실제 control과 연결한다. 이유가 필요하면 해당 필드 또는 관련 묶음 아래 한 번만 짧게 설명하고 `aria-describedby`로 연결한다. 시세 두 필드에는 `시세는 ‘가격 갱신’으로 업데이트됩니다.` 하나로 충분하다.
- 티커·현재가·기준일·변경 불가 종류처럼 편집 폼 안의 고정 속성, 공유 상세의 짧은 속성이 대상이다. 마크다운 원칙/기록 본문, 도움말, 오류, 변경 비교 문장, 태그 칩·요일·체크박스, 표 편집의 조밀한 셀은 의미에 맞는 기존 표현을 유지한다. 불필요한 날짜/출처 필드를 새로 추가하지 않는다.
- PC 자산 상세는 `종목명 | 티커`, `통화 | 종류`, `현재가 | 기준일`의 같은 두 열이다. 모바일에서는 긴 종목명·티커는 전체 폭으로, 짧은 쌍은 충분히 읽힐 때만 두 열로 유지한다. 다른 모달도 제목·본문은 전체 폭, 짧고 관련된 값만 두 열이다. 긴 값/글자 확대 시 한 열로 바꾸며 글자를 줄여 맞추지 않는다.
- textarea도 동일 테두리·모서리·좌우 여백을 사용하되 내용에 맞는 높이를 유지한다. 태그는 라벨 아래 칩 목록 하나를 두며 테두리 입력칸 안에 다시 감싸지 않는다. 선택한 참조는 기존 검색/해제 의미를 유지한다.

태그 선택의 간격·상태 전환은 [태그 가이드](./tag-guidelines.md)의 고정 간격 규칙을 따른다. 라벨과 첫 칩 영역은 8px이며 선택 시 라벨 행에 개수/해제 버튼을 추가해 높이가 달라지면 안 된다. [#143](../tickets/ui-32-stable-tag-selection-spacing.md)은 실제 구현에서 발견한 간격 회귀의 후속 수정이다.

이미지는 배치와 시각 위계의 승인 예시다. 정확한 색상·크기·접근성·반응형 동작은 이 문서가 기준이다. 별도 범용 폼 엔진 없이 공통 필드 스타일과 필요한 얇은 라벨/읽기 전용 표현만 재사용한다. 자산과 계좌/활동에서 실제로 소비하며 키보드·저장 로직은 기존 기능에 남긴다. [모달 적용표](../tickets/ui-29-modal-field-consistency.md)의 모든 행을 적용/검증/의도적 예외로 기록해야 전수 완료다.

필수 입력은 바로 보이게 한다. 출처·부가 메모·태그 관리처럼 선택적인 세부 입력은 필요할 때 펼칠 수 있다. 값이 있으면 요약/개수로 알리고, 접어도 입력값을 지우지 않는다. 검증 오류가 생기면 해당 영역을 펼쳐 입력으로 안내한다. 태그의 종류 선택과 태그 사전 편집은 시각적으로 구분한다.

## 4. 액션

자산의 구체적인 적용은 [#120](../tickets/ui-13-asset-detail-inline-edit.md)을 따른다. 위 직접 편집·단일 저장 원칙은 모든 모달의 공통 규칙이며 아직 전수 구현 전이다.

- 저장·확정 같은 대표 쓰기 버튼은 footer 오른쪽의 accent 버튼 하나. 닫기/취소는 그 앞의 보조 버튼이다.
- 닫기는 현재 모달을 종료한다. 미저장 초안을 버리거나 계속 편집할 선택은 같은 shell의 확인으로 제공한다. 별도 읽기/편집 모드 전환 버튼을 기본 액션으로 만들지 않는다.
- 버튼은 최소 44px, rounded-2xl, 타이포그래피 `action`. 모바일 기본 액션 두 개는 같은 행의 충분한 폭으로, PC는 오른쪽 정렬한다.
- 삭제·반복 종료는 대표 저장과 구별된 위험/보조 영역에 둔다. 실행 전 확인과 영향 설명은 위 계층 2에 제공한다.
- 본문에는 조회·검색·선택 입력 등 보조 조작을 둔다. 현재 대상의 태그 선택은 일반 저장에 포함한다. 태그 사전 관리나 금융 미리보기→확정 등 다른 대상/행동은 같은 shell의 명확한 영역/단계에서 처리한다. 기존 API가 나뉘어 있다는 이유로 같은 대상의 속성 저장을 분리하지 않는다.

## 5. 입력 보호와 접근성

- 저장 중 중복 제출과 닫기를 막고 진행 상태를 표시한다. 실패하면 초안을 유지하고 같은 자리에서 재시도한다.
- X/닫기/Escape/브라우저 뒤로가기의 미저장 확인은 공통 계층 2 경로를 사용한다. 배경 클릭으로 초안을 잃지 않는다.
- label 연결, dialog 이름, Tab/Shift+Tab 순환, 호출 버튼으로 초점 복귀, background inert/스크롤 잠금을 유지한다. 접힌 입력은 키보드 탐색에서 제외한다.
- resize·회전으로 초안을 초기화하지 않는다. 긴 제목, URL, 오류는 줄바꿈하며 닫기 버튼을 밀거나 화면을 넘치지 않는다.

## 6. 적용과 유지 관리

새 모달과 수정한 모달은 이 가이드를 기준으로 리뷰한다. 의도적 예외는 관련 티켓에 용도·이유·검증 결과를 적는다. 일반적인 여백 변경마다 ADR을 만들지 않는다.

2026-09-25 현재 `ModalShell` 소비자는 자산 상세/로딩/오류(`AssetDetailModal`, `AssetsPage`), 계좌·종목·보유·태그 등록/수정(`EditorModals`), 태그 관리 탐색(`AssetViewToolbar`), 표 편집(`SpreadsheetEditor`), 활동 추가·기록/할 일 상세(`GeneralActionModal`, `ActivityDetailModal`, `GeneralTaskDetail`), 현재/과거 원칙(`PrincipleJournal`)이다. 증권사 확인 전용 `HoldingIntegrityModal`은 확인 상태와 함께 퇴역했다. 구 보유 메모 전용 `HoldingReasonModal`과 판단·점검 별도 상세/배분 설정 모달도 현재 진입 경로에서 제거됐다. 도달 불가능한 구 화면은 새로 활성화하지 않는다. 전수 판정과 미검증 상태는 [#123](../tickets/ui-16-modal-inline-edit.md)에 기록한다.

완료 보고에는 360/390/768/1024/1440px 중 확인한 폭과 빈값·긴값·오류·로딩·초안·선택 영역 상태, 키보드 및 저장/닫기 동작을 적는다. 모바일/PC 캡처로 참조 폼과 비교한다. 실기기 키보드·스크린리더 미검증은 따로 표시한다. 문서 작성과 실제 전체 적용 완료를 구분한다.
