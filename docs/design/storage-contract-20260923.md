# #86 최소 저장·API 계약

상태: 2026-09-23 로컬 구현 기준 계약. 운영 DB에는 적용하지 않았다.
근거: [전수 대조](./storage-inventory-20260923.md), [ADR-0008](../adr/0008-minimal-portfolio-storage.md).

## 기본값과 적용 순서

2026-09-23 최신 결정: 사용자는 기존 투자 데이터 전체 삭제를 허용했다. 아래 이관·기존 값 보존 조건은 이전 설계의 배경이며, 남은 구 저장소의 퇴역은 새 데이터의 기능·권한·계산 검증을 기준으로 한다. 인증·다중 사용자·새 공유 정책은 계속 필요하다. 운영 적용은 별도 릴리스 단계다.

초기 조사 당시 로컬 78개와 운영 62개 스키마가 달랐고, 운영에는 실제 계좌 7·보유 43건과 보정/검증 이력이 있었다. 이후 사용자가 해당 기존 투자 데이터 삭제를 허용했으므로 행 복사·과거 사실 대조는 필수가 아니다. 다만 새 구조는 증분 migration으로 적용하고, 현재 코드의 소비자·권한·금융 안전성을 검증한 다음 구 테이블과 함수를 종료한다. 운영 적용은 별도 게이트다.

## 활동

- 정본: 기존 `activity_events`. 실제 컬럼 `record_kind`는 `general | research | review | decision | retrospective | trade | reconciliation | task` 중 하나다. 수동 기록은 앞의 비금융 다섯 종류만 선택할 수 있고, 매매·보정·할 일 수행은 서버의 실제 동작으로만 분류한다. 기존 `action_type`에서 backfill한다.
- `context`는 작은 검증된 JSON 객체다. research에는 `sources` 배열(제목/URL/확인 시각), review에는 조사 범위/미확인과 결과, retrospective에는 기간/참조 ID를 둔다. 동일 내용의 별도 근거/보고서 레코드를 새로 만들지 않는다. 길이·배열 상한과 소유권/공유 응답을 검사한다.
- 일반 기록은 기존 제목/메모/결과/결론을 같은 행에서 편집한다. 수동 삭제는 성공 목록에서 제외하되 원본 금융 사실이나 완료 회차를 건드리지 않는다. 자동 금융 이벤트는 원본 수량/전후/참조를 수정·삭제할 수 없다.
- 최신 review는 사용자와 category, `occurred_at,id` 정렬로 조회한다. 미확인과 변화 없음은 별도 context 값이다. 뉴스 검색/의견 생성은 ChatGPT가 한다.

## 할 일

- 정본: `portfolio_tasks`. 할 일은 일반 과제 한 종류이며 열린 일과 완료/종료만 사용한다. 구 조사 상태와 수량 실행 계획 저장소는 퇴역했다.
- 매일 반복 완료는 해당 날짜의 활동을 남기고 다음 날 다시 열린다. 반복 전체 종료/삭제는 미래 회차 표시를 멈추지만 과거 완료 활동은 보존한다. 오늘 완료 해제는 해당 회차만 바꾸며 전체 반복을 재개하는 명령이 아니다.
- `general_task_occurrence_states`는 기존 동시 완료 방지에 필요하므로 이관 중 유지한다. 대체 알고리즘이 실제로 단순함을 증명한 뒤에만 제거한다.

## 원칙

- 한 `principles` 테이블에 변경마다 새 행. `id`는 행 ID, `principle_id`는 안정 식별자, `user_id`는 소유자. `kind`, `body`, 선택 `scope`, `effective_at`, `ended`를 둔다.
- 기본 편집·종료의 `effective_at`은 서버 현재시각. 사용자가 소급/예약 날짜를 입력하지 않는다. 같은 원칙의 변경을 잠금으로 직렬화하고 같은 시각이면 `id`로 안정 정렬한다. 현재/특정 날짜는 먼저 원칙별 마지막 행을 선택한 후 종료 상태를 적용한다. 날짜는 사용자 시간대의 하루 끝이다.
- 기존 개인 기준·운영 규칙·전략 상세 문구는 뜻과 공유 권한을 구별해 이관한다. 전략 버킷/모드 계산은 그대로 둔다. 과거 snapshot을 원칙 단위·시각에 확실히 대응시킬 수 없는 경우 추정 이력을 만들지 않고 내보내기로 보존한다.

## 자산

- `holdings`의 numeric 원가/수량과 state_version을 금융 변경의 기준으로 사용한다. 웹 표시용 real 컬럼만으로 연산하지 않는다. 매수/매도와 보정은 holdings+서버 생성 활동을 한 트랜잭션으로 쓴다. 초과 매도 금지, 수수료/세금 제외 이동평균, 매도 평균가 유지/전량 원가 0.
- 보유 이유는 holding 또는 instrument 행의 메모로 관리한다. 기존 공유 note에 비공개 이유를 조용히 합치지 않는다. 비공개 메모 칸 또는 공유 DTO 차단 중 기존 공유 동작을 가장 덜 바꾸는 작은 방법을 #89 첫 저장 테스트에서 확정한다.
- 잘못 입력한 체결은 사용자가 증권사 현재 수량/평균가를 확인해 절대 보정한다. 과거 재생·매매 되돌리기·저장 preview는 새 흐름에 없다. 과거일 체결은 현재 보유값에 반영하는 현재 기록으로 입력하되, 이후 매매를 재정렬/재계산하지 않는다. 이 의미를 입력 화면과 MCP에 설명한다.
- 금융 쓰기는 소유권/대상 잠금/현 상태 충돌 검사/요청별 멱등성과 원자성을 유지한다. 일반 메모는 선택 필드 patch로 단순화한다. 현금·평가형 자산에는 시장형 매매 계산을 적용하지 않는다.

## 이관과 공유

기존 원문·당시 판단·실행 사실은 추정으로 새 금융 사실로 만들지 않는다. 현재 자산값과 실제 활동은 전후 대조하고, 세부 수정 과정은 소유자별 내보내기와 접근 제한된 백업으로 보존한다. 친구/게스트 공개는 구 도메인별 기존 허용 범위를 합집합으로 확대하지 않는다. 소유자가 보던 내용은 이관 후에도 읽을 수 있어야 한다.

각 슬라이스 완료는 DB/API/MCP/앱 저장·재조회와 실패/권한/중복 회귀, 해당 구 쓰기 경로 종료 또는 명시한 전환 게이트를 포함한다. 구 테이블 최종 제거는 #91에서 소비자 확인 후 한다.
