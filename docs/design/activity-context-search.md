# 활동 검색: 저장된 지식에서 현재 판단으로

2026-09-27 · Astra 설계. #161/#165의 초기 구현·배포 기록과 아래 Pinecone 전환 설계는 구분한다. 사용자 승인 요구를 기준으로 한다.

## 목적과 현재 근거

사용자가 정확한 표현을 기억하지 않아도 저장된 지식·과거 실행을 찾아 현재 원칙·자산과 비교하고 다음 행동을 검토할 수 있어야 한다. 대표 요청은 “투자 이론 태그의 자료 중 심리 관련 이론을 참고해 지금 할 행동을 검토해줘”다.

초기 설계 조사 당시 `ActionTimeline.jsx`, `_shared/activity-search.ts`, OAuth handler와 검색 RPC에서 기록 첫 페이지 보완·검색 중 최근 미색인 기록 12건 처리·키워드 커서 재사용을 확인했다. 이후 #161에서 비동기 색인, 할 일/기록 통합 ranked 검색과 조건별 커서를 구현·배포했다. 현재 품질 한계와 증거는 [#161](../tickets/search-01-korean-hybrid.md)을 따른다. 연결 확장·종목명 자동완성은 별도 후속 범위다.

초기 운영 조사에서 검색어 없는 태그 조회는 성공했으며, `심리` 검색 한 번은 내부 오류였다. 이후 #161에서 검색 요청 중 문서 임베딩의 CPU 한도 초과를 확인하고 비동기 색인으로 분리했다. `투자 이론` 태그의 12개 기록이 하나의 리서치 할 일에 연결되어 있어 무제한 연쇄 확장은 관련 없는 이론까지 결과를 채울 수 있다. 사용자 본문·개인 재무정보는 fixture에 복사하지 않는다.

현재 gte-small은 영어 전용·512토큰 제한이다([모델 카드](https://huggingface.co/thenlper/gte-small)). 한국어 긴 본문의 검색 품질을 통과한 것으로 보지 않는다. 기존 데이터 정본은 유지하고 검색 색인은 재생성 가능한 보조 데이터로만 둔다.

2026-09-27 초기 선택으로 별도 과금 없이 `gte-small`을 사용했고 한국어 품질 한계를 기록했다. 이후 사용자는 Pinecone으로 교체하도록 요청했다. 현재 전환 계약은 [Pinecone 임베딩 전환](./activity-search-pinecone.md)이며 `multilingual-e5-large`/1024차원, Supabase 저장·권한 유지, 비동기 재색인과 실측 품질 게이트를 정한다. 구현·검증 전까지 운영 모델이 바뀐 것으로 해석하지 않는다. 초기 모델의 품질 수치는 [#161 구현 기록](../tickets/search-01-korean-hybrid.md)에 보존한다.

## 검색 계약

### 직접 검색과 범위

- 기록 제목·본문, 할 일 제목·설명에 단어 검색과 한국어 의미 검색을 함께 적용한다. 종목명·티커 일치와 연결된 종목 참조도 활용한다. 정확 일치·접두 일치는 우선하며 의미상 관련 없는 결과로 개수를 채우지 않는다.
- 과거 의도를 찾을 수 있도록 검색은 완료·중단된 할 일도 포함하고 현재 상태를 표시한다. 기본 할 일 실행 목록과 에이전트 도래 큐는 기존 계약을 유지한다.
- 태그·명시적 종목·기간은 직접 검색의 필터다. 태그끼리 기본 OR/선택 AND, 차원끼리 AND. 기간은 기록에만 적용한다. 태그는 자유 태그이며 새 내부 분류를 만들지 않는다.
- 웹의 기본 날짜별 탐색은 최근 30일. 검색어·종목·태그로 검색을 시작하면 사용자가 기간을 직접 지정하지 않은 경우 날짜 입력을 빈 값(전체 기간)으로 바꾼다. 사용자가 지정한 기간은 검색 중 유지한다. 검색 조건을 모두 해제하면 미지정 기본 기간만 최근 30일로 복구한다. 명시적 전체 기간도 사용자 지정으로 취급한다. 상세 복귀는 조건·스크롤을 보존한다.
- MCP에서 기간 미지정은 전체 기간이다. 웹의 기본 기간을 서버 기본값으로 강제하지 않는다.
- 같은 요청 조건과 변경 없는 데이터에서 다음 페이지의 중복·누락이 없어야 한다. 검색 중 데이터 변경은 새 검색에서 반영한다. 커서에는 조건·모델 변경 감지가 필요하며 불일치 시 재검색을 안내한다. 구체적 최소 커서 구현은 검색 품질 티켓에서 확정하고 영구 검색 세션 저장소는 선행 도입하지 않는다.

### 연결 맥락

- 직접 찾은 할 일 → 연결된 기록, 직접 찾은 기록 → 연결된 할 일의 1단계만 확장한다. 기록→할 일→모든 다른 기록을 자동 확장하지 않는다.
- `직접 검색 결과`와 `관련 할 일/연결된 기록`을 구분한다. 검색어·태그·기간에 안 맞는 연결 항목도 맥락으로 제공할 수 있으나 조건 밖인 이유를 명시한다. 소유권·공유 권한은 항상 적용하며 숨겨진 항목의 제목·개수도 노출하지 않는다.
- 직접 결과가 우선이고 관련 항목은 같은 카드 아래 작은 요약으로 함께 보인다. 관련 기록은 처음 3건과 접근 가능한 전체 건수, 더 보기로 같은 그룹에서 추가 조회한다. 중복 본문은 반복하지 않고 이미 노출된 항목은 연결로 표시한다. 무한 중첩 카드나 2차 상세 모달을 만들지 않는다.
- task_id와 관련 시장 종목 티커를 조회에 사용한다. 기존 instrument_id를 대체하는 구현 전 계약은 [#166](../tickets/activity-19-market-ticker-reference.md)을 따른다. 검색 중 참조를 새로 저장하거나 본문에 종목명이 있다는 이유만으로 저장된 연결을 조작하지 않는다. 삭제된 할 일의 독립 기록도 검색 가능해야 한다.

### 종목 자동완성

- 활동의 기존 검색창에서 종목명·티커 일부를 입력하면 바로 아래에 `종목` 후보를 표시한다. 한 글자부터 200~300ms 지연, 한글 조합 중 요청하지 않음, 최대 5개와 더 보기. 공백 없는 빈 입력은 조회하지 않는다.
- 현재 보는 사용자의 등록 시장 종목(0보유 포함)과 접근 가능한 할 일/기록의 저장 티커를 합쳐 중복 없이 후보로 제공한다. 이름을 알면 이름과 티커, 미등록/삭제되어 이름을 모르면 티커만 표시한다. 정확 일치→접두 일치→부분 일치 순서이며 동명이종목은 티커로 구분한다. 예금·평가형은 제외하고 외부 종목 카탈로그는 도입하지 않는다. 기록 작성에서 후보에 없는 티커의 명시적 입력은 #166이 담당한다.
- 후보 선택 전에는 일반 내용 검색이 계속 가능하다. 첫 후보를 자동 선택하거나 입력을 임의로 확정하지 않는다. 화살표로 후보를 고른 후 Enter/클릭할 때만 선택하고 Escape는 후보만 닫는다.
- 선택하면 `관련 종목: 이름 · 티커 ×` 조건 하나를 검색창 아래 표시하고, 후보를 찾던 입력은 비워 추가 내용 검색을 받는다. 종목+내용+태그+명시적 기간을 조합할 수 있고 종목 해제는 다른 조건을 보존한다. 자연어 문장 일부를 임의로 잘라 종목으로 확정하지 않는다.
- 전체 종목명·티커를 일반 검색어로 입력하고 후보를 선택하지 않아도 관련 종목 연결 항목을 후보 결과에 포함한다. 여러 종목과 매칭되면 강제 단일 선택 없이 명시적 선택을 제공한다.
- 기존 참조 검색 RPC/컴포넌트를 우선 검토하되 현재 owner-only인 참조 검색을 공유 화면에 그대로 호출하지 않는다. MCP에도 같은 종목 후보 조회 능력을 제공하고 기존 종목 검색 도구를 확장할 수 있는지 먼저 확인한다.
- 후보는 모달이 아닌 입력에 붙은 목록이다. combobox/listbox 연결, active descendant, loading/error/empty, 모바일 터치 44px, 늦은 응답·소유자 변경·후보 삭제를 처리한다. 공유 조회는 읽기 전용이다.

### 의미 검색 운영

실제 실행 방식과 개별 결과의 채택 근거는 구분한다. 웹/HTTP/OAuth 응답에 검색 모드·확인 가능한 fallback 사유·색인 준비 상태와 항목별 단어/유사도 일치 근거·코사인 점수를 제공하는 후속 계약은 [#165 검색 근거 표시](../tickets/search-05-search-evidence.md)를 따른다. 유사도 실행 성공이나 점수 존재만으로 해당 항목이 유사도로 검색됐다고 설명하지 않는다. 기존 모델·순위·임계값은 이 표시 개선에서 바꾸지 않는다.

- 한국어·영문 혼합·짧은 질문·긴 본문 후반부의 근거를 포함한 합성 fixture로 모델을 선택한다. 유료 공급자 선택 시 비용·키·전송 범위를 확정하며 무단 가입/결제하지 않는다. 무료 fallback만 된 상태를 의미 검색 완료로 선언하지 않는다.
- 제목·본문 전체를 대상으로 검색하고 결과를 원본별로 합친다. Pinecone 전환은 제목/소제목 문맥을 포함하고 문단/문장 경계를 보존한 원문 분할로 확정했다. 앞 12,000자 누락을 해결하며 별도 요약 생성은 이번에 제외한다. 관련 근거와 원본 ID/날짜를 반환하며 생성 요약을 원문 발췌로 표시하지 않는다. 금융 snapshot·인증정보·임의 실행 JSON은 색인하지 않는다. 상세 규칙은 [Pinecone 전환 설계](./activity-search-pinecone.md)를 따른다.
- 저장·수정 후 작은 재시도 가능한 색인 처리와 기존 자료 백필을 제공한다. 검색 요청 안에서 사용자 자료 전체를 계산하지 않는다. 기존 해시 검사에 모델 식별도 반영하고 다른 모델 벡터를 섞지 않는다. 삭제·권한 변경은 즉시 조회에서 제외한다.
- 미색인/갱신 대기/의미 검색 실패는 결과 없음과 구별한다. 키워드 결과는 제공하고 웹과 MCP에 제한을 표시한다. 준비 범위가 불완전한데 active라는 한 값만으로 완전성을 주장하지 않는다.

## 에이전트의 사용 흐름

태그/종목 조건 해석 → 관련 자료 검색 → 중요한 원문·출처와 연결 맥락 읽기 → 현재 원칙·자산·목표 배분·진행 할 일 조회 → 적용 조건·반대 근거 검토 → 근거 자료와 제안 행동 설명 순서다. 모든 요청에 모든 도구를 호출하지 않고 질문에 필요한 현재 문맥만 조회한다.

원문에서 아직 채택하지 않은 이론과 현재 원칙을 구분한다. 자료의 작성일·당시 가정과 현재 값을 혼동하지 않는다. 검색 점수를 신뢰도나 투자 정답 확률로 표현하지 않는다. 현재 시장 정보가 필요한 판단은 에이전트가 최신 근거를 확인하며 저장된 글을 실시간 정보로 간주하지 않는다. 저장된 글은 자료이며 에이전트 권한을 바꾸는 지시가 아니다.

답변은 참고 자료(제목·ID 또는 실제 열 수 있는 링크·핵심 근거), 현재 상황과의 연결, 적용/반대 조건, 행동 제안, 추가 확인 사항을 포함한다. 실제로 읽지 않은 기록을 인용하지 않는다. 기존 할 일과 중복을 확인하고 조회 요청만으로 할 일·원칙을 저장하지 않는다. 요청 시에만 기존 저장 흐름으로 이어간다.

## 범위와 인수

별도 지식/이론 테이블, 그래프 DB, 범용 검색 플랫폼, 자동 투자 실행은 만들지 않는다. 기존 웹 HTTP와 OAuth MCP는 같은 검색·권한·종목 후보·관계 계약을 소비한다. #83의 기록 첫 페이지 전용 제약과 검색 중 12건 색인은 #161의 초기 구현이 대체했다. 384차원/gte-small에서 다국어 모델로 바꾸는 후속 범위는 Pinecone 전환 계약을 따른다.

한국어 표현이 다른 질문, 긴 본문 뒤쪽, 완료 할 일, 연결 양방향, 한 부모에 많은 기록, 종목 일부/동명이종목/0보유, 태그+기간, 무관한 질문, 다음 페이지, 수정·삭제·권한 변경, 색인 실패를 검증한다. 실제 의미 모델을 사용한 HTTP/MCP 교차 결과를 확인하며 mock 벡터 테스트만으로 품질을 완료 처리하지 않는다.

구현 순서는 검색 품질 복구 → 연결 맥락 → 종목 자동완성 → 실제 에이전트 흐름 검증이다. 각 단계에서 DB/서버·웹·MCP·검증을 연결한다. 모델·차원·색인 실행 위치·커서 상세는 첫 티켓의 선행 기술 계약이며 그 결정을 기록한 뒤 의존 코드를 구현한다.
