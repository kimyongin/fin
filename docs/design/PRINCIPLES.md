# Portfolio 디자인 원칙

상태: 사용자와 합의한 설계 기준 · 구조 일관성 계약 추가 2026-09-21

## 제품과 화면의 역할

활동 분류의 최신 후속 설계는 [#122](../tickets/activity-15-tags-and-references.md)다. 활동 종류를 제거하고 하나의 태그 입력/표시/검색으로 통합한다. 활동 종류별 필터 대신 태그를 사용한다. 적용/검증 근거는 해당 티켓을 따른다.

ChatGPT는 조사하고 생각하고 설명한다. Portfolio는 기억하고 계산하고 검증한다.
앱은 출근길에 지난 점검 이후의 변화, 현재 자산 배분, 다음 확인할 일을 쉽게 파악하게 한다.
새 분석은 사용자가 요청할 때 생성한다. 앱을 여는 것만으로 분석을 실행하지 않는다.

기존 핵심인 여러 계좌의 종목 관리, 카테고리·태그, 현재/목표 비중 비교를 유지한다.
유지는 화면을 그대로 고정한다는 뜻이 아니다. 기능별 유지·재구성·신규·보조 이동과 책임은 [제품 재정리](./product-reorganization.md)를 따른다. 기존 어두운 테마와 공통 컴포넌트로 새 화면을 통합한다.
투자 원칙 → 판단 기록 → 실행·점검할 일 → 실제 체결을 연결하되, 결정이나 계획을 체결로 취급하지 않는다.

## 1. 모바일 우선, PC에서도 완전한 기능

- 모바일에서 자주 읽고 짧게 입력하는 흐름을 먼저 설계한다. PC에서는 비교와 대량 편집의 효율을 높인다.
- 모바일의 기능을 삭제하지 않는다. 표를 카드로 바꾸거나 상세 단계로 이동시킨다.
- 화면 너비에 따라 레이아웃을 전환한다. 기기 종류로 기능을 제한하지 않는다.
- 현재 구현 기준: 자산/배분/활동/원칙 네 주 메뉴는 모바일과 데스크톱 모두 화면 하단에 고정한다. 배분은 자산을 거치지 않고 바로 연다. 화면 폭에 따라 탐색 위치를 바꾸지 않아 시선과 조작 위치를 일관되게 유지한다. 긴 조회 전용 상세는 1024px 이상 오른쪽 modal drawer를 사용할 수 있다. 활동·할 일·공유 점검 상세는 편집 왕복의 일관성을 위해 기본 모달로 통일한다(640px 미만 전체 화면, 이상 중앙 모달). 예외와 검증은 screen-structure.md에 기록한다.

## 2. 결론 먼저, 상세는 필요할 때

- 자산을 기본 화면으로 열어 현재 보유를 확인한다. 지난 점검의 시각·조사 상태·결론은 활동의 점검 이력에서 찾는다.
- 자산은 보유 목록을 기본으로 보여준다. 계좌 선택과 종목 검색 후 상세에서 보유를 수정하고, 태그별 구성·목표 비교와 표 편집은 별도 진입으로 제공한다. 여러 계좌·태그 비중·PC 대량 편집 능력은 유지한다.
- 긴 분석과 이력은 상세에서 읽는다. 기존 수량·평균가·현재가 비교를 일괄 숨기지 않고 실제 과밀·넘침이 있는 부분만 개선한다.

## 3. 작은 화면에서는 표를 축소하지 않는다

배분 계약 [#121](../tickets/ui-14-tag-allocation.md)은 아래 버킷별 목표 구분 규칙을 대체한다. 태그별 현재/목표/차이를 같은 목록에 두고 작은 화면에서는 태그별 두 줄, 넓은 화면에서는 열 정렬로 표시한다. 버킷/모드는 사용하지 않는다. 검증 범위는 해당 티켓에 기록한다.

- 일반 조회는 화면 폭 안의 요약 행이나 카드로 제공한다. 글자를 작게 줄여 데스크톱 표를 밀어 넣지 않는다.
- 배분 점검은 자산 태그별 현재 비중·목표·차이(%p)를 같은 목록에 표시한다.
- 가로 스크롤은 표 편집처럼 열 비교가 필수인 명시적 편집 모드에서만 허용하고 안내한다. 스크롤은 표 내부에 한정한다.
- PC에서는 같은 데이터를 표로 비교할 수 있다. 휴대폰에서도 수량·평균가 수정에 도달할 수 있어야 한다.

## 4. 한 화면의 대표 행동은 하나

- 자산: 종목 등록과 상세의 보유 편집을 구분한다. 활동: 할 일과 기록을 함께 보여주고 점검 이력은 태그로 찾는다. 상세 화면: 그 대상의 주된 행동 하나.
- 같은 강조색 버튼을 반복하지 않는다. 조회·설정·필터는 보조 행동으로 구분한다.
- 첫 분석 요청 안내와 문구 복사는 연결 가이드에서 제공한다. 자동 전송·자동 생성처럼 보이게 하지 않는다.
- 입력 전후 미리보기와 실제 저장을 구분한다. 긴 설정을 첫 점검의 필수 과정으로 만들지 않는다.

## 5. 숫자와 상태의 의미를 숨기지 않는다

- 분석 작성일, 조사 범위, 시세 시점은 서로 다른 정보다. 별도의 잔고 확인 상태나 날짜는 유지하지 않는다.
- 최근 저장 결과를 오늘의 실시간 분석처럼 표시하지 않는다. 자료 부족, 부분 조사, 분석 없음, 확인한 범위 내 변화 없음을 구별한다.
- ChatGPT 제안과 사용자가 채택한 판단은 텍스트로 표시한다. 색만으로 상태나 수익/손실을 구분하지 않는다.
- 평가금액은 기록과 시세에 따른 추정치다. 증권사 총자산과 완전히 일치한다고 표현하지 않는다.
- 배분의 분모를 명시한다. 보유 목록 필터를 바꿔도 전체 비중의 분모를 몰래 바꾸지 않는다.
- 자산 태그별 목표를 직접 저장하고 미분류 자산과 누락 시세·환율의 처리 기준을 표시한다. 활동 분류 태그와 자산 배분 태그는 다른 개념이다.

## 6. 누르기 쉽고 돌아오기 쉽다

- 버튼·필터·접기/펼치기 등 조작 영역은 최소 44×44 CSS px. 아이콘 버튼에는 이해 가능한 접근성 이름을 붙인다.
- 글자 역할은 [타이포그래피 가이드](./typography-guidelines.md)를 따른다. 본문·입력·주요 이름/수치는 16px, 라벨·조작·보조 설명은 14px, 코드·시각 등 메타 정보는 12px다. 제목·굵기·줄간격·예외도 같은 가이드에서 관리하며 PC/모바일에 같은 역할 크기를 적용한다. 숫자는 자리 정렬과 단위를 유지한다. 전 영역 적용은 [구현 티켓](../tickets/ui-24-typography-consistency.md)에서 관리한다.
- 하단 메뉴와 고정 버튼은 본문 및 안전 영역을 가리지 않는다.
- 상세 닫기 시 필터·목록 위치를 보존한다. 중첩 상세는 이전 상세로 돌아갈 수 있게 한다.
- 키보드 포커스를 표시하고, 대화상자에서 포커스를 유지하며, 닫으면 적절한 시작점으로 복귀한다. hover만으로 제공하는 기능은 두지 않는다.
- 일반 텍스트 대비 4.5:1, 큰 글자 및 조작요소 경계/포커스 대비 3:1을 검수 목표로 삼는다.

## 7. 페이지와 오버레이의 구조

탐색 기준은 [#137](../tickets/ui-26-footer-profile-navigation.md)이다. 상단 앱 헤더를 제거하고 하단의 아이콘 전용 프로필 전환·네 탭·메뉴로 통합한다. 현재 대상 이름은 프로필 목록에서 확인하고, 공유 화면은 최상단 카드에 읽기 전용 상태를 표시한다. 최상단 카드는 짧은 문맥과 기능을 함께 제공한다. 아래 헤더 관련 기존 규칙보다 이 구현이 우선한다.

상단 카드·문맥·행동·필터의 배치는 [페이지 상단 카드 가이드](./page-panel-guidelines.md)를 정본으로 한다. 자산 필터도 요약과 같은 카드 안에 배치한다. 자산 조회 결과 평가액은 목록 조건과 일치시키며 배분의 전체 계좌 분모는 유지한다. 적용·검증 상태는 [적용 티켓](../tickets/ui-25-page-panels-and-asset-filters.md)에서 확인한다.

태그 표현은 [태그 디자인 가이드](./tag-guidelines.md)를 따른다. 선택·검색·관리는 고정 곡률의 칩, 배분의 주된 대상은 제목, 자산 목록의 부가 정보는 보조 텍스트로 구분한다. #129/#130은 #128의 일괄 읽기 칩 요구를 이 범위에서 대체한다.

상세 모달은 편집 가능한 현재 대상의 속성을 바로 수정하고 하단 저장 하나로 반영한다. 별도 편집 모드/속성 모달 왕복은 기본 동선으로 두지 않는다. 읽기 전용 권한/과거 이력과 별도 업무 행동은 모달 가이드에 따라 구분한다. 전체 적용은 #123에서 관리한다.

시간순 기록의 공통 기준은 [타임라인 디자인 가이드](./timeline-guidelines.md)다. 활동/원칙 적용은 #119에서 관리하며 날짜 그룹·항목 표현은 공통화하고 각 기록의 의미는 유지한다. 공통 Timeline을 사용하며 실제 검증 범위는 해당 티켓을 따른다.

모든 모달의 상세 규칙은 [모달 디자인 가이드](./modal-guidelines.md)를 따른다. 계좌·보유 추가 폼이 시각적 참조이며, 아래 과거의 일괄 드로어 표현보다 가이드의 용도별 규칙이 우선한다.

구현할 상세 계약은 [화면 구조 규칙](./screen-structure.md)을 따른다. 같은 역할의 제목·보기 전환·필터·결과·편집 액션은 같은 위치와 동작을 사용한다. 자산 비교, 활동·점검 기록, 원칙 설정은 각자의 정보 구조를 유지한다.

- 페이지 시작·하단 탐색 여백은 공통 레이아웃 한 곳에서 관리한다. 반복적인 소개 카드가 목록과 필터를 아래로 밀어내지 않게 한다.
- 보기 전환 → 필터·검색 → 결과 순서를 따른다. 페이지 대표 행동과 개별 항목 행동을 구분한다.
- 조회 화면에 형식적인 푸터를 만들지 않는다. 편집 화면은 스크롤 본문과 하단 저장·취소 영역을 분리한다.
- 일반 편집 상세는 640px 미만 전체 화면·넓은 화면 중앙 모달이다. 긴 조회 전용 상세의 드로어 예외와 짧은 확인창은 모달 가이드를 따른다. 공통 초점·닫기·스크롤 규칙을 공유한다.
- 표 편집 전체 화면은 헤더·표 본문·저장 영역을 함께 포함한다. 기존 비교·붙여넣기·필터·롤백 기능을 유지한다.

## 개발 완료 체크리스트

- [ ] 360 / 390 / 768 / 1024 / 1440px에서 관련 화면을 검토했다.
- [ ] 일반 조회와 상세에서 페이지/표 가로 넘침이 없다. 표 편집 예외는 표 안에서만 스크롤된다.
- [ ] 같은 역할의 글자 크기·굵기·줄간격이 타이포그래피 가이드와 일치하고, 입력·버튼 상속 및 200% 확대의 가독성을 확인했다.
- [ ] 화면 목적에 맞는 현재 값·기록 시점·조회 범위를 알 수 있고, 전체 편집 표가 기본 조회를 대신하지 않는다.
- [ ] 여러 계좌, 카테고리/목표/차이, 계좌별·종목별 조회와 편집 진입이 유지된다.
- [ ] 필터 후 상세 열기/닫기, 확인 취소 후 초안 복귀, 모바일 메뉴와 PC 메뉴를 점검했다.
- [ ] 분석 없음 / 자료 부족 / 변화 없음 / 긴 이름 / 빈 필터 / 값 0의 상태를 점검했다.
- [ ] 대표 행동과 상태 의미가 명확하고, 클릭·키보드·초점·조작 크기·색 대비를 점검했다.
- [ ] 실제 연결이 없는 시안 동작, 미구현 기능 및 미검증 항목을 명시했다.

## 문서 운영

이 문서가 공통 기준이다. `AGENTS.md`는 화면 작업 전 이 문서를 읽도록 연결한다.
현재 정보 구조는 `product-reorganization.md`를 따른다. `portfolio-v2.md`와 prototype v1~v3는 과거 검토 자료이며 v3의 자산 전면 재설계는 채택하지 않는다. 다음 시안은 실제 React 구조를 바탕으로 별도 검증한다.
티켓에는 위 체크리스트 중 해당하는 수용 조건과 예외를 적고, PR에는 실제 검증 결과를 남긴다.
제품 책임이나 데이터 의미가 바뀌면 PRD/ADR을 함께 갱신한다. 모든 간격·색상 조정을 ADR로 만들 필요는 없다.
