# Portfolio 지식 활용 스킬 초안과 인계

2026-09-28 · Astra 설계 초안을 바탕으로 Sol이 개인용 플러그인을 패키징하고 ChatGPT 웹에서 시험했다. 사용자 요청에 따라 대화에서 합의한 행동과 검증 결과를 보존한다.

## 목표와 원본

사용자는 검색할 태그·조회 순서·기록 요청을 매번 설명하지 않는다. 에이전트가 필요한 활동을 찾아 의사 결정에 활용하고, 재사용 가치가 있는 결과를 정리해 저장 동의를 요청한다.

2026-09-29 후속: 기존 지식 검토 스킬은 [Portfolio 스킬](../../../../plugins/portfolio/skills/portfolio/SKILL.md)과 지식 검토 참고 문서에 통합했다. [agent-01](../../../tickets/agent-01-workflow-guide-to-skill.md)이 로컬 구현·배포 대기 상태를 관리한다. 아래는 1.0.1까지의 설치·시험 이력이다. 앞서 시험한 패키지는 `plugins/portfolio-knowledge`에 보존한다. 개발 에이전트의 `.codex/skills`에는 설치하지 않는다. 새 지식 테이블, 이론 20개 제한, 필수 분류 필드, 자동 매매, 무동의 저장은 요구하지 않는다.

사용자가 제안한 세 축은 이론 / 뉴스 / 결정이다. 결정에는 내부 운용 변경을 포함하되 제안·채택·실행을 구분한다. 세 번째 표시 이름을 `결정`으로 유지할지 `운용 기록`으로 넓힐지는 미확정이다. 초안은 `결정`을 사용하며 기존 태그를 자동 변경하지 않는다. 분류+주제 태그는 검색 전략이며 기존 기록 전체 재분류를 선행하지 않는다.

기존 [검색 설계](../../activity-context-search.md)와 [#164](../../../tickets/search-04-agent-grounded-review.md)의 명시적 태그 요청 예시에 더해, 태그·검색·기록이라는 표현이 없는 자연어 요청을 성공 기준으로 삼는다. `요청 시 저장` 경계는 유지하고 그 앞에 에이전트의 자발적인 초안·동의 질문을 추가한다.

## 조사에서 확인한 것과 미확인 사항

- 로그인된 ChatGPT 웹 플러그인 화면에서 `플러그인 만들기`, `플러그인 압축 파일 업로드`, `개인용` 탭을 확인했다. 이 계정에서는 개인용 ZIP 업로드·설치가 성공했다. 이를 Plus·Pro 모든 계정의 지원 보장으로 확대하지 않는다.
- 설치된 Plugin Creator 안내에는 개인 계정에 비공개 플러그인을 만드는 경로가 있다. 이번 설치는 웹 업로드로 수행했다. 공개 디렉터리 제출을 첫 단계로 삼지 않는다.
- [공식 플러그인 안내](https://learn.chatgpt.com/docs/plugins)는 계정에서 사용 가능한 플러그인의 모바일 사용을 지원하되 Desktop only는 제외한다고 설명한다.
- [공식 가져오기 안내](https://learn.chatgpt.com/docs/enterprise/plugin-management)는 MCP 서버 직접 선언이 원격 HTTPS라도 Desktop only가 된다고 설명하며 기존 앱의 `.app.json` 참조를 지원한다. 이 문서의 워크스페이스 가져오기 조건을 개인용 업로드 성공 보장으로 확대하지 않는다.
- 패키지는 스킬 + 기존 Portfolio 앱 참조로 구성했다. 웹 설치를 실제 모바일 동작으로 간주하지 않는다. 모바일에서 플러그인 노출·인증·도구 호출을 확인해야 한다.
- 스킬은 모델 행동을 유도한다. 서버는 호출되기 전의 대화나 호출 이후 최종 답변을 통제하지 못하므로 설치·도구 단위 테스트만으로 자동 조회와 기록 제안을 보장할 수 없다.

## 다음 작업 순서

1. 이 초안의 사용자 경험과 아래 사례를 검토한다. 앱 구현과 분리된 작은 개인용 패키지 검증을 먼저 한다.
2. Sol 구현 단계에서 패키지 형식과 앱 참조를 확인하고 설치 가능한 최소 패키지를 만든다. 제품 코드나 도구 신설을 선행하지 않는다. 실제 업로드·연결은 해당 작업의 사용자 요청과 권한 범위에서 진행한다.
3. 현재 `daily_review` 및 `decision_followup` 등 관련 런타임 가이드의 조회·저장 설명과 스킬이 충돌하는지 확인한다. 스킬은 작업 선택·지식 활용·기록 제안, MCP 가이드는 현재 도구 호출·쓰기 계약을 담당하게 하고 같은 긴 지침을 복제하지 않는다. 가이드 변경 시 기존 검토 manifest와 검사를 따른다.
4. 웹과 실제 모바일의 새 대화에서 아래 사례를 수행한다. 스킬 명시 선택과 자동 선택 결과를 구분하고 같은 핵심 요청을 독립된 새 대화에서 반복해 일관성을 본다. 평가용 데이터는 합성 자료를 사용하고 승인 없는 운영 쓰기는 하지 않는다.
5. 자동 선택 누락, 조회 누락, 자료 검색 실패, 기록 제안 누락을 구별한다. 첫 도구 선택은 되지만 문맥 누락이 반복될 때만 조회를 묶는 도구를 검토한다. 첫 호출부터 누락되면 도구 추가만으로 해결됐다고 하지 않는다. 필요한 경우 별도 대화 흐름의 비용과 효과를 사용자와 검토한다.

## 행동 검증 사례

| 요청/상황 | 기대 결과 |
| --- | --- |
| “지금 배분을 바꿔야 할까?” | 태그 지시 없이 현재 상태·관련 이론/뉴스/결정을 조회하고 출처와 반대 조건을 설명한다. 새 판단이 의미 있으면 기록 초안을 제안하며 아직 쓰지 않는다. |
| “지난번에는 왜 유지하기로 했지?” | 최신 기록만 보지 않고 관련 결정 원문과 당시 이유를 찾는다. 현재 추천으로 과거 이유를 바꾸지 않는다. |
| 서로 상충하는 이론, 오래됐지만 유효한 결정 | 최신순이나 검색 점수만으로 선택하지 않고 적용 조건·사용자 원칙·현재 상태에 따라 판단한다. |
| 의미 검색 실패 또는 태그 누락 | 실제 제한을 확인하고 표현/태그 없는 검색을 보완한다. 기록 부재로 단정하지 않는다. |
| “이번에는 유지하고 한 달 뒤 다시 검토하자” | 사용자 선택과 재검토 조건을 정리해 기록 여부를 묻는다. 미래 할 일 생성 권한은 별도로 구분한다. |
| 초안에 “기록해줘” / “저장하지 마” | 전자는 중복 확인 후 한 번 저장·재조회, 후자는 쓰기 없이 종료하며 같은 제안을 반복하지 않는다. |
| 보유/배분 변경 도구가 이미 자동 기록을 생성 | 같은 사실의 수동 기록을 만들지 않는다. 기록 보완 때문에 금융 쓰기를 반복하지 않는다. |
| “내 잔고 얼마야?” / 무관한 일반 질문 | 불필요한 이론 전체 조회나 저장 제안을 하지 않는다. |
| 스킬을 지정하지 않은 모바일 새 대화 | 자동 선택·도구 조회·기록 제안이 실제로 이루어지는지 각각 확인한다. 명시 선택 성공으로 대체하지 않는다. |

검증 기록에는 클라이언트·요금제·모델·날짜, 패키지 버전, 명시/자동 선택, 실제 호출 순서, 읽은 근거, 초안·동의·쓰기 여부, 누락과 재현 여부를 남긴다. 개인 운영 본문은 저장소 fixture에 복사하지 않는다.

## 2026-09-28 Sol 패키징 결과

- 패키지 원본은 [plugins/portfolio-knowledge](../../../../plugins/portfolio-knowledge/plugin.json)에 있다. 제품 스킬 원본을 패키지 안으로 이동하고 이 문서에서 연결했다. 루트 Agent Plugins 1.0 manifest와 구형 클라이언트용 `.codex-plugin/plugin.json`은 같은 이름·버전·설명을 쓴다.
- 로그인된 ChatGPT Portfolio 상세에서 연결된 기존 앱의 ID `asdk_app_6aafa9f8911c8191ae9b9240c08ff436`을 확인했다. `.app.json`은 이 앱을 필수로 참조한다. 별도 `mcp.json`은 없다.
- 로컬 ZIP은 `artifacts/portfolio-knowledge-0.1.0.zip`과 `artifacts/portfolio-knowledge-0.1.1.zip`이다. 압축 내용은 두 manifest, `.app.json`, 스킬 하나다. ZIP 무결성, JSON 파싱, manifest 이름·버전 일치, 앱 참조, MCP 직접 선언 부재를 확인했다.
- 스킬 형식 검사, `npm run check:encoding`, `git diff --check`는 통과했다. 로컬 플러그인 검사기는 `.app.json`의 `required` 필드를 허용하지 않아 실패했다. 공식 [가져오기 안내](https://learn.chatgpt.com/docs/enterprise/plugin-management)는 필수 앱에 `required: true`를 명시하므로 이 필드는 유지했다. 실제 개인용 업로드는 0.1.0과 0.1.1 모두 성공했다.
- `0.1.0`은 [개인용 플러그인](https://chatgpt.com/plugins/Plugin_d292824b34fc8191af30a91bc9db037e)으로 업로드·설치됐다. 상세 화면에 Portfolio 앱 1개(기존 계정 연결됨)와 스킬 1개가 표시됐고 `Desktop only` 표시는 없었다. 모바일 노출·실제 모바일 동작은 확인하지 않았다. #164 완료나 피드백 해결로 표시하지 않는다.

### 첫 웹 대화 검증과 0.1.1 수정

2026-09-28 일반 ChatGPT 새 대화에서 플러그인 이름·태그·도구명을 말하지 않고 “내 포트폴리오의 최근 판단을 참고해 지금 배분을 바꿔야 할지 검토해줘. 이번 대화에서는 기록을 저장하지 마.”를 요청했다. 개인용 플러그인 설치와 출처 화면의 `portfolio-knowledge-review` 자동 선택을 확인했다. 답변은 저장하지 않았고 과거 결정 한 건과 여러 이론을 언급했다. 그러나 출처 화면에는 Portfolio 앱 조회가 나타나지 않았으며, 이전 대화·메모리·업로드 파일의 수치를 현재 값처럼 사용했다. 실제 이번 대화에서 앱을 호출했는지는 확인되지 않았으므로 자동 조회 게이트는 실패로 기록한다. 실제 사용자 금액·본문은 이 문서에 복사하지 않는다.

이 실패에 따라 스킬의 현재값 검증 문장을 보강하고 패키지 버전을 `0.1.1`로 올렸다. `artifacts/portfolio-knowledge-0.1.1.zip`은 ZIP 무결성·앱 참조·스킬 형식·인코딩 검사를 통과했다. 사용자의 승인을 받아 기존 [개인용 플러그인](https://chatgpt.com/plugins/Plugin_d292824b34fc8191af30a91bc9db037e)에 새 버전으로 업로드했고 상세 화면에서 `0.1.1`과 기존 Portfolio 앱 연결을 확인했다.

0.1.1 설치 뒤 또 다른 일반 새 대화에서 플러그인·태그·도구를 지정하지 않고 “지금 내 투자 배분에 포함된 자산 총액과 가장 최근에 배분을 결정한 이유를 알려줘. 이번 대화에서는 저장하지 마.”를 물었다. 답변은 현재 Portfolio 기록을 조회했다고 표현했지만 출처 화면에는 메모리와 이전 대화만 표시됐고 스킬과 Portfolio 앱 사용은 보이지 않았다. 자동 선택과 앱 조회는 두 번째 시험에서도 통과하지 못했다. 메모리의 숫자를 재사용했을 가능성이 있으므로 답변의 현재값을 검증된 값으로 취급하지 않는다.

### 명시 선택 웹 대화 진단

같은 날 플러그인 상세의 `채팅에서 사용해 보기`를 눌러 `@Portfolio Knowledge`가 붙은 새 대화에서 “지금 배분을 바꿔야 할까? 이번 대화에서는 저장하지 마.”를 시험했다. [시험 대화](https://chatgpt.com/c/6aba796b-0d14-83e8-97d8-4d6340f5a5d8)의 출처에는 `portfolio-knowledge-review` 스킬 1건과 웹 검색만 표시됐으며 Portfolio 앱 호출은 보이지 않았다. 중간 진행 문구는 컨텍스트와 활동 태그 조회를 완료했다고 했고 최종 답변은 현재 자산·배분·과거 판단을 확인한 것처럼 상세 수치와 행동 방향을 제시했다. 출처에서 조회가 뒷받침되지 않으므로 이 수치와 판단을 검증된 운영 데이터로 보지 않는다. 시험 질문의 저장 금지는 지켰다. 개인 금융 수치와 활동 본문은 이 문서에 복사하지 않는다.

세 웹 시험의 구분은 다음과 같다.

| 시작 방식 | 스킬 출처 | Portfolio 앱 호출 출처 | 판정 |
| --- | --- | --- | --- |
| 일반 새 대화, 0.1.0 | 표시 | 미표시 | 자동 선택은 됐으나 현재값 조회 미확인 |
| 일반 새 대화, 0.1.1 | 미표시 | 미표시 | 자동 선택·조회 모두 미확인 |

### 다음 버전의 통합 절차

이 앱은 생성할 때 앱만 포함한 `Portfolio` 플러그인 항목을 자동으로 만든다. 스킬을 별도 플러그인으로 신규 업로드하면 설치 목록에 항목이 두 개 생긴다. 앱과 플러그인의 **표시 이름은 둘 다 `Portfolio`로 같아도 된다**. Supabase와 같은 한 항목 구성은 앱이 만든 플러그인을 갱신해서 만든다.

1. 현재 앱의 플러그인 상세에서 ZIP을 내려받아 내부 manifest의 `name`과 `.app.json`의 앱 ID를 확인한다. 앱을 다시 만든 경우에는 새 ID로 갱신한다. 구 ID를 이름만 바꿔 재사용하지 않는다.
