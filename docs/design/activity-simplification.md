# 활동 중심 경험·태그·검색

상태: 단순화 합의 반영 / 구현 전 · 2026-09-23.

## 목적과 기준

쉽게 쓰는 투자 활동 기록장을 만든다. 사용자는 기록 유형을 고르지 않고 할 일 등록·완료·한 일 기록·편집·검색을 한다. 판단은 활동의 선택적인 결론/이유로 읽는다.
이 문서와 ADR-0007은 이전 별도 판단 탐색 및 결과 테이블 분리 요구를 대체한다. 기존 금융 계산·공유 경계·반복 동작과 자산 네 가지 보기/메모/원칙을 유지한다.

## 재사용할 구현

- LifecyclePage/ActionTimeline/ActivityEventViewer: 판단 모아보기 탭과 할 일 완료/한 일 기록 라벨을 정리하고 기존 목록·모달·상세를 활용한다.
- portfolio_tasks: 예정·일정·반복·상태와 기존 완료/재개 동작을 유지한다.
- activity_events: 한 일과 그 제목·결과·판단을 같은 레코드에 둔다. activity_results/event_result 테이블은 도입하지 않는다.
- investment_decisions 및 연결/이력: 과거 본문·제안/채택·당시 원칙·대체 관계를 보존하며 활동에서 읽게 한다. 이관/호환 방식은 #80에서 정하고 즉시 물리 삭제를 요구하지 않는다.
- 기존 OAuth 도구의 등록/완료/조회 경로를 활동 흐름으로 정리한다. 범용 execute 엔진을 만들지 않는다.

## 화면과 입력

할 일 → 날짜별 한 일을 같은 화면에 제공한다. 사전 등록 후 완료와 사후 기록은 동일한 제목·결과 표현을 사용한다. 자동 변경은 무엇이 바뀌었는지 표시한다.
내용만으로 등록하고 결과 없이 완료할 수 있다. 같은 상세에서 나중에 결과를 추가하거나 편집한다. 메모·태그·종목/계좌 연결은 선택이고 상세한 판단 내용은 필요할 때 펼친다.
기존 활동 편집과 새 활동 등록은 사용자가 선택한다. 정정인지 새 판단인지 시스템이 분류하거나 대체 관계 설정을 강제하지 않는다.
같은 수행을 중복 표시하지 않되 날짜/제목/세션 유사성으로 다른 활동을 묶지 않는다. 기존 판단-task 연결은 후속 조사 근거일 수 있으므로 동일 수행으로 추정하지 않는다.

## 최소 저장·편집 계약

| 대상 | 편집 범위 |
| --- | --- |
| 수동 활동 | 같은 레코드의 제목·수행일·메모·결론·선택 대상·태그 |
| 자동 금융 활동 | 설명/태그. 금융 원본·수량·변경 전후 값·원본 참조·발생시각은 보호 |
| 기존 금융 원본 | 기존 체결 취소·잔고 정정 등 목적별 기능 |
| 반복/완료/재개 | 기존 동작 재사용 |

활동 전체 불변성은 요구하지 않는다. 일반 편집마다 수정 이벤트·이력 테이블·본문 revision을 만들지 않는다. 금융/기존 태스크 이력과 과거 데이터의 보존은 유지한다.
편집 가능한 필드는 서버에서 제한한다. 자동 이벤트 JSON 전체를 덮어쓸 권한은 주지 않는다. 내용/메모/결과의 현재 정본은 하나로 두고 UI와 MCP가 동일하게 읽는다. 필요한 최소 갱신시각/충돌 검사는 #80에서 정한다.
잘못 입력한 수동 제목/날짜도 일반 편집으로 고친다. 이후 날짜별 목록과 검색은 수정된 값을 반영한다. 금융 증빙이나 반복 완료 회차 변경은 일반 날짜 편집으로 처리하지 않는다.

## 후속 할 일 연결

event.task_id는 기존 관련 태스크 참조이고, task.origin_event_id는 직접 계기가 된 활동 하나를 참조하는 선택 필드다.
task A → event E → 후속 task B에서 E.task_id=A, B.origin_event_id=E다. A 없이 사후 활동을 기록하거나 B 없이 활동만 남길 수 있다. 하나의 활동에서 여러 후속 할 일이 가능하다.
활동 상세에서 후속 할 일을 추가하면 연결하고 양쪽에서 찾아갈 수 있게 한다. 재검토 메모와 실제 등록된 할 일은 구분한다. 동일 소유자만 참조하며 연결 상대의 상태를 자동 변경하지 않는다. 다대다 관계 엔진이나 영구 업무 번들은 도입하지 않는다.

## 태그와 검색

실적점검/잔고대조/리밸런싱 등의 다중 태그를 선택적으로 붙인다. 태그 없는 저장도 가능하고 기존 태그를 우선 재사용한다. 완료 시 태그를 이어주며 반복 태스크 태그 변경이 과거 회차를 자동 재분류하지 않게 한다. 활동 태그는 자산 비중 계산과 분리한다.
검색창 하나에서 기간·종목·계좌·상태·결론 유무·태그와 키워드를 조합한다. 제목만 보고 종목/계좌를 확정 연결하지 않는다. 기술 모드 선택 없이 의미 검색을 보완하고 일반 날짜순과 관련도 정렬을 명시한다.
현재 활동 내용을 검색하며 편집 후 keyword/snippet·임베딩을 갱신한다. updated_at 또는 내용 해시 등 최소 기준으로 오래된 임베딩의 덮어쓰기를 막는다. 별도 결과 버전/이력 모델은 필요 없다.
권한과 필터는 페이지/집계/태그 자동완성에도 적용한다. 비공개 판단/태그를 기존 활동 공유에 노출하지 않는다. 임베딩 실패/미설정에서도 일반 기록과 기본 검색은 동작한다.
#83에서 한국어 품질·지연·비용과 공급자 설정을 검증한다. ChatGPT 구독이 임베딩 API 비용을 포함한다고 가정하지 않는다. 뉴스 조사/의견 생성은 ChatGPT 책임이다.

## 문맥·리포트와 MCP

문맥은 최신 활동 내용을 읽고 모델 제안과 사용자 채택, 실제 후속 할 일을 구분한다. 유사도 점수로 완료/채택/현재 판단을 결정하지 않는다.
리포트는 생성 당시 요약을 유지한다. 참조 활동의 수정시각 등 최소 정보로 원본 변경을 감지해 재생성 필요를 표시하고 자동 재작성하지 않는다. 날짜 정정 시 관련된 이전/새 기간도 고려한다. 변경 감지를 위해 일반 편집마다 감사 이벤트나 결과 revision을 만들지 않는다.
MCP는 등록·완료·편집·새 기록·선택 후속 연결·검색을 지원한다. 사용자에게 내부 유형/ID나 선택 필드 전체 입력을 요구하지 않는다. 단순 조회/분석만 요청하면 저장하지 않으며 금융 작업의 자동 활동을 수동으로 중복 기록하지 않는다.
#84는 각 기능 공개와 함께 도구 설명·가이드를 갱신한다.
