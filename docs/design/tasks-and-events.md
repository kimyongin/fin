# 태스크・이벤트 통합 설계

2026-09-23 후속: [활동·결과·태그·검색](./activity-simplification.md)과 ADR-0007이 판단 별도 탐색 및 기록 방식별 표시를 대체한다. 아래는 기존 구현 기준이며 반복·금융 원본·원자 기록 계약은 유지한다. 후속 #80~#85는 구현 전이다.
상태: 로컬 구현 및 자동 검증 완료, 운영 배포・실제 ChatGPT 평가는 미실행. 2026-09-22.

## 사용자 경험
사용자 화면의 이름은 `활동`으로 통일한다. 주 메뉴와 페이지 제목은 활동, 화면 안의 구체적인 상태는 `할 일`과 `한 일`로 표시한다. `행동 이벤트`는 내부 데이터와 설계 용어로만 사용한다.
사용자에게는 앞으로 할 일과 이미 한 일이 하나의 행동 목록이다. 사전 등록 여부에 따라 화면/메뉴가 갈리지 않는다. 태스크는 예정과 현재 상태, 이벤트는 수행한 사실을 담당한다. 업무 번들 선택이나 bundle_id는 필요 없다.
미리 등록한 일을 완료하면 태스크에 연결된 완료 이벤트가 생긴다. 사전 등록 없이 수량/메모를 수정하면 변경 이벤트만 자동 생성된다. 완료된 ToDo를 따로 작성하지 않는다.
화면은 미완료 행동과 날짜별 수행 행동을 함께 제공한다. 2026-09-23 후속 사용성 결정에 따라 중복된 전체/할 일/한 일 선택 필터는 화면에서 제거했다. 검색은 둘을 함께 찾으며 독립된 저장 시스템을 사용자에게 노출하지 않는다. 판단 상세/변경 상세/CSV와 기존 URL은 유지한다.

## 기존 구현에 근거한 변경
- portfolio_tasks, portfolio_task_history, execution_plans, task_fill_links는 유지한다. 일반 할 일을 기존 task 모델에 추가하며 정확한 DDL/RPC는 첫 티켓에서 확정한다.
- activity_events를 공통 행동 이력으로 재사용한다. 도메인의 금융/판단/확인 원본은 각 테이블에 유지하고 이벤트는 원본 참조와 표시용 최소 정보만 가진다.
- 기존 값 편집/메모/규칙 변경은 이미 자동 활동을 기록한다. app_verify_holding, execution task 전이/체결 연결 등 누락 경로와 프런트 후행 로그를 조사해 보완한다.
- 현재 ActivityEventViewer는 날짜별 표시를 이미 지원하지만 최근 30건만 읽는다. 기간/커서 조회와 통합 표시가 필요하다.
- todo_bundles/todo_items의 일반 항목과 task 연결은 `todo_item_action_migrations` 대응표로 전환한다. 운영 규칙/계좌・종목・보유 메모 기능(#69/#70)은 유지한다.
- 번들 UI와 MCP 광고는 제거했고 기존 데이터는 증분 migration의 대응표로 보존한다. 구 API는 한 릴리스의 읽기/복구 호환 기간 뒤 제거하며 신규 쓰기에는 사용하지 않는다.

## 저장 책임
1. 승인된 도메인 변경과 자동 이벤트를 서버의 동일 트랜잭션으로 저장한다. 이벤트를 위해 사용자에게 별도 승인을 요구하지 않는다.
2. 자동 이벤트는 에이전트가 별도 도구로 재작성하지 않는다. 에이전트는 원래 변경 도구를 호출하고 서버가 기록한다.
3. 태스크 생성/수정/완료/재개/취소는 이력을 남긴다. 같은 태스크 완료를 완료 ToDo와 활동 두 행으로 중복 표시하지 않는다. 과거 완료와 후일 재개는 서로 다른 사실로 보존한다.
4. 단순 조회/분석/변화 없는 저장을 완료 행동으로 만들지 않는다. 실패는 성공 행동 집계에서 제외한다. 멱등 재시도는 이벤트 중복도 막는다.
5. 앱 밖에서 한 일은 명시적 기록 요청 시 수동 이벤트로 저장 가능하다. 사용자 진술과 서버가 확인한 변경을 구분하며 매매/잔고 확인 원본을 위조하는 범용 로그 도구로 사용하지 않는다.
6. 배열 입력은 여러 일반 할 일 또는 수동 활동을 편리하게 저장하는 요청 형식이다. 영구 번들이 아니다. 금융 작업까지 범용 일괄 쓰기로 합치지 않는다.
7. 종전 공유 활동에 새 개인 태스크/원칙 정보를 자동 노출하지 않는다. 이벤트 원본/필드/연결 태스크의 권한을 검사하고 개수/날짜별 집계에도 같은 필터를 적용한다.

## 반복 태스크
- 첫 제공은 일반 태스크의 매일 반복이다. 설정은 task에 두고 매일 task 행을 복제하지 않는다.
- 완료 판정은 해당 task의 해당 회차를 완료한 유효 이벤트로 한다. 편집/조회/다른 대상의 확인 이벤트로 추정 완료하지 않는다.
- 현재 회차 상태는 완료/재개 이벤트와 같은 트랜잭션에서 갱신하는 작은 projection으로 조회한다. 이벤트가 원본 이력이고 projection은 현재 상태와 동시 완료 방지를 위한 파생 데이터다.
- task_id + 회차 날짜로 논리적 회차를 식별하고 사용자 시간대를 고정해 날짜 경계를 계산한다. 이벤트의 저장 시각과 완료 대상 날짜를 구분한다.
- 오늘 완료해도 반복 태스크 전체는 활성 상태이며 내일 회차가 다시 할 일로 나타난다.
- 어제 회차를 오늘 기록할 수 있다. 동일 회차 동시 완료/재시도는 중복 성공을 만들지 않는다. 완료 정정은 원본을 삭제하지 않고 취소/정정 연결로 유효 완료를 판정한다.
- 과거 미실행 날짜를 무한 태스크 행으로 생성하지 않는다. 요청 기간에서 미실행/완료를 계산한다. 최초 화면은 현재 회차와 사용자가 요청한 과거 범위를 제공한다.
- 일시정지/종료/일정 변경은 과거 회차를 바꾸지 않는다. 시작일/일정 변경 적용일/시간대 변경 정책과 필요한 최소 이력은 담당 티켓에서 테스트 가능한 계약으로 확정한다.
- 주간/월간 반복 설정과 research/execution 반복은 후속이다. 일반 완료 체크로 체결/증권사 확인/판단 채택을 대체하지 않는다.

## 통합 목록과 날짜
예정은 due_date, 활동은 실제 수행일/시각, 저장은 recorded_at(기존 created_at 활용 가능)을 구분한다. 자동 편집은 서버 변경 시각이 수행 시각이며 과거 체결일과도 구별한다.
태스크 완료 이벤트가 있는 날짜에 완료 행동 한 건을 보여준다. 새 등록/편집/재개 등 다른 이벤트는 상세 이력 또는 적절한 분류로 접근 가능하게 한다. 과거 기록을 현재 task 상태로 덮어쓰지 않는다.
혼합 목록의 필터/중복 제거는 페이지 제한 전에 처리한다. 같은 시각의 안정 커서와 권한별 빈 상태를 검증한다. 모든 감사 행을 상위 카드로 펼치지 않고 날짜별 요약/접기로 복잡도를 줄인다.

구현된 읽기 계약은 `app_list_action_timeline(owner, filter, from, to, limit, cursor, timezone)`이다. 응답은 `pending`, `days`, `next_cursor`로 고정하며 이벤트 커서는 `(occurred_at,id)`다. 공유 조회에서는 tasks/activity 권한을 별도로 검사하고, tasks 권한이 없으면 task 연결 이벤트도 반환하지 않는다.

## 통합 화면의 표현 기준
- 기본 전체 화면은 같은 화면 안에서 '지금 할 일 → 날짜별 한 일' 순서다. 둘을 단순 시간순으로 섞어 미완료 과제가 로그에 묻히지 않게 한다. 미래 예정/날짜 없는 과제도 별도 필터 또는 펼치기로 접근 가능해야 한다.
- 날짜별 요약은 행동 종류와 건수처럼 서버가 확인한 사실로 만들고 접기/펼치기를 제공한다. 요약을 위해 LLM을 호출하지 않는다. 작은 메모/태그 수정은 날짜별 요약에서 접어도 상세에서 모두 확인할 수 있다.
- 태스크 완료는 체크 표시와 결과를 대표로 표시한다. 독립 값 수정은 '수정', 체결은 '매수/매도', 잔고 대조는 '확인'을 명시한다. 모든 이벤트에 완료 체크를 붙이지 않는다. 색이나 아이콘만으로 의미를 구분하지 않는다.
- 같은 태스크/회차의 등록・편집 과정은 상세 이력에서 제공하고 완료 결과를 대표 행으로 표시한다. 후일 재개/정정 사실은 숨기지 않으며 과거 완료를 지우지 않는다. 연결 ID가 없는 유사한 제목의 행동은 합치지 않는다.
- 태스크 없는 이벤트도 행동 이름/대상/시각/결과와 변경 전후 상세를 제공한다. 태스크 연결이 없는 것을 오류/불완전 기록으로 표시하지 않는다.
- 반복 과제는 오늘 회차를 우선 표시한다. 과거 미실행 회차를 매일 연체 목록으로 누적하지 않고 요청 기간의 이력에서 확인한다. 일회성 미완료 과제까지 숨기는 정책으로 확대하지 않는다.
- 자동 기록은 무엇을 바꿨는지 알려준다. 이유는 기존 판단 연결 또는 필요할 때 작성하는 선택 메모로 제공하고 필수 입력이나 에이전트 추론으로 채우지 않는다. 기존 도메인에서 필요한 취소/정정 사유 계약은 유지한다.

## 기간 리포트
통합 목록(#77)의 대표 시나리오 사용성을 먼저 검증한 뒤 리포트(#78)를 연결한다. 기록의 양보다 지금 할 일, 최근 변화, 행동 결과를 쉽게 파악하는지를 평가한다.
일간/주간/월간은 기간별 원본 이벤트와 관련 판단/태스크를 근거로 ChatGPT가 요청 시 작성하고 Portfolio가 저장한다. 자동 스케줄 생성은 도입하지 않는다.
리포트는 기간/시간대/생성시각/참고 원본 범위와 ID를 기록한다. 주간/월간은 일간 요약만 이어 붙이지 않고 원본을 조회한다. 기간 내 활동과 기간 말 미완료 상태를 구분하며 후자는 당시 이력으로 계산 가능한 범위만 보고한다.
현재 계약은 지정 기간 원본 활동을 끝까지 커서 조회한 뒤, 사용자가 저장을 요청하면 `retrospective` 분류의 활동 한 건으로 기록한다. 기간은 활동 `context.scope`에 표시하고 사실·해석을 구분한다. 미완료 목록은 정확한 과거 시점 복원이 아니라 요청 당시 상태이며, 별도 리포트 테이블·자동 재생성 상태는 두지 않는다.
기존 daily_briefings/daily_reports를 먼저 조사해 최소 변경을 선택한다. 기존 시장/포트폴리오 점검과 활동 회고의 목적을 구분한다. 추가/정정 이벤트 이후 저장 리포트는 자동으로 최신인 척하지 않으며 재생성 필요 여부를 표시한다. 리포트 저장 자체가 다음 리포트의 투자 행동 건수를 늘리지 않게 분류한다.

## 전환과 검증
기존 migration은 보존하고 증분 변경으로 전환했다. 일반 open/paused/cancelled 항목은 task, 일반 done 항목은 출처가 표시된 과거 수동 기록이며 실제 금융 이벤트로 승격하지 않는다. paused/cancelled/result/performed_at/제목/태그/규칙 snapshot/판단・확인 관계는 `todo_item_action_migrations`에 보존한다.
연결 task는 원본 ID를 유지한다. 동일한 제목/날짜만으로 자동 이벤트와 기존 완료 항목을 삭제・병합하지 않는다. 원본 대응표와 읽기 호환을 두고 재실행 가능/건수 대조를 검증한다.
코드/도구/가이드/문서/manifest를 함께 전환한다. 신규 도구는 구현 전 광고하지 않는다. 로컬 테스트와 운영 배포/실제 ChatGPT 웹・모바일 평가를 별도 기록한다.

## 대표 인수 시나리오
- A01 메모/수량 수정 → task 생성 없이 자동 이벤트 한 건; 실패/재시도/무변경 확인.
- A02 일반 태스크 등록 → 완료 → 재개: 현재 상태와 과거 사실 보존, 완료 행 중복 없음.
- A03 사전 task 없이 앱 밖에서 한 일 기록: 수동 출처 표시, 금융 상태 변화 없음.
- A04 매일 반복 task: 오늘 완료/내일 미완료, 어제 회차 늦은 기록, 중복 완료/완료 취소/시간대 경계.
- A05 자산 수정/일반 task/research/execution 이벤트 혼합 조회: 기간/페이지/권한/오래된 URL・CSV 보존.
- A06 기간 리포트: 원본 누락/중복 없이 참조, 정정 후 재생성, 개인정보 공유 차단.
