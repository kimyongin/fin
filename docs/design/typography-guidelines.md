# 타이포그래피 가이드

2026-09-26 · 현재 표현 계약 · 앱 적용과 검증 결과는 [전 영역 타이포그래피 티켓](../tickets/ui-24-typography-consistency.md)에서 관리한다.

상위 기준은 [디자인 원칙](./PRINCIPLES.md)이다. 글꼴·크기·굵기·줄간격·숫자 표현은 이 문서가 정본이며, 모달·태그·타임라인 가이드는 배치와 동작을 담당한다. 기존 문서의 모달 라벨 12px, 본문 ‘16px 수준’처럼 충돌하거나 모호한 표현을 아래 계약으로 대체한다. 과거 티켓의 검증 기록을 수정하거나 전체 화면 적용 완료로 간주하지 않는다.

## 1. 목적과 적용 범위

사용자가 페이지를 바꿔도 무엇이 이름인지, 주요 값인지, 설명인지 바로 알아볼 수 있어야 한다. 같은 역할은 같은 크기·굵기·줄간격을 사용한다. 문자열이 숫자이거나 태그라는 이유만으로 크기를 결정하지 않고, 그 위치에서 전달하는 역할을 먼저 판단한다.

- 자산·배분·활동·원칙과 모든 상세/등록/확인 모달, 표 편집, 태그 관리, 설정·공유·피드백·연결 가이드·로그인·OAuth 동의까지 도달 가능한 웹 UI에 적용한다.
- 모바일과 PC에서 역할의 크기를 유지한다. 반응형은 열·줄바꿈·여백을 바꾸며, 화면 폭만을 이유로 `12 → 14px`처럼 같은 역할을 바꾸지 않는다.
- 계층을 표현하려고 설명·배지·반복 행마다 새로운 글자 크기를 만들지 않는다. 위치와 간격, 제한된 굵기로 구분한다.
- 메뉴·데이터·계산·저장·권한·API/MCP 의미는 기존 계약을 따른다. 접근 불가능한 옛 화면이나 역사적 HTML 시안을 되살려 적용하지 않는다.

## 2. 기본 규칙

- 기존 Pretendard와 한글 fallback을 유지한다. 브라우저 기본 글자 크기를 강제로 축소하지 않는다.
- 아래 px는 루트 16px 기준이다. 구현은 rem 크기·줄간격을 사용해 사용자 글자 확대를 존중한다. 12/14/16/18/20/24px의 여섯 단계만 사용한다.
- 기본 굵기는 400, 강조는 600이다. 선택·위험·누락 상태를 위해 500/700/800을 각 화면에서 추가하지 않는다. 마크다운의 강조도 600을 사용한다.
- 기본 자간은 normal이다. 한국어 라벨·제목에 임의의 넓은 자간, 대문자 장식, 음수 자간을 넣지 않는다.
- UI 일반 텍스트는 기존 `--ink`, 보조 문구는 `--muted-ink`, 상태는 기존 의미별 색을 사용한다. 보조라는 이유만으로 부모 opacity를 낮추지 않는다. 실제 배경과 글자 대비 4.5:1을 확인하며, 작은 흰 글자+밝은 accent 버튼도 검사 대상이다.
- h1/h2/h3, label/legend, button 등 HTML 의미와 시각 역할은 구분한다. 같은 크기가 필요하다고 제목을 일반 div로 바꾸거나, 본문을 제목 태그로 만들지 않는다.

## 3. 역할별 계약

크기/줄간격은 CSS px 환산값이다. 역할 이름은 공통 CSS 클래스의 권장 명칭이며 구현 시 한 곳에서 정의한다.

| 역할 | 크기 / 줄간격 | 굵기 | 적용 예 |
| --- | --- | --- | --- |
| `page-title` 페이지 제목 | 24 / 32 | 600 | 로그인 화면의 주 제목. 네 탭의 상단 카드는 section-title이며 별도 앱 헤더를 만들지 않음 |
| `dialog-title` 모달 제목 | 20 / 28 | 600 | 종목 상세, 활동 추가, 변경 버리기 확인. 1차·2차 같은 역할 |
| `section-title` 섹션 제목 | 18 / 28 | 600 | 할 일, 날짜별 기록, 변경 이력, 태그별 배분 |
| `item-title` 항목 이름·소제목 | 16 / 24 | 600 | 종목명, 배분 태그명, 할 일/기록 제목, 타임라인 날짜, 폼 내부 섹션 이름 |
| `value` 주요 수치 | 16 / 24 | 600 | 목록 수량·평가금액, 배분 현재 비중·차이 |
| `summary-value` 대표 합계 | 24 / 32 | 600 | 독립 대표 합계가 필요한 경우의 역할. 현재 자산·배분 상단 한 줄 평가액에는 secondary 사용 |
| `body` 읽기 본문 | 16 / 24 | 400 | 메모, 기록 내용, 원칙, 피드백 본문, 가이드의 설명 문단 |
| `label` 입력·열 라벨 | 14 / 20 | 600 | 계좌·수량·평균가 라벨, 종목/보유/평가 헤더, 기간·검색·태그 영역 이름 |
| `input` 입력값 | 16 / 24 | 400 | input/select/textarea, 검색·날짜·목표 비중·비밀번호. placeholder도 같은 크기 |
| `action` 조작 문구 | 14 / 20 | 600 | 버튼, 메뉴, 하단 탭, 선택/관리/필터 태그 칩, 더 보기 |
| `secondary` 보조 설명·보조 값 | 14 / 20 | 400 | 짧은 도움말, 목록 미리보기, 평균가·현재가·수익률·환산액, 오류/성공/로딩/빈 상태 |
| `meta` 메타 정보 | 12 / 18 | 400 | 종목 코드·목록의 보조 태그, 타임라인 시각, 시세 기준일, 개수·앱 버전, 읽기 전용 태그/상태 배지 |

`value`와 `item-title`, `summary-value`와 `page-title`은 각각 같은 CSS 선언을 공유할 수 있다. 역할 수만큼 React 컴포넌트나 별도 토큰 계층을 만들 필요는 없다.

### 분류가 헷갈릴 때

- 그 행을 식별하는 대표 이름은 `item-title`, 뒤에 붙는 코드/태그/시각은 `meta`다. 태그 관리에서 누르는 태그는 `action`, 배분에서 행을 식별하는 태그 이름은 `item-title`이다.
- 사용자가 직접 읽고 작성한 내용은 `body`다. 목록에서 그 내용의 일부를 보여주는 미리보기만 `secondary`로 줄인다. 상세 본문에 목록 크기를 그대로 사용하지 않는다.
- 수량·평가금액처럼 행의 주요 비교값은 `value`, 평균가·현재가·수익률·환산액은 `secondary`와 숫자 정렬을 사용한다. 수익률의 중요도는 부호·색·배치로 표현한다.
- 필수 조작을 이해하는 라벨, 누락 시세·저장 실패·삭제 영향 안내는 `meta`로 축소하지 않는다. 짧은 안내는 `secondary`, 확인창의 영향 설명은 `body`다. 배지에만 오류 설명을 넣지 않는다.
- 클릭 가능한 카드/행 전체가 button이라고 제목·본문까지 모두 `action`으로 바꾸지 않는다. 내부 이름·수치·본문은 각자의 역할을 명시한다.
- 페이지 소개 문구나 장식용 영문 소제목은 새로운 대형 크기를 만들지 않는다. 같은 화면의 실제 페이지 제목·섹션·보조 정보 역할에 맞춘다.

## 4. 숫자·날짜·긴 본문

### 숫자

- 금액·가격·수량·비중·수익률·시각에는 공통 숫자 modifier(`tabular-nums`)를 적용한다. 숫자라는 이유로 monospace 글꼴이나 별도 크기를 지정하지 않는다.
- 비교 열의 값은 오른쪽 정렬하고 헤더도 맞춘다. 문장 안의 숫자는 문장 흐름을 유지한다. 숫자 정렬 modifier는 크기·굵기·색을 바꾸지 않는다.
- 금융 포맷·소수 정밀도·통화·부호·미확정 `—`를 유지한다. 작은 화면에서도 자릿수를 없애거나 임의로 ‘억/만’ 단위로 축약하지 않는다.
- 값과 바로 붙는 원/주/%는 같은 크기·굵기를 사용한다. 라벨과 값은 분리할 수 있지만 단위만 작게 줄여 셀 폭을 맞추지 않는다.
- 큰 외화/원화 환산액은 원금액과 환산액을 별도 줄에 두고 컨테이너 안에서 자연스럽게 줄바꿈한다. 숫자 그룹·단위의 읽는 순서를 보존하고 실제 긴 값으로 검증한다.

### 원칙·기록·가이드의 긴 본문

- `body`를 기반으로 문단·마크다운 영역의 줄간격만 26px로 한다. 목록 미리보기·입력값은 이 긴 본문 modifier를 적용하지 않는다.
- 마크다운의 첫 수준 제목은 18/28·600, 하위 제목은 16/24·600이다. 본문에 페이지 제목용 24px가 반복되지 않도록 한다. 제목의 의미 구조·문단·목록은 유지한다.
- 마크다운 입력도 일반 Pretendard 16/24다. 원칙이 마크다운이라는 이유로 긴 한글 본문 전체를 monospace로 표시하지 않는다.
- 기술적인 코드/토큰/연결 설정만 monospace 14/20을 허용한다. inline code는 주변 글자 크기를 상속하고 기존 `0.9em` 축소를 제거한다. 설정 JSON 등 pre 영역의 가로 스크롤은 기존 기술 예시 영역에 한정한다.
- 링크는 주변 크기를 상속하고 밑줄/기존 색으로 알린다. 긴 URL/종목명/태그가 컨테이너를 밀어내지 않도록 줄바꿈한다.

| 자산 3열 목록 | 헤더 `label`, 종목명 `item-title`, 수량/평가금액 `value`, 평균가·현재가·환산·수익률 `secondary`, 코드·태그·계좌 개수 `meta` |

태그·타임라인·모달을 새로 분류하는 데이터 모델이나 화면 전환은 필요 없다. 같은 데이터도 역할이 다르면 표시 방식이 다른 이유를 위 표로 설명할 수 있어야 한다.

## 6. 모바일·접근성·예외

- 360/390/768/1024/1440px에서 같은 역할의 실제 크기가 동일해야 한다. 라벨·입력은 전체 너비가 필요하면 줄을 바꾼다. 입력·버튼·태그의 최소 44px 조작 영역을 유지한다.
- 일반 자산 목록은 기존 종목/보유/평가 3열을 유지한다. 셀 안 줄바꿈·열 폭·간격을 조정하며, 긴 이름이나 금액 때문에 임의의 11/13/15px 폰트를 추가하지 않는다. 표 편집의 내부 가로 스크롤 예외는 유지한다.
- 모든 일반 입력/검색/select/textarea는 모바일과 PC 모두 16px다. 조밀한 표 편집의 읽기 셀은 14px지만 활성 입력은 16px다. 모바일 입력 확대를 브라우저 설정으로 차단하지 않는다.
- 긴 본문과 오류는 고정 높이로 잘라 숨기지 않는다. 기존 목록 미리보기의 줄 수 제한은 유지할 수 있으며 상세에서 전문에 접근 가능해야 한다.
- 브라우저 200% 확대에서도 제목·버튼·입력·확인창의 필수 문구가 잘리지 않고 조작할 수 있어야 한다. 실제 기기 글자 확대/키보드 검증 여부는 따로 기록한다.
- 허용 예외는 기술 코드의 monospace, 긴 본문의 줄간격, 표 편집 읽기 셀뿐이다. 이외 예외는 구현 티켓에 대상·사용 목적·가이드로 해결되지 않는 이유·검증을 남기고 기준을 갱신한다. 페이지별 우연한 차이를 예외로 보존하지 않는다.

## 7. 공통 구현과 유지 관리

1. `src/styles.css`에 위 역할을 작은 공통 스타일 묶음으로 정의하고 기존 AppHeader/ModalShell/ModalActions/Timeline/TagChip/MarkdownContent부터 소비한다. 글자만 감싸는 범용 React 컴포넌트나 새 디자인 라이브러리는 만들지 않는다.
2. 스타일은 크기·굵기·줄간격을 담당한다. 기존 레이아웃·상태 색은 별도로 유지하고, 각 요소에 역할 하나만 적용한다. 숫자·긴 본문 modifier만 조합한다.
3. Tailwind의 CSS layer와 전역 `button, input, select, textarea { font: inherit; }`를 함께 확인한다. 전역 상속이 역할 클래스를 덮지 않도록 위치/범위를 정리하고, 버튼 내부 본문과 입력값은 자신의 역할을 유지한다. `!important`나 더 강한 페이지별 선택자로 덮어 쌓지 않는다.
4. 소비 화면의 중복 `text-xs/sm/base/...`, font/leading/임의 px·자간 지정은 해당 역할로 정리한다. 저장소 전체 정규식 치환은 하지 않는다. 도달하지 않는 과거 코드의 광범위한 정리는 이 작업 범위가 아니다.
5. 모든 신규·수정 UI는 이 가이드를 읽고 기존 역할을 선택한다. 역할 계약을 바꾸면 이 문서 → 공통 정의 → 영향받는 화면 → 검증을 같이 갱신한다. 다른 디자인 가이드에 크기 표를 중복 복제하지 않는다.
6. 구현 티켓에 전체 화면 적용표를 유지한다. 각 행은 미착수/적용/검증/예외/비활성 중 실제 상태를 기록한다. 소스 클래스 검색만으로 전수 적용 완료라고 하지 않는다.

## 8. 인수 기준

- 역할별 font-family/font-size/font-weight/line-height가 대표 화면과 입력·확인창의 computed style에서 일치한다. 웹 폰트 로드 완료와 fallback 동작을 구분한다.
- 주요 4개 페이지와 도달 가능한 모든 모달·보조 화면을 적용표에 대조한다. 오류·빈 상태·공유 읽기도 같은 역할을 사용한다.
- 좁은 화면과 넓은 화면의 캡처로 이름/주요 값/보조 정보를 구분할 수 있고, 기존 3열·버튼·footer에 넘침이 없다.
- 자동 검사는 공통 역할과 대표 소비 경로를 검증한다. 모든 문구의 CSS를 각각 snapshot으로 고정하거나 raw 클래스가 0개라는 숫자를 목표로 삼지 않는다.
- 실제 확인한 폭·상태·확대·키보드·미검증 범위를 티켓에 기록한다. 가이드 작성과 코드 적용·배포 완료는 별개다.
