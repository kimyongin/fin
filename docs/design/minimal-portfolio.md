## 목표 구조

사용자 개념은 자산·원칙·할 일·활동·피드백이다. 주 메뉴 오늘/자산/활동/원칙을 유지한다. 오늘은 최근 점검 활동과 열린 할 일을 조회하는 화면이다. 자산 네 가지 보기·계좌·카테고리 비중·표 편집을 보존한다.

## 최소 계약과 시나리오

- S1 보유 메모 편집: 기존 내용을 덮어쓰지 않고 보유 이유를 이관. 기존 비공개 이유가 공유 메모로 노출되면 안 된다. 메모 공개 범위를 분리하거나 안전한 공개 DTO를 적용하며 소유자 화면은 통합한다.
- S2 매수: 현재 수량/평균 원가 + 체결 수량/가격으로 서버 계산, holdings와 자동 활동을 한 트랜잭션으로 저장. 매도는 잔여 평균가 유지, 전량 매도 원가 0, 초과 매도 차단. decimal 계산 유지.
- S3 보정/잘못된 매매: 현재값을 직접 절대 보정하고 사유/전후를 활동에 남긴다. 과거 활동의 설명 정정은 잔고를 바꾸지 않는다. 즉시 실행 취소의 별도 엔진은 도입하지 않는다. 과거일 매매는 기록만 할지 현재에 반영할지 명확한 입력 계약을 정하고 소급 재생으로 추정하지 않는다.
- S4 할 일→완료/사후 기록: 수행 기록 한 건과 선택 후속 할 일을 제공한다. 반복의 오늘 완료는 오늘만 완료하고 내일 다시 표시한다. 반복 전체 종료(할 일 완료) 또는 삭제는 앞으로 표시하지 않으며 이전 수행 기록을 보존한다. 다시 필요하면 새로 등록한다. 일시정지/재개 기능은 만들지 않는다. 잘못 체크한 오늘 완료를 해제하는 동작은 반복 전체 재개와 구별한다.
- S5 조사/판단: 활동 내용/결론/출처/태그 저장. 모델 제안과 사용자 선택은 구분하되 채택 절차를 필수로 만들지 않는다. 기존 명시적 제안/채택/기각 상태는 이관 중 사실대로 보존한다.
- S6 오늘 점검: 문맥 조회→ChatGPT 조사→점검 활동 저장→오늘 표시. 조사 실패/미확인과 변화 없음 구분, 대상별 마지막 조사 기간은 활동 범위 배열에서 조회한다. 실시간 가격 변화만으로 저장 실패를 만들지 않는다.
- S7 기간 회고: 원본 활동을 페이지 끝까지 조회해 요약 활동 저장. 요약/시스템 수정 로그를 다음 요약의 실제 투자 행동 수에 포함하지 않는다. 생성 당시 보고서임을 표시하고 재작성은 명시적 요청 시 한다.
- S8 원칙 인터뷰: 현행 원칙 조회→변경 필드만 저장, 누락 취향 추정 금지. 계산용 배분·개인 선호·데이터 입력 규칙의 뜻과 공유 범위는 유지한다.
- S9 앱과 MCP에서 같은 현재값·활동을 조회/수정. 금융 자동 기록을 별도 수동 활동으로 중복 생성하지 않는다. 기간/대상/태그/키워드/의미 검색 유지.
- S10 본인·친구/게스트·운영자: 통합 전보다 공개 범위가 넓어지지 않는다. 출처와 개인 원칙이 섞인 활동은 필드별 안전한 응답 또는 보수적인 비공개로 전환한다.

## API·보조 구조

### 추가 확정 — 분류·삭제·원칙·보존 범위

- 활동에는 점검·조사·매매·회고 등 최소 분류 속성을 둔다. 자유 검색용 태그와 별개이며 사용 기능에 따라 앱/ChatGPT가 기본 지정한다. 분류 선택을 일반 등록의 필수 사용자 단계로 만들거나 분류마다 별도 상태 엔진을 만들지 않는다. 금융 분류만 지정해서 잔고 변경이나 서버 확인 사실을 만들 수 없다.
- 매매 되돌리기는 최신 매매 한 건에도 제공하지 않는다. 잘못된 수량/평균가는 증권사에서 확인한 현재값으로 보정한다. 정상 신규 매매의 평균가 계산은 유지하며 과거 재계산/역산은 하지 않는다.
- 활동 삭제는 기록 삭제이고 보유값/할 일 상태를 변경하지 않는다. 완료 체크 해제는 명시적 동작이다. 할 일 삭제는 이미 남긴 수행 활동을 연쇄 삭제하지 않는다. 계좌·종목 삭제 뒤에도 활동의 대상 이름/내용을 읽을 수 있게 최소 표시 정보를 보존한다. 삭제된 활동의 검색/임베딩은 제거하며 과거 회고 본문은 자동 재작성하지 않는다.
- 서술형 원칙은 같은 테이블에 변경마다 새 행을 저장한다. 안정 원칙 ID와 각 행 ID를 구분하고 사용자·종류·내용·적용 시작 시각·종료 여부 및 필요한 선택 적용 범위를 둔다. 수정/종료 모두 새 행 추가다. 종류별 하나가 아닌 원칙 ID별 최신 행을 조회하므로 같은 종류의 여러 원칙을 유지한다. 계산용 목표 비중 구조는 유지한다.
- 과거 원칙은 지정 시각 이하의 원칙별 마지막 행을 선택한 후 종료된 원칙을 제외한다. 기본 적용 시각은 서버 저장 시각, 동일 시각 순서는 안정적인 서버 저장 순서로 정한다. 날짜 지정은 사용자 시간대의 해당 날짜 말 기준이다. 현재/과거 조회를 앱과 MCP에서 제공하되 별도 이력 테이블·버전 번호·소급/예약 편집·과거 잔고 복원은 만들지 않는다.
- 현재 메모/원칙/보유값과 실제 수행·조사 결과는 새 구조로 이관한다. 원칙은 과거 적용 내용 조회를 지원하는 예외다. 기존 원칙 이력은 실제 시각과 개별 원칙의 대응을 확인할 수 있는 범위만 이관하고 불명확한 과거 원칙을 추정 생성하지 않는다. 나머지 세부 수정 과정과 폐기된 상태 전이는 백업/내보내기로 충분하며 과거 앱 상태 복원 기능은 만들지 않는다.
- 현금·직접 평가금액 자산의 입력/보정은 유지한다. 시장형 매매 계산을 모든 자산에 강제하지 않는다.

기존 데이터 접근 함수를 활용해 목적별 API를 축소한다. 활동 저장/편집/검색, 할 일 저장/완료, 원칙 조회/수정, 자산 직접 변경과 매매 계산 중심이다. 금융 쓰기는 서버의 목적별 계약을 유지하고 범용 활동 저장으로 실행하지 않는다.

MCP 입력에서 필요 없는 schema_version 상수·변경 사유·조회 후 버전 왕복을 제거할 수 있는지 실제 클라이언트 스키마 조건과 대조한다. 안전에 필요한 충돌 값과 재시도 키는 유지하며 자동으로 다른 키로 재시도하지 않는다. 변경 부분만 patch하는 일반 편집은 마지막 저장 우선임을 명시한다.

일반 메모·태그 편집마다 새 활동을 만들지 않는다. 자산값·원칙 변경처럼 실제 확인 가치가 있는 자동 기록은 명확한 표시 정책을 갖는다. 기술 오류 로그는 사용자 투자 활동과 분리한다.

테이블 개수 목표를 맞추기 위한 JSON 몰아넣기는 금지한다. 관계의 실제 검색·권한이 필요하면 작은 관계 테이블 유지가 더 단순할 수 있다. 저장 후 별도 state projection을 없애느라 매번 이력 재생을 구현하지 않는다.

## 이관·종료

2026-09-23 이후 사용자 승인에 따라 구 투자 데이터는 이관하지 않고 삭제할 수 있다. 따라서 구 행의 ID/건수/본문 대조는 종료 기준이 아니다. 새 데이터의 저장·재조회, 권한, 중복 요청, 금융 계산, 실패 복구를 검증한다. 이전 문단의 보존/이관 설계는 최초 계획의 기록으로만 읽는다.

백업 후 새 읽기/쓰기 경로 전환, 구 쓰기 차단, 기존 소비자 이전, 참조가 없는지 검증, 테이블/API 물리 정리 순서다. 단순히 숨기고 무기한 유지하지 않는다. 세부 과거 이력은 소유자별 읽기 가능한 내보내기와 접근 통제된 백업으로 충분하며 전용 조회 서비스를 만들지 않는다. 적용된 migration은 수정하지 않는다.

운영과 로컬 배포 차이, 백업 복원 가능성, 구 토큰 이용 여부는 아직 미확인이다. 첫 티켓의 read-only 감사와 마지막 티켓의 릴리스 게이트로 해결한다.
