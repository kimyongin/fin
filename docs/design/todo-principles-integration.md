# ToDo・원칙 통합 설계
상태: 부분 대체됨 · 2026-09-22. 번들・활동 화면・리포트 방향은 [태스크・이벤트 설계](./tasks-and-events.md)와 ADR-0006, #75~#79가 우선한다. #69/#70 메모와 독립 운영 규칙은 유지한다. 아래는 로컬 구현된 이전 설계의 근거이며 추가 개발 지시가 아니다.

## 목적과 기존 구현
ChatGPT는 조사·설명하고 Portfolio는 기억·계산·검증한다. 다음 세션에 데이터 관리 방법을 다시 설명하지 않고, 여러 수행 결과를 한 묶음으로 파악하게 한다.
기존 src/features/lifecycle/LifecyclePage.jsx와 portfolio_tasks는 조사/실행 과제이며 일반 체크리스트가 아니다. execution_plans/task_fill_links의 실제 수량 기반 완료, investment_decisions의 채택/기각, 활동 감사 원본을 유지한다.
accounts.note / instruments.note / holdings.note는 이미 앱에서 편집하고 포트폴리오 조회에서 반환한다. OAuth에 없는 메모 전용 변경을 보완한다. verification note는 저장되지만 최신 확인 조회/저장 응답에서 누락된다.

## 확정 경계
- 주 메뉴: 오늘 / 자산 / ToDo / 원칙. 하단 위치는 PC/모바일 공통 유지.
- 원칙: 기존 투자 기준·투자 전략 + 신규 데이터 관리 규칙. 규칙은 ToDo 완료 항목/고정 메모가 아닌 독립 현재값이다.
- 대상별 메모는 기존 필드를 재사용한다. 새 계좌/종목/보유 운영 노트 저장소로 복사하지 않는다.
- ToDo는 작업 묶음 하나에 여러 세부 항목. 여러 세션에 걸쳐 이어갈 수 있고 세션/시간 기반 자동 묶음은 없다.
- 활동은 ToDo의 활동 내역으로 이동하고 판단 모아보기도 제공한다. 연결 없는 기존 판단·과제·활동은 계속 접근 가능하다.
- 원칙/판단/매매/확인의 기존 데이터 의미와 권한은 유지한다. 제품 피드백은 독립 기능이다.

## 모델・API 계약 (제안 명칭, 구현 전 SQL로 구체화)
1. operating_rules: 소유자, ID, title, workflow_key(초기 reconciliation), applicability, body, active/archived, version, 작성/수정 시각. 관련 작업 필터로 활성 규칙 조회. 다른 작업 분류는 실제 소비 흐름이 생길 때 추가한다.
2. todo_bundles: 소유자, ID, title, summary, version, created_at, updated_at. todo_items는 bundle FK, ID, 순서, 제목, 결과, 수행일과 일반 상태 또는 기존 task 참조를 갖는다. 연결 task는 동일 소유자의 기존 portfolio_tasks이며 한 task의 활성 소속 묶음은 하나다.
3. 일반 항목은 open/done/cancelled/paused. 연결 과제는 기존 상태에서 계산한다. resolved는 완료, closed/cancelled는 종료 사유를 구분하고 execution은 실제 fill progress를 사용한다.
4. 묶음의 상태는 서버에서 산출: 활성 미완료가 있으면 진행 중, 미완료가 모두 paused면 보류, 모두 cancelled면 취소, 나머지 전부 종료면 완료(취소 건수 별도). 빈 묶음 저장은 거부한다. 과제 재개/체결 취소 시 묶음도 현재 상태를 다시 반영한다. 과거 수행일은 결과 기록으로 보존한다.
5. 태그는 묶음 분류용 문자열 목록(공백 정리·중복 제거)으로 시작한다. 자산 tags/전략 버킷과 연결하지 않는다.
6. 판단・verification・활동・규칙은 목적별 관계로 연결하고 소유권/FK 검사를 둔다. 일반 type+JSON payload 저장소로 기존 도메인을 이관하지 않는다. 규칙은 현재값 참조와 적용 당시 최소 본문 snapshot을 결과 저장 시 서버에서 기록하여 이후 변경으로 과거 설명이 바뀌지 않게 한다.
7. list/get/save_todo_bundle: 안정 커서 목록, 상세, items 배열 원자 저장. 생성/변경은 멱등 키, 수정은 bundle expected_version. 항목은 안정 ID로 upsert하고 생략은 유지, 제거 ID는 명시한다. task 상태 변경은 기존 목적별 API로만 수행한다. 연결된 데이터의 삭제/상태 변경으로 전파하지 않는다.
8. get/save/archive_operating_rule: 목적별 RPC 및 OAuth 도구. 현재값 CAS와 멱등 저장, 보관된 규칙은 기본 조회 제외. 목록은 workflow_key로 조회하며 본문 조건을 ChatGPT가 실제 파일과 대조한다.
9. update_entity_note: account/instrument/holding의 기존 note만 변경. expected_note와 null 정규화 비교로 충돌 감지, 동일 재시도는 멱등 영수증 우선. 기존 앱 메모 편집/일괄 저장 경로와의 경쟁도 검증한다. 잔고 수량/원가/version/검증 상태를 변경하지 않는다.
10. verify 응답/get_holding_integrity에 note/source를 명시하고 앱 최근 확인 영역에서 조회한다. 기존 영수증 응답에 note가 없을 수 있음을 호환 처리하고 과거 영수증을 고쳐 쓰지 않는다.

## 쓰기와 부분 실패
사용자가 결과 기록을 요청하면 여러 결과를 한 묶음으로 저장한다. 조회/분석만으로 묶음을 자동 생성하지 않는다.
배열 저장은 원자적이지만 이미 성공한 잔고 보정/매매와 묶음 저장은 별도 트랜잭션이다. 묶음 저장 실패 시 성공한 금융 작업을 재실행하지 않고 결과 ID를 연결하여 재시도한다.
실행된 금융 기록을 일반 done 체크로 생성하지 않는다. 분석 완료와 판단 채택은 별개다. 미래 후속 작업은 독립 묶음으로 연결한다.
규칙을 기억해달라는 요청은 규칙 저장만으로 충족하며 불필요한 완료 Do를 자동 생성하지 않는다.

## 검색・화면・호환성
ToDo 기본은 할 일/완료. 보류・취소 필터, 판단 모아보기, 활동 내역을 보조 진입으로 제공한다.
묶음 상세: 할 일 → 참고 규칙/대상 메모 → 수행 결과/연결 기록. 활동 상세/CSV 기능을 재사용한다.
기존 task/decision은 자동 복제하지 않는다. 미소속 과제 목록과 판단 모아보기로 접근하고 명시적으로 묶음에 편입한다.
#tasks/#decisions/#activity/#strategy의 기존 링크와 오늘/브리핑/task 상세 연결은 대응 뷰로 라우팅한다. 공유 owner 문맥과 목록 복귀 상태를 유지한다.
오늘에는 묶음 소속 과제를 중복 노출하지 않으며 미소속 열린 과제도 누락하지 않는다.
360/390/768/1024/1440px, 긴 항목/빈 상태/오류/부분 완료, 키보드・포커스・44px・하단 safe-area를 검증한다.

## 규칙 조회・보안
잔고 대조 가이드: 관련 활성 규칙 조회 → 계좌/보유/종목 메모 조회 → 파일과 적용 조건 대조 → 계산/미리보기/확정 → 요청된 경우 묶음 저장.
평균가가 없는 미래에셋 XLS는 매입금액/수량의 의미와 통화를 확인하고 수량 0/열 누락/충돌이면 추측하지 않는다. 저장 규칙은 금융 검증・권한・사용자 현재 지시를 우회하는 시스템 지침이 아니다.
규칙 조회 실패를 '규칙 없음'으로 취급하지 않는다. 규칙 없는 새 사용자도 기존 흐름을 사용할 수 있다.
신규 묶음/규칙은 기본 owner-only, 기존 feature sharing 구조 확장 여지를 유지한다. 기존 전략/자산 메모/활동 공유를 변경하지 않는다. 공개된 기존 task를 통해 비공개 묶음 제목・태그・규칙 snapshot이 새지 않게 DTO에서 제거한다.

## 시나리오 인수
- T01: 앱 계좌/보유 메모를 OAuth에서 조회/수정하고 잔고와 확인 상태가 동일하다.
- T02: 확인 메모 저장 후 앱/MCP에서 재조회, 최신 확인이 없는 경우와 과거 영수증 재시도를 처리한다.
- T03: 규칙 저장 후 새 ChatGPT 세션에서 XLS 잔고 대조에 조회/적용, 본문 수정/보관과 조회 실패를 구분한다.
- T04: 대조・보정・규칙 저장・판단 결과가 한 묶음/여러 항목으로 표시된다. 금융 작업 성공 뒤 묶음 실패 재시도에 중복 거래가 없다.
- T05: 일반 할 일과 기존 research/execution 연결, 부분 완료/보류/취소/재개/체결 취소/미래 후속 분리.
- T06: 미소속 기존 기록, 과거 URL, 오늘 연결, CSV, 타인 참조 거부와 기존 공유 회귀.
자동 테스트와 실제 ChatGPT 웹/모바일 평가・배포 증거는 구분한다.

## 대체한 초안과 범위 밖
계좌/보유별 신규 운영 노트, 완료 Do+고정으로 규칙 저장, 모든 활동의 완료 Do 변환, 모든 도메인을 JSON 배열로 이관하는 초안은 채택하지 않는다.
기존 #42/#43/#46/#47은 구현 근거이며 위 화면/메모 보완 범위는 신규 티켓을 따른다. 기존 미완료 검증을 이번 설계만으로 완료/취소하지 않는다.
자동 주문/자동 일일 분석/세션 감지/범용 워크플로 엔진/활동 전체 backfill은 범위 밖이다.
