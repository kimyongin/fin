# 페이지 상단 카드·검색·필터 가이드

2026-09-26 · 상단 구조 계약 보완 · [#138 로컬 구현](../tickets/ui-27-page-panel-structure.md). #136의 필터 기능 이후 네 카드의 제목·행동·본문 배치를 공통 `PagePanel`에 연결했다. 운영 배포·실기기 검증 상태는 티켓을 따른다.

활동 필터 후속 승인: [필터 카드 정돈](../tickets/ui-31-activity-filter-fields.md)·[시안](./assets/activity-filter-preview-20260926.png). 검색/기록 기간/태그를 모달 공통 필드 규칙으로 정렬하고 기간 상시 설명을 제거한다. 현재 구현은 이 계약을 소비하며 적용/검증 범위는 해당 티켓에 기록한다.

상위 기준은 [디자인 원칙](./PRINCIPLES.md), 글자는 [타이포그래피](./typography-guidelines.md), 선택 칩은 [태그 가이드](./tag-guidelines.md)를 따른다. 이 문서는 상단 정보·조작·필터의 배치 정본이다. 데이터 의미와 저장 동작은 각 기능 계약에 둔다.

## 목적

어느 탭에서도 현재 보는 범위, 관련 행동, 조회 조건을 같은 위치에서 찾는다. 자산의 필터만 카드 밖에 떠 있거나 같은 검색이 페이지마다 다른 구획에 배치되지 않게 한다. 화면별 목적은 유지하며, 모양을 맞추려고 숫자 요약·소개 문구·검색·빈 카드를 추가하지 않는다.

## 공통 골격

1. [#137](../tickets/ui-26-footer-profile-navigation.md)에 따라 상단 앱 헤더 대신 대상 전환·보조 메뉴를 하단에 둔다. 최상단 카드는 짧은 목적/범위와 실제 기능을 담당한다. 페이지 h1은 카드 또는 접근성 전용 제목으로 유지하며 별도 소개 카드를 추가하지 않는다.
2. 상단 카드는 제목과 오른쪽 위 작업 메뉴 → 선택적 보조 정보 → 선택적 핵심 수치 → 구분선과 선택적 필터/문서 본문 순서로 구성한다. 없는 영역은 여백과 구분선까지 생략한다.
3. 제목은 네 화면 모두 18px/600/28px·기본색으로 표시한다. 첫 행은 왼쪽 제목/오른쪽 작업 메뉴 버튼의 세로 중심을 맞춘다. 메뉴를 평가액 묶음이나 날짜 행에 붙이지 않는다. 보조 정보는 14px/400/20px·보조색이다. 제목 아래 보조 정보는 가까운 8px 간격으로 이어진다. 현재 제목은 자산/태그별 배분/할 일과 기록/현재 원칙이다.
4. 필터 또는 문서 본문 위에 얇은 구분선 하나를 둔다. 검색어·기간·태그는 동일한 필터 구획 안에 두며 필터 안에 또 카드를 만들지 않는다. 검색과 필터 사이를 서로 다른 패널로 나누지 않는다. 배분처럼 하단 구획이 없으면 구분선도 없다.
5. 필터는 항상 보인다. 상세 필터 접기, 가로 칩 스크롤, 좁은 화면에서만 숨기는 옵션을 추가하지 않는다. 태그는 가로 나열 후 줄바꿈한다.
6. 카드 radius 16px, 내부 여백 모바일 16px/640px 이상 24px, 제목/보조 정보 간격 8px, 하단 구획 앞 간격 16px, 필터 행 간격 12px, 조작/칩 사이 8px, 카드와 다음 본문 간격 20px을 기본으로 한다. 한 높이로 강제 정렬하지 않는다.
7. 상단 카드의 행동은 개수에 관계없이 오른쪽 위 44×44px 햄버거 버튼 하나에 모은다. 아이콘의 선·크기·간격·버튼 배경/hover는 하단 푸터 햄버거와 동일하게 하고 테두리 버튼처럼 강조하지 않는다. 버튼에는 해당 화면의 작업 메뉴임을 알리는 접근성 이름을 붙인다. 열린 목록은 텍스트 버튼을 세로로 표시하고, 선택·바깥 클릭·Escape로 닫는다. 기존 행동의 순서·권한·비활성 조건은 유지하며, 저장/확정 버튼은 해당 편집 본문에 남긴다. 제목 → 보조 정보 → 수치 → 하단 구획 순서를 유지한다. 입력의 높이·배경·테두리·모서리도 공통 스타일을 쓴다.
8. 페이지 저장 액션은 해당 편집 본문의 하단에 둔다. 배분의 변경 시 취소/저장은 유지하며 조회 카드에 빈 footer를 만들지 않는다. 원칙의 수정은 현재 원칙 카드에 한 번만 둔다.

## 화면별 적용

| 화면 | 상단 카드 | 다음 본문 |
| --- | --- | --- |
| 자산 | 자산 + 작업 메뉴(가격 갱신/종목 추가/계좌 추가/표 편집) → 한 줄 평가액·필요한 품질 상태 → 구분선 → 계좌/종목 검색/대표 태그 필터 | 종목·보유·평가 3열 목록, 시세 기준일·수익률 안내 |
| 배분 | 태그별 배분 + 작업 메뉴(태그 관리) → 전체 계좌 기준·평가액·필요한 상태 안내 | 태그별 현재/목표/차이, 변경 시 하단 취소/저장 |
| 활동 | 할 일과 기록 + 작업 메뉴(태그 관리/활동 추가) → 구분선 → 라벨이 있는 검색/기록 기간/태그. 상시 기간 설명은 생략 | 할 일 → 기록 |
| 원칙 | 현재 원칙 + 작업 메뉴(수정/작성) → 적용 일시 → 구분선 → 현재 마크다운 또는 빈 상태 안내 | 변경 이력 |

원칙은 문서 카드 자체가 상단 카드다. 별도 요약·필터·수정 버튼을 더 만들지 않는다. 현재 원칙이 없을 때는 같은 영역에 등록 안내와 등록 행동을 제공한다. 배분에도 무의미한 검색 필터를 추가하지 않는다. 공유 상태에서는 허용된 조회 조건을 사용할 수 있지만 추가·수정·관리 버튼은 기존 권한대로 숨긴다.

자산·배분 목록의 데스크톱 열 머리글은 같은 36px 높이와 세로 중앙 정렬을 사용한다. 열 머리글은 버튼이 아니므로 44px 터치 목표 높이를 강제하지 않는다. 두 목록 모두 카드 테두리 바로 아래에 머리글을 두고 같은 가로 안쪽 여백을 사용한다. 배분 목록만 카드 전체에 별도 패딩을 추가해 머리글 위에 빈 공간을 만들지 않는다. 모바일 자산은 3열 비교를 유지해 머리글을 표시하고, 배분은 각 행에 `현재/목표/차이` 라벨이 있어 별도 열 머리글을 숨긴다.

## 필터의 의미와 상태

활동의 필드 표현은 [모달 가이드 3절](./modal-guidelines.md)을 재사용한다. 검색/기록 기간/태그 세 묶음은 16px 간격, 라벨과 입력은 8px, 검색/날짜 control은 48px 높이와 12px 모서리/좌우 여백으로 통일한다. 위 공통 골격의 기본 12px 필터 행 간격보다 이 명시적 필드 묶음 규칙이 우선한다. `기록 기간` 아래 날짜 두 개를 배치하고 날짜별 접근성 라벨은 유지한다. `전체 기간`은 같은 라벨 행 오른쪽의 텍스트 버튼(터치 영역 최소 44px)이다. 좁아서 두 날짜가 잘리면 한 열과 보이는 시작일/종료일 라벨로 전환한다. 기간 아래와 검색 결과의 중복 적용 설명은 제거하며 오류·실패 안내는 남긴다. 다른 탭을 함께 재배치하거나 모든 PagePanel 간격을 바꾸라는 뜻은 아니다.

- 각 필터는 이름과 적용 대상을 명시한다. 상단에 보인다는 이유로 다른 탭이나 데이터까지 범위를 바꾸지 않는다.
- 자산은 기존 즉시 검색을 유지한다. 계좌/검색어/태그를 바꾸면 같은 렌더링 기준의 목록과 평가 요약을 함께 갱신한다. 검색 실행 버튼을 추가하지 않는다.
- 활동은 검색 버튼을 두지 않는다. 날짜·태그는 선택 즉시, 검색어는 입력이 멈춘 뒤 짧은 지연을 두고 서버 조회에 적용한다. 무효한 날짜 범위는 요청하지 않는다. 기간은 기록에만 적용하고 미완료 할 일은 예정일과 무관하게 유지한다. 입력 중 중복 요청과 늦은 응답은 기존 요청 보호로 제어한다.
- 배분은 전체 계좌를 분모로 유지한다. 자산의 계좌·태그·검색 조건을 배분이나 배분 목표 저장에 전달하지 않는다.
- 상세를 열고 닫거나 저장 실패로 돌아올 때 조건을 유지한다. 다른 포트폴리오로 전환하면 이전 소유자의 계좌·태그 ID와 검색 상태를 넘기지 않는다.
- 처음부터 데이터 없음, 조건에 맞는 결과 없음, 로딩, 조회 실패를 구분한다. 결과 없음에는 조건 해제를 제공한다. 잘못된 조건을 조용히 무시해 전체 데이터로 확대하지 않는다.

## 자산 대표 태그 필터

- 칩은 `전체`, `태그 없음`, 기존 자산 태그 순서로 둔다. `전체`는 태그 조건만 초기화하며 계좌와 검색어는 유지한다. 선택이 하나도 없으면 `전체`가 선택된 상태다.
- 실제 태그 여러 개와 `태그 없음`을 함께 선택할 수 있다. 태그 조건끼리는 OR, 계좌·검색어와는 AND다. 종목 대표 태그가 하나이므로 AND 선택 UI는 제공하지 않는다.
- `태그 없음`은 종목 대표 태그 연결이 없는 상태이며 사전에 저장하는 가짜 태그가 아니다. 공유 사용자에게 권한상 숨긴 데이터를 미분류로 추정하지 않는다.
- 선택 기준은 ID다. 태그 이름 변경 후에도 선택은 유지한다. 선택 태그가 삭제된 경우 해당 조건을 제거하고 조회 조건이 바뀌었음을 알린다. 계좌 변경 시 태그 조건은 유지하며 결과가 없으면 그대로 빈 결과를 보여준다.
- 태그 필터는 자산 목록의 종목을 대상으로 한다. [#139](../tickets/ui-28-instrument-registration-and-quote-display.md)에 따라 전체 계좌에서는 등록된 0보유 종목도 표시하고 같은 종목의 보유를 합산한다. 특정 계좌에서는 그 계좌의 보유만 표시·계산한다.
- 계좌만 선택된 경우 `{계좌 범위} · 평가액 {금액}`, 검색어 또는 태그 조건이 있으면 `조회 결과 · 평가액 {금액}`을 한 줄 보조 정보로 표시한다. 계좌 범위는 선택 필터에서도 확인할 수 있다. 중복되는 결과 종목 수와 큰 숫자 블록을 상단 카드에 넣지 않는다.
- 합계는 표시 결과에 속한 보유의 기존 평가 로직을 재사용한다. 외화 환산·현금·평가형·누락/오래된 시세 정책을 유지한다. 시세 경고 개수는 평가액 근처에, 가장 최근 시세 기준일은 목록 하단 수익률 안내에 조회 범위 기준으로 표시하며 누락액을 정상 0으로 표현하지 않는다. 결과가 없을 때는 0원과 빈 결과를 표시한다.
- 가격 갱신은 기존 전체 가격 갱신 동작을 유지한다. 검색 결과만 갱신한다고 표현하지 않는다. 표 편집도 자체 계좌/필터 범위를 유지하며 상단 조건을 몰래 이식하지 않는다.

## 미분류 정리 시나리오

`태그 없음` 선택 → 종목 상세 → 기존 대표 태그 선택 → 저장 → 갱신된 목록에서 해당 종목 제외 순서다. 태그는 종목 공통이므로 여러 계좌 보유에 함께 적용된다. 별도 계좌별 태그나 일괄 편집 API는 만들지 않는다.

저장/재조회 실패 시 기존 초안·오류 정책을 유지하고 성공 전 목록에서 제거하지 않는다. 저장 후에도 태그 조건을 유지한다. 상세 닫기 후 기존 종목이 사라졌다면 다음 결과 행, 결과가 없으면 목록 제목/빈 결과 안내로 초점을 복귀한다. 스크롤은 가능한 기존 위치를 유지하며 목록이 짧아진 경우 유효 범위로 제한한다. 조건 해제를 자동으로 하지 않는다.

## 공통화와 검증

공통 상단 카드 컴포넌트가 제목·행동·보조 정보·수치·하단 구획의 실제 DOM과 스타일을 소유하고 네 페이지가 내용을 전달한다. CSS 문자열만 공유하고 각 페이지가 헤더를 따로 조립하지 않는다. 자산·활동부터 연결한 뒤 배분·원칙까지 적용한다. 공유 UI는 조회·합계 계산·저장·필터 상태를 소유하지 않는다. 페이지별 설정 객체를 해석하는 범용 레이아웃/필터 엔진은 만들지 않는다.

같은 viewport에서 네 카드의 비교 캡처를 직접 검토하고 제목의 실제 적용 글자 크기·색·위치, 행동 정렬·줄바꿈, 여백·구분선의 일관성을 기록한다. 가로 넘침 없음과 빌드 성공만으로 시각 일관성 검증을 대신하지 않는다. 공유 상태는 공통 제목 옆에 표시하고 편집 행동의 빈 자리를 남기지 않는다.
