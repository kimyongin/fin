# 타임라인 디자인 가이드

2026-09-24 · 설계 기준. 로컬 적용 결과와 미검증 범위는 #119에서 관리한다.

적용 티켓: [#119 활동·원칙 타임라인 통일](../tickets/ui-12-timeline-consistency.md). 원칙의 내용/이력 계약은 [#118](../tickets/ui-11-markdown-principles.md)을 따른다.

상위 기준은 [디자인 원칙](./PRINCIPLES.md), 상세 열기/닫기는 [모달 가이드](./modal-guidelines.md)다. 적용 대상은 활동의 날짜별 기록과 원칙의 변경 이력이다. 할 일 목록·현재 원칙·검색 결과를 시간순 타임라인으로 강제하지 않는다.

## 목적과 정보 구조

활동 분류의 최신 기준은 [#122](../tickets/activity-15-tags-and-references.md)다. 아래 종류 배지/필드별 변경 표시 요구 중 충돌 부분은 일반 태그·기록 본문·대상 참조로 대체한다. ‘할 일 완료’ 전용 종류 배지는 없으며 실제 기록 제목을 표시한다. 두 화면의 날짜/간격/조작 규칙은 유지한다.

날짜별로 무슨 일이 있었는지 훑고 관심 있는 항목의 상세를 읽는다. 두 화면은 날짜 그룹·시각·제목·보조 정보·상세 진입의 위치를 공유한다. 활동 기록과 원칙 변경의 의미 및 저장 구조는 각각 유지한다.

```text
섹션 제목

2026. 09. 24. (목)                     접기
  09:30  ● 활동 제목 또는 원칙 변경 메모
           종류/상태 · 필요한 짧은 보조 정보
  08:20  ● 활동 제목 또는 원칙 변경 메모
           종류/상태 · 필요한 짧은 보조 정보

2026. 09. 23. (수)                     접기
  ...

                이전 기록 더 보기
```

## 날짜 그룹과 항목

- 섹션 제목은 카드 밖, 날짜는 카드 안의 공통 그룹 헤더에 둔다. 날짜별 카드 한 겹만 사용하고 항목마다 다시 카드를 감싸지 않는다.
- 날짜 카드는 기존 `--panel`, `--line`, radius 16px, 모바일 padding 16px/640px 이상 24px을 사용한다. 그룹 사이 간격은 12px, 섹션 제목 아래도 12px이다.
- 날짜 헤더 전체는 최소 44px의 접기/펼치기 버튼이며 `aria-expanded`와 제어 대상 연결을 제공한다. 기본은 펼침이다. 날짜·상태 표현은 두 화면에서 같게 하며 그룹 건수는 정확히 알 때만 선택적으로 표시한다. 원칙에는 활동 종류별 집계를 만들지 않는다.
- 날짜는 연도를 포함해 실제 날짜를 표시한다. 시각은 24시간제 `HH:mm`. 활동은 발생 시각, 원칙은 적용 시각을 사용하고 그룹 날짜와 표시 시각은 같은 기존 업무 시간대 기준으로 변환한다. 기기 시간대 때문에 날짜 그룹과 시각이 어긋나지 않게 한다.
- 데이터가 제공하는 최신순과 동일 시각의 안정 순서를 유지한다. 표시 단계에서 브라우저 현지 날짜로 다시 정렬하거나 기록을 합치지 않는다.
- 넓은 화면은 짧은 시각 열 → 점/세로선 → 내용, 640px 미만에서는 시각을 내용 위로 올려 본문 폭을 확보한다. 작은 화면에서 넓은 시간 열을 유지하지 않는다.
- 항목 간 세로 여백은 16px, 제목/메타 사이 간격은 8px을 기본으로 한다. 제목은 16px 수준, 시각·배지는 12px 이상이다. 긴 문자열은 줄바꿈하고 페이지 가로 넘침을 만들지 않는다.
- 선은 1px `--line`, 점은 동일한 8px 중립색이다. 장식은 `aria-hidden`으로 처리한다. 앱/에이전트나 원칙 종류를 점 색으로 구별하지 않는다. 실패 등 의미는 필요한 텍스트 배지로 명시한다.

## 내용의 밀도와 상호작용

- 항목의 대표 텍스트는 최대 3줄, 보조 요약은 최대 2줄로 표시한다. 전체는 상세에서 읽는다. 줄임은 표시만 하며 저장 내용을 자르지 않는다. hover tooltip이 전체 내용 확인의 유일한 수단이어서는 안 된다.
- 활동은 제목을 먼저, 종류 배지와 필요한 상태/출처를 다음 줄에 표시한다. 종류와 사용자 태그는 구별한다. 태그가 많으면 제한된 미리보기와 나머지 개수를 표시하고 상세에서 전체를 읽는다. 결과/결론은 짧은 요약으로만 표시하며 긴 본문·필드별 변경 전후 값·CSV 조작은 상세에 둔다.
- 원칙은 #118의 변경 메모를 대표 텍스트로 사용한다. 메모가 없으면 추가/수정/적용 종료 문구를 쓴다. 필요한 원칙 식별 문구만 보조로 두며 목록에 본문·본문 자동 요약·DIFF를 넣지 않는다.
- 항목의 주 읽기 영역은 하나의 명확한 상세 열기 버튼으로 만든다. 최소 44px 높이·키보드 초점·읽을 수 있는 접근성 이름을 제공하고 버튼 안에 링크나 다른 버튼을 중첩하지 않는다. 목록의 일반 배지/태그는 필터 버튼처럼 보이지 않게 한다.
- 상세는 공통 ModalShell 기준을 따른다. 활동은 관련 할 일과 전체 기록/변경 값을, 원칙은 선택한 변경 행의 메모와 당시 본문을 표시한다. 원칙을 위해 과거/현재 비교 모달을 추가하지 않는다.
- 닫으면 호출 항목으로 초점이 돌아오고 필터·날짜 접힘·더 보기·스크롤이 유지된다. 창 크기 변경만으로 상세를 닫거나 목록을 초기화하지 않는다.

## 로딩·오류·페이지 연결

- 최초 로딩/기록 없음/검색 결과 없음/조회 오류를 구분한다. 동일한 상태 스타일을 사용하고 문구만 화면 의미에 맞춘다.
- 더 보기는 목록 아래의 같은 폭·높이·보조 버튼 스타일을 사용한다. 활동은 `이전 기록 더 보기`, 원칙은 `이전 변경 더 보기`로 명확하게 표시한다.
- 추가 로딩과 실패 때 기존 목록·상세·접힘을 보존한다. 해당 구간에서 재시도하며 빈 목록으로 바꾸지 않는다.
- 다음 페이지가 같은 날짜로 이어지면 기존 날짜 카드에 합친다. 날짜 카드·항목이 중복되지 않고 기존 접힘 상태가 유지되어야 한다. 일부만 받은 그룹을 전체 건수처럼 표시하지 않는다.
- 본문은 페이지의 자연스러운 세로 스크롤을 사용한다. 카드별 내부 스크롤, 무한 스크롤, 가상화, 좌우 교대 타임라인은 필요하지 않다. 하단 탭과 safe-area가 마지막 항목/더 보기를 가리지 않는다.

## 공통화와 유지 관리

활동과 원칙의 두 실제 소비자가 공유하는 날짜 그룹/항목 표현만 `src/components`의 작은 컴포넌트로 추출한다. 이름은 구현 시 정하고 슬롯/children으로 도메인 내용을 전달한다. 공통 컴포넌트는 fetching·커서·권한·저장·날짜의 업무 의미를 소유하지 않는다. 범용 타임라인 데이터 모델이나 새 라이브러리는 도입하지 않는다.

신규/수정 타임라인은 이 문서를 기준으로 구현하고 의도적인 차이는 담당 티켓에 목적을 기록한다. 간격·색·반응형 변경은 공통 컴포넌트와 두 소비자를 함께 확인한다. 구현 티켓은 360/390/768/1024/1440px의 정상·긴 내용·빈 상태·오류·더 보기·상세 복귀 및 키보드 검증 범위를 기록한다.
