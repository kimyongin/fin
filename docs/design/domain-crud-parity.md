# 웹 HTTP · OAuth MCP 도메인 CRUD 완결성

2026-09-26 · Astra 검토 및 구현 인계. 코드/DB/운영 변경 없음.
사용자 요구: 모든 도메인 데이터를 웹과 에이전트 양쪽에서 생성·조회·수정·삭제할 수 있어야 한다.
이 문서는 목표 계약이다. 아래 현황은 저장소 코드 감사이며 운영 호출 성공을 의미하지 않는다.

검토 기준 커밋: a18de82。GitHub #151~#158 생성 및 로컬 티켓 본문 동기화 확인. 문서 인코딩 검사와 새 문서 9개의 상대 링크/LF 검사 통과. 앱·DB·운영 호출 테스트는 이 설계 작업에서 수행하지 않았다. 문서는 미커밋 상태이며 사용자 로컬 설정 및 기존 .e2e 파일을 보존했다.

## 목표와 경계

- 웹 HTTP는 기존 Supabase RPC/Edge HTTP 경로다. 별도 REST 서버를 만들지 않는다.
- MCP 기준은 신규 연결용 portfolio-mcp-oauth다. 구 token endpoint에 도구가 있어도 OAuth 지원으로 세지 않는다.
- 동일 목적의 양쪽 요청은 동일 app_* 업무 규칙을 소비한다. 범용 CRUD/payload 엔진, 모든 객체용 버전/이력/휴지통을 추가하지 않는다.
- 목록만 있고 단건 식별/전체 페이지 탐색이 안 되면 R 완료가 아니다. 제목 대신 안정 ID를 쓰고 필요한 검색/페이지/연결 대상 조회를 제공한다.
- C/U/D의 이름은 동일할 필요 없지만 결과·권한·삭제 영향·충돌·재시도 의미가 같아야 한다. 웹에 있는 목적별 행위(가격 갱신, 반복 완료 등)도 MCP에 있어야 한다.
- 사용자 데이터의 CRUD와 시스템 테이블 직접 CRUD를 구별한다. 아래 제외를 묵시적으로 확대하지 않는다.
- 현재 구현·스키마 색인은 새 기능 구현 후 갱신한다. 설계만으로 구현됐다고 고쳐 쓰지 않는다.

기호: C 생성, R 조회, U 수정, D 삭제. 부분은 사용 시나리오가 제한되거나 속성별 저장이 나뉜 상태다.

계좌/종목 메모는 부모 속성이지 별도 도메인/테이블이 아니다. 매매·보정은 보유를 변경하고 활동을 남기는 행위다. 별도 거래 원장 CRUD를 복원하지 않는다.

## 시스템 관리 범위: 원시 행 CRUD를 노출하지 않는다

- auth 사용자/세션, OAuth/legacy token, 비밀번호/hash, 관리자 allowlist: 도메인 편집이 아닌 보안 운영. 비밀번호는 설정 요청에만 쓰며 기존 값을 조회하지 않는다.
- mutation receipts, 반복 회차 상태, 태그 연결 행: 부모의 목적별 저장/삭제/완료에서 관리. 사용자에게 독립 CRUD를 요구하지 않는다.
- 임베딩, 집계/view, 가격 동기화 실행 로그, 관리자 처리 감사행: 파생/운영 자료. 원본 데이터의 편집과 필요한 관리 행위로 유지한다.
- 친구의 자산은 읽기 공유다. CRUD 동등성은 소유자 권한을 뜻하며 친구 쓰기나 피드백 공개를 뜻하지 않는다.
- 시세·환율은 2026-09-26 사용자 재확정에 따라 직접 CRUD 대상이 아니다. 웹과 MCP 모두 동일한 가격 갱신 기능을 호출하며 공급자 데이터 조회·갱신만 제공한다. 수동 입력/삭제/보정 API를 추가하지 않는다.

## 삭제·수정 최소 규칙

1. 할 일 삭제: 관련 기록 본문/발생시각/종목/태그를 보존하고 task_id만 끊는다. 반복 회차와 할 일 태그 연결은 제거한다. 완료/중단/삭제를 혼동하지 않는다.
2. 기록 삭제/정정: 보유값·할 일 완료 상태를 되돌리지 않는다. 관련 태그/임베딩은 정리하고 금융 성공 receipt는 보존한다. 삭제 뒤 이전 금융 요청 재시도가 잔고를 재변경하면 실패다.
3. 계좌/종목: 보유가 있으면 삭제 차단 및 정리할 대상 반환. 보유 삭제와 종목 삭제는 다르다. 종목 참조 기록은 유지하며 더 이상 존재하지 않는 대상을 이동 링크로 만들지 않는다.
4. 자산 태그: 목표 비중이 남으면 삭제 차단. 태그 삭제를 핑계로 배분을 재정규화하지 않는다. 삭제 가능한 태그의 연결은 해제하고 종목 자체는 보존한다. 활동 태그도 기록/할 일 자체를 지우지 않는다.
5. 배분: 행별 수치 변경도 집합 원자 저장. 전체 초기화는 미설정 상태이며 0% 또는 균등 배분을 자동 생성하지 않는다.
6. 원칙: 현재의 실제 정책 변경은 새 날짜 행 추가를 유지한다. 잘못 쓴 이력은 선택 행의 본문/변경 메모만 정정할 수 있고 적용시각은 바꾸지 않는다. 행 삭제 후 남은 최신 행이 현재, 마지막 행 삭제 후 빈 상태다. 최신 삭제 확인에는 이전 원칙이 현재가 된다는 영향을 표시한다. 무조건 새 불변 이력/별도 event_result를 만들지 않는다.
7. 피드백: 작성자는 자기 본문만 정정하고 자기 제출을 삭제한다. 관리자 상태/답변/이슈 링크를 사용자 U payload로 변경하지 못한다. GitHub 이슈는 자동 수정/삭제하지 않는다.
8. 설정: '초기화'는 포트폴리오/인증 계정 삭제가 아니다. 공개 이름/비밀번호/공유 활성화의 초기화는 공유 접근을 해제하고 프로필 아이콘 초기화와 구분한다. 친구 연결 갱신은 재인증이지 상대 프로필 편집이 아니다.

삭제는 명시적 대상·영향 확인 후 실행한다. 서버에서는 인증된 소유자만 쓰고, 참조 대상도 같은 소유자인지 검사한다. UI 확인/도구 description만으로 권한을 보장하지 않는다.

## 코드 감사 근거

- OAuth 정의: supabase/functions/_shared/mcp/portfolio-tools.ts, handler: supabase/functions/portfolio-mcp-oauth/index.ts.
- delete_activity/ delete_activity_tag는 이미 정의돼 있으나 공통 idempotentWriteAnnotations의 destructiveHint=false를 사용한다. 실제 의미에 맞게 수정하고 다른 쓰기도 전수 검사한다.
- 이 세션에 연결된 도구 목록에는 퇴역 도구가 남고 새 활동 CRUD가 빠져 있다. 배포된 OAuth tools/list와 직접 대조하지 않았으므로 캐시/잘못된 endpoint 중 어느 원인인지 단정하지 않는다.
- 자산: src/features/portfolio/accountActions.js, instrumentActions.js, src/features/assets/AssetDetailModal.jsx. token 서버 supabase/functions/portfolio-mcp/index.ts의 지원을 OAuth 지원으로 오인하지 않는다.
- 활동: src/features/lifecycle/data.js의 app_save_activity_detail / app_save_general_task_detail과 OAuth 속성별 저장 경로 차이.
- 원칙: src/features/strategy/data.js, PrincipleJournal.jsx, 20260924174000_single_current_principle.sql.
- 태스크 관계: 20260922062418_action_events_general_tasks.sql의 owner/task 복합 FK는 RESTRICT, 반복 상태는 20260922064935_recurring_general_tasks.sql에서 CASCADE. 구현 전 이후 migration까지 해당 제약만 추적해 현재 DDL을 확인한다.
- 배분: 20260923175703_simplify_tag_allocation.sql은 빈 배열을 거부한다.
- 피드백: src/features/feedback/data.js와 202609210028_product_feedback.sql; version은 있으나 작성자 수정/삭제 API는 없다.
- 공유: src/features/auth/accessActions.js, useSharingProfile.js; 웹 전용 설정/연결 RPC 사용.

## 실행과 완료 기준

CRUD-01 → CRUD-02 → CRUD-03 → CRUD-04 → CRUD-05 → CRUD-06 순서 권장.
CRUD-07의 가격 갱신 동등성은 CRUD-03과 이어서 진행한다. 직접 CRUD 예외는 사용자 확인 완료다.
CRUD-08은 첫 slice부터 계약표/발견 검사를 소비하며 최종 릴리스에서 전체 교차 검증한다. 공통 프레임워크 선개발은 금지한다.

각 slice는 DB/RPC → 웹 → OAuth MCP → 교차 재조회 → 가이드/테스트까지 끝낸 뒤 커밋한다.
공통 수용 조건:

- 웹 C → MCP R/U → 웹 R/D → MCP 미존재 확인, 반대 방향도 수행. 편집 가능한 전체 필드와 페이지 마지막 항목 포함.
- owner/다른 사용자/친구/익명별 R 및 직접 HTTP/MCP 쓰기 거부를 확인. 서비스 역할 우회 테스트로 대체하지 않는다.
- 참조 보존, 동일 요청 재시도, 필요한 기존 충돌 검사, 실패 시 부분 저장 없음. 삭제 뒤 오래된 create/update 재시도가 부활시키지 않는지 확인한다.
- 조회 description은 저장을 제안하는 명령으로 쓰지 않는다. 삭제는 destructiveHint=true, idempotent/readOnly hint는 실제 부수효과와 일치시킨다.
- 각 추가 도구의 이름/schema/handler/guide/실제 tools/list 및 호출까지 검증. 신규 DB 요구는 기존 호환성 검사에 추가한다.
- UI 변경은 공통 모달/타이포그래피 가이드와 360/390/768/1024/1440px, 키보드·확인 취소·초안/검색 범위 보존을 확인한다.
- 로컬 테스트와 운영 마이그레이션/Edge/웹 배포 및 실제 ChatGPT 웹·모바일 평가는 구분한다. 운영 사용자 데이터로 파괴적 테스트하지 않는다.
- 코드에 함수가 있다는 이유로 완료 표시하지 않는다. 각 표 행에 API/도구/테스트/운영 확인 증거 또는 명시적 결정 대기를 남긴다.
