# PRD — 매일의 판단을 이어가는 Portfolio

2026-09-23 현재 제품 기준. 이전 기획과 당시 상태는 [PRD 이력](../history/portfolio-prd-before-stability-20260923.md)에 보존한다. 충돌 시 [ADR-0008](../adr/0008-minimal-portfolio-storage.md)과 [단순성 원칙](../engineering/SIMPLICITY.md)이 우선한다.

## 목적과 역할

사용자가 출근길에 마지막 점검 이후 달라진 점과 지금 할 일을 빠르게 이해하고, 실제 행동을 부담 없이 남기게 한다. ChatGPT는 조사·해석·설명을 담당하고 Portfolio는 사용자별 사실을 기억·계산·검증한다. 자동 분석이나 주문은 하지 않는다. 완벽한 증권사 잔고 동기화도 약속하지 않는다.

본인과 초대한 지인이 각자의 데이터를 쓰는 다중 사용자 앱이다. 모바일에서 읽기와 간단한 기록을 우선하고, PC에서 비교·대량 편집을 지원한다. 로그인과 공유는 별개이며 비공개 정보는 명시적 공유 없이 노출되지 않는다.

2026-09-26 공유 기준은 [ADR-0009](../adr/0009-whole-portfolio-sharing.md)와 [#145](../tickets/ui-33-sharing-settings-autosave.md)다. 자산·배분·활동·원칙과 이력을 전체 읽기 전용으로 공유하며 항목별 공개 정책을 제거한다. 설정은 공유 하기/공유 받기로 정돈하고 비밀번호·토큰·피드백 등 계정 운영 정보는 제외한다. 기존 공유의 범위가 자동 확대되지 않도록 전환 후 사용자가 다시 켠다. 일반 로컬 구현·DB 적용을 마쳤고 운영 전이며 아래 과거 개별 공유 문장보다 우선한다. 후속 [#146](../tickets/ui-34-sharing-form-and-viewers.md)은 공유 설정을 일괄 저장하고 소유자 설정에서 공유받는 친구의 공개 이름·아이콘·최근 웹 열람 시각을 표시한다. 후속 UX와 시각 저장도 일반 로컬에 구현했으며 운영 적용 전이다.

## 사용자가 하는 일과 화면

2026-09-26 자산 등록 후속 설계 [#139](../tickets/ui-28-instrument-registration-and-quote-display.md): 종목을 먼저 등록하면 전체 계좌 목록에 보유 0으로 보이고, 종목 상세에서 계좌별 보유값을 입력한다. 계좌 없는 종목 등록을 허용하며 가짜 0보유 행은 저장하지 않는다. 자산 등록·상세의 시장 현재가/기준일은 직접 편집하지 않고 가격 갱신으로 관리한다. 평가형 금액·현금 잔액·개인 평균가/수량의 직접 편집은 유지한다. 구현 전이다.

| 화면 | 목적 |
| --- | --- |
| 자산 | 계좌별 보유 종목·수량·평균가·가격을 확인하고 편집한다. 가격 갱신과 표 편집을 제공한다. |
| 배분 | 전체 계좌의 태그별 구성과 목표 비중을 비교하고, 같은 화면에서 목표를 직접 편집하며 종목 태그를 관리한다. 자산을 거치지 않고 하단 탭에서 연다. |
| 활동 | 할 일과 수행한 기록을 한 흐름에서 보고, 태그·검색으로 조사·점검·판단의 내용과 근거를 찾는다. |
| 원칙 | 독립 탭에서 서술형 투자 기준·운영 규칙을 관리하고 원칙의 과거 변경을 본다. |
| 설정·피드백 | 계정·공유·연결을 관리하고 앱 사용 중 발견한 문제를 접수한다. |

자산의 다계좌·카테고리 배분과 데스크톱 표 편집은 유지한다. 햄버거에 별도 자료 보관함·변경 로그를 핵심 사용자 개념으로 되살리지 않는다. 현재 정보 구조는 [제품 재정리](../design/product-reorganization.md), 모바일 규칙은 [디자인 원칙](../design/PRINCIPLES.md)을 따른다.

## 저장 정본과 제약

2026-09-24 활동 최신 설계 [#122](../tickets/activity-15-tags-and-references.md): 내부 종류와 종류별 폼/공유/편집 제한을 제거하고 제목·본문·날짜·태그·대상 참조로 기록한다. 공유는 활동 단위로 켜며 기존 활동 관련 허용은 자동 승계하지 않는다. 자동 금융 기록도 소유자가 편집/삭제할 수 있지만 실제 잔고/할 일 상태는 바뀌지 않는다. 아래 금융 기록 원본 보호·종류 검색 요구 중 충돌 부분을 대체한다. 구현 전이다.

2026-09-24 최신 배분 계약 [#121](../tickets/ui-14-tag-allocation.md): 태그별 현재/목표/차이 조회와 목표 비중 직접 편집으로 줄인다. 모드·버킷·별도 설정 화면과 적립금/매매 한도/보정 기간의 추천 계산을 제거한다. 목표 합계 100%와 기존 공유 경계를 유지한다. 아래 및 #118 당시의 계산용 한도 유지 문구는 이 결정으로 대체한다. 로컬 구현은 진행 중이며 운영 DB에는 아직 적용하지 않았다.

최신 UI 기준은 [#113 보유 확인 중심의 자산 UX](../tickets/ui-06-assets-holdings-first.md)의 후속 사용자 결정이다. 자산은 기본 보유 목록·계좌 선택과 전체 화면 표 편집을 제공하고, 배분은 독립 하단 탭으로 직접 연다. 기존 네 보기 탭이나 자산 내부 배분 진입 버튼을 되살리지 않는다. 사용자 목적이 없는 기능은 축소 가능하다. 로컬 구현과 검증 결과는 티켓에 기록하며 운영 배포는 별개다.

오늘 탭을 없애고 자산을 기본 화면으로 연다. 마지막 점검과 점검 이력은 활동의 기록에서, 미완료 과제는 활동의 할 일에서 본다. 보유값은 필요할 때 직접 수정·보정하며 별도의 잔고 확인 상태는 관리하지 않는다. `#today` 옛 링크는 활동으로 이동한다. 공유 사용자가 점검 기록만 볼 권한이 있는 경우에도 활동에서 해당 기록을 열 수 있다.

[#112](../tickets/ui-05-asset-management-placement.md)는 가격 갱신·종목 태그 관리의 자산 배치를 정한 당시 기록이다. 배분 설정·계산 계약은 위 #121로 대체한다. 운영 배포는 별개다.

- 계좌·종목·보유·카테고리는 현재 자산 상태의 정본이다. 보유 이유는 보유 종목 메모에 적는다.
- 조사·판단·점검·회고와 수동 수행은 편집 가능한 활동 기록에 남긴다. 출처·결론·태그는 기록에 붙이고 검색한다. 금융 변경의 자동 기록은 원본 보호를 유지한다.
- 예정·반복은 할 일에 저장하고 수행되면 활동과 연결한다. 할 일 없이 수행한 활동도 가능하다. [#133](../tickets/activity-18-agent-due-recurrence.md)의 목표는 매일/선택 요일·시간에 도래한 일을 사용자 요청 시 에이전트가 수행하는 것이다. 밀린 회차는 최신 한 번으로 처리하고 회차 완료와 전체 종료/삭제를 구분한다. 자동 실행·알림은 없다. 후속 UI [#144](../tickets/activity-19-recurring-list-actions.md)는 목록의 `이번 완료`와 `중단`을 구분하고 상세 종료 버튼을 없앴다. 완료/예정 활성 반복도 웹 목록에서 중단할 수 있지만 에이전트에게는 실행할 미처리 도래 회차만 전달한다. 운영 배포 전이다.
- 서술형 원칙은 사용자별 현재 마크다운 문서 하나이며 같은 테이블에 본문·변경 메모·시각을 새 행으로 저장한다. 최신 저장본만 현재이고 나머지는 이력이다. [#132](../tickets/principles-01-single-current-document.md)가 기존 원칙 ID별 최신 여러 문서 요구를 대체한다. 다른 일반 데이터의 의무 이력으로 확대하지 않는다. 기존 데이터 전환·웹/MCP 구현은 아직 남았다.
- 2026-09-24 [#118](../tickets/ui-11-markdown-principles.md): 원칙은 자유 마크다운 본문만 입력한다. 분류·적용 범위는 저장/API/가이드까지 제거하며 필수 제목·태그로 대체하지 않는다. 여러 기준을 한 본문에 담을 수 있고 원칙 변경 이력은 유지한다. 로컬 구현·검증 완료, 운영 전환 전이다. 계산용 배분 설정은 별개다.
- 매매는 체결가 기준 수량·평균가를 계산한다. 증권사 현재값과 다르면 사용자가 직접 보정한다. 과거 거래를 다시 재생하거나 취소해 현재 잔고를 자동 역산하지 않는다.
- 인증·소유권·공유 대상 관계와 읽기 전용 경계, 금융 쓰기의 원자성·중복 방지·정밀 계산은 유지한다. 공유는 ADR-0009에 따라 포트폴리오 전체에 하나의 ON/OFF를 사용하고 개별 정책 저장소를 제거한다.

구체적 저장·API 계약은 [저장 계약](../design/storage-contract-20260923.md), 현재 물리 스키마는 [스키마 개요](../../supabase/schema/OVERVIEW.md)에 있다. 적용된 migration은 이력으로 보존한다.

## 완료 판단과 현재 상태

#118의 원칙 변경 이력은 날짜와 선택적으로 남긴 변경 메모로 탐색하고, 선택한 시점의 본문 전체를 읽는다. 메모는 당시 변경 설명이며 현재 원칙 본문과 구분한다. 본문 전체 반복 표시나 줄 단위 DIFF는 요구하지 않는다. 구현 전 설계다.

성공은 사용자가 약 60초 안에 중요한 변화와 다음 행동을 이해하고, 같은 배경을 반복 설명하지 않아도 다음 점검을 이어가는 것이다. 실제 습관 형성은 실사용 관찰 전까지 검증됐다고 하지 않는다.

로컬 구현·자동 검증과 운영 DB 적용·배포·실제 ChatGPT 웹/모바일 평가는 별도 상태다. 최신 진척은 [START-HERE](../START-HERE.md), [티켓](../tickets/README.md), [운영 인계](../design/storage-release-readiness-20260923.md)에서 확인한다. 수직 슬라이스별 개발 방식은 [개발 방법](../engineering/development.md)을 따른다.
