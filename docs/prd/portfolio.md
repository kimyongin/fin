# Portfolio 제품 요구사항

2026-09-26 · 현재 승인 계약. 구현/배포 상태는 [티켓](../tickets/README.md)과 [배포 기록](../engineering/deployment.md)에서 구분한다. 이전 세부 결정·작업 서술은 [PRD 스냅샷](../history/prd-before-149-20260926.md)에 보존한다.

## 목적과 책임

사용자와 ChatGPT가 자산을 확인하고, 원칙을 참고하며, 할 일과 기록을 이어가는 개인 포트폴리오 앱이다. ChatGPT는 사용자의 요청에 따라 조사·해석·설명을 하고, 앱은 현재 값과 사용자가 저장한 내용을 관리한다. 앱을 여는 것만으로 분석·거래를 실행하지 않는다.

과거 기능을 유지하기 위해 개념·테이블·이력을 늘리지 않는다. [단순성 원칙](../engineering/SIMPLICITY.md)과 [ADR-0008](../adr/0008-minimal-portfolio-storage.md)이 구 설계를 대체한다. 금융 쓰기의 소유권·원자성·중복 방지는 간소화 과정에서도 지킨다.

## 네 화면

| 화면 | 사용자 목적 | 필요한 기능 |
| --- | --- | --- |
| 자산 | 무엇을 보유하고 얼마인지 확인·수정 | 계좌/종목 등록, 계좌별 보유, 대표 태그·검색, 시세 갱신, 상세 직접 편집, 전체 화면 표 편집 |
| 배분 | 태그별 현재/목표 차이 확인 | 전체 계좌 기준 태그별 현재·목표·차이와 목표 저장, 태그 관리 |
| 활동 | 할 일을 실행하고 결과를 남김 | 할 일과 날짜별 기록, 반복 일정, 검색·기간·태그, 관련 종목/할 일 |
| 원칙 | 현재 판단 기준과 변경 이유 확인 | 현재 마크다운 한 문서, 변경 메모, 과거 본문 타임라인 |

오늘·자료·판단 전용 화면을 다시 만들지 않는다. 조사·점검·판단은 활동 기록과 태그로 남긴다. 설정·가이드·피드백은 보조 메뉴에 둔다.

### 자산과 배분

- 종목 등록과 보유 추가를 구분한다. 종목을 등록하면 전체 계좌 목록에 보유 0으로 나타나며 상세에서 계좌별 수량/평균가 등을 수정한다. 특정 계좌 목록은 그 계좌의 보유 범위를 따른다.
- 일반 메모는 종목에 둔다. 보유 이유용 별도 테이블/비공개 메모, 계좌별 보유 메모, 잔고 확인 flag/이력은 되살리지 않는다. 계좌 자체 메모와 종목 메모의 의미를 혼동하지 않는다.
- 현재가·기준일은 상세에서 읽기 전용이며 가격 갱신으로 변경한다. 일반 편집으로 시세를 쓰지 않는다. 금융값 변경의 확정은 작은 확인창에서 처리하며 상세 초안을 유지한다.
- 평균가는 사용자가 증권사 기준으로 보정할 수 있다. 과거 거래 재계산·되돌리기 엔진을 만들지 않는다. 기록 편집/삭제가 보유값을 다시 계산하지 않는다.
- 배분은 별도 모드/버킷 없이 자산 태그별 목표를 사용한다. 전체 계좌 분모는 자산 검색 필터와 독립적이다. 누락 시세/환율을 정상 0으로 숨기지 않는다.
- 모바일 조회와 여러 계좌 편집을 유지하고 대량 편집은 전체 화면 표에서 제공한다.

### 활동과 반복

- 할 일은 예정된 작업, 기록은 수행/관찰/판단의 내용이다. 내부 테이블 차이를 사용자가 알아야 하는 UI로 만들지 않는다.
- 기록은 편집 가능한 제목·본문·태그와 필요한 종목/할 일 참조로 관리한다. 별도 내부 활동 종류·event_result·번들 ID를 도입하지 않는다.
- 완료 시 연결 기록을 만들 수 있고 할 일 없이 기록만 남길 수도 있다. 금융 변경에서 자동 기록을 남겨도 기록 수정과 보유 수정은 별개다.
- 반복은 매일 또는 선택 요일과 시각에 따라 에이전트 접속 시 해야 할 회차를 확인하는 용도다. 사용자가 비정기적으로 “할 일 확인하고 진행해”라고 요청한다. 별도 자동 실행/알림 스케줄러를 전제하지 않는다. 누적 회차 처리·완료/중단 의미는 해당 반복 계약을 따른다.
- 기록 기간은 기록 조회에 적용한다. 미완료 할 일을 기간 밖이라는 이유로 숨기지 않는다. 검색·태그 선택 의미와 즉시 적용은 페이지 가이드를 따른다.

### 원칙

- 현재 원칙은 최신 적용 문서 하나이며 마크다운 자유 텍스트다. 분류·적용 범위별 현재 문서 여러 개로 나누지 않는다.
- 변경 시 메모와 해당 시점 본문을 남긴다. 이력 목록은 날짜/변경 메모 중심이고 선택하면 당시 본문을 읽는다. 긴 본문이나 diff를 목록에 반복하지 않는다.
- 이 이력은 실제 과거 원칙을 확인하기 위한 예외다. 다른 모든 데이터에 불변/버저닝을 일반화하지 않는다.

## 공유와 에이전트

[ADR-0009](../adr/0009-whole-portfolio-sharing.md)에 따라 포트폴리오 전체를 읽기 전용으로 공유한다. “전체”는 자산·배분·활동·할 일·원칙 등 승인된 포트폴리오 조회 범위이며 인증 비밀·개인 설정·친구 목록·피드백·내부 JSON의 무제한 공개가 아니다. 항목/종류별 공유 스위치를 복원하지 않는다.

공유 하기/공유 받기의 공개 이름·비밀번호와 연결 친구를 관리한다. 권한 검증은 서버에서 수행하며 UI의 읽기 전용 표시로 대신하지 않는다. 현재 보는 소유자는 하단 프로필 전환에서 확인한다.

새 에이전트 연결은 OAuth다. 개인 토큰 발급 UI/API를 새 사용 흐름으로 제공하지 않는다. 과거 토큰 endpoint의 호환 유지 여부는 [아키텍처](../engineering/architecture.md)와 배포 기록에서 관리한다.

MCP는 실제 도구 schema/description과 workflow guide를 함께 유지한다. 사용자의 조회 요청을 저장 요청으로 해석하지 않고, 금융 변경·공유 같은 중요한 쓰기는 목적별 승인·권한 계약을 지킨다.

## 설계와 완료 기준

공통 디자인은 [PRINCIPLES](../design/PRINCIPLES.md)와 연결 가이드를 따른다. 같은 대상의 모달은 직접 편집·한 번 저장이며 2차 모달은 의사 확인에만 쓴다.

완료는 해당 티켓의 실제 저장/재조회·권한·실패/재시도·UI 검증 증거로 판정한다. 문서 승인, 로컬 자동 테스트, 운영 배포, 실제 ChatGPT/모바일 확인은 서로 대체하지 않는다. 현재 미검증 항목은 해당 티켓과 배포 기록에 남긴다.
