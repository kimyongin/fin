## 현재 기준

- ChatGPT는 조사·해석·설명, Portfolio는 기억·계산·검증한다.
- 계좌/종목/보유/카테고리 비중과 유용한 기존 자산 편집은 유지한다.
- 보유 이유는 메모, 조사/판단/점검/회고는 활동, 예정/반복은 할 일, 서술형 기준은 원칙으로 단순화한다.
- 일반 편집의 불변/revision/의무 이력/변경 사유는 제거한다. 금융 중복 방지·원자성·정밀 계산·사용자 격리는 유지한다.
- 현재값 직접 보정으로 금융 기능을 축소하며 과거 거래 자동 재생은 요구하지 않는다.
- 최신 매매도 되돌리기 없이 증권사 현재값으로 보정한다. 반복은 오늘 완료와 전체 종료/삭제만 구분하고 일시정지/재개는 없다. 기록 삭제는 잔고/할 일 상태를 되돌리지 않는다. 활동은 최소 자동 분류, 원칙은 한 행에 하나씩 저장하며 세부 과거 이력 복원 기능은 만들지 않는다.
- 통합은 기존 비공개 정보를 공개할 권한이 아니다. 필드별 공유 경계를 검증한다.
- 2026-09-23 최신 사용자 결정: 기존 투자 데이터 전체는 삭제해도 된다. 재입력·재사용을 전제로 레거시 행 이관/읽기 호환을 완료 조건으로 두지 않고 구 저장소·API·화면을 정리한다. 인증, 사용자 격리, 다중 사용자용 공유 기능의 구조는 유지한다. 운영 DB 적용·배포는 개발과 별도 게이트다.

## 다음 작업과 상태

원칙만 이력 예외: 같은 테이블에 변경 행을 추가하고 안정 원칙 ID·적용 시작 시각·종료 여부로 현재/과거를 조회한다. #86/#89를 따른다. 다른 데이터의 과거 상태 복원 기능으로 확대하지 않는다.

#80~#85는 이전 활동 UI/검색 통합의 로컬 구현 기록이다. 새 저장 구조 전환 완료를 뜻하지 않는다. 운영 배포/실제 ChatGPT 검증 상태는 GitHub 최신 기록과 환경을 확인한다. 과거 검사 수치나 배포 전 문구로 현재 상태를 단정하지 않는다.

storage-simplification-01의 운영/로컬 테이블 전수 대조와 최소 계약은 `docs/design/storage-inventory-20260923.md` 및 `docs/design/storage-contract-20260923.md`에 기록했다. #89의 원칙 행·비공개 보유 메모, #87의 활동 분류·출처·수동 기록 삭제, #88의 반복 전체 종료와 일반 일시정지 제거, #90의 매매 취소 신규 UI/MCP 제거를 로컬 수직 슬라이스로 구현했다. 조사·점검·판단·회고의 새 저장/조회는 활동 중심으로 전환했고 구 뉴스·리포트·브리핑·판단·조사/실행계획 저장소와 사용되지 않는 구 테이블을 증분 migration으로 제거했다. 일반 할 일의 중복 revision 테이블과 구 조사 상태 컬럼도 제거했다. 매매 예상 계산은 저장 없이, 확정은 직접 잠금/버전 검증으로 전환했고 구 매매 preview 테이블/RPC도 제거했다. 금융 거래 원장과 구 보정/확인 구조는 아직 남아 있다. 일반 로컬/운영 DB의 물리 축소와 운영 배포는 아직 하지 않았다. 현재 진척은 각 티켓을 확인한다. 공통 프레임워크 선구현 없이 슬라이스별 구현·검증·커밋한다. 운영 배포는 명시적 요청 범위에서 수행한다.

Git 상태를 확인하고 .claude/settings.local.json 및 .e2e/supabase/.temp/cli-latest 등 사용자 로컬 변경을 보존한다. 적용된 migration을 수정하거나 로컬 DB를 임의 초기화하지 않는다.

## 문서와 인계

충돌 범위는 ADR-0008과 새 재설계/티켓이 우선한다. 과거 ADR/티켓의 완료 증거와 미검증 게이트를 보존하되 폐기 구조 재구현 지시로 읽지 않는다. [이전 시작점 원문](./history/start-here-before-storage-simplification.md)은 배경 이력이다.

종료 시 실제 완료/미완료, 변경 계약, 검사 결과, 다음 작업을 티켓에 남긴다. API 변경은 앱·MCP 설명·get_workflow_guide·검증과 함께 갱신한다. 문서만 수정한 것을 구현/배포 완료로 표시하지 않는다.
