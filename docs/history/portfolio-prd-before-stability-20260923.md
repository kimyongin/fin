# PRD — 매일의 판단을 이어가는 Portfolio

## 우선 적용: 현재값·활동 중심 저장 단순화 (2026-09-23)

[ADR-0008](../adr/0008-minimal-portfolio-storage.md), [단순성 원칙](../engineering/SIMPLICITY.md), [재설계](../design/minimal-portfolio.md)가 아래 과거 기준 중 충돌 범위를 대체한다. 보유 이유는 메모, 조사·판단·점검·회고는 활동, 예정·반복은 할 일로 관리한다. 과거 잔고 재생·자동 체결 진행률·일반 편집 의무 이력은 축소한다. 사용자는 구 투자 데이터 삭제를 허용했고, 새 데이터의 인증·소유권·공유 경계는 유지한다. 로컬 수직 구현과 회귀 검증은 진행됐지만 운영 적용·실제 ChatGPT 평가는 남았다. 현재 상태는 [시작점](../START-HERE.md)과 [운영 인계](../design/storage-release-readiness-20260923.md)를 확인한다. 아래 과거 계획/상태 문장은 작성 당시 이력이다.

## 현재 개발 기준 — 활동·결과·태그·검색 (2026-09-23)

최신 단순화: 기존 activity_events를 편집 가능한 활동 저장으로 활용한다. 별도 결과 테이블과 일반 편집의 의무 수정 이력·판단 정정 자동 분류는 제외한다. 자동 금융 원본의 보호와 기존 반복 동작은 유지한다. ADR-0007 및 #80~#85의 축소된 인수 조건을 따른다.

[새 설계](../design/activity-simplification.md)와 [ADR-0007](../adr/0007-activity-results-and-search.md)을 먼저 읽는다. 사용자에게 활동 하나로 할 일·한 일·결론을 제공한다. 판단 모아보기 탭과 등록 경로별 라벨을 제거하고 다중 활동 태그 및 조건·키워드·유사도 검색을 제공하는 계획이다. 물리적 판단 테이블 통합 여부는 #80에서 결정한다.

티켓 #80 계약 → #81 활동/결과 수직 통합 → #82 태그/기본 검색 → #83 하이브리드 검색. #84 문맥/MCP 가이드는 각 slice와 함께, #85 전환/검증은 첫 slice부터 진행한다. 이 문단은 당시 구현 순서이며 현재 구현 전이라는 뜻이 아니다. #75~#79 기반과 미검증 외부 게이트는 보존하고, 검색용 임베딩은 정본이 아닌 파생 데이터로 사용한다. 뉴스 조사·의견 생성은 ChatGPT가 담당한다.


## 현재 개발 기준 — 태스크・자동 행동 이벤트 (2026-09-22)

[설계](../design/tasks-and-events.md)와 [ADR-0006](../adr/0006-tasks-and-action-events.md)이 우선한다. 내부 태스크/이벤트는 분리하고 사용자에게는 예정된 행동과 수행한 행동을 하나의 목록으로 제공한다. 값 수정은 자동 이벤트, 태스크 완료는 연결 이벤트, 매일 반복은 회차별 유효 완료 이벤트로 기록한다. 영구 번들은 제거 방향이며 날짜별 표시와 요청 기반 일/주/월 리포트를 제공한다.

당시 순서: #75 자동 이벤트/일반 태스크 → #76 매일 반복 → #77 통합 목록 → #78 기간 리포트 → #79 전환/가이드/검증. 명세는 docs/tickets/action-timeline-01~05의 역사 기록이며, 새 저장 축소와 충돌하면 ADR-0008이 우선한다.

#69/#70 메모/운영 규칙은 유지한다. #71~#74는 로컬 구현/검증 이력을 보존하되 해당 후속 작업은 #75~#79로 대체한다. 기존 migration과 로컬 기록을 삭제하지 않는다. 운영 배포/사람 평가 완료를 뜻하지 않는다.

## 이전 개발 기준 — ToDo·원칙 통합 (대체된 설계 이력)
설계/티켓 작성 완료, 구현 전. [공통 설계](../design/todo-principles-integration.md)와 [ADR-0005](../adr/0005-todo-bundles-and-operating-rules.md)를 먼저 읽는다.
신규 순서: #69 기존 메모/확인 메모 → #70 원칙의 데이터 관리 규칙 → #71 ToDo 묶음 → #72 탐색/판단/활동 통합 → #73 오늘/MCP 연결 → #74 검증. 각 티켓은 docs/tickets/todo-principles-01~06 로컬 명세에 대응한다.
주 메뉴는 오늘/자산/ToDo/원칙으로 변경 예정이며 기존 대상 메모・조사/실행・판단・금융/활동 원본을 유지한다. 규칙은 독립 저장하고 관련 작업에서 조회하며, ToDo는 여러 작업을 한 묶음으로 기록한다.
아래 과거 메뉴·구현 전 표기·작업 순서는 작성 당시 이력이다. 충돌하는 범위에서는 이번 설계를 적용한다. 기존 미완료 검증은 자동 완료 처리하지 않는다.
GitHub 대조: #66/#68 closed, #67 실제 모델 평가 open. 피드백 기능은 구현되어 있으므로 아래 '아직 미구현'을 새 구현 지시로 읽지 않는다. 운영/평가 상태는 개별 최신 티켓을 확인한다.

상태: 제품 방향 합의, 로컬 핵심 구현 완료, 운영 배포·5일 파일럿 전 · 2026-09-21

## 목적과 문제

여러 계좌의 자산을 관리하면서 마지막 점검 이후 무엇이 달라졌고 내 기준에 비춰 무엇을 판단해야 하는지 빠르게 파악한다. 판단·질문·실행을 다음 점검까지 이어간다.
사용자가 겪는 문제는 수동 관리의 귀찮음, 증권사와 완벽히 일치시키려는 부담, 뉴스와 보유 이유를 매번 다시 연결해야 하는 수고다.
따라서 앱 사용·뉴스 수집·매매 횟수를 늘리는 것이 아니라 반복 입력과 판단 부담을 줄인다.

## 사용자와 사용 환경

- 본인과 초대한 지인이 각자의 포트폴리오를 사용하는 다중 사용자 앱이다. 개인 전용 하드코딩이나 공용 서비스 계정 데이터 모델을 사용하지 않는다.
- 모바일에서 자주 읽고 간단히 기록하고, PC에서 비교·대량 편집한다. 양쪽에서 핵심 기능에 접근할 수 있어야 한다.
- 사용자 인증과 명시적 공유를 구분한다. 개인 기준·판단을 기존 친구 공유에 자동 노출하지 않는다.
- 새 개인 기준·판단·브리핑·할 일은 기본 비공개이며 사용자가 선택적으로 공유할 수 있다. 체결가 평균 및 보정 기준점 정책과 함께 [ADR-0002](../adr/0002-cost-basis-reconciliation-and-sharing.md)를 따른다.
- 공유 구조는 [ADR-0003](../adr/0003-extensible-feature-sharing.md)의 기능별 read 권한으로 설계하고 UI는 권한 묶음으로 단순화한다. 친구별 예외·문서별 ACL은 첫 버전에서 제외한다.

## 제품 역할

ChatGPT는 조사하고 생각하고 설명하며, Portfolio는 기억하고 계산하고 검증한다.
뉴스 조사와 의견 생성은 ChatGPT에서, 계산·버전·관계·권한·저장 검증은 Portfolio에서 수행한다. 사용자는 판단을 채택하고 증권사에서 직접 주문한다.
Portfolio의 출처 검증은 URL·필드·참조 검증이지 기사 사실성의 보증이 아니다.

## 대표 시나리오

1. 출근길: ‘오늘 내 포트폴리오 점검하고 저장해줘.’ 기존 문맥과 열린 질문 → ChatGPT 조사 → 결론·근거·미확인 범위 저장 → 대화에서 확인. 앱 재방문은 선택이다.
2. 며칠 후 복귀: 마지막 브리핑 날짜만이 아니라 대상별 조사 범위·이전 미확인 항목·열린 질문에서 이어간다. 같은 사건을 매일 새로운 일로 복제하지 않는다.
3. 판단: 제안을 읽고 유지/변경/보류를 선택한다. 당시 원칙과 근거를 남긴다. 유지 결정에는 실행할 일이 없어도 된다.
4. 체결: 실제 매매의 계좌·종목·수량·가격을 기록하고 수량/평균가 변화를 확인한다. 사전 판단 문서나 계획은 필수가 아니다.
5. 불일치: 실제 현재 잔고로 보정한다. 과거 원장 전체 복원을 강요하지 않는다. 값 없는 실제 확인은 보정과 별도다.

브리핑은 한 줄 결론 → 중요한 변화 최대 3개 → 보유 이유 영향 → 관련 할 일 0~3개를 기본으로 한다. 전체 기록의 저장 상한이라는 뜻은 아니다.
추가 행동 없음 / 확인 필요 / 자료 부족 / 저장된 분석 없음·오래됨을 구분한다. 검색 실패를 변화 없음으로 표현하지 않는다.

## 기능과 메뉴의 목적

| 화면 | 사용자 목적 |
| --- | --- |
| 오늘 | 마지막 점검 이후 변화와 지금 확인할 일을 파악 |
| 자산 | 여러 계좌의 보유 종목·수량·평균가·비중 관리 |
| 판단·할 일 | 제안·채택한 결정의 근거와 다음 질문·실행 진행을 한 흐름에서 관리 |
| 투자 원칙 | 개인 투자 기준과 목표·적립·운용 제한 관리 |
| 자료 보관함 | 뉴스·출처 등 판단 근거 조회와 기존 자료 편집 |
| 활동 내역 | 데이터 변경과 저장 전후 값 감사 |
| 설정·사용 안내 | 계정·공유·연결 관리와 초기 사용 지원 |
| 피드백 (계획) | 앱·대화에서 발견한 불편과 제안을 쉽게 접수하고 처리 결과 확인 |

주 탐색은 앞의 네 항목, 나머지는 보조 진입이다. ‘배분 점검’은 자산의 ‘목표와 비교’로 연결하며 별도 주 메뉴를 늘리지 않는다.
자산의 기존 네 가지 보기와 입력 장점은 유지하고, 전략의 기준 편집과 상태 계산은 분리한다. 세부 대응표는 [제품 재정리](../design/product-reorganization.md)가 원본이다.

## 데이터 의미와 필수 제약

- 투자 원칙/운용 계획, 판단 기록, 조사·실행할 일, 실제 체결/잔고를 연결하지만 서로 대체하지 않는다.
- 앱에서 PRD/ADR/Ticket 문서 작성 절차를 사용자에게 요구하지 않는다. 이 문서들은 개발 문서이며 제품 데이터의 비유와 구별한다.
- 종목 태그와 전략 버킷, 투자 성향과 운용 모드를 구분한다.
- 사용자가 입력한 기준점/매매에 따른 수량·이동평균 원가는 정확해야 한다. 증권사 현금·세금·총수익과 자동 일치는 약속하지 않는다.
- 시장형·평가형·현금성·외화 자산의 기존 의미를 보존한다. 시세·환율 누락을 정상적인 0값으로 숨기지 않는다.
- 분석/조사 완료, 사용자 열람, 실제 잔고 확인은 각각 별개다. 과거 판단은 당시 기준·출처를 보존한다.

## 이번 범위 밖

제품 개선 피드백은 투자 판단·할 일과 별도 도메인으로 계획한다. 햄버거 자유 텍스트 입력과 ChatGPT 대화 등록을 같은 접수함에 연결하며, 구체적 불편에 등록을 제안하되 사용자 요청/동의가 있을 때만 저장한다. [피드백 설계](../design/product-feedback.md)와 후속 티켓이 구현 범위의 기준이다. 아직 제공 중인 기능은 아니다.

- 증권사 자동 주문·완전한 잔고 동기화 및 자동 뉴스 조사/예약 분석.
- Portfolio 서버의 별도 LLM API 도입, 필수 skill 패키지 배포, 공개 앱 심사 통과를 선행 조건으로 삼는 것.
- 모든 자산 화면 재작성, 전체 기본 접힘 적용, v3 밝은 테마로 전면 교체.
- 필수 투자 설문·매일 매매 유도·모든 과거 거래 입력·사용자 강제 왕복.
- 범용 워크플로 엔진/지식 그래프. 우선 관계형 데이터와 버전으로 해결한다.

## 성공과 인수

- 생성 대기와 별도로 약 60초 안에 중요한 변화와 다음 행동을 이해한다.
- 같은 배경 재설명, 중복 기록, 화면 왕복이 줄고 다음 점검이 이전 질문에서 이어진다.
- 기존 표 편집/집계/자료/공유 흐름이 의도한 위치에서 유지되고 데이터 손실·무단 공개가 없다.
- 실제 웹/모바일, 다중 사용자, 부분 실패·재시도·동시 변경을 검증한다. 실사용 5일을 관찰하기 전 습관 형성이 검증됐다고 하지 않는다.
- 계산·공개 필드·상태 전이 등의 미정 상세는 [시작 문서의 미정 계약](../START-HERE.md)에 담당 티켓과 함께 관리한다. PRD 작성은 #32 완료와 같지 않다.
