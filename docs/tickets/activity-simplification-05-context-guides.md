## 인수 조건

- [x] get_daily_context와 기간 리포트는 최신 활동 내용과 기존 태스크/판단 참조를 읽고 같은 활동의 중복 집계를 제거한다.
- [x] 사용자 채택과 모델 제안, 메모와 실제 후속 할 일을 구분한다. 새 판단 유효성 엔진이나 수정/새 판단 자동 분류를 도입하지 않는다.
- [x] 리포트는 생성 당시 저장된 요약이다. 원본 수정 시 `updated_at` 등 최소 정보로 재생성 필요를 알리고 자동 재작성하지 않는다. 원본 날짜 이동의 전후 기간도 고려하되 결과별 revision/digest 관리 체계를 새로 만들지 않는다.
- [x] 기간 조회·원본 참조·요청 시 생성과 과거 시점 복원 한계를 유지한다. 단순 결과 편집에 감사 이벤트를 강제해 리포트 변경을 감지하지 않는다.
- [x] 도구 설명/가이드는 등록·빠른 완료·같은 활동 편집·새 활동 추가·선택 후속 연결·태그/검색으로 정리한다. 별도 결과 ID나 기록 유형을 사용자에게 요구하지 않는다.
- [x] 명시적 기록 요청은 불필요한 재확인 없이 수행하고 선택 필드를 채우려는 반복 질문을 피한다. 조회만 요청했을 때 자동 저장하지 않고 금융 작업의 자동 이벤트를 중복 기록하지 않는다.
- [x] 기존 가이드 소스/tool-descriptions/workflows/review manifest와 구 도구 호환·비노출 계획을 기능별로 갱신한다. 구현 전 도구를 광고하지 않는다.
- [x] 계약 검사와 실제 ChatGPT 웹/모바일 평가를 구분하고 자동 검증으로 사람 평가 완료를 주장하지 않는다.

## 실행 기준

기존 문맥 snapshot과 리포트 원본 ID를 그대로 사용하고, 최신 현재 내용과 `updated_at` 비교만 추가했다. 일반 활동 불변성·별도 결과 저장·의무 수정 이력은 도입하지 않았다. 로컬 구현과 자동 계약 검증은 완료했지만 실제 ChatGPT 웹·모바일 평가는 운영 배포 후 별도로 기록한다.
