# [후속 정리] 활동 본문·출처 표시 재사용과 편집 모달 분리

우선순위: P2 · 상태: 로컬 구현 완료, 최종 E2E·운영 배포 전 · 2026-09-23
관련: #59, #60, #87 · 기준 코드: 8cb943f

## 문제와 근거

DailyReviewPage의 ReviewDetail, DecisionActivitiesPage의 DecisionDetail, ActivityDetailModal이 활동 제목·날짜·본문·결론·출처 표시를 중복 구현한다. LifecyclePage에는 신규 편집 모달, 할 일 상세, 화면 조회/저장이 함께 있다.

## 범위

- 저장/요청 안정화와 미사용 코드 제거 이후 현재 소비자가 2개 이상인 본문/출처 표시만 작은 표현 컴포넌트로 추출한다.
- GeneralActionModal과 할 일 상세를 기능 폴더 내 파일로 분리해 화면 조립 책임을 줄인다.
- ModalShell/ModalActions/MarkdownContent를 재사용한다. 서버 권한/저장 규칙은 표현 컴포넌트로 옮기지 않는다.
- 점검 상태·조사 범위, 판단 제안/채택/미채택, 금융 활동 편집 제한과 친구용 좁은 응답을 유지한다.
- 메뉴 변경·상세 DTO 통합·범용 폼/카드/페이지 엔진은 포함하지 않는다.

## 완료 조건

- [x] 세 화면에서 실제로 중복되던 본문·출처 표시를 `ActivityNarrative`로 모았다. 빈 필드는 숨기고, URL은 http(s)만 링크로 표시한다.
- [x] 전달된 DTO의 필드만 표시하며, 새 요청이나 권한 로직은 표현 컴포넌트에 넣지 않았다.
- [x] `GeneralActionModal`과 `GeneralTaskDetail`을 기능 내부 파일로 분리하되, 기존 `ModalShell`과 저장/닫기/뒤로가기 처리자를 그대로 유지했다.
- [ ] 전체 E2E에서 활동 등록·재조회·편집 및 모바일/데스크톱 회귀 결과 확인 예정.
