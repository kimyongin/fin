## 목적

모바일의 본문 공간을 늘리고, 누구의 데이터를 보는지·어떤 기능을 볼지·설정을 어디서 여는지 하단에서 선택한다. 각 탭의 최상단 카드는 짧은 문맥과 실제 데이터·기능으로 화면의 목적을 설명한다.

## 기존 구현과 재사용

- `src/components/AppHeader.jsx`가 상단 h1·포트폴리오 select·햄버거와 하단 네 탭을 함께 렌더링한다. 보조 메뉴는 피드백/설정/가이드/로그아웃이다.
- `src/App.jsx`의 `handlePortfolioChange`와 `viewContext`, 기존 요청 보호·공유 권한 조회를 재사용한다. 현재 전환 시 `overview`로 고정 이동하는 부분을 수정한다.
- `src/features/portfolio/data.js`의 `fetchViewerProfile`은 `profiles`의 공개 이름/공유 설정을, `fetchFriends`는 `list_friends`의 친구 소유자 ID/이름을 읽는다. 현행 DTO에는 선택형 아이콘이 없다.
- `SettingsPage.jsx`의 기존 내 공개 프로필 설정에 아이콘 선택을 추가한다. 별도 프로필 관리 화면·아이콘 테이블·이미지 업로드·이력 저장은 만들지 않는다.
- 상단 카드 표현은 `page-panel-guidelines.md`, 수정 중 이탈은 기존 모달/페이지 초안 보호를 재사용한다.

## 확정 UI 계약

하단 순서: `[현재 프로필 아이콘] [자산] [배분] [활동] [원칙] [메뉴 아이콘]`.

- 모바일·PC 모두 하단 고정. 프로필 아이콘은 현재 대상을 쉽게 알아보도록 약 1.3배인 32px로 표시하고 좌우 버튼은 최소 44×44px로 둔다. 가운데 네 탭은 남는 너비를 균등 배분한다. safe-area와 본문 하단 여백을 유지한다.

2026-09-26 사용자 후속 조정: 프로필 버튼은 44×44px의 투명한 원형 윤곽으로 표시하고 윤곽색은 메뉴 아이콘과 같은 전경색을 쓴다. 원 안의 프로필 그림만 32px에서 28px로 줄인다. 기존 프로필/메뉴 위치와 팝오버·접근성 동작은 유지한다.

후속 검증: `npm test` 102개, 빌드·인코딩 검사, 격리 DB 580개/MCP 계약과 360/390/768/1024/1440px 탐색 E2E 1개가 통과했다. 각 폭에서 원형 윤곽·1px 테두리·메뉴 아이콘과 같은 색·44px 조작 영역·28px 그림을 계산 스타일로 확인했다. 실기기 시각 검증·운영 배포는 아직이다.

사용자 캡처 확인 후 그림이 탭 글자와 메뉴 아이콘보다 과하게 커 보여 원형 버튼은 유지하고 내부 그림만 20px로 줄였다. 이전 28px 검증 기록은 조정 전 결과이며, 새 기대값의 브라우저 검증은 별도다.

후속으로 44px 윤곽도 과해 보여 클릭 영역은 44px로 유지하고 눈에 보이는 투명 원만 32px로 줄였다. 아이콘은 20px를 유지한다.

사용자 확인 후 흰 원이 과하게 강조되어 윤곽색만 밝은 전경색 대신 공통 보조 텍스트 색(`--muted-ink`)으로 낮췄다. 앞의 메뉴 아이콘과 같은 색이라는 시각 계약은 이 후속 조정으로 대체한다.
- 프로필 버튼에는 이름·`나`·화살표 등 텍스트를 표시하지 않는다. 메뉴 버튼도 아이콘만 표시한다. 프로필의 접근성 이름은 현재 대상 이름과 전환 동작, 메뉴는 `메뉴 열기`로 제공한다.
- 프로필을 누르면 푸터 위 목록에 `아이콘 + 나/친구 공개 이름 + 현재 선택 체크`를 표시한다. 같은 아이콘도 허용하며 이름은 목록에서 구분한다. 친구가 없어도 `나` 항목과 현재 아이콘을 표시한다.
- 프로필 목록과 보조 메뉴는 푸터에 연결된 가벼운 팝오버로 열고 동시에 하나만 연다. 선택·바깥 클릭·Escape로 닫으며 키보드 이동과 버튼으로 초점 복귀를 지원한다. 목록이 길면 화면 안에서 내부 스크롤한다. 프로필 목록에서 아이콘 편집창을 중첩해서 열지 않는다.
- 프로필 아이콘은 동물·과일 등 고정된 소규모 목록에서 선택한다. 기존 설정의 내 프로필 영역에서 선택·저장하며 저장 성공 후 내 푸터 아이콘을 갱신한다. 친구 아이콘은 친구 본인이 고른 값을 읽는다. 미설정/알 수 없는 값은 고정 기본 아이콘을 표시하고 랜덤 배정하지 않는다.
- 기존 피드백/설정/가이드/로그아웃을 오른쪽 메뉴에서 유지한다. 설정·피드백은 로그인한 나의 기능임을 명시하며 친구 계정의 설정처럼 보이지 않게 한다.
- 인증 후 포트폴리오 화면의 상단 앱 헤더와 그 여백을 제거한다. 로그인·게스트 진입·OAuth 동의 화면의 독립 제목/인증 흐름은 유지한다.

## 최상단 카드

| 탭 | 목적을 전달하는 문맥 | 함께 제공할 데이터·행동 |
| --- | --- | --- |
| 자산 | 전체 계좌/선택 계좌 평가액 | 평가액·시세 기준, 갱신/보유 추가/계좌 추가/표 편집, 아래 검색·필터 |
| 배분 | 태그별 현재·목표 비중 | 전체 계좌 범위·목표 합계, 태그 관리, 본문의 목표 편집 |
| 활동 | 할 일과 기록 | 활동 추가·태그 관리, 아래 검색어·기록 기간·태그 |
| 원칙 | 현재 투자 원칙 | 변경 시각·수정·마크다운 본문, 아래 이력 |

새 소개 카드를 추가하지 않고 기존 카드의 문맥을 간결하게 정돈한다. 불필요한 메인 수치나 설명을 억지로 만들지 않는다. 페이지당 의미 있는 h1을 최상단 카드에 두거나 시각적으로 숨긴 제목으로 유지한다. 설정/피드백/가이드도 본문 내 제목과 기존 조작을 유지한다.

## 데이터 대상과 전환

- 현재 선택 아이콘은 실제 본문 데이터 소유자와 일치해야 한다. 친구를 보는 동안 최상단 카드에는 이름 반복 없이 `공유 · 읽기 전용`을 표시한다. 이름은 프로필 목록과 접근성 안내에서 확인한다.
- 사람을 바꿀 때 가능한 경우 현재 주요 탭을 유지한다. 그 탭이 새 대상에게 허용되지 않으면 기존 권한 기준의 첫 허용 탭으로 이동하고 간단히 안내한다. 아무 탭도 허용되지 않으면 공유 접근 불가와 내 포트폴리오 복귀를 제공한다.
- 전환 시 이전 소유자의 계좌·태그·검색 결과·선택 상세를 비운다. 새 아이콘 아래에 이전 사람의 데이터를 잠시 보여주지 않는다. 늦은 요청을 무시하고 로딩/실패/재시도를 명시한다.
- 미저장 모달 또는 배분/표 편집 초안은 기존 이탈 보호를 적용한다. 취소하면 대상·초안 모두 유지한다. 모달이 열려 있으면 하단 탐색은 기존 inert 정책을 따른다.
- 공유 해제/친구 삭제 후 접근을 유지하지 않는다. 게스트는 권한 있는 현재 대상 아이콘만 표시하고 다른 사람 목록을 노출하지 않는다. 내 설정 같은 개인 화면에서는 프로필 전환을 제공하지 않고 내 아이콘을 표시한다.

## 최소 저장·API 계약 — 구현 결과

- 기존 `profiles`에 선택 아이콘의 안정 키 하나를 추가하는 최소 변경을 우선한다. 허용 키만 저장하고 외부 URL/임의 HTML을 받지 않는다. 본인만 수정할 수 있게 한다.
- 기존 프로필 저장 경로를 확인해 아이콘만 바꿀 때 공개 이름이나 공유 비밀번호 설정을 요구하거나 변경하지 않게 한다. 필요할 때에만 목적별 작은 저장 함수를 추가한다.
- 내 프로필 조회와 권한 있는 친구/게스트 조회에 아이콘 키를 추가한다. 프로필 전체 공개 범위를 넓히지 않는다. 기본값은 기존 사용자 행을 파괴적으로 재작성하지 않고 처리한다.
- migration/RLS·DTO 영향과 최종 키/필드명은 구현 티켓에 기록한다. 아이콘은 앱 탐색용이며 투자 MCP 도구나 워크플로우 가이드에 별도 편집 기능을 추가할 필요가 없다.

구현에서는 `profiles.avatar_key`를 허용 목록과 기본값 `bear`로 추가했다. `app_set_profile_avatar(text)`는 인증한 본인의 키만 저장한다. 기존 이름·비밀번호 저장 RPC는 바꾸지 않았다. `list_friends`와 `get_active_viewer_access`에는 접근 가능한 소유자의 `owner_avatar_key`만 추가했다. 새 테이블이나 MCP 도구는 없다. 일반 로컬 DB에는 이 migration만 적용했고 운영 DB에는 적용하지 않았다.

## 문서 관계

이 티켓은 #136의 상단 카드·필터 원칙을 유지하면서 앱 헤더가 제목/전환/메뉴를 소유한다는 부분을 대체한다. 네 주요 탭·공유 권한·계산 의미는 유지한다. 기존 로컬 미커밋 작업과 사용자 설정을 보존했다. 로컬 구현은 운영 배포 완료를 뜻하지 않는다.
