# [안정화 재검토] 필수 저장 RPC 누락을 잡는 배포 호환성 검사

우선순위: P1 · 상태: 티켓 작성, 구현 전 · 2026-09-23
관련: #91, #97, #92 · 기준 코드: b7ee31d

## 문제와 근거
`scripts/check-deployment-readiness.mjs`는 일부 조회 RPC와 OAuth MCP initialize/tools-list만 확인한다. 새 app_create_activity_with_tags/app_create_general_task_with_tags RPC가 없는 환경에서도 현재 검사를 통과할 수 있다. UI는 두 함수를 직접 호출한다.

## 범위
- 현재 웹/MCP가 필수로 사용하는 RPC의 최소 호환성 목록을 확정하고 이름뿐 아니라 입력 시그니처 누락도 검출한다.
- 운영 데이터에 쓰지 않는 확인 방법을 먼저 선택한다. 메타데이터/노출 스키마 확인 또는 안전한 거부 응답 검증 중 실제 환경에서 검증 가능한 최소 방법을 사용한다.
- 무효 입력 호출을 사용한다면 데이터 변경 없이 실패하는 경로임을 격리 DB에서 입증한다. 서비스 키를 브라우저나 출력에 노출하지 않는다.
- 운영 readiness와 격리 E2E 역할을 유지한다. DB/Edge/웹 적용 순서와 준비 실패 복구 안내를 runbook에 연결한다.

## 완료 조건
- [ ] 격리 환경에서 필수 RPC 하나 누락/시그니처 불일치 시 배포 준비 검사가 실패한다.
- [ ] 현재 정상 스키마에서는 검사에 성공하고 데이터가 변하지 않는다.
- [ ] MCP 도구 이름 존재만으로 서버 저장 계약 준비 완료를 판단하지 않는다.
- [ ] 인증 실패·RPC 누락·권한 오류를 구별해 비밀값 없이 진단한다.
- [ ] 로컬 검증과 실제 운영 readiness 실행 여부를 따로 기록한다. 이 티켓 작성은 배포 실행 지시가 아니다.

## 진행 규칙

- docs/START-HERE.md, ADR-0008, SIMPLICITY.md와 관련 티켓을 먼저 읽는다. UI 변경 전 디자인 원칙/컴포넌트 규칙, DB 변경 전 schema/OVERVIEW를 확인한다.
- 필요한 기존 helper와 목적별 API를 재사용해 수직 슬라이스로 구현·검증·커밋한다. 사용자 로컬 설정과 무관한 변경은 보존한다.
- 기존 티켓의 검증 기록은 유지하고 새 결과를 교차 연결한다. 코드 검토로 추론한 문제와 실제 재현 결과를 구분한다.
