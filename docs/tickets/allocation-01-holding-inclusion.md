# 계좌별 보유의 배분 포함 여부

2026-09-27 · Astra 설계, Sol 구현. 사용자는 계좌 단위가 아닌 **계좌별 보유 항목 단위**를 승인했다.

GitHub: [#160](https://github.com/kimyongin/fin/issues/160).

## 목적과 근거

비상금·지출 예정 자금도 자산에는 등록하되 투자 비중과 리밸런싱 제안에서 제외한다. 목표 0%는 분모에서 제외하는 의미가 아니므로 대체할 수 없다.

- 피드백: `4c009442-87cf-4e20-8f52-760afe1464a5` (2026-09-27, MCP 접수).
- 현재 `usePortfolioDerivedData.js`는 모든 보유를 종목별로 합산한 후 `tagCards`를 만들고, `StrategyPage.jsx`는 전체 `totalValue`로 비중을 계산한다. 종목 합산 이전에 포함 여부를 적용해야 한다.
- #121의 태그별 목표·미분류·100% 계약, #153의 자산 HTTP/OAuth 관리, #159의 저장 확인·활동 원자 저장을 재사용한다.
- PRD, ADR-0008/0009, 단순성 원칙과 모달·페이지 상단 가이드를 따른다. 새 계좌/종목/태그별 중복 설정이나 제외 전용 테이블은 만들지 않는다.

## 최소 계약

1. 기존 `holdings`의 각 행에 boolean `include_in_allocation` 하나를 추가한다. 기존 행과 새 행의 기본값은 true, null은 허용하지 않는다. 정본은 보유 행 하나다.
2. 동일 종목도 A계좌 보유는 포함, B계좌 보유는 제외할 수 있다. 시장형·현금성·평가형 모두 적용한다. 계좌 자체/종목 공통/태그에는 포함 flag나 상속 우선순위를 두지 않는다.
3. false여도 자산 조회·잔고·총평가액·가격 갱신·사용자의 명시적 매매/보정은 유지한다. 배분 제외는 접근 제한이나 거래 금지가 아니다.
4. 수량/평균가 수정, 매매, 표 편집·엑셀 입력 등 기존 행 갱신에서 필드 생략은 기존값 유지다. 신규 행 생성 시 생략만 true다. 잘못된 타입/null은 거부한다. 계좌 이동으로 동일 보유를 갱신하면 설정도 유지한다. 명시적으로 삭제 후 신규 등록하면 새 행의 기본값을 적용한다.
5. 기존 보유 충돌 검사·멱등성·원자 저장을 재사용한다. 포함 여부만 바뀌어도 보유 상태 버전을 갱신하고 하나의 변경 활동에 반영한다. 별도 이력/버전 저장소는 만들지 않는다. 무변경 저장·동일 재시도로 활동이 중복되지 않는다.
6. 기본 대표 태그는 기존처럼 종목 공통이다. 용도는 계좌 이름/메모·종목 메모로 설명한다. 보유별 메모를 복원하지 않는다.

## 계산과 조회

- 전체 자산 합계는 기존 전체 보유 기준을 유지한다. 자산 화면의 계좌/검색/태그 필터 의미도 유지한다.
- 배분은 **전체 계좌 중 포함된 보유**만으로 태그별 평가액, 분모, 파이 차트, 현재 비중, 목표 대비 차이를 계산한다. 자산 검색 조건에 따라 바뀌지 않는다.
- 같은 종목을 포함/제외 양쪽 계좌에서 보유해도 포함분만 태그 합계에 더한다. 포함된 미분류 보유도 분모와 미분류 행에 포함한다.
- 목표는 기존 태그별 100% 계약을 유지한다. 제외 설정 때문에 목표값/태그를 자동 삭제하거나 재분배하지 않는다. 특정 태그 보유가 모두 제외돼도 설정된 목표는 유지한다.
- 전체/배분 대상/제외 평가액은 저장하지 않는 파생값이다. 기존 평가·환율 규칙을 재사용하고 양쪽 인터페이스의 수치 fixture를 일치시킨다.
- 평가 품질은 전체·포함·제외 범위별로 구별한다. 제외 보유의 시세/환율 누락만으로 포함분 비중을 막지 않는다. 포함분 누락 시 정확한 비중·차이·차트는 계산 불가다. 누락액을 0으로 확정하지 않으며 부분 합계는 `확인 가능한 평가액`으로 표시한다.
- 포함 합계가 0이거나 전부 제외된 경우 차트/비중/차이는 계산 불가 안내, 목표 편집은 유지한다. 오래된 시세는 기존 경고 정책을 적용한다.
- 읽기 전용 공유에서도 같은 설정·합계·품질을 제공하되 변경은 소유자만 가능하다. 다른 소유자로 전환할 때 이전 계산/초안을 남기지 않는다.

## 웹 UX

- 자산 상세의 **계좌별 보유 카드 안**, 수량/금액 필드 다음에 `배분에서 제외` 체크를 둔다. 기본은 체크 해제(배분에 포함)이며, 체크하면 해당 보유만 제외한다. 종목 공통 영역이나 계좌 설정창에는 두지 않는다. 이는 2026-09-27 사용자 확인으로 초기 `배분에 포함` 체크 표현을 대체하며 저장 필드의 의미는 바꾸지 않는다.
- 체크는 상세 초안이며 기존 하단 저장으로 함께 확정한다. 별도 설정 모달·즉시 저장을 만들지 않는다. 기존 저장 확인에서 선택 메모·활동 태그를 함께 받아 원자 저장한다. 실패/확인 취소 시 초안을 유지한다.
- 체크 옆 도움말은 필요한 최소 문장 `체크해도 자산 합계에는 포함됩니다.`로 한다. 기존 공통 체크/라벨 스타일과 조작 영역을 재사용한다.
- 배분 요약의 기존 전체 계좌 평가액 표현을 `배분 대상 {금액} · 제외 {금액}`으로 바꾼다. 제외 행이 없으면 제외 부분은 생략한다. 제외 금액이 0이어도 제외 행이 있으면 범위가 있다는 사실을 표시한다. 전체 자산 합계는 자산 탭에서 확인하므로 새 요약 카드를 중복 추가하지 않는다.
- 자산 목록에 복잡한 보유별 상태 열은 추가하지 않는다. 제외 여부는 계좌별 상세에서 확인한다. 표 편집에도 `배분에서 제외` 열을 제공하되 서버의 `include_in_allocation`과 경계에서 반대로 변환한다. CSV 내보내기/붙여넣기 왕복과 이전 `배분에 포함` 헤더 입력의 의미 보존을 검증한다.
- 360/390/768/1024/1440px에서 긴 계좌명·두 계좌 이상·체크/저장/실패/공유 읽기 전용을 확인한다. 라벨과 체크는 키보드로 조작 가능해야 한다. 불필요한 접기·중첩 모달은 추가하지 않는다.

## HTTP · OAuth MCP · 가이드

- 기존 보유 생성/수정 및 자산 상세/표 편집 저장 계약에 optional boolean을 추가한다. 별도 범용 설정 API나 계좌 일괄 설정 API는 만들지 않는다.
- `get_portfolio_state`, 보유 검색/단건 상세, 배분/점검 문맥 등 실제 소비 경로에서 포함 여부가 누락되지 않게 한다. 기존 전체 자산 합계의 의미를 배분 합계로 바꾸지 않는다.
- 기존 포트폴리오 조회 응답에 배분 대상/제외 합계·범위별 품질·태그별 포함 평가를 명시적으로 제공하고 웹과 동일한 계산 계약을 검증한다. 기존 전략 목표 조회를 전체 자산 계산 엔진으로 확장하지 않는다. 정확한 응답 필드와 소비 경로 목록은 첫 슬라이스에서 티켓에 기록한다.
- 도구 schema/description·작업 가이드·review manifest를 함께 갱신한다. 에이전트는 제외 보유를 리밸런싱 제안이나 투자 가능 현금에 넣지 않는다. 사용자가 명시적으로 요청한 보정/매매를 서버가 금지하는 규칙은 아니다.
- 신규 생성→반대 인터페이스 조회, 웹 제외→MCP 확인, MCP 재포함→웹 재조회까지 실제 검증한다. 기존 공유 allowlist와 소유권 검사를 유지한다.

## 제외 범위와 인계

한 보유 안에서 일부 금액만 제외하는 예약금 기능, 계좌 전체 토글, 규칙 상속, 자동 매매/리밸런싱 실행, 별도 제외 이력·테이블은 범위 밖이다. 첫 버전은 보유 행 전체의 포함/제외다.

## 구현 계약과 검증

- `holdings.include_in_allocation`이 정본이다. `app_get_portfolio_state`의 기존 `holdings[]`에 이 값이 포함되고, 새 `allocation` 객체가 `known_total_krw`, `known_included_krw`, `known_excluded_krw`, 범위별 보유/누락 수, `included_is_complete`, 포함분 `tag_values`를 제공한다. 숫자는 확인 가능한 평가액이며 누락 상태는 별도 필드로 판단한다.
- 자산 상세 `app_save_asset_detail_with_activity`와 표 편집 `app_bulk_save_portfolio_rows`에 optional boolean을 연결했다. 새 행은 true, 기존 행은 생략 시 이전 값 유지, 명시적 null/다른 타입은 거부한다. 상태 버전 트리거와 활동 저장은 기존 계약을 사용한다.
- 웹 배분 파이·목표 대비 현재 비중은 보유 행 필터링 후 태그별 집계한다. `find_holdings` MCP 읽기도 보유 flag를 노출한다. MCP `save_asset_detail`은 같은 HTTP RPC를 호출한다.
- `CSV 복사`는 표 편집의 입력 열을 먼저 내보내고, 현재 평가액·현재가·수익률을 읽기 전용 참고 열로 뒤에 붙인다. 붙여넣기는 참고 열을 무시하고 입력 열의 `true`/`false` 설정을 복원한다.
- 후속 UI 변경: `배분에서 제외`는 자산 상세에서 기본 체크 해제, 표 편집에서 기본 `아니요`다. 두 입력 모두 저장 직전에만 기존 `include_in_allocation` boolean으로 뒤집어 전달한다. 읽기 전용 상세·저장 확인도 제외 관점으로 표시한다.
- 후속 변경 검증: 단위 24파일/118건, 빌드·인코딩 검사, 격리 DB·OAuth MCP 계약·자산 브라우저 E2E 10건 통과. E2E의 보유 상세는 360/390/768/1024/1440px에서 체크 기본값, 변경 후 저장, 실패 후 재시도와 화면 넘침을 확인했다. 표 편집의 새/기존 행·CSV 왕복과 이전 헤더 변환은 단위 검사로 확인했다. 실제 모바일 기기와 표 편집의 수동 시각 점검은 아직 수행하지 않았다.

## 2026-09-27 배분 제외 목록 후속 구현

- 사용자 승인 시안에 따라 상단의 작은 `제외` 합계 문구를 태그별 목록 아래 `배분 제외 보유` 구역으로 옮겼다. 같은 종목도 계좌별 별도 행이며 종목·계좌·확인 가능한 평가액을 보여준다. 평가 누락은 `평가 불가`로 표시하고 부분 합계 사유를 별도 안내한다. 제외가 없거나 자산 공유가 허용되지 않은 화면에는 구역을 표시하지 않는다.
- 제외 항목을 선택하면 해당 계좌 범위의 자산 종목 상세를 연다. 기존 전체 자산/배분 계산과 저장 계약은 바꾸지 않는다. 로컬 단위 24파일/119건, 빌드·인코딩·diff 검사, 격리 DB 725건과 OAuth 계약 및 관련 Chromium 2건 통과. 360/390/768/1024/1440px에서 가로 넘침을 확인했다. 공유 화면·실기기 시각 확인은 남아 있다.
- 단위 검사: 24 파일/118 테스트 통과(후속 UI 변경 포함). 격리된 DB: 기존 58 파일/713 테스트와 신규 `holding_allocation_inclusion_test.sql` 12 테스트. OAuth MCP 계약, 배포 준비 검사, 자산 E2E 10건 통과. `npm run check:edge`는 이 환경에 Deno 실행 파일이 없어 직접 실행하지 못했으며, MCP 계약 검사는 격리 E2E에서 통과했다.
- 남은 실사용 확인: 배포 후 실제 계정의 공유 화면, 실제 ChatGPT OAuth, 외화·평가형·미분류·전부 제외·목표만 있는 태그의 시각 상태, Excel 왕복, 모바일 실기기. 자동 테스트는 해당 상태를 모두 대체하지 않는다.

운영 DB 변경·푸시·배포는 이 구현 단계에서 수행하지 않는다. 사용자 로컬 설정과 무관한 dirty 파일은 보존한다.
