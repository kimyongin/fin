# [MCP-first] Portfolio 오늘 화면과 지인용 OAuth 온보딩

## 구현 진행 (2026-09-21)

- 소유자의 기본 진입을 `오늘`로 바꾸고 최신 저장 브리핑의 분석 시각·결론·행동 상태·조사 품질을 먼저 표시한다. 새 분석은 앱이 자동 생성하지 않고 ChatGPT 요청 문구를 명확히 복사한다.
- 브리핑 이력과 상세에서 중요한 변화, 불확실성, 대상별 조사 범위, 확인 출처 수, 근거 링크를 읽는다. 원본 context snapshot은 화면에 그대로 노출하지 않는다.
- 새 기능의 공유는 아직 기본 거부이므로 친구/익명 공유 화면에서는 `오늘` 메뉴를 숨긴다. 기능별 공유 DTO 구현 후 별도 확장한다.
- 390×844 E2E에서 브리핑 저장→새로고침→최신 결론→상세와 가로 넘침 없음을 검증했다. 360/768/1024/1440 및 키보드·포커스 검증은 남았다.
- 소유자 메뉴에 `판단`·`할 일`을 추가하고 목록/상세에서 채택 여부, 이유, 불확실성, 재검토 조건, 연결 질문을 읽도록 했다. 신규 민감정보 공유 DTO 전이므로 친구/익명 화면에서는 두 메뉴를 숨긴다.

## 구현 인계 확정 사항 (2026-09-20)

- 필독: [ADR-0002](https://github.com/kimyongin/fin/blob/master/docs/adr/0002-cost-basis-reconciliation-and-sharing.md), [ADR-0003](https://github.com/kimyongin/fin/blob/master/docs/adr/0003-extensible-feature-sharing.md), [구현 계약 초안](https://github.com/kimyongin/fin/blob/master/docs/design/implementation-contract-draft.md).
- 단순 공유 UI는 기능별 권한 묶음을 조작한다. ‘투자 점검 기록도 공유’는 브리핑/판단/할 일 묶음의 UI 제안이며 본문·기존/향후 기록·대상 범위를 미리 보여준다. 친구별 예외/문서별 ACL은 첫 버전에서 구현하지 않는다.
- 문서화는 구현/배포/보안 검증 완료가 아니다. 미검증 DDL·정밀도·상태 전이는 해당 티켓의 첫 작업으로 남기며 완료 체크를 앞당기지 않는다.

## 목적 중심 화면 재구성 — 기존 overview 대체 금지
- 기준: [제품 재정리](../design/product-reorganization.md), [디자인 원칙](../design/PRINCIPLES.md). prototype v1~v3는 참고 자료이며 v3 자산 구조를 구현 명세로 쓰지 않는다.
- 주 탐색은 오늘/자산/판단/할 일/원칙. 오늘은 별도 화면이며 기존 자산 overview 위에 큰 브리핑을 삽입하지 않는다.
- 자산의 태그/계좌/종목/표 편집과 기본 정보 표현을 유지한다. 기본 전체 접힘·강제 카드 교체를 하지 않고 보유 이유/관련 판단/확인 상태 진입을 추가한다.
- 전략 재구성은 #43이 원칙·운용 계획 편집 및 배분 점검 본문을 담당한다. 이 티켓은 원칙 메뉴와 자산의 ‘목표와 비교’ 진입·오늘 요약을 연결한다.
- 뉴스는 판단/브리핑의 근거 및 자료 보관함으로, 활동 기록은 보조 메뉴로 이동한다. 직접 자료 편집과 감사·CSV 기능은 제거하지 않는다.
- 기존 어두운 테마·공통 컴포넌트를 기반으로 통합한다. 모바일 우선은 기존 기능 축소의 근거가 아니다.
- 기존 #overview/#accounts/#instruments/#sheet/#strategy/#news/#activity 등의 진입을 보존하거나 의미에 맞는 목적지로 안내한다. 내/친구 포트폴리오 문맥도 유지한다.
- 구현 단위: A 탐색과 기존 화면 연결 → B 오늘/판단/할 일 및 상세 → C 자료/활동 재배치·OAuth 온보딩. 각 단계에서 데이터 없는 상태도 동작해야 한다.
- [ ] 대표 자산 작업을 이전과 비교하고 변경한 진입/표현은 이유를 기록한다.
- [ ] 360/390/768/1024/1440px, 터치 크기, 미저장 편집 이탈, 필터/위치 복귀를 검증한다.
- [ ] 누락 시세·환율 상태와 계좌 전체 합계/필터된 목록 범위를 표시한다. 계산은 #34 계약을 사용한다.

## 사용자 용어와 연결된 화면
- PRD/ADR/Ticket 대신 “투자 원칙”, “판단 기록”, “할 일”을 사용한다.
- 판단 상세에서 당시 원칙·선택 이유·관련 근거·다음 할 일·연결된 실제 매매를 따라갈 수 있게 한다.
- 할 일은 조사·점검/실행으로 구분하고 각각 자료 대기 또는 체결 진행 상태를 보여준다.
- 사용자가 문서 세 종류를 작성해야 매매를 기록할 수 있는 절차를 만들지 않는다. 일상 대화와 간단한 입력으로 기록을 연결한다.
- [ ] 실행할 일 완료 버튼만으로 잔고가 변경되지 않으며 부분 체결이 정확히 표시된다.

## 질문을 이어가는 화면 — #44 연계
- 브리핑 상세에서 중요한 변화가 어떤 이전 판단/열린 질문에 연결되는지 읽을 수 있게 한다.
- 검토 질문별 다음 확인 조건, 상태와 마지막 근거를 보여주고 사용자 보류/종료·재검토 진입을 제공한다. 근거 기반 질문 해결과 사용자 할 일 완료를 구분한다.
- 초안/부분 조사/완료 및 미확인 범위를 짧게 표시한다. “저장됨”을 “모든 조사 완료”로 표시하지 않는다.
- 사용자가 직접 분석을 요청하는 방식에 맞춰 최근 분석과 새 점검 진입만 제공한다. 자동 생성·예약을 현재 구현에 포함하지 않는다.
- [ ] 같은 뉴스와 미해결 질문을 매일 새 할 일처럼 복제하지 않고 이전 기록에서 이어지는지 확인한다.

## 투자 기준 화면 연결 — #43 연계
- 투자 기준 편집·기존 상세 원칙 노출 문제의 조사/수정은 #43이 담당한다. 이 티켓은 전략 화면으로의 진입과 오늘 브리핑의 적용 기준 표시를 담당한다.
- 사용자 기준, 운용 모드/비중, 종목별 이유를 구분해 보여준다. 원칙 미입력이어도 브리핑 진입을 막지 않는다.
- 실제 노출을 확인하기 전에는 상세 원칙을 현재 사용 가능한 기능으로 안내하지 않는다.
- [ ] #43에서 저장한 기준과 오늘 의견의 “적용한 내 원칙”을 모바일에서 확인한다.

## 오늘 화면 구성과 이동 부담
- 오늘 화면은 최근 브리핑 날짜/한 줄 결론 → 주요 변화 → 보유 이유 영향 → 오늘 할 일 순서로 구성한다. 시세와 전체 자산 상세는 이어서 열 수 있게 한다.
- 출처/전체 분석은 펼치기로 제공하고 거래·매도 중심 버튼을 기본 행동으로 강요하지 않는다.
- 새 브리핑이 없으면 “최근 분석: 날짜”를 그대로 보여준다. 조회 시각을 분석 생성시각으로 표시하지 않는다.
- “오늘 점검하고 저장해줘” 복사와 검증된 ChatGPT 진입 경로를 제공한다. 앱 복귀 없이 ChatGPT에서 결과 확인까지 끝낼 수 있다.
- 종목 상세에는 #41의 선택적 보유 이유/재검토 조건을, 잔고에는 #42의 마지막 확인 범위를 표시한다.
- 신규 사용자 입력은 자산 유형별 최소 현재값(시장형 수량·평균가, 평가형 금액, 현금 잔액)으로 제한한다. 보유 이유와 전략을 길게 쓰도록 강요하지 않는다.
- #41/#42의 데이터 계약 확정 후 화면 구현이 가능하며 두 기능 연동은 최종 인수 범위에 포함한다.
- 잔고 미확인 상태는 차분한 안내로 표현하고 매일 반복 확인을 요구하지 않는다.

### 추가 완료 조건
- [ ] 사용자 한 명이 ChatGPT만으로 아침 점검·저장을 끝내고, 필요할 때 앱에서 같은 결과를 읽는다.
- [ ] “할 일 없음”, “자료 부족”, “새 분석 없음”의 화면을 각각 검증한다.
- [ ] 생성 대기 시간을 제외한 약 60초 안에 주요 변화와 다음 행동을 파악하는지 파일럿에서 평가한다.

## 목적
앱을 열었을 때 “오늘 무엇을 확인해야 하는지”와 최근 분석 결과가 즉시 보이게 한다.

## 범위
- 별도 오늘 화면에 최근 브리핑·기준시각·핵심 변화·검토할 항목을 표시하고 기존 자산 overview와 연결한다.
- 브리핑 없음/과거 브리핑/오늘 작성됨 상태를 구분한다. 작성됨은 열람이나 실제 잔고 확인을 의미하지 않는다.
- ChatGPT에서 점검할 수 있는 짧은 시작 문구와 복사 동작을 제공한다. 검증되지 않은 딥링크·자동 프롬프트 전송에 의존하지 않는다.
- 매매 입력과 잔고 보정 진입점을 간단히 제공한다(해당 기능 완료 전에는 활성화하지 않는다).
- 앱 가입→초기 잔고→개인 MCP 주소 등록→OAuth→첫 점검을 안내한다.
- 기존 GuidePage의 agent-token 중심 안내를 OAuth 방식과 구분한다.
- 사용 가능 요금제/계정/모바일 UI는 지인 계정으로 검증하고 관찰일을 남긴다.
- 출근 시간 알림/PWA/예약 실행은 사용성 확인 뒤 후속으로 분리한다.

## 완료 조건
- [ ] 모바일 첫 화면에서 최근 브리핑과 자료 시점을 스크롤을 최소화해 확인한다.
- [ ] 지인 테스트 계정이 별도 skill 설치 없이 첫 점검·저장·앱 재열람을 완료한다.
- [ ] 다른 사용자 계정 데이터 및 친구 공유 데이터가 본인 데이터로 섞이지 않는다.
- [ ] 빈 상태/실패 상태/오래된 브리핑에서 다음 행동이 명확하다.
