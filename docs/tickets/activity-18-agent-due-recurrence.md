# [활동/MCP] 비정기 에이전트 요청을 위한 반복 일정·실행 대상 조회

GitHub: https://github.com/kimyongin/fin/issues/133

## 사용자 시나리오

사용자가 `매주 월·목 오전 8시 포트폴리오를 점검하고 근거와 결과를 기록`이라는 할 일을 등록한다. 비정기적으로 ChatGPT에 접속해 “할 일 있는지 확인해보고 진행해”라고 한다. Portfolio가 처리할 대상을 계산하고 ChatGPT가 조사·실행·설명한 뒤 결과와 완료를 남긴다. 자동 스케줄 실행/푸시 알림이 목적이 아니다.

## 사용자 설정과 표시

2026-09-26 UI 후속 설계 [#144](./activity-19-recurring-list-actions.md): 반복 회차의 `이번 완료`와 전체 `중단`을 목록에서 구분하고 상세의 종료 버튼을 제거한다. 웹 목록에는 완료/예정인 활성 반복도 남겨 중단할 수 있게 하되, 에이전트 실행 대상은 기존 미처리 도래 회차만 유지한다. 구현 전이며 아래 완료/종료의 의미는 바꾸지 않는다.

- 반복 없음: 선택적 예정일·시간. 매일: 시작일(오늘 기본)·선택적 시간. 매주: 시작일·요일 복수 선택·선택적 시간. 시간대는 기존 할 일 timezone을 재사용하고 화면과 MCP에 노출한다.
- 매주에는 요일 최소 하나가 필요하다. 시간 미설정은 해당 날짜 00:00부터 도래로 본다. `매주 월·목 오전 8시`처럼 결과를 한 줄로 보여준다.
- 할 일 본문/기존 설명에 수행할 내용과 남길 결과를 적는다. 새 작업 유형·실행자 분류 필드·범용 워크플로우 모델은 만들지 않는다.
- 상세 한 폼에서 일정도 함께 편집·저장한다. 회차 완료와 반복 전체 종료/삭제를 구분하고 일시정지/재개는 추가하지 않는다. 기존 기록은 보존한다.

## 실행 대상과 완료 계약

- 서버가 현재시각·할 일 시간대로 예정 시점이 지났고 미처리인 할 일을 계산한다. 예정일 없는 일반 미완료 할 일도 대상이다. 미래 예정/종료/일반 완료는 제외한다.
- 장기간 미접속으로 여러 회차가 지났어도 최신 도래 회차 한 번만 수행한다. 회차별 미완료 행/카드를 미리 만들거나 지난 분석을 날짜별로 재생하지 않는다. 예: 월·목 반복을 금요일에 확인하면 목요일 회차를 한 번 처리한다.
- 반복 정의는 기존 할 일 행, 수행 결과는 기존 활동 기록과 연결한다. 오늘 단위 처리에서 일정상 최신 도래 회차 처리로 확장한다. 일정 계산은 웹/MCP가 각자 추측하지 않고 서버 계약을 공유한다.
- 조회는 읽기 전용이며 실행/완료를 만들지 않는다. 응답에는 대상 ID·본문·반복 요약·도래 회차 식별값/예정시각·시간대·기존 완료 확인에 필요한 최소 정보만 제공한다. 완료 요청은 조회한 회차를 지정하고 서버가 소유권/일정/이미 완료 여부를 검증한다.
- 실제 성공 후 결과 기록과 회차 완료를 원자 처리한다. 완료된 같은 회차의 재시도는 기록을 중복 생성하지 않는다. 수행 중 새 예정 시각이 지나더라도 조회한 회차를 몰래 다른 회차로 바꾸지 않는다.
- 실패·자료 부족·사용자 확인 필요는 완료로 처리하지 않는다. 이유는 필요한 경우 기존 활동 기록에 남기고 할 일은 미완료로 둔다. 별도 실패 이력 테이블/복잡한 상태 머신은 없다.
- 완료 기록을 나중에 편집/삭제해도 완료 상태를 되돌리지 않는 기존 계약을 유지한다. 따라서 편집 가능한 활동 본문의 존재 여부만으로 실행 대상을 판정하지 않는다. 최소 완료 표식은 기존 할 일/완료 계약에서 재사용한다.
- 반복 일정 수정은 기존 완료를 지우거나 같은 날 중복 실행을 유도하지 않게 한다. 정확한 회차 키·일정 변경 이후 기준은 아래 첫 기술 계약에서 예제와 함께 확정한다.

## MCP와 가이드

- 기존 할 일 생성/수정/조회/완료 도구와 get_workflow_guide를 우선 확장한다. 실행 대상 조회가 기존 조회 옵션으로 가능한지 확인하고, 불가능할 때만 목적별 읽기 도구 하나를 추가한다.
- 가이드는 조회→수행 가능/확인 필요 구분→업무 수행→출처/결과 저장·완료→성공/미완료 보고를 설명한다. 일반 검색의 최근 30일 필터를 실행 대상 조회에 적용하지 않는다.
- “진행해”는 모든 외부 행동의 포괄 승인으로 해석하지 않는다. 실제 매매, 외부 전송, 파괴적 변경 및 사용자 판단이 필요한 일은 권한 범위에 따라 확인하고 허위 완료하지 않는다.
- 실행 대상이 없으면 없다고 답한다. 외부 실행 자체의 exactly-once를 보장한다고 표현하지 않는다. 재시도/동시 완료의 DB 중복 방지와 에이전트 조사 중복은 구분한다.

## 최소 기술 계약과 수직 슬라이스

1. 기존 general_tasks·완료 처리·action_events·멱등성 계약을 대조한다. 주기(none/daily/weekly), 요일 집합, 선택적 로컬 시간, 시간대 및 마지막 처리 회차의 최소 필드/DTO를 정한다. 별도 스케줄 테이블·cron/큐·RRULE 엔진·회차 미리 생성은 제외한다.
2. 일일/주간 예정 계산과 조회→기록·완료 API/MCP를 한 슬라이스로 구현·검증한다. 날짜 경계, 미접속, 일정 변경, 시간대/DST의 모호·누락 시각 처리와 동시 완료 정책을 fixture로 확정한 후 구현한다. 현재 시간대 기본값을 조용히 바꾸지 않는다.
3. 동일 계약의 웹 설정/목록/완료와 설명·workflow·계약 테스트를 연결한다. 기존 daily 데이터/기록/사용자 격리를 유지하는 증분 migration을 사용한다.

## 구현 기록과 최소 계약 (2026-09-24)

기존 `portfolio_tasks`에 요일 배열과 선택적 로컬 시간을 추가하고, `general_task_occurrence_states`의 완료 표식을 그대로 쓴다. 서버는 날짜 없는 일반 할 일 또는 해당 시간대에서 가장 최근 도래한 매일/주간 회차 하나를 계산한다. 매주 1~7은 월~일, 시간 미지정은 00:00이다. 봄 DST의 없는 시각은 현지 시계가 그 시각을 지나면 도래하며, 가을 중복 시각은 첫 번째 시각부터 도래한다. 반복 일정 편집에서 같은 회차 날짜의 완료 표식은 유지하며, 다른 회차 날짜로 바꾼 경우에는 새 일정 기준으로 계산한다. 회차를 미리 만들지 않는다.

OAuth MCP의 `list_due_general_tasks`는 소유자 전용 읽기이며 `next_offset`을 따라 전체 페이지를 읽어야 한다. 한 번 실행한 최신 회차만 완료하고 기존 활동 기록/멱등성 영수증을 사용한다. 웹 설정→DB 도래 목록→완료→목록 제거, 고정 시각·DST·사용자 격리 DB 테스트와 MCP 검색/읽기 계약이 통과했다. 다른 시각으로 수행 중 넘어간 경우에는 조회한 회차가 구 회차가 되어 서버가 거부하고 재조회해야 한다. 브라우저 실기기와 실제 ChatGPT 웹·모바일, 운영 배포는 남아 있다.
