# [배분] 모드·버킷을 제거하고 태그별 목표 비중으로 단순화

2026-09-24 · P2 · 설계 완료, 구현 전.

GitHub: https://github.com/kimyongin/fin/issues/121

## 목적과 결정

사용자는 태그별로 현재 얼마나 보유하고 있고 목표와 얼마나 다른지 확인하고, 같은 화면에서 목표 비중을 설정한다. 모드별 프리셋과 여러 태그를 다시 묶는 버킷은 제거한다. 현재 태그 구성과 목표 버킷을 따로 표시하던 화면을 태그 기준 한 목록으로 합친다. 독립 하단 배분 탭은 유지한다.

## 현재 구현과 제거 범위

- `src/features/strategy/StrategyPage.jsx`: 태그별 현재 구성, 전략 이름/모드/버킷/태그 연결 편집, 모드 변경 모달, 계산 한도 모달, 적립금 배분·리밸런싱 제안을 제공한다. 현재 배분 설정 자체는 본문 편집 전환이며 모든 설정이 모달인 것은 아니다. 이 모든 설정 왕복을 목표 칸 직접 편집으로 대체한다.
- `calculations.js`: 모드별 버킷 목표·허용 이탈 폭·월 적립금·매매 한도·보정 기간으로 추천 금액을 계산한다. 새 화면에 필요한 태그별 합산/현재 비중/목표/차이만 남긴다.
- `data.js`, `app_get_strategy_state`, `app_save_strategy`: 버킷/모드 단위 계약을 태그별 목표 계약으로 바꾼다.
- 현재 저장소는 `strategies`, `strategy_buckets`, `strategy_bucket_tags`, `strategy_bucket_mode_targets`다. 사용처와 FK/RPC/뷰를 확인하고 대체 후 네 저장소와 미사용 분기를 제거한다. 가격 동기화의 `sync_runs`와 원칙 테이블은 별개다.
- 제거: 모드/모드 사유·전략 이름·버킷/태그 연결·모드별 목표·월 적립금·점검일·허용 이탈 폭·매매 한도·보정 기간 및 이에 의존한 추천 계산. 별도 설정 화면/모드·한도 모달도 제거한다. 점검 일정이나 사용자 규칙을 자동으로 할 일/원칙에 생성하지 않는다.

## 화면과 입력 계약

상단에 전체 계좌 기준과 평가 상태를 표시하고 다음 한 목록을 보여준다.

| 태그 | 현재 | 목표 | 차이 |
| --- | --- | --- | --- |
| 국내 주식 | 35% | 숫자 입력 30% | 5%p 초과 |
| 해외 주식 | 45% | 숫자 입력 50% | 5%p 부족 |
| 현금 | 20% | 숫자 입력 20% | 일치 |

- 넓은 화면에서는 열 정렬, 모바일에서는 태그별 두 줄 배치로 표시한다. 목표는 숫자 입력이며 슬라이더·별도 모달은 필요 없다. 현재 금액은 짧은 보조 정보로 표시할 수 있다.
- 하단에는 `목표 합계 100%`, `취소`, `저장`을 둔다. 입력은 초안이며 저장 전에 서버 값이 바뀌지 않는다. 미저장 상태에서 다른 탭으로 이동할 때 기존 초안 보호 방식을 적용한다. 별도 전략 만들기 과정은 없고 최초에도 같은 화면에서 입력한다.
- 현재 보유가 없어도 사용자의 모든 자산 태그에 목표를 설정할 수 있다. 활동 태그는 별개이며 목록에 섞지 않는다. 태그 관리 진입은 보조 동작으로 유지한다.
- 목표가 한 번도 설정되지 않은 경우 전체를 `미설정`으로 표시하고 차이를 계산하지 않는다. 현재 비중을 목표로 자동 채우지 않는다.
- 설정 후 목표가 없는 태그/새로 추가한 태그는 목표 0%로 해석한다. 일부 태그만 입력해도 나머지는 0%이며 합계는 100%여야 한다. 0% 목표는 금지 조건이 아닌 목표 비중이다. 설정 전체를 지우는 별도 기능은 이번 범위에 추가하지 않는다.
- 목표 입력은 0~100%, 소수점 둘째 자리까지 허용한다. 서버는 고정 소수점 기준 합계 100.00%를 검증한다. 음수·범위 초과·NaN·중복 태그·과도한 자릿수는 거부하며 임의 반올림/자동 정규화하지 않는다.
- `미분류`는 실제 미지정 자산의 현재 금액/비중만 보여준다. 목표 입력 대상이나 새 태그로 만들지 않는다. 종목에 태그를 지정하는 기존 경로로 안내한다. 미분류 자산도 현재 비중의 분모에 포함한다.
- 현재 비중은 전체 계좌의 평가 가능한 전체 자산을 같은 기준통화로 합산한다. 자산 화면의 계좌 선택/검색에 따라 분모가 달라지지 않는다. 합계가 0이면 비중/차이는 계산 불가로 표시하며 보유 없는 목표 설정 자체는 허용한다.
- 시세/환율 누락으로 전체 평가가 불완전하면 정확한 현재 비중/차이를 표시하지 않고 필요한 데이터가 없음을 알린다. 목표 편집은 가능하다. 오래된 시세와 누락은 구분하고 기존 품질 표시를 유지한다.
- 목표 편집 중 비교는 입력값 기준 미리보기임을 표시하고 저장된 목표와 혼동시키지 않는다. 자동 매매 금액·적립금 배분 제안은 제공하지 않는다. 의견은 ChatGPT가 원칙과 현재/목표 자료를 보고 설명한다.

## 최소 저장과 API 방향

목표 저장은 사용자·자산 태그·목표 비중의 한 목적별 저장소로 충분하다. `allocation_targets(user_id, tag_id, target_percentage)` 한 테이블을 우선안으로 하고 사용자/태그 유일성과 소유권을 검증한다. 별도 모드·부모 전략·이력·버전 테이블을 만들지 않는다. 행이 없으면 미설정, 유효한 목표 집합이 있으면 설정됨이다. 목표를 자산 태그 공개 응답에 섞지 않아 기존 자산/전략 공유 경계를 유지한다.

구현 첫 단계에서 정확한 현재 의존성과 DTO/RPC 명칭을 확인해 이 티켓에 확정한다. 읽기는 목표 집합과 설정 여부를, 쓰기는 해당 사용자의 목표 집합 전체를 한 트랜잭션으로 교체한다. 동일 입력 재전송은 같은 결과이며 일부 목표만 반영되는 상태를 만들지 않는다. 동시에 저장한 경우의 최소 충돌 처리도 기존 공통 계약과 대조해 기록하며 범용 저장 프레임워크를 만들지 않는다.

- 조회 실패를 목표 미설정으로 바꾸지 않는다. 실패/저장 후 재조회 실패에서 초안을 유지하고 잘못된 빈 목록을 저장하지 않는다.
- 목표를 가진 태그 삭제로 합계가 깨져서는 안 된다. 양수 목표 태그 삭제는 먼저 목표를 다른 태그에 재배분·저장하도록 안내한다. 0%/목표 없는 태그는 기존 삭제 규칙을 따르고 이름 변경은 목표에 영향이 없다. 새 태그 생성은 기존 목표를 바꾸지 않는다.
- 목표와 실제 자산 정보의 공유 권한을 별도로 유지한다. 목표만 공유한 상대에게 잔고를 노출하거나 자산만 공유한 상대에게 목표를 노출하지 않는다. 원칙/비공개 메모도 노출하지 않는다.
- 웹·현재 문맥·MCP의 기존 전략 조회를 새 목표 읽기로 함께 정리한다. 도구 이름 변경 여부는 소비자 대조 후 결정하되 모드/버킷이 존재하는 것처럼 설명하거나 비어 있는 구 객체를 계속 요구하지 않는다. 이번 티켓 때문에 새 MCP 쓰기 기능을 추가하지 않는다.
- `get_workflow_guide`·배분/점검 안내·도구 설명·응답 스키마·배포 RPC 검사·더미 데이터·계약 테스트를 함께 갱신한다. 원칙 #118과 별개로 실제 계산용 목표는 구조화된 숫자로 유지한다.

## 기존 목표와 제거 데이터

기존 목표는 활성 모드 기준으로 전수 확인한다. 모든 활성 버킷이 하나의 서로 다른 유효 태그에 연결되고 총합이 100%인 경우에만 태그별 목표로 옮긴다. 다중 태그 버킷·중복 연결·미연결·잘못된 합계가 있으면 임의 균등 분배하거나 현재 평가액으로 비례 분할하지 않는다. 해당 사용자는 목표 재설정 대상으로 분류하고 새로운 목표는 미설정으로 둔다. 일부만 이관해 완성된 목표처럼 보이지 않게 한다.

삭제 전 기존 목표/설정의 내보내기와 재설정 대상·영향을 인계 자료로 남긴다. 개인 데이터/과거 모드 정보를 공개 Git 문서에 넣지 않는다. 사용자별 재설정 안내는 전환 결과에 근거해 제공하며 범용 migration 상태 엔진을 추가하지 않는다. 일반 로컬/운영 적용을 구분하고 운영 적용·삭제는 릴리스 범위에서 수행한다. 기존 원칙·보유·계좌·태그 자체는 삭제하지 않는다.

## 작업 순서와 다른 티켓

최소 계약/기존 설정 대조 → 태그별 목표 DB·읽기/저장과 웹 직접 편집 수직 슬라이스 → 모드·버킷·추천 UI/코드/테이블 제거 → 문맥/MCP/가이드·공유 회귀 순서다. 적용된 migration을 수정하지 않고 증분 migration을 사용한다.

#118의 원칙 마크다운, #119의 타임라인, #120의 자산 상세와 별개다. 이들 문서의 ‘계산용 배분 한도 유지’는 이 티켓의 제거 결정으로 대체한다. 하단 배분 탭과 자산 태그 기능은 유지한다.
