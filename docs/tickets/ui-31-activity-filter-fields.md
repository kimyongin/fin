# [활동 UX] 검색·기간·태그 필터 카드 정돈

2026-09-26 · Astra 설계 기준 · Sol 로컬 구현. 사용자 승인 시안 기준. 운영 배포 전.

GitHub: https://github.com/kimyongin/fin/issues/142

## 목적과 근거

활동 상단의 검색·기간·태그를 모달과 같은 `라벨 → 입력` 리듬으로 정렬한다. 기간 설명과 반복되는 날짜 라벨을 줄여 입력할 위치가 한눈에 들어오게 한다.

- [승인 시안](../design/assets/activity-filter-preview-20260926.png): AI 생성 참고 이미지이며 실행 화면이 아니다. 아래 동작·접근성 계약이 우선한다.
- [상단 카드 가이드](../design/page-panel-guidelines.md), [모달 필드 가이드](../design/modal-guidelines.md), [태그 가이드](../design/tag-guidelines.md).
- #140의 공통 필드 표현을 재사용한다. #141은 모달 안의 태그 이름 검색 제거이며, 이 티켓은 활동 페이지의 **기록 조회 필터**다. 서로 다른 기능이다.
- #131/#136/#138의 날짜 입력 근처에 기간 적용 설명을 상시 표시하는 요구를 대체한다. 검색 의미·기본 날짜·공유 범위는 유지한다.

## 현재 구현과 수정 범위

`src/features/lifecycle/ActionTimeline.jsx`가 상단 카드의 필터와 검색 결과를 렌더링한다.

- 검색은 aria-label만 있고 화면에 보이는 라벨이 없다.
- 기간은 `기록 기간` → 적용 설명 → `기록 시작일/기록 종료일`로 제목이 반복되고 전체 기간 버튼의 테두리가 강하다.
- 검색/날짜의 gap·padding이 모달 필드 기준과 다르다.
- 검색 결과에도 기간 적용 설명이 반복된다.

기존 `PagePanel`의 제목·햄버거·구분선·권한 처리는 유지하고 그 아래 필터 구획과 중복 안내를 정돈한다. 다른 탭/모달/전체 검색 기능을 다시 설계하지 않는다.

## 목표 배치

```text
할 일과 기록                                      ☰
──────────────────────────────────────────────────
검색
[ 제목·본문 검색                                  ]

기록 기간                                전체 기간
[ 2026-08-28  📅 ]  ~  [ 2026-09-26  📅 ]

태그
[리스크] [매매] [실적] [점검] ... (가로 나열·줄바꿈)
```

1. 검색 위에 보이는 `검색` 라벨을 연결한다. 기존 접근성 이름 `활동 검색`을 유지해도 되며 placeholder는 `제목·본문 검색`이다. 돋보기는 기존 아이콘으로 쉽게 재사용 가능한 경우에만 장식으로 허용한다. 검색 실행 버튼은 없다.
2. 기간은 `기록 기간`이라는 그룹 라벨 하나 아래 두 native date 입력을 둔다. 날짜 사이의 `~`는 장식이다. 각각의 `기록 시작일`, `기록 종료일` 접근성 라벨은 시각적으로 숨겨 보존한다. 커스텀 달력/범용 기간 선택기는 만들지 않는다.
3. `전체 기간`은 그룹 라벨 오른쪽의 테두리 없는 텍스트 버튼이다. 시각적 강조는 낮추되 최소 44px 터치 영역과 키보드 초점을 유지하고 날짜 필드와 영역이 겹치지 않게 한다.
4. `기록에만 적용 · 미완료 할 일은 기간과 무관` 문장과 검색 결과의 같은 기간 설명은 제거한다. 다른 위치에 같은 문장을 반복하거나 새 설명 아이콘/툴팁을 추가하지 않는다. 실제 오류·조회 실패·의미 있는 검색 상태 안내는 유지한다. 남는 안내가 없으면 빈 p/여백도 없앤다.
5. 검색·기간·태그 라벨은 같은 크기/색/왼쪽 기준선이다. control 높이 48px, radius/좌우 여백 12px, label 간격 8px, 필드 묶음 간격 16px은 #140의 공통 스타일을 사용한다. 기간 라벨 옆 행동의 터치 공간만 필요에 맞게 확보하며 별도 큰 헤더 행을 만들지 않는다.
6. 태그는 기존 전체 목록을 가로로 나열·줄바꿈한다. 선택 시의 선택 개수/초기화, 복수 선택 시 `선택한 태그 모두 포함`은 유지한다. 시안은 미선택 상태이므로 이 기능들이 없다는 뜻이 아니다. 태그 이름 검색을 새로 만들지 않는다.
7. 날짜 두 칸은 폭이 충분하면 같은 행에 놓는다. 360/390px 및 확대에서 값·달력 아이콘이 잘리면 한 열로 전환하며 그 경우 시작일/종료일 라벨을 보이게 해 순서를 알린다. 필드 글자를 줄이거나 가로 스크롤을 만들지 않는다.

## 유지할 검색 계약

- 최초 기간은 서울 업무일 기준 오늘 포함 최근 30일이다. 시안의 날짜를 하드코딩하지 않는다.
- 날짜·태그는 즉시, 검색어는 기존 450ms 지연 후 적용한다. 검색 버튼을 추가하지 않는다. 기존 늦은 응답/페이지 추가/재시도 보호를 유지한다.
- 기간은 기록에만 적용한다. 미완료 할 일은 날짜 범위 밖이어도 검색어·태그 등 해당 조건에 맞으면 유지한다. 라벨 간소화를 이유로 날짜를 할 일에도 적용하지 않는다.
- `전체 기간`은 from/to만 함께 비우고 검색어·태그·태그 OR/모두 포함 조건은 보존한다. 빈 양 끝은 기간 제한 없음, 한쪽만 있으면 기존 단방향 범위 의미를 유지한다.
- 시작일이 종료일보다 늦으면 기간 아래 현재 오류를 표시하고 잘못된 범위를 요청하지 않는다. 마지막 정상 결과는 기존 처리대로 유지한다. 상시 설명 제거와 오류 제거를 혼동하지 않는다.
- 상세 열기/닫기 후 조회 조건을 보존하고, 공유 포트폴리오/소유자 변경은 기존 경계를 유지한다. API/MCP·DB·저장 데이터 변경은 없다.

## 구현·검증

1. #140에서 정한 공통 필드 스타일을 사용한다. 미구현이면 활동 필터를 실제 소비자로 함께 연결하되 페이지 전용 복사 스타일이나 범용 폼 엔진을 추가하지 않는다.
2. `ActionTimeline.jsx`의 검색 라벨/기간 묶음/전체 기간 버튼/중복 안내를 변경한다. 공통 `PagePanel`의 모든 소비자 간격을 무심코 바꾸지 않는다.
3. 기존 활동 날짜·검색·태그 E2E를 활용해 실 API 조회 결과를 검증하고, 승인 이미지와 같은 폭으로 비교한다. 모양만 비슷한 목업 완료로 보고하지 않는다.

- [ ] 검색·기간·태그가 승인 시안 및 #140 필드 기준과 일치한다. 날짜 중복 라벨·상시 기간 설명·빈 안내 여백이 없다.
- [ ] 초기 최근 30일, 날짜 변경, 전체 기간, 한쪽만 지정, 역전 범위 오류를 확인한다. 범위 밖 미완료 할 일은 사라지지 않는다.
- [ ] 검색어+태그 OR/모두 포함+기간 조합과 전체 기간 선택 시 다른 조건 보존이 동작한다.
- [ ] 늦은 검색 응답, 다음 페이지, 상세 후 복귀, 공유 읽기를 기존 대표 회귀로 확인한다.
- [ ] 360/390/768/1024/1440px와 200% 확대에서 날짜/라벨/전체 기간/태그가 잘리지 않고 키보드로 조작된다. 선택 태그/0개 태그/긴 태그도 확인한다.
- [ ] 공통 모달 필드와 나란히 비교한 캡처 및 실제 검증 범위를 티켓에 기록한다. 인코딩 검사와 관련 프런트엔드 검증을 수행하고 운영 배포·실기기 미검증은 구분한다.

검색 라벨/공통 입력, 기록 기간의 한 줄 라벨·전체 기간 텍스트 행동, 반응형 날짜 필드와 태그 라벨을 적용했다. 상시 범위 설명과 검색 결과의 중복 설명을 제거했다. 필터 API 의미는 바꾸지 않았으며 활동 E2E에서 날짜 즉시 적용·전체 기간·검색 지연·태그 OR/AND·늦은 응답 경로를 통과했다. 실기기·운영 배포는 미검증이다.

### 2026-09-26 날짜·시간 입력 후속

사용자가 브라우저 기본 달력·시간 선택창의 불안정한 표시 위치를 보고하여, 위 2번의 `native date 입력`과 `커스텀 달력을 만들지 않는다`는 당시 구현 제한을 이 후속 결정에서 대체한다. 필터 의미·초기값·즉시 조회는 유지한다. `@daypicker/react` 기반 공통 `CalendarDateField`를 활동 필터·기록 추가/상세·할 일 일정에 사용하고, 유일한 시간 입력은 팝업 없는 `ClockTimeField`로 바꾼다. 달력은 2차 모달이 아니라 입력 바로 아래 본문 안에 펼쳐진다. 날짜 값은 기존 `YYYY-MM-DD`, 시간 값은 `HH:mm` 계약을 유지한다. 단위 102개·빌드·활동 E2E 23개를 통과했다. 별도 E2E에서 360/390/768/1024/1440px의 달력 열기·Escape·가로 넘침·날짜 선택과 시간 입력을 확인했다. 실제 시각 비교 캡처·실기기 키보드/스크린리더는 추가 확인 대상이다. 운영 배포는 하지 않았다.
