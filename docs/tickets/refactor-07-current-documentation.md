## 목적과 근거

새 세션이 이미 구현된 구조를 다시 만들거나 옛 계약을 복원하지 않도록 현재 규칙과 상태를 명확히 한다. component-system은 Timeline을 미구현이라고 쓰면서 뒤에서는 구현 결과를 설명한다. 필드·타이포그래피의 구현 대기 문장, PRD의 종목 등록 구현 전 문장, START-HERE/티켓 목록의 과거 배포 대기 문장도 현재 코드·배포 기록과 대조가 필요하다. 원격 issue가 열려 있다는 사실만으로 미구현이라고 판정하지 않는다.

## 범위

- START-HERE, PRD, architecture, component-system, 관련 modal/page-panel/tag/typography 가이드와 티켓 목록을 현재 코드·accepted ADR·개별 티켓·검증/배포 기록에 대조한다.
- 현재 제품 규칙은 각 정본 문서에 남기고, 대체된 지시와 날짜별 작업 서술은 history 또는 기존 티켓으로 연결한다. 승인된 최신 요구를 문서 정리 명목으로 바꾸지 않는다.
- START-HERE는 필수 읽기 경로와 현재 작업 목록 중심으로 줄인다. 구현 상태를 여러 문서에 중복해 적기보다 상태 원본으로 연결한다.
- 로컬 구현/검증, 커밋/푸시, 운영 DB·Edge·웹 배포, 실제 ChatGPT/실기기 확인을 구분한다. 확인되지 않은 상태는 미확인으로 명시한다.
- refactor-05/06/08은 구현 완료 후 자기 변경의 문서 상태를 이 기준에 맞춰 갱신한다.

## 제외

앱·migration·실행 설정 변경, 미완료 티켓의 자동 종료, 과거 검증 기록 삭제, 문서 생성 프레임워크 도입은 제외한다. 단계 규칙상 Astra가 현재 계약 정리를, Sol이 자기 구현 결과의 문서 반영을 담당한다.

## 상태 경계와 검증

- 문서 작업만 수행했다. 앱·테스트 코드·migration·실행 설정·MCP 런타임/가이드는 변경하지 않았다. 제품 계약도 새로 추가하지 않았다.
- #147 f324518, #148 7d3bb2b, #150 32a60dc는 로컬 구현 커밋이다. 이 문서 작업으로 푸시·운영 DB/Edge/웹 배포를 수행하지 않았다.
- 운영 배포 확인은 기존 deployment.md 기록과 성공한 [GitHub 실행](https://github.com/kimyongin/fin/actions/runs/36229110158)을 읽기 전용으로 대조한 것이다. 운영 기능을 이번에 다시 테스트한 것이 아니다.
- #148의 viewport/메뉴/초점 등 미체크 항목, #150의 지연 응답·초안 등 미체크 항목을 유지했다. 실제 Google 본인/친구 로그인·ChatGPT 웹/모바일·실기기 확인을 완료로 바꾸지 않았다.
- 문서 검사 결과는 아래 최종 검증 기록에 남긴다. 앱 테스트는 문서 전용 변경이므로 재실행하지 않는다.
