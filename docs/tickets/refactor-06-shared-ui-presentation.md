## 목적과 근거

같은 디자인 수정이 여러 화면에서 반복되지 않도록 실제 사용하는 표현의 정본을 줄인다. AssetsPage의 검색/select는 자체 control 문자열을, ActionTimeline의 검색은 form-control을 사용한다. ActivityDetailModal은 공통 ModalActions와 별도로 footer 버튼을 작성한다. PageControls의 PageActionMenu와 AppHeader는 햄버거 모양·메뉴 스타일·바깥 클릭/Escape 닫기를 각각 정의한다.

## 범위와 수직 슬라이스

1. 자산 검색·계좌 선택을 기존 공통 필드 스타일에 맞추고 활동 필터와 비교한다. 라벨 표시 여부와 필터 의미는 바꾸지 않는다.
2. 기록 상세의 닫기/저장/삭제 표현을 기존 ModalActions 또는 그 최소 표현 부분으로 수렴시킨다. 공유 읽기와 오류 표시를 검증한다. 삭제 확인 상태의 소유자는 하나만 두고 기존 확인 취소·재시도·초안 보존을 유지한다.
3. 상단/푸터의 햄버거 버튼·목록 스타일을 작은 공통 표현으로 묶는다. 같은 닫기 처리만 필요 시 추출한다. 상단은 아래, 푸터는 위로 여는 위치 및 프로필 선택 상태는 호출자가 담당한다.

## 계약과 제외

- modal/tag/typography/page-panel 가이드, PRINCIPLES, component-system을 먼저 읽는다. 가이드가 충돌하면 최신 승인 계약과 실제 소비 화면을 확인해 근거를 남긴다.
- 검색 지연·기간 범위·태그 OR/AND·계좌 범위·권한·저장 API·메뉴 순서를 유지한다.
- 2차 모달은 확인 전용, 추가 확인 단계와 편집 모달 중첩을 만들지 않는다.
- 새 UI 프레임워크·범용 폼/메뉴 엔진·전역 CSS 재작성은 제외한다. 단순 스타일 재사용이면 그것으로 끝낸다.
- 태그 단일/다중 선택 로직이나 도메인 저장 처리를 같은 컴포넌트에 억지로 합치지 않는다.

## 구현·검증 기록

- 자산 검색·계좌 선택은 공통 `form-control`을 사용한다. 빈 목록의 동작 버튼은 입력과 구분해 기존 행동을 유지한다.
- 기록 상세의 버튼과 삭제 확인은 `ModalActions`가 소유한다. 삭제 확인 오류·취소 시 상태를 초기화하는 호출자 콜백만 추가했다.
- 상단·푸터 메뉴의 햄버거 형태, 트리거·메뉴 표면 스타일을 `MenuPresentation`으로 공유한다. 항목 선택 시 상단 트리거로 강제 초점 복귀하지 않도록 수정했으며 Escape는 기존 초점 복귀를 유지한다.
- `npm test` 21파일/105개 통과, `npm run build` 및 encoding 680파일 통과. 격리 E2E DB 50파일/604개, OAuth MCP 계약·readiness, 브라우저 3개 + 추가 2개 통과. 360/390/768/1024/1440/1920px에서 1차 화면의 가로 넘침 없음과 자산 검색의 실제 48px 높이·12px 모서리·16px 글자를 확인했다. 기록 삭제 확인과 초안 보존, 상단 메뉴 Escape·모달 개방 시 초점도 확인했다.
- 2차 메뉴 바깥 클릭, 삭제 실패의 실제 네트워크 경로, 모든 폭에서 긴 텍스트와 모든 모달의 실측 간격은 별도로 검증하지 않았다. 기능 계약·서버·MCP 도구 설명은 변경하지 않아 가이드 갱신 대상이 없다.
