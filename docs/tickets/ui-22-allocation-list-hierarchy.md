# [배분 UX] 태그 제목 강조와 변경 시에만 저장 액션 표시

2026-09-24 · Astra 설계 · Sol 로컬 구현/자동 검증 · 운영 전 · P2

GitHub: https://github.com/kimyongin/fin/issues/130

## 목적과 현재 구현

태그별 현재/목표/차이를 빠르게 비교하고 바꾼 값이 있을 때만 저장한다. `StrategyPage.jsx`는 이미 dirty를 계산하지만 footer 액션은 항상 보인다. #121의 직접 목표 편집과 목표 합계 100% 정책은 유지한다.

## 범위

- 태그명은 목록 행/카드의 일반 텍스트 제목으로 강조한다. 작은 읽기 칩으로 감싸지 않는다. 현재 비중·목표 입력·차이(%p)는 제목보다 하위 정보로 일관되게 정렬한다.
- 색상 기능/컬럼을 새로 추가하지 않는다. 제목만으로 충분하며 색상에 의미를 의존하지 않는다.
- 목표 합계와 유효성 설명은 항상 제공한다. 취소/저장은 실제 변경 또는 저장 진행 중에만 표시하고, 성공/취소 뒤 숨긴다. 실패 시 초안과 재시도 액션을 유지한다.
- 숫자상 같은 값(예: 10과 10.0)은 불필요한 변경으로 보지 않는다. 최초 미설정과 명시적 0 목표의 구분은 유지하고, 실제 목표 입력 후 최초 저장할 수 있어야 한다.
- 별도 편집 모드/설정 모달을 추가하지 않는다. 태그 관리는 전체 계좌·태그별 배분 박스의 제목 오른쪽에 유지한다.
- 태그 관리 전후 목표 초안, 외부 변경 경고, 화면 이탈 보호 및 공유 읽기 전용 상태를 유지한다. 새 DB/API는 불필요하다.

## 완료 기준

- [ ] 미수정/변경/원래 값 복원/취소/저장 성공/실패/저장 중 상태에서 버튼 표시와 초안을 검증한다.
- [ ] 최초 미설정, 합계 100% 미달·초과, 소수 비중, 태그 추가·삭제·이름 수정과 목표 충돌을 검증한다.
- [ ] 공유 읽기에서 편집 액션이 없다. 기존 배분 분모/계산/태그 권한은 변하지 않는다.
- [ ] 360/390/768/1024/1440px, 긴 태그명, 모바일 숫자 입력에서 제목·수치·footer가 겹치지 않는다.
- [ ] 관련 테스트·빌드·인코딩 검사와 실제/미검증 범위를 기록한다.

#128의 배분 태그명 읽기 칩 규칙은 이 티켓으로 대체한다. 관리/선택 칩은 그대로다. 운영 적용 전이다.

## 구현 기록 (2026-09-24)

태그를 일반 제목으로 강조했고 수치가 같은 목표(예: 10/10.0)는 미변경으로 계산한다. 저장·취소는 초안 변경 또는 저장 중에만 보인다. 배분 관련 브라우저 회귀, unit/DB 검사 및 빌드가 통과했다. 실제 모바일 기기와 운영 배포는 미검증이다.
