# [UI] 가격 갱신·종목 태그·배분 설정을 자산으로 모으기

2026-09-23 · P2 · 로컬 UI 구현 및 자동 검증. 운영 배포 전.

후속: [#113 보유 확인 중심의 자산 UX](https://github.com/kimyongin/fin/issues/113), [로컬 명세](./ui-06-assets-holdings-first.md)가 네 보기 유지·더보기·공통 CSV 배치를 대체한다. 아래는 #112 당시 구현/검증 이력이다. 남은 사용자 확인은 새 화면 기준으로 #113에서 진행하며 완료됐다고 간주하지 않는다.

## 목적

보유 자산을 보면서 가격을 갱신하고, 분류와 목표 배분을 관리할 수 있게 한다. 설정과 원칙을 오가며 자산 관리 기능을 찾는 부담을 줄인다. 원칙은 독립된 하단 탭으로 유지한다.

## 확정한 배치

| 기능 | 현재 | 변경 |
| --- | --- | --- |
| 가격 동기화 | 설정 하단 | 자산 공통 도구 영역의 보조 버튼 `가격 갱신`. 진행·성공·부분 실패·실패 결과를 실행 위치에 표시 |
| 종목 태그 관리 | 설정 하단 | 자산 공통 도구 영역의 `더보기` 메뉴 → `종목 태그 관리` → 관리 모달 |
| 운용 전략 | 원칙 화면의 전략 조회·편집, 자산의 배분 점검 | 자산 → 기존 `목표와 비교`(`#allocation`) → `배분 설정`에서 생성·편집 |
| 서술형 원칙 | 원칙 탭 | 독립 탭과 날짜별 조회·추가·수정·종료 기능 유지 |

가격 갱신과 더보기는 보조 강조로 둔다. 모바일에서는 도구줄을 줄바꿈하고 버튼을 축소하지 않는다. 기존 자산 네 가지 보기·보기별 필터/등록·CSV 복사·표 편집은 유지한다. 배분 점검에서 자산으로 복귀하는 기존 흐름도 유지한다. 별도 최상위 메뉴나 다섯 번째 기본 자산 보기를 만들지 않는다.

## 사용자 흐름과 세부 조건

1. 자산에서 `가격 갱신`을 누르면 기존 동기화를 실행하고 중복 실행을 막는다. 저장된 가격을 다시 읽어 평가값에 반영하고 부분 실패도 설명한다. 갱신 요청 시각과 실제 시세 기준일은 구별한다. 동기화했다고 거래소 시세 날짜를 오늘로 덮어쓰지 않는다.
2. 자산 → 더보기 → 종목 태그 관리에서 목록·추가·수정과 기존 정렬값 편집을 제공한다. 기존 편집 모달과 상태 처리를 재사용하고 불필요한 중첩 모달은 피한다. 저장 후 자산의 태그 목록·필터와 관련 표시를 갱신한다. 활동 검색 태그와 혼동하지 않도록 `종목 태그`라고 명시한다.
3. 자산 → 목표와 비교에서 현재/목표/차이와 계산 결과를 보고 `배분 설정`으로 편집한다. 기존 버킷·태그 연결·모드별 목표 비중·월 적립금·계산 한도를 유지한다. 전략이 없으면 같은 화면에서 `배분 설정 만들기`를 제공한다. 전략 모드 전환도 자산 배분 화면에서 접근한다.
4. 원칙(`#strategy`)은 서술형 원칙만 제공한다. 투자 기준·운영 규칙·전략 메모와 과거 원칙 조회는 그대로 둔다. 문장에 적은 수치를 배분 설정으로 자동 반영하지 않는다. 배분 설정을 원칙 탭에서 중복 편집하지 않는다.
5. 설정에서는 옮긴 두 섹션을 제거하고 계정·공유·연결 기능을 유지한다. 기존 안내·빈 상태·화면 링크가 옛 위치를 가리키지 않도록 갱신한다.

## 기존 구현 재사용과 범위

- `SettingsPage.jsx`의 동기화/태그 UI를 이동하고 `features/portfolio/actions.js`의 기존 동작과 태그 편집 처리를 재사용한다.
- `AssetsPage.jsx`, `AssetViewToolbar.jsx`, `App.jsx`의 페이지 연결을 최소 변경한다. 데이터 처리 책임을 공통 도구줄로 옮기지 않는다.
- `StrategyPage.jsx`의 기존 `principles`/`allocation` 분기와 `PrincipleJournal.jsx`를 활용해 원칙 목록과 배분 설정의 표시 위치를 정리한다. 기존 전략 계산 모듈을 재작성하지 않는다.
- 새 테이블·API·저장 이력·범용 설정 프레임워크를 만들지 않는다. `strategy` 등 내부 식별자와 MCP 도구명은 화면 명칭 변경만을 이유로 바꾸지 않는다.
- 자산 조회 권한이 전략 조회/수정 권한을 뜻하지 않는다. 본인·친구·게스트의 기존 기능별 공유/편집 경계를 유지하고 비공개 원칙을 자산에 노출하지 않는다. 가격/태그 변경도 기존 허용 대상에만 노출한다.
- MCP 가이드나 사용자 가이드에 원칙/설정의 옛 UI 위치 안내가 있으면 해당 문구만 갱신한다. 데이터 계약 변경으로 확대하지 않는다.
- #111의 원칙 하단 운용 전략 유지 조건은 이 티켓으로 대체한다. 기존 구현·검증 기록은 보존한다.

## 완료 기준

- [x] 자산에서 가격 갱신과 상태/결과 확인이 가능하고 설정에는 중복 진입점이 없다.
- [x] 자산에서 종목 태그 목록·추가·수정이 가능하고 저장 결과가 자산 조회에 반영된다.
- [x] 배분 점검에서 기존 설정 생성·편집·모드 변경과 계산 결과 확인을 완료할 수 있다. 기존 저장 오류 시 초안·재시도 경로를 보존한다.
- [x] 본인 원칙은 독립 하단 탭이며 서술형 원칙/과거 조회만 제공한다. 지난 원칙 조회에 현재 배분 설정을 섞지 않는다.
- [ ] 본인 및 공유 읽기에서 기존 접근 경계와 자산 네 보기·CSV·표 편집·배분 왕복 흐름이 유지된다. 공유 UI 실기기 확인은 남는다.
- [ ] 360/390/768/1024/1440px에서 도구줄 가로 넘침을 자동 확인했다. 메뉴/모달의 실제 터치·키보드/초점 복귀와 긴 태그·누락 시세의 실기기 확인은 남는다.
- [x] 관련 기존 브라우저 회귀를 갱신하고 build·check:encoding·diff 검사를 통과한다. 실제 검증한 viewport·상태·상호작용과 미검증 범위를 기록한다.
- [x] PRD·화면 구조·제품 재정리·사용자 안내와 티켓의 구현 상태를 일치시킨다. MCP 도구 계약은 변경되지 않는다.

## 현재 상태

설정의 가격/태그 섹션을 자산 공통 도구 영역으로 이동했다. 종목 태그 관리는 기존 편집 모달을 한 번에 하나만 열도록 연결했다. 원칙 소유자 화면에서는 기존 전략 조회를 빼고, 자산 배분 점검에서 목표 버킷·모드·월 적립금·계산 한도를 관리한다. 공유 전략은 기존 허용 범위의 읽기 경로를 유지해 공개 범위를 넓히지 않았다.

로컬 검증: Vitest 105건, production build/인코딩, 격리 DB 510건·MCP 준비 검사, Chromium의 가격 성공/실패·배분 왕복·종목 태그 저장/재조회. 자산 도구줄은 360/390/768/1024/1440px에서 가로 넘침이 없었다. 배분 모드 저장 회귀를 추가하면서 E2E 기준 스키마에 기존 `202607190014_strategy_modes_and_principles.sql` 누락을 발견했다. 테스트 시작 시 이 적용된 앱 마이그레이션을 격리 DB로 복사하도록 수정했다. 운영 DB 마이그레이션은 새로 추가하지 않았다. 실제 사용자 데이터에 대한 실기기 시각 확인, 공유 권한 조합 전체, 운영 배포는 별개로 남긴다.
