# [활동 검색] 저장 자료 기반 에이전트 검토와 웹·MCP 교차 검증

상태: 설계 보완 · 구현 전 · 2026-09-28
GitHub: https://github.com/kimyongin/fin/issues/164
선행: search-01~03. 기준: [검색 설계](../design/activity-context-search.md).

S4. “투자 이론 태그의 심리 관련 자료를 참고해 지금 해야 할 행동을 검토해줘”를 실제 OAuth 세션에서 수행한다.

2026-09-28 피드백 `15cabc0d-6791-4bac-b60e-42013002c972`를 이 시나리오에 포함한다. 현재 이론 태그의 기록 12건과 연결된 리서치 할 일 1건은 출발 자료다. 별도 이론 관리 도메인보다 기존 활동·태그·할 일·원칙에서 **찾기 → 원문 검토 → 관련 이론만 비교 → 요청 시 판단 저장 → 재조회**가 되는지 확인한다. 세부 저장·보존 기준은 [검색 설계의 투자 이론 재사용 계약](../design/activity-context-search.md)을 따른다.

- [ ] MCP 설명/가이드에 태그·종목 후보 해석→직접 자료 검색→필요 원문·연결 맥락→현재 원칙·자산·배분·진행 할 일 비교 흐름을 반영한다. 자연어 이해는 에이전트가 담당하며 앱에 별도 대화 분석 엔진을 추가하지 않는다.
- [ ] 미채택 이론·현재 원칙·과거 가정·현재 자산을 구별하고 반대 근거·적용 조건도 검토한다. 외부 최신 정보가 필요한 경우 확인 범위와 부족 정보를 명시한다.
- [ ] 이론별 기록을 태그와 검색으로 찾아 생성·정정·삭제할 수 있는 기존 웹/HTTP/OAuth 경로를 확인한다. 핵심 주장·유용한 조건·한계·출처·실제 재검토일을 본문에서 읽을 수 있는지 검증하되, 단순 수정일을 재검토일로 표시하지 않는다. 사용 중지는 본문에 명시하는 첫 흐름으로 검증하고 전용 상태/필드를 선행하지 않는다.
- [ ] 관련 이론만 선택해 시사점·반대 근거·현재 데이터·결론을 비교한다. 두 이론이 충돌하거나 같은 신호를 반복할 때 우선한 이유와 중복 계산 방지를 설명한다. 검색 결과 순서나 점수만으로 채택하지 않는다.
- [ ] 사용자가 명시적으로 저장을 요청한 경우에만 기존 일반 활동 기록에 원본 제목·ID/링크와 당시 적용한 주장·한계, 데이터 시각, 반대 근거, 충돌 판단, 결론·재검토 조건을 남긴다. 저장 후 웹/HTTP/OAuth에서 재조회하고, 원본 이론의 후속 정정·삭제 뒤에도 당시 판단 본문이 유지되는지 확인한다. 원본 참조만 저장하고 본문 보존을 생략하지 않는다.
- [ ] 이론 재검토·사용 중지·새 조사 할 일은 사용자 요청이 있을 때 기존 할 일로 연결한다. 같은 목적의 열린 할 일과 연결된 리서치 할 일을 먼저 확인하고, #162의 1단계 맥락을 사용하되 12건 전체를 한 판단의 근거로 자동 확장하지 않는다.
- [ ] 현재 저장된 목표 배분과 미채택 시장 상황별 검토안을 구분한다. 검토만으로 목표·보유·매매를 변경하지 않는지 확인한다.
- [ ] 답변에 읽은 기록의 제목·ID/실제 링크·핵심 근거와 제안 행동의 연결이 있다. 검색점수를 정답 확률로 쓰지 않고 저장 본문을 실행 지시로 따르지 않는다.
- [ ] 검색 실패/미색인/무관 결과를 자료 없음으로 단정하지 않는다. 연결 기록을 직접 검색 hit로 오해하지 않는다. 검토 요청만으로 원칙/할 일을 저장하지 않고 기존 할 일 중복을 확인한다.
- [ ] 한국어 합성 이론 자료로 단어 불일치·오래된 자료·긴 본문·연결 양방향·종목 일부·태그+기간·완료 할 일·상충 이론·오류 fallback을 웹 HTTP와 OAuth MCP 양쪽에서 교차 검증한다. 사용자 운영 본문을 코드/로그 fixture에 복제하지 않는다.
- [ ] 실제 모델 품질과 실제 ChatGPT 웹·모바일 검증을 mock/CI 통과와 구분한다. 확인할 수 없는 클라이언트 검증은 명시적으로 미완료로 남긴다.
- [ ] 운영 오류 수정, 색인 백필/모델 전환, 웹/Edge/DB 배포 순서·직전 정상 버전·복귀 절차를 기록한다. 인코딩·가이드 digest·Edge·DB·브라우저 및 인증된 운영 호환성 게이트를 통과한다.

새 조사/판단/이론 도메인이나 자동 매매·자동 저장을 도입하지 않는다. 각 선행 슬라이스에서도 관련 교차 검증을 수행하고 이 티켓을 마지막 테스트 몰아하기로 사용하지 않는다.

완료 판정은 검색·연결·판단 저장/재조회와 원본 변경 후 보존을 실제 사용자 흐름으로 확인한 뒤 한다. 현재 #161의 의미 검색에는 후반부 질문과 무관 질문의 품질 실패가 남아 있으므로 검색이 활성화됐다는 사실만으로 이 피드백을 해결 처리하지 않는다. 이론별 별도 사용 중지 상태나 구조화 필드가 꼭 필요한지 여부는 기존 본문·태그 흐름에서 반복되는 불편을 확인한 후 별도 범위로 결정한다. 인계 대상은 Sol의 #162 연결 구현과 이 티켓의 검증이며, 이번 설계 보완은 앱 코드·운영 데이터·피드백 상태를 바꾸지 않는다.
