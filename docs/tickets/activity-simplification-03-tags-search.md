# [활동 단순화] 다중 활동 태그와 조건·키워드 검색

GitHub: https://github.com/kimyongin/fin/issues/82
선행: 01 최소 계약, 02 활동 경로.
기준: [공통 설계](../design/activity-simplification.md), [ADR-0007](../adr/0007-activity-results-and-search.md).

## 목적

U05. 선택 태그와 정확한 조건·키워드로 활동을 찾는다.

## 인수 조건

- [ ] 사용자별 다중 활동 태그의 재사용/추가/해제와 이름 변경·삭제를 제공한다. 기존 자산 태그/전략 버킷과 분리하고 비중 계산에 영향을 주지 않는다.
- [ ] 태그 없이 등록/완료할 수 있다. 완료 시 태그를 이어주되 반복 태스크의 태그 수정이 과거 회차를 자동 변경하지 않도록 한다. 일반 태그 수정에 별도 이력 저장을 강제하지 않는다.
- [ ] 기간·종목·계좌·할 일/한 일·결론 유무·다중 태그와 제목/메모/결과 키워드를 조합한다. AND/OR·날짜 범위·커서/정렬을 명시한다.
- [ ] 검색창 하나와 펼치는 상세 필터를 사용한다. 기술적인 키워드/벡터 모드 선택을 요구하지 않는다. 필터 해제·빈 결과·실패·상세 복귀 시 상태를 처리한다.
- [ ] 최신 활동 내용을 검색하며 편집 후 제목/수행일/결과/태그가 조건과 snippet에 반영된다. 편집은 한 일의 건수를 늘리지 않는다.
- [ ] 권한·조건·대표 행 중복 제거를 페이지 제한 전에 적용한다. 태그 사전/자동완성/집계에도 같은 공유 제한을 적용하고 전체 데이터를 클라이언트로 가져오지 않는다.
- [ ] 한글 제목/문장/태그와 영문 ticker fixture, 복합 필터 페이지 경계·사용자 격리·완료 태그 계승을 실제 DB/앱/MCP에서 검증한다. 기존 조회 기반에 필요한 인덱스만 추가한다.
- [ ] MCP도 동일 필터와 안정 ID를 사용하고 사용자에게 내부 기록 유형 선택을 요구하지 않는다. #84의 검색 설명을 동시에 갱신한다.

## 실행 기준

기존 구조를 활용해 필요한 최소 변경을 사용자 기능 단위로 구현한다. 일반 활동에 불변성·별도 결과 저장·의무 수정 이력을 도입하지 않는다. 금융 원본/계산/인증/권한과 기존 재시도·반복 동작은 유지한다. 이번 갱신은 설계·티켓만 변경하며 구현·배포 완료를 뜻하지 않는다.
