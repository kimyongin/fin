# [CRUD 동등성] 원칙 이력 조회·정정·삭제를 웹과 OAuth MCP에 제공

2026-09-26 · [#151](https://github.com/kimyongin/fin/issues/151) · 로컬 구현·검증 완료, 운영 배포 확인 전.

## 목적
“잘못 저장한 원칙 이력을 찾아 수정하거나 삭제한다”를 양쪽에서 완결한다.

## 현재 구현과 재사용
app_list_principles / app_list_principle_changes / app_save_principle, PrincipleJournal.jsx를 재사용한다. OAuth list_principles는 날짜 기반 현재 조회이며 이력 페이지·단건 탐색을 대신하지 않는다. delete RPC는 없다.

## 구현 계약
- 현재 원칙의 변경은 기존처럼 새 행 추가. 이력 상세에는 본문·변경 메모 정정과 해당 행 삭제를 제공한다. 시각·소유자·원칙 ID는 수정 대상이 아니다.
- OAuth에 이력 페이지 조회, 행 ID 단건 조회, 정정/삭제를 제공한다. 입력 ID는 논리 principle_id와 이력 row_id를 명확히 구별한다.
- 기존 테이블을 유지한다. 행 정정의 오래된 덮어쓰기 방지는 읽은 body/change_note 비교로 처리하고 최신 문서 추가의 expected_row_id와 함께 의미를 명시한다. 동일 내용 정정은 no-op. 현재 행 정정과 새 이력 저장도 같은 owner 잠금 경계에서 검사한다.
- 새 이력 저장이 오래된 본문을 기반으로 현재 행 정정을 덮지 않도록 expected current body/change_note 검사를 양쪽 클라이언트에 연결한다. 공개 입력 변경은 배포 호환 검사에 포함한다.
- 삭제 후 남은 최신 행이 현재가 된다. 마지막 행 삭제 시 빈 상태와 원칙 작성 진입을 표시한다. 현재 행 삭제는 예상 최신 ID도 검사해 확인 뒤 새 원칙이 생겼으면 재확인을 요구한다.
- 삭제 확인에 삭제 대상 일시와 이후 현재 원칙 일시/빈 상태를 알린다. 기록/자산은 변경하지 않는다. 별도 원칙 삭제 이력 테이블은 만들지 않는다.
- HTTP RPC와 OAuth는 같은 목적별 함수를 호출. 기존 과거 읽기 전용 문구는 이 티켓의 정정/삭제 예외로 변경한다.

## 수용 조건
- [x] 과거/현재/마지막 행 정정·삭제, 같은 시각 ID 정렬, 페이지 다음 이력 조회 — DB 및 MCP 계약 테스트.
- [x] 삭제 뒤 현재/as-of/타임라인/일일 문맥이 같은 결과 — DB 회귀 테스트.
- [x] 동시 현재 저장·이력 정정/삭제, 동일 요청 반복, 타인·친구 쓰기 거부 — 잠금·CAS·RLS 검증.
- [x] 웹↔MCP 교차 CRUD와 모달 확인 취소/초안 보호 — 웹 E2E 및 MCP 계약 테스트.
- [x] 가이드/스키마 색인/원칙 테스트 갱신. 실제 운영 배포/ChatGPT 클라이언트 검증은 미실시.

## 구현·검증 기록 (2026-09-26)

- 저장은 현재 행의 본문과 변경 메모를 함께 비교하는 `app_save_principle_checked`로 전환했다. 이력 행 정정은 제자리 수정, 삭제는 남은 최신 행을 현재로 읽는다. 기존 5인자 저장 함수는 정정된 현재 행 위에 확인 없는 쓰기를 거부한다.
- 웹의 변경 이력 상세에서 정정·삭제를 제공하고, OAuth MCP에는 목록·단건·정정·삭제 도구를 추가했다. 관련 가이드와 배포 RPC 계약도 갱신했다.
- 일반 로컬 DB의 새 마이그레이션을 데이터 초기화 없이 적용했다. `npm test` 110/110, `npm run test:db` 618/618, 전체 격리 E2E 15/15, MCP 계약, Edge Deno 타입 검사, 빌드를 통과했다.
- 새 웹 정정·삭제 E2E는 390px에서 검증했다. 기존 원칙 이력 읽기 E2E는 360/390/768/1024/1440px을 검증한다. 정정·삭제의 나머지 폭과 실제 ChatGPT 연결은 운영 검증 항목으로 남긴다.
