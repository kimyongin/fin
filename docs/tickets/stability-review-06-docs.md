# [안정화 재검토] 현재 개발 기준과 과거 설계 문서 분리

우선순위: P2 · 상태: 티켓 작성, 구현 전 · 2026-09-23
관련: #91, #92~#97 · 기준 코드: b7ee31d

## 문제와 근거
PRD와 backend-modules 등에는 현재 방향과 폐기된 판단/브리핑/원장 구조가 함께 남아 있고 '현재 개발 기준' 제목도 여러 번 반복된다. 우선순위 안내가 있지만 새 세션에서 낡은 구조를 다시 구현할 위험이 있다. START-HERE의 일괄 완료 표현과 개별 티켓의 미검증 항목도 함께 읽어야 한다.

## 범위
- START-HERE → 현재 PRD/accepted ADR → 실제 아키텍처 → 관련 티켓의 읽기 경로를 간결하게 정리한다.
- 현재 규칙은 실제 코드와 ADR-0008 기준으로 한 곳에서 읽히게 하고 폐기 계획/과거 상태는 history로 이동하거나 명확히 분리한다.
- 기존 결정 근거·검증 수치·미검증/운영 게이트는 보존한다. migration 이력이나 미완료 티켓을 삭제/종료하지 않는다.
- 신설 공통 라이브러리/테이블을 문서 정리 명목으로 요구하지 않는다. 이번 안정화 진행 상태를 목록/시작점/해당 티켓에 맞춘다.

## 완료 조건
- [ ] 현재 문서만 읽고 메뉴·저장 정본·공유·매매/보정·원칙 이력·개발 방식이 모순 없이 파악된다.
- [ ] 폐기된 별도 도메인/원장/범용 엔진 구축 지시가 현재 명세처럼 남지 않는다.
- [ ] 로컬 구현, 자동/수동 검증, 원격 CI, 운영 배포 상태가 구분된다.
- [ ] 이동 문서의 링크·인코딩 검사와 git diff --check를 통과한다.

## 진행 규칙

- docs/START-HERE.md, ADR-0008, SIMPLICITY.md와 관련 티켓을 먼저 읽는다. UI 변경 전 디자인 원칙/컴포넌트 규칙, DB 변경 전 schema/OVERVIEW를 확인한다.
- 필요한 기존 helper와 목적별 API를 재사용해 수직 슬라이스로 구현·검증·커밋한다. 사용자 로컬 설정과 무관한 변경은 보존한다.
- 기존 티켓의 검증 기록은 유지하고 새 결과를 교차 연결한다. 코드 검토로 추론한 문제와 실제 재현 결과를 구분한다.
