# [저장 단순화] 현재 보유값 중심 매매·보정·확인 단순화

상태: 로컬 구현·회귀 검증 완료; 운영 배포·실사용 검증 대기 · 2026-09-23
GitHub: https://github.com/kimyongin/fin/issues/90
선행: 01; 02의 자동 활동 계약
시나리오: S2/S3/S9/S10
기준: docs/engineering/SIMPLICITY.md, docs/adr/0008-minimal-portfolio-storage.md, docs/design/minimal-portfolio.md

## 목적

사용자 기능에 필요한 최소 저장·처리만 유지한다. 삭제 허용된 구 투자 행의 이관은 요구하지 않지만 새 데이터의 접근·공개 범위와 금융 안전성은 보존한다. 기존 구현의 존재는 유지 근거가 아니다.

## 인수 조건

- [x] 최신 매매 한 건도 되돌리기 기능을 제공하지 않는다. 오류는 증권사에서 확인한 현재 수량/평균가를 직접 보정한다. 신규 매매 평균가 계산은 유지하고 과거 재계산/역산을 하지 않는다. 금융 활동 삭제로 잔고가 변경되지 않음을 앱/MCP에 설명하고 검증한다.
- [x] 현금·평가금액 직접 입력 자산의 기존 입력/보정과 표 편집을 회귀 검증한다. 시장형 수량/평균가 계산을 모든 자산에 강제하지 않는다.

- [x] 매수/매도 입력을 서버에서 decimal 계산해 holdings와 자동 활동을 한 트랜잭션으로 저장한다. 수수료·세금 제외 이동평균, 매도 평균가 유지, 전량 매도 원가 0, 초과 매도 차단을 검증한다.
- [x] 영구 preview/commit 왕복과 과거 원장 재생·취소 엔진을 제거한다. 설명용 예상 결과가 필요하면 저장 없는 계산으로 제공하고 실제 저장에서 현재값을 다시 검증한다.
- [x] 현재값 직접 보정과 확인 시각/메모를 기존 보유 모델에 최소 저장한다. 확인은 시세 변경과 구별하며 마지막 확인 후 수량/평균가가 바뀌었음을 최소 기준으로 표시한다.
- [x] 잘못된 매매는 현재값 보정과 사유 기록으로 처리한다. 과거 활동의 설명 편집은 현재 잔고를 바꾸지 않는다. 과거일 체결의 기록/현재 반영 여부를 명확히 설명하고 추정 재생하지 않는다.
- [x] 서버 잠금/오래된 자산값 검사, 동일 요청 재전송, 응답 유실 재시도, 실패 rollback, 이중 활동 방지를 검증한다. 같은 입력으로 실제 매수를 두 번 한 경우 서로 다른 요청은 허용한다.
- [x] 직접 편집·표 편집·MCP 매매·보정의 현재값/기록 규칙과 신규 활동의 전후 값을 검증한다. 사용자가 삭제를 허용한 구 거래·보정·확인 행의 이관/원문 보존은 완료 조건이 아니다.
- [x] 금액을 바꾸는 매매·보정·확인의 재전송 방지 영수증과 잠금은 실제 금융 위험 때문에 유지한다. 저장형 preview·취소·구 원장 전용 영수증/쓰기 경로는 종료하고 범용 payload 엔진은 만들지 않는다. 그 밖의 활동·메모·할 일 영수증은 #91에서 실제 사용 근거로 개별 판단한다.

## 구현 방식

관련 DB/API·MCP/UI·가이드·검증을 수직 슬라이스로 연결하고 슬라이스마다 커밋한다. 일반 코드 구현/배포는 이 티켓 작성에 포함하지 않는다. 미정 세부 기술 선택은 위 범위 안에서 구현자가 근거를 기록해 확정한다. 제품 기능 축소 범위를 추가로 넓히면 먼저 영향과 대안을 명시한다.

## 진행 기록

아래는 수직 슬라이스 순서의 기록이다. 앞선 항목의 임시 호환 테이블/함수 유지 문구는 뒤의 퇴역 슬라이스가 대체한다. 현재 정본은 `supabase/schema/OVERVIEW.md`와 최신 migration이다.

- 저장 없는 매매 예상·직접 확정 슬라이스(2026-09-23): 기존 `preview_trade_entry`는 같은 입력을 현재 보유값으로 읽기만 하며 보유 ID/버전을 돌려준다. 새 `app_record_completed_trade`는 해당 입력·기대 버전·멱등 키를 받아 계좌/종목 스트림을 잠그고 현재값을 재계산한다. 앱/MCP의 확정 호출은 새 경로로 전환했다. 응답 유실 시 동일 키/입력으로 원 응답을 받는다. 거래 목록 호환을 위해 이번 단계는 `trade_entries`와 금융 영수증을 유지한다. 보정 preview와 검증 원장/화면은 후속 정리 대상이다. 격리 DB 34파일/466검증, OAuth/토큰 MCP 계약, Chromium 모바일 매매 1건, 단위 19파일/94건, 웹 빌드·인코딩·가이드 검사 통과. 일반 로컬/운영 DB에는 미적용이다.
- 구 매매 미리보기 저장소 종료(2026-09-23): 현행 소비자가 없는 UUID-preview 확정 RPC를 닫고 `trade_entries.preview_id` FK/컬럼 및 `trade_previews` 테이블을 제거했다. 매매 추정은 여전히 서버의 읽기 전용 계산이고 재전송 방지는 별도 금융 영수증으로 유지한다. 격리 DB 34파일/466검증, OAuth/토큰 MCP 계약, Chromium 모바일 매매 1건 통과. 일반 로컬/운영 DB 미적용.
- 매매 원장 통합(2026-09-23): 새 매매는 `holdings` 현재값과 자동 `activity_events` 한 행을 원자적으로 저장하며 거래 목록도 그 활동을 읽는다. 중복 전송 영수증은 보유 변경 안전성을 위해 유지한다. 구 `trade_entries` 테이블은 퇴역하고 구 활동의 무효가 된 테이블 링크만 끊는다. 신규 거래 목록은 불완전한 구 payload를 완전한 체결로 복원한다고 주장하지 않는다. 정확한 체결 단가·수량이 포함된 매매 활동은 친구의 일반 활동 grant로 노출하지 않고 소유자 전용으로 제한한다. 격리 DB 34파일/475검증, OAuth/토큰 MCP 계약, Chromium 전체 35건, 단위 19파일/94건 통과. 일반 로컬/운영 DB 미적용.
- 저장 없는 보정 예상·직접 현재값 적용(2026-09-23): 보정 예상은 읽기만 하고 `holding_state_version`을 반환한다. 새 직접 적용 함수는 같은 절대값·사유·일자·확인 범위·기대 버전을 잠금 후 검증하고 `holdings`와 보정 활동을 원자적으로 갱신한다. 명시적으로 확인한 필드는 기존 verification 경로에만 선택 저장한다. UI/OAuth MCP 호출은 새 함수로 연결했다. 보정 활동의 정확한 값·이유는 친구 일반 활동 grant로 노출하지 않는다. 입력은 정밀도 제한 decimal 문자열로 검증한다. 격리 DB 34파일/484검증, OAuth·토큰 MCP 계약, Chromium 모바일 보정 1건, 단위 19파일/94건, 웹 빌드·가이드 검사 통과. 구 preview/보정 테이블과 함수, 확인 테이블은 후속 종료가 필요하다. 일반 로컬/운영 DB 미적용.
- 구 보정 저장소 종료(2026-09-23): 앱/MCP가 저장 없는 예상과 직접 적용으로 전환된 뒤 사용하지 않는 `holding_reconciliation_previews`, `holding_reconciliations`, 구 UUID 확정 RPC를 증분 migration으로 제거했다. 보정 활동과 현재 보유값, 별도 확인 정보 및 금융 재전송 영수증은 유지한다. 격리 DB 35파일/488검증, OAuth·토큰 MCP 계약, Chromium 모바일 보정 1건 통과. 일반 로컬/운영 DB 미적용.
- 최신 확인 정보 통합(2026-09-23): 별도 `holding_verifications` 테이블과 삽입 트리거를 제거하고 최신 명시적 확인 범위·값·일자·메모·작성 경로를 `holdings.last_verification`에 보관한다. 확인만 수행하면 비공개 자동 활동 한 건을 남기고, 보정과 동시에 확인하면 보정 활동 하나로 묶는다. 증권사 확인값은 일반 자산 DTO/편집 활동에서 가리며 소유자 integrity API에서만 읽는다. 버전 충돌·재전송 영수증은 유지한다. 격리 DB 35파일/495검증, OAuth·토큰 MCP 계약, Chromium 모바일 보정·확인 1건, 단위 19파일/94건, 가이드 검사 통과. 일반 로컬/운영 DB 미적용.

- 추가 물리 정리 슬라이스: 운영·로컬에서 행 수 0인 체결 취소 preview/reversal/receipt 3개 테이블 및 전용 DB RPC를 증분 migration에서 제거했다. 과거 trade_entries의 reversed_at/reversal_reason 읽기 필드는 유지하며, 잘못된 입력의 현재값 보정 경로는 그대로 둔다. execution-task 테스트에서 더 이상 제품에 없는 취소 시나리오를 제거하고 부재 검증으로 대체했다. 격리 DB 37개 파일/553개 assertion, MCP 계약, Chromium 34개 시나리오 통과. 일반 로컬/운영에는 미적용이다.

- 최신 매매도 되돌리기하지 않는 제품 결정을 먼저 웹과 OAuth MCP에 반영했다. 매매 모달의 `기록 취소` 흐름과 MCP reversal 도구 2개를 제거하고, 잘못 입력한 경우 증권사 현재 수량·평균가 확인 후 보정하도록 안내한다. 기존 과거 취소 표시와 DB 원문은 보존한다.
- 이 변경은 저장 preview/commit이나 DB `trade_reversals`를 아직 제거하지 않았다. 현재값 직접 저장·검증·구 금융 원장 이관을 완료하기 전에는 DB RPC/테이블 제거 또는 운영 배포 완료로 간주하지 않는다.
