# [UI] 오늘·자산·활동·원칙의 상단 구조 통일

2026-09-23 · P2 · 로컬 구현 및 자동 검증 완료. 운영 배포 전.

## 목적과 확인한 문제

주 메뉴를 오갈 때 제목·대표 행동·필터 위치를 다시 찾지 않아도 되게 한다. 기존 `AppHeader`는 공통이지만 그 아래 상단은 개별 구현되어 있다. 실제 로컬 화면에서 자산은 탭, 활동은 중복 안내와 검색, 원칙은 카드 내부 제목·추가·날짜 필터로 시작하는 차이를 확인했다.

`docs/design/PRINCIPLES.md` 및 `screen-structure.md`의 후속 적용이다. 이전 화면 구조 정리의 검증 기록은 유지하고, 이번 티켓은 현재 네 페이지의 상단만 담당한다. 기존 활동/원칙 초안 보호 티켓 #104~#106의 동작을 보존한다.

## 공통 배치 계약

- 제목줄: 페이지 h1과 햄버거 메뉴의 높이·글자·구분선을 통일한다. 기존 내/친구 포트폴리오 전환과 공유 문맥은 유지한다. 같은 페이지 제목을 본문 시작에서 반복하지 않는다.
- 조작 영역: 보기 전환 또는 주요 필터를 왼쪽, 대표 행동을 오른쪽에 둔다. 필요한 검색·추가 필터는 다음 줄에 둔다. 조작이 없는 오늘에는 빈 도구 영역을 만들지 않는다.
- 모바일: 의미 순서는 보기/주요 필터 → 대표 행동 → 검색/추가 필터 → 본문이다. 같은 행에 들어가면 함께 배치하고, 넘치면 순서대로 줄바꿈한다. 버튼·글자를 줄여 억지로 한 줄에 넣지 않는다.
- 간격: 앱 헤더 아래 24px은 공통 레이아웃이 소유한다. 조작 영역 내부 간격 12px, 조작 영역과 본문 및 본문 섹션 사이 20px을 기본으로 한다.
- 첫 본문 카드와 섹션의 모서리·제목·padding을 맞춘다. 카드 radius 16px, padding 모바일 16px/넓은 화면 24px, 일반 섹션 제목 18px을 기준으로 한다. 오늘의 핵심 결론은 정보 위계에 맞게 더 크게 표시할 수 있다.
- 강조색은 대표 행동에 사용하고 새로고침·CSV 복사·조회 등 보조 행동과 구별한다. 활성 탭/필터의 선택 표시는 유지한다. 상시 설명은 필요한 경우 짧게 한 번만 제공한다.

| 화면 | 변경 | 보존할 흐름 |
| --- | --- | --- |
| 오늘 | 제목 아래 마지막 점검 카드를 바로 배치. 날짜·상태·결론 위계를 유지하며 첫 카드와 이어갈 일 카드의 시각 규칙을 정돈 | 분석 없음/이전 점검/현재 점검 상태, 상세·이력·연결 과제, 기존 빈 상태 진입 버튼 |

## 구현 위치와 경계

- 기존 `src/components/AppHeader.jsx`, `PageToolbar`를 재사용한다. `DailyReviewPage`, `AssetsPage`, `LifecyclePage`/`ActionTimeline`, `PrincipleJournal`/`StrategyPage`의 상단 배치를 조정한다.
- 페이지별 데이터 로직을 공통 도구줄로 옮기지 않는다. 공통 UI 확장은 실제 네 화면에 필요한 최소 props로 제한한다.
- 이번 범위에서 DB/API/MCP, 권한, 자산 계산, 원칙 저장 방식, 메뉴 개수, 하단 탐색, 모달 내부를 재설계하지 않는다. 자산 이외 CSV 경로가 있다면 해당 기능을 실수로 제거하지 않는다.
- `screen-structure.md`의 현재 화면별 상단 계약을 이 내용과 맞춘다. 과거 판단/자료 화면의 오래된 표기를 이번 네 화면의 구현 지시로 사용하지 않는다.

## 완료 기준과 검증

- [x] 네 페이지가 제목 → 필요한 조작 영역 → 본문 순서를 따르고 중복 소개/자기 링크가 없다.
- [x] 자산 CSV 복사와 성공 안내, 네 보기 전환, 목표 비교, 현재 보기별 필터·등록이 기존 기능을 유지한다.
- [x] 활동의 할 일·한 일 통합 표시, 검색·조건 해제·활동 추가가 작동하고 원칙 날짜 전환·현재 복귀·추가/수정·전략 편집이 유지된다.
- [x] 소유자와 공유 보기에서 기존 포트폴리오 문맥과 편집 권한 경계가 유지된다.

- [ ] 빈 상태와 내용이 있는 상태를 자동 회귀로 확인. 긴 제목 및 과거 원칙 조회의 실기기 시각 검토는 남긴다.

## 구현·검증 기록

- 공통 제목줄의 CSV 복사를 자산 도구줄로 옮겼다. 네 자산 보기와 별도 배분 점검 화면에서 같은 복사 기능과 성공 안내를 제공한다. 화면별 데이터를 도구줄로 이동하지 않았다.
- 활동의 중복 소개와 자기 링크를 제거했다. 이후 사용자 피드백으로 전체/할 일/한 일 필터도 제거하고 검색·활동 추가를 첫 줄에 두며 할 일과 한 일을 항상 연속 표시한다. 원칙은 날짜 조회·추가를 목록 밖으로 옮기고 중복 제목을 제거했다. 오늘의 첫 점검/할 일 카드와 활동 첫 카드의 radius·padding·섹션 제목을 공통 기준으로 조정했다.
- 로컬 자동 확인: Vitest 105개, production build/인코딩, 격리된 Supabase DB 510개와 OAuth·RPC 준비 검사, Chromium E2E의 자산 복사·네 보기·배분 왕복·공유 읽기·4페이지×5 viewport 가로 넘침 검사. 활동·원칙의 추가 회귀 결과도 반영한다.
- 검증 중 배분 화면 테스트가 불완전 평가 데이터를 만들지 않은 채 경고 문구를 기대하던 조건 오류를 발견해, 해당 테스트의 목적을 저장된 전략 표시 확인으로 명확히 했다. 실제 불완전 평가 경고는 별도 E2E가 검증한다.
- 사용자 로컬 설정과 기존 데이터는 변경하지 않았다. 운영 배포와 실제 모바일·PC 시각 확인은 별도이며, 이 티켓의 남은 확인 항목으로 둔다.
- 후속 필터 제거 검증: 활동 화면은 timeline 전체 조회를 고정하되 오늘 화면의 pending 전용 조회는 유지했다. 검색은 할 일·한 일을 함께 찾는다. Vitest 105개, 빌드·인코딩·diff 검사, 격리 DB 510개와 Chromium E2E 37개가 통과했다. 360/390/768/1024/1440px에서 두 구역과 검색·추가 노출 및 가로 넘침을 확인했다. DB/API/MCP 변경이나 운영 배포는 없다.
