# [공통 UX] 모달의 라벨·입력·읽기 전용 필드 디자인 통일

2026-09-26 · Astra 설계 기준 · Sol 로컬 구현. 사용자 승인 시안 기준. 운영 배포 전.

GitHub: https://github.com/kimyongin/fin/issues/140

## 목적과 승인 기준

모달을 옮겨도 라벨·값·편집 가능 여부를 같은 방식으로 읽고 수정하게 한다. 자산 상세에서 티커/가격만 일반 문장이고 다른 속성은 입력칸인 혼합 표현을 없애고, 활동·계좌·원칙·태그 관리까지 같은 필드 리듬을 적용한다.

- 정본: [모달 가이드 3절](../design/modal-guidelines.md), [타이포그래피](../design/typography-guidelines.md).
- 승인된 이미지: [자산 상세 필드 시안](../design/assets/modal-field-preview-20260926.png). AI 생성 시안이며 실제 실행 화면/검증 증거는 아니다. 구현 수치는 가이드가 우선한다.
- #139의 일반 텍스트 시세/disabled 입력 금지라는 **표현**만 대체한다. 시세 읽기 전용·등록/보유 분리·가격 저장 금지는 유지한다. #117/#123/#126/#135의 모달/권한/저장/타이포그래피 규칙을 보완한다.

## 현재 코드에서 확인한 문제

- `AssetDetailModal.jsx`: 티커·현재가·날짜가 문장으로 흩어져 있고, 보유가 있는 종류는 disabled select다. 공유 분기도 값들을 한 줄 문장으로 합친다.
- `EditorModals.jsx`: 계좌·종목마다 라벨/필드의 긴 Tailwind 문자열이 반복되고 과거 자간/크기 지정이 남아 있다. 현재 CSS 전역 보정이 일부 크기를 맞춰 주지만 명시적인 필드 계약은 없다.
- `GeneralActionModal`, `GeneralTaskDetail`, `TaskScheduleFields`, `ActivityReferences`: 입력 스타일·세로 padding·그리드가 각각 선언된다. 관련 대상 검색은 다른 입력보다 얕다.
- `ActivityDetailModal`: 편집 가능 필드는 라벨+입력, 고정/공유 필드는 제목·문장으로 바뀐다. 수행일과 상단 수행 시각은 역할을 확인해 중복 값만 줄여야 한다. 별도 수정 모드가 있는 것은 아니다.
- `TagManagerModal`, `PrincipleJournal`: 공통 shell을 쓰지만 내부 필드·footer 스타일이 따로 남아 있다.
- `TradeEntryModal.jsx`는 현재 import/사용자가 없는 잔존 코드다. 이번 전수 적용을 이유로 다시 노출하거나 별도 매매 모달을 만들지 않는다.

## 바꿀 경험

1. 자산 상세의 종목명/티커, 통화/종류, 현재가/기준일을 일정한 두 열로 읽는다. 모바일 긴 값은 한 열로 읽는다.
2. 수정 가능한 값은 그 자리에서 입력하고, 고정값은 같은 크기의 읽기 전용 필드에서 복사할 수 있다. 보유 중 종류에 드롭다운 화살표가 나타나지 않는다. 보유가 없어 종류를 바꿀 수 있는 기존 권한은 유지한다.
3. 같은 방식으로 계좌, 활동 추가, 기록/할 일 상세, 원칙 작성, 태그 관리의 필드를 읽는다. 제목/본문/메모는 충분한 전체 폭을 쓴다.
4. 태그/요일 선택, 참조 검색·해제는 목적에 맞는 컨트롤을 유지한다. 긴 원칙 이력과 기록 본문은 읽을 수 있는 텍스트/마크다운으로 남긴다.
5. 하단 저장/닫기, 미저장 닫기·삭제·보유값 확인의 2차 모달 규칙은 그대로다. 확인용 문장을 input으로 바꾸지 않는다.

## 공통 표현의 최소 계약

- scalar control: 48px 높이, 12px 모서리/좌우 여백, label 14/20·600, value 16/24·400, 라벨 간격 8px/필드 간격 16px/섹션 24px.
- readOnly는 배경과 작은 잠금으로 구분하고, 흐리게 비활성화하지 않는다. readonly select/date 대신 복사 가능한 텍스트 필드. 잠금은 장식이고 읽기 전용 상태는 control의 의미로 제공한다.
- 읽기 전용/저장 중 disabled/오류/focus를 구분한다. 기존 저장 입력·dirty 계산·숫자 정밀도·권한을 변경하지 않는다.
- `styles.css`에 최소 공통 필드 스타일을 두고 실제 반복이 있는 라벨·설명/오류 연결·읽기 전용 표시에만 얇은 공통 표현을 사용한다. schema-driven form, validation/CRUD 엔진, 별도 라이브러리, 전역 모든 input 강제 치환은 불필요하다.
- `ModalShell`/`ModalActions`의 계층·초점·scroll·저장 보호를 재사용한다. 관련 화면의 오래된 개별 font/padding/radius 선언은 제거해 공통 스타일이 우선하도록 한다.

## 구현 순서와 저장/API 경계

1. **자산·계좌 슬라이스**: 필요한 공통 필드 스타일과 읽기 전용 표현을 두 실제 소비자에 적용. 상세 열기→수정→저장/재조회·읽기 전용 복사까지 검증한다. 공통 토큰만 만들어 놓고 완료하지 않는다.
2. **활동 슬라이스**: 추가·기록·할 일·일정·참조에 적용. [#141 태그 검색 간소화](./ui-30-activity-tags-without-search.md)와 충돌 없이 검색 없는 칩 선택을 연결한다. 날짜/시간·태그·참조 저장은 기존 계약을 사용한다.
3. **태그·원칙과 예외 대조**: 두 관리창, 원칙 편집, 공유/이력/확인/표 편집을 대조하고 표를 완료한다. 검증한 단위로 커밋하되 기존 무관한 변경은 보존한다.

새 DB/API/MCP/권한 변경 없음. 기존 목적별 저장을 사용하며 특히 #139에서 제거한 가격 key를 UI 통일 때문에 payload에 추가하지 않는다. 프런트엔드 회귀와 실제 저장/재조회로 검증하며 UI 크기마다 새 테스트를 양산하지 않는다.

## 인수 조건

- [ ] 위 표의 모든 활성 경로를 적용/검증/이유 있는 예외로 채우고 같은 폭의 비교 캡처를 남긴다.
- [ ] 자산·계좌·활동·원칙·태그 관리에서 label/control/readOnly의 computed font·높이·간격이 일치한다.
- [ ] 360/390/768/1024/1440px에서 필요한 반응형, 긴 한글명/티커/금액, 미입력/시세 없음 `—`, 긴 본문을 읽고 조작할 수 있다. PC/모바일에서 읽기 전용 값 선택·복사와 Tab 초점을 확인한다.
- [ ] 편집 중 resize/닫기/저장/실패 재시도에도 초안이 유지된다. 기존 대표 E2E를 재사용하고 실제 변경 경로만 보강한다.
- [ ] 공유/읽기 전용의 값이 편집되지 않고 저장 버튼/권한이 새로 생기지 않는다. 시세는 상세 저장 payload에 없다.
- [ ] 긴 원칙/기록·확인 설명·표 편집 예외가 사용성을 유지하며 별도 중첩 모달이 생기지 않는다.
- [ ] 가이드/적용표·관련 테스트·인코딩 확인을 갱신하고, 브라우저 viewport 검증과 실기기/운영 배포를 구분해 보고한다.

## 로컬 구현·검증 기록

`src/styles.css`의 `form-field/form-label/form-control`과 작은 `ReadOnlyField`를 실제 자산·계좌·활동·원칙 소비자에 적용했다. 읽기 전용 티커/종류/시세/날짜와 공유 자산의 짧은 값은 선택·복사할 수 있는 실제 `readOnly` input이다. 긴 원칙/기록 본문, 확인 설명, 조밀한 표 셀은 의도적으로 텍스트/기존 표 표현을 유지한다. 시세를 상세 저장 payload에 추가하지 않았다.

`npm test` 102개, `npm run build` 통과. 격리된 `npm run test:e2e -- e2e/activity.spec.js e2e/assets-access.spec.js` 재실행에서 32개, `npm run test:e2e -- e2e/modal-visual.spec.js e2e/app.spec.js`에서 15개 통과했다. 내부 DB 567개와 MCP 계약·배포 준비 상태 검증도 통과했다. `modal-visual` 검사는 360/390/768/1024/1440px에서 계좌·자산 상세·활동 편집·필터를 캡처하고 계산 스타일을 비교한다. 모바일 인앱 브라우저에서 자산 상세 필드와 활동 필터·태그 관리를 직접 확인했다. 실기기·스크린리더·운영 배포는 아직 확인하지 않았다.

## 인계

미해결 제품 결정 없음. 승인 이미지는 저장소에 보존했다. 남은 검증은 운영 배포/실기기와 원칙 공유·이력 등 전용 브라우저 경로의 수동 확인이다.
