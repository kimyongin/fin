# [안정화 재검토] 활동 모달의 미저장·저장 중 닫기·뒤로가기 일관화

우선순위: P1 · 상태: 티켓 작성, 구현 전 · 2026-09-23
관련: #93, #96 · 기준 코드: b7ee31d

## 문제와 근거
`ModalShell`에는 dirty/closeDisabled가 있지만 활동 추가·수정에서 사용하지 않는다. 활동 추가를 저장 중 닫고 새 모달을 열면 이전 저장의 setGeneralEditor(null)이 새 모달을 닫을 수 있다. `LifecyclePage`는 할 일 상세에만 useDetailHistoryEntry를 적용한다.

## 범위
- 기존 ModalShell과 useDetailHistoryEntry를 재사용해 활동 추가·편집·태그 미저장 상태, 저장 중 닫기, 상세 뒤로가기를 연결한다.
- 닫기 버튼·취소·Escape·브라우저 뒤로가기의 일관된 규칙을 정하고 기록한다. 읽기 취소를 서버 쓰기 취소로 표현하지 않는다.
- 이전 저장의 성공/오류가 다른 편집 세션에 적용되지 않도록 최소 세션 구분 또는 저장 중 닫기 제한을 적용한다.
- 본문 저장과 태그 저장이 별도인 현재 구조에서 dirty 해제 시점을 구분한다. 새 모달 프레임워크는 만들지 않는다.

## 완료 조건
- [ ] 미저장 입력이 있는 활동 추가/수정에서 닫기·취소·Escape의 확인과 계속 편집/버리기가 동작한다.
- [ ] 저장 중 닫기·뒤로가기 후 늦은 성공/실패가 새 모달이나 다른 활동에 영향을 주지 않는다.
- [ ] 활동 상세 → 후속 할 일 상세 → 닫기/뒤로가기에서 의도한 화면과 포커스로 돌아간다.
- [ ] 금융 자동 기록의 편집 제한 및 친구 읽기 전용을 유지한다.
- [ ] 360/390/768/1024/1440px 중 관련 상태·포커스·스크롤의 검증 범위와 미검증 범위를 기록한다.

## 진행 규칙

- docs/START-HERE.md, ADR-0008, SIMPLICITY.md와 관련 티켓을 먼저 읽는다. UI 변경 전 디자인 원칙/컴포넌트 규칙, DB 변경 전 schema/OVERVIEW를 확인한다.
- 필요한 기존 helper와 목적별 API를 재사용해 수직 슬라이스로 구현·검증·커밋한다. 사용자 로컬 설정과 무관한 변경은 보존한다.
- 기존 티켓의 검증 기록은 유지하고 새 결과를 교차 연결한다. 코드 검토로 추론한 문제와 실제 재현 결과를 구분한다.
