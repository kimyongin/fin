# [리팩토링] App의 공유·프로필·표 편집 상태와 동작을 기능으로 이동

2026-09-26 · P3 · 구현 및 주요 회귀 검증 완료 · 검토 기준: 82826e6.

GitHub: [#150](https://github.com/kimyongin/fin/issues/150). #149 → #147 → #148 이후 후순위로 진행한다.

관련: #108은 자산 액션에서 접근 액션을 분리한 완료 이력이다. 이번 작업은 이후 App에 남거나 추가된 친구·프로필·표 편집 책임을 정리하며 #108을 다시 구현하지 않는다. refactor-05 뒤 진행하고 UI 정리보다 후순위다.

## 목적과 근거

App.jsx의 handleAvatarSelect, handleAddFriend/handleRemoveFriend, 친구·열람자 조회 상태, handleSpreadsheetSave가 화면 조립과 섞여 있다. 기능 하나를 수정할 때 앱의 무관한 상태까지 추적하는 비용을 줄인다. 파일 길이나 hook 개수 감소 자체는 목표가 아니다.

## 범위와 경계

1. 친구/프로필/공유받는 친구의 조회·초안·저장·오류 상태를 기존 auth 기능의 작은 hook/data adapter로 함께 옮긴다. accessActions와 bootstrap을 재사용하고 같은 상태의 두 소유자를 만들지 않는다. 친구 연결→대상 전환→공유 화면 표시까지 검증해 첫 슬라이스를 끝낸다.
2. 표 편집의 payload 변환·저장·saving 상태를 assets/portfolio의 기존 책임에 맞게 옮긴다. 표 편집→저장→목록 재조회까지 별도 슬라이스로 검증한다.
3. App은 세션·현재 대상·탭의 조립과 기능 간 명시적 콜백만 소유한다. request gate의 무효화/늦은 응답 차단, bootstrap 순서, 로그아웃 초기화를 보존한다.

## 유지·제외

- 공개 이름/비밀번호 일괄 저장, 아이콘 선택 즉시 저장·실패 복구, 친구 연결 성공 후 이동, 열람 표시의 성공 시점 의미를 유지한다.
- 공유 읽기 전용·게스트·현재 대상 분리, 표의 숫자 직렬화/검증·원자 저장 계약을 바꾸지 않는다. 별도 문제를 발견하면 근거를 기록하고 버그/계약 변경으로 분리한다.
- 전역 상태 라이브러리·Context 일괄 도입·범용 CRUD/controller·서버 계산의 프런트 이전은 제외한다.
- 기존 API/MCP·DB 스키마 변경은 요구하지 않는다. 폴더 전체 이동이나 이름 정리만을 위한 변경은 피한다.

## 구현·검증 기록

- auth의 `useSharingProfile`로 프로필/아이콘/친구/열람자 상태와 조회·저장 동작을 옮겼다. App은 세션·대상 전환·탭·포트폴리오 요청 게이트를 조립한다. 사용자 변경이나 로그아웃 뒤 늦게 온 공유 응답은 현재 사용자 확인 후 무시한다.
- assets의 `useSpreadsheetSave`로 행 직렬화·RPC 저장·저장 중 상태를 옮겼다. 기존 원자 저장 RPC와 새로고침 순서, 읽기 전용 거부는 유지한다.
- `npm test` 21파일/105개, `npm run build` 및 encoding 682파일, `git diff --check` 통과. 격리 E2E DB 50파일/604개와 OAuth MCP 계약/readiness 통과. 브라우저에서 친구 연결·해제, 프로필 전환, 아이콘 성공/실패 복구, 로그아웃, 공유 폼 저장 실패 후 초안 유지, 게스트 공유 읽기, 표 저장 실패 후 초안 유지·재시도·저장 후 재조회를 확인했다. 새 표 테스트가 시드 종목명을 바꿔 뒤의 공유 테스트에 간섭한 문제는 테스트 종료 시 원복하도록 수정하고 두 테스트를 함께 재실행해 통과했다.
- 공유 쓰기 차단을 UI에서 다시 시도하거나 늦은 응답을 인위적으로 지연시킨 브라우저 시나리오는 이 변경에서 별도 재검증하지 않았다. 기존 App 포트폴리오 요청 게이트와 서버/RPC 계약은 그대로다. MCP 도구·가이드 의미 변경은 없다.
- #149의 독립 문서 현행화는 Astra 담당으로 별도 남아 있다. 구현 결과를 문서에 기록한 것과 문서 정본의 전체 정리는 구분한다. 푸시·배포하지 않았다.
