# 활동 상세 초안 보존·취소·연결 이동 수정

2026-09-23 · 로컬 구현·격리 검증 완료, 운영 배포 전 · #100/#101 로컬 구현 이후 발견한 후속 버그. 기존 검증 증거와 운영 게이트는 유지한다.

## 코드에서 확인한 재현 조건

- ActivityDetailModal에서 본문 수정 중 태그를 저장하거나 후속 할 일을 추가하면, onSaved → refreshActivityDetail → activity 변경 effect가 초안과 editing을 초기화한다.
- 수정 → 취소 → 변경 버리기 → 다시 수정하면 버렸던 draft가 남아 있다.
- 미저장 편집/태그/후속 입력이 있는 상태에서 원래 할 일 또는 이어진 할 일을 누르면 LifecyclePage의 직접 dismiss 경로가 확인 없이 상세를 교체한다.
- 정적 경로 확인 단계이며 브라우저 재현은 구현 착수 시 수행한다.

## 최소 수정 범위

ActivityDetailModal.jsx, LifecyclePage.jsx의 해당 흐름과 회귀 테스트. 다른 영역 저장 응답이 미저장 초안을 덮지 않게 한다. 취소는 저장된 값으로 복원한다. 연결 이동도 닫기와 동일한 미저장 확인을 거치고 확인 후 원래 목적지로 이동한다. 범용 폼/명령 엔진, 새 테이블/API는 추가하지 않는다.

## 완료 기준

- [x] 본문 편집 + 태그 저장/후속 생성의 조합에서 미저장 본문이 보존된다.
- [x] 태그 선택 후 본문 저장 시에도 태그 초안 처리 규칙이 일관되고 묵시적으로 유실되지 않는다.
- [x] 변경 버리기 후 재편집하면 저장된 값으로 시작한다.
- [x] 연결된 할 일 이동에서 계속 편집/버리기 선택을 검증한다.
- [x] 저장 중 중복 요청·이동을 막고 기존 재시도 키 동작을 유지한다.
- [ ] 모바일 390px/PC 1440px에서 관련 상호작용을 회귀 검증하고 결과를 기록한다.

## 상태

이 티켓은 버그 수정이며 구조 리팩토링 검토와 구분한다.

## 구현·검증 기록 (2026-09-23)

ActivityDetailModal에서 같은 활동의 서버 갱신은 현재 미저장 본문/태그 초안을 덮지 않고, 다른 활동으로 전환할 때만 초기화한다. '변경 버리기'는 저장된 활동 값으로 초안을 복원한다. 연결된 할 일로 이동할 때 미저장 입력 확인을 거치며 저장 중 이동은 막는다. 격리 브라우저의 태그 저장 중 본문 초안 보존, 기존 뒤로가기/닫기 회귀는 통과했다. 새 후속 할 일·취소·연결 이동 조합 테스트도 선택자 수정 후 격리 단독 실행으로 통과했다. 실제 운영 배포와 실기기 확인은 하지 않았다.
