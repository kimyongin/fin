# [공유] 포트폴리오 전체 읽기 공유와 공유 하기·공유 받기 정돈

2026-09-26 · Astra 재설계 완료 · Sol 로컬 구현 및 자동 검증 완료. 운영 배포·실사용 확인 대기.

GitHub: https://github.com/kimyongin/fin/issues/145

후속 설계 [#146](./ui-34-sharing-form-and-viewers.md)이 아래 제목 옆 토글·즉시 저장·접속 정보 별도 저장 요구를 대체한다. 이름/비밀번호/공유 여부를 한 번에 저장하고 공유받는 친구·최근 열람을 추가한다. 아래 내용과 검증은 #145 당시 구현 기록이며 전체 공유 권한과 전환 계약은 유지한다.

이 본문은 #145의 기존 ‘기록/할 일 개별 스위치’ 명세를 대체한다. 정본은 [ADR-0009](../adr/0009-whole-portfolio-sharing.md)다. 기존 개별 스위치 구현은 완료/배포 기준이 아니다.

## 목적과 범위

사용자는 내 포트폴리오를 공유하거나 다른 사람의 포트폴리오를 받아 본다. 항목별 공개 여부를 관리하지 않는다. 설정은 `공유 하기`와 `공유 받기` 카드 두 개로 정돈한다.

- 공유 대상: 자산(계좌·종목·보유·일반 메모·태그·시세), 배분, 활동의 할 일·기록·연결·태그, 원칙의 현재 본문·변경 메모·과거 본문. 네 탭에서 읽는 사용자 콘텐츠를 읽기 전용으로 공유한다.
- 제외: 비밀번호/해시, 로그인/뷰어 세션, 연결 토큰, 친구 목록, 설정, 제품 피드백/관리 정보, 내부 실행 JSON·중복 방지 영수증·임베딩. ‘전체 공유’는 DB 모든 컬럼을 반환한다는 뜻이 아니다.
- 공개 이름/비밀번호로 기존 친구/게스트 접근을 검증한다. 인터넷 전체 공개나 수정 권한을 추가하지 않는다. MCP의 기존 본인 데이터 접근도 별개다.

## 목표 화면

```text
공유 하기                                  [공유 스위치]
자산·배분·활동·원칙과 이력을 읽기 전용으로 공유합니다.
──────────────────────────────────────────────────────
공개 이름                         보기 비밀번호
[내 공개 이름                 ]   [변경할 때만 입력   ]
                                     [접속 정보 저장] *

공유 받기
공유받은 이름과 비밀번호를 입력하세요.
──────────────────────────────────────────────────────
공개 이름                         보기 비밀번호
[상대방의 공개 이름           ]   [비밀번호           ]
                                             [연결하기]

🍎 친구 이름                               [보기] [해제]
🐻 다른 친구 이름                          [보기] [해제]
```

1. 기존 `공유 보기`와 `친구 포트폴리오` 카드를 각각 `공유 하기`, `공유 받기`로 바꾼다. 두 카드의 제목/설명/구분선/라벨·필드/행동을 같은 디자인으로 맞춘다. 별도 메뉴·접기·모달은 만들지 않는다.
2. 전체 스위치 하나만 제목 오른쪽에 둔다. 공개 항목 목록, 기록/할 일 스위치, 현재 상태 박스, 상단 `공유 설정 저장`을 모두 제거한다. 제목과 스위치는 세로 중앙 정렬한다.
3. 별표 버튼은 최초 접속 정보 설정 또는 입력 변경이 있을 때만 필드 아래에 나타난다. 미저장 입력에는 이 영역에서만 `저장 전`을 표시한다. 스위치에는 별도의 초안 상태를 두지 않는다.
4. 입력은 [모달 가이드 3절](../design/modal-guidelines.md)의 공통 필드를 재사용한다. 라벨→필드 8px, 필드 묶음 16px, 의미 구획 24px. 입력 높이 48px/모서리 12px. 글자 역할은 [타이포그래피](../design/typography-guidelines.md)를 따른다.
5. 모바일에서는 필드를 한 열로, 넓은 화면에서는 이름/비밀번호 두 열로 배치한다. 연결 목록은 아이콘+이름 왼쪽, 보기/해제 오른쪽이다. 이름이 길면 줄바꿈하고 좁을 때 행동을 다음 줄로 옮긴다. 행마다 설명 박스를 만들지 않는다.
6. 공유 받기의 성공은 연결을 저장하고 그 사람의 자산 화면으로 이동한다. 이후 하단 프로필 목록 또는 이 카드의 `보기`로 다시 연다. 새 연결 성공 후 입력한 비밀번호를 비운다. 중복 연결은 새 행을 만들지 않고 기존 포트폴리오로 이동한다.
7. `해제`는 내가 연결한 상대방을 내 목록에서 제거하는 기존 의미다. 상대방의 전체 공유를 끄지 않는다. 상대방이 공유를 중지한 경우 보기/연결 실패를 짧게 알리고 권한을 우회하거나 기존 내용을 새 데이터처럼 남기지 않는다. 기존 list_friends가 비활성 상대를 숨기는 정책은 유지하며 중지된 상대를 위한 새 상태 저장소는 만들지 않는다.

## 저장 동작

- 공유 스위치는 즉시 저장하며 성공한 서버 상태만 확정 표시한다. 처리 중 중복 조작을 막고 `저장 중`을 알린다. 별도의 켜기 확인 모달은 필요 없다. 제목 아래 문장이 원칙/과거 본문까지 포함한 공개 범위를 항상 명시한다.
- 저장된 이름/비밀번호가 없는 최초 ON은 OFF를 유지하고 첫 누락 필드에 초점을 둔다. `공개 이름과 비밀번호를 먼저 저장해 주세요.`를 표시한다. 접속 정보 저장 자체가 공유를 켜지 않는다.
- 공개 이름·비밀번호는 입력/blur 때 저장하지 않고 `접속 정보 저장`으로 함께 검증한다. 기존 이름 형식/중복·비밀번호 최소 길이 검증을 유지한다. 비밀번호 빈값은 기존 값 유지이며 삭제가 아니다. 저장 성공 시 비밀번호 입력을 비우고 실패하면 초안을 유지한다.
- 접속 정보 저장은 현재 저장된 공유 여부를 유지한다. 전체 스위치는 저장된 이름과 빈 비밀번호를 보내므로 미저장 이름/비밀번호/아이콘을 함께 저장하거나 버리지 않는다. 같은 프로필을 쓰는 두 요청은 처리 중 직렬화한다.
- 최초 조회 실패를 정상 OFF로 표시하지 않는다. 저장 실패 시 해당 구획에 오류를 알리고, 응답 유실/충돌이면 실제 값을 재조회한다. 권한 확대를 자동 재전송하지 않는다. 입력 중 초안을 보호하고 프로필 아이콘 오류와 공유/연결 오류를 섞지 않는다. 새 자동 저장 엔진·큐·영수증은 만들지 않는다.
- 전체 OFF면 기존 친구/게스트의 다음 읽기 요청부터 차단한다. ON은 기존 유효한 연결의 접근을 다시 허용한다. 비밀번호 변경은 기존 친구 연결을 해제하지 않으며 기존 게스트 비밀번호 버전 검증은 유지한다.

## 현재 구현과 서버 변경

현재 #145 로컬 작업에는 `SharingSwitch`, 전체 스위치 즉시 저장, 접속 정보 초안 분리와 개별 공유 UI가 들어 있다. 검증된 초안 분리/실패 처리/공통 스위치는 재사용하되 `SharingPolicyPanel`은 제거한다. 현재 원칙의 `PrincipleJournal`과 두 조회 RPC는 owner 선택을 받지 않아 단순히 메뉴만 열어서는 공유가 되지 않는다.

### 하나의 공유 여부로 단순화

- `profiles.sharing_enabled`, 비밀번호 검증, `friendships`/`viewer_sessions`, `can_view_owner`를 정본으로 유지한다. 읽기 권한은 본인 또는 전체 공유 ON + 유효한 연결이다. 쓰기는 본인만 가능하다.
- `feature_sharing_policies`, `feature_sharing_grants` 및 `app_get_sharing_policy`/`app_update_sharing_policy`를 퇴역한다. 개별 정책 상태, 정책 버전, 기본 공개 preset을 유지하지 않는다.
- 기존 조회가 호출하는 `can_view_feature(owner,key)`는 필요하면 지원하는 현재 포트폴리오 읽기 키만 허용하고 `can_view_owner`에 위임하는 얇은 호환 함수로 유지한다. 알려지지 않은 키/계정 운영 정보는 거부한다. 사용자별 기능 권한 저장소를 다시 조회하지 않는다. 이 함수 이름을 바꾸기 위한 대규모 별도 리팩토링은 하지 않는다.
- `app_get_shared_feature_access` 응답은 기존 소비자 전환에 필요하면 유지할 수 있지만 feature 값은 하나의 관계 접근 여부에서 파생한다. UI의 설정 가능한 개별 정책으로 사용하지 않는다. 원칙 경로를 명시적으로 연결하고 배분과 원칙을 같은 화면으로 취급하지 않는다.
- 원칙 현재/변경 이력 RPC에 선택적 `input_owner_user_id`를 추가해 본인 기본 호출과 공유 대상 조회를 지원한다. 현재 본문/변경 메모/시각/과거 본문을 기존 타임라인으로 읽는다. 기존 owner-only 쓰기 RPC는 그대로 유지한다. PostgREST에서 구/신 signature가 중복 매칭되지 않도록 migration과 호출자를 함께 정리한다.
- `PrincipleJournal`에 대상 owner와 읽기 전용을 전달하고 수정/저장 버튼을 제공하지 않는다. 대상 전환 시 이전 사람의 현재 문서/이력/상세를 지우고 늦은 응답을 폐기한다. 공유의 기록/할 일 연결도 한 공유 경계 아래에서 읽되 사용자 콘텐츠 allowlist는 유지한다.
- 정책 테이블/RPC의 의존 함수·테스트·앱 상태·문서/MCP 안내를 검색하고 정리한 뒤 삭제한다. 과거 migration은 수정하지 않고 증분 migration을 만든다. 무차별 CASCADE 삭제는 하지 않는다. 실제 DDL 변경 시 `supabase/schema/OVERVIEW.md`를 갱신한다.

### 전환

기존 공유는 원칙을 포함하지 않았고 기록/할 일이 거부된 사용자도 있다. migration에서 기존 전체 공유를 OFF로 바꿔 묵시적 범위 확대를 막는다. 이름·비밀번호·친구 연결·포트폴리오 내용은 보존한다. 새 화면의 범위를 보고 사용자가 ON하면 전부 공유된다. 별도의 동의 버전·상태 머신은 만들지 않는다.

구 클라이언트가 포괄 범위를 모른 채 기존 `set_viewer_profile`로 다시 ON하는 경로도 차단한다. 최소 계약은 새 클라이언트가 ON 요청에 고정된 전체 공유 범위 값(예: `input_share_scope: 'portfolio_all'`)을 명시하게 하는 것이다. 이 값은 프로필에 저장하는 버전이 아니라 ON API의 필수 의도 확인이다. 구 signature는 OFF/접속 정보 유지에만 허용하거나 명확한 앱 새로고침 오류로 퇴역한다. ON을 허용하는 wrapper로 남기지 않는다. Sol은 동일 이름 overload 충돌이 없는 최종 signature와 실제 호출 검증을 티켓에 기록한다.

원격 migration/웹·Edge 배포는 같은 릴리스 범위로 관리한다. 원격 적용 전 별도 배포 승인을 확인하며 로컬 구현 요청을 운영 권한 변경으로 확대하지 않는다.

## 수직 슬라이스와 인수

1. **내 전체 공유 → 친구/게스트 네 탭 읽기 → 공유 중지**: 서버 읽기 경계·원칙 조회·전체 스위치/새 ON 계약·읽기 전용 웹을 연결한다. 전체 OFF, 무관한 제3자, 다른 owner ID, 직접 쓰기 호출 거부를 검증한다.
2. **공유 하기/공유 받기 화면 정돈 → 연결/보기/해제**: 두 카드와 공통 필드, 입력 초안 보존, 연결 성공/실패를 실제 API로 검증한다. 이어 사용하지 않는 개별 정책 코드/테이블/RPC를 정리하고 의존성 검사를 수행한다.
3. 실제 검증 기록·MCP 가이드 영향 검토·인계 갱신 후 관련 변경만 커밋한다. 기존 dirty 작업을 함께 커밋하지 않는다.

- [x] 개별 공유 스위치/현재 상태 박스/상단 저장 버튼이 없고 공유 하기/공유 받기 카드가 같은 배치를 따른다.
- [ ] 이름·비밀번호 최초 설정/수정, 빈 비밀번호 유지, 중복 이름/짧은 비밀번호, 입력 중 ON/OFF, 실패·응답 유실 시 초안과 확정 상태를 검증한다.
- [ ] 자산/배분/할 일·기록/원칙 현재·이력·본문 및 연결 상세를 친구와 게스트가 읽고, 모든 수정/삭제/금융 실행은 서버에서 거부된다. 설정/토큰/피드백/내부 JSON이 노출되지 않는다.
- [ ] 전체 OFF·친구 연결 해제·게스트 만료/비밀번호 변경 뒤 접근이 기존 의미대로 차단된다. 이전 owner 데이터나 늦은 응답이 새 화면에 남지 않는다.
- [x] 기존 ON 사용자는 전환 후 OFF, 구 클라이언트 ON 요청은 거부, 새 화면에서 ON하면 포괄 공유가 가능하다. 투자 데이터/접속 정보/연결은 보존된다.
- [x] 개별 정책 테이블·쓰기 RPC·UI 의존성을 제거했고 기능 키 호환은 저장 상태 없이 작동한다. owner MCP 호출과 입력 스키마/가이드 계약이 여전히 맞는다.
- [ ] 360/390/768/1024/1440px에서 긴 이름·오류·로딩·연결 없음/여러 명, 200% 확대·키보드·44px 터치 영역을 확인한다. 공유 하기/받기의 같은 폭 캡처를 비교한다.

## 현재 상태와 Sol 인계
