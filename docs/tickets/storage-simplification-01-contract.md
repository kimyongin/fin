## 목적

사용자 기능에 필요한 최소 저장·처리만 유지하고 기존 데이터와 공개 범위를 보존한다. 기존 구현의 존재는 유지 근거가 아니다.

## 인수 조건

- [ ] 원칙만 같은 테이블의 변경 행으로 이력을 관리한다. 안정 원칙 ID와 행 ID를 구분하고 적용 시작 시각/종료 여부로 현재·특정 시점 조회 계약을 확정한다. 최신 행 선택 후 종료 필터, 동일 시각 정렬, 사용자 시간대 날짜 경계를 검증한다. 다른 도메인에 의무 이력을 확대하지 않는다.

- [ ] 추가 확정사항을 계약에 반영한다: 활동의 최소 자동 분류, 활동 삭제와 잔고/할 일 상태의 독립, 반복 오늘 완료와 전체 종료, 일시정지/재개 제외, 원칙 한 행 단위 저장, 최신 매매 포함 되돌리기 제외, 세부 과거 이력은 내보내기로 보존. 이 항목들을 미정 제품 선택으로 다시 열지 않는다.

- [ ] 로컬/운영 적용 상태를 구분해 테이블·RPC·트리거·FK·웹·MCP 소비자와 실제 데이터 건수(내용 비노출)를 조사한다. 전체 테이블마다 유지/통합/보관/삭제 후보, 목적지, 소비자, 종료 조건을 한 행으로 남긴다. 검색에서 안 보인다는 이유로 미사용 판정하지 않는다.
- [ ] 새 활동·할 일·원칙·자산 쓰기의 최소 DDL/입출력/권한 계약을 정한다. 기존 컬럼 재사용을 우선하고 기존 상태·출처·복수 연결 이관표를 작성한다.
- [ ] 일반 편집은 선택 필드 patch·현재값, 금융 쓰기는 잠금/충돌 감지·중복 요청 방지·원자 저장으로 구분한다. 공통 영수증의 범위/재시도 보존기간을 실제 매수 슬라이스에 필요한 만큼 정한다.
- [ ] 과거일 매매의 현재 반영 여부, 완료 취소/반복 회차, 원칙 적용 범위, 출처·메모 공유를 예제 입력/출력과 fixture로 확정한다. 기존 비공개 값은 통합 뒤에도 비공개여야 한다.
- [ ] 테이블·MCP 도구·사용자 저장 단계 수의 현행 기준과 목표를 기록한다. 독립 기능 근거 없는 history/revision/preview 추가를 금지한다. 전체 프레임워크 선구현 없이 02의 저장/재조회 계약이 검증되면 종료한다.

## 구현 방식

관련 DB/API·MCP/UI·가이드·검증을 수직 슬라이스로 연결하고 슬라이스마다 커밋한다. 일반 코드 구현/배포는 이 티켓 작성에 포함하지 않는다. 미정 세부 기술 선택은 위 범위 안에서 구현자가 근거를 기록해 확정한다. 제품 기능 축소 범위를 추가로 넓히면 먼저 영향과 대안을 명시한다.
