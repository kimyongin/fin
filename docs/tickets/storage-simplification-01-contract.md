## 목적

사용자 기능에 필요한 최소 저장·처리만 유지한다. 구 투자 행의 삭제는 사용자가 허용했고 새 데이터의 공개/접근 경계는 지킨다. 기존 구현의 존재는 유지 근거가 아니다.

## 인수 조건

- [x] 원칙만 같은 테이블의 변경 행으로 이력을 관리한다. 안정 원칙 ID와 행 ID를 구분하고 적용 시작 시각/종료 여부로 현재·특정 시점 조회 계약을 확정한다. 최신 행 선택 후 종료 필터, 동일 시각 정렬, 사용자 시간대 날짜 경계를 검증한다. 다른 도메인에 의무 이력을 확대하지 않는다.

- [x] 확정사항을 계약에 반영한다: 활동의 최소 자동 분류, 활동 삭제와 잔고/할 일 상태의 독립, 반복 오늘 완료와 전체 종료, 일시정지/재개 제외, 원칙 한 행 단위 저장, 최신 매매 포함 되돌리기 제외. 사용자가 구 투자 행 삭제를 허용했으므로 세부 과거 이력의 의무 내보내기는 요구하지 않는다.

- [x] 로컬/운영 적용 상태를 구분해 테이블·RPC·트리거·FK·웹·MCP 소비자와 초기 데이터 건수(내용 비노출)를 조사한다. 처분 후보와 남은 외부 소비자 예외는 전수 대조/운영 인계에 기록한다. 검색에서 안 보인다는 이유만으로 토큰 MCP를 미사용 판정하지 않는다.
- [x] 새 활동·할 일·원칙·자산 쓰기의 최소 DDL/입출력/권한 계약을 정하고 수직 슬라이스에서 기존 컬럼 재사용을 우선한다. 사용자가 삭제를 허용한 구 행의 상태/출처 이관표는 더 이상 완료 조건이 아니다.
- [x] 일반 현재값 편집과 금융 잠금/충돌 감지·중복 요청 방지·원자 저장을 구분한다. 금융 영수증은 응답 유실/재전송에 필요한 범위로 유지하고 범용 변경 엔진은 만들지 않는다.
- [x] 과거일 매매의 현재 반영, 반복 회차/전체 종료, 원칙 적용 범위, 출처·메모 공유를 예제와 DB/브라우저 fixture로 검증한다. 새 비공개 값은 통합 뒤에도 비공개다.
- [x] 초기 조사 대비 현재 분리 DB 테이블·함수, OAuth MCP 도구, 대표 저장 단계 수를 운영 인계에 기록했다. 독립 근거 없는 history/revision/preview 추가를 금지하고 02의 저장/재조회까지 수직 검증했다.

## 구현 방식

관련 DB/API·MCP/UI·가이드·검증을 수직 슬라이스로 연결하고 슬라이스마다 커밋한다. 일반 코드 구현/배포는 이 티켓 작성에 포함하지 않는다. 미정 세부 기술 선택은 위 범위 안에서 구현자가 근거를 기록해 확정한다. 제품 기능 축소 범위를 추가로 넓히면 먼저 영향과 대안을 명시한다.
