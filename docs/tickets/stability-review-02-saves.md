# [안정화 재검토] 원칙·후속 할 일 저장 재시도와 날짜 기준 정리

우선순위: P1 · 상태: 티켓 작성, 구현 전 · 2026-09-23
관련: #92, #94, #89 · 기준 코드: b7ee31d

## 문제와 근거
`PrincipleJournal.jsx:45`는 신규 저장마다 principle_id를 만들고, 저장과 reload를 같은 try/catch로 처리한다. 저장 성공 후 조회 실패 시 재시도로 신규 원칙이 중복될 수 있다. `ActivityDetailModal.jsx:82`의 후속 할 일도 재시도마다 요청 키가 달라진다. `strategy/data.js:41`의 과거 원칙 조회는 웹 기본 Asia/Seoul 대신 기기 시간대를 사용한다. 정적 검토 결과이며 응답 유실/조회 실패를 주입해 재현한다.

## 범위
- 신규 원칙 ID는 편집 세션 동안 유지한다. 같은 원칙 ID/내용 재전송을 처리하는 기존 app_save_principle 계약을 활용한다.
- 후속 할 일은 origin activity ID와 제출 내용에 묶인 요청 키를 유지한다. 입력 수정/성공/새 작성 시도에서 키를 갱신하는 규칙을 명시한다.
- 저장 성공과 새로고침 실패를 구분하고, 성공한 저장을 다시 실행하지 않고 읽기만 재시도하게 한다.
- 일반 편집/태그/완료의 재시도도 현행 계약과 대조하되 새 영수증 테이블이나 범용 mutation 엔진을 추가하지 않는다. 실제 재사용되는 작은 helper만 허용한다.
- 과거 원칙 날짜 조회는 웹의 Asia/Seoul 업무 기준을 사용한다. MCP의 명시적 timezone과 기존 timestamps는 유지한다.

## 완료 조건
- [ ] 원칙/후속 할 일 저장 응답 유실 후 같은 입력 재시도에서 한 건만 생성된다.
- [ ] 원칙 저장 성공 후 목록 실패를 저장 실패로 표시하지 않고 읽기 재시도로 복구한다.
- [ ] 원칙 변경·종료 이력 및 동시 수정 충돌 검사를 유지한다.
- [ ] 입력 변경·다른 원본 활동·새 편집 세션이 이전 제출과 혼동되지 않는다.
- [ ] 한국 날짜 경계와 해외 기기 시간대에서 같은 선택일의 원칙을 조회한다.
- [ ] API 변경 여부와 MCP 설명/가이드 영향을 기록하고 필요한 회귀를 실행한다.
