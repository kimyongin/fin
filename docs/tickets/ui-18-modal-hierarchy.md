# [공통 UX] 모달 계층·확인 단계 통일

2026-09-24 · 로컬 구현/검증 진행. 운영 배포 전.

GitHub: https://github.com/kimyongin/fin/issues/126

후속 설계 [#127](./ui-19-tag-management-consistency.md)은 2차를 의사 확인 전용으로 제한하고 태그 관리 흐름을 통일한다. 이 티켓의 확인 기반과 남은 검증을 대체/완료 처리하지 않는다. 태그 목록→별도 편집창 전환과 활동 상세의 태그 사전 CRUD는 #127에서 정리한다.

상위 기준: [모달 디자인 가이드](../design/modal-guidelines.md), [모바일 디자인 원칙](../design/PRINCIPLES.md). 연계: [#123 직접 편집·단일 저장](./ui-16-modal-inline-edit.md), [#124 자산 상세](./ui-17-asset-detail-simplification.md).

## 목적

사용자가 상세 모달에서 편집하다 닫기·삭제·반복 종료·금융값 저장을 선택할 때 확인 위치와 동작을 예측할 수 있어야 한다. 지금은 어떤 확인은 별도 모달처럼 보이고, 어떤 확인은 기존 footer가 커지거나 버튼 이름만 바뀐다. 단일 대상의 편집은 유지하면서 짧은 최종 결정만 계층 2의 확인 모달로 통일한다.

## 현행 대조

| 경로 | 현재 방식 | 목표 |
| --- | --- | --- |
| `ModalShell`의 미저장 닫기 | footer 안에 문구·버튼 삽입 | 계층 2 확인. X/Escape/푸터 닫기/뒤로가기가 같은 경로 |
| `ModalActions`의 계좌·종목·보유·태그 삭제 | footer를 삭제 확인 카드로 교체 | 대상·영향이 적힌 계층 2 확인 |
| `ActivityDetailModal` 기록 삭제 | footer 버튼명과 안내문 변경 | 계층 2 확인. 잔고/할 일 불변 설명 유지 |
| `GeneralTaskDetail` 반복 종료 | footer 버튼명과 안내문 변경 | 계층 2 확인. 과거 완료 기록 유지 설명 |
| `AssetDetailModal` 보유값 저장·보유 삭제 | 원래 상세를 짧은 `ModalShell`로 교체, 미저장 삭제는 footer 확인을 먼저 거침 | 상세 초안·스크롤을 화면에 유지하고 계층 2 하나만 활성화. 미저장 삭제는 한 번에 영향 확인 |
| `PrincipleJournal` 원칙 적용 종료 | 상세 footer에서 바로 실행 | 영향 확인이 필요한지 검토 후 같은 규칙 적용 또는 이유 기록 |

`TradeEntryModal`/`HoldingIntegrityModal`의 미리보기는 최종 확인 모달이 아니라 같은 업무 입력의 단계다. `SpreadsheetEditor`와 다른 편집 모달의 미저장 닫기는 공통 `ModalShell` 변경을 함께 적용한다. `StrategyPage`의 페이지 이동 `window.confirm`은 모달 내부 사례가 아니므로 별도 대조만 기록하고 이 티켓에서 무리하게 교체하지 않는다.

## 적용 계약

1. 계층은 페이지(0) → 대상의 조회·편집 모달(1) → 짧은 최종 확인(2)까지만 둔다. 2가 열리면 1은 초안·스크롤을 유지하며 비활성화한다. 키보드와 접근성 트리에서 활성 dialog는 하나다. 3단계는 금지한다.
2. 확인을 취소하거나 X/Escape를 누르면 1로 돌아오고 입력과 포커스가 보존된다. 1의 X/Escape/푸터 닫기/뒤로가기는 dirty 여부와 관계없이 같은 닫기 규칙을 사용한다. 깨끗한 폼은 확인 없이 닫는다.
3. 미저장 상태에서 삭제 같은 별도 행동을 하면 2에서 버려지는 초안과 삭제 영향을 함께 설명한다. `버리고 계속` → `삭제 확인`처럼 두 번 연속 묻지 않는다. 사용자가 변경을 먼저 저장하려면 1로 돌아가 저장한다.
4. 확인은 짧은 제목·대상·영향·취소/구체적인 실행 버튼으로 구성한다. 저장 확정은 강조색, 삭제/버리기는 위험색. 단순 입력 오류나 성공 알림을 새 모달로 만들지 않는다. 실패·중복 클릭·진행 중 닫기 방지는 확인 계층에서 처리하고 실제 쓰기 계약은 바꾸지 않는다.
5. 공통 모달의 포커스·배경 inert·스크롤 잠금·레이어 순서만 공유한다. 자산/활동/할 일의 저장·삭제 판단은 각 기능에 남긴다. 데이터 모델·RPC·MCP 계약을 바꾸지 않는다.

## 구현 순서

1. 기존 `ModalShell`을 재사용하는 얇은 확인 계층을 만든다. 부모/자식 대화상자를 DOM·포커스·aria 관점에서 검증하며 기존 초안과 스크롤을 보존한다.
2. 공통 미저장 닫기와 `ModalActions` 삭제를 이 계층으로 바꾼다. 계좌·종목·보유·태그·표 편집·원칙·활동 추가의 경로를 회귀한다.
3. 기록 삭제·반복 종료·자산 저장/삭제를 적용한다. 자산의 미저장 삭제는 하나의 확인으로 줄이고, 오류 시 동일 확인에서 재시도한다. 나머지 도달 가능한 모달을 전수 대조해 예외가 있으면 가이드와 이 티켓에 이유를 적는다.

## 완료 기준

- [x] 위 현행 대조의 모든 도달 가능한 경로가 가이드와 일치하며 footer 확장형 확인이 없다. 의도적 예외는 사유·화면을 명시한다.
- [x] 동시에 조작 가능한 dialog가 하나이고 2단계에서 1단계의 초안·스크롤·목록 문맥이 보존된다. 취소/Escape·확정 뒤 초점 복귀를 자동 검증했다. X는 같은 `onClose` 경로를 사용한다.
- [ ] 미저장 닫기·삭제, 반복 종료, 금융값 저장의 정상/실패/재시도와 저장 중 잠금을 검증한다. 일반 삭제·금융 저장의 실패/재시도는 확인했으나 반복 종료 실패·확인창 저장 중 잠금은 자동 사례가 남았다.
- [ ] 360/390/768/1024/1440px의 짧은/긴 대상명, 키보드·가로 넘침·footer·모바일 확인창 높이를 확인한다. 자동 폭 검사와 390/1024px 캡처는 확인했고 긴 이름·실기기 키보드·스크린리더는 미검증이다.
- [x] 관련 E2E, 단위 테스트, 빌드·인코딩·diff 검사와 문서 적용표를 갱신한다. 운영 배포는 별도 게이트다.

## 로컬 적용 기록

- `ModalShell` 미저장 닫기를 portal 기반 `ConfirmDialog`로 통일했다. 2단계가 열린 동안 1단계는 DOM·화면·초안·스크롤을 유지하고 조상 `inert`로 입력·접근성 탐색에서 제외된다. 2단계가 닫히면 호출 버튼으로 초점이 복귀한다.
- `ModalActions` 삭제, 기록 삭제, 반복 종료, 원칙 적용 종료와 자산 상세의 보유값 저장·보유 삭제를 같은 계층으로 전환했다. 미저장 삭제는 한 확인에서 초안 폐기와 삭제 영향을 함께 설명한다. 실패 시 같은 확인에 오류를 보여주고 재시도한다.
- 매매/보정 미리보기는 최종 확인 모달로 바꾸지 않았다. 해당 업무의 입력 단계이고 기존 금융 계약을 유지한다. `StrategyPage`의 페이지 이동 `window.confirm`도 모달 내부 사례가 아니므로 범위 밖이다.
- DB·RPC·MCP 계약은 변경하지 않았다. 운영 배포 및 실기기 키보드·스크린리더 검증은 별도 게이트다.

## 검증

- `npm test`: 101개 통과. `npm run build`, `npm run check:encoding`, `git diff --check` 통과. 빌드의 기존 500 kB 청크 경고는 남는다.
- 격리 E2E: DB 542개, OAuth/토큰 MCP 계약, 브라우저 60개 중 최초 전체 실행은 59개 통과. 남은 하나는 퇴역한 `app_save_holding.input_note`를 보내던 테스트였고 현재 RPC 계약으로 고쳐 단독 재검증을 통과했다. 이후 추가한 미저장 삭제·시각 검사 2개와 초점·Escape·스크롤 검사 2개도 각각 통과했다. 따라서 전체 60개 경로는 분할 실행 기준 통과했고, 최종 수정 상태의 일괄 60개 재실행은 하지 않았다.
- 브라우저에서 360/390/768/1024/1440px의 자산 저장 확인창 가로 넘침을 검사했다. 390/1024px의 공통 미저장 확인창 캡처를 직접 확인했다. 부모 초안·스크롤·`inert`, 확인 취소 뒤 초점, 확인 중 뒤로가기가 3단계 확인을 만들지 않는 경우를 검사했다.
- 실기기 가상 키보드, 스크린리더, 긴 대상명과 모든 위험 행동의 실패/진행 중 상태는 아직 검증하지 않았다. 운영 배포는 하지 않았다.
