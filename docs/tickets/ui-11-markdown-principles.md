# [원칙] 분류·적용 범위를 없애고 자유로운 마크다운으로 관리

2026-09-24 · P2 · 로컬 구현·자동 검증 완료, 운영 전환 전.

GitHub: https://github.com/kimyongin/fin/issues/118

## 목적과 결정

후속 설계 [#132](./principles-01-single-current-document.md)는 사용자별 현재 문서를 하나로 제한한다. 아래 다중 원칙 항목 추가/ID별 현재 조회·개별 종료 요구는 대체되며 본문·변경 메모·이력 표현은 유지한다. 기존 구현/검증 기록은 당시 상태이며 단일 문서 전환 완료 증거가 아니다.

배분의 계산 가능한 태그별 목표 숫자는 [#121](./ui-14-tag-allocation.md)에서 관리한다. 이 티켓은 서술형 원칙 본문/변경 메모를 담당한다.

사용자는 자신의 투자 기준과 데이터 관리 방법을 자유롭게 적고 ChatGPT가 그 내용을 읽어 조언에 활용하기를 원한다. 분류나 적용 범위를 먼저 정해야 하는 구조는 입력 부담과 확장 제약을 만든다. 원칙 내용은 마크다운 본문으로 줄이고 저장 시 선택적인 변경 메모를 받는다. 메모는 원칙의 속성이나 현재 지킬 기준이 아니라 해당 변경을 설명하는 이력 정보다. 화면뿐 아니라 DB·웹 API·MCP·가이드에서도 분류/범위 의존을 제거한다.

하나의 원칙에 여러 제목과 항목을 적어도 된다. 필요하면 여러 원칙으로 나눌 수 있지만 한 문장이나 주제마다 별도 레코드를 만들도록 요구하지 않는다. 기존 원칙들을 강제로 한 문서로 합치지도 않는다. 별도 필수 제목·태그·유형·구조화 JSON·마크다운 frontmatter는 추가하지 않는다.

과거 어떤 원칙으로 운영했는지 보는 목적은 유효하므로 #114의 현재 원칙/변경 타임라인과 동일 테이블 이력을 유지한다. 목표 비중은 배분의 구조화된 입력이고, 본문에 쓴 숫자가 그 설정을 자동 변경하지 않는다.

## 실제 구현에서 바꿀 곳

- `src/features/strategy/PrincipleJournal.jsx`: 8가지 분류 선택, 범위 입력, 현재/이력의 분류 배지와 단순 텍스트 표시를 제공한다.
- `src/features/strategy/data.js`: 저장 시 `input_kind`, `input_scope`를 전달한다.
- `principles`: `kind`, `scope`, `body`와 소유자·안정 ID·행 ID·적용 시각·종료 여부를 저장한다. `principles_kind_idx`도 제거 대상이다.
- `app_list_principles`, `app_save_principle`, `app_list_principle_changes`, `app_get_daily_context`: 새 원칙 형태로 저장·현재/과거/이력·문맥을 일치시킨다.
- `supabase/functions/_shared/mcp/portfolio-tools.ts`, `portfolio-mcp-oauth/index.ts`: `save_principle`은 현재 `kind`가 필수이고 `scope`를 허용한다.
- `workflow-guides.ts`의 policy/reconciliation 및 `docs/design/contracts/agent/`에는 원칙 하나씩 저장하거나 `kind=operation`/scope로 선별하라는 안내가 있다.
- 기존 `src/components/MarkdownContent.jsx`는 제목·목록·강조·링크의 일부 문법만 처리한다. 원칙에서 재사용하기 전에 지원 문법과 링크 URL 처리를 점검한다.

## 사용자 경험

1. 원칙 추가/수정 모달에는 넓은 `내용` 입력란과 짧은 `변경 메모 (선택)` 입력란, 저장/닫기를 둔다. 메모 예시는 `주택 구입 예정으로 현금 확보를 우선하기로 함`이다. 기존 항목의 적용 종료는 유지하고 종료 시에도 메모를 남길 수 있다. 메모는 매번 새로 입력하며 이전 메모를 자동 복사하지 않는다.
2. 예: `## 투자 방향`, `- 장기 보유를 기본으로 한다`, `## 엑셀 입력 시`, `- 현금 행은 별도로 확인한다`를 한 번에 입력한다. 예시를 자동 저장하거나 템플릿 작성을 강제하지 않는다.
3. 현재 원칙에는 최신 본문 전체를 마크다운으로 표시한다. 항목 구별이 필요한 곳은 첫 비어 있지 않은 줄의 짧은 요약을 파생한다. 제목 컬럼은 추가하지 않는다.
4. 변경 타임라인에는 날짜·시각과 변경 메모를 간결하게 나열한다. 긴 본문이나 본문에서 자동 생성한 요약은 목록에 반복하지 않는다. 메모가 없으면 `원칙 추가 / 원칙 수정 / 적용 종료`를 표시한다. 여러 원칙을 구별해야 할 때만 항목의 짧은 식별 문구를 보조 표시한다.
5. 타임라인 항목을 선택하면 해당 변경 행의 날짜·메모·본문 전체를 읽기 전용 상세 모달로 보여준다. 종료 행은 종료 직전 적용하던 본문임을 표시한다. 닫으면 기존 타임라인 위치와 더 보기 상태로 돌아온다. 이전/이후 본문을 쌍으로 표시하거나 줄 단위 DIFF를 생성하지 않는다. 선택한 행의 본문을 보여주며 같은 날 마지막 내용이나 현재 원칙으로 대체하지 않는다.
6. 모바일 전체 화면/넓은 화면 중앙 모달, 고정 액션, 초안 보호는 공통 모달 가이드를 따른다. 리치 텍스트 편집기·분할 편집 화면·새 편집기 프레임워크는 도입하지 않는다.

## 최소 저장·API 계약

- 정본은 기존 `principles.body`의 마크다운 원문이다. 렌더링 HTML이나 추출 분류를 별도로 저장하지 않는다. 소유권과 기존 이력 식별자는 유지한다.
- 같은 변경 행에 nullable `change_note`를 추가해 본문·시각과 원자적으로 저장한다. 별도 메모/이력 테이블은 만들지 않는다. 메모는 일반 텍스트 최대 1,000자, 미입력/공백은 null이다. 기존 행은 null로 두고 과거 변경 이유를 추측하지 않는다.
- 저장 RPC의 선택 인자 `input_change_note`와 MCP의 선택 인자 `change_note`를 일치시킨다. 동일 요청 재시도 판정에는 메모도 포함하고 응답 유실 재시도로 이력이 중복되지 않게 한다. 본문이 같아도 메모가 다른 명시적 저장을 동일 요청으로 무시하지 않는다. 과거 메모 수정 전용 기능은 추가하지 않는다.
- 타임라인의 이전 행 전체를 함께 읽는 `previous` 응답은 이 화면에 더 이상 필요하지 않다. 실제 소비자를 확인해 불필요한 이전 행 조회/응답을 정리한다. 선택 시점 조회는 정확한 행 ID와 소유권을 기준으로 하며 이미 받은 본문이 있으면 재사용한다. 단순히 화면에서 접는다는 이유로 새 조회 API를 만들지는 않는다.
- 증분 migration으로 `kind`, `scope`와 관련 인덱스/검증/SQL 의존을 제거한다. 기존 migration을 수정하지 않는다. 현재 행과 이전 행 응답에서도 두 필드를 제거한다.
- 기존 데이터의 의미를 보존하기 위해 제거할 분류·범위가 있으면 각 기존 행의 본문 앞에 사람이 읽을 수 있는 설명으로 한 번 옮긴다. ID·적용 시각·종료 상태·본문 원문은 보존하며 가짜 변경 시각/추가 이력을 만들지 않는다. 새 입력에는 이 접두부를 요구하지 않는다.
- 쓰기는 기존 원칙 ID·현재 행 ID·본문·종료 의미를 재사용한다. `input_kind`, `input_scope` 없는 RPC 시그니처로 교체하고 구 오버로드·권한 잔재를 제거한다. 충돌/동일 요청 재시도 처리는 유지하며 새 버전 체계를 만들지 않는다.
- 본문의 줄바꿈·들여쓰기를 보존한다. 공백뿐인 본문은 거부하고 기존 10,000자 상한을 웹·RPC·MCP에서 일치시킨다. 이관 접두부 때문에 한도를 넘는 기존 행은 자르지 않는다. 구현 계약 단계에서 해당 행 수와 손실 없는 처리 방식을 기록한다.
- 현재/지정 날짜/변경 이력 조회의 의미와 소유자 전용 경계는 유지한다. 전체 문맥 응답의 크기 제한 때문에 일부 원칙을 제외한다면 누락을 명시하고 전체 원칙 조회 경로를 제공한다. 임의 분류나 앞부분만으로 사용자의 전체 원칙을 판단하지 않는다.

## MCP와 가이드

- 기존 `list_principles`/`save_principle` 이름을 사용한다. 입력 스키마에서 `kind`, `scope`를 제거하고 `body`가 자유 마크다운임을 명시한다. 조회는 원문과 기존 이력 메타데이터를 반환한다.
- 변경 메모는 사용자가 말한 수정 내용/이유를 간결하게 기록하며 추측한 동기는 넣지 않는다. 이유가 없어도 저장을 막거나 반드시 추가 질문하지 않는다. 현재 조언의 기준은 활성 본문이며 과거 변경 메모를 현재 원칙으로 섞지 않는다.
- 인터뷰 → 기존 내용 조회 → 사용자가 요청한 내용 반영 → 저장 → 다시 읽기 흐름을 유지한다. 하나의 문서에 여러 기준을 담을 수 있고, 기존 항목 수정 시 관계없는 본문을 지우지 않도록 설명한다.
- 운영 규칙과 투자 기준의 관련성은 본문을 읽어 판단한다. 분류/범위 필터에 의존하는 지침을 없앤다. 사용자 요청 없는 재분류·자동 분할·자동 저장은 하지 않는다.
- 저장된 원칙은 사용자 선호와 업무 맥락이다. 인증·권한·도구 검증 또는 현재 사용자 지시를 우회하는 시스템 지침으로 취급하지 않는다.
- 웹/MCP를 함께 변경하고 계약 테스트, 워크플로 가이드, 배포 RPC 검사, 로컬 더미 데이터 스크립트의 구 인자를 함께 갱신한다. 운영 전환 시 DB·함수·프런트 적용 순서와 ChatGPT 도구 목록 새로고침을 인계한다.

## 마크다운 표시 범위

제목·단락·순서/비순서 목록·강조·인라인 코드·일반 링크를 지원한다. HTML 실행은 허용하지 않고 위험한 링크 프로토콜을 차단한다. 지원하지 않는 문법도 원문 저장에서 손실되지 않아야 한다. 기존 렌더러 개선이 활동 표시에도 영향을 주므로 활동 회귀를 확인한다. 문서 편집 플랫폼 수준의 기능을 추가하지 않는다.

## 완료 기준

- [ ] 분류·범위·제목 없이 마크다운만 입력해 웹에서 생성/수정/종료하고 현재/이전 내용을 읽는다.
- [ ] 변경 메모 입력/생략/종료 시 저장과 1,000자 상한이 웹·RPC·MCP에서 일치하고 기존 이력은 메모 없는 기본 문구로 읽힌다.
- [ ] 긴 본문이 있는 여러 이력에서도 타임라인은 날짜·메모 중심으로 간결하다. 선택한 행의 전체 본문을 읽고 닫으면 목록 위치가 유지된다. 같은 날 여러 수정·종료 행·더 보기 이후 항목도 정확한 시점의 본문을 표시한다.
- [ ] 본문·메모의 원자 저장과 메모를 포함한 동일 요청 재시도를 검증한다. 메모 없이 저장한 경우를 실패로 보거나 변경 이유를 자동 생성하지 않는다.
- [ ] DB·RPC·MCP 스키마와 응답·가이드에 원칙 분류/범위 의존이 남지 않는다. #121의 태그별 목표 저장은 독립적으로 검증한다.
- [ ] 기존 현재/과거 행의 내용·범위 의미·ID·시각·종료 여부가 보존되고 이관을 재실행해 접두부가 중복되지 않는다.
- [ ] MCP 저장 → 웹 표시와 웹 수정 → MCP 원문 조회를 실제 로컬 API로 검증한다. 한 본문에 여러 기준을 저장할 수 있다.
- [ ] 동일 요청 재시도·충돌·저장 후 조회 실패·비인증/다른 사용자 접근 회귀를 검증한다.
- [ ] 줄바꿈·들여쓰기·한글·목록·긴 URL·빈 내용·상한과 위험한 링크/HTML 표시를 검증한다.
- [ ] 360/390/768/1024/1440px에서 읽기/편집/타임라인/닫기와 하단 메뉴 겹침을 확인한다. 실제 확인한 범위만 기록한다.
- [ ] MCP 계약·관련 DB/E2E·빌드·가이드·인코딩 검사를 수행한다. PRD/ADR/스키마 개요/시작 문서와 배포 검사를 구현에 맞게 갱신한다.

## 순서와 인계

공통 타임라인 표현은 [#119](./ui-12-timeline-consistency.md)와 [타임라인 디자인 가이드](../design/timeline-guidelines.md)를 따른다. 이 티켓은 메모 저장·조회/선택한 행의 본문 상세를 담당하고 #119는 활동과 함께 날짜 그룹·행·상태 표현을 맞춘다. 독자적인 타임라인 스타일을 새로 만들지 않는다.

한 수직 슬라이스로 진행한다. 첫 단계에서 현재 함수 정의와 의존성을 확인해 새 RPC 시그니처/이관 계약을 확정한 다음 DB → 웹/MCP → 타임라인·가이드 → 시나리오 검증을 연결한다. 별도 기반 프로젝트나 범용 문서 모델은 필요 없다.

#114의 동일 테이블 이력과 최신순 탐색을 재사용하되 분류·범위 표시/쓰기 계약 유지 및 목록에서 변경 후·이전 본문을 함께 펼치는 요구는 이 티켓으로 대체한다. 변경 메모 중심 목록과 선택 시점의 전체 본문 상세가 최신 기준이다. #117의 모달 기준은 유지한다.
