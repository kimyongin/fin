# [후속 정리] 업무 날짜와 시간대 처리 통일

우선순위: P2 · 상태: 티켓 작성, 구현 전 · 2026-09-23
관련: #90, #88, #87 · 기준 코드: 8cb943f

## 문제와 근거

TradeEntryModal.jsx/HoldingIntegrityModal.jsx는 UTC 날짜(toISOString)를, 활동 입력은 기기 날짜를, DailyReviewPage.jsx는 Asia/Seoul 날짜를 사용한다. 2026-09-23 한국 오전 7시에서 기존 매매 기본값이 2026-09-22로 계산됨을 확인했다.

## 범위와 최소 계약

- 날짜 입력(YYYY-MM-DD)과 발생 시각(timestamp)을 구분한다. 기존 데이터와 시장 시세 날짜를 일괄 변환하지 않는다.
- 현재 웹의 업무 기본 시간대는 Asia/Seoul로 일관되게 적용하되, 이미 명시된 task/activity/MCP 시간대는 존중한다. 사용자 시간대 설정 기능은 추가하지 않는다.
- 날짜 계산·표시의 작은 helper를 src/lib에 두고 매매/보정/확인, 활동 입력/편집, 반복 시작일, 오늘 판정을 연결한다.
- 날짜만 받은 활동의 시각 변환은 기존 정오 관례와 실제 occurred_at 보존을 검토하고 명시한다. 시세 일자는 거래소 기준이므로 별도로 취급한다.
- API의 명시적 timezone과 웹 기본값 관계를 문서화하고 가이드 영향 여부를 확인한다.

## 완료 조건

- [ ] 한국 00시/07시/09시/23시 및 UTC 날짜 경계에서 기본 날짜와 오늘 판정이 일치한다.
- [ ] 기기 시간대가 한국과 달라도 업무 날짜가 의도대로 표시된다.
- [ ] 명시적 해외 시간대의 반복 회차/활동 날짜가 보존된다.
- [ ] 매매·보정·수행일 저장/재조회와 반복 오늘 완료를 확인한다.
- [ ] 기존 timestamps 및 시장 시세 원본 날짜를 소급 변경하지 않는다.
