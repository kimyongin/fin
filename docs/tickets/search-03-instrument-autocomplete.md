# [활동 검색] 종목명·티커 자동완성과 관련 활동 검색

상태: 설계 완료 · 구현 전 · 2026-09-27
GitHub: https://github.com/kimyongin/fin/issues/163
선행: search-01, 연결 표시 검증은 search-02. 기준: [검색 설계](../design/activity-context-search.md).

S3. `삼성`, `SK`, `005`처럼 일부만 입력해 후보를 고르고, 해당 종목의 할 일·기록을 찾은 뒤 `리스크` 등 내용 조건을 추가한다.

- [ ] 기존 검색창 아래 종목 후보를 제공한다. 1글자부터 짧은 지연, 한글 IME 조합 종료 후 조회, 이름·티커 표시, 최대 5개와 더 보기. 빈 문자열은 후보 없음, 0보유도 포함, 정확/접두/부분 일치 우선이다.
- [ ] 후보를 자동 확정하지 않는다. 선택 시 검색어는 비우고 해제 가능한 관련 종목 조건 1개로 전환한다. 종목+추가 내용+태그+명시적 기간을 조합하며 해제는 나머지 조건을 보존한다.
- [ ] 후보를 고르지 않아도 일반 의미 검색을 유지하고 전체 종목명/티커의 직접 검색은 연결 항목도 찾는다. 자연어 문장을 임의로 파괴하지 않는다.
- [ ] 등록 종목 검색 능력을 웹 HTTP/OAuth 양쪽에 제공한다. 기존 도구/RPC 재사용을 우선하고 owner-only 참조 RPC의 공유 유출을 막는다. 종목 연결 없는 본문 검색과 종목에 명시적으로 연결된 결과를 구분한다.
- [ ] 기존 form-control·TagChip/타이포그래피·PagePanel을 사용한다. 후보는 모달 없이 입력 아래 listbox이며 화살표/Enter/Escape/Tab, active descendant, 터치, 로딩/빈/실패, 늦은 응답과 소유자 전환을 처리한다.
- [ ] 한 글자/한글 조합/영문 대소문자/숫자 티커/동명이종목/긴 이름/0보유/삭제/공유 및 360/390/768/1024/1440px·200% 확대를 검증한다. 선택→검색→상세→복귀→조건 해제의 HTTP/E2E와 MCP 후보→ID 검색을 확인한다.

전역 종목 등록 서비스·검색 전용 화면·외부 주식 카탈로그는 범위 밖이다. 새로운 추상 UI 엔진을 만들지 않는다.
