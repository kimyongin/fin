# [리팩토링] 전략 계산과 화면 표현 분리

2026-09-23 · P2 · 로컬 구현·격리 검증 완료, 운영 배포 전. 관련: #106, docs/engineering/refactoring-review-20260923.md.

## 목적과 근거

src/features/strategy/StrategyPage.jsx의 StrategyDashboard에 비중·부족액·이탈·한도·적립금 계산과 JSX가 함께 있다. 화면 변경과 계산 검증의 범위를 분리한다. 첫 소비자는 기존 전략 대시보드이며 파일 길이 자체를 줄이는 것이 목표가 아니다.

## 범위

- 현재 계산과 입력 기본값/경계 동작을 특성화 테스트로 먼저 고정한다.
- 전략 폴더 내부 순수 함수로 표시용 계산을 추출하고 기존 화면이 사용한다.
- 계산을 분리한 뒤 필요한 경우에만 편집 컴포넌트를 책임별로 이동한다. 모든 내부 컴포넌트를 의무적으로 나누지 않는다.
- 화면·저장값·API·MCP·권한·서버 금융 확정 계산은 유지한다. 잘못된 계산을 발견하면 버그로 기록하고 순수 이동과 구분한다.

## 완료 기준

- [ ] 0원 자산, 평가액 미확인, 모드별 목표, 이탈 기준, 한도와 적립금 경계의 기존 결과를 테스트한다.
- [x] 순수 함수는 React/네트워크/저장 의존성 없이 테스트 가능하다.
- [x] 기존 대시보드가 추출 함수를 소비하고 중복 계산이 남지 않는다.
- [ ] 목표 비중 편집·모드 변경·계산 표시의 수직 회귀를 확인한다. 390px/1440px에서 해당 화면과 편집 상호작용을 검증한다.
- [x] 단위 테스트·관련 E2E·빌드·인코딩 검사를 수행하고 결과/미검증 범위를 기록한다.

범용 계산 엔진/폼 프레임워크, 새 테이블, 금융 계약 변경은 제외한다.

## 구현·검증 기록 (2026-09-23)

StrategyDashboard의 표시용 목표·현재 비중, 부족액, 이탈, 거래 한도 및 적립금 계산을 `src/features/strategy/calculations.js`로 옮겼다. 기존 화면은 같은 반환값을 사용한다. 단위 테스트에 모드별 목표, 0원/미확인 평가액, 이탈 기준과 거래 한도 경계를 추가했다. 기존 전략 저장·누락 평가액·화면 폭 E2E는 격리 전체 실행에서 통과했다. 금융 확정 계산/DB는 변경하지 않았다. 운영 배포·실기기 확인은 하지 않았다.
