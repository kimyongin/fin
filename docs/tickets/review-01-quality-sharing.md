# [제품 리뷰] 계산 품질과 공유 점검 기록 접근 수정

상태: 구현·로컬 검증 완료 · 운영 배포/실사용 확인 전 · 2026-09-21
상위: #40. 기존 책임: #32/#34/#36/#39/#43. 기존 구현을 보완하는 후속 티켓이며 기존 티켓의 미충족 인수 조건을 대체 완료하지 않는다.

## 문제와 사용자 시나리오

- S05/S09: 시세가 없을 때 평균가를 정상 평가처럼 사용하고 환율 누락을 0원으로 합산한다. 사용자는 불완전한 비중으로 판단할 수 있다.
- S23/S24: 소유자가 점검 기록 공유를 켜도 친구 화면은 오늘/판단/할 일 메뉴를 일괄 숨겨 읽을 수 없다.

## 수직 단계 A: 공유 접근

- 기존 can_view_feature 및 *_for_owner RPC를 사용해 현재 사용자와 선택한 소유자의 읽기 권한으로 메뉴를 결정한다.
- 조회 실패/권한 없음은 허용으로 추정하지 않는다. 소유자 전환 시 이전 권한과 상세 데이터가 남지 않아야 한다.
- 공유 화면에는 소유자용 분석 요청/편집 행동을 제공하지 않는다. 기존 공개 DTO와 기본 비공개 정책을 유지한다.
- DB 변경은 필요할 때만 추가하며 grants/개인 기준/보유/체결은 이 읽기 흐름에서 변경하지 않는다.
- [x] 친구가 공유된 브리핑/판단/할 일을 실제 메뉴에서 열 수 있다.
- [x] 기능별 허용/거부, 관계 철회 및 직접 URL 차단을 서버/탐색 계약에서 확인한다.
- [x] 읽기 실패를 허용으로 추정하지 않고 기존 allowlist DTO로 타인 내부 snapshot/근거를 제외한다.

## 수직 단계 B: 계산 품질

- 계산 계약의 누락 시세/환율/오래된 시세/실제 0을 먼저 대조한다. 평균가를 사용한 추정은 명시하며 원가를 시세처럼 설명하지 않는다.
- 앱의 portfolioMath/derived data, 자산 합계/태그/계좌, 전략 계산 및 get_daily_context 소비 경로를 함께 점검한다.
- 알려진 평가액 소계와 미평가 보유를 구분하고 비중 분모를 명시한다. 불완전한 배분으로 확정적인 조정 금액을 제안하지 않는다.
- 모델/응답에 품질 필드를 추가하면 OVERVIEW/API 계약/도구 설명을 함께 갱신한다. 잔고 원장/평균가/과거 분석은 변경하지 않는다.
- [x] 시세 없음, 환율 없음/0, 정상 0, KRW/USD/JPY, 평가형/현금성 fixture를 검증한다. 전부 미평가는 같은 `known_values_only` 계약의 `known_value_krw = 0`으로 처리한다.
- [x] 같은 입력의 앱/MCP 평가 의미와 품질 상태가 `app_get_portfolio_state.valuation_quality`로 일치한다.
- [x] 360/390/768/1024/1440px에서 누락 표시와 가로 넘침이 없음을 확인한다.

## 완료 증거

각 단계의 명령/환경/결과를 기록한다. 운영 배포와 실제 지인 검증은 로컬 자동 테스트와 구별한다. 단계별 검증 후 커밋한다.

### 단계 A 증거

- migration 020의 `app_get_shared_feature_access`가 관계와 기능별 grant를 결합하며 관계 없음/공유 비활성은 fail-closed로 반환한다.
- React 탐색은 공유 소유자마다 접근 범위를 다시 읽고 오늘/판단/할 일/전략/자료/활동을 독립적으로 노출한다. 설정과 쓰기 행동은 공유 화면에서 제외한다.
- `npm run test:db`: 16개 SQL 파일, 227 assertion 통과.
- `npm test -- --run`: 13개 파일, 54개 테스트 통과.
- `E2E_PORT=4180 npm run test:e2e`: 22개 통과. 기존 4173 개발 서버는 유지했다.
- `npm run build`, `npm run check:encoding`, `git diff --check` 통과. 운영 migration/배포와 실제 지인 계정 확인은 아직 수행하지 않았다.

### 단계 B 증거

- migration 021이 보유별 `complete/stale/missing`, 원인 코드, 알려진 원화 소계와 품질 요약을 계산해 `app_get_portfolio_state`와 일일 점검 문맥에 함께 제공한다. OAuth MCP 도구 설명도 누락값을 0으로 취급하지 않도록 갱신했다.
- 앱은 시세 대신 평균가를 사용하지 않고, 환율 누락/0을 평가 불가로 표시한다. 오래된 시세·환율은 알려진 소계에 포함하되 경고하며, 실제 0은 알려진 0으로 유지한다.
- 자산 화면은 알려진 평가액과 제외/오래된 항목 수를 표시하고, 원칙 화면은 평가가 불완전하면 목표 비중·적립금·리밸런싱 금액을 생성하지 않는다.
- `npm run test:db`: 17개 SQL 파일, 245 assertion 통과.
- `npm test -- --run`: 13개 파일, 55개 테스트 통과.
- `E2E_PORT=4180 npm run test:e2e`: 23개 통과. 360/390/768/1024/1440px 반응형 품질 표시를 포함하며 기존 4173 개발 서버는 유지했다.
- `npm run build`, `npm run check:encoding`, `git diff --check` 통과. 운영 migration/배포와 실제 계정 확인은 아직 수행하지 않았다.
