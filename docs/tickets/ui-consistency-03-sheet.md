# [UI 일관성] 표 편집 전체 화면 구조와 저장 영역 개선

우선순위: P1 · 상태: 로컬 구현·자동 검증 완료 · 2026-09-21
상위: #40 · 관련 기존 UI: #36/#47/#53
선행: 01, 02의 실제 구현 surface를 재사용한다.

## 목적과 기준

모바일에서 페이지를 바꿔도 제목·보기·필터·본문·행동 위치를 예측할 수 있게 한다. [화면 구조 규칙](../design/screen-structure.md), [디자인 원칙](../design/PRINCIPLES.md), [컴포넌트 계약](../design/component-system.md)을 적용한다. 기존 유용한 자산 흐름을 보존한다.

## 대상과 작업

대상: features/assets/SpreadsheetEditor.jsx, features/assets/AssetsPage.jsx, components/ModalShell.jsx.

- 현재 표만 fixed z-50이고 저장/롤백이 밖에 남는 구조를 전체 화면 편집 surface로 묶는다.
- 제목/종료·필터/검색·표·개수/오류·롤백/저장을 포함하고 앱 헤더 z-60 및 하단 탐색과 충돌하지 않게 한다.
- 전체 화면 전환 전후 같은 draft와 필터·표 스크롤을 보존한다. 종료는 inline 복귀이며 버리기가 아니다.
- 가로 스크롤은 표 내부에 한정하고 전체 화면/행 취소 등 조작 영역을 44px 이상으로 확보한다.
- 붙여넣기, 행 추가/취소, 이전 값, 전체 롤백, 저장과 기존 내보내기 진입 등 현재 실제 기능을 조사해 보존 목록을 남긴다.

## API·데이터 불변 조건

표현과 상호작용만 변경한다. 기존 feature data/actions 및 RPC를 재사용하며 DB migration·MCP 계약·권한 확대·원가 계산 변경은 없다. 초기 작업에서 실제 호출 API와 보존할 흐름을 기록한다. 서버 소유권·멱등성·버전 충돌·매매/보정 규칙을 우회하지 않는다. 새 프레임워크/라우터/범용 CRUD 엔진을 선행 작업으로 추가하지 않는다.

## 완료 조건

- [x] 필터→붙여넣기/행 편집→확대→축소→저장 후 재조회가 동일 데이터로 이어진다.

## 구현 결과

기존 inline 표와 같은 state를 사용하는 전체 화면 `ModalShell`을 연결하고 필터·표·상태·오류·롤백·저장을 한 surface 안에 배치했다. 확대/축소 뒤 수정 draft가 유지되는 흐름과 5개 viewport를 E2E로 검증했다. 구현 커밋은 `71d0c13`, 회귀 보완은 `e6623dc`다.
