# [활동 UX] 태그 검색 입력 제거와 바로 선택하는 칩 목록

2026-09-26 · Astra 설계 기준 · Sol 로컬 구현. 운영 배포 전.

GitHub: https://github.com/kimyongin/fin/issues/141

## 목적과 범위

활동 모달에서 별도 검색어를 입력할 필요 없이 기존 태그를 보고 바로 선택한다. 태그 관리도 칩 목록에서 바로 대상을 고른다. 사용자 요청의 `활동 태그 검색 제거`는 **태그 이름을 찾는 입력칸 제거**로 정리한다. 활동 목록의 제목/본문 검색, 날짜 필터, 태그를 조건으로 한 기록 조회는 유지한다.

- 제거: 활동 추가·기록 상세·할 일 상세의 `ActivityTagPicker` 검색 input/query/matches/검색 결과 없음 분기.
- 제거: 활동 페이지에서 여는 `TagManagerModal`의 태그 이름 검색 입력과 해당 검색 상태. 태그 목록→새 태그→선택 후 하단 편집은 유지.
- 유지: 자산 태그 관리의 기존 검색. 공유 컴포넌트 변경으로 함께 제거하지 않는다. 검색 유무는 단순한 명시 옵션으로 구별하고 `title` 문자열이나 `showSortOrder`로 기능을 추론하지 않는다.
- 유지: 활동 목록의 태그 OR/모두 포함 조건, 종목/할 일 참조 검색, 자산 태그 단일 선택, 활동 태그 복수 선택, 관리창 추가/수정/삭제·권한.

정본: [태그 가이드](../design/tag-guidelines.md). #127/#128/#125의 활동 태그 검색 요구를 위 범위에서 대체한다. [모달 필드 통일](./ui-29-modal-field-consistency.md)과 같이 적용하되 데이터 모델/API는 바꾸지 않는다.

## 실제 코드와 목표 동작

1. `ActivityTagPicker.jsx`는 현재 query로 tags를 필터링하고 입력/결과 없음 문구를 보여준다. 이를 제거하고 라벨 아래 전체 태그를 기존 순서대로 가로 나열·줄바꿈한다. 선택해도 칩이 재정렬되거나 다른 목록에 복제되지 않는다.
2. 후속 [#143](./ui-32-stable-tag-selection-spacing.md)이 라벨 행의 선택 N개/초기화 표현을 대체한다. 개수는 제거하고 `선택 해제`를 모든 칩 뒤에 두어 라벨 아래 8px 간격과 첫 칩 위치를 유지한다. 부모의 일반 저장에만 연결 상태를 반영한다. #143 구현 전에는 기존 개수/초기화 UI가 남아 있다.
3. 태그가 0개이면 `활동 페이지의 태그 관리에서 태그를 추가할 수 있습니다.`를 표시한다. 로딩/읽기 실패/재시도는 기존 부모 상태를 유지하며 실패를 빈 목록으로 간주하지 않는다.
4. 활동 태그 관리창은 열자마자 `편집할 태그` 칩 목록을 보여준다. `+ 새 태그`, 선택 후 하단 편집, 초기 미선택, 저장 결과, 미저장 전환/삭제 확인은 그대로다. 삭제 후 빈 목록을 검색 결과 없음으로 표현하지 않는다.
5. 목록은 모달 본문과 함께 스크롤한다. 새 접기/더 보기/일정 개수 숨기기/중첩 스크롤/자동 검색 노출 조건을 추가하지 않는다. 태그 수가 많아도 전체 태그에 접근할 수 있다.

## 수정 대상과 구현 경계

- `src/features/lifecycle/ActivityTagPicker.jsx`와 세 소비자 `GeneralActionModal`/`ActivityDetailModal`/`GeneralTaskDetail`.
- `src/components/TagManagerModal.jsx`, 활동 호출자 `LifecyclePage.jsx`. 자산 호출자 `AssetViewToolbar.jsx`가 기존 검색을 유지하는지 함께 확인한다.
- `e2e/activity.spec.js`의 태그 관리 검색 관련 검사는 새 사용자 동작으로 교체한다. 자산 태그 관리 검색과 활동 목록 태그 필터 기존 회귀는 유지한다.
- 검색 제거로 사용하지 않는 state/import/분기를 실제로 없앤다. CSS로 input만 숨기지 않는다.
- DB·MCP 도구/가이드의 태그 기반 검색 계약은 바뀌지 않는다. UI 입력 제거를 서버 검색/API 퇴역으로 확대하지 않는다.

## 인수 조건

- [ ] 활동의 추가/기록 상세/할 일 상세/태그 관리에서 `태그 검색` 입력이 없고 모든 태그가 바로 보인다.
- [ ] 복수 선택·해제·초기화→저장→재조회가 같은 태그 ID를 유지한다. 공유 사용자는 연결 편집/관리에 접근하지 못한다.
- [ ] 활동 목록은 기존 제목/본문/기간/태그 OR·모두 포함 조회가 동작하며, 관련 종목/할 일 검색도 유지된다.
- [ ] 활동 태그 관리의 추가/이름 수정/삭제·미저장 보호·재시도와 자산 관리의 기존 검색이 정상이다.
- [ ] 360/390/768/1024/1440px의 0/1/30개·50자/공백 없는 이름을 확인한다. 칩 잘림/가로 넘침/중첩 스크롤 없이 키보드·모바일 터치로 선택할 수 있다.
- [ ] 태그 가이드와 테스트에서 제거된 검색 요구를 대체하고 인코딩 검사 결과를 기록한다. 구현/실기기/운영 상태를 구분한다.

## 인계

활동 선택기에서 검색 state/입력/빈 결과 분기를 제거하고 전체 칩을 표시한다. 공통 태그 관리창은 활동 호출자에 명시적 `showSearch={false}`를 주고 자산은 검색을 유지한다. 기능/권한/저장 계약은 바꾸지 않았다. 활동·자산 E2E 32개와 360/390/768/1024/1440px의 태그 관리·활동 상세 경로가 통과했다. 실기기·운영 배포는 미검증이다.
