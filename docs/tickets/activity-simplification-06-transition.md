## 인수 조건

- [x] #75~#79 실제 로컬 구현을 코드·migration·테스트로 확인하고 재사용했다. 이전 운영 적용 기록은 유지하며 이번 운영 배포를 완료한 것으로 표기하지 않는다.
- [x] 기존 판단 상태·본문·원칙·복수 task/브리핑/보유 이유/리포트 연결과 이전 번들 metadata 태그를 보존한다. 활동의 판단 제목과 상세 이동을 추가하되 판단 정본·이력은 기존 테이블에 남겼다.
- [x] 기존 migration은 보존하고 증분 적용과 격리 환경 전체 재적용, ID 매핑·건수/관계/본문 fixture를 검증했다. 이름/날짜 추정 병합이나 기존 테이블 선삭제를 하지 않는다.
- [x] 수동 활동의 제목/날짜/결과 수정이 같은 ID 한 건에 반영되고 자동 금융 원본은 일반 편집으로 바뀌지 않음을 검증했다. 새로운 활동은 사용자 등록에 따라 생기며 강제 판단 대체 절차는 없다.
- [x] 기존 반복/완료 취소·재개·회차 태그, 사전 태스크 없는 한 일, 선택 후속 연결과 기존 참조 탐색을 회귀 검증했다. 새 완료 이력 체계를 추가하지 않는다.
- [x] 편집 후 키워드·임베딩 stale 처리·저장 리포트 재생성 표시와 사용자 격리를 검증했다. 별도 변경 이벤트 없이 현재 행의 해시/수정시각을 사용한다.
- [x] 종류 선택 없는 등록/완료, 같은 상세의 결과 수정·후속/판단 이동, 중복 없는 한 일, 단일 검색창, 앱/MCP 동일 기록을 검증했다. Chromium에서 360/390/768/1024/1440px 핵심 활동 흐름의 가로 넘침 없음도 확인했다.
- [x] 격리 DB→OAuth MCP→브라우저 게이트와 임베딩 활성/fallback을 인계했다. 운영 DB/Edge/앱 배포와 실제 ChatGPT 웹·모바일 사람 평가는 미실행 외부 게이트로 분리했다.

## 로컬 릴리스 증거

- 새 격리 Supabase에 migration 전체를 순서대로 재적용하고 DB 516 assertions를 통과했다.
- OAuth/legacy MCP initialize·도구 discovery·인증·저장/재조회·오류 계약을 실제 Edge 호출로 통과했다.
- Chromium 33개 시나리오에서 활동 통합, 기존 금융/공유/피드백/원칙 흐름과 360~1440px 핵심 상태를 검증했다.
- Vitest 107개, production build, Deno Edge type check, UTF-8/LF 및 workflow guide review 검사를 통과했다.
- 운영 readiness 검사는 현재 셸에 `SUPABASE_URL`, anon key, smoke 계정 비밀값이 없어 실행하지 않았다. 격리 E2E 성공과 운영 readiness를 구분한다.

기존 구조를 활용해 필요한 최소 변경만 적용했다. 일반 활동에 불변성·별도 결과 저장·의무 수정 이력을 도입하지 않았고 금융 원본/계산/인증/권한과 기존 재시도·반복 동작을 유지했다. 사용자 로컬 설정과 실제 로컬 데이터는 초기화하거나 커밋하지 않았다. 운영 배포와 실제 ChatGPT 사람 평가는 사용자의 별도 배포 요청 범위다.
