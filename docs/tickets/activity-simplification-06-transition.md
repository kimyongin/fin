## 목적

U01~U08. 필요한 보존과 실제 사용성을 확인하며 과거 기록을 전환한다.

## 인수 조건

- [ ] #75~#79 실제 로컬/운영 적용 상태를 확인한다. 과거 티켓 문구만으로 재구현하거나 미검증 게이트를 닫지 않는다.
- [ ] 기존 판단 상태·본문·원칙·복수 task/브리핑/보유 이유/리포트 연결과 이전 번들 metadata 태그를 보존한다. 기존 이력 보존과 신규 일반 편집의 이력 생성을 혼동하지 않는다.
- [ ] 기존 migration은 보존하고 증분 이관·ID 매핑·건수/관계/본문 대조·재실행을 검증한다. 이름/날짜 추정 병합이나 기존 테이블 선삭제를 하지 않는다.
- [ ] 수동 활동의 제목/날짜/결과 수정이 같은 ID 한 건에 반영되고 자동 금융 원본은 일반 편집으로 바뀌지 않음을 검증한다. 새로운 활동은 사용자 등록에 따라 생기며 강제 판단 대체 절차는 없다.
- [ ] 기존 반복/완료 취소·재개·회차 태그, 사전 태스크 없는 한 일, 선택 후속 연결과 기존 참조 탐색을 회귀 검증한다. 새 완료 이력 체계를 추가하지 않는다.
- [ ] 편집 후 keyword/snippet·임베딩 갱신·저장 리포트의 재생성 필요 표시와 공유 정보 차단을 검증한다. 별도 변경 이벤트가 없어도 정상 동작해야 한다.
- [ ] 사용성 기준은 종류 선택 없이 등록/완료, 같은 상세에서 결과 추가/수정·후속 확인, 중복 없는 한 일, 단일 검색창, 앱/MCP 동일 기록이다. 360/390/768/1024/1440px의 관련 상태와 실제 관찰 결과를 기록한다.
- [ ] DB→Edge→readiness→앱 배포/복구와 임베딩 설정/미활성 상태를 인계한다. 운영 배포·실제 ChatGPT 평가를 별도 기록하고 문서/스키마 인덱스/티켓을 실제 구현과 맞춘다.

## 실행 기준

기존 구조를 활용해 필요한 최소 변경을 사용자 기능 단위로 구현한다. 일반 활동에 불변성·별도 결과 저장·의무 수정 이력을 도입하지 않는다. 금융 원본/계산/인증/권한과 기존 재시도·반복 동작은 유지한다. 이번 갱신은 설계·티켓만 변경하며 구현·배포 완료를 뜻하지 않는다.
