# [공통 UX] 상단 카드 구조 통일과 자산 태그·미분류 필터

GitHub: https://github.com/kimyongin/fin/issues/136

## 목적과 정본

자산·배분·활동·원칙에서 문맥/조작/검색의 위치를 예측할 수 있게 하고, 자산의 미분류 종목을 찾아 태그를 지정하는 흐름을 제공한다.

정본: [페이지 상단 카드·필터 가이드](../design/page-panel-guidelines.md). 글자는 #135, 자산 3열은 #134, 태그 표현은 #128, 활동 기간/검색 의미는 #131을 따른다. 이 티켓은 표현과 자산 조회 조건을 변경하며 데이터 모델·원칙 문서·반복 의미는 바꾸지 않는다.

## 현재 구현 근거

- `AssetsPage.jsx`: 평가 요약 section과 별도 계좌/검색/추가/표 편집 div. `visibleRows`는 이름/티커 검색만 적용하며 합계는 계좌 범위만 사용한다. `tagMapByTicker`, `tags`가 이미 전달된다.
- `ActionTimeline.jsx`: 카드 내부 PageToolbar 검색/행동과 기간/태그 폼. 적용 전 검색 초안과 서버 검색 조건을 구분한다.
- `StrategyPage.jsx`: 전체 계좌 태그별 배분 상단과 별도 목표 편집 본문. `assetToolbar`로 태그 관리를 삽입한다.
- `PrincipleJournal.jsx`: 현재 원칙 섹션·카드 내부 날짜/수정/본문과 변경 이력. 새로운 요약 카드가 필요하지 않다.
- `AssetDetailModal.jsx`의 대표 태그 선택/저장과 기존 종목 갱신을 재사용한다. 태그는 계좌별 보유가 아니라 종목 공통이다.

## 확정 계약

- 네 화면의 상단은 문맥·행동/선택적 핵심·보조 정보/선택적 필터의 공통 골격과 여백을 따른다. 없는 영역은 생략한다. 활동에 통계를 추가하거나 원칙에 수정 버튼을 중복하지 않는다.
- 자산의 계좌/검색/태그를 상단 카드 내부 필터 구획으로 이동한다. 가격 갱신·보유 추가·계좌 추가·표 편집은 카드 첫 줄 행동으로 묶는다. 계좌 수정 접근은 현재 계좌 선택과 연결된 보조 행동으로 필터 구획에 유지한다.
- 자산 태그는 전체/태그 없음/실제 태그 칩. 복수 OR, 계좌·검색과 AND, 즉시 적용. 전체는 태그 조건만 해제한다. 활동의 OR/AND는 유지하되 검색어도 짧은 입력 지연 후 자동 적용한다.
- 목록과 평가 요약은 같은 필터 결과다. 검색/태그 선택 시 `조회 결과 평가액`과 결과 종목 수·계좌 범위를 표시한다. 기존 환산/미확정 평가 정책을 그대로 사용한다. 배분의 전체 계좌 분모는 바꾸지 않는다.
- 태그 없음은 별도 데이터가 아닌 연결 부재 조건이다. 미분류 상세에서 태그 저장 후 목록 갱신·상세 복귀·조건 유지·사라진 행의 초점 복귀까지 연결한다.
- 표 편집/가격 갱신의 기존 범위, 공유 권한, 활동 기간의 기록 한정 의미를 유지한다. API·DB·MCP 변경은 계획하지 않는다.

## 슬라이스 A — 공통 상단 구조를 네 화면에 적용

자산과 활동의 실제 카드에서 표현만 공통화한 뒤 배분·원칙에 적용한다. 최소 wrapper 또는 공통 스타일을 사용하고 상태/계산은 feature에 둔다.

- [x] 가이드의 카드·여백·구획·버튼 배치 적용. 필터는 같은 카드 내부에서 상시 노출.
- [x] 자산의 기존 계좌/검색/추가/계좌 수정/표 편집/가격 갱신 흐름 보존.
- [x] 활동 검색 초안/적용 표시·기록 기간/태그·할 일/기록 순서 보존.
- [x] 배분 태그 관리·전체 계좌 기준·변경 시에만 저장/취소 보존.
- [x] 현재 원칙 카드의 날짜/수정/본문과 이력 연결. 빈 원칙 상태 포함.
- [ ] 5개 viewport의 4개 탭 캡처/실제 넘침·키보드 확인. 범위가 분리되면 검증 후 커밋.

## 슬라이스 B — 자산 태그 조회부터 미분류 정리까지

- [x] 기존 전달 데이터로 계좌+검색어+태그 조건과 visible rows를 한 경로에서 계산한다. 필터 적용과 합계가 별도 조건으로 어긋나지 않게 한다.
- [x] 전체/태그 없음/복수 태그 OR, 이름·티커 검색과 AND. 0개 태그라도 전체/태그 없음 제공.
- [x] 결과 범위 합계·미확정/오래된 시세 안내·결과 종목 수. 계좌 전체 중복 종목과 외화/현금/평가형을 기존 계산으로 검증.
- [x] 태그 없음 → 상세 선택·저장 → 재조회 → 목록 제외, 초점/스크롤/조건 유지. 저장 실패·재조회 실패에서 성공을 가장하지 않음.
- [x] 계좌 변경 시 태그 유지, 다른 포트폴리오 전환 시 조회 상태 분리/초기화, 태그 이름 변경·삭제 후 조건 정합성.
- [x] 읽기 공유에서도 허용된 태그 필터 사용, 수정 권한 노출 없음. 배분과 표 편집의 별도 범위 확인.
- [ ] 목적 중심 단위/브라우저 회귀, 문서·GitHub 상태 갱신, 분리 가능한 슬라이스 커밋.

## 검증·완료 기준

대표 시나리오: 전체 계좌에서 태그 없음과 실제 태그를 OR로 조회 → 계좌·검색어로 좁힘 → 상세에서 대표 태그 저장 → 미분류 결과에서 사라져 다음 대상을 계속 정리. 조건 해제 후 전체 자산 복귀, 배분의 분모/목표는 불변.

- 360/390/768/1024/1440px, 0/1/30개 태그, 긴 이름, 빈 결과, 누락 시세·환율, 소수 수량, 복수 계좌 동일 종목.
- 태그 칩 키보드/선택 상태, 모달 닫기와 초점 복귀, 저장 실패, 계좌/소유자 전환, 조회·배분·표 편집 범위 구분.
- `npm run check:encoding`, `git diff --check`, 단위/빌드 및 변경 흐름의 E2E. UI만 바꾸면서 별도 DB/API 구조를 선행하지 않는다.
- 실제 확인한 화면·폭·상태와 미검증 실기기 항목 기록. 설계 작성만으로 구현/배포 완료 처리하지 않는다.

## 인계

로컬 구현 완료. `PageControls`의 작은 표현 클래스만 네 탭에 공유하고 조회·합계·권한은 각 기능에 남겼다. 자산은 대표 태그 칩, `태그 없음`, 결과 범위 평가액/시세 경고/기준일, 상세 저장 후 초점 복귀를 제공한다. 소유자 전환 시 계좌·검색·태그 상태를 초기화한다. 후속 사용자 피드백으로 자산 행동을 첫 줄에 모으고 활동의 검색을 필터 구획으로 옮겨 버튼 없는 자동 적용으로 맞췄다. DB/API/MCP 변경은 없다.

검증: `npm run build`(인코딩 포함), 단위 100개, 격리 DB 558개, MCP 계약/배포 준비 검사, Chromium E2E 69개 통과. 새 E2E에서 미분류 종목의 태그 저장 후 목록 제외와 목록 초점, 네 탭의 360/390/768/1024/1440px 가로 넘침을 확인했다. 기존 자산·배분·활동·원칙·공유/표 편집 회귀도 통과했다. 실제 기기 캡처/시각 판독, 30개·긴 태그의 상세 외관, 스크린리더는 아직 확인하지 않았다. 운영 배포도 하지 않았다.

커밋은 이 턴 전부터 같은 소스 파일에 다른 미커밋 구현이 광범위하게 섞여 있어 수행하지 않았다. 사용자 로컬 설정과 다른 변경을 임의로 함께 커밋하지 않기 위한 보존 조치다. 위 미검증 항목과 분리 가능한 커밋 정리 후 이슈를 닫는다.

문서 검증: 인코딩 검사 545개 파일 및 `git diff --check` 통과. 화면 구조의 자산 필터 위치/평가 범위와 태그 가이드의 미분류/공유 필터 설명을 최신 계약에 맞췄다. AGENTS·START-HERE·PRINCIPLES·component-system·티켓 목록에 정본을 연결했다.

## 2026-09-25 후속 UX 정돈

사용자 피드백에 따라 자산의 가격 갱신·보유 추가·계좌 추가·표 편집을 같은 첫 줄 행동 영역으로 모으고, 계좌·종목 검색·대표 태그만 구분선 아래 필터 영역에 남겼다. 활동도 첫 줄에 `할 일 · 기록` 문맥과 추가/태그 관리, 구분선 아래에 검색어·기간·태그를 둔다. 활동 검색 버튼은 제거했다. 날짜·태그는 즉시, 검색어는 입력이 멈춘 뒤 450ms 후 기존 서버 검색으로 적용한다. 검색 의미·DB/API/MCP 계약은 바꾸지 않았다.

로컬 검증: `npm run build` 및 인코딩 검사, `git diff --check`, 격리 DB 558개, MCP 계약·배포 준비 검사, 활동/자산 필터/내비게이션 Chromium E2E 37개 통과. 360/390/768/1024/1440px 가로 넘침, 자산 행동 진입, 날짜·태그·검색어 자동 적용과 늦은 응답 무시를 포함한다. 실제 기기의 시각·키보드 평가는 아직 하지 않았다. 운영 배포도 하지 않았다. 기존 미커밋 변경이 넓게 섞인 작업트리 상태를 보존하므로 이 후속 작업만 따로 커밋하지 않았다.
