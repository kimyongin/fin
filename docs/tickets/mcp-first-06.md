# [MCP-first] 초기 잔고 기반 매매 미리보기·확정·거래 조회

## 구현 인계 확정 사항 (2026-09-20)

- 필독: [ADR-0002](https://github.com/kimyongin/fin/blob/master/docs/adr/0002-cost-basis-reconciliation-and-sharing.md), [ADR-0003](https://github.com/kimyongin/fin/blob/master/docs/adr/0003-extensible-feature-sharing.md), [구현 계약 초안](https://github.com/kimyongin/fin/blob/master/docs/design/implementation-contract-draft.md).
- 수수료·세금을 제외한 체결가로 원가/평균가를 계산한다. 보정 이전 거래는 과거 이력만 정정한다. 구현 전 기존 트리거/거래 DDL과 정밀도·동일일 순서 계약을 검증한다.
- 문서화는 구현/배포/보안 검증 완료가 아니다. 미검증 DDL·정밀도·상태 전이는 해당 티켓의 첫 작업으로 남기며 완료 체크를 앞당기지 않는다.

## 기존 입력을 대체하지 않는 체결 기록
- 현재값 등록/보정은 기존 보유·표 편집 경로, 이 티켓은 실제 체결 기록 경로다. 기존 수정 내용을 가상의 매매로 변환하지 않는다.
- 보유값·원장 통합 규칙은 #38과 공유하고 시장형 매매를 평가형/현금성 자산에 강제 적용하지 않는다.
- [ ] 기존 보유값을 안전하게 기준점으로 사용하며 과거 거래 재입력이나 사전 판단 작성 없이 실제 매매를 기록한다.

## 실행 계획과 실제 체결 분리
- 완료 매매는 원장에 저장하고 선택적으로 #44 실행할 일/사용자 결정과 연결한다. 선행 계획 없는 매매도 바로 기록할 수 있다.
- 하나의 실행할 일에 여러 체결을 연결해 부분 완료를 표현한다. 첫 버전은 각 체결의 연결 대상 할 일을 최대 하나로 제한해 수량 이중 집계를 방지한다.
- 계획 수량·실제 수량·단위와 완료 기준은 #44 계약을 따른다. 금액 기반/조건부 계획에 수량 완료 규칙을 임의 적용하지 않는다.
- [ ] “10주 매수 계획 → 6주 체결 → 4주 체결”에서 잔고는 각 체결로만 갱신되고 계획의 진행은 합산 결과와 일치한다.
- [ ] 할 일 생성/취소/완료 상태만으로 거래나 잔고가 바뀌지 않는다.

## 잔고 확인과의 연결
- #42의 마지막 실제 잔고 확인은 매매 기록 성공으로 갱신하지 않는다. 확인 이후 기록된 거래가 있음을 별도로 표시한다.
- 매매 후 응답은 변경된 수량·평균가와 저장 성공 여부를 짧게 보여준다. 보유 이유 입력이나 장문 투자일지를 필수로 요구하지 않는다.
- 사용자 최초 매수 이유가 대화에 있더라도 #41 저장 의도를 확인할 수 있는 경우에만 연결한다.

## 선행 작업
- #32 [MCP-first] 제품 계약·잔고 계산 규칙과 사용자 시나리오 확정
- #33 [MCP-first] OAuth MCP 계약 정비와 클라이언트 호환성 검증

## 사용자 시나리오
“삼성전자 10주를 7만원에 샀어”를 완료 매매로 기록하고 수량·평균가 변화를 확인한다.

## 범위
- 현재 보유 수량과 평균가를 기준점으로 기존 자산을 이관한다. 불완전한 과거 원장으로 기존 holdings를 덮어쓰지 않는다.
- preview_trade_entry, log_completed_trade, list_transactions를 구현한다.
- 미리보기/확정은 동일 계산 로직을 사용한다. preview_id에 소유자·거래 입력·잔고 버전·만료를 서버에서 결합한다.
- 확정은 DB 트랜잭션/락 또는 버전 비교로 처리한다. 미리보기 후 상태가 바뀌면 stale_preview를 반환한다.
- 원가 계산은 DECIMAL 등 정밀 수치로 처리하고 정책에서 정한 소수 수량/통화 단위를 지킨다.
- 계좌·종목 식별, 초과 매도, 잘못된 날짜/가격/수량, 미지원 자산 유형을 검증한다.
- 중복 요청은 같은 저장 결과를 반환하고 idempotency key 재사용에 입력이 다르면 거부한다.
- 여러 계좌 중 대상이 모호하면 질문한다. 동일 문구의 실제 별도 매매는 자동으로 중복 취급하지 않는다.
- 평균가·보유량·거래·활동 기록을 원자적으로 갱신한다.
- preview_id만으로 인간 확인을 증명한다고 주장하지 않는다. FIN 제품 계약의 확인 정책을 적용한다.

## 완료 조건
- [ ] 초기 잔고, 매수, 부분/전량 매도, 재매수의 기대값을 DB 테스트로 검증한다.
- [ ] 동시 요청·재시도·만료 preview·타 사용자 preview·초과 매도 테스트를 통과한다.
- [ ] 기존 편집/일괄 편집 경로에서도 잔고 버전/기준점 규칙이 유지된다.
- [ ] 웹/모바일에서 기록 후 조회 결과와 앱 표시가 일치한다.
- [ ] 실제 주문·현금 이체나 증권사 자동 동기화는 실행하지 않는다.
