# [안정화 재검토] 활동 태그 목록 상태와 갱신 경로 통합

우선순위: P2 · 상태: 티켓 작성, 구현 전 · 2026-09-23
관련: #82, #92, #96 · 기준 코드: b7ee31d

## 문제와 근거
`LifecyclePage`, `ActionTimeline`, `ActivityDetailModal`이 각각 태그 목록을 조회·보관한다. 추가 모달에서 생성한 태그가 검색 필터에 반영되지 않고 상세에서 이름 변경/삭제한 태그도 다른 소비자에 남는다.

## 범위
- 활동 화면의 공통 상위에서 태그 목록과 갱신을 관리하고 세 소비자에 전달한다.
- 태그 선택값은 각 폼/검색의 책임으로 유지한다. 전역 상태 라이브러리나 범용 cache는 추가하지 않는다.
- 삭제된 태그가 선택/검색 조건에 남지 않도록 처리하고 적용 중 검색의 재조회 정책을 정한다.
- 본인/친구 전환과 언마운트 시 늦은 태그 응답을 무효화한다. 읽기 실패를 빈 목록과 구별한다.

## 완료 조건
- [ ] 생성·이름 변경·삭제가 추가 모달/상세/검색 필터에 페이지 새로고침 없이 반영된다.
- [ ] 선택 중 태그 삭제 후 저장/검색에 무효 ID가 전송되지 않는다.
- [ ] 태그 목록 로딩/오류/재시도가 소비 화면에서 일관된다.
- [ ] 친구 화면에 본인의 비공개 태그 목록이 남지 않는다.
- [ ] 신규 활동/할 일의 태그 원자 저장과 기존 연결 편집 회귀를 확인한다.

## 진행 규칙

- docs/START-HERE.md, ADR-0008, SIMPLICITY.md와 관련 티켓을 먼저 읽는다. UI 변경 전 디자인 원칙/컴포넌트 규칙, DB 변경 전 schema/OVERVIEW를 확인한다.
- 필요한 기존 helper와 목적별 API를 재사용해 수직 슬라이스로 구현·검증·커밋한다. 사용자 로컬 설정과 무관한 변경은 보존한다.
- 기존 티켓의 검증 기록은 유지하고 새 결과를 교차 연결한다. 코드 검토로 추론한 문제와 실제 재현 결과를 구분한다.
