# [활동 검색] 할 일·기록의 연결 맥락 함께 조회

상태: 설계 완료 · 구현 전 · 2026-09-27
GitHub: https://github.com/kimyongin/fin/issues/162
선행: search-01. 기준: [검색 설계](../design/activity-context-search.md).

S2. 이론 기록을 찾으면 리서치 할 일을 함께 읽고, 할 일을 찾으면 수행 기록도 확인한다.

- [ ] 기존 task_id로 1단계 양방향 관계를 조회한다. 직접 찾은 기록에서 부모를 거쳐 다른 모든 기록으로 재귀 확장하지 않는다.
- [ ] HTTP/OAuth 응답에서 직접 hit와 관련 항목, 연결 이유·조건 밖 이유·원본 ID·접근 가능한 총수·관련 항목 페이지를 구분한다. 직접 결과의 커서/개수를 확장 결과가 밀어내지 않는다.
- [ ] 웹에서는 같은 결과 카드 아래 관련 할 일 또는 연결 기록 3개와 더 보기를 제공한다. 검색 근거 발췌·날짜·할 일 상태를 표시하고 중복 원문은 재나열하지 않는다. 독립 기록은 불필요한 빈 관계 영역 없이 표시한다.
- [ ] 관련 항목이 기간·태그 밖이어도 맥락으로 표시하되 권한 필터는 절대 넘지 않는다. 삭제된 참조·완료/중단 할 일·같은 부모의 기록 12개·동일 항목의 여러 직접 hit를 검증한다.
- [ ] 상세 진입/복귀 시 검색 조건·목록 위치를 유지하고 중첩 상세 모달을 추가하지 않는다. 360/390/768/1024/1440px·200% 확대·키보드·공유 읽기를 확인한다.
- [ ] 에이전트가 관련 항목을 직접 일치 자료로 오해하지 않는 MCP 응답/도구 설명을 검증한다. 원문 수정/삭제가 원본 참조와 검색 결과에 반영됨을 HTTP/MCP 양쪽에서 확인한다.

관계 복제 테이블·범용 그래프는 만들지 않는다. API 추가가 필요하면 기존 검색/단건/관계 조회의 최소 확장으로 제한하고 최종 계약을 기록한다.
