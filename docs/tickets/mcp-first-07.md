# [MCP-first] 잔고 보정·거래 취소와 기존 편집 경로 통합

## 구현 인계 확정 사항 (2026-09-20)

- 필독: [ADR-0002](https://github.com/kimyongin/fin/blob/master/docs/adr/0002-cost-basis-reconciliation-and-sharing.md), [ADR-0003](https://github.com/kimyongin/fin/blob/master/docs/adr/0003-extensible-feature-sharing.md), [구현 계약 초안](https://github.com/kimyongin/fin/blob/master/docs/design/implementation-contract-draft.md).
- 최신 절대 보정 기준점보다 이전 거래의 추가/취소는 그 기준점의 현재값을 바꾸지 않는다. 이후 거래는 유효 순서로 재생하고 초과 매도는 원자 거부한다. 메타데이터/무변경 저장은 새 기준점이 아니다.
- 문서화는 구현/배포/보안 검증 완료가 아니다. 미검증 DDL·정밀도·상태 전이는 해당 티켓의 첫 작업으로 남기며 완료 체크를 앞당기지 않는다.

## 기존 표 편집과 보정 통합의 보존 조건
- 기존 SpreadsheetEditor의 붙여넣기/기존 행 매칭, 계좌·태그 필터, 검색, 이전 값 표시, 행 취소, 전체 롤백, 전체 화면, 일괄 저장을 유지한다.
- 수정된 잔고 필드에만 보정 의미를 적용한다. 태그/이름/메모 변경과 변경 없는 행의 재저장은 잔고 기준점·실제 확인 날짜를 바꾸지 않는다.
- 전체 행 저장이 필터 밖 데이터를 삭제하거나 불필요한 보정을 만들지 않는지 검증한다. 배치 원자성/충돌 정책을 명시한다.
- 활동 기록의 저장 전후 스냅샷·CSV를 유지한다. 사용자가 편집 화면을 떠날 때 미저장 변경의 처리도 정의한다.
- [x] 시장형 수량·평균가, 평가형 매입/평가액, 현금 잔액이 각 타입의 의미대로 저장된다.
- [x] 붙여넣기 후 일부 행 수정, 필터 상태 저장, 변경 없는 저장, 메모만 수정, 동시 매매 충돌을 DB·전체 앱 E2E로 회귀 검증한다.

## 거래 취소와 실행할 일의 관계
- 체결 기록을 취소하면 원장 정책에 따라 잔고를 재계산하고 연결된 실행할 일의 체결 진행도 갱신한다.
- 실행할 일 취소/보류는 과거 실제 매매 취소나 사용자 판단의 철회를 의미하지 않는다.
- 잔고 보정은 실행할 일을 완료한 체결로 간주하지 않는다.
- [x] 부분 체결 후 계획 취소, 완료 후 체결 기록 정정, 보정만 수행한 경우의 상태와 잔고를 검증한다.

## 확인 상태와 보정 UX
- #42에서 실제 잔고와 비교 확인한 값으로 보정하는 경우 확인 범위·스냅샷을 함께 기록한다. 단순 오류 수정은 실제 잔고 확인으로 간주하지 않는다.
- 마지막 확인이 오래되었다는 사실만으로 틀린 잔고라고 판단하지 않는다.
- 사용자가 차이를 발견하면 대상 잔고 한 곳에서 수량·평균가를 맞추고 마칠 수 있게 한다. 과거 전체 거래를 재입력하도록 요구하지 않는다.

## 선행 작업
- #32 [MCP-first] 제품 계약·잔고 계산 규칙과 사용자 시나리오 확정
- #37 [MCP-first] 초기 잔고 기반 매매 미리보기·확정·거래 조회

## 사용자 시나리오
“실제 잔고는 25주, 평균가는 68000원이야” 또는 “방금 기록한 매수를 취소해줘”라고 하면 이력을 보존하며 복구한다.

## 범위
- preview_holding_reconciliation, reconcile_holding, reverse_trade_entry를 구현한다.
- 보정의 유효시각·수량·평균가·이유를 새로운 기준점으로 저장한다.
- 거래 취소는 원본 참조와 취소 이력을 보존한다. 반대 방향 매매를 추가하는 것으로 원가 취소를 대체하지 않는다.
- 이후 거래가 있으면 정책에 따라 재계산/사전 검증하고 불가능한 경우 원인을 설명한다.
- 보정 전 거래를 취소할 때 현재 기준점에 미치는 영향을 명시한다.
- 과거일 입력/편집/스프레드시트 일괄 저장과 보정 기준점의 관계를 통합한다.
- 미리보기 중 변경·중복 요청·권한을 매매 확정과 동일하게 검증한다.

## 완료 조건
- [x] 후속 매도가 있는 매수 취소, 전량 매도 취소, 반복 취소, 보정 후 취소 시나리오를 검증한다.
- [x] 보정이 과거 기록을 삭제하지 않고 현재 잔고 재계산에도 유지된다.
- [x] 미지원 분할·이체·배당 사건은 보정 이유로 남길 수 있다.
- [x] 사용자가 변경 전후와 원인을 앱 활동 기록에서 확인할 수 있다.

## 구현 진행 (2026-09-21)

- 시장형 수량/평균가, 평가형 매입/평가액, 현금 잔액의 절대 보정 preview/confirm을 구현했다. 보정은 기존 거래나 메모를 삭제하지 않고 별도 기준점/감사 이력으로 남는다.
- 실제 증권사 확인 여부는 보정과 분리하되, 사용자가 명시한 필드만 보정과 함께 확인 snapshot으로 저장할 수 있다.
- 거래 취소 preview/confirm과 원본 보존, 후속 거래 재생, 최신 보정 이전 거래 취소 시 현재값 유지, 반복 요청 멱등 처리를 구현했다. 모바일의 최근 거래에서 영향 확인 후 취소할 수 있다.
- 기존 단건/표 편집의 시장형·평가형·현금성 잔고 변경은 holding 기준점/version을 올리고 메모만 또는 무변경 저장은 올리지 않도록 통합했다. 붙여넣기·필터·동시 매매의 화면 회귀는 최종 E2E에 남아 있다.
- 실행 계획 진행도는 유효한 연결 체결에서 계산되며 거래 기록 취소 시 자동으로 되돌아간다.
