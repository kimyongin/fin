# [공통 UX] 태그 칩 디자인 통일과 관리창 사용성 개선

2026-09-24 · Astra 설계, Sol 로컬 구현·자동 검증. 운영 배포 전.

GitHub: https://github.com/kimyongin/fin/issues/128

2026-09-26 후속 [활동 태그 검색 간소화](./ui-30-activity-tags-without-search.md)는 활동 선택/관리창의 검색 입력을 제거한다. 칩·태그 ID·복수 선택·저장·관리 흐름과 아래 당시 구현/검증 이력은 유지한다. 현재 공통 표현은 갱신된 태그 가이드가 우선한다.

2026-09-26 후속 시각 수정: 글자 수·줄바꿈에 따라 끝 곡률이 달라 보이지 않도록 공통 `TagChip`의 `rounded-full`을 고정 12px 반경(`rounded-xl`)으로 바꾼다. 선택·필터·관리·읽기 칩에 함께 적용하고, 선택 의미·터치 높이·태그 저장은 그대로 둔다. 아래의 타원형 표현은 당시 설계 기록이며 현재 곡률은 태그 가이드를 따른다.

사용자 확인 후 곡률을 12px에서 10px로 한 단계 낮췄다. 이후 공통 칩의 기준은 태그 가이드의 10px이다. `npm test` 102개·빌드·인코딩 검사는 통과했고, 브라우저 E2E의 10px 기대값은 수정했으나 이번 미세 조정 뒤 재실행하지 않았다.

로컬 확인: `npm test` 102개, `npm run build`(인코딩 검사 포함), 격리 E2E의 DB 580개·MCP 계약·자산/배분/활동/원칙 화면 360/390/768/1024/1440px 1개 시나리오가 통과했다. 자산 필터에서 짧은/긴 태그 칩의 실제 계산된 반경이 모두 12px이고 가로 넘침이 없는지 검사했다. 실기기 수동 시각 검증과 운영 배포는 아직 하지 않았다.

## 목적과 검토 결과

태그를 작은 화면에서 한눈에 읽고 선택·관리할 수 있게 한다. 현재 `TagManagerModal`은 `w-full` 행과 `max-h-48` 목록으로 공간을 낭비하고 검색→긴 목록→하단 입력을 왕복하게 한다. 처음부터 새 태그가 선택되어 생성과 검색의 의미도 흐리다. `ActivityTagPicker`와 `ActionTimeline` 필터는 이미 타원형 버튼이지만 스타일이 중복되고 기록의 읽기 태그와 자산 대표 태그 select도 제각각이다.

확정 기준은 [태그 가이드](../design/tag-guidelines.md). #127의 저장·권한·관리 위치는 유지하고 목록 배치/초기 선택/편집 위치만 이 티켓으로 대체한다. 기존 구현을 폐기하거나 완료된 테스트 전체를 다시 만드는 작업이 아니다.

## 사용자 시나리오

| 시나리오 | 경험 | 데이터/API |
| --- | --- | --- |
| T1 태그 정리 | 페이지에서 관리창 → 칩 탐색/검색 → 선택 즉시 목록 아래에서 이름 수정 → 저장 | 기존 자산/활동 태그 저장·조회 API, 같은 ID 유지 |
| T2 새 태그 | `+ 새 태그` → 명확한 이름 입력 → `추가` → 추가된 태그 확인 | 기존 생성 API; 특정 기록에 자동 연결하지 않음 |
| T3 기록·종목에 붙이기 | 같은 타원형 칩에서 선택/해제 → 상세 저장 | 자산 단일·활동 복수 연결 계약 유지 |
| T4 기록 찾기 | 태그 칩 복수 선택 → OR 기본 검색, 기존 모두 포함 옵션 사용 | 검색 조건/API 변경 없음 |
| T5 읽기 | 기록·할 일·자산·배분에서 동일한 작은 태그 라벨 읽기 | 기존 조회 DTO 사용 |

## 구현 계약

후속 설계 #129/#130(구현 전): 아래 자산 목록·배분 태그명을 모두 읽기 칩으로 통일하는 요구는 대체됐다. 자산은 코드 옆 보조 텍스트, 배분은 행 제목이다. 선택·관리·활동 읽기 칩은 유지한다. 기존 로컬 구현/검증 기록은 당시 상태로 보존한다.

- 태그는 내용 너비의 타원형 칩, 가로 나열·자동 줄바꿈. 표시 24~28px, 조작 44px 이상, 간격 8px. 긴 이름은 전체를 줄바꿈하고 가로 넘침 없이 읽는다.
- 관리창은 초기 미선택 목록. 검색 → 칩 목록 → `+ 새 태그` → 선택 시 인라인 편집 영역 → 고정 footer. 편집 영역은 같은 본문에서 목록 아래에 두고 선택 시 입력 초점과 스크롤로 바로 안내한다. 별도 속성 모달이나 칩별 작은 수정/삭제 아이콘은 없다.
- 미선택은 닫기만, 추가/수정은 닫기와 추가/저장. 현재 태그 하나만 저장한다. 저장 성공 후 편집 대상 유지·성공 표시. 삭제 성공 후 미선택. 기본 목록 내부 높이 제한/스크롤을 없애 본문 스크롤 하나를 사용한다.
- 삭제/초안 폐기만 공통 ConfirmDialog. #127의 실패·재시도·배분 목표 초안 보존·공유 경계 유지. 자산 태그 결과불명 자동 복구 등 새 예외처리 구조를 추가하지 않는다.
- 자산 단일 선택/활동 다중 선택은 같은 칩 표현을 사용한다. 선택된 태그의 이름/연결과 검색 상태를 혼동하지 않게 그룹 라벨을 유지한다. 검색 중 감춰진 선택도 개수/초기화로 확인한다.
- 표시용 칩은 비조작 요소, 선택/관리용은 키보드 버튼과 상태 제공. 카드 전체가 버튼이면 내부 태그는 읽기 요소로 렌더한다.
- 배분 수치 행은 유지하고 이름만 읽기 칩으로 통일한다. 표 편집 셀 select는 표 입력의 예외로 유지한다. 상태 배지·계좌·종목 이름까지 태그로 바꾸지 않는다.
- 신규 DB/API/MCP/태그별 색상/일괄 저장/드래그 정렬은 필요 없다. 기존 자산 순서 입력은 유지한다.

## 로컬 구현과 검증

`TagChip`과 `SingleTagPicker`를 만들어 관리·읽기·선택/필터·자산 대표 태그에서 공유한다. `TagManagerModal`은 초기 미선택, 검색→칩 목록→새 태그→선택 후 하단 편집으로 바꿨다. 선택 시 편집 입력에 초점이 가고 목록 내부 스크롤을 없앴다. 관리창이 자산/활동 두 기능의 기존 API와 확인창을 사용한다. 배분의 `태그 관리`는 전체 계좌·태그별 배분 박스 제목 오른쪽으로 옮겨 별도 도구 행을 없앴다.

적용 확인: `TagManagerModal`, `ActivityTagPicker`, `ActionTimeline`, `ActivityEventViewer`, `ActivityDetailModal`, `GeneralTaskDetail`, `AssetDetailModal`, `EditorModals`, `StrategyPage`, `AssetsPage`. 표 편집의 셀/필터 select는 긴 표 조작을 위해 유지한다. 활동 상태·출처 배지와 미분류 문구는 태그가 아니므로 칩으로 바꾸지 않았다. DB 스키마와 웹/MCP 저장 의미가 그대로여서 migration·도구 설명 변경은 필요 없다.

검증: `npm test` 102개, `npm run build`, `npm run check:encoding`, `npm run check:workflow-guides`, `git diff --check` 통과. 격리 `.e2e`에서 DB 542개와 MCP 계약을 통과했고, 활동·탐색 32개 및 자산 접근·활동 29개 중 28개가 먼저 통과했다. 나머지 1개는 짧은 태그 사이에 기존 태그가 끼어 있는 테스트 전제 오류여서 두 이름으로 검색한 뒤 비교하도록 수정하고 단독 재실행을 통과했다. 0개→1개 태그 추가도 빈 사용자로 단독 재검증했다. 자산 상세 대표 태그 저장은 RPC 재조회로 확인했다. 360/390/768/1024/1440px의 가로 넘침·footer·칩 줄바꿈·배분 버튼 위치를 관련 브라우저 테스트로 확인했다.

후속 검증: 실제 휴대폰의 키보드/safe-area와 스크린리더 발화, 수동 시각 캡처는 아직 확인하지 않았다. 운영 배포는 하지 않았다. 자동 브라우저 검증이 실기기 평가를 대신하지 않는다.
