# [후속 정리] 활동 상세·검색의 늦은 응답과 조회 상태 정리

우선순위: P1 · 상태: 로컬 구현·대표 검증 완료 · 2026-09-23
관련: #50, #81, #83 · 기준 코드: 8cb943f

## 문제와 근거

LifecyclePage.jsx의 openActivity/refreshActivityDetail은 닫기 이후에도 응답을 적용한다. 모의 지연 응답 검사에서 닫은 상세가 다시 열렸다. ActionTimeline.jsx의 runSearch/clearSearch는 일반 목록 load와 달리 request gate가 없다.

## 범위

- 기존 src/lib/requestGate.js를 재사용해 상세 조회/재조회와 검색 응답의 유효성을 검사한다.
- 상세 닫기·다른 항목 선택·언마운트·소유자/공유 대상 전환·검색 초기화 때 이전 읽기를 무효화한다.
- 검색어/필터/페이지 커서에 대한 최신 요청만 결과와 loading/error를 변경한다. 이전 목록과 새 검색 요청이 서로의 상태를 덮지 않게 한다.
- 읽기 요청 취소와 서버 쓰기 취소를 혼동하지 않는다. 새 캐시 프레임워크나 공통 비동기 엔진은 추가하지 않는다.

## 완료 조건

- [x] A 조회 중 닫기 뒤 늦은 응답으로 상세가 재개방되지 않음을 브라우저에서 검증했다. A→B와 저장 후 재조회는 같은 request gate를 사용한다.
- [x] 검색 A/B의 응답 역전을 브라우저에서 검증했다. 검색 초기화·필터 변경·더 보기 중 초기화는 동일 request gate로 처리하며 전용 브라우저 검사는 미실행이다.
- [ ] 소유자/친구 전환 뒤 이전 대상의 결과·오류가 새 화면에 표시되지 않는다. 코드에서 owner 변경/언마운트 무효화, 브라우저 전용 검증은 미실행.
- [ ] 정상 상세/검색/뒤로가기/페이지 추가 흐름과 모바일·PC 조작을 확인한다. 대표 회귀 일부만 실행.

## 진행 규칙

- docs/START-HERE.md, ADR-0008, SIMPLICITY.md와 해당 기능의 최신 구현을 먼저 확인한다.
- 최소 변경으로 수직 구현·검증한다. 새 테이블/이력/범용 프레임워크를 기본 해법으로 삼지 않는다.
- 관련 코드·계약·MCP 설명/가이드 영향과 실제 검사 결과를 함께 기록한다. DB 변경 시 schema/OVERVIEW.md를 갱신한다.
- 사용자 로컬 설정을 보존한다. 로컬 완료와 운영 배포/실제 ChatGPT 검증을 구분한다.

## 구현 기록

- 활동 상세 조회/저장 후 재조회에 request gate를 사용한다. 닫기, 다른 활동 열기, 친구 대상 전환, 언마운트에서 구 응답을 무효화한다.
- 목록·검색은 같은 request gate를 사용하고, 검색 조건/필터/대상 변경 시 구 결과·오류·loading을 반영하지 않는다. 다시 시도는 현재 목록 또는 검색 경로를 따른다.
- 지연 상세 응답 후 모달이 다시 열리지 않는 브라우저 검사와 검색 A/B 역전 브라우저 검사를 통과했다.
- 로컬 unit 20파일/96건, 빌드, 최종 분리 E2E DB 510건/MCP 계약과 브라우저 37건 통과. 전용 지연 응답 2건은 별도 통과했다. 소유자 전환의 의도적 지연 오류와 모든 검색 커서 조합의 전용 브라우저 검사는 아직 수행하지 않았다.
