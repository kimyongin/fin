# [활동 UX] 검색·기간·태그 필터 상시 노출과 날짜 의미 정리

2026-09-24 · Astra 설계 · Sol 로컬 구현/자동 검증 · 운영 전 · P2

GitHub: https://github.com/kimyongin/fin/issues/131

## 목적과 현재 구현

사용자가 필터 범위와 결과를 이해하고, 최근 기록을 찾아도 미완료 할 일을 놓치지 않는다.
`ActionTimeline.jsx`의 날짜 초기값은 빈 문자열이고 검색 제출 후 `searchActivities`로 적용된다. 검색은 할 일 예정일과 기록일을 다르게 비교하며, 기본 타임라인과 검색 결과 화면이 갈린다. 단순히 입력 기본값만 채우면 표시 기간과 실제 결과가 달라지므로 조회 경로까지 연결한다.

## 목표 계약

- 검색·시작일·종료일·태그를 한 필터 영역에 항상 표시한다. 상세 필터 details/접기를 제거한다. 모바일은 줄바꿈하며 태그 OR 기본/모두 포함 선택은 유지한다.
- 기간은 `기록 기간`으로 명명한다. 최초 시작일은 사용자 업무 날짜 기준 오늘-29일, 종료일은 오늘(양 끝 포함 최근 30일). 초기 실제 조회에도 같은 조건을 적용한다.
- `전체 기간`으로 제한을 해제하고 날짜 필드는 비우되 전체 기간 상태를 명시한다. 초기화는 최근 30일·검색어 없음·태그 없음으로 돌아간다.
- 기간은 기록에만 적용한다. 미완료 할 일은 과거/미래/날짜 없음과 무관하게 유지한다. 검색어·태그는 두 영역에 적용하고 할 일/기록 구역을 유지한다.
- 후속 사용자 결정(2026-09-25): 검색 버튼과 미적용 조건 문구를 제거한다. 날짜·태그는 변경 즉시 적용하고, 검색어는 입력이 멈춘 뒤 짧은 지연을 두고 적용한다. 기본 최근 30일과 `전체 기간`의 날짜 필드는 실제 조회와 일치해야 한다. 기존 한 번에 적용 계약은 이 결정으로 대체한다.

- 시작일>종료일은 입력 근처에서 안내하고 요청하지 않는다. 조건 변경 시 cursor를 초기화하며 더 보기/오류 재시도는 적용된 조건을 유지한다. 사용자 전환 시 이전 사용자 조건/결과를 섞지 않는다.
- 앱의 기록 기간 정책을 MCP의 범용 검색에 무조건 강제하지 않는다. 기존 RPC/Edge 호출자를 대조하고, 할 일과 기록의 필터 의미를 명시적으로 나누는 최소 변경을 선택한다. 새 검색 엔진/테이블은 만들지 않는다.

## 구현 첫 단계와 검증

- [ ] `fetchActionTimeline`, `searchActivities`, activity-search Edge, SQL, MCP 검색의 날짜 의미와 페이지네이션 소비자를 대조하고 최소 API 변경을 기록한다.
- [ ] 기준시각을 고정한 fixture로 시작/종료 당일, 자정 전후·시간대, 기간 밖 기록, 기간 밖/날짜 없는 미완료 할 일을 검증한다.
- [ ] 초기 조회가 최근 30일과 일치하며 전체 기간에서 오래된 기록을 찾는다. 검색·태그 OR/AND·기간 조합과 결과 없음·더 보기·재시도를 검증한다.
- [ ] 직접 API와 실제 브라우저에서 같은 결과를 확인한다. 보이는 필드/문자열만 검사하고 완료하지 않는다.
- [ ] 360/390/768/1024/1440px에서 필터 상시 노출·날짜 입력·태그 줄바꿈·목록 구분을 확인한다.
- [ ] API 변경 시 MCP 설명/워크플로우 가이드/계약 테스트를 함께 갱신한다. 사용자 격리와 공유 참조 제거 회귀를 확인한다.

UI 기본 기간과 에이전트 실행 대상 조회는 별개이며 반복 할 일 티켓과 혼동하지 않는다.

## 구현 기록 (2026-09-24)

검색·날짜·태그를 상시 노출하고 서울 업무 날짜 기준 최근 30일을 실제 기록 조회에 적용한다. 전체 기간 선택과 역전된 날짜 경고를 제공하며, SQL 검색 날짜 조건은 기록에만 적용한다. 미완료 할 일은 기간과 관계없이 남는다. 고정 데이터 DB 계약 검사 및 브라우저 검색 회귀가 통과했다. 실기기 평가는 아직이다.

## 후속 구현 기록 (2026-09-25)

검색어는 450ms 입력 지연 뒤 기존 검색 API로 조회하고 날짜·태그는 즉시 반영한다. 유효하지 않은 시작/종료일은 요청하지 않는다. 격리 DB 558개 및 활동 브라우저 회귀를 포함한 E2E 37개가 통과했다. 운영 배포·실기기 검증은 별개다.
