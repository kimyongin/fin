# [UI/UX] 활동 상세에서 할 일·한 일을 함께 표시하고 후속 연결 제거

2026-09-24 · P2 · 로컬 구현 및 자동 검증. 운영 DB 적용·배포·실기기 평가는 별개다.

GitHub: https://github.com/kimyongin/fin/issues/115

최신 용어: [할 일·기록 용어 정리](./ui-09-activity-terminology.md)를 함께 적용한다. 아래 기존 설명의 ‘한 일’은 화면에서 ‘기록’, ‘원래 할 일’ 요약 제목은 ‘관련 할 일’, 결과 영역은 ‘기록 내용’으로 표시한다. 기존 코드명·API 관계는 바꾸지 않는다.

## 목적

한 일의 상세를 열면 무엇을 하려고 했고 실제로 무엇을 했는지 한 번에 읽는다. 원래 할 일을 보기 위해 다른 모달로 이동하거나, 활동에서 또 다른 후속 할 일을 연결하는 흐름을 없앤다. 필요할 때는 기존 활동 추가에서 일반 할 일을 등록한다.

## 현재 구현에서 확인한 것

- `ActivityDetailModal.jsx`에 원래 할 일 이동 버튼, 이어진 할 일 목록, 후속 할 일 입력과 관련 미저장 이동 확인이 있다.
- `app_get_activity`가 사용하는 `app_get_activity_without_tags`는 이미 `activity_events.task_id`로 `portfolio_tasks`를 조회하여 `origin_task`의 id/title/kind를 반환한다. 별도 관계 테이블은 필요 없다.
- 반대 방향의 후속 관계는 `portfolio_tasks.origin_event_id`로 저장하고, 상세 응답의 `follow_up_tasks`에서 역조회한다. 이것은 한 일을 만든 원래 할 일과 다른 관계다.
- 웹의 `createActivityFollowUp` 및 `app_create_activity_follow_up`, MCP `save_general_task.origin_activity_id`가 후속 관계를 생성한다. `decision_followup`/`todo` 가이드에도 연결 생성 지침이 있다.
- `LifecyclePage`는 상세 사이 이동과 `follow_up_tasks` 응답 여부에 의존한 새로고침 분기를 가진다. 버튼만 숨기면 이 복잡성이 남는다.

## 변경 범위

### 1. 한 모달에서 읽기

활동 목록에서 한 일을 열면 기존 활동 상세 모달 안에서 다음 정보를 바로 읽는다.

```text
활동 상세                             닫기
  제목 · 활동 종류 · 수행 날짜

  관련 할 일                         (연결된 경우)
  하려고 했던 일의 제목
  확인할 때 / 예정일 / 매일 반복       (값이 있는 정보만)

  기록 내용
  결과 / 결론 / 메모                  (값이 있는 정보만)

  태그 편집                          (필요할 때 펼침)
                                 수정 / 저장·취소
```

- `원래 할 일 보기` 이동 버튼을 읽기 전용 요약으로 바꾼다. 별도 클릭이나 중첩 상세 이동 없이 계획과 수행 내용을 함께 표시한다.
- 같은 제목을 불필요하게 반복하지 않는다. 본문은 계획 요약과 이번 활동 결과의 두 영역으로 정리한다.
- 할 일 없이 기록한 한 일은 한 일 내용만 표시한다. 원래 할 일이 없는 빈 박스나 등록 유도는 만들지 않는다.
- 원래 할 일이 삭제되었거나 볼 권한이 없어도 접근 가능한 한 일 내용은 정상 표시한다. 권한 없는 할 일의 존재나 내용을 노출하지 않는다.
- 반복 할 일은 해당 활동의 수행일·회차와 결과를 보여준다. 오늘의 미완료 상태를 과거 회차의 상태로 표시하지 않는다. 전체 회차 목록을 모달에 추가하지 않는다.
- 계획 요약은 연결된 할 일의 현재 저장 내용이다. 과거 작성 당시의 계획 복원이나 별도 스냅샷을 새로 만들지 않는다. 현재 반복 설정과 해당 활동의 수행 사실이 혼동되지 않게 표시한다.
- 원래 할 일은 여기서 읽기 전용이며 기존 활동 편집은 한 일의 편집 가능한 필드만 수정한다. 하나의 저장으로 두 레코드를 동시에 수정하는 폼은 추가하지 않는다.
- 지금 할 일에서 미완료 항목을 여는 기존 상세/완료 흐름은 유지한다. 아직 없는 결과를 만들거나 모든 한 일을 역으로 펼치는 기능은 범위 밖이다.
- 공통 ModalShell을 사용한다. 640px 미만 전체 화면, 이상 중앙 모달, 본문 스크롤과 하단 저장 영역 분리, 초안·저장 중 닫기 보호를 유지한다.

### 2. 후속 연결 기능 제거

- 활동 상세의 `후속 할 일 추가`, `이어진 할 일`, 후속 생성 오류·재시도·입력 상태를 제거한다.
- 한 일에서 할 일 상세로 이동하기 위한 callback 및 전용 이동 확인/상태를 제거한다. 다른 소비자가 있는 공통 모달/history 기능은 유지한다.
- 새로운 할 일은 앱의 활동 추가 또는 MCP `save_general_task`에서 일반 할 일로 등록한다. 태그·내용·예정일만으로 관리하고 특정 활동과 원인 관계를 저장하지 않는다.
- 기존 후속 할 일의 제목·일정·반복·완료 기록·태그를 보존한다. 연결만 해제하여 일반 할 일로 계속 사용할 수 있게 한다.

### 3. 조회·저장 구조도 함께 간소화

- `activity_events.task_id`는 유지한다. 할 일 완료 → 실제 한 일의 관계이며 반복 완료에도 필요하다.
- 기존 `app_get_activity` 응답의 `origin_task`에 화면에서 실제 사용할 요약 필드만 보완한다. 기존 같은 소유자 조건과 할 일 공유 권한을 적용한다. 클라이언트가 원래 할 일을 추가 요청하지 않도록 한 응답으로 제공한다.
- `follow_up_tasks` 응답과 후속 전용 RPC/웹 adapter를 제거하고 현재 상세 갱신 분기를 단순화한다.
- `portfolio_tasks.origin_event_id`와 후속 전용 인덱스·제약은 실제 쓰기/읽기/삭제 함수 의존성을 조사한 뒤 증분 migration으로 정리한다. 기존 할 일 행이나 완료 연결은 삭제하지 않는다. 기존 migration 파일은 수정하지 않는다.
- MCP `save_general_task`의 공개 schema에서 `origin_activity_id`를 제거하고 handler의 전용 분기를 정리한다. 오래된 요청에 해당 값이 들어오면 연결이 저장됐다고 오인하게 성공시키지 말고, 일반 할 일로 다시 요청하도록 명확한 입력 오류를 반환한다. 새 버전 엔진이나 영구 호환 API는 만들지 않는다.
- MCP `get_activity` 설명/응답과 `save_general_task` 설명을 실제 동작에 맞춘다. `decision_followup`/`todo` 등 가이드는 필요할 때 독립된 일반 할 일을 등록하도록 수정한다. 기존 topic 이름 변경은 필수 범위가 아니다.
- 새 테이블, 관계 그래프, 이력·스냅샷 저장, 범용 조인 API를 만들지 않는다. 최종 필드/함수 삭제 목록은 구현 시작 시 이 티켓에 확정한다.

## 기존 티켓과 문서의 우선순위

이 결정은 #81의 활동 후속 연결, #99/#104의 후속 입력 재시도·상세 이동, #84의 후속 연결 가이드 중 충돌하는 요구를 대체한다. 해당 티켓의 일반 초안 보호·저장 재시도·권한 검증은 유지한다. #114 원칙 타임라인과 독립적으로 구현할 수 있다.

구현 시 PRD·화면 구조·현재 API 설명·스키마 개요·MCP 도구와 가이드 검토 기록을 함께 갱신한다. 과거 티켓의 구현 기록을 삭제하거나 이 문서만으로 완료 처리하지 않는다.

## 완료 기준

- [x] 한 일 상세를 열면 원래 할 일의 요약과 이번 결과를 추가 화면 이동 없이 읽는다. 별도 원래 할 일 조회 요청이 없다.
- [ ] 할 일 없는 기록, 삭제된 원래 할 일, 반복 활동의 개별 수행일, 빈 결과·긴 내용을 자연스럽게 표시한다.
- [x] 후속 추가/목록/전용 이동 UI 및 불필요한 상태·API·MCP 입력·가이드 연결 지침을 제거한다.
- [x] 기존 후속 할 일은 일반 할 일로 남고, 할 일 완료 관계·반복 동작·활동 편집·태그·금융 기록을 보존한다.
- [x] 소유자와 공유자의 조회에서 원래 할 일의 권한을 검증하고 공유가 확대되지 않는다.
- [ ] 기존 검색 조건/스크롤 복귀, 미저장 초안·저장 중 닫기 보호가 유지된다.
- [ ] 360/390/768/1024/1440px에서 계획·결과 읽기, 편집, 본문 스크롤/푸터, 키보드 조작을 검증한다. 실기기 미검증은 구분한다.
- [ ] 관련 DB·MCP·브라우저 회귀, 빌드·인코딩 검사 결과와 실제 제거 목록을 기록한다.

## 현재 상태

로컬 변경: `app_get_activity`의 `origin_task`에 제목·확인 조건·일정·반복을 추가해 기록 상세에 바로 표시한다. 다른 사용자가 활동만 볼 수 있고 할 일은 볼 수 없을 때 할 일 완료 기록 자체를 숨겨 기존 타임라인/검색의 권한 경계와 맞춘다. 독립 수동 기록은 활동 권한대로 계속 읽는다. `follow_up_tasks`, 후속 전용 RPC/웹 adapter, `portfolio_tasks.origin_event_id`와 전용 인덱스를 제거했다. 기존 할 일 행은 삭제하지 않고 일반 할 일로 남는다. MCP `save_general_task.origin_activity_id`는 공개 schema에서 제거하고 옛 입력은 오류로 거부한다. 완료 기록의 `activity_events.task_id`는 유지한다.

검증: 완료 기록의 관련 할 일 표시·후속 연결 부재, 기존 수동 기록 삭제·편집·태그·반복, 친구 공유 권한 분리, MCP 후속 입력 거부, DB/E2E·빌드·인코딩 통과. 기존 운영 데이터의 이관·운영 DB 적용·실기기 평가는 미검증이다.
