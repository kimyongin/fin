## 목적과 현재 문제

### 모바일 줄바꿈 후속 수정 · 2026-09-29

- 사용자 실기기 화면에서 여러 줄 제목 뒤의 남은 공간을 쓰지 않고 조작이 별도 줄로 내려가는 문제를 확인했다. 이전 flex 항목 단위 배치와 여러 줄 제목의 강제 다음 줄 규칙을 인라인 흐름으로 수정했다.
- 자산·활동 할 일/검색·활동/원칙 타임라인·배분 제외 목록·친구 목록의 공통 제목 행에 적용했다. 제목 마지막 글자 뒤에 조작이 이어지고, 남은 공간이 부족할 때만 묶음 전체가 다음 줄로 넘어간다. 타임라인 제목의 3줄 제한은 제거하고 요약 제한은 유지한다.
- 로컬 검증: 단위 137개, DB 809개, 브라우저 87개 통과. 빌드·인코딩·workflow guide 검사 통과. 보존할 기존 `.e2e` 상태를 건드리지 않고 별도 테스트 체크아웃에서 실행했다.
- 줄바꿈 회귀는 320/360/390/414/768px에서 마지막 제목 텍스트의 실제 줄 경계와 조작 위치를 비교했다. 390px에서 긴 영문 제목의 마지막 `HEDGED` 옆에 `보기 · 편집`이 붙는 화면을 캡처해 확인했다. 자산의 360/390/768/1024/1440px 폭·타이포그래피·가로 넘침 검사도 통과했다.
- 후속 수정 커밋 `4affcca`를 푸시했다. [서버 검증·배포](https://github.com/kimyongin/fin/actions/runs/36464333576)와 [Pages 게시](https://github.com/kimyongin/fin/actions/runs/36465138743)가 성공했다. 공개 사이트는 HTTP 200으로 새 `index-DHMLEbuu.css`를 제공하며, 파일 안에 인라인 제목/조작 규칙이 있는 것을 확인했다.
- 미검증: iPhone Safari 실기기 및 200% 수동 확대. 아래 최초 배포 기록과 구별한다.

목록에서 내용을 읽거나 고치는 진입점을 쉽게 알아보고, 제목과 조작의 정렬·줄바꿈을 일관되게 만든다. 아이콘의 시각 중심과 넓은 누름 영역을 맞추려는 개별 보정이 반복됐고, 자산·활동·원칙에서 결과가 달랐다. 사용자는 문서/연필 대신 글자로 `보기`, `편집`을 표시하도록 요청했다.

#167의 행 전체 클릭 금지, 마크다운 읽기, 공유 권한, 상세 복귀 계약은 유지한다. 그 티켓의 문서/연필 아이콘·SVG 이동·음수 여백을 이용한 정렬 요구는 이번 티켓의 텍스트 규칙이 대체한다. 텍스트로 바꾼다는 사실만으로 정렬·반응형 처리가 해결됐다고 판단하지 않는다.

## 표현과 배치 계약

- 보이는 문구는 `보기`, `편집`. 두 동작이 있으면 `보기 · 편집` 순서로 묶는다. 괄호·아이콘·테두리·배경·그림자는 사용하지 않는다. 하나만 허용되면 그 문구만 표시하고 구분점·빈 자리도 제거한다.
- 공통 `action`의 차분한 텍스트 조작 modifier를 사용한다: 14px/20px·보통 굵기 400, 기본 색 `--muted-ink`. 제목의 `item-title` 16px/24px·600보다 작고 가볍게 보여 제목과 구분한다. 기본 상태에도 얇은 밑줄로 누를 수 있음을 알리고 hover에서는 글자 색만 `--ink`로 밝아진다. focus-visible 표시는 유지한다. 페이지마다 글자 크기나 위치를 따로 보정하지 않는다.
- 목록에서는 제목 바로 옆에 두고 글자의 기준선(baseline)을 맞춘다. 오른쪽 끝의 별도 조작 열이나 `margin-left:auto`로 밀어내지 않는다. 제목과 조작 묶음은 일반 공백으로 구분하는 인라인 흐름을 사용한다.
- 한 줄에 들어가지 않으면 `보기 · 편집` 묶음 전체가 제목 아래 새 줄의 왼쪽 시작점으로 이동한다. `보기`와 `편집`, 구분점은 서로 다른 줄로 갈라지지 않는다. 개별 단어도 줄바꿈하지 않는다.
- 제목이 여러 줄이어도 마지막 글자 뒤에 조작을 이어 붙이며, 그 줄의 남은 폭이 부족할 때만 다음 줄로 옮긴다. 여러 줄 제목의 중간 높이나 오른쪽 빈 공간에 떠 있지 않는다. 제목·부가 정보·금액·태그는 현재 정보 순서와 가용 폭을 유지한다.
- 긴 한글·띄어쓰기 없는 티커·URL은 컨테이너 안에서 줄바꿈한다. 공통 제목 행은 줄 수 제한 없이 표시하여 마지막 글자와 조작이 이어지게 한다. 보조 요약의 기존 줄 수 제한은 유지한다.
- 조작 하나당 최소 44×44 CSS px 누름 영역을 유지한다. 시각적으로는 글자만 보이게 하되 필요한 행 높이는 정상 레이아웃으로 확보한다. 음수 마진·transform·절대 위치로 누름 영역을 제목/태그/옆 액션 위에 겹치지 않는다. 텍스트가 작다는 이유로 조작 영역까지 줄이지 않는다.
- 구분점은 장식이며 클릭 대상이나 별도 Tab 정지점이 아니다. 두 조작의 누름 영역 사이에 불필요한 별도 gap을 더하지 않는다.

```text
공간이 충분할 때
투자 이론 리서치  보기 · 편집

여러 줄 제목의 마지막 줄에 공간이 있을 때
시장·대출 조건에 따른 장기
투자 배분 재검토  보기 · 편집

마지막 줄의 공간도 부족할 때
시장·대출 조건에 따른 장기 투자 배분
보기 · 편집
```

## 동작과 접근성

화면에서 링크처럼 보이는 것과 HTML 요소의 역할은 구분한다. 현재 모달 열기·동일 모달의 편집 전환은 `button type="button"` 의미를 유지한다. `href="#"`나 클릭 가능한 일반 span으로 대체하지 않는다. 실제 URL로 이동하는 기능에만 링크를 쓴다.

- 접근성 이름은 보이는 `보기`/`편집` 문구와 대상 이름을 포함한다. 예: `기록 보기: 투자 이론 리서치`. 글자만으로 기능을 이해할 수 있어 tooltip은 필수 진입 설명이 아니다.
- Tab 순서는 보기 → 편집이며 Enter/Space로 해당 동작을 실행한다. 상세를 닫으면 호출 조작으로 초점을 되돌리고 필터·검색·스크롤을 유지한다.
- 행·제목·본문을 클릭하거나 드래그해서 조작을 실행하지 않는다. 터치 스크롤 중 의도하지 않은 상세 열기가 없어야 한다.
- 보기는 기존 마크다운 읽기 경로, 편집은 기존 편집 경로를 사용한다. 읽기→편집은 같은 1차 모달 전환이다. 공유 조회에서 편집을 추가하지 않는다.

## 구현 순서와 범위

1. 활동의 할 일/기록과 자산을 첫 소비자로 기존 `ListItemAction(s)` 표현을 바꾸고 실제 보기·편집·상세 복귀까지 연결한다. 기존 공통 스타일을 재사용하며 범용 링크/레이아웃 엔진이나 새 라이브러리를 만들지 않는다.
2. `Timeline`을 통한 원칙 이력, 활동 검색 결과와 나머지 적용표를 같은 규칙으로 맞춘다. 호출부의 아이콘 전용 SVG 이동·음수 여백·오른쪽 자동 정렬 보정을 제거한다. 숨은 읽기 상세·공유 상태도 빠뜨리지 않는다.
3. 관련 브라우저 검사를 새 사용자 조작 기준으로 보완한다. 버튼의 부모가 전체 행이라는 DOM 깊이 가정이나 숨긴 모바일 헤더 좌표 비교를 되풀이하지 않는다. 대상 행과 조작의 의미로 범위를 정하고 기존 값·반응형·권한 검증을 보존한다.

DB·HTTP·MCP·저장 데이터의 변경은 없다. 현재 타이포그래피·터치 크기·모달 계약을 사용한다. 구현 시 소비 지점의 예외가 발견되면 위 적용표에 근거를 남긴다.

## 완료 조건과 검증

- [x] 모든 적용표의 읽기/편집이 텍스트로 표시된다. 단일 조작에는 불필요한 구분점이 없고 공유 화면의 편집은 노출되지 않는다.
- [ ] 360/390/768/1024/1440px, 200% 확대에서 짧은 제목·여러 줄 제목·띄어쓰기 없는 긴 문자열·큰 금액을 확인한다. 제목과 텍스트 조작의 baseline이 맞고, 좁을 때 조작 묶음 전체가 다음 줄 왼쪽으로 이동한다. 조작끼리·제목/태그와 누름 영역이 겹치지 않는다.
- [ ] 기본·hover·active 상태에서 테두리·배경·그림자가 없고 focus-visible은 식별 가능하다. 글자 computed style은 공통 action의 차분한 텍스트 조작 modifier(14px/20px·400, 기본 `--muted-ink`, 얇은 밑줄)와 일치한다. hover는 글자 색만 `--ink`로 바뀌고 실제 배경 대비 4.5:1을 충족한다. 음수 마진/위치 이동 보정이 없다.
- [ ] 페이지·카드·제목·조작의 실제 경계가 화면 안에 있다. 전역 overflow 숨김이나 제목 강제 축소로 실패를 감추지 않는다. 모바일 숨김 헤더와 데스크톱 열 정렬은 각각 실제 표시 규칙에 맞게 검사한다.
- [ ] 보기/편집 클릭·Enter/Space·닫기 후 초점 복귀와 필터/스크롤 보존, 읽기→편집·저장·취소, 소유자/친구 상태를 확인한다. 내용 스크롤/선택만으로 상세가 열리지 않는다. 모바일 실기기와 자동 검증 범위를 구분해 기록한다.
- [x] 로컬에서 관련 단위 테스트, 빌드·인코딩 검사와 관련 E2E를 통과한다. 공통 컴포넌트의 여러 화면 변경이므로 전체 `npm run test:e2e`도 로컬에서 통과한 뒤 푸시한다. 기존 작업 파일을 덮어야 하는 상황이면 별도 깨끗한 체크아웃을 사용한다.
- [x] 실행 명령·결과, 확인한 화면/폭/상태·캡처와 미검증 범위를 이 티켓에 기록한다. CI는 독립된 최종 배포 게이트로 사용한다.
