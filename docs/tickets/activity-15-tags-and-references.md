# [활동] 내부 종류 제거·태그와 대상 참조 중심 기록·공유 단순화

2026-09-24 · 설계 완료, 구현 전.

GitHub: https://github.com/kimyongin/fin/issues/122

## 목적과 확정 결정

사용자는 활동을 날짜·내용·태그로 기록하고 찾는다. 조사/점검/판단/회고를 한 가지 종류로 먼저 정할 필요가 없다. 화면에서 종류를 숨기는 데 그치지 않고 내부 활동 종류도 제거한다. 공유도 종류별로 나누지 않고 기존 관계별 `활동 공유` 하나로 통합한다.

활동의 기본은 날짜·제목·본문·태그, 연결은 관련 할 일/보유 등의 참조다. 매매·잔고 보정·할 일 완료는 실행 기능이 자기 상태를 변경한 뒤 사람이 읽을 수 있는 결과를 활동에 남긴다. 활동을 수정/삭제해도 잔고나 할 일 완료 상태를 역산하거나 되돌리지 않는다.

## 현재 구현과 영향

- `activity_events.record_kind`가 일반/조사/점검/판단/회고/매매/보정/할 일을 구분한다. `action_type`도 제목/필드별 표시와 수행 동작 구분에 쓰인다. 이 두 가지를 포함한 활동 분류 의존을 조사한다.
- `GeneralActionModal`은 종류 select와 판단 전용 상태/선택안/이유 폼을 제공한다. `ActionTimeline`은 종류 OR 조건과 태그 조건을 따로 처리하고 `ActivityKindBadge`를 사용한다.
- 활동 쓰기/수정/삭제, 타임라인/키워드·유사도 검색, 점검/판단 조회, 일일/기간 문맥, 금융 자동 기록과 반복 할 일 처리가 종류를 참조한다.
- 현재 `briefings`, `decisions`, `activity` 등으로 나눈 공유와 종류 기반 비공개/수정 제한도 재설계해야 한다.
- `activity_tags`와 기록/할 일의 태그 연결은 이미 있다. 자산 배분 태그와 별개로 재사용하며 새로운 분류 테이블이나 태그 엔진을 만들지 않는다.

## 화면과 검색

- 등록/편집에서 종류 선택과 종류에 따라 나타나는 판단 전용 폼을 없앤다. 제목·날짜·본문·태그와 필요한 참조를 입력한다. 선택 이유/채택 여부는 본문에 표현하고 별도 상태 엔진으로 유지하지 않는다. 기존 출처는 본문 링크 등 읽을 수 있는 형태로 보존한다.
- 조사/점검/판단/회고/매매/잔고 보정은 필요하면 일반 태그로 사용한다. 여러 개를 함께 붙일 수 있다. `일반`, `할 일 완료` 태그를 자동으로 만들지 않는다. 아무 태그 없이도 기록 가능하다.
- 모든 태그는 검색을 위한 일반 분류다. 예약 이름·숨겨진 system kind·특정 태그가 여는 전용 폼/권한/삭제 제한을 만들지 않는다. 기존 태그와 이름이 같으면 재사용하고 이관 재실행으로 중복 생성하지 않는다.
- 목록·상세·검색 결과에는 태그 영역 하나를 사용한다. ‘할 일 완료’ 종류 배지는 제거하고 실제 제목을 보여준다. 연결된 할 일은 기존 상세의 인라인 요약으로 읽는다. 매매도 별도의 보호 종류 배지가 아니라 필요한 일반 태그/본문으로 표현한다.
- 검색은 종류 필터를 제거하고 태그 필터 하나로 통합한다. 기본은 선택 태그 중 하나라도 포함(OR), 필요하면 `모두 포함`(AND)을 선택한다. 태그 미선택은 전체이며 날짜/검색어/관련 대상 조건과는 AND다. 필터는 페이지 자르기 전에 서버에서 적용한다.
- 할 일과 기록의 구분은 미래 계획/수행 기록의 실제 차이이므로 기존 화면과 저장 구조를 유지한다. 이를 활동 ‘종류’로 다시 저장하지 않는다. 할 일에 붙인 태그가 수행 기록에 복사되는 기존 편의는 유지한다.

## 저장과 참조 계약

기존 활동 테이블을 정본으로 재사용한다. `record_kind`와 활동 동작을 분류하는 `action_type` 등은 필요한 내용을 읽기 본문으로 옮기고 종류 의존 소비자를 대체한 뒤 제거한다. 이름만 다른 `type`, `is_trade`, 시스템 태그 키 또는 참조 유무로 숨은 종류를 재구성하지 않는다.

활동 입력/출력은 제목·본문·발생 시각과 기존 태그/참조 중심으로 줄인다. 기존 result/conclusion/note/판단 필드와 before/after 값은 의미가 드러나는 본문으로 보존하는 방향으로 통합한다. 금융 변화는 `10주 매수, 보유 수량 20→30주`처럼 실행 시점 값을 기록한다. 현재 보유를 재조회해 과거 본문을 재생성하지 않는다. 보존이 필요한 기존 대량 변경 내역/CSV는 현 사용처와 대조해 기존 파일 내보내기 등 최소 보존 방법을 계약에 적고 조용히 버리지 않는다. 이 보존 때문에 새 종류·범용 감사 원장을 만들지 않는다.

- `task_id`는 관련 할 일, `holding_id`는 계좌별 특정 보유를 가리킨다. 종목 ID만으로 여러 계좌 중 대상을 추정하지 않는다. 연결은 탐색용이지 완료 증거나 금융 권한이 아니다.
- 하나의 기록에 할 일과 보유 참조가 함께 있을 수 있다. 계좌/종목 메모 변경이나 여러 보유의 일괄 수정처럼 단일 holding으로 부족한 기존 시나리오도 목록화한다. 첫 계약 단계에서 기존 연결 재사용 또는 필요한 명시적 복수 참조의 최소 구조를 확정한다. 임의 테이블명/ID를 받는 범용 관계 엔진을 만들지 않는다.
- 참조는 서버에서 소유자와 존재를 검증한다. 대상 삭제로 활동 본문을 cascade 삭제하지 않고 연결을 해제하거나 삭제된 대상으로 표시한다. 본문에 남긴 당시 이름·값은 읽을 수 있어야 한다.
- 본문은 소유자가 수정/삭제할 수 있고 원래 금융 동작 여부에 따른 편집 제한은 없앤다. 잘못 적은 기록 수정과 실제 잔고 수정은 독립이다. 활동 날짜 수정도 반복 할 일의 회차 완료일을 옮기지 않는다.
- 인증/소유권/일반 충돌 검사와 금융 실행 RPC의 정밀 계산·잠금·멱등성·원자성은 유지한다. 금융 명령의 중복 방지용 내부 영수증은 활동 종류가 아니며 삭제 범위에 넣지 않는다. 활동 삭제 뒤 금융 요청을 재시도해도 체결을 재실행하면 안 된다.
- 반복 완료 여부는 기존 `general_task_occurrence_states` 등 할 일 쪽 상태가 정본이다. 활동 종류나 자유 태그를 읽어 완료를 판단하지 않는다. 기록 삭제/본문 수정/참조 변경은 완료 상태를 바꾸지 않고 완료/다시 열기는 해당 할 일 기능만 수행한다. 활동 행에 대한 참조가 상태 테이블에 있다면 기록 삭제 시 상태 행이 지워지지 않도록 FK/조회도 점검한다.
- 기술적 사용자 ID/시간/참조/재시도 정보는 실제 목적이 있는 범위에서 유지한다. 기능별 명령 이름까지 없애라는 뜻은 아니며, 활동 내용의 숨은 분류값으로 남기지 않는 것이 결정이다.

## 공유 단순화

기존 친구/공유 관계 구조는 유지하고 활동 종류별 공유 토글을 `활동 공유` 하나로 통합한다. 자산·배분·할 일 등 다른 기능의 권한까지 전부 합치지는 않는다.

- 전환 때 기존 활동 관련 공유 허용은 해제한다. 구 `activity` 허용이 새 전체 활동 허용으로 자동 승계되어서는 안 된다. 사용자에게 범위가 넓어졌음을 설명하고 직접 다시 켜게 한다. 호환 fallback/이전 세션에서도 자동으로 허용되지 않게 서버에서 처리한다.
- 켜면 기존과 앞으로 작성하는 활동의 제목·날짜·본문·태그가 공유된다는 범위를 명확히 표시한다. 행별/태그별 추가 권한은 도입하지 않는다. 기본은 비공개다.
- 관련 할 일/보유 상세는 해당 기능 접근 권한이 있을 때만 보여준다. 활동 공유만으로 비공개 원칙·보유 메모·확인 정보나 다른 데이터 전체를 조인해 노출하지 않는다.
- 자동 기록 생성 시 비공개 메모 원문/토큰/전체 내부 JSON 등을 활동 본문에 복사하지 않는다. 사용자가 본문에 직접 적은 내용은 활동 공유의 대상이다. 기존 자동 payload는 공개 가능 본문으로 변환하면서 민감 필드 제외를 검증한다.
- 타임라인·상세·검색·최근 기록·기간 문맥과 웹/MCP 모두 동일한 공유 규칙을 사용한다. 태그 이름 변경/삭제로 접근 권한이 바뀌면 안 된다.

## MCP·문맥·가이드

활동 등록/수정/검색에서 category/record_kind 입력과 자동 종류 추론을 제거한다. 명확한 사용자 요청에 따라 일반 태그와 본문/대상 참조를 저장한다. 기존 조사/점검/판단 전용 도구가 단순 래퍼라면 실제 소비자를 확인하고 일반 기록/검색 도구로 통합한다. 금융 실행/할 일 완료 도구는 고유 실행 책임 때문에 유지한다.

일일 점검·기간 회고에 필요한 기록은 날짜·태그·본문으로 찾는다. 최근 ‘점검’이나 ‘판단’이 없다고 빈 문맥을 숨기지 않고 최근 관련 기록을 제공한다. 모델이 특정 태그 이름을 필수 내부 분류처럼 생성하게 하지 않는다. 회고를 다시 요약할 때 이전 요약을 새로운 실제 행동으로 중복 집계하지 않도록 가이드에 설명하고, 보장할 수 없는 자동 종류별 통계/요약 제외 기능은 제거한다. 이를 위해 숨은 retrospective 플래그를 만들지 않는다.

도구 목록/description/JSON 스키마·가이드·테스트·배포 검사·더미 데이터를 함께 갱신한다. 오래된 호출의 종류 인자를 조용히 무시하지 않고 도구 갱신이 필요한 계약 변경으로 처리한다. 별도 조사/판단 모델을 다시 만들지 않는다.

## 구현 순서와 최소 계약

1. 종류 의존을 웹·SQL·트리거·RLS·공유·검색·회차 상태·MCP별로 목록화한다. 각 의존을 제거/본문/태그/명시적 참조/실행 기능으로 대체하는 표와 최종 필드·RPC·공유 전환 계약을 이 티켓에 기록한다.
2. 일반 기록의 종류 없는 생성·수정·태그 검색 수직 슬라이스를 연결한다. 기존 기록의 본문/태그/참조 이관과 공유 기본 차단을 함께 검증한다.
3. 금융/할 일 자동 기록을 연결하고 편집/삭제 후에도 실제 상태·재시도가 정상인 것을 검증한다. 문맥/MCP 소비자를 대체한 뒤 구 컬럼/인덱스/함수 분기·도구를 제거한다.
4. 문서와 실제 스키마 개요를 갱신하고 로컬 검증·운영 적용/기존 공유 해제 안내·ChatGPT 도구 갱신을 인계한다. 적용된 migration은 수정하지 않는다.

#119의 타임라인은 종류 배지 대신 태그를 표시한다. #120의 자산 변경 기록은 새 본문/보유 참조 계약을 따른다. 두 티켓의 종류별 보호/필드별 표시를 유지하라는 문구 중 충돌 부분은 이 티켓으로 대체한다. 원칙/배분 설계와는 독립이다.

## 완료 기준

- [ ] 화면/DB/API/MCP/가이드에 활동 종류 선택·내부 분류·종류 기반 폼/권한이 남지 않는다. 숨은 플래그나 예약 태그로 대체하지 않는다.
- [ ] 다중 태그/태그 없는 기록·OR/AND 검색·이름 변경/삭제가 작동하고 기존 종류 이관 태그가 중복되지 않는다.
- [ ] 기록에서 관련 할 일·계좌별 보유를 정확히 읽고, 대상 삭제/다중 대상/타인 참조/대상 접근 권한 없음을 처리한다.
- [ ] 매매/보정/할 일 완료가 기록을 남기며 기록 편집/삭제 후 잔고·반복 완료 상태·동일 요청 재시도가 영향받지 않는다.
- [ ] 기존 본문·금융 변화 정보와 유효한 기록 연결을 보존한다. 이관 전후 누락과 민감 필드의 공유 유출을 검증한다.
- [ ] 기존 활동/점검/판단 공유는 전환 후 자동 차단되고 명시적으로 활동 공유를 켠 관계만 접근한다. 종류·태그 변경으로 권한이 달라지지 않는다.
- [ ] 웹 저장→MCP 조회와 MCP 저장→웹 표시, 일일/기간 문맥 및 키워드·유사도 검색을 실제 로컬 API로 검증한다.
- [ ] 360/390/768/1024/1440px에서 입력·태그·검색·상세·빈 상태/오류·미저장 보호를 검증하고 실제 확인 범위를 기록한다.
- [ ] 관련 DB/API/MCP/E2E·가이드·빌드·인코딩 검사와 종류 의존 제거 전수 검색을 수행한다. 구현/운영 적용·실제 ChatGPT 평가는 구분한다.

현재는 설계·티켓 작성이며 제품 코드·DB·배포는 변경하지 않았다.
