# [안정화 재검토] 활동 필터 재선택과 조회 상태 회귀 수정

우선순위: P1 · 상태: 티켓 작성, 구현 전 · 2026-09-23
관련: #93 · 기준 코드: b7ee31d

## 문제와 근거
`ActionTimeline.jsx:106`은 선택된 필터 재클릭에도 request gate를 무효화하고 loading을 켠다. filter 값이 같으면 조회 effect가 실행되지 않아 로딩이 끝나지 않는다. `FilterChips`는 선택된 버튼도 클릭 가능하다. 기준 코드 b7ee31d의 정적 검토 결과이며 브라우저 재현은 구현 시작 시 수행한다.

## 범위
- 같은 필터 선택은 상태를 바꾸지 않게 한다. loading 시작/종료와 요청 무효화의 책임을 실제 조회 흐름에 맞춘다.
- 기존 requestGate를 재사용한다. 일반 목록·검색·더 보기·해제 간 늦은 응답 처리를 함께 점검한다.
- #93의 소유자 전환/검색 초기화 미검증 항목을 여기서 검증하고 원 티켓에 결과를 연결한다.

## 완료 조건
- [ ] 조회 완료 및 조회 중에 현재 필터를 재클릭해도 화면이 멈추지 않는다.
- [ ] 검색 중 필터 변경, 검색 해제, 더 보기 중 초기화 후 이전 응답/오류가 새 결과를 덮지 않는다.
- [ ] 친구/본인 전환 뒤 이전 대상의 내용·오류가 남지 않는다.
- [ ] 관련 브라우저 회귀를 390/1440px에서 실행하고 결과를 기록한다.

## 진행 규칙

- docs/START-HERE.md, ADR-0008, SIMPLICITY.md와 관련 티켓을 먼저 읽는다. UI 변경 전 디자인 원칙/컴포넌트 규칙, DB 변경 전 schema/OVERVIEW를 확인한다.
- 필요한 기존 helper와 목적별 API를 재사용해 수직 슬라이스로 구현·검증·커밋한다. 사용자 로컬 설정과 무관한 변경은 보존한다.
- 기존 티켓의 검증 기록은 유지하고 새 결과를 교차 연결한다. 코드 검토로 추론한 문제와 실제 재현 결과를 구분한다.
