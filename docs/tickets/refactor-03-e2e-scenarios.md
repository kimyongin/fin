# [리팩토링] E2E 테스트를 사용자 흐름별로 분리

2026-09-23 · P2 · 로컬 구현·격리 검증 완료, 운영 배포 전. 관련: #97, #104~#106.

## 목적과 근거

e2e/app.spec.js에 배포 계약·피드백·점검·원칙·활동·자산·공유·반응형 테스트가 함께 있다. 기능별 실행과 실패 탐색을 쉽게 하되 검증 범위를 축소하지 않는다.

## 범위

- 착수 시 실제 테스트 목록을 기준점으로 저장하고 사용자 흐름별 spec으로 옮긴다. 기존 48개라는 과거 숫자를 고정 목표로 삼지 않는다.
- 재사용하는 메뉴 탐색은 기존 e2e/helpers.js로 이동한다. 범용 page-object 프레임워크는 도입하지 않는다.
- 공유 테스트 사용자/DB 쓰기의 의존성을 조사한다. 파일 분리 후에도 안전하게 직렬 실행되도록 worker 설정을 명시하거나 기존 격리가 충분한지 입증한다. fullyParallel=false만으로 파일 간 병렬 실행을 막는다고 가정하지 않는다.
- docs/engineering/development.md에 격리 환경을 사용하는 기능별 실행 방법을 기록한다. 일반 로컬/원격 DB로 테스트가 전환되지 않게 한다.

## 완료 기준

- [x] 이동 전후 테스트 이름/개수/검증 내용을 대조해 누락·중복이 없다.
- [x] 테스트 순서와 공유 데이터 의존성을 명시하고 분리 후 단독 실행도 가능하다.
- [ ] 활동/원칙/자산 등 기능별 실행과 전체 격리 E2E를 검증한다.
- [x] 기존 DB/MCP/배포 계약 검사를 우회하지 않는다.
- [x] 테스트 설정·실행 문서·인코딩 검사 결과와 미검증 범위를 기록한다.

실행 속도 향상·병렬화는 별도 측정 없이는 약속하지 않는다.

## 구현·검증 기록 (2026-09-23)

기존 `e2e/app.spec.js`의 48개 테스트를 app/activity/assets-access/navigation/integrations 다섯 파일로 옮겼다. 이동 전후 테스트 이름을 대조해 기존 48개 누락/중복이 없음을 확인했고 새 버그 회귀 4개를 추가했다. 공통 메뉴 이동은 `e2e/helpers.js`로 옮겼다. `playwright.config.js`에 worker 1개를 명시해 같은 격리 DB에 대한 파일 간 동시 쓰기를 방지한다. `docs/engineering/development.md`에 기능별 실행법을 기록했다. 2026-09-23 격리 전체 실행에서 기존 시나리오와 신규 3건은 통과했다. 신규 활동 상세 시나리오는 선택자 수정 후 격리 단독 실행으로 통과했다. 마지막 수정본에 대한 전체 52건 단일 재실행은 하지 않았다. 운영 배포는 하지 않았다.
