# [MCP 개선] 안정적 오류 코드와 멱등 재시도 계약 보완

우선순위: P1 · 상태: 로컬 구현·DB/MCP 검증 완료 · 운영 미배포 · 작성: 2026-09-21
상위: #40 · 시나리오/연관: S24/S18~S22 · W06/W08 · #49/#53 후속
선행/통합: 01-contracts와 계약 조율, 독립 착수 가능

## 목적

ChatGPT가 추측 없이 Portfolio 도구를 선택·사용·복구하고, 운영자가 계약 변경을 안전하게 유지할 수 있게 한다. ChatGPT는 조사·해석·설명, Portfolio는 기억·계산·검증을 담당한다.

## 검토 근거

- errors.ts가 영어 오류 문자열로 분류하고 미분류 오류를 일률적으로 재시도 가능으로 반환한다.
- migration 011의 app_verify_holding은 성공 receipt 조회 전에 holding version을 검사한다. 성공 응답 유실 후 잔고가 변경되면 같은 요청으로 성공 결과를 회수하지 못한다.

## 작업 범위

- 입력 수정/동일 요청 재시도/재조회·재검토/접근 거부를 명확히 구분한다.
- 관련 RPC에 안정적인 업무 오류 식별자를 적용하고 Edge에서 안전한 code/action으로 변환한다. 기존 오류와의 호환 adapter는 한시적으로 명시한다.
- 인증된 동일 요청의 기존 성공 확인을 새 버전 검사보다 먼저 처리하도록 보완한다. 타 사용자 receipt 접근과 다른 payload의 키 재사용은 거부한다.
- 요청 키 보존과 새 시도 생성 조건, 충돌 후 무조건 최신 버전 덮어쓰기 금지를 instructions/description에 반영한다.

## 인수 조건

- [x] verify 성공→응답 유실→잔고 변경→동일 키 재시도에서 원래 성공 결과가 반환되고 확인 기록은 중복되지 않는다.
- [x] 동일 키 다른 입력, 타 사용자, preview 만료/stale/consumed, version 충돌을 실제 RPC→MCP 경로로 검증한다.
- [x] 확정 입력 오류를 transient로 안내하지 않으며 오류/로그에 SQL 원문·토큰·개인 payload를 노출하지 않는다.
- [x] #49/#53의 기존 완료 주장과 이번에 추가로 검증한 범위를 구분해 기록한다.

## 구현 결과

- migration 026에서 확인 성공 receipt를 현재 holding version보다 먼저 조회한다. 응답 유실 뒤 잔고가 바뀌어도 동일 payload/key는 원래 성공을 반환한다.
- 입력 오류는 비재시도 validation_error로, 미분류 오류는 무조건 재시도하지 않도록 안전한 action으로 바꿨다.
- 동일 키 재시도·중복 방지·stale 충돌을 실제 OAuth MCP와 DB 오류 계약으로 검증했다.

## 진행 규칙

- docs/START-HERE.md, 관련 계약과 ADR-0004를 읽고 기존 구현을 먼저 확인한다. 과거 티켓의 구현을 재작성하지 말고 위 후속 차이만 처리한다.
- 최소 공통 기반 + 수직 슬라이스로 구현·검증한다. 기존 migration을 고치지 말고 필요한 증분 migration과 schema/OVERVIEW.md를 갱신한다.
- 실제 실행한 검증과 미검증 항목을 구분하고 npm run check:encoding을 수행한다. 운영 배포·push·실사용 검증을 자동 완료 처리하지 않는다.
