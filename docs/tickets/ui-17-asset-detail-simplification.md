# [자산 UX] 상세 입력 간소화·현재값 직접 수정·저장 사유 확인

2026-09-24 · 로컬 수직 슬라이스 구현 중. 운영 배포 전.

GitHub: https://github.com/kimyongin/fin/issues/124

연계: [#125 기록 입력 간소화](./activity-16-record-editor-simplification.md)가 활동의 보유 참조를 종목 참조로 바꾼다. 본 티켓의 자동 활동도 종목 연결과 당시 계좌별 변경값·선택적 사유를 사용한다. 실제 보유 저장의 대상 ID는 유지하고 두 티켓이 중복 활동을 생성하지 않게 한다.

## 목적과 대체 범위

모바일에서 자산 상세를 열어 현재가와 계좌별 보유값을 바로 수정하고 저장한다. 공개/비공개 메모와 반복 입력, 매매·보정 화면 왕복을 줄인다. 접기·펼치기로 복잡함을 숨기지 않고 필드와 버튼 자체를 줄인다.

#120의 비공개 보유 메모·계좌별 메모 노출, 수동 가격 접기, 상세의 매매/증권사 확인 단계 진입 요구를 대체한다. #123의 직접 편집·단일 원자 저장은 유지한다. 저장 직전의 작은 사유 확인창은 편집용 모달 왕복과 구별되는 명시적 예외다. 제품 코드와 DB는 이 티켓 작성으로 변경하지 않는다.

## 실제 구현 기준

- `AssetDetailModal.jsx`는 종목 일반/비공개 메모와 계좌별 일반/비공개 메모를 모두 입력받고, 수동 가격을 `details`에 숨긴다.
- `stage`에 따라 `TradeEntryModal`/`HoldingIntegrityModal`로 교체된다. 동시에 겹치는 모달은 아니지만 사용자는 다른 폼으로 이동한다.
- `app_save_asset_detail`은 종목·보유·태그·메모를 원자 저장하며 예상값/보유 버전과 멱등 키를 검증한다. 이 목적별 저장을 개선하며 새 원장·변경 사유 테이블·범용 폼 엔진을 만들지 않는다.

## 화면 계약

| 순서 | 내용 |
| --- | --- |
| 헤더 | 종목명·티커·닫기 |
| 종목 정보 | 종목명·태그와 필요한 통화 표시/입력. 시세형은 현재가·기준일 입력을 처음부터 표시 |
| 계좌별 보유 | 계좌명과 시세형 수량·평균가, 평가형 매입/평가금액, 현금성 잔액. 모든 보유 계좌를 펼쳐서 표시 |
| 메모 | 종목 공통의 일반 `메모` 하나 |
| 하단 | 닫기·저장 |

- 종목 정보·계좌·가격에 아코디언/추가 설정/더 보기 토글을 넣지 않는다. 현재 선택 계좌를 먼저 배치할 수 있지만 다른 계좌를 숨기지 않는다.
- 종목 공통의 `보유 이유 · 나만 보기`와 계좌별 모든 메모 입력을 제거한다. 계좌 자체의 독립 관리 화면에 있는 계좌 메모까지 제거하는 요청은 아니다.
- 기존 보유가 있어 바꿀 수 없는 유형과 티커는 입력칸 대신 짧은 읽기 정보로 표시한다. 수정 가능한 통화 등 유효한 기존 속성을 숨기지 않고 간결하게 배치한다.
- 계좌명 반복 제목/선택기와 평가액 설명을 줄인다. 기존 보유의 계좌 재지정이 필요하면 계좌 선택기 하나가 계좌 표시를 겸한다. 다른 계좌 보유 추가·명시적 삭제는 유지하며 별도 메모를 입력받지 않는다.
- 상세에서 `매매 기록`, `증권사 확인·보정` 진입 버튼을 제거한다. 사용자는 증권사에서 확인한 최종 수량·평균가/금액을 바로 입력한다. 체결가로 평균가를 계산하는 추가 폼을 이 상세에 다시 넣지 않는다.
- 640px 미만 전체 화면, 이상 중앙 모달과 고정 footer를 유지한다. 짧은 관련 숫자는 공간이 허용하면 같은 행에 두되 작은 글자나 가로 스크롤로 압축하지 않는다.

## 가격 편집

- 기존 최신 가격과 그 기준일을 처음부터 보여준다. 별도의 빈 `수동 가격` 폼을 접어서 두지 않는다. 시세형에만 제공한다.
- 가격 또는 기준일을 사용자가 실제로 변경한 경우에만 가격 쓰기를 포함한다. 다른 필드 저장·변경 없음 저장으로 가격 행/기준일을 새로 만들지 않는다. 기준일만 명시적으로 바꾼 경우는 가격 정보 변경으로 처리한다.
- 시세 없음은 빈 값으로 표시하며 0이나 오늘 날짜를 저장된 값처럼 꾸미지 않는다. 새 가격 입력 시 필요한 기준일을 검증한다.
- 입력 중 자동 가격 갱신이 초안을 덮어쓰거나, 사용자가 건드리지 않은 과거 가격을 다시 저장하지 않게 한다.

## 저장과 변경 사유

1. 상세에서 값을 수정한다. 보유 수량·평균가·매입/평가금액·잔액 변경 또는 새 보유 추가가 있으면 저장 전에 작은 확인창을 연다. 여러 계좌 변경도 확인은 한 번이다.
2. 확인창은 계좌별 실제 변경 전후 값과 `변경 사유 (선택)` 입력, 취소/저장을 제공한다. 사유는 자유 텍스트이며 필수 분류나 자동 사유 추론은 없다. 종목명·태그·종목 메모·가격만 바꾼 경우 이 추가 단계를 생략한다.
3. 취소/Escape는 확인만 닫고 상세 초안으로 돌아간다. 상세는 뒤에 보존하지만 확인 중에는 inert로 두어 활성 dialog/포커스 트랩은 하나다. 확인 때문에 상세 초안을 다시 생성하거나 전체 편집 화면으로 이동하지 않는다. 작은 화면에서도 확인창은 짧은 내용 크기를 유지하되 키보드/화면 높이를 넘으면 내부 스크롤한다.
4. 실제 변경이 있는 자산 상세 저장 한 번당 활동은 한 건만 생성한다. 같은 종목의 여러 계좌를 수정해도 한 본문에 종목 공통 변경·계좌별 변경 전후 값·선택적 사유를 모으고 해당 종목 하나에 연결한다. 자산 변경과 이 활동은 한 트랜잭션으로 저장한다. 내부 종목/보유 쓰기의 개별 자동 기록과 종합 기록을 동시에 남기지 않도록 이 목적별 저장 경로에서 처리한다. 다른 개별 쓰기의 필요한 기록까지 전역으로 끄지 않는다. 변경 없음과 동일 요청 재시도는 새 기록을 생성하지 않는다. 별도 번들 ID·관계 테이블은 추가하지 않는다.
5. 성공 후 상세를 유지하고 초안 기준·목록을 갱신한다. 실패 시 초안과 사유를 보존한다. 중복 클릭·응답 유실 재시도에도 자산/활동이 중복 반영되지 않는다. 저장 후 조회 실패는 조회만 재시도한다.

수량/평균가의 차이로 체결가·매수/매도 사실을 추정하지 않는다. 입력한 현재값과 사람이 적은 사유를 기록하며 저장 자체를 증권사 확인 완료로 취급하지 않는다. 기록 편집/삭제도 실제 잔고를 되돌리지 않는다. 기존 금융 정밀도·소유권·충돌 검증을 유지한다.

## 데이터·다른 진입 경로·MCP

- 메모 정본은 기존 종목 일반 메모다. 메모가 공유되는 범위는 기존 자산 공유 정책을 따른다. 기존 비공개 내용을 여기에 자동 복사하거나 공개 활동에 옮기지 않는다.
- 퇴역 범위는 종목 비공개 보유 메모와 보유 행의 일반/비공개 메모다. 종목 일반 메모와 계좌 자체의 메모는 유지한다. 상세뿐 아니라 등록/수정·표 편집/가져오기·MCP 쓰기/조회·일일/기간 문맥·가이드·테스트에서 퇴역 메모를 다시 입력하거나 조언에 사용하는 경로도 함께 정리한다.
- 구현 첫 단계에서 해당 데이터와 소비자를 대조하고 제거 목록을 기록한다. 대상 환경 적용 전 기존 내용을 소유자별로 식별 가능한 비공개 복구용 내보내기로 보존하고, 전환 migration에서 퇴역 컬럼·전용 RPC 및 잔여 의존을 제거한다. 일반 메모/공유 활동으로 자동 합치지 않으며 새 보관 테이블·복원 UI·상시 호환 API는 만들지 않는다. 내보내기는 Git에 넣지 않는다. 완료 조건은 입력란만 숨기는 것이 아니라 웹/MCP에서 같은 메모 모델을 사용하는 것이다.
- 비공개 메모 로딩 실패가 새 상세 전체를 막는 현재 의존은 제거한다. 전환 전 구 저장 함수를 쓰는 중간 단계에서 누락 필드를 빈값으로 보내 기존 메모를 지우지 않는다. 전환 완료 후에는 구 메모 인자를 제거하고 이전 호출을 조용히 수용하지 않는다.
- 기존 `app_save_asset_detail`에 선택적 사유와 실제 변경 판정을 연결한다. 사유 길이 제한·재시도 동일성은 기존 계약과 대조해 최소한으로 확정한다. 활동 작성 단위는 위의 상세 저장 한 번당 한 건으로 고정한다. 별도 보유 삭제·다른 화면의 일괄 저장까지 이번 기록 묶음 규칙을 자동 확대하지 않는다.
- 상세의 버튼 제거만으로 MCP의 명시적 매매/확인 API까지 폐기하지 않는다. 실제 소비자가 없는 컴포넌트만 제거하고 남은 호출 경로를 기록한다. 이번 웹 흐름을 MCP 안내에서 별도 매매 폼 사용으로 잘못 설명하지 않도록 도구 설명·워크플로 가이드를 검토하고 영향 범위 또는 영향 없음 근거를 남긴다.

## 완료 기준

- [ ] 가격/기준일·모든 계좌별 보유·메모 하나가 접기 없이 보이고 구 메모/매매/확인 버튼이 없다.
- [ ] 시세형·평가형·현금성·다계좌·신규 보유를 올바르게 입력/저장하며 기존 계좌 추가·표 편집은 정상이다.
- [ ] 보유값 변경에만 사유 확인이 한 번 나타나고 사유 없이도 저장된다. 취소/뒤로/Escape/저장 실패가 상세 초안을 보존한다.
- [ ] 자산/활동/사유는 원자 저장되고 중복 클릭·응답 유실·충돌·잘못된 계좌에서 부분 저장이 없다.
- [ ] 종목 정보와 두 계좌 이상을 함께 수정해도 활동은 한 건이며 종목 연결·계좌별 변경값·사유를 포함한다. 변경 없음/재전송은 기록을 늘리지 않는다.
- [ ] 변경하지 않은 시세/기준일을 쓰지 않는다. 가격만/기준일만 변경·시세 없음·자동 갱신 중 초안을 검증한다.
- [ ] 기존 비공개 메모의 자동 공개·묵시적 삭제가 없고 공유 사용자의 편집/비공개 접근을 차단한다.
- [ ] 퇴역 메모의 비공개 내보내기와 삭제 범위를 확인하고 컬럼·전용 API·표 편집/가져오기·MCP/문맥/가이드 의존을 제거한다. 종목 일반 메모와 계좌 자체의 메모는 유지된다.
- [ ] 360/390/768/1024/1440px에서 긴 종목명·복수 계좌·빈값·오류·확인창·초점 복귀·footer를 확인하고 실기기 미검증은 구분한다.
- [ ] 관련 DB/API·웹/MCP 회귀, 가이드·빌드·인코딩 검사 및 문서/기존 티켓 대체 표시를 마친다. 운영 배포 여부는 별도로 기록한다.

## 구현 진행 기록 (2026-09-24)

- 자산 상세에서 현재가·기준일·모든 계좌별 현재값·종목 공통 메모를 바로 편집한다. 금융값 변경은 작은 사유 확인창 한 번을 거치며 새 `app_save_asset_detail_current` RPC가 원자성·버전·멱등성을 지키고 실제 변경당 종목 연결 활동 한 건을 만든다. 단순 종목 정보/가격 변경은 확인창을 건너뛴다.
- 보유별 메모 입력은 상세·별도 보유 편집·표 편집/CSV에서 제거했다. 다만 기존 메모 값의 묵시적 삭제를 막기 위해 내부 저장값·DB 컬럼·RPC 계약은 아직 유지한다. 종목 비공개 메모 로딩 의존도 아직 남았다. 따라서 메모 퇴역 완료로 표시하지 않는다.
- 일반 로컬 DB의 기존 종목·보유 메모는 Git 외부의 비공개 SQL 덤프로 보존한 뒤 새 migration 두 개를 로컬에만 적용했다. 운영 데이터의 내보내기·컬럼 제거·운영 배포는 아직 하지 않았다.
- `npm test` 103개, DB pgTAP 556개, 관련 Chromium E2E 27개(자산 10·활동 17), 빌드/인코딩 검사가 통과했다. 추가로 실기기/전 지정 뷰포트, 운영 환경에서의 회귀가 필요하다.
