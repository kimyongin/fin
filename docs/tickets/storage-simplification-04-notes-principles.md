## 목적

사용자 기능에 필요한 최소 저장·처리만 유지하고 기존 데이터와 공개 범위를 보존한다. 기존 구현의 존재는 유지 근거가 아니다.

## 인수 조건

- [ ] 원칙은 같은 테이블에 변경마다 새 행을 저장한다. 각 행의 고유 ID와 별도로 같은 원칙을 묶는 원칙 ID, 사용자·종류·내용·적용 시작 시각·종료 여부 및 필요한 선택 적용 범위를 둔다. 별도 현재값/이력 테이블이나 버전 번호는 만들지 않는다.
- [ ] 평소에는 사용자·원칙 ID별 최신 행을 조회하고 종료된 원칙을 제외한다. 과거 조회는 지정 시각 이하의 마지막 행을 원칙별로 선택한 후 종료 여부를 적용한다. 종료 행을 먼저 제외하여 이전 원칙이 되살아나지 않게 한다. 같은 종류의 여러 원칙이 모두 조회되어야 한다.
- [ ] 수정은 새 내용 행, 삭제/종료는 같은 원칙 ID의 종료 행 추가로 처리한다. 기본 적용 시각은 서버 저장 시각이며 소급/예약 편집 UI는 만들지 않는다. 동일 시각에는 서버가 정한 안정적인 저장 순서로 최신값을 결정한다. 날짜 조회는 사용자 시간대 기준 해당 날짜 말까지 적용된 원칙을 반환한다.
- [ ] 앱과 MCP에서 현재/특정 시점 원칙 조회를 제공하고 가이드에도 같은 의미를 설명한다. 변경 전/후·종료 전/후·생성 전·같은 종류 복수 원칙·같은 날 복수 변경·타인 접근을 검증한다. 원칙 조회 이력만 지원하며 과거 포트폴리오 복원은 만들지 않는다.

- [ ] holding_theses는 해당 holding.note 또는 instrument.note로 매핑한다. 기존 메모와 충돌하면 원문 구분을 보존해 합치고 조용히 덮어쓰지 않는다. 보유가 없는 과거 이유는 활동/보관으로 읽을 수 있게 한다.
- [ ] 보유 이유의 history/task link/재활성화 수명과 전용 MCP 도구를 제거한다. 후속 점검은 공통 할 일로 전환하고 기존 날짜/연결을 보존한다.
- [ ] 개인 목표·성향·상세 원칙·운영 규칙을 종류/적용 범위가 있는 공통 원칙으로 읽고 편집한다. 목표 비중/버킷/모드 계산은 기존 전략 구조를 유지한다.
- [ ] 메모는 현재 행을 편집하고 원칙만 같은 테이블에 변경 후 내용 전체를 새 행으로 저장한다. 의무 변경 사유나 범용 revision 엔진은 만들지 않는다. 과거 분석에 이미 저장된 당시 기준은 소급 수정하지 않는다.
- [ ] 원칙 인터뷰→MCP 저장→앱 조회와 계좌/종목/보유 메모 편집을 검증한다. 개인 이유/원칙의 기존 비공개 경계, 계좌별 서로 다른 메모, 전량 매도 후 기록 보존을 검증한다.
- [ ] 원칙 변경의 자동 활동은 유용한 요약 한 건으로 제한하고 본문 이력을 별도 중복 저장하지 않는다. 가이드/스키마 인덱스를 갱신한다.

## 구현 방식

관련 DB/API·MCP/UI·가이드·검증을 수직 슬라이스로 연결하고 슬라이스마다 커밋한다. 일반 코드 구현/배포는 이 티켓 작성에 포함하지 않는다. 미정 세부 기술 선택은 위 범위 안에서 구현자가 근거를 기록해 확정한다. 제품 기능 축소 범위를 추가로 넓히면 먼저 영향과 대안을 명시한다.
