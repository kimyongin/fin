## 구현 기록 (2026-09-23)

아래는 시간순 중간 상태다. 뒤의 구 정책/규칙/thesis 퇴역 슬라이스가 앞선 임시 호환 문구를 대체한다. 현재 구조는 schema overview와 `docs/design/storage-release-readiness-20260923.md`를 따른다.

- 추가 물리 정리 슬라이스: 운영·로컬에서 비어 있는 구 보유 이유 5개 테이블과 전용 RPC/종료 트리거를 삭제하는 증분 migration을 작성했다. 비공개 보유 메모는 유지하고 오늘 점검 snapshot의 구 `holding_theses` 복사본을 제거했다. 신규/기존 MCP 세션에서 구 도구를 더는 호출할 수 없게 처리기·정의를 제거했다. 격리 DB 35개 파일/536개 assertion, MCP 계약, Chromium 34개 시나리오 통과. 일반 로컬/운영에는 미적용이다.
- 운영 규칙도 기존 `principles`의 `kind=operation`/workflow scope로 이미 매핑돼 있다. 별도 운영 규칙 테이블 3개 및 DB/MCP CRUD를 삭제하는 migration을 추가하고, 잔고 보정 가이드는 `list_principles`를 읽도록 전환했다. 역사적 활동 라벨은 유지한다. 격리 DB 35개 파일/525개 assertion, MCP 계약, Chromium 34개 시나리오 통과. 일반 로컬/운영 미적용.

- 로컬 증분 migration으로 단일 `principles` 테이블에 실제 과거 정책/운영 규칙과 현재 값을 복사했다. 기존 테이블은 아직 지우지 않았으며 원문 백업/대조가 필요하다.
- `app_list_principles`/`app_save_principle`의 소유자 격리·현재/날짜 조회·종료·동일 재시도·수정 행을 pgTAP 14건으로 검증했다. 현재 조회에 트랜잭션 시작 시각을 쓰면 방금 저장한 행이 보이지 않는 문제를 후속 migration에서 수정했다.
- 앱의 원칙 목록/편집과 MCP `list_principles`/`save_principle`, policy workflow guide를 연결했다. `npm test` 109건, build, 가이드 검사 통과. Deno가 현재 PATH에 없어서 edge typecheck 미실행. 전체 DB 테스트에는 기존 `price_sync_contract_test`의 `sync_runs` 누락, `todo_bundle_test`의 UUID fixture 오류가 남는다.
- 구 개인 정책·운영 규칙 도구/API와 전략 notes는 전환 기간 동안 살아 있다. 후속 작업은 보유 이유 비공개 메모 이관, 구 도구/화면 정리, 공유/실제 MCP 호출 검증, 운영 데이터 대조다. 이 기록은 #89 전체 완료를 의미하지 않는다.
- 격리 E2E baseline은 현재 앱 스키마보다 오래돼 전략 JSON 컬럼만 E2E 전용 증분 migration으로 보정했다. 격리 DB 530건, MCP 계약 검사, 새 원칙의 모바일 저장/수정/종료 2개 브라우저 테스트 통과. 이전 원칙/운영 규칙 UI를 가정한 두 테스트는 새 흐름으로 교체했다. 새 화면의 360/768/1024/1440px 수동 검토와 실제 ChatGPT 웹·모바일 호출은 미검증이다.
- 기존 점검 흐름과의 접점을 위해 `app_create_daily_context`의 저장 snapshot에 현행 `principles.items`를 추가했다. 구 `investment_policy` 키는 소비자 이전까지 남겨 둔다. 신규 원칙을 저장해도 이전 정책 카드/스냅샷이 자동 갱신된다고 주장하지 않는다.
- 보유 이유는 기존 공개 `note`에 합치면 친구에게 노출된다. 따라서 같은 instrument/holding 행의 `private_note`로 옮기고, 기존 공개 메모는 그대로 두었다. 현재 활성 thesis의 원문/기간/재검토 조건/날짜를 해당 행에 줄바꿈 문장으로 복사하며 구 행은 지우지 않았다. 일반 portfolio DTO 및 자동 활동 payload에서 중첩 private_note를 제거하고, 소유자 전용 조회·현재값 CAS 편집·점검 문맥 연결을 구현했다. pgTAP 13건에서 친구 공유/기존 공개 메모/금융 버전 불변을 검증했다. 보유가 없는 과거 이유와 링크는 #91 보관 전 대조가 필요하다.
- 격리 E2E 전체 34개 DB 파일 543건, MCP 계약(신규 원칙 도구 포함), 브라우저 33건 통과. 앱 자산 화면의 보유 이유 편집은 비공개 메모로 전환했지만 구 thesis API/테이블과 자동 점검 문맥의 구 복사본은 #91까지 남는다. 친구 공유와 계좌별 예외의 브라우저 수동 검수, 실제 ChatGPT 웹/모바일 평가는 미실시다.
- 새 MCP `tools/list`에서는 구 개인 기준·보유 이유·전용 연결 도구 5개를 숨겨 새 세션이 원칙·비공개 보유 메모만 발견하게 한다. 기존 세션의 호출 처리기는 이관 기간에만 남겨 둔다. 구 DB 쓰기 경로와 테이블이 종료됐다는 뜻은 아니다.

## 목적

사용자 기능에 필요한 최소 저장·처리만 유지한다. 구 투자 행의 이관은 사용자가 면제했고 새 개인 메모의 비공개 경계는 지킨다. 기존 구현의 존재는 유지 근거가 아니다.

## 인수 조건

- [x] 원칙은 같은 테이블에 변경마다 새 행을 저장한다. 각 행의 고유 ID와 별도로 같은 원칙을 묶는 원칙 ID, 사용자·종류·내용·적용 시작 시각·종료 여부 및 필요한 선택 적용 범위를 둔다. 별도 현재값/이력 테이블이나 버전 번호는 만들지 않는다.
- [x] 평소에는 사용자·원칙 ID별 최신 행을 조회하고 종료된 원칙을 제외한다. 과거 조회는 지정 시각 이하의 마지막 행을 원칙별로 선택한 후 종료 여부를 적용한다. 종료 행을 먼저 제외하여 이전 원칙이 되살아나지 않게 한다. 같은 종류의 여러 원칙이 모두 조회되어야 한다.
- [x] 수정은 새 내용 행, 삭제/종료는 같은 원칙 ID의 종료 행 추가로 처리한다. 기본 적용 시각은 서버 저장 시각이며 소급/예약 편집 UI는 만들지 않는다. 동일 시각에는 서버가 정한 안정적인 저장 순서로 최신값을 결정한다. 날짜 조회는 사용자 시간대 기준 해당 날짜 말까지 적용된 원칙을 반환한다.
- [x] 앱과 MCP에서 현재/특정 시점 원칙 조회를 제공하고 가이드에도 같은 의미를 설명한다. 변경 전/후·종료 전/후·생성 전·같은 종류 복수 원칙·같은 날 복수 변경·타인 접근을 검증한다. 원칙 조회 이력만 지원하며 과거 포트폴리오 복원은 만들지 않는다.

- [x] 보유 이유는 공유 `note`와 섞지 않고 같은 instrument/holding 행의 비공개 `private_note`에 둔다. 삭제 허용된 구 thesis 행의 읽기 보관은 요구하지 않고 새 메모의 계좌별 범위와 공개 메모 분리를 검증한다.
- [x] 보유 이유의 별도 history/task link/재활성화 수명과 전용 MCP 도구를 제거한다. 후속 점검은 공통 할 일로 등록한다.
- [x] 개인 목표·성향·상세 원칙·운영 규칙을 종류/적용 범위가 있는 공통 원칙으로 읽고 편집한다. 목표 비중/버킷/모드 계산은 기존 전략 구조를 유지한다.
- [x] 메모는 현재 행을 편집하고 원칙만 같은 테이블에 변경 후 내용 전체를 새 행으로 저장한다. 의무 변경 사유나 범용 revision 엔진은 만들지 않는다. 과거 분석에 이미 저장된 당시 기준은 소급 수정하지 않는다.
- [ ] 실제 ChatGPT 웹·모바일에서 원칙 인터뷰→OAuth MCP 저장→앱 조회를 사용자 계정으로 평가한다. 로컬 MCP 계약/앱 저장·조회와 비공개 메모 검증은 통과했으나 실제 ChatGPT 평가를 대신하지 않는다.
- [x] 원칙 변경의 자동 활동은 유용한 요약 한 건으로 제한하고 본문 이력을 별도 중복 저장하지 않는다. 가이드/스키마 인덱스를 갱신한다.

## 구현 방식

관련 DB/API·MCP/UI·가이드·검증을 수직 슬라이스로 연결하고 슬라이스마다 커밋한다. 일반 코드 구현/배포는 이 티켓 작성에 포함하지 않는다. 미정 세부 기술 선택은 위 범위 안에서 구현자가 근거를 기록해 확정한다. 제품 기능 축소 범위를 추가로 넓히면 먼저 영향과 대안을 명시한다.
