# [저장 단순화] 할 일과 반복 완료 흐름 단순화

상태: 설계 완료 · 구현 전 · 2026-09-23
GitHub: https://github.com/kimyongin/fin/issues/88
선행: 01; 02의 활동 계약
시나리오: S4/S9/S10
기준: docs/engineering/SIMPLICITY.md, docs/adr/0008-minimal-portfolio-storage.md, docs/design/minimal-portfolio.md

## 목적

사용자 기능에 필요한 최소 저장·처리만 유지하고 기존 데이터와 공개 범위를 보존한다. 기존 구현의 존재는 유지 근거가 아니다.

## 인수 조건

- [ ] 일반/조사/실행 할 일을 열린 일/완료 중심의 공통 계약으로 통일한다. 일시정지/재개와 research_state 전용 상태 엔진을 제거한다. 기존 paused/cancelled는 종료로 매핑하고 과거 상태 설명을 보존하되 실제 수행 완료로 집계하지 않는다. answered 결과는 활동으로 이관한다.
- [ ] 수량 기반 execution_plans/task_fill_links 자동 체결 진행률을 제거한다. 기존 목표/체결 참조는 읽기 가능한 내용으로 보존하며 할 일 완료가 매매를 실행하거나 잔고를 바꾸지 않는다.
- [ ] 할 일 완료 결과는 활동 한 건, 사후 활동도 같은 화면으로 제공한다. 후속 원인 활동과 수행 대상 할 일의 두 관계를 유지하되 범용 관계 엔진은 도입하지 않는다.
- [ ] 반복의 오늘 완료는 내일 다시 표시하고, 전체 종료(할 일 완료) 또는 삭제는 앞으로 표시하지 않는다. 필요하면 새로 등록하며 종료된 반복의 재개 기능은 만들지 않는다. 전체 종료가 수행하지 않은 회차의 완료 기록을 생성하지 않음을 검증한다.
- [ ] 오늘 완료 체크 해제·과거 회차 기록·중복 완료를 검증한다. 오늘 체크 해제와 반복 전체 종료를 구분한다. occurrence projection은 제거 비용이 더 크면 유지 사유를 적고 중복 정본을 피한다.
- [ ] 할 일 삭제는 기존 수행 기록을 연쇄 삭제하지 않는다. 활동만 삭제해도 할 일은 자동 재개되지 않는다. 삭제 이후에도 반복 완료 판정과 중복 방지가 모순되지 않도록 최소 회차 상태를 유지한다.
- [ ] 일반 제목/날짜 수정의 의무 이력과 변경 사유를 제거한다. 태그를 할 일 저장에 함께 처리해 추가 왕복을 줄이고 과거 완료의 태그 의미를 보존한다.
- [ ] 웹/MCP/가이드를 공통 할 일 흐름으로 갱신하고 같은 수행이 목록·리포트에서 한 번만 나타나는지 검증한다.

## 구현 방식

관련 DB/API·MCP/UI·가이드·검증을 수직 슬라이스로 연결하고 슬라이스마다 커밋한다. 일반 코드 구현/배포는 이 티켓 작성에 포함하지 않는다. 미정 세부 기술 선택은 위 범위 안에서 구현자가 근거를 기록해 확정한다. 제품 기능 축소 범위를 추가로 넓히면 먼저 영향과 대안을 명시한다.
