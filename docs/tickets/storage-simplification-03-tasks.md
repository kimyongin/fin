# [저장 단순화] 할 일과 반복 완료 흐름 단순화

상태: 일반 할 일·회차·활동 통합의 로컬 구현/회귀 검증 완료; 운영 배포 대기 · 2026-09-23
GitHub: https://github.com/kimyongin/fin/issues/88
선행: 01; 02의 활동 계약
시나리오: S4/S9/S10
기준: docs/engineering/SIMPLICITY.md, docs/adr/0008-minimal-portfolio-storage.md, docs/design/minimal-portfolio.md

## 목적

사용자 기능에 필요한 최소 저장·처리만 유지한다. 구 투자 행의 이관은 사용자가 면제했고 새 데이터의 접근 경계는 지킨다. 기존 구현의 존재는 유지 근거가 아니다.

## 인수 조건

- [x] 새 할 일은 일반 종류 한 가지이며, 일시정지/재개와 `research_state` 전용 엔진을 제거한다. 이전 paused 일반 할 일은 완료 사실로 집계하지 않고 종료하며, 삭제 허용된 구 조사/실행 행의 내용 이관은 요구하지 않는다.
- [x] 수량 기반 execution 계획/체결 연결 자동 진행률을 제거한다. 할 일 완료는 매매를 실행하거나 잔고를 바꾸지 않는다.
- [x] 할 일 완료 결과는 활동 한 건, 사후 활동도 같은 화면으로 제공한다. 후속 원인 활동과 수행 대상 할 일의 필요한 관계만 유지한다.
- [x] 반복의 오늘 완료는 내일 다시 표시하고, 전체 종료/삭제는 앞으로 표시하지 않는다. 필요하면 새로 등록하며 종료된 반복의 재개 기능은 만들지 않는다. 종료만으로 수행하지 않은 회차의 완료 기록을 만들지 않는다.
- [x] 오늘 완료 체크 해제·과거 회차·중복 완료를 검증한다. 회차 상태 테이블은 오늘/과거 완료 판정에 필요한 최소 projection이라 유지하고 별도 이력 정본으로 사용하지 않는다.
- [x] 할 일 종료/삭제는 기존 수행 활동을 연쇄 삭제하지 않고, 활동 정정/삭제로 할 일을 자동 재개하지 않는다.
- [x] 제목/날짜 수정의 의무 이력과 변경 사유를 제거한다. 태그는 실제로 지정할 때만 별도 공통 태그 API로 편집한다. 모든 할 일 저장에 태그 payload/두 번째 왕복을 강제하지 않으며 완료 당시 태그는 수행 활동에 복사한다.
- [x] 웹/MCP/가이드를 공통 할 일 흐름으로 갱신하고 같은 수행이 목록·리포트에서 한 번만 나타나는지 검증한다.

## 구현 방식

관련 DB/API·MCP/UI·가이드·검증을 수직 슬라이스로 연결하고 슬라이스마다 커밋한다. 일반 코드 구현/배포는 이 티켓 작성에 포함하지 않는다. 미정 세부 기술 선택은 위 범위 안에서 구현자가 근거를 기록해 확정한다. 제품 기능 축소 범위를 추가로 넓히면 먼저 영향과 대안을 명시한다.

## 진행 기록

아래는 시간순 중간 상태다. 이후 구 조사/실행 저장소·일반 할 일 revision·조사 상태 컬럼을 제거했다. 현재 구조는 schema overview와 `docs/design/storage-release-readiness-20260923.md`를 따른다. 운영/실사용은 별도다.

- 반복 할 일 상세에 두 단계 확인이 있는 `반복 종료`를 추가한다. 기존 서버 `cancel` 전이를 사용하되 사용자에게는 미래 회차 종료로 설명하며 이전 완료 활동을 유지한다. 앱은 일시정지/재개를 제공하지 않고 새 MCP 도구 스키마에서도 두 전이를 제거했다. 구 데이터/RPC의 상태 엔진과 이력은 아직 남아 있으므로 티켓 완료가 아니다.
- 기존 반복 테스트에 종료 후 추가 완료 활동·미래 회차가 생성되지 않는 검증을 추가했다. #88의 연구/실행 할 일 단순화, 변경 이력 제거, 삭제 계약은 후속이다.
- 서버 일반 할 일 RPC에서도 신규 pause/resume 호출을 거부하고, 이전 paused 일반 할 일은 기존 수행 기록을 보존한 채 종료 상태로 매핑한다. 사전 fixture가 있는 격리 E2E에서 수량·상태를 검증한다. 과거 paused 이력은 아직 삭제하지 않는다.
