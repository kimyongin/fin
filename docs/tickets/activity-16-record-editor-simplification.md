# [활동 UX] 기록 입력 간소화·종목 연결·검색형 할 일 선택

2026-09-24 · 로컬 수직 슬라이스 구현 중. 운영 배포 전.

GitHub: https://github.com/kimyongin/fin/issues/125

## 목적과 대체 범위

기록은 제목·날짜·내용을 적고 필요할 때 태그·종목·할 일을 연결하는 짧은 폼으로 만든다. 기록 추가와 상세 편집에 같은 구성을 적용한다. 종목 관련 기록을 남기기 위해 보유 계좌를 고르거나 긴 할 일 셀렉트를 뒤지는 단계를 없앤다.

#122의 계좌별 `holding_id` 연결을 종목 연결로 대체한다. #123의 직접 편집·태그 포함 단일 저장과 관련 할 일 인라인 읽기는 유지한다. 관련 할 일은 하나, 관련 종목도 하나이며 다대다 관계나 범용 대상 연결 엔진을 추가하지 않는다. 이번 티켓 작성은 구현·DB 전환을 의미하지 않는다.

## 확인한 현재 구현

- `ActivityReferences.jsx`는 할 일을 `app_list_general_task_page`로 100개씩 가져와 select에 쌓으며 제목 검색이 없다. 보유는 `app_find_holdings` 검색 입력과 별도 select 두 조작으로 선택한다.
- `ActivityDetailModal.jsx`는 관련 할 일 요약과 선택기를 따로 표시하고, 기존 태그 배지와 접힌 태그 편집 영역을 중복 제공한다.
- 현재 활동에는 `task_id`와 `holding_id`가 있으며 본문·태그·참조를 함께 저장한다. 참조 수정/삭제는 금융 상태나 할 일 완료 여부를 변경하지 않는다.

## 화면 계약

| 순서 | 내용 |
| --- | --- |
| 기본 입력 | 제목·기록 날짜·내용. 날짜 입력과 동일 날짜의 별도 메타데이터 반복을 줄임 |
| 태그 | 선택된 태그만 칩으로 표시하고 하나의 검색 입력에서 후보를 찾아 추가. 칩에서 해제하며 선택은 저장 전 초안 |
| 관련 종목 (선택) | 종목명·티커 검색 → 바로 아래 결과 선택 → 선택된 종목 칩과 연결 해제 |
| 관련 할 일 (선택) | 제목 검색 → 바로 아래 결과 선택 → 선택된 할 일 제목·일정·설명을 같은 자리에서 읽음 |
| 하단 | 상세는 삭제·닫기·저장, 신규는 닫기·저장 |

- 태그/연결 입력에 접기·펼치기나 추가 편집 모달을 두지 않는다. 검색 결과는 검색 중일 때만 표시하며, 선택한 대상은 같은 영역에 계속 보인다.
- 처음 열거나 검색어가 비어 있을 때는 선택된 태그/연결 요약과 짧은 검색 입력만 표시한다. 포커스만으로 전체 태그·종목·할 일 목록을 펼치지 않는다. 검색어를 지우면 후보와 이전 커서를 비우되 선택값은 유지한다. 선택/결과 닫기 후에도 선택된 대상은 보인다.
- 검색 입력과 별도 select를 없앤다. 선택 대상을 바꾸거나 연결을 해제해도 제목·본문·날짜·다른 선택값은 유지한다. 변경은 최종 저장 전까지 서버에 반영하지 않는다.
- 태그의 읽기 배지와 편집 UI를 중복 표시하지 않는다. 태그 사전 이름/삭제 관리까지 기록의 기본 폼에 펼쳐 놓지 않으며, 기존 사전 관리 기능의 위치와 접근 경로를 구현 시 대조한다. 태그 선택은 기록 저장과 함께 처리한다.
- 등록된 모든 태그를 체크박스 목록으로 펼쳐 놓는 기존 선택기를 그대로 사용하지 않는다. 태그명 입력으로 제한된 후보를 표시하며 이미 선택한 태그를 중복 추가하지 않는다. 새 태그 생성은 자동으로 하지 않고 기존 생성 기능의 명시적 동작으로 제공한다. 태그 사전 생성/이름 변경/삭제의 저장 시점과 기록에 태그를 연결하는 최종 저장을 구분해 구현 계약에 기록한다.
- 관련 할 일의 요약은 선택 영역 하나에서 표시한다. 완료 시 생성된 기록은 기존 할 일 연결을 자동 표시하므로 사용자가 다시 선택하지 않는다. 할 일을 연결해도 완료 상태는 바뀌지 않는다.
- 두 연결 모두 선택 사항이다. 연결 없이도 기록을 만들 수 있으며 관련 할 일/종목 조회 오류를 기록 본문의 오류나 연결 없음으로 오인하지 않는다. 조회 실패로 기존 연결을 지우지 않는다.
- 공유 읽기는 허용된 내용만 텍스트로 보여주며 편집 검색창을 표시하지 않는다. 작성 경로(앱/ChatGPT)는 필요한 보조 정보 한 줄로 유지할 수 있다.

## 검색 계약

- 태그는 기존 태그명 검색을 재사용한다. 태그·종목·할 일 모두 검색어 없는 최초 화면에서 후보 전체를 읽거나 표시하지 않는다. 선택된 항목의 요약 조회는 검색과 독립이다.
- 종목 검색은 사용자의 기존 종목을 이름·티커로 찾는다. 보유 계좌별로 중복된 후보를 만들지 않으며 보유가 없는 등록 종목도 선택할 수 있다. 이 검색에서 외부 종목을 자동 생성하지 않는다.
- 할 일은 제목을 서버에서 검색한다. 완료된 오래된 할 일도 검색 대상이며 현재 로드된 100개에만 검색을 적용하지 않는다. 동일 제목은 예정일·반복 여부·상태 등의 짧은 보조 정보로 구분한다.
- 결과 개수와 페이지 크기를 제한하고 검색 조건을 페이지 자르기 전에 적용한다. 더 많은 결과는 같은 검색 조건의 추가 조회로 가져온다. 전체 목록을 모두 읽어 select로 만드는 방식은 제거한다.
- 짧은 입력 지연과 요청 식별을 사용해 오래된 검색 응답이 최신 결과를 덮지 않게 한다. 검색어 변경 시 이전 커서/결과를 재사용하지 않는다.
- 검색 결과에 선택한 대상이 없더라도 기존 선택 요약을 유지한다. 로딩·결과 없음·조회 실패를 구분하고 재시도할 수 있다.
- 키보드 이동/Enter 선택/Escape 결과 닫기와 터치 선택을 지원한다. 검색 목록을 닫는 Escape가 곧바로 기록 모달 전체를 닫지 않게 한다. 선택/해제 버튼은 접근성 이름과 44px 조작 영역을 갖는다.
- 기존 조회/검색 API를 먼저 재사용한다. 부족한 검색 조건·페이지 조회만 목적별로 보완하고 범용 검색 프레임워크를 만들지 않는다.

## 종목 참조 전환과 의미

- 활동의 선택적 `instrument_id`를 사용자의 종목에 연결한다. `holding_id`를 영구적으로 함께 남기거나 account ID/숨은 플래그로 같은 분류를 재구성하지 않는다. 금융 RPC의 실행 대상인 holding ID까지 제거하는 요청은 아니다.
- 기존 활동의 유효한 `holding_id`를 해당 보유의 `instrument_id`로 전환한다. 기존 활동 ID·본문·날짜·태그·할 일 연결은 유지한다. 이미 삭제돼 대응 종목을 알 수 없는 연결은 임의로 추정하지 않고 null로 남기며 전환 건수를 확인한다.
- 자동 금융 기록은 해당 종목을 연결하고 당시 계좌명·변경 전후 값을 본문에 남긴다. 현재 보유값을 다시 읽어 과거 기록의 본문을 재작성하지 않는다. 비공개 메모는 본문에 복사하지 않는다.
- 여러 종목에 걸친 일괄 변경은 특정 종목 하나로 임의 연결하지 않는다. 기존 본문 내역을 유지하고 연결은 비워 둔다.
- 계좌별 보유 ID로 활동을 정확히 필터링하는 기능은 종료한다. 관련 검색/문맥/API 소비자를 종목 기준으로 함께 갱신한다. 계좌 정보는 기록 당시 본문으로 읽으며 본문 검색을 정확한 계좌 식별 필터라고 표현하지 않는다.
- 보유 삭제만으로 종목 연결은 끊기지 않는다. 종목 자체가 삭제되면 활동 본문은 보존하고 참조만 해제한다.
- 서버가 종목과 할 일의 존재·동일 소유자를 검증한다. 활동 공유 권한만으로 연결된 자산/할 일을 공개하지 않고 각 기능의 권한을 확인한다. 제목·ID·검색 후보·필터에서도 같은 경계를 적용한다.
- 참조는 탐색용이다. 연결 수정/해제·기록 삭제는 잔고, 반복 회차, 할 일 완료 상태나 금융 재시도 영수증을 변경하지 않는다.

## 구현 순서와 연계

1. 기존 활동 CRUD/상세 저장/검색/문맥·자동 금융 기록·MCP·가이드의 holding 참조 의존을 대조하고 최소 RPC/DTO와 이관 계약을 확정한다. 적용된 migration은 수정하지 않는다.
2. 종목 연결 전환을 DB→API/MCP→기록 추가/상세→검색·테스트까지 한 슬라이스로 연결한다. 기존 필드·태그의 원자 저장/재시도·충돌 검사를 유지한다.
3. 검색형 할 일 선택과 태그 표시/편집 통합을 기존 컴포넌트에서 구현한다. 필요하면 실제 두 소비자인 기록 추가/상세가 공유하는 최소 입력만 추출한다.
4. 도구 스키마/description·workflow guide에서 기록 대상은 종목, 금융 실행 대상은 계좌별 보유임을 구분한다. 오래된 `holding_id` 입력을 조용히 종목 ID로 해석하지 않으며 도구 갱신이 필요한 계약 변경으로 처리한다. 스키마 개요·문서·더미 데이터·배포 검사도 갱신한다.

#124 자산 상세 저장은 한 번당 활동 한 건을 만들고 새 종목 참조와 당시 변경 본문을 사용한다. 같은 종목의 여러 계좌 변경은 이 한 본문에 모으며 선택적 저장 사유도 포함한다. 별도 번들/다대다 관계를 추가하지 않는다. #125의 상세에서 이를 하나의 기록으로 읽고 편집하며 두 티켓이 별도 기록을 중복 생성하지 않는다. 구현 시 두 계좌 이상 변경→활동 한 건 조회→종목 연결 표시 흐름을 함께 검증한다.

## 완료 기준

- [ ] 기록 추가/상세에 동일한 간결한 폼을 제공하고 관련 보유 검색+select, 할 일 전체 select, 접힌 태그/중복 배지가 사라진다.
- [ ] 태그가 많아도 기본 화면에는 선택된 칩과 검색 입력만 보인다. 태그·종목·할 일은 빈 검색어에서 전체 후보를 펼치지 않으며 검색어 지우기/결과 닫기가 기존 선택을 지우지 않는다.
- [ ] 같은 종목을 여러 계좌에 보유해도 종목 후보는 하나다. 보유 없는 등록 종목·무연결 기록도 처리한다.
- [ ] 100개를 넘는 할 일에서 오래된 완료 항목·동명 항목을 서버 검색/추가 조회로 찾아 연결한다.
- [ ] 기존 선택 유지, 검색 오류·빈 결과·늦은 응답·선택 변경·해제·취소·저장 실패에서 초안을 보존한다.
- [ ] 내용·태그·참조가 한 번에 저장되고 재시도·충돌·타인 참조·부분 실패를 검증한다.
- [ ] 기존 보유 참조를 정확히 종목으로 옮기고 보유/종목 삭제 후 본문·할 일 상태·금융 데이터가 의도대로 유지된다.
- [ ] 자동 기록의 당시 계좌/변경값을 보존하고 공유·검색·MCP에서 권한 없는 관련 정보가 노출되지 않는다.
- [ ] #124에서 한 종목의 여러 계좌를 수정한 활동 한 건을 읽고 종목 연결·각 계좌의 변경값·사유를 확인한다. 수정/삭제가 실제 자산이나 할 일 상태를 바꾸지 않는다.
- [ ] 360/390/768/1024/1440px에서 긴 제목·다중 태그·검색 결과·선택 요약·키보드·footer를 검증하고 실기기 미검증을 구분한다.
- [ ] 관련 DB/API/MCP/웹 회귀·가이드·빌드·인코딩 검사를 수행하고 로컬 구현/운영 배포 여부를 기록한다.

## 구현 진행 기록 (2026-09-24)

- 기록 추가/상세에서 종목명·티커, 할 일 제목의 지연 서버 검색·제한 결과·추가 조회와 선택 요약을 제공한다. 태그는 선택 칩과 검색 입력으로 통합했다. 새 수동 기록/MCP 입력은 종목 참조를 사용하며 연결 편집은 금융값·할 일 상태를 바꾸지 않는다.
- 기존 유효한 보유 참조를 종목 참조로 backfill했다. 다만 구 `activity_events.holding_id`, 조회 DTO, 자동 금융 기록과 일부 문맥/검색 소비자는 남아 있어 전체 참조 퇴역은 미완료다. API 입력에서 구 ID를 종목 ID로 자동 해석하지 않는다.
- 새 검색 RPC는 소유자의 종목/할 일만 검색한다. 관련 pgTAP 및 Chromium E2E가 통과했고 MCP 스키마/워크플로 가이드의 신규 기록 설명을 갱신했다. 구 참조 전 경로 제거와 공유/실기기 회귀를 마치기 전까지 티켓을 완료로 표시하지 않는다.
