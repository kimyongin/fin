# [활동 검색] 한국어 제목·본문 검색 품질과 운영 오류 복구

상태: 로컬 구현·운영 DB/Edge 적용 · 웹 공개 검증 중 · 2026-09-27
GitHub: https://github.com/kimyongin/fin/issues/161
기준: [검색 설계](../design/activity-context-search.md). #83의 후속 구현이며 과거 완료 증거를 지우지 않는다.

## 목적·소비 시나리오

S1. `투자 이론` 태그에서 `심리`, `불안해서 팔고 싶다`처럼 원문과 다른 표현으로 관련 기록·할 일을 찾는다. 검색 기반은 이 시나리오의 웹·OAuth 결과로 바로 검증한다.

## 구현·완료 조건

- [ ] 운영 `query=심리` 내부 오류의 로그/재현 원인을 확인하고 최소 수정한다. 검색어 없는 정상 조회와 비교하되 런타임 원인을 추측으로 확정하지 않는다.
- [ ] 최소 12개 한국어 합성 질문의 기대 관련/무관 자료를 고정하고 모델·차원·길이/분할·실행 위치·비용·백필·커서 계약을 기록한다. 초기 `gte-small` 품질은 측정해 공개한다. 사용자가 검색 품질이 낮더라도 비용 없는 내장 모델부터 쓰기로 선택했으므로, 이전 80% 품질 게이트는 Cloudflare 등 다음 모델 평가 기준으로 넘긴다. 무관 질문으로 억지 결과를 채우지 않음은 유지한다.
- [ ] 기존 검색 RPC와 `_shared/activity-search.ts`를 보완해 할 일 제목/설명·기록 제목/본문을 함께 검색한다. 완료·중단 할 일도 찾고 상태를 구분한다. 도래 실행 큐는 유지한다.
- [ ] 긴 본문 후반부 검색·발췌와 원본별 중복 제거, 태그/종목/기간/권한 선필터, 일관된 페이지 이어보기를 구현한다. 모델/조건 변경 후 커서 재사용은 명확히 거절한다.
- [ ] 저장/수정 후 색인, 백필·실패 재시도·내용 해시와 모델 구분·삭제 즉시 제외를 최소 구조로 구현한다. 기본 저장은 검색 색인 실패와 분리한다.
- [ ] 웹/HTTP·OAuth 동일 계약과 불완전 검색 상태를 표시한다. 기본 탐색 최근 30일/미지정 검색 전체 기간 전환 및 명시적 기간 보존을 적용한다.
- [ ] 실제 모델의 품질, 첫/후속 요청 지연(p50/p95)·검색/색인 비용을 기록한다. 한국어 근거 누락·공유 권한·다른 소유자·오류 fallback·편집 후 재검색을 검증한다.
- [ ] schema OVERVIEW, MCP 설명/가이드/review manifest, 현재 검색 계약을 갱신하고 단위·DB·관련 E2E·Edge·encoding 검사를 통과한다. 운영 배포와 실제 ChatGPT 확인은 별도로 기록한다.

기존 데이터 정본은 보존한다. 검색 파생 색인의 전환·백필·복귀 절차를 준비하고 승인 범위에서 배포한다. 별도 도메인/영구 검색 세션/범용 큐는 선행 도입하지 않는다.

## 구현 조사 · 2026-09-27

- 운영 `activity-search`의 검색어 입력 실패를 로그에서 확인했다. 해당 요청은 HTTP 546이고 함수 로그는 `CPU Time exceeded`다. 같은 시각 `app_search_activities`와 `app_list_activity_embedding_jobs`, 여러 `app_upsert_activity_embedding` 호출이 성공했다. 검색 요청 안에서 최대 12건의 `gte-small` 임베딩을 병렬 생성한 경로가 CPU 한도를 넘었다. 개인 검색어/본문은 로그에 남기거나 티켓에 복제하지 않는다.
- 서버 검색 경로에서 요청 중 문서 임베딩을 제거했다. 검색어 임베딩은 별도 Edge 호출로 분리하고, 호출 실패 시 키워드 결과와 `semantic_status=unavailable`을 반환한다. 이 조치는 한국어 의미 검색의 품질 완료가 아니다. 운영 배포 전까지 기존 운영 오류는 남아 있다.
- Supabase 공식 문서상 내장 임베딩 모델은 `gte-small`뿐이다. `pgvector`는 임베딩 보관·비교용이고 한국어 문장을 벡터로 생성하지 않는다. Edge CPU 2초/메모리 256MB 제약에서 대형 다국어 모델을 함수 안에 올리는 방안은 현재 선택하지 않는다.
- 사용자는 별도 과금/외부 전송 없이 `gte-small`을 초기 모델로 사용하고, Cloudflare 연동은 추후 결정하기로 했다. 모델 호출은 한 모듈에 두되 1024차원 등 다른 제공자로 바꿀 때는 벡터 컬럼/인덱스와 백필 migration이 필요함을 기록한다.

## 구현 기록 · 로컬 2026-09-27

- 운영 오류는 `POST activity-search`의 HTTP 546과 `CPU Time exceeded`로 확인했다. 검색 중 최근 미색인 기록 12건을 병렬 계산하는 흐름을 제거했다.
- `20260927095839_activity_search_async_index.sql`은 활동·할 일 저장/수정 시 400자 청크를 전용 pgmq 큐에 넣는다. cron/pg_net은 Vault URL·서비스 키가 설정된 환경에서 최대 3개를 10초마다 각 별도 Edge 호출로 보낸다. 120초 가시성 제한으로 유실된 호출을 다시 시도하고 5회 넘은 메시지는 보관한다. 편집은 구 벡터를 즉시 무효화하며 삭제는 파생 벡터를 지운다. 기존 행 백필도 같은 큐에 넣는다.
- `activity-search-index`는 서비스 역할만 호출하고 현재 내용 해시를 다시 확인한다. `activity-search`는 문서를 색인하지 않고 별도 호출로 검색어 벡터 하나만 만든다. 실패하면 같은 ranked RPC를 벡터 없이 호출해 단어 결과를 제공한다. 검색어/범위/태그/종목/상태/모드별 fingerprint가 다른 커서는 거절한다. 완료·중단 할 일도 검색할 수 있다.
- 실제 로컬 Edge `gte-small`이 384차원 벡터를 반환했고 pgmq 메시지 한 건을 처리해 벡터 저장/ack를 확인했다. 로컬 Vault를 설정한 뒤 자동 처리도 확인했다(중간 관측: 벡터 115건, 남은 큐 57건, 보관 0건). 운영 Vault/Edge/DB에는 적용하지 않았다.
- `scripts/evaluate-search-embedding.mjs`의 합성 질문 12개에서 기대 문서 상위 5개 적중은 9/12였다. 무관 질문 3개도 최고 유사도 0.935~0.945를 받아 모델 구별력이 낮다. 잘못된 자료를 대량 노출하지 않도록 초기 임계값 0.96을 적용하니 합성 12문항의 의미 검색 단독 적중은 0/12다. 정확/부분 단어 검색은 계속 제공하지만 한국어 유사 표현 검색의 실효 품질은 아직 미달이다. Cloudflare 전환 전 이 한계를 화면/MCP에 명시한다.
- 신규 DB pgtap 17개와 전체 DB 742개, 검색 단위 5개, 타입 검사, 웹 build, 격리 브라우저의 45일 전 기록 검색이 통과했다. 브라우저 360/390/768/1024/1440px에서 결과 표시와 가로 넘침 없음도 확인했다. 실 ChatGPT 웹·모바일과 운영 지연/비용·공유 화면 검증은 남았다.

## 운영 적용 · 2026-09-27

- 프로젝트 `ubmtflglqudrvumepzij`에 색인 Edge를 먼저 배포하고 `20260927095839` migration을 적용했다. 원본 활동 171건과 할 일 1건은 수정하지 않았다. Vault URL/키를 설정한 후 내부 호출의 401을 발견해 웹 공개는 보류했다.
- 운영 Edge 기본 환경 키와 호출 키가 다른 상태를 명시적 `ACTIVITY_SEARCH_WORKER_KEY` 비밀과 `apikey` 단일 헤더로 바로잡았다. 보정 migration `20260927114341`을 적용한 뒤 운영 색인 함수의 합성 쿼리에서 `gte-small` 384차원 HTTP 200을 확인했다. 대기열 62→47, 벡터 0→15, 보관 0으로 실제 색인 진행을 확인했다.
- `activity-search`와 `portfolio-mcp-oauth`를 새 코드로 배포했다. 사용자 인증 HTTP/OAuth 검색과 Pages CI 검증·공개 결과는 후속 기록으로 남긴다. `gte-small`의 한국어 의미 품질 제한은 배포 후에도 유효하다.
