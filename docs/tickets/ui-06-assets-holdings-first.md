# [UI/UX] 자산을 보유 확인·잔고 수정 중심으로 단순화

2026-09-23 · P2 · 로컬 UI 구현, 운영 배포 전.

## 목적과 이전 작업의 문제

자산을 열면 무엇을 얼마나 보유하는지 바로 확인하고, 증권사와 다른 수량·평균가를 쉽게 고친다. 전체 배분 판단과 대량 입력은 필요할 때 진입한다. 사용자가 보기 방식을 먼저 선택하거나 여러 상단 버튼의 의미를 해석할 필요가 없게 한다.

#112는 관련 기능을 자산으로 옮겼지만 네 보기 탭과 목표 비교·갱신·더보기·CSV를 한 도구줄에 모아 복잡해졌다. 이 티켓은 그 배치를 대체한다. 사용자는 기존 기능 자체의 보존을 요구하지 않으며 필요성이 낮으면 제거할 수 있다고 승인했다. 실제 보유 데이터 삭제나 접근 권한 확대를 뜻하지 않는다.

## 화면별 목적과 기능

| 화면 | 목적 | 필요한 기능 |
| --- | --- | --- |
| 자산 기본 화면 | 현재 보유 확인·실제 잔고와 비교 | 평가금액, 시세/평가 상태, 간단한 구성 요약, 종목별 보유 목록, 계좌 선택, 종목 검색, 가격 갱신 |
| 종목 상세 | 계좌별 보유 확인·수정 | 계좌별 수량·평균가·현재가·메모, 해당 보유 편집 진입 |
| 배분 상세 | 어디에 얼마나 몰렸고 목표와 얼마나 다른지 판단 | 전체 계좌의 현재 구성, 목표/현재/차이, 목표 설정, 태그 관리 |
| 표 편집 | 엑셀·대량 데이터 입력/수정 | 붙여넣기, 행 편집, 필요한 필터, 저장/취소, CSV 복사 |
| 원칙 | 서술형 투자 기준·운영 규칙 관리 | 독립 하단 탭과 과거 원칙 조회 유지 |

## To-Be 화면 계약

주 메뉴 오늘/자산/활동/원칙은 유지한다. 자산 내부에 보유/배분 탭이나 종목별/계좌별 묶기 선택을 추가하지 않는다.

```text
자산
  전체 평가금액                         가격 갱신
  시세·평가 상태 / 간단한 구성 요약       배분 보기

  [전체 계좌 ▾] [종목 검색]
                                추가 ▾ · 표 편집
  보유 종목 목록                  ├ 보유 추가
                                 └ 계좌 추가

  종목 선택 → 계좌별 보유 상세·수정
  배분 보기 → 전체 구성·목표 비교·배분 설정·태그 관리
  표 편집 → 일괄 편집·CSV 복사·저장/취소
```

- 기본값은 전체 계좌. 같은 종목은 계좌들을 합산한다. 기존 계산/표시 유틸리티를 재사용하며 단순 산술평균으로 평균가를 합치지 않는다. 시장형·평가형·현금성에 적절한 필드와 단위를 표시한다.
- 목록은 이름·수량·평균가·평가금액 중심, 상세에는 현재가·계좌별 값·메모를 둔다. 한 종목을 여러 계좌에서 보유하면 계좌 수를 표시한다. 모바일에서 글자를 축소하거나 수평 스크롤로 해결하지 않는다. PC에서는 같은 정보를 열로 정렬한다.
- 특정 계좌를 선택하면 목록·평가금액·간단한 구성 요약은 해당 계좌 기준으로 바뀌고 제목에 계좌 이름을 표시한다. 종목 검색은 목록만 좁히며 계좌 평가금액의 분모를 바꾸지 않는다.
- 특정 계좌의 종목을 누르면 그 계좌 보유의 상세/수정에 바로 도달한다. 전체 계좌에서는 상세의 계좌별 행에서 수정한다. 상세를 닫으면 검색·계좌·스크롤을 보존한다.
- 계좌 선택란에는 보유가 없는 계좌도 포함한다. 선택한 계좌 이름 옆에서 계좌 수정에 진입한다. 추가 메뉴는 보기 전환 없이 보유 추가/계좌 추가를 제공한다. 빈 포트폴리오는 계좌 만들기 → 보유 추가로 안내한다.
- 배분 상세는 항상 전체 계좌 기준이며 범위를 명시한다. 자산에서 선택했던 계좌가 전체 배분의 분모를 바꾸지 않는다. 돌아오면 기존 계좌/검색을 복원한다.
- 태그별 현재 구성과 목표 버킷은 같은 분류로 가장하지 않는다. 목표가 없어도 현재 비중을 보여주고 목표 설정을 보조 행동으로 제공한다. 태그 관리는 배분 상세에서 직접 노출한다.
- 가격 갱신과 결과는 평가금액 영역 가까이에 배치한다. 시세 기준일과 갱신 요청 시각을 구분하며 누락 시세·환율을 실제 0이나 최신 값처럼 표시하지 않는다.
- 표 편집은 보유 목록의 버튼으로 전체 화면 모달을 즉시 연다. 별도 표 편집 페이지·두 번째 확대 버튼은 두지 않고 닫으면 자산의 계좌/검색/스크롤을 그대로 보여준다. 첫 화면의 보기 탭이나 공통 도구줄에 CSV를 두지 않는다. CSV는 기존 저장된 자산 기준을 유지하고 `저장된 자산 CSV 복사`로 표시하여 미저장 초안/필터 결과의 복사로 오해하지 않게 한다. 편집 중 이탈의 초안 보호를 확인한다.

## 제거·재사용·검토 범위

- 제거: 태그 기준/계좌 기준/종목 기준/표 편집 네 탭, 기본 화면의 상시 태그 필터, 항목 하나뿐인 더보기, 공통 CSV 버튼. 해당 화면만을 위한 불필요한 상태/분기도 함께 정리한다.
- 재사용: 기존 자산 계산, 계좌/보유 편집, 모달·드로어, 표 편집, 배분 계산. 기존 구현 자체를 이유로 중복 화면을 남기지 않는다.
- 배분 설정의 운용 모드·모드 조정폭·거래 한도 등은 실제 계산 소비자·사용자 시나리오·MCP 의존성을 먼저 대조한다. 이 티켓에서 일괄 삭제를 확정하지 않는다. 구현 첫 단계에 유지/축소 근거를 기록하고, 별도 데이터/API 변경이 필요하면 구체적인 후속 범위를 명시한다. 핵심 보유 화면 개선을 이 검토 때문에 지연시키지 않는다.
- 계좌/종목 메모, 매매 기록, 현재값 보정·확인 등 기존 편집 행동의 필요성을 점검하고 상세에 필요한 진입점을 둔다. 제거하는 행동이 있으면 티켓에 이유를 기록한다. 금융 저장·사용자 격리 계약은 유지한다.
- #overview/#instruments/#accounts/#sheet/#allocation 기존 URL의 목적지를 명시한다. 현재 선택 계좌가 없는 #accounts 링크는 기본 자산 화면으로 연결한다. 공유 자산/전략의 독립 권한을 확인하고 공유 전략만 허용된 경우도 도달 가능하게 한다. 원칙 탭으로 자산 기능을 다시 넣어 해결하지 않는다.
- 새 테이블·범용 설정 엔진·중복 API를 추가하지 않는다. 명칭/경로가 바뀌는 사용자 안내와 해당 MCP 가이드가 있다면 함께 갱신한다.

## 구현 순서

1. 실제 React 컴포넌트와 기존 데이터 형태로 390px/1440px 화면 구성과 주요 상호작용을 확인한다. 기존 코드의 유지/삭제 목록, 계산 범위, 배분 설정 검토 결과를 이 티켓에 기록한다. 별도의 방대한 시안 체계를 만들지 않는다.
2. 자산 기본 목록 → 계좌 선택 → 보유 상세/수정 → 재조회 슬라이스를 완성한다. 계좌/보유 추가와 빈 상태를 연결한다.
3. 배분 상세·태그 관리·표 편집/CSV를 연결하고 네 보기 탭과 사용되지 않는 화면 분기를 정리한다.
4. 사용자 흐름을 검증하고 문서·가이드·티켓을 실제 상태로 갱신한다. 슬라이스별 커밋, 운영 배포는 별도다.

## 구현 판단과 범위

- 기존 `usePortfolioDerivedData`의 종목별 통합 수량·원가 가중 평균가를 전체 계좌 목록에 재사용했다. 특정 계좌는 계산된 단일 보유 행으로 표시하며 검색은 목록만 좁힌다. 평가액은 선택 계좌의 모든 보유로 계산하고 누락/오래된 가격을 별도로 알린다.
- 종목 상세에는 선택 범위의 계좌별 보유와 수정·잔고 보정·매매 기록·비공개 보유 메모를 연결했다. 상세는 공통 `ModalShell`을 사용하여 목록 계좌/검색/스크롤을 유지한다. 빈 계좌도 선택하고 계좌 수정·보유 추가에 도달할 수 있다.
- 네 보기 탭, 태그 필터, 한 항목 더보기, 공통 CSV, 해당 필터용 파생 카드/상태를 제거했다. 계좌/보유/종목 입력, 태그 관리, 가격 갱신, 거래·보정, 표 저장은 기존 API/권한을 재사용한다. 새 DB 테이블·MCP 도구는 없다. 제품 MCP 가이드에 더 이상 유효하지 않은 네 탭 안내는 없어 MCP 설명 변경이 필요하지 않았다.
- 배분 상세의 분모는 선택 계좌와 무관한 전체 계좌로 고정했다. 태그별 현재 구성과 목표 버킷을 별개 섹션으로 구분한다. 자산만 공유된 경우 목표 전략 RPC를 호출하지 않고 현재 구성만 표시한다. 전략만 공유된 사용자의 기존 원칙/전략 읽기 경로는 그대로 둔다.
- 표 편집은 기존 붙여넣기/저장/롤백을 사용한다. CSV는 모달 안에서만 저장된 자산 전체를 복사한다. 편집 중 닫기·새로고침에서 변경 폐기 확인을 요청한다.
- 배분 설정 대조: `mode_targets`, `drift_threshold`, `monthly_contribution`, 거래 한도와 적립금 보정 기간은 `calculateStrategyDashboard`가 사용한다. `mode_change_max_percentage`는 화면 편집/표시 외 실제 계산 소비자가 없어 이번 UI에서 숨겼다. 저장된 값은 이 티켓에서 삭제하거나 변환하지 않았다. 서버 저장 계약 제거는 별도 판단이 필요하다.
- 기존 링크 `#accounts/#instruments/#tags/#sheet`는 기본 자산으로, `#allocation`은 배분 상세로 연결한다. 표 편집은 URL을 바꾸지 않고 자산 위에서 바로 연다. 설계 전용 별도 시안은 만들지 않았고 실제 React 화면과 E2E viewport로 확인한다.

- [x] 배분 설정 없음/있음, 미분류/미연결 자산, 누락 가격·환율을 표시하고 태그 관리에 직접 진입한다.

## 후속 변경: 표 편집 직접 열기

사용자 사용성 검토에 따라 보유 목록의 `표 편집` 버튼은 URL/화면을 바꾸지 않고 전체 화면 모달을 바로 연다. 기존 인라인 표 편집 페이지와 두 번째 전체 화면 확대 버튼을 제거했다. 닫기는 원래 계좌 선택·검색·스크롤을 보존하고, 초안이 있으면 공통 모달의 변경 폐기 확인을 거친다. CSV 복사·필터·붙여넣기·롤백·저장은 모달 안에 유지한다. 과거 `#sheet` 링크는 기본 자산으로 이동한다. DB/API/MCP 계약은 바뀌지 않았다.

후속 검증: 빌드와 UTF-8/LF 검사, Vitest 105개, 격리 DB 510개, MCP 준비도, Chromium 자산/탐색 E2E 18개, 360/390/768/1024/1440px 가로 넘침, `git diff --check` 통과. 실제 기기/가상 키보드/운영 배포는 검증하지 않았다.

## 현재 상태

코드와 관련 문서를 로컬에서 변경했다. DB/API 변경과 운영 배포는 하지 않았다. #112의 기존 구현/검증 이력은 보존하고 상충하는 네 보기 유지·공통 도구줄 배치 조건은 이 티켓으로 대체한다.

검증: Vitest 105개, 격리 DB 510개, MCP 계약/배포 준비도, Chromium E2E 전역 57개, 프로덕션 빌드, UTF-8/LF, `git diff --check`를 수행한다. 360/390/768/1024/1440px 자동 검사에서는 보유 목록·상세·배분·표 편집의 페이지 가로 넘침이 없었다. 다계좌 가중 평균가, 계좌/검색 유지, 누락 시세, CSV 범위, 태그/원칙 분리, 과거 URL을 검사했다. 실제 모바일 브라우저·가상 키보드·스크린리더와 운영 공유 정책의 모든 조합은 별도 사용자 검증 대상이다.
