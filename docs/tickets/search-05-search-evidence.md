# [활동 검색] 실제 검색 방식·폴백 사유·결과별 검색 근거 표시

상태: 로컬 구현·격리 검증 완료 · 운영 배포 및 실제 ChatGPT 검증 전 · 2026-09-27
GitHub: https://github.com/kimyongin/fin/issues/165
선행: [#161](./search-01-korean-hybrid.md)의 배포된 비동기 색인·혼합 검색. [검색 정본](../design/activity-context-search.md)의 후속 표시 계약이다.

## 목적과 현재 문제

S5. 사용자와 에이전트가 검색 결과를 해석할 때, 유사도 검색이 실제 실행됐는지, 단어 검색으로 대체됐는지, 각각의 항목은 왜 검색됐는지 확인한다. 검색 결과가 없다는 이유만으로 관련 자료 자체가 없다고 단정하지 않는다.

- 현재 `semantic_status=active` 문구는 유사도 경로 실행을 나타낼 뿐, 개별 결과가 유사도 조건을 만족했다는 증거가 아니다.
- ranked RPC는 `semantic_score`를 반환하지만 웹은 표시하지 않는다. 단어 일치 결과에도 임계값 미만 점수가 있을 수 있어 점수 존재만으로 유사도 일치를 추정하면 안 된다.
- 서버 임베딩 실패와 웹 Edge 호출 실패 후 직접 RPC 대체 경로가 있고 현재 사유 표시는 없다.
- 현재 단어 검색은 대소문자를 구분하지 않는 입력 문자열 포함 검색이다. UI에서는 구현 세부인 LIKE 대신 `단어 포함 검색`이라고 표현한다. 오타·동의어 검색을 수행한다고 설명하지 않는다.

## 최소 응답 계약 — 웹 HTTP와 OAuth MCP 공통

기존 응답에 아래 정보를 추가한다. 새 테이블, 영구 검색 세션, 검색 로그 저장소는 만들지 않는다. 기존 `semantic_status` 등은 호환성을 유지한다.

| 정보 | 계약 |
| --- | --- |
| `search_mode` | `browse` / `keyword` / `hybrid`. 요청한 모드가 아니라 실제 결과 산출 모드 |
| `fallback_reason` | 대체 없이 성공하면 null. `embedding_timeout`, `embedding_unavailable`, `search_service_unavailable`로 확인 가능한 실패만 구분. 원인 불명은 unavailable로 처리하고 CPU/한도/인증 오류라고 추측하지 않음 |
| `embedding_model`, `semantic_threshold` | 실제 사용한 모델과 검색 채택 임계값. 화면 상수를 복제하지 않고 서버 기준을 반환. 벡터 미사용 시 null |
| `index_status` | `complete` / `partial` / `unknown` / `not_checked`. 색인 상태 조회 실패를 색인 대기라고 단정하지 않음 |
| 항목별 `matched_by` | 직접 결과에 `keyword`, `semantic` 중 실제 조건을 만족한 값만 배열로 반환. 양쪽 일치면 둘 다 포함 |
| 항목별 `semantic_score` | 검색어와 현재 원본의 유효 청크 중 최고 코사인 유사도 원값. 미계산은 null이며 0과 구분. 단어 일치 결과에 낮은 점수가 있어도 semantic 근거를 붙이지 않음 |

- 개별 검색 근거는 DB의 실제 채택 조건에서 산출한다. 잘린 발췌·프런트 본문 검사·점수 유무로 추정하지 않는다. 판정은 반올림 전 값으로 한다.
- 정렬용 혼합 rank와 코사인 유사도는 별개다. rank를 유사도 점수로 노출하거나 점수순으로 새 정렬하지 않는다.
- 웹의 직접 RPC fallback도 같은 메타데이터 형태로 정규화한다. 검색어 없는 탐색은 browse이며 유사도 실패 안내를 표시하지 않는다.
- 권한 없는 원본·개수·색인 정보를 새로 노출하지 않는다. pending 개수를 사용할 경우 그 범위를 표시한다. 검색 조건 전체의 색인율을 증명할 수 없으면 `일부 자료가 색인 대기 중입니다`만 표시하고 비율/검색 결과 건수로 오인하게 하지 않는다.
- 다음 페이지는 첫 페이지의 모드와 순서를 유지한다. hybrid 후속 요청 실패를 keyword 결과에 조용히 이어 붙이지 않고 재시도/새 검색을 안내한다. keyword 커서라 임베딩 호출을 건너뛴 경우 새로운 실패가 발생했다고 표시하지 않는다. 기존 검색의 대체 사유는 웹 상태에 유지하며, API만으로 최초 사유를 복원할 수 없으면 추정하지 않는다.
- 향후 #162의 연결 맥락 항목은 직접 일치와 별개다. 부모의 검색 근거나 점수를 자식에 복사하지 않는다. 이번 작업에서 연결 확장 자체를 구현하지 않는다.

## 화면 표현

검색 결과 제목 아래 기존 경고 문구를 실제 상태에 따른 짧은 설명으로 교체한다. 별도 진단 모달이나 접기 메뉴는 만들지 않는다.

- 정상: `단어 포함 검색 + 유사도 검색 · gte-small`
- 폴백: `단어 포함 검색만 사용 · 유사도 검색 응답 시간 초과` 또는 확인된 사유에 맞는 설명. Edge 전체 실패는 `검색 서비스에 연결하지 못해 단어 포함 검색으로 전환했습니다.`
- 부분 색인: `일부 자료가 색인 대기 중이며, 해당 자료는 단어 포함 검색만 적용됩니다.` 상태 확인 실패는 `색인 준비 상태를 확인하지 못했습니다.`
- 혼합 검색이 실행돼도 유사도 조건을 만족한 직접 결과가 없으면 `현재 표시된 결과는 모두 단어 일치로 찾았습니다.`로 구분한다. 빈 결과에서는 이 문구를 쓰지 않는다. 페이지 결과를 전체 검색 통계로 표현하지 않는다.
- `gte-small`의 한국어 한계는 `한국어의 비슷한 표현은 놓칠 수 있습니다.`로 짧게 유지한다. 실행 성공을 품질 보장으로 표현하지 않는다.

각 결과의 제목/발췌 아래 메타 줄에 `단어 일치`, `유사도 일치 · 유사도 0.972`, `단어·유사도 일치 · 유사도 0.981`처럼 표시한다. 숫자는 예시다. 단어 일치만 있어도 계산된 점수는 `단어 일치 · 유사도 0.912 (기준 미달)`처럼 표시할 수 있게 한다. 미계산이면 숫자를 만들지 않는다.

점수는 소수 셋째 자리로 표시하되 판정은 원값 기준이다. 검색 결과 영역에 한 번만 `유사도는 정확도나 확률이 아닌 비교 점수입니다. 유사도 검색 기준: …`를 제공한다. 반올림 때문에 임계값과 같아 보이는 미달 항목도 `기준 미달` 의미를 유지한다. 모델이 다른 검색 간 점수를 직접 비교하지 않는다.

기존 `secondary` 역할은 검색 방식/실패 설명, `meta`는 항목 근거/점수에 사용하며 숫자 자리 정렬을 유지한다. 색상만으로 구분하거나 자유 태그처럼 선택 가능한 칩으로 만들지 않는다. 점수 때문에 본문이나 기존 상세 진입을 숨기지 않는다. 긴 문구는 줄바꿈한다.

## 구현 순서와 비범위

1. 기존 ranked RPC·공통 검색 함수·웹 fallback의 성공/실패/커서 경로에 최소 메타데이터를 연결한다. 적용된 migration은 수정하지 않는다.
2. 같은 응답을 웹 결과 표시와 MCP `search_activities`에 연결한다. MCP 설명·workflow guide에는 fallback/부분 색인 결과의 한계, 점수를 정확도라고 해석하지 않는 규칙을 반영한다.
3. DB → HTTP/OAuth → 웹의 실제 흐름에서 검증하고 계약·티켓에 증거를 기록한다.

모델 변경, 임계값/정렬 조정, 검색 품질 개선, 자동완성, 연결 확장, 별도 운영 대시보드는 범위 밖이다. #161의 한국어 품질 미완료를 이 표시 작업으로 닫지 않는다.

## 인수·검증 기준

- [ ] 단어만/유사도만/양쪽 일치, 임계값 미만·경계·null 점수에서 서버 판정과 표시가 일치한다. 점수 반올림은 판정을 바꾸지 않는다.
- [ ] 유사도 실행 성공이지만 유사도 채택 결과가 없는 경우, 결과 0건, 검색어 없는 태그/기간 탐색을 구분한다.
- [ ] 임베딩 timeout/실패, Edge 전체 실패 후 웹 fallback, 색인 대기/상태 조회 실패를 각각 검증한다. 내부 오류 문자열·키·개인 본문을 진단 정보로 노출하지 않는다.
- [ ] 첫/다음 페이지, keyword fallback 유지, hybrid 후속 실패, 재검색 및 늦은 응답에서 모드·사유·결과가 뒤섞이지 않는다.
- [ ] 동일 합성 데이터/질문의 웹 HTTP·OAuth MCP에서 근거·점수·검색 모드가 일치한다. 직접 RPC fallback은 keyword이며 점수는 null이다.
- [ ] 본인/친구/접근 불가 데이터의 기존 경계, 수정·삭제한 원본의 유효 색인 사용을 회귀 검증한다.
- [ ] 360/390/768/1024/1440px, 200% 확대에서 긴 사유·점수가 넘치지 않고 필터 후 상세 왕복을 보존한다. 실제 확인 폭·상태·미검증 항목을 기록한다.
- [ ] 단위·관련 DB/E2E·Edge 타입·encoding·workflow guide 검사와 실제 모델 경로 smoke를 기록한다. 강제 실패 fixture는 fallback을 검증하지만 실제 모델 품질 증거로 취급하지 않는다.
- [ ] 구현/커밋/푸시/운영 배포/실제 ChatGPT 확인을 분리 기록한다.

## 로컬 구현·검증 · 2026-09-27

- 신규 `20260927121702_activity_search_evidence.sql`에서 기존 ranked RPC 응답에 `search_mode`, `semantic_threshold` 및 결과별 `matched_by`를 추가했다. 기존 검색 임계값·정렬·필터·권한·커서의 판정식은 유지했다. 적용된 migration을 수정하지 않았고 원본 저장 데이터도 바꾸지 않았다.
- 공통 Edge/MCP 검색은 실제 실행 모드, 확인된 timeout/실패, 색인 확인 상태를 반환한다. 후속 hybrid 요청 실패는 내부 오류를 드러내지 않고 재시도를 안내하며 결과 모드를 바꾸지 않는다. 웹 직접 RPC fallback의 항목은 단어 일치로 정규화한다.
- 활동 화면은 검색 경로·부분 색인/알 수 없는 상태·결과별 일치 근거와 점수를 표시한다. 점수는 3자리로 읽되 서버 원값이 임계값을 결정한다. MCP 도구 설명·작업 가이드와 API 계약·스키마 색인을 갱신했다.
- `npm test` 25파일/127건, 웹 build/encoding, Edge Deno 타입 검사, workflow guide 검사 통과. `npm run test:e2e -- e2e/activity.spec.js`는 격리 `.e2e` DB를 초기화하여 DB SQL 전체, OAuth MCP 계약·인증된 readiness 및 활동 브라우저 25건을 통과했다. 바뀐 경계값 UI 사례를 추가한 뒤 동일 격리 DB/MCP 검사와 해당 브라우저 1건을 재통과했다.
- 브라우저에서 360/390/768/1024/1440px의 정상 혼합 검색·부분 색인·점수 및 단어 폴백·임계값 미달 문구와 가로 넘침 없음을 확인했다. 실제 사용자·친구 데이터, 200% 확대, ChatGPT 웹/모바일, 운영 배포는 확인하지 않았다.
