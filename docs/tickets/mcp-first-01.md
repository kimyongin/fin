# [MCP-first] 제품 계약·잔고 계산 규칙과 사용자 시나리오 확정

## 현행 앱을 기준으로 한 재구성 계약
- 공통 기준: [제품 재정리](../design/product-reorganization.md). 기존 기능을 무조건 보존하거나 전면 재개발하지 않고 유지/재구성/신규/보조 이동을 구분한다.
- 태그·계좌·종목·표 편집은 유지하고, 전략은 원칙·운용 계획과 배분 점검으로 분리한다. 뉴스는 근거 자료, 활동 기록은 감사 내역으로 재배치한다.
- 종목 태그와 여러 태그를 묶는 전략 버킷을 구분한다. 현재/목표 비중의 분모와 미분류·버킷 미연결 자산 정책을 명시한다.
- 시세 미확인 시 평균가 대체와 환율 누락 시 0 처리의 현재 동작을 조사하고, 품질 상태 및 계산 제외/분모 정책을 확정한다. 미확인을 실제 0으로 표현하지 않는다.
- 초기/대량 등록, 보정, 실제 매매, 값 없는 확인의 사용자 동작과 저장 의미를 각각 정의한다.
- [ ] 기존 구현 근거·유지 기능·의도적 변경·범위 밖·데이터/권한 영향·인수 조건 대응표를 확정한다.
- [ ] 기존 공유 원칙과 새 개인 기준의 공개 범위를 #43과 합의하고 기존 URL 이동 정책을 #36에 전달한다.

## 공통 제품 모델: 투자 원칙·판단·할 일
- PRD/ADR/Ticket은 개발 시 비유로 사용한다. 앱의 사용자 용어는 “투자 원칙·운용 계획”, “판단 기록”, “할 일”로 통일한다.
- 투자 원칙은 목적/성향/배분/실행 제한의 기준, 판단 기록은 상황/선택지/근거/결정/재검토 조건, 할 일은 조사·점검 또는 실행 단위이다.
- 실제 체결과 잔고는 별도 원장으로 관리한다. 계획·제안·결정·실제 매매를 구분한다.
- 조사할 일은 결정 전에 생길 수 있고, 결정에서 실행할 일이 파생될 수 있다. 유지/보류 결정은 실행할 일 없이도 유효하다.
- 매일의 브리핑을 판단 기록으로 강제 생성하지 않는다. 의미 있는 결정 또는 사용자 요청 시 생성한다.
- [ ] “지금은 유지하고 다음 실적 때 다시 보자. 기록해줘”가 유지 결정과 조사할 일로 연결되는 예시를 확정한다.
- [ ] 계획하지 않은 매매도 원칙 문서·판단·할 일을 먼저 작성하지 않고 바로 기록하는 예시를 포함한다.

## 연속 점검 계약 — #44
- 사용자 요청으로 매일 분석을 시작하는 방식으로 확정한다. 자동/예약 생성은 현재 마일스톤에서 제외한다.
- #44에서 점검 범위·사건·검토 질문·판단 이력을 설계한 뒤 #34/#35의 구현 계약을 확정한다.
- [ ] 며칠 만에 돌아온 사용자도 마지막 조사 이후 변화와 미해결 질문을 따라잡는 시나리오를 추가한다.
- [ ] 질문 해결/사용자 결정/실제 매매/브리핑 열람은 서로 다른 사건으로 정의한다.

## 투자 기준 계약 — #43 연계
- 사용자 목적·기간·성향, 현재 운용 전략/모드, 종목별 보유 이유를 구분한다.
- #43에서 투자 기준을 Portfolio 원본으로 관리하고 기준 미입력/충돌 시 제안 범위와 질문 정책을 정한다.
- [ ] 개인 기준을 적용한 근거가 있는 브리핑과 기준 부족을 알리는 예시를 제품 계약에 포함한다.

## 아침 경험 중심의 제품 계약 보완
- 핵심 약속: “출근할 때 잠깐 보면, 내 투자 상태와 오늘 신경 쓸 것만 알 수 있다.”
- 기본 브리핑은 한 줄 결론 → 중요한 변화 최대 3개 → 보유 이유에 미치는 영향 → 오늘 할 일 0~3개. 출처와 세부 내용은 펼쳐 본다.
- 결과 상태는 추가 행동 없음 / 확인할 항목 있음 / 자료 부족으로 구분한다. 뉴스 미조회·검색 실패를 변화 없음으로 처리하지 않는다.
- “오늘 할 일”에는 관찰·일정 확인·기록 보완도 포함한다. 매매와 일일 사용을 연결하지 않는다.
- 대표 예시 4개를 먼저 작성한다: 변화 없는 날, 보유 가설 재검토가 필요한 날, 최신 자료가 부족한 날, 잔고가 오래 미확인인 날.
- 기본 아침 흐름은 ChatGPT에서 점검 완료. 앱은 최근 결과를 바로 보여주는 기록/수정 진입점이며 매일 양쪽 방문을 요구하지 않는다.
- 사용자 시작형 분석이므로 앱을 연 것만으로 새 브리핑이 생성되지는 않는다. 새 브리핑이 없으면 최근 날짜와 시작 안내를 보여준다.
- “오늘 점검하고 저장해줘”를 기본 시작 문구로 제공한다. 단순 조회 요청에는 저장을 추정하지 않으며 클라이언트 자체 권한 확인은 우회하지 않는다.
- 성공 지표는 로그인 횟수/거래 횟수보다 핵심 파악 시간, 필요한 결정 인지, 반복 입력과 화면 전환 부담이다.
- #41 보유 이유와 #42 잔고 확인은 선택 기능으로 시작하고 신규 사용자의 첫 브리핑을 막지 않는다.

### 추가 완료 조건
- [ ] 대표 4개 브리핑 문안을 사용자 관점에서 검토하고 화면/저장 스키마의 공통 기준으로 사용한다.
- [ ] 시간 목표를 생성 대기 시간과 브리핑 읽기 시간으로 분리한다. 읽기는 약 60초를 목표로 한다.

## 목적
ChatGPT는 조사·해석·설명을, Portfolio는 저장·계산·구조 검증을 담당한다. 사용자는 매일 출근할 때 짧게 점검하고 필요할 때 완료한 매매를 기록한다.

## 범위
- 진입점 두 개를 정의: ChatGPT에서 점검 시작, Portfolio 앱에서 저장된 브리핑 열람.
- 정확성 범위: 입력한 초기 잔고와 완료 매매에 대한 수량·이동평균 원가. 증권사 잔고/현금/세금/총수익과의 자동 일치는 제공하지 않는다.
- 계좌+종목+통화 기준의 잔고 기준점, 매수 가중평균, 부분 매도 시 평균가 유지, 전량 매도 후 재매수, 소수 수량/가격과 반올림 규칙을 결정한다.
- 수수료·세금·배당·분할·이체는 첫 버전 지원 범위와 보정 방법을 명시한다.
- 과거일 거래, 거래 취소, 잔고 보정 이후 과거 기록 변경의 재계산 규칙을 정한다.
- 기존 holdings 직접 편집/일괄 편집과 거래 원장 중 어느 경로가 기준점을 만드는지 명시한다.
- 프리뷰는 동시 수정/계산 검증 장치다. 일반적인 “완료 매매 기록”은 사용자 의도가 분명할 때 불필요한 재질문을 최소화하고, 모호한 계좌·종목·수량과 큰 보정은 확인한다. 확인 UI/명시적 확인 적용 범위를 문서화한다.
- server instructions, 도구 설명, 작업별 가이드, 서버 강제 규칙을 구분한다.

## 완료 조건

- [ ] 매수/부분 매도/전량 매도/재매수/기준점 이후 거래의 숫자 예제를 확정한다.
- [ ] 기존 거래 테이블·트리거·RPC의 실제 배포 상태를 타깃 조사한다. schema overview와 과거 closed issue만으로 현행 구현을 가정하지 않는다.
- [ ] 비용은 ChatGPT 사용과 Portfolio 운영으로 분리하며 별도 LLM API 호출은 이 마일스톤에 추가하지 않는다.
