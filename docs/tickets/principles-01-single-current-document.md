# [원칙] 사용자당 현재 문서 하나와 변경 메모 중심 이력

2026-09-24 · Astra 설계 · Sol 로컬 구현/자동 검증 · 운영 전 · P1

GitHub: https://github.com/kimyongin/fin/issues/132

## 목적과 현재 차이

사용자와 에이전트가 읽을 현재 원칙은 자유 마크다운 문서 하나다. 여러 기준은 한 본문 안에 쓴다.
현재 `PrincipleJournal.jsx`의 추가는 새 principle_id를 발급하고 `app_list_principles`는 ID별 최신 행을 반환하므로 여러 문서가 동시에 현재로 나온다. #118의 마크다운/변경 메모/과거 본문 읽기는 유지하되 다중 현재 문서는 없앤다.

## 목표 계약

- 사용자당 현재 문서 0~1개. 최초 작성 이후에는 기존 문서 수정으로 저장하고 같은 principles 테이블에 본문·선택적 변경 메모·서버 저장시각을 새 행으로 남긴다.
- 사용자별 가장 최근 저장본이 현재 원칙이다. 현재 문서가 없으면 작성 안내, 있으면 본문 하나와 수정 진입을 제공한다. 임의 원칙 ID로 두 번째 현재 문서를 만들 수 없게 서버에서도 강제한다.
- 이력은 날짜·변경 메모 중심 타임라인이며 선택 시 당시 본문 전체를 읽기 전용으로 연다. DIFF/본문 반복 목록/새 revision 테이블/자동 복원 기능은 추가하지 않는다.
- 원칙별 개별 종료/여러 문서 추가 UI 및 MCP 입력은 퇴역한다. 과거 행은 일반 수정 대상이 아니다. 기존 동시 저장 보호는 최소한으로 재사용해 다른 세션의 최신 본문을 조용히 덮어쓰지 않는다.
- 웹 저장/조회, MCP 원칙 저장/조회, 일일 문맥과 인터뷰 workflow 모두 현재 문서 하나를 정본으로 사용한다. 변경 메모를 지켜야 할 원칙 본문에 섞지 않는다.
- 원칙은 소유자 전용을 유지한다. 활동/배분 공유로 노출하지 않는다.

## 기존 데이터와 최소 기술 계약

- 새 migration 전 사용자별 현재 문서 수/종료 상태를 확인한다. 기존 활성 문서 중 최신 effective_at, 동률이면 id 기준 하나를 현재로 선택하고 나머지 본문·메모·시각은 보존된 이전 저장본으로 조회 가능하게 한다. 종료된 문서가 더 오래된 본문으로 부활하면 안 된다.
- 기존 독립 문서들을 실제 시간순 수정본이었다고 설명하지 않는다. 전환 당시 복수 문서가 있었음과 최신 하나가 선택됐음을 인계에 기록한다. 자동 본문 합치기·내용 삭제는 하지 않는다.
- 구현 첫 단계에서 기존 principle_id/ended 컬럼·RPC 호출자 의존성을 조사해 필요한 최소 조회/저장 계약과 이관 fixture를 확정한다. 화면에서 배열 첫 항목만 자르는 패치는 불충분하다.
- 적용된 migration을 수정하지 않는다. 사용자 로컬 설정·기타 투자 데이터는 건드리지 않는다. 운영 적용은 별도 요청/검증 게이트다.

## 완료 기준

- [ ] 사용자별 0/1/4개 현재 문서, 종료 행, 같은 시각의 행을 가진 이관 fixture에서 현재 0~1개와 과거 본문 보존을 검증한다.
- [ ] 최초 작성→두 번 수정→최신 한 개 조회→각 과거 본문/메모 조회가 웹과 인증된 MCP 모두 일치한다.
- [ ] 동시 첫 작성/동시 수정·잘못된 사용자 접근·쓰기 실패를 검증한다. 테스트를 통과하기 위해 사용자 격리를 줄이지 않는다.
- [ ] 구 다중 문서 추가/종료 계약과 호출자를 정리하고 MCP description·get_workflow_guide·정본 문서·스키마 개요를 갱신한다.
- [ ] 360/390/768/1024/1440px에서 긴 마크다운·이력·수정·미저장 닫기와 공통 모달 규칙을 확인한다.

일반 로컬 DB 적용과 운영 배포를 구분한다. 이 티켓 작성만으로 운영 DB 변경/배포를 완료한 것은 아니다.

## 구현 기록 (2026-09-24)

증분 migration에서 사용자별 최신 원칙 행 하나만 현재로 조회하고 이전 본문·메모는 모두 보존한다. 새 저장은 현재 ID의 다음 행으로만 허용하며 개별 종료를 거부한다. 기존 복수 독립 문서는 자동 병합하지 않으며 최신 행만 현재로 선택한다. 4개 원칙/동일 시각/종료 행/사용자 격리 DB fixture, 웹 원칙 이력, OAuth MCP 저장·읽기 검사가 통과했다. 일반 로컬 DB에는 적용했고 운영 DB/실기기는 아직이다.

## 원칙 화면 후속 정돈 (2026-09-24)

- 현재 문서가 있으면 상단의 중복 `원칙 수정` 버튼을 없애고 현재 원칙 카드의 `수정`만 남겼다. 문서가 없을 때는 빈 상태 카드 안에서 `원칙 작성`으로 진입한다.
- 카드 안의 불필요한 `원칙` 제목을 제거하고 적용 일시와 수정 버튼을 한 줄에 배치했다. 이력 읽기 모달은 `당시 원칙` 대신 해당 저장 일시를 제목으로 표시하고 본문의 중복 시각을 제거했다. 저장·조회·권한 계약 변경은 없다.
- `npm run check:encoding`, `npm run build`, `npm test` 통과. 격리 E2E에서 원칙 흐름 6개 중 5개는 처음부터 통과했고, 1개는 테스트의 Node/브라우저 한국어 시각 표기 차이만 수정한 뒤 재실행 통과했다. 이력 모달은 360/390/768/1024/1440px에서 열림과 가로 넘침 없음을 자동 확인했다. 실제 기기 키보드·스크린리더 및 운영 배포는 검증하지 않았다.
