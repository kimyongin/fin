# [MCP-first] 아침 점검용 get_daily_context 구현

## 구현 진행 (2026-09-21)

- `202609210001_daily_review_foundation.sql`에서 소유자 전용 6시간 임시 context, 만료 정리, 사용자별 활성 context 10개·subject 200개·snapshot 2 MiB 제한, 기존 portfolio/strategy/news/activity/이전 브리핑 snapshot 조립을 구현했다.
- context 생성은 브리핑·열람·잔고 확인이나 완료 activity를 만들지 않으며, 저장 시 원본 snapshot이 브리핑으로 복사되는 것을 DB 테스트로 검증했다.
- 이전 조사 scope 요약과 3일 겹침 설정, 열린 질문·판단·개인 기준·보유 이유·실제 잔고 확인 요약을 context에 포함했다.
- OAuth MCP `get_daily_context` 등록과 로컬 인증 호출을 검증했다. 실제 대규모 계정 응답 시간·분할 DTO 필요성, 운영 배포·클라이언트 검증은 남아 있다.

## 단순화 적용 기준 — ADR-0004 (2026-09-21)

[ADR-0004](https://github.com/kimyongin/fin/blob/master/docs/adr/0004-domain-storage-and-minimal-mutation-contract.md)가 아래 이전 설계의 물리 구조 요구보다 우선한다. 해당 ADR은 현재 작업 트리에서 작성됐으며 원격 링크는 푸시 후 유효하다. 도메인 테이블+공통 변경 규약, 필요한 대상만 version 검사, 현재값+중요 변경 이력/당시 snapshot을 사용한다. 모든 모델에 head/revision 쌍을 만들지 않는다.

- 문맥은 서버 임시 context_id, 결과는 단일 briefing으로 저장한다. signed receipt·전역 가격/메타데이터 버전 차단은 도입하지 않는다. TTL/정리/생성 제한과 소유권은 테스트한다.
- 사건 엔진/일반 조사구간 집합 엔진/보유 구간 자동 복원/가이드 전용 도구는 후순위다. 아래 사건·이력 인수 조건은 첫 버전에서 근거 정정 참조, 판단/task 연결, 중요 변경 이력과 snapshot으로 충족한다. 보안·원가·보정 보호·원자성은 줄이지 않는다.
- 구현되지 않은 과거 진행 기록은 역사다. 신규 완료 게이트는 갱신된 contracts 문서와 이 절을 따른다. 기능 제공/자동 테스트 통과/티켓 완료를 뜻하지 않는다.

## 구현 인계 확정 사항 (2026-09-20)

- 필독: [ADR-0002](https://github.com/kimyongin/fin/blob/master/docs/adr/0002-cost-basis-reconciliation-and-sharing.md), [ADR-0003](https://github.com/kimyongin/fin/blob/master/docs/adr/0003-extensible-feature-sharing.md), [구현 계약 초안](https://github.com/kimyongin/fin/blob/master/docs/design/implementation-contract-draft.md).
- 평가·비중·배분의 기술 초안을 검증 후 공통 계약으로 확정한다. 인증된 본인 문맥과 공유용 응답을 분리하며 임의 owner 입력으로 문맥을 얻지 못하게 한다.
- 문서화는 구현/배포/보안 검증 완료가 아니다. 미검증 DDL·정밀도·상태 전이는 해당 티켓의 첫 작업으로 남기며 완료 체크를 앞당기지 않는다.

## 기존 계산을 재사용하는 문맥 계약
- 기존 태그 → 전략 버킷 → 현재 운용 모드 목표를 ID로 구분한다. 태그마다 독립 목표가 있다고 가정하지 않는다.
- #32에서 확정한 평가·환산·분모·누락값 정책을 공통 계산 경로로 구현하고 #43 배분 점검에 제공한다. 기존 전략 계산을 별도의 MCP 추천 엔진으로 복제하지 않는다.
- 규칙 기반 적립금 배분/조정 후보는 계산 근거·시점·기준 버전과 함께 제공한다. 모델 해석/사용자 결정과 구분한다.
- #44와 #43 계약 및 #35-A 스키마 기반 이후 실제 통합한다. 스키마 생성 전에 이 티켓의 완료를 요구하지 않는다.
- [ ] 동일 fixture의 앱/MCP 금액·비중·버킷·목표·계산 결과가 일치한다.
- [ ] 복수 계좌, 시장형/평가형/현금성, 외화, 누락 시세/환율, 버킷 미연결 태그를 검증한다.

## 투자 관리 문맥 구성
- #43 투자 원칙의 현재 버전, #41 보유 이유, #44 유효한 판단·조사/실행할 일을 구분해 제공한다.
- 사용자가 채택한 결정과 모델 제안, 대체된 과거 판단을 명시한다. 새 분석이 과거 사용자 결정을 자동 변경하지 않도록 한다.
- [x] 실행할 일의 미체결/부분 체결과 조사할 일의 자료 대기를 서로 다른 상태로 반환한다.

## 마지막 조사 이후 따라잡기 — #44 계약 적용
- #44 데이터 계약 확정 후 조사 범위별 마지막 확인, 누락 범위, 열린 질문/자료 대기/보류, 관련 사건과 과거 판단을 읽는 구현을 담당한다.
- 마지막 브리핑 날짜 하나를 조사 시작점으로 사용하지 않는다. 늦은 보도를 위한 기간 겹침과 알려진 사건 ID를 반환한다.
- 해결된 질문은 새 정정/근거가 있거나 명시적 재검토가 필요한 경우에 연결하고 매일 무조건 재조사 대상으로 만들지 않는다.
- 질문/이력은 관련 최신 상태 우선 요약하고 상세 조회·페이지네이션을 제공한다. 모든 과거 본문을 매번 반환하지 않는다.
- [ ] 며칠 후 복귀, 일부 종목 조사 실패, 뒤늦게 발표된 자료, 같은 사건 반복 보도를 검증한다.

## 내 투자 기준 문맥 — #43 연계
- 확정된 투자 목적·기간·자금 필요 시점·변동성 수용·매매 선호·금지사항과 버전/유효시각을 운용 전략·종목별 이유와 구분해 반환한다.
- 미입력/사용자 확정/모델 제안/화면 기본값을 혼동하지 않고 누락·충돌을 명시한다.
- optional 필드 계약으로 먼저 구현할 수 있으나 최종 완료에는 #43 연동을 포함한다.
- [ ] 같은 뉴스에 서로 다른 기준을 적용하는 사례, 기준 미입력·충돌 사례를 검증한다.

## 보유 이유·확인 범위와 아침 브리핑 연결
- #41의 보유 이유/판단 버전/재검토 조건/점검 예정일과 #42의 실제 잔고 확인 범위·시점을 문맥에 포함한다.
- 두 기능 전에는 해당 정보 없음으로 반환하도록 optional 계약을 먼저 정의한다. 확장 데이터 연동은 #41/#42 완료 후 이 티켓의 최종 완료 조건에 포함한다.
- 직전 브리핑의 이미 전달한 사건과 미해결 항목을 식별자로 제공해 같은 뉴스를 매일 새로운 변화로 반복하지 않도록 한다.
- 기한 도래처럼 서버가 계산 가능한 사실과 뉴스 해석 같은 모델 판단을 구분한다. 기한 도래가 곧 매도 조건 충족은 아니다.
- 요청 업무 가이드는 #32의 기본 브리핑 형식과 자료 부족 구분을 포함한다.

## 사용자 시나리오
“오늘 내 포트폴리오 점검해줘”라고 하면 ChatGPT가 필요한 문맥을 한 번에 받고, 필요한 최신 자료는 직접 조사한다.

## 범위
- 도구명은 get_daily_context 하나로 통일한다. prepare_daily_portfolio_review를 중복 추가하지 않는다.
- 기존 app_get_portfolio_state, app_get_strategy_state, 뉴스/활동 읽기를 재사용해 소유자 문맥을 구성한다.
- 보유 계좌·종목·수량·평균가, 전략, 최근 변경, 직전 브리핑, 저장 뉴스 요약을 반환한다.
- as_of, 사용자 시간대, 가격 기준시각, 누락/오래된 데이터, 요약/페이지네이션을 제공한다.
- 변화는 비교 가능한 저장된 기준이 있을 때만 계산한다. 없으면 기준 없음으로 표시한다.
- 서버는 보유 티커/저장 기록 등 검색 재료만 제공한다. 뉴스 중요도 판단과 검색 주제 선정은 ChatGPT가 담당한다.
- 평가형·현금·환율 자산은 시장형 수량/평균가 계산과 구분한다.
- 조회만으로 점검 완료 처리하지 않는다. 과도한 전체 기록 반환을 막는다.
