# [리팩토링] 공유·게스트 접근을 자산 액션에서 분리

2026-09-23 · P2 · 로컬 구현·격리 검증 완료, 운영 배포 전. 관련: docs/engineering/refactoring-review-20260923.md.

## 목적과 근거

src/features/portfolio/actions.js의 createPortfolioActions가 자산 액션 조립 외에 게스트 접근·공유 프로필·로그아웃을 담당한다. App.jsx에서 인증/공유 setter와 자산 편집 상태를 함께 전달하므로 공유 변경에도 자산 액션의 의존성을 살펴야 한다.

## 범위

- 기존 auth/공유 책임에 맞는 기능 내부 hook 또는 모듈로 게스트 unlock·공유 프로필 동작과 해당 상태를 분리한다. 정확한 위치는 architecture.md와 기존 코드 의존성을 확인해 결정한다.
- App의 세션/소유자 전환 조립은 유지하고 자산 액션 팩토리에서 불필요해진 공유 의존성을 제거한다. 로그아웃의 공유 상태 초기화도 누락하지 않는다.
- 이미 분리한 계좌/종목/보유/태그 액션은 유지한다. 시세 동기화와 다른 기능의 재설계까지 확대하지 않는다.
- 서버 권한, 게스트·친구·본인 동작, 오류 안내, 활동 기록 동작은 바꾸지 않는다.

## 완료 기준

- [x] 기존 동작 테스트를 먼저 확인하고 공유 모듈 테스트에 무관한 자산 편집 상태가 필요하지 않다.
- [x] createPortfolioActions 입력에서 공유 관련 초안/setter 의존성이 제거된다.
- [x] 게스트 접근 성공/실패, 공유 프로필 저장 성공/실패, 로그아웃 초기화를 검증한다.
- [x] 친구→본인 전환과 공유 읽기 전용·사용자 격리의 기존 회귀가 유지된다.
- [x] 자산 CRUD 회귀, 단위 테스트·관련 E2E·빌드·인코딩 결과와 미검증 범위를 기록한다.

전역 Context/상태관리 라이브러리, DI/repository 엔진, 서버 권한 이동은 제외한다.

## 구현·검증 기록 (2026-09-23)

게스트 unlock·공유 프로필 저장·로그아웃을 `src/features/auth/accessActions.js`로 옮기고 App에서 자산 액션과 별도로 조립했다. createPortfolioActions에서 공유 초안/setter/session 의존성을 제거했다. 자산 액션 단위 테스트 fixture도 해당 의존성을 제거하고 접근 액션의 성공/실패/로그아웃 테스트를 분리했다. 격리 전체 E2E에서 친구 추가/해제, 공유 읽기, 게스트 잠금 해제/오류, 기존 자산 CRUD가 통과했다. 서버 권한은 변경하지 않았다. 운영 배포·실기기 확인은 하지 않았다.
