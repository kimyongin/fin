# [MCP-first] 내 투자 기준·성향 관리와 기존 상세 원칙 화면 확인

## 단순화 적용 기준 — ADR-0004 (2026-09-21)

[ADR-0004](https://github.com/kimyongin/fin/blob/master/docs/adr/0004-domain-storage-and-minimal-mutation-contract.md)가 아래 이전 설계의 물리 구조 요구보다 우선한다. 해당 ADR은 현재 작업 트리에서 작성됐으며 원격 링크는 푸시 후 유효하다. 도메인 테이블+공통 변경 규약, 필요한 대상만 version 검사, 현재값+중요 변경 이력/당시 snapshot을 사용한다. 모든 모델에 head/revision 쌍을 만들지 않는다.

- 문맥은 서버 임시 context_id, 결과는 단일 briefing으로 저장한다. signed receipt·전역 가격/메타데이터 버전 차단은 도입하지 않는다. TTL/정리/생성 제한과 소유권은 테스트한다.
- 사건 엔진/일반 조사구간 집합 엔진/보유 구간 자동 복원/가이드 전용 도구는 후순위다. 아래 사건·이력 인수 조건은 첫 버전에서 근거 정정 참조, 판단/task 연결, 중요 변경 이력과 snapshot으로 충족한다. 보안·원가·보정 보호·원자성은 줄이지 않는다.
- 구현되지 않은 과거 진행 기록은 역사다. 신규 완료 게이트는 갱신된 contracts 문서와 이 절을 따른다. 기능 제공/자동 테스트 통과/티켓 완료를 뜻하지 않는다.

## 구현 인계 확정 사항 (2026-09-20)

- 필독: [ADR-0002](https://github.com/kimyongin/fin/blob/master/docs/adr/0002-cost-basis-reconciliation-and-sharing.md), [ADR-0003](https://github.com/kimyongin/fin/blob/master/docs/adr/0003-extensible-feature-sharing.md), [구현 계약 초안](https://github.com/kimyongin/fin/blob/master/docs/design/implementation-contract-draft.md).
- 기능별 공유 구조의 데이터/API/RLS 구현을 이 티켓에서 소유한다. 내부 owner/audience/feature/action, 첫 버전 read와 기존 공유 대상 집합만 지원한다. #44는 관계·공개 필드 계약, #36은 UI, #39는 통합 검증을 담당한다. 기존 버킷 삭제·재생성 및 전략 전체 JSON 공유 경로를 개선해 중요 변경 이력/당시 snapshot과 allowlist를 적용한다.
- 문서화는 구현/배포/보안 검증 완료가 아니다. 미검증 DDL·정밀도·상태 전이는 해당 티켓의 첫 작업으로 남기며 완료 체크를 앞당기지 않는다.

## 기존 전략의 재구성 범위
- 재사용: StrategyPage의 상세 원칙/운용 한도, 모드별 버킷 목표, 태그 연결, 적립금, 이탈 폭, 모드 변경 사유.
- 변경: 원칙 화면에서 개인 기준·상세 원칙·운용 계획을 편집한다. 현재/목표 비교·적립금 배분·조정 후보는 자산에서 여는 배분 점검 본문으로 분리한다. #36은 탐색 연결을 담당한다.
- 전략 버킷과 종목 태그를 합치지 않는다. 모드 프리셋을 개인 성향으로 해석하지 않는다.
- 기존 규칙 기반 ‘리밸런싱 제안’은 ‘배분 계산 결과’로 명확히 표시한다. #34의 공통 평가/배분 계약을 사용하고 모델 의견·사용자 결정·실제 매매와 구분한다.
- 신규 개발은 선택적 개인 기준, 기존 원칙/계획의 버전·이력, MCP 공통 변경 계약, 판단의 당시 기준 참조에 집중한다. 기존 상세 원칙을 중복 구현하지 않는다.
- 기존 공유 전략은 현재 notes를 표시하는 경로가 있다. 기존 공유 항목과 새 비공개 개인 기준을 필드별로 정의하고 API/RLS까지 검증한다. 전체 strategy 응답에 새 민감정보를 섞어 자동 공개하지 않는다.
- 기존 노출 미확인 보고는 배포/권한/전략 생성·진입 조건으로 재현한다. 로컬 코드 존재만으로 운영 노출 완료를 선언하지 않는다.
- [ ] 재구성 전후 목표·모드·태그 연결·원칙·한도가 보존되고 변경 사유를 판단 기록에 연결할 수 있다.
- [ ] 원칙 편집과 배분 계산이 중복 구현되지 않으며 친구 공유와 소유자/MCP 응답의 공개 범위가 일치한다.

## 투자 원칙·운용 계획(PRD 역할)
- 사용자 화면에서는 “투자 원칙·운용 계획”으로 제공한다. 목적·기간·자금 필요·성향과 목표 배분·적립·리밸런싱 규칙·한도·예외 조건을 구분해 한 기준 체계로 관리한다.
- #44 판단 기록은 결정 당시 원칙의 버전을 참조한다. 원칙 수정으로 과거 결정의 근거가 바뀌지 않아야 한다.
- 문서 완성을 필수로 하지 않는다. “장기 투자하고 자주 매매하고 싶지 않아”처럼 짧은 기준으로 시작할 수 있다.
- [ ] 원칙 버전 변경 후 과거 판단과 현재 제안이 각각 올바른 버전을 참조하는지 검증한다.

## 선행 작업
- #32 제품 계약 확정, #33 OAuth MCP 계약 정비.
- #41 종목별 보유 이유와 저장 범위를 구분한다. 서로를 구현 선행 조건으로 두지 않는다.

## 목적
Portfolio에 사용자 투자 기준을 저장하고 ChatGPT가 일일 제안에서 동일한 기준을 읽고 적용하도록 한다. 대화 기억이나 모델의 추측에만 의존하지 않는다.

## 현행 확인 및 재사용
- 로컬 src/features/strategy/StrategyPage.jsx에는 PrinciplesModal의 상세 원칙 입력란과 principles.notes가 있고, data.js는 input_principles를 app_save_strategy로 전달한다.
- 사용자는 현재 앱에서 이 항목이 보이지 않는다고 보고했다. 실제 배포 화면의 노출 여부와 원인은 미확인이다.
- 배포 버전, 본인/공유 보기 권한, 전략 생성 여부와 편집 진입 경로를 확인하여 재현 근거를 남긴다. 원인을 확인하기 전에 미배포/버그로 단정하지 않는다.
- 기존 상세 원칙과 운용 규칙을 우선 재사용하고 기존 데이터는 보존한다. 프런트엔드 기본값을 사용자 확정 원칙으로 간주하지 않는다.

## 설계 범위
- 사용자 투자 기준: 투자 목적, 기간, 자금 필요 시점, 손실/변동성 수용 정도, 선호 매매 빈도, 피하고 싶은 상품/행동을 선택 입력으로 관리한다.
- 손실 수용 정도가 자동 손절 규칙을 의미하지 않도록 의미와 단위를 명시한다. 미입력은 unknown으로 유지하고 모델이 숫자를 채우지 않는다.
- 세 층을 구분한다: 비교적 안정적인 사용자 기준 / 목표 비중·적립금·거래 한도·현재 운용 모드 / #41 종목별 보유 이유.
- 성장/중립/방어 운용 모드를 사용자 성향으로 자동 환산하지 않는다.
- 기준의 저장 원본은 Portfolio이다. 앱과 OAuth MCP는 같은 읽기/변경 계약을 사용한다. get_profile의 인증 프로필과 투자 기준을 혼합하지 않는다.
- 자유 서술 원문과 구조화 필드를 함께 보존한다. 명시적 금지/한도와 선호를 구분하고 서로 충돌하면 임의로 우선순위를 확정하지 않는다.
- “이걸 내 기본 원칙으로 저장해줘”처럼 의도가 분명한 요청은 변경 항목을 반영한다. 모델이 추론한 성향은 사용자 채택 전까지 제안으로만 취급한다.
- 버전, 유효시각, 변경 출처와 이력을 보존한다. 부분 수정으로 다른 원칙을 지우지 않고 동시 수정 충돌을 처리한다.
- 분석은 적용한 기준과 충돌/정보 부족을 드러낸다. 원칙에 반하는 제안을 하면서 사용자 원칙을 자동 수정하지 않는다.
- 개인 기준은 기본 소유자 전용이며 친구 공유에 자동 포함하지 않는다.
- 긴 설문을 필수로 하지 않는다. 기준이 없으면 제한된 분석과 꼭 필요한 질문을 제공하고 개인화가 완료됐다고 표현하지 않는다.
- DB 변경 시 supabase/schema/OVERVIEW.md를 갱신한다.

## 완료 조건

- [ ] 기존 상세 원칙·목표 비중·운용 한도를 잃지 않고 기준을 저장·수정·다시 읽는다.
- [ ] 앱과 ChatGPT에서 수정한 내용이 같은 버전으로 조회된다.
- [ ] 미입력, 기본값, 사용자 확정, 모델 제안 상태를 구분한다.
- [ ] 동일 뉴스라도 서로 다른 기간/매매 선호에 적용한 이유가 드러나는 예시를 검증한다. 반드시 다른 결론을 내도록 강제하지 않는다.
- [ ] 상충하는 기준·미입력·동시 변경·타 사용자 접근을 검증한다.
- [ ] #34/#35/#36/#39의 문맥·근거 저장·표시·사용성 검증과 연결한다.
