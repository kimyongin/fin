# [활동 UX] 반복 할 일의 이번 완료·중단을 목록에서 구분

2026-09-26 · Astra 설계 · Sol 로컬 구현. 운영 배포 전.

GitHub: https://github.com/kimyongin/fin/issues/144

## 목적과 현재 의미

반복 할 일을 수행했는지와 앞으로 반복할지를 목록에서 명확히 조작하고, 상세 모달은 속성 편집·저장에 집중한다. [#133 반복 계약](./activity-18-agent-due-recurrence.md)의 비정기 에이전트 요청 시나리오를 유지한다.

현재 `ActionTimeline`의 `완료`는 `transitionGeneralTask(..., 'complete', { occurrenceOn })`로 해당 회차를 완료한다. `GeneralTaskDetail`의 `반복 종료`는 `LifecyclePage.endGeneralTask`를 통해 같은 API의 `cancel`로 앞으로의 반복을 종료한다. 두 동작은 서로 대체할 수 없다. 목록의 완료 버튼을 단순히 중단으로 개명하면 정상 수행을 기록하는 기능이 사라진다.

현재 타임라인 RPC는 `control_state='active'`여도 최신 회차 상태가 open인 행만 pending에 담는다. 따라서 상세의 종료를 목록으로 이동하려면 이번 회차 완료 직후의 반복도 목록에서 찾을 수 있어야 한다. 프런트에 이전 행을 임시로 남기는 방식으로는 새로고침 이후 동작을 보장할 수 없다.

## 목표 경험

| 대상/상태 | 목록 표시와 행동 |
| --- | --- |
| 일반 할 일 | 기존 `완료`. 완료하면 할 일 목록에서 사라지고 기록으로 남음 |
| 도래한 반복·이번 회차 미완료 | `이번 완료`와 보조 `중단` |
| 반복·이번 회차 완료 | 행 유지, `이번 완료됨` 상태와 `중단`. 완료를 다시 실행하는 버튼 없음 |
| 반복·아직 예정 시각 전 | 반복 일정 + `예정` 상태와 `중단`. 미도래 회차 완료 금지 |
| 중단한 반복 | 현재 할 일 목록에서 제외. 기존 수행 기록은 유지 |
| 친구/공유 화면 | 허용된 조회만 제공. 완료·중단 버튼 없음 |

1. 반복의 목록 버튼은 `이번 완료`와 `중단`으로 구분한다. 중단은 일시정지가 아니라 앞으로 반복을 끝내는 동작이다. 재개 상태·버튼·새 테이블을 만들지 않는다. 다시 필요하면 새로 등록한다.
2. `중단`을 누르면 공통 확인창: 제목 `반복을 중단할까요?`, 내용 `앞으로 이 할 일을 반복하지 않습니다. 기존 기록은 남습니다.`, 버튼 `취소 / 중단`. 대상 제목도 확인할 수 있게 한다. 완료 처리로 오해할 성공 문구를 쓰지 않는다.
3. `GeneralTaskDetail`의 `반복 종료` 버튼과 전용 확인 state/callback을 제거한다. 상세는 바로 편집하고 닫기/저장하는 기존 모달 규칙을 따른다. 목록 중단을 위해 상세 초안을 열거나 버릴 필요가 없다.
4. 활성 반복은 이번 회차 완료 여부와 관계없이 할 일 목록에 한 행만 표시한다. 기존 반복 요약 아래 `이번 완료됨` 또는 `예정`을 표시한다. 미처리 도래 행을 먼저 보여주고 완료/예정 반복은 뒤에 둔다. 새 탭·접기·반복 관리 페이지를 만들지 않는다.
5. `미완료 과제 N개`에 완료된 반복을 섞어 세지 않는다. 불필요한 새 통계를 만들기보다 이 보조 개수 문구를 제거한다. 일반/반복 제목은 기존 `할 일`을 유지한다.
6. 검색어·태그로 좁힌 할 일 결과에서도 같은 행과 행동을 사용한다. 기록 결과는 기존대로 유지한다. native button 안에 완료/중단 버튼을 중첩하지 않는다.
7. 360px에서는 제목/일정 다음 줄에 행동을 두어 텍스트가 지나치게 좁아지지 않게 한다. 넓은 화면은 오른쪽 정렬한다. 이번 완료는 기존 주 행동, 중단은 보조 행동이다.

목록의 `중단`은 텍스트 링크가 아니라 `이번 완료`와 동일한 높이·테두리·모서리·내부 여백의 버튼으로 표시한다. 글자 색만 보조 행동으로 구분하고, 확인창·저장 의미는 바꾸지 않는다.

## 최소 기술 계약

- 쓰기 API는 기존 `app_transition_general_task`의 complete/cancel을 재사용한다. 상태 enum, 중단 API, 반복/회차 테이블을 추가하지 않는다. 중단을 완료로 저장하거나 완료 활동을 허위로 만들지 않는다.
- 웹 타임라인/키워드·태그 검색의 할 일 읽기에는 활성 반복의 최신 회차 상태를 포함한다. 기존 occurrence 계산/상태를 사용하고 필요한 경우 기존 읽기 RPC의 투영만 증분 변경한다. 소유자/공유 allowlist를 유지한다.
- `app_list_due_general_tasks`와 MCP `list_due_general_tasks`는 여전히 **지금 실행할 미처리 도래 회차만** 반환한다. 웹에서 완료/예정 반복을 관리할 수 있게 한다고 에이전트에게 실행 대상으로 반환하면 안 된다.
- 일반 기록 검색의 todo/done 분류와 회차 상태를 혼동하지 않는다. 반복 정의는 살아 있는 할 일, 회차 수행은 기록이다. 검색 결과가 상태/버전/회차 식별값을 주지 않는다면 기존 읽기에서 필요한 최소 값만 추가하거나 기존 상세 읽기로 현재값을 확인한 뒤 실행한다. 제목이나 표시 문자열로 추정하지 않는다.
- 중단은 기존 버전·권한·멱등 처리와 오류 재시도를 유지한다. 처리 중 중복 클릭을 막고 실패하면 목록/확인창에서 오류를 알린다. 최신 상태 충돌은 재조회하며 완료/중단이 모두 성공했다고 낙관 표시하지 않는다.
- 목록 새로고침, 검색·태그 변경, 상세 왕복 뒤에도 활성 반복의 접근성이 유지되어야 한다. 시간 도래 판정은 기존 서버 계약을 사용한다. 자동 실행·알림·새 스케줄러는 범위 밖이다.
- MCP의 완료/중단 의미는 변경하지 않는다. 관련 도구 설명·워크플로우에서 회차 완료와 전체 중단을 혼동하는 문구가 있는지만 확인하고, UI 명칭을 설명하는 문서가 있다면 같이 갱신한다.

## 구현 순서

1. 현재 타임라인/검색 DTO와 기존 회차 상태·완료/취소 API를 대조한다. 활성 반복의 완료/예정 표시를 기존 읽기 경로로 제공할 최소 변경을 기록한다.
2. 대표 시나리오 하나를 읽기 → 목록 이번 완료 → 기록 저장/재조회 → 완료된 반복 중단으로 연결한다. 그다음 같은 행을 검색 결과에 적용한다.
3. 상세의 종료 UI/state를 정리하고 기존 활동 E2E의 모달 종료 시나리오를 목록 동작으로 바꾼다. 기존 회차 계산 테스트를 반복해서 새로 만들지 않는다.

## 인계

`GeneralTaskListActions`를 목록/검색 결과에서 공유한다. `이번 완료`는 기존 complete 전이, `중단`은 기존 cancel 전이와 공통 확인창을 쓴다. 상세의 `반복 종료` UI만 제거했다. 웹 읽기 RPC 두 개가 완료·미도래 활성 반복 정의를 한 행씩 제공하고 상태/회차 정보를 투영한다. 쓰기 API·테이블·MCP 도구는 새로 만들지 않았다. 에이전트용 `app_list_due_general_tasks`는 수정하지 않았고 도래한 미완료 회차만 돌려준다. 도구 설명·워크플로우의 이번 완료/전체 중단 문구는 이미 이 의미와 일치해 변경하지 않았으며 `npm run check:workflow-guides`를 통과했다.

격리 DB 580개(DB 신규 13개 포함), 활동 브라우저 E2E 22개와 5개 폭 시각 회귀 1개, MCP 계약/인증 준비 검사, `npm test` 102개 및 빌드를 통과했다. 미래 시작/완료 반복, 중단 후 기록 보존, 소유권 차단은 DB에서 확인했다. 웹 E2E는 이번 완료 후 새로고침, 검색 결과·목록 중단, 상세 종료 버튼 제거, 360/390/768/1024/1440px 가로 넘침을 확인했다. 일반 로컬 DB에는 `20260926023847` 읽기 migration만 `supabase migration up --local`로 증분 적용했고 초기화하지 않았다. 실제 친구 화면, 실기기 보조공학, 긴 제목의 모든 줄바꿈, 운영 배포는 별도 확인이 필요하다.
