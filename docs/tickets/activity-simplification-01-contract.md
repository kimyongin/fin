선행: 없음. 기존 #75~#79 구현 재사용.
기준: [공통 설계](../design/activity-simplification.md), [ADR-0007](../adr/0007-activity-results-and-search.md).

## 목적

U01~U08 중 첫 활동 기능에 필요한 최소 모델/API와 기존 데이터 매핑을 확정한다.

## 인수 조건

- [ ] portfolio_tasks는 예정/반복, activity_events는 한 일과 현재 제목·내용·결과·판단을 저장한다. 별도 activity_results/event_result 테이블은 만들지 않는다. 기존 필드와 필요한 최소 컬럼을 비교해 읽기/쓰기 정본을 하나로 정한다.
- [ ] 수동 활동의 제목·수행일·메모·결론은 같은 레코드에서 수정한다. 자동 금융 이벤트의 거래/수량·변경 전후 값·원본 참조·발생시각은 일반 편집에서 보호하고 설명/태그만 허용한다. 허용 필드를 서버에서 검증하며 JSON 전체 덮어쓰기를 허용하지 않는다.
- [ ] 일반 메모/태그 편집에 별도 수정 이벤트·이력 테이블·범용 버전 엔진을 요구하지 않는다. 저장 재시도와 앱/MCP 동시 편집은 기존 규약을 재사용해 필요한 최소 충돌 검사만 정한다.
- [ ] event.task_id는 기존 관련 태스크 참조를 유지한다. 후속 할 일의 선택적 origin_event_id는 직접 계기 하나를 참조하고 동일 소유자만 연결한다. 한 활동에서 여러 후속 할 일이 가능하며 범용 관계 엔진을 만들지 않는다.
- [ ] 기존 판단의 내용·제안/채택 상태·당시 원칙·연결/이력을 보존하는 전환 매핑을 작성한다. 기존 판단 테이블 삭제는 선행조건이 아니다. 과거 판단-task 연결만으로 같은 수행이라고 병합하지 않는다.
- [ ] 종목·계좌 연결은 검색용 선택 필드다. 기존 반복 회차/완료 취소·재개와 금융 정정 흐름을 재사용하며 새 완료 이력 체계를 설계하지 않는다.
- [ ] 기존 기록 수정과 새 활동 등록은 사용자가 선택한다. 설명 정정/새 판단을 시스템이 분류하거나 대체 연결을 강제하지 않는다. 기존 대체 관계는 보존하고 명시적인 관련 기록 연결만 허용한다.
- [ ] 첫 소비자인 #81의 조회·등록·편집·완료·후속 연결 DTO/RPC/MCP, 필드별 권한, 대표 fixture를 기록하면 종료한다. 태그/검색의 상세 인덱스·모델은 #82/#83에서 정한다.

## 실행 기준

기존 구조를 활용해 필요한 최소 변경을 사용자 기능 단위로 구현한다. 일반 활동에 불변성·별도 결과 저장·의무 수정 이력을 도입하지 않는다. 금융 원본/계산/인증/권한과 기존 재시도·반복 동작은 유지한다. 이번 갱신은 설계·티켓만 변경하며 구현·배포 완료를 뜻하지 않는다.
