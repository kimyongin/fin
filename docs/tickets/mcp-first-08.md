# [MCP-first] 5일 출근 사용 파일럿과 릴리스 검증

## 구현 인계 확정 사항 (2026-09-20)

- 필독: [ADR-0002](https://github.com/kimyongin/fin/blob/master/docs/adr/0002-cost-basis-reconciliation-and-sharing.md), [ADR-0003](https://github.com/kimyongin/fin/blob/master/docs/adr/0003-extensible-feature-sharing.md), [구현 계약 초안](https://github.com/kimyongin/fin/blob/master/docs/design/implementation-contract-draft.md).
- 체결가 평균, 보정 이전 정정의 현재값 유지, 기능별 read 권한을 회귀 항목으로 추가한다. 공유 철회·직접 링크·검색/건수·CSV·비공개 연결 누출과 새 기능 기본 deny를 검증한다.
- 문서화는 구현/배포/보안 검증 완료가 아니다. 미검증 DDL·정밀도·상태 전이는 해당 티켓의 첫 작업으로 남기며 완료 체크를 앞당기지 않는다.

## 기존 앱 회귀와 재구성 효과 검증
- [ ] 기존 태그/계좌/종목/표 편집, 복수 계좌 집계, 외화·평가형·현금성, 직접 보정 흐름이 보존된다.
- [ ] 표 붙여넣기/검색/필터/이전 값/취소/전체 화면/일괄 저장/전후 CSV를 검증한다.
- [ ] 기존 전략의 모드별 목표·상세 원칙·적립금·한도가 새 위치에서 유지되고 공통 계산 결과가 MCP와 일치한다.
- [ ] 뉴스 직접 편집·자료 조회 및 활동 감사는 살아 있고 사용자 판단과 혼동되지 않는다.
- [ ] 승인된 화면 재배치와 회귀를 구분해 기존 URL, 내/친구 문맥, 필드별 공유·비공개를 점검한다.
- [ ] 360/390/768/1024/1440px에서 주요 흐름·긴 이름·빈 목록·누락 가격·미저장 이탈을 검증한다.
- 기능 수가 아니라 기존 대비 중복 입력·화면 왕복·불필요한 판단 부담이 줄었는지 전후 시나리오로 기록한다.
- 새 기능이 돌아가더라도 기존 데이터 손실·무단 공개·핵심 편집 회귀가 있으면 릴리스하지 않는다.

## 원칙 → 판단 → 할 일 → 실제 매매 통합 검증
- [ ] 사용자 원칙에 근거한 제안, 사용자 채택, 실행할 일, 분할 체결, 다음 점검이 연결된다.
- [ ] 조사할 일 → 근거 확인 → 판단 생성/대체 → 후속 점검을 검증한다.
- [ ] 유지 결정은 매매할 일 없이 저장 가능하고, 계획 없는 실제 매매는 선행 문서 없이 입력 가능하다.
- [ ] 할 일 취소는 체결을 취소하지 않으며 체결 정정은 실행 진행에 반영된다.
- [ ] 사용자는 개발 문서 용어를 배우거나 양식을 여러 번 작성할 필요 없이 대화로 흐름을 완료한다.

## 연속성 검증 — #44 연계
- #44 설계 및 #34/#35 구현을 바탕으로 2일 연속 점검, 며칠 후 복귀, 일부 실패, 반복 보도, 정정 기사, 질문 해결/재개를 검증한다.
- [ ] 어제 미확인한 종목이 오늘 조사 완료 상태로 잘못 승격되지 않는다.
- [ ] 웹/모바일 두 대화가 동시에 저장해도 오래된 실행이 최신 판단과 질문 상태를 덮어쓰지 않는다.
- [ ] 사용자가 보류/종료한 질문과 채택하지 않은 분석 의견이 모델에 의해 자동 결정/완료되지 않는다.
- [ ] 열린 질문이 실제 답/근거로 갱신되고 사용자가 같은 배경을 다시 설명할 필요가 줄었는지 평가한다.
- 파일럿은 사용자 요청 기반으로 진행한다. 자동 생성은 현재 범위에서 제외한다.

## 투자 기준 개인화 검증 — #43 연계
- 같은 뉴스에 장기/단기 목적, 낮은/높은 매매 빈도 선호를 적용하고 제안 근거가 기준을 실제 반영하는지 검증한다. 결론 차이를 억지로 요구하지 않는다.
- 기본값을 사용자 선택으로 처리하지 않는지, 기준 없음/상충 시 불확실성을 알리는지 확인한다.
- [ ] 앱·ChatGPT 양쪽의 기준 수정, 다음 분석 반영, 과거 분석 기준 보존과 사용자 격리를 검증한다.
- [ ] 사용자가 자신의 기준에 맞는 제안이라고 이해하는지 확인한다. 최종 검증에 #43 완료를 포함한다.

## 아침 가치 검증 보완
- 읽기 파일럿에서 #41 보유 이유와 #42 잔고 확인의 빈 상태 및 실제 입력 상태를 모두 다룬다.
- 대표 4개 결과(변화 없음/가설 재검토/자료 부족/오래 미확인)를 포함한다. 자료 부족일 때 근거 없는 안심을 주지 않는지 확인한다.
- 생성 대기 시간과 읽는 시간을 따로 기록한다. 약 60초 목표는 결과 읽기와 핵심 파악 시간이다.
- 화면 전환 횟수, 질문/확인 횟수, 중복 입력, 저장 누락/실패, 같은 뉴스 반복, 불필요한 매매 유도 여부를 기록한다.
- “오늘 신경 쓸 것을 알았는가”, “보유 이유를 다시 생각할 근거가 있었는가”, “다음 날 다시 사용하고 싶은가”를 짧게 확인한다.
- 앱 로그인이나 매매 횟수를 성공 지표로 삼지 않는다. ChatGPT에서만 점검을 끝낸 날도 정상 사용으로 집계한다.
- 5일 실사용 관찰 전에는 일일 습관 형성이 검증되었다고 판단하지 않는다.

## 목적
기능 존재보다 “매일 쉽게 확인하고 기록할 수 있는지”를 검증한다. 보안/계산 테스트는 각 구현 티켓에서 수행하고 이 티켓은 통합 검증을 담당한다.

## 범위
- 읽기 파일럿은 일일 문맥·저장·오늘 화면 완료 즉시 시작할 수 있다. 전체 릴리스는 매매/보정까지 검증한다.
- 실제 웹과 모바일, 소유자 2명으로 아침 점검→뉴스 조사→저장→앱 재열람을 수행한다.
- 매매 기록→중복 전송→수정/보정→다음 날 점검까지 테스트한다.
- 세션 만료·연결 해제·재연결, 데이터 없음/오래됨, 모호한 계좌, 악의적인 뉴스 본문을 점검한다.
- 데이터 격리는 소유자/친구 공유/토큰 MCP/직접 웹 RPC 경로를 함께 검증한다.
- 첫 결과까지 시간, 필요한 입력·확인 횟수, 도중 포기 이유를 수동 기록한다.
- 5회 출근 시 사용 기록을 바탕으로 60초 내 핵심 파악 목표와 입력 부담을 평가한다. 승인 없는 예약 작업/알림은 만들지 않는다.

## 완료 조건
- [ ] 테스트 날짜·클라이언트·케이스·관찰 결과와 실패 시 재현 방법을 남긴다.
- [ ] 사전에 정의한 사용자별 격리와 데이터 정합성 검증을 통과한다.
- [ ] 5일 결과 또는 아직 확보하지 못한 관찰을 명시하고 완료를 허위 처리하지 않는다.
- [ ] 알림·자동 분석·별도 skill 배포는 파일럿에서 확인된 필요에 따라 후속 티켓으로 결정한다.
