# [운영 개선] 사용자 전환과 비동기 조회 상태 격리

우선순위: P1 · 규모: 중 · 상태: 로컬 구현·검증 완료
상위: #40 · 연관: #45/#46/#47 · 권장 순서: 금융 쓰기 안정화 다음

## 근거와 발생 조건
- `src/App.jsx:111,197`: refreshState는 응답 소유자를 확인하지 않고 setState한다. 친구→본인 전환 뒤 늦은 친구 응답이 본인 문맥을 덮어쓸 수 있다.
- `src/features/review/DailyReviewPage.jsx:146`: 소유자 변경 시 이전 요청을 폐기하지 않으며 상세/연결 과제 상태도 남는다.
- `src/features/lifecycle/LifecyclePage.jsx`: 초기 effect는 active guard가 있지만 loadPage/openDetail에는 동일 보호가 없다.
- 서버 권한 우회가 확인됐다는 뜻은 아니다. 이전에 허용된 데이터가 잘못된 현재 화면에 표시되는 위험이다.

## 최소 변경 범위
- 조회 키에 로그인 사용자/선택 소유자/필터/커서를 포함하고 요청 세대 또는 취소로 이전 응답을 폐기한다.
- 소유자 변경 시 데이터·상세·커서·선택 상태를 초기화하고 해당 문맥 로딩이 끝나기 전 편집을 방지한다.
- 오늘의 목록·상세·관련 과제 실패를 분리해 이전 소유자 데이터와 새 데이터가 혼합되지 않게 한다.
- 로그아웃/토큰 갱신/bootstrap과 수동 전환의 상호작용을 확인한다.
- 기존 React 구조에서 필요한 작은 hook부터 적용한다. 전면 상태관리 도입은 필수가 아니다.

## 인수 조건
- [x] 친구 A→친구 B→본인 요청을 역순 완료시켜도 최종 문맥 데이터만 보인다.
- [x] 로그아웃 후 늦은 응답이 데이터나 상세 화면을 복구하지 않는다.
- [x] 상세 닫기/필터 변경/더 보기 도중 응답 역전이 목록을 섞거나 모달을 다시 열지 않는다.
- [x] 부분 조회 실패를 없음/성공으로 표시하지 않고 해당 영역 재시도로 복구한다.
- [x] 공유 권한 철회 후 새 요청은 차단되고 소유자 전환 시 이전 편집 상태가 남지 않는다.
- [x] 지연 응답을 제어하는 E2E로 검증하고 기존 입력·필터/스크롤 복귀를 보존한다.

## 구현 결과

- `fef165f`: 작은 request-generation gate를 앱, 오늘, 판단·할 일 목록/상세에 적용하고 문맥 전환 때 데이터·상세·편집 상태를 초기화했다.
- 연결 과제 조회 실패를 빈 목록과 분리했고, 상세 닫기와 로그아웃도 진행 중 응답을 무효화한다.
- `34f8512`: 공유 포트폴리오 응답을 지연시킨 채 본인으로 되돌아와도 늦은 공유 데이터가 나타나지 않는 E2E를 추가했다.
