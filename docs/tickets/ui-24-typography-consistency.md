# [공통 UX] 데이터 역할별 타이포그래피 기준과 전 영역 적용

2026-09-25 · Astra 설계 완료 · Sol 코드 구현·자동 검증 완료 · 실기기 확대 확인 대기 · P2

GitHub: https://github.com/kimyongin/fin/issues/135

## 목적

자산·배분·활동·원칙을 오가거나 상세를 열어도 같은 역할의 정보가 같은 크기·굵기·줄간격으로 보이게 한다. 작은 화면에서 핵심 이름/수치와 보조 정보를 쉽게 구분하면서 읽기 크기를 유지한다.

설계 정본: [타이포그래피 가이드](../design/typography-guidelines.md). 기존 모달·태그·타임라인·화면 구조의 배치/상호작용은 유지하고 글자 스타일의 충돌은 이 가이드로 해소한다. #134 자산 3열과 #128 태그의 역할별 표현을 유지한다.

## 실제 구현 조사와 문제

- `src/styles.css`에 글꼴은 있지만 역할별 글자 스타일은 없다. 조사 시 JSX에서 `text-sm` 276곳, `text-xs` 117곳이 사용됐다. 횟수 자체가 문제는 아니며 역할 판정 없이 서로 다른 크기가 선택된 것이 문제다.
- 소스 선언상 `AssetsPage.jsx`의 종목명/수량/평가금액은 14px, `PortfolioEntityIdentity.jsx`와 `Timeline.jsx`의 항목명은 16px다. 자산 평균가·현재가·수익률은 코드/시각과 같은 12px다.
- 소스 선언상 `PrincipleJournal.jsx`의 긴 마크다운은 14px이고 원칙 입력 전체에 monospace를 사용한다. 모달 폼 라벨은 12px, 피드백 라벨은 14px다.
- `AppHeader`/`PageControls`는 같은 탐색 역할을 폭에 따라 12/14px로 바꾼다. 일부 가이드/인증 화면은 별도 큰 제목·장식 자간을 사용한다.
- 전역 `font: inherit`가 Tailwind 역할 스타일을 덮을 가능성이 있다. 브라우저 computed style로 확인해야 하며 소스 클래스만 보고 실제 크기를 단정하지 않는다.
- 이 조사는 코드/문서 기준이다. 이번 설계 단계에 실제 화면·모바일 렌더링을 검증한 것은 아니다.

## 확정 계약

- 제목은 페이지 24px / 모달 20px / 섹션 18px / 항목 16px, 주요 값 16px·대표 합계 24px이다. 제목·주요 값은 600, 본문/입력은 16px·400이다.
- 라벨·버튼은 14px·600, 짧은 안내/평균가/현재가/수익률/환산액은 14px·400, 코드·날짜·읽기 태그는 12px·400이다. 정확한 줄간격과 맥락별 판정은 가이드 표를 따른다.
- PC/모바일에 같은 역할 크기를 사용한다. 숫자는 tabular-nums와 기존 포맷, 문단은 26px 줄간격, 코드만 monospace를 쓴다.
- 기본 폼·필터·날짜·select·표 셀 입력은 모두 16px다. 부모 button/label이 자식의 본문/입력 스타일을 바꾸지 않아야 한다.
- 오류/누락 시세/확인 영향 등 행동 판단에 필요한 문구를 12px 메타 정보로 분류하지 않는다. 기존 색/부호·접근성 의미는 유지하고 실제 대비를 확인한다.
- 가이드→공통 CSS→실제 소비 화면 순서로 적용한다. 범용 Text/Form/디자인 시스템 엔진이나 데이터 저장/API 변경은 필요 없다. 제품 MCP 출력은 웹 typography 대상이 아니며 MCP 가이드의 업무 의미 변경도 없다.

## 구현 순서: 작은 화면 흐름별 적용

### A. 공통 역할 + 자산 조회·편집

소비 시나리오: 자산 목록에서 보유와 평가를 읽고 종목 상세의 값을 편집한다.

- `styles.css`에 역할 스타일을 만들고 AppHeader·ModalShell·ModalActions에서 바로 소비한다. 전역 font 상속의 cascade를 확인·정리한다.
- 자산 요약/종목·보유·평가 3열/계좌 선택·검색/상세/계좌·보유 등록/표 편집에 적용한다. 이름·수량·평가액은 16px, 가격·수익률은 14px, 코드·태그는 12px다.
- 원화·외화·소수 수량·큰 금액·긴 이름/태그·누락 시세로 폭을 검사하고 2차 확인창까지 같은 글자 역할을 사용한다.
- 종료 조건: 실제 목록→상세→입력→확인→복귀와 표 편집에서 역할/가독성/폭을 검증한다. CSS 정의만 만든 상태로 기반 완료 처리하지 않는다.

### B. 배분·활동·원칙과 공통 태그/타임라인

소비 시나리오: 태그별 비중 비교·목표 입력, 할 일/기록 조회·편집, 원칙 읽기·변경 이력 확인.

- 배분 태그명/현재·목표·차이, 활동 필터/목록/상세·관련 대상·반복 일정, 원칙 현재/이력/편집을 가이드에 맞춘다.
- TagChip/TagManagerModal/Timeline/MarkdownContent와 그 소비자를 함께 정리한다. 조작 태그 14px와 읽기 태그 12px, 태그 제목 16px의 의도적인 역할 차이는 유지한다.
- 긴 원칙/기록 본문 16px·26px 줄간격을 적용하고 마크다운 입력의 전체 monospace 및 inline code 축소를 정리한다.
- 종료 조건: 두 태그 관리자, 두 타임라인, 기록/할 일 상세·편집과 원칙의 현재/과거 본문을 확인한다. 전역 스타일 변경으로 A가 달라졌다면 해당 대표 화면도 재확인한다.

### C. 보조 화면·전수 대조와 최종 검증

- 설정/공유, 연결 가이드, 피드백/관리, 로그인/공유 진입/OAuth 동의, 앱 오류/로딩/권한 안내를 적용한다.
- 남은 크기·굵기·줄간격·font 상속을 검색하고 아래 적용표에서 도달 가능한 모든 화면을 대조한다. 표에 없는 실제 소비자는 추가한다. 비활성 파일은 import/진입 근거와 함께 구분한다.
- 소스의 직접 스타일을 무조건 0개로 만들지 않는다. 역할 정의·코드 예외 밖의 임의 값이 남으면 이유를 기록한다.
- 종료 조건: 적용표의 모든 활성 경로가 검증되거나 명시적인 미검증으로 남아 있고, 전수 완료 여부를 사실대로 보고한다.

슬라이스별 구현·검증 후 범위가 분리되는 커밋을 만든다. 현재 작업 트리에는 이전 작업의 많은 변경이 있으므로 사용자 로컬 설정이나 무관한 변경을 함께 stage하지 않는다. 푸시·운영 배포는 별도다.

- [x] 자산 행의 이름·수량·가격·코드, 검색 입력, 상세 제목, 계좌/활동 모달 입력의 computed size/weight/line-height가 가이드와 일치한다. 자산 행 검사는 `document.fonts.ready` 뒤에 실행한다. OS fallback의 실제 글꼴 렌더링은 별도 실기기 확인 대상이다.

## 구현·검증 기록

- 공통 CSS 역할을 실제 컴포넌트와 화면에 적용했다. 전역 `font: inherit` 충돌을 정리하면서 입력·버튼의 글꼴 상속은 유지했다. 자산 검색창이 버튼 역할과 입력 역할을 함께 받아 실제로 14px로 보이던 문제는 역할을 분리해 16px로 고쳤다. 밝은 주황색 버튼의 글자를 짙은 색으로 바꿔 대비를 개선했다.
- `npm test`: 20개 파일, 98개 통과. `npm run build`: 통과(인코딩 검사 543개 파일 포함). 격리된 E2E는 DB 46개 파일·558개 검사, MCP/배포 준비 계약, Playwright 67개가 최종 재실행에서 모두 통과했다. 첫 전체 실행의 활동 태그 검색 1건은 단독·전체 재실행에서 재현되지 않았으며 검색 입력값 assertion을 보강했다.
- 360/390/768/1024/1440px에서 주요 탐색·자산 3열·계좌/활동 모달을 검사했다. `test-results/modal-visual-*/`의 390/1024px 캡처를 직접 확인했고, 긴 종목명/외화·현금·시세 누락은 자산 목록 E2E에서 다뤘다. 캡처는 테스트 산출물이며 저장소에 추가하지 않았다.
- 브라우저 200% 확대, 실제 모바일 기기의 폰트 대체/키보드, 모든 오류·공유 읽기 조합의 시각 검수는 아직 수행하지 않았다. 자동 테스트 통과를 이 항목의 완료로 대체하지 않는다.
- 다른 작업의 변경과 사용자 로컬 설정이 많은 동일 작업 트리에 있으므로 혼합 커밋을 만들지 않았다. 푸시·운영 배포도 수행하지 않았다. 구현과 검증 결과를 GitHub #135와 동기화한다.
