# [MCP 개선] 시나리오 평가와 실제 계약·배포 게이트 보강

우선순위: P1 · 상태: 미착수 · 작성: 2026-09-21
상위: #40 · 시나리오/연관: S05~S24 · W01~W08 · #39/#48/#51 후속
선행/통합: 평가 fixture는 즉시 작성, 01~04 구현 뒤 통합 검증

## 목적

ChatGPT가 추측 없이 Portfolio 도구를 선택·사용·복구하고, 운영자가 계약 변경을 안전하게 유지할 수 있게 한다. ChatGPT는 조사·해석·설명, Portfolio는 기억·계산·검증을 담당한다.

## 검토 근거

- 기존 계약 smoke는 initialize/list/profile/필수 입력 누락 중심이며 실제 저장→재조회 시나리오는 보장하지 않는다.
- 운영 readiness는 목록 RPC 3개만 확인하고 새 RPC·MCP 계약은 확인하지 않는다.
- test-e2e.mjs에는 pgTAP 실행이 없어 DB test 실패가 Pages gate에 연결되었다는 기존 완료 주장과 차이가 있다.

## 작업 범위

- MCP→DB→웹 흐름의 대표 fixture를 만들고 단위/schema 검사와 실제 업무 검증을 구분한다.
- 분석만/점검 후 저장/매수 검토/실제 체결/계획 취소/잔고 보정/부분 조사 실패/두 계좌 모호성/응답 유실/외부 콘텐츠 악성 지시의 기대 호출·금지 효과를 정한다.
- 모델 선택 평가는 별도 계층으로 관리한다. 사용 모델·클라이언트·날짜·호출과 실제 상태 변화를 기록하며 자동 결정론 테스트 통과를 ChatGPT 성공으로 대체하지 않는다.
- 격리 DB에서 실제 DB test와 Edge/계약/E2E를 같은 커밋 gate로 연결한다. 필요한 RPC·응답과 MCP discovery/read를 인증된 전용 계정으로 확인한다.
- 누락 RPC, 잘못된 응답, 미배포 Edge, DB test 실패를 주입해 배포 차단을 검증한다. E2E 파일 동기화는 기존 사본의 오래된 내용도 탐지하고 실패 artifact/정리를 검증한다.
- readiness에서 운영 사용자 데이터에 쓰지 않는다. 운영 배포·계정/secret 설정·유료 모델 평가 실행은 별도 승인과 환경 준비 범위다.
