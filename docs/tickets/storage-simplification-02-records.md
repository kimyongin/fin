# [저장 단순화] 조사·판단·점검·회고를 활동 결과로 통합

## 목적

사용자 기능에 필요한 최소 저장·처리만 유지하고 기존 데이터와 공개 범위를 보존한다. 기존 구현의 존재는 유지 근거가 아니다.

## 인수 조건

- [ ] 활동의 최소 분류(점검·조사·매매·회고 등)를 앱/MCP가 기본 지정하고 오늘 조회·회고 집계에 사용한다. 자유 태그와 구분하며 일반 등록에서 사용자 필수 선택이나 분류별 상태 엔진을 만들지 않는다. 금융 분류 지정만으로 서버 변경 사실을 위조할 수 없어야 한다.
- [ ] 활동 삭제는 보유값과 할 일 상태를 바꾸지 않는다. 삭제 기록은 검색/임베딩에서 제거하고 기존 회고 본문은 자동 재작성하지 않는다. 계좌·종목·할 일 삭제 뒤에도 남은 활동의 대상 설명은 읽을 수 있어야 한다.

- [ ] 판단·뉴스·브리핑·리포트를 activity_events 기반으로 저장/편집/검색한다. 내용·결론·출처·조사 범위·기간의 최소 필드를 검증한다. 별도 수정 이력/근거 연결 테이블을 새로 만들지 않는다.
- [ ] 조사/판단 한 건 저장→재조회부터 구현한 뒤 점검→오늘, 기간 회고를 차례로 연결한다. 새 활동과 이미 있는 자동 대표 활동을 ID로 매핑해 중복 없이 표시한다.
- [ ] 오늘 화면은 최신 점검 활동·미확인 범위·열린 할 일을 표시한다. 별도 자료 메뉴와 판단 전용 등록/조회 도구를 활동으로 대체한다. 기존 URL은 새 상세로 안내한다.
- [ ] daily_review_contexts 영구 저장/TTL 의존을 제거하고 문맥을 조회한다. 분석 기준 시각을 남기고 조사 실패/변화 없음/오래된 분석을 구분한다.
- [ ] 리포트는 기간·작성시각·근거가 있는 활동이다. 별도 revision/자동 stale 판정 제거, 원본 페이지 전체 조회 및 요약 자체의 재집계 제외를 검증한다.
- [ ] 기존 상태/출처/당시 원칙/관계/원문을 이관 또는 읽기 가능한 보관으로 보존한다. 타인 데이터·이전 비공개 증거 노출 차단, 태그/키워드/의미 검색과 편집 반영을 검증한다.
- [ ] 웹·MCP·get_workflow_guide와 영향 manifest를 함께 갱신한다. 관련 구 RPC/테이블 제거 목록과 남은 소비자를 06에 인계한다.

## 구현 방식

관련 DB/API·MCP/UI·가이드·검증을 수직 슬라이스로 연결하고 슬라이스마다 커밋한다. 일반 코드 구현/배포는 이 티켓 작성에 포함하지 않는다. 미정 세부 기술 선택은 위 범위 안에서 구현자가 근거를 기록해 확정한다. 제품 기능 축소 범위를 추가로 넓히면 먼저 영향과 대안을 명시한다.
