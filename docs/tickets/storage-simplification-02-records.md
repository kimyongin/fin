# [저장 단순화] 조사·판단·점검·회고를 활동 결과로 통합

상태: 로컬 구현·회귀 검증 완료; 운영 배포·실제 ChatGPT 평가 대기 · 2026-09-23
GitHub: https://github.com/kimyongin/fin/issues/87
선행: 01
시나리오: S5/S6/S7/S9/S10
기준: docs/engineering/SIMPLICITY.md, docs/adr/0008-minimal-portfolio-storage.md, docs/design/minimal-portfolio.md

## 목적

사용자 기능에 필요한 최소 저장·처리만 유지한다. 구 투자 행의 이관은 사용자가 면제했지만 새 데이터의 비공개/공유 경계는 지킨다. 기존 구현의 존재는 유지 근거가 아니다.

## 인수 조건

- [x] 활동의 최소 분류(점검·조사·매매·회고 등)를 앱/MCP가 기본 지정하고 오늘 조회·회고 집계에 사용한다. 자유 태그와 구분하며 일반 등록에서 사용자 필수 선택이나 분류별 상태 엔진을 만들지 않는다. 금융 분류 지정만으로 서버 변경 사실을 위조할 수 없어야 한다.
- [x] 활동 삭제는 보유값과 할 일 상태를 바꾸지 않는다. 삭제 기록은 검색/임베딩에서 제거하고 기존 회고 본문은 자동 재작성하지 않는다. 계좌·종목·할 일 삭제 뒤에도 남은 활동의 대상 설명은 읽을 수 있어야 한다.

- [x] 판단·뉴스·브리핑·리포트를 activity_events 기반으로 저장/편집/검색한다. 내용·결론·출처·조사 범위·기간의 최소 필드를 검증한다. 별도 수정 이력/근거 연결 테이블을 새로 만들지 않는다.
- [x] 조사/판단 한 건 저장→재조회부터 구현한 뒤 점검→오늘, 기간 회고를 차례로 연결한다. 새 활동과 이미 있는 자동 대표 활동을 ID로 매핑해 중복 없이 표시한다.
- [x] 오늘 화면은 최신 점검 활동·미확인 범위·열린 할 일을 표시한다. 별도 자료 메뉴와 판단 전용 등록/조회 도구를 활동으로 대체한다. 기존 URL은 새 상세로 안내한다.
- [x] daily_review_contexts 영구 저장/TTL 의존을 제거하고 문맥을 조회한다. 분석 기준 시각을 남기고 조사 실패/변화 없음/오래된 분석을 구분한다.
- [x] 리포트는 기간·작성시각·근거가 있는 활동이다. 별도 revision/자동 stale 판정 제거, 원본 페이지 전체 조회 및 요약 자체의 재집계 제외를 검증한다.
- [x] 삭제 허용된 구 투자 행의 이관/원문 보관은 완료 조건에서 제외한다. 새 기록의 타인 데이터·비공개 증거 노출을 차단하고 태그/키워드/의미 검색과 편집 반영을 검증한다.
- [x] 웹·MCP·get_workflow_guide와 영향 manifest를 함께 갱신한다. 구 RPC/테이블 제거와 남은 예외는 06 및 운영 인계 문서에 기록한다.

## 구현 방식

관련 DB/API·MCP/UI·가이드·검증을 수직 슬라이스로 연결하고 슬라이스마다 커밋한다. 일반 코드 구현/배포는 이 티켓 작성에 포함하지 않는다. 미정 세부 기술 선택은 위 범위 안에서 구현자가 근거를 기록해 확정한다. 제품 기능 축소 범위를 추가로 넓히면 먼저 영향과 대안을 명시한다.

## 진행 기록

이하는 시간순 중간 상태다. 뒤의 퇴역/전환 슬라이스가 앞선 임시 호환 문구를 대체한다. 최종 로컬 계약은 `docs/design/storage-release-readiness-20260923.md`와 schema overview를 따른다. 운영/ChatGPT 실사용은 별도다.

- 첫 수직 슬라이스: `activity_events.record_kind`로 현재 활동을 분류하고, 수동 조사·점검·판단·회고의 선택적 출처/범위를 같은 행의 `after_data.context`에 보관한다. 기존 분류는 자동 백필하고 새 자동 사건은 서버 트리거가 분류한다. 별도 근거/분류 테이블을 만들지 않는다.
- MCP `record_manual_activity`와 웹 활동 추가에 분류를 선택 사항으로 연결한다. 기본값은 일반이며, 금융·태스크 종류는 수동 저장할 수 없다.
- 기존 친구 공유 범위가 새 사적 조사·점검·판단·회고를 뜻하지 않으므로 상세·타임라인·최근·키워드·의미 검색에서 이 종류는 소유자만 볼 수 있게 사전 필터링한다. 프로필·전략과 같은 별도 상세 권한은 이후 제품 결정 전까지 확대하지 않는다.
- 단일 pgTAP 시나리오로 소유자 저장·재조회, 허위 금융 분류 거절, 친구의 검색·상세·타임라인 접근 차단을 검증한다. 기존 분리 저장소를 옮기거나 제거하는 작업과 삭제/회고 계약은 뒤 슬라이스로 남겨둔다.
- 다음 슬라이스: 수동 활동의 분류와 출처/범위를 같은 행에서 정정한다. 자동 금융·할 일 사건의 분류/문맥 편집은 거부한다. 소유자 상세 화면에서 분류와 HTTP(S) 출처를 보여주고 수동 분류만 고칠 수 있게 한다.
- 웹의 새 자료 입력과 햄버거 `자료` 메뉴를 제거한다. 새 조사는 활동으로 등록한다. 이전 `#news` 주소와 기존 기록의 조회·정정·삭제는 이관 전까지 유지하고, 활동에서 이전 자료로 이동할 수 있게 한다. 아직 `news_facts` 이관이나 구 RPC 제거가 끝난 것은 아니다.
- 사용자가 직접 만든 활동의 삭제는 같은 `activity_events` 행을 삭제 상태로 전환하며 내용을 비우고 태그·임베딩을 제거한다. 행 ID는 연결된 후속 할 일/기존 회고의 참조를 위해 남긴다. 자동 금융·할 일 완료 사건은 이 도구로 삭제하지 않으며, 삭제가 보유값이나 할 일 상태를 바꾸지 않는다. 레거시 별도 기록 저장소의 삭제/이관은 여전히 남아 있다.
- 새 활동 등록 화면에서 선택적 조사 범위와 HTTP(S) 출처 한 건을 입력할 수 있게 한다. 기존 `after_data.context`를 사용하므로 새 테이블은 없고, 여러 출처가 필요하면 MCP의 구조화된 context를 사용할 수 있다.
- 새 OAuth MCP `tools/list`에서 구 `get_news_state`를 숨긴다. 기존 세션 호출과 일일 문맥의 이전 뉴스 복사본은 데이터 이관 전까지 유지한다. 새 조사는 활동 검색·기록으로 안내한다.
- 최신 사용자 허용 범위에 따라 기존 뉴스 행은 이관하지 않는다. 구 `#news`는 활동으로 이동하고 별도 뉴스 UI/DB 테이블·쓰기 RPC·OAuth 및 토큰 MCP 도구를 제거했다. 새 조사는 활동의 `research` 분류·출처로 저장한다. 옛 일일 문맥 기저 함수가 요구하는 빈 `saved_news` 키/조회 함수만 점검 문맥 재작성 전까지 남긴다. 새 사용자 연구 결과는 소유자 전용이다. 격리 DB, OAuth/토큰 MCP 계약, Chromium 34개 시나리오, unit/build를 통과했다. 일반 로컬/운영 DB는 아직 변경하지 않았다.
