## 목적

사용자 기능에 필요한 최소 저장·처리만 유지한다. 기존 투자 데이터는 삭제 가능하지만 새 데이터의 인증·격리·공유·금융 안전성은 유지한다. 기존 구현의 존재는 유지 근거가 아니다.

## 현재 인계

아래 진행 항목은 시간순 기록이며 앞선 임시 유지/대기 상태는 뒤의 완료 슬라이스가 대체한다. 최신 상태는 `docs/design/storage-release-readiness-20260923.md`와 `supabase/schema/OVERVIEW.md`를 우선한다.

- 사용자 최신 결정(2026-09-23): 기존 투자 데이터 전체 삭제를 허용한다. 구 행 보존·이관·기존 세션 호환은 필수 조건에서 제외한다. 새 사용자 데이터의 인증·격리·공유 구조와 기능은 유지하며, 삭제 전 코드 소비자를 제거한다. 운영 DB 배포는 별도 게이트다.
- 첫 물리 정리 슬라이스: 운영에는 없고 로컬/E2E에만 있던 구 ToDo 묶음 7개 테이블과 전용 RPC를 증분 migration으로 제거했다. 이전 이관 migration의 general task/활동 기록은 유지하고, 열린 조사 할 일 조회가 구 item 테이블에 의존하지 않도록 수정했다. 격리 테스트 결과는 아래 검증 기록으로 갱신한다.
- 검증: 격리 E2E에서 migration 적용, DB 37개 파일/562개 assertion, OAuth·토큰 MCP 계약 및 Chromium 34개 시나리오 통과. 마이그레이션은 일반 로컬/운영 DB에 적용하지 않았다. 기존 구 묶음 작성 테스트는 삭제 계약·공개 점검 API에서의 열린 할 일 조회 테스트로 교체했다. 내부 전용 함수를 `authenticated` 역할로 직접 호출한 테스트는 잘못된 권한 경로여서 제거했다.
- 다음 물리 정리: 운영·로컬 모두 행 수 0인 매매 되돌리기 preview/reversal/receipt 3개 테이블과 전용 RPC를 제거했다. trade_entries의 이전 취소 표시 필드와 매매/절대 보정 경로는 남긴다. 격리 DB 37개 파일/553개 assertion, MCP 계약, Chromium 34개 시나리오 통과. 일반 로컬/운영 미적용.
- 보유 이유 정리: 운영·로컬 모두 행 수 0인 구 thesis/history/task-link/receipt 5개 테이블, 전용 RPC 및 포지션 종료 트리거를 제거했다. 비공개 보유 메모·현재 점검 문맥은 유지한다. 격리 DB 35개 파일/536개 assertion, MCP 계약, Chromium 34개 시나리오 통과. 일반 로컬/운영 미적용.
- 운영 규칙 정리: 구 규칙/history/receipt 3개 테이블과 전용 DB/MCP CRUD를 제거하고, 사용자가 승인한 워크플로 규칙은 `kind=operation`·scope가 있는 원칙 한 행의 revision으로 읽고 쓴다. 기존 구 규칙은 선행 원칙 migration에서 복사된다. 격리 DB 35개 파일/525개 assertion, MCP 계약, Chromium 34개 시나리오 통과. 일반 로컬/운영 미적용.
- 개인 정책 정리: 구 profile/history/receipt 3개 테이블과 전용 DB/MCP CRUD를 제거한다. 기존 서술형 필드는 선행 원칙 migration에서 복사했고, 현재 `restrictions` 배열의 각 승인 문구는 삭제 migration에서 `preference`/`prohibition` 원칙 행으로 복사한다. 구 snapshot에 개별 제한 항목의 안정 ID가 없어 항목별 과거 이력은 추정하지 않는다. 점검 문맥의 구 `investment_policy` 복사본도 제거하고 `principles.items`를 정본으로 유지한다. 격리/운영 적용 상태는 검증 기록과 구분한다.
- 사용되지 않는 구 출력 정리: 2026-09-23 조사에서 운영 0건·로컬 부재였고 현재 코드 소비자가 없는 `transactions`, `portfolio_snapshots`, `daily_reports`, `rebalance_suggestions` 4개 테이블을 조건부 제거한다. 적용 당시 행이 하나라도 생겼으면 migration 전체를 실패시켜 별도 대조한다. `sync_runs` 등 실제 소비자가 있는 운영 기록은 유지한다. 격리 DB 36개 파일/519개 assertion, MCP 계약, Chromium 34개 시나리오 통과. 일반 로컬/운영 미적용.
- 이전 게이트 해소: 기존 뉴스 2건 및 금융 원장/검증 기록은 사용자가 삭제를 허용했으므로 내용 이관은 요구하지 않는다. 다만 `#news` 등 구 화면과 DB/Edge 소비자는 새 활동 경로로 이전하고 새 데이터의 소유권·공유 경계는 검증한다.
- 자료 정리 슬라이스: 구 뉴스 팩트/의견 2개 테이블과 쓰기 RPC·토큰 MCP를 제거했다. `#news`는 활동으로 이동한다. 일일 문맥 기저 함수의 빈 `saved_news` 호환 응답은 이후 점검 구조 단순화에서 제거한다. 격리 DB·OAuth/토큰 MCP 계약·Chromium 34개 시나리오·unit/build 통과. 일반 로컬/운영 미적용.
- 회고 정리 슬라이스: 별도 활동 리포트/리비전/영수증 3개 테이블과 저장·목록 RPC/MCP를 제거한다. 기간 원본 조회는 유지하고 회고 저장/조회는 `retrospective` 활동·통합 검색으로 처리한다. 기존 리포트 행은 사용자 결정에 따라 이관 없이 삭제할 수 있다. 검증 상태는 실행 결과로 갱신한다.
- 후속 집계 수정: `get_activity_report_context`는 회고 활동을 기간 원본에서 제외해 다음 주·월 회고가 앞선 요약을 실제 행동으로 다시 세지 않게 한다.
- 연결 확인용 `chatgpt-mcp-probe`는 포트폴리오 데이터·인증 기능이 없는 실험 endpoint이며 레포 내 호출자가 없다. 소스와 로컬 function 설정에서 제거했다. 이미 배포된 원격 endpoint 제거는 배포 단계에서 별도로 확인한다.
- 검증 완료: 회고 정리 뒤 unit 19파일/103건, 격리 DB 테스트, OAuth/토큰 MCP 계약, Chromium 34건, 웹 빌드, 인코딩·워크플로 가이드 검사 통과. 보통 로컬/원격 DB에는 증분 migration 미적용. `deno` 미설치로 독립 Edge 타입 검사는 미실행.

## 당시 수직 슬라이스 계획(로컬 전환 전 작성)

1. 판단: 신규 판단은 `decision` 활동과 선택 후속 할 일로 읽고 쓴다. 명시적 채택과 모델 제안을 활동 내용에서 구분한다. 친구 공유의 기존 `decisions` grant가 조용히 사라지지 않게 권한 계약을 정리한 다음 UI·MCP·DB 소비자를 전환하고 구 결정/상태/연결 저장소를 퇴역한다.
2. 점검: 현재 문맥을 저장 없이 읽고, 요청한 점검은 `review` 활동으로 저장한다. 오늘 화면은 마지막 점검 활동과 열린 할 일을 표시한다. 조사 실패/미확인과 변화 없음, 출처와 확인 범위, 소유자/친구 접근을 회귀 검증한 뒤 문맥 snapshot 및 브리핑 하위 테이블을 종료한다.
3. 할 일·금융: 조사 전용 상태·실행 계획·history를 단순 할 일/수행 활동으로 축소한다. 금융 현재값과 계산을 정본으로 유지하면서 저장 preview/reversal/세부 검증 원장의 실제 소비자를 없앤다. 중복 매매·동시 편집·초과 매도·절대 보정은 계속 서버에서 막는다.
4. 공유·MCP·릴리스: 기능별 grant와 통합 활동 DTO를 대조한다. 구 토큰 MCP의 실제 사용 여부를 확인하고 중복 도구를 정리한다. 전체 테이블/RPC/도구 수 전후와 대표 웹·MCP 흐름을 검증하고, 운영 배포 요청 시 DB→Edge→웹 순서로 적용한다. 기존 데이터 복구/이관은 새 요구가 아니다.

위 항목은 당시 계획이다. 현재 로컬 전환·전체 회귀는 아래 최종 진행 기록과 운영 인계에 반영했다. 원격 배포·실제 ChatGPT 모바일 평가는 별도다.
- 개발 환경 게이트: `npm run check:edge`는 이 PC에 `deno` 실행 파일이 없어 시작하지 못했다. 독립 E2E의 실제 Edge 호출과 웹 테스트는 별도로 통과했지만 타입 검증을 통과했다고 표시하지 않는다.

- 앱의 구 개인 정책/운영 규칙/보유 이유 UI 데이터 어댑터와 새 자료 등록 경로를 제거했다. 새 OAuth MCP 목록에서는 구 정책·보유 이유·뉴스 조회 및 매매 취소 도구를 숨겼다. 기존 핸들러와 DB RPC는 이전 세션/데이터 이관 전 호환을 위해 남아 있다.
- 기존 `news_facts`는 친구 공유 가능하지만 새 조사 활동은 소유자 전용이다. 이 둘을 물리 통합할 때 과거 공개 범위를 좁히거나 새 비공개 내용을 노출하지 않는 매핑을 먼저 검증해야 한다. 본문 길이·주석·원본 출처와 당시 날짜도 누락 없이 대조한다.
- `portfolio_tasks.origin_event_id`와 이전 ToDo 매핑은 활동 ID를 참조한다. 수동 활동 삭제는 행 ID를 유지하는 tombstone으로 구현했고 검색·임베딩·중복요청 원문을 정리한다. 자동 금융/완료 활동은 이 삭제 계약에서 제외한다.
- 격리 E2E에서 37개 DB 파일/580개 assertion, OAuth/토큰 MCP 계약, Chromium 34개 시나리오가 통과했다. 일반 로컬 DB/운영 DB에는 이번 증분 migration을 적용하지 않았다. GitHub 티켓 상태, 원격 배포와 실제 ChatGPT 웹·모바일 평가는 별도로 검증해야 한다.
- 다음 우선순위는 위의 남은 수직 슬라이스를 따른다. 구 데이터 이관은 더 이상 필수가 아니다. 운영 DB 삭제·배포를 로컬 테스트 통과만으로 수행하지 않는다.
- 점검 전환 진행(2026-09-23): `review` 활동을 기준으로 오늘 화면과 OAuth MCP 조회를 연결했다. `list_review_activities`는 명시적 `briefings` grant만 허용하고 비공개 메모·문맥·출처는 공유하지 않는다. 새 저장은 기존 `record_manual_activity(category=review)`를 사용하도록 가이드를 전환했다. 구 브리핑 도구는 새 OAuth 목록에서 빠졌으나 구 DB 저장소·문맥의 브리핑 소비자 제거와 물리 삭제는 아직 남았다. 격리 DB 37파일/516검증, MCP 계약, Chromium 34건, 단위 19파일/95검증, 빌드 통과. 운영·일반 로컬 DB에는 적용하지 않았다.
- 다음 물리 정리의 의존 관계: `investment_decisions.source_briefing_id`가 구 브리핑 FK이고, `app_create_daily_context` 래퍼 체인은 `daily_review_contexts`에 snapshot을 여러 번 갱신한다. 판단 저장을 활동으로 전환하고 일일 문맥을 저장 없는 현재 조회로 대체하기 전에는 브리핑 테이블만 단독으로 삭제하지 않는다. `app_list_briefing_related_tasks` 및 구 공유 DTO도 함께 종료해야 한다.
- 판단 전환 진행(2026-09-23): 새 OAuth MCP의 판단 전용 CRUD/상태전이 도구를 목록에서 제거하고 `record_manual_activity(category=decision)`·`list_decision_activities`·`get/update_activity`·선택 후속 `save_general_task`로 가이드를 전환했다. 앱의 옛 `#decisions` 경로는 판단 활동을 읽고 수동 입력에서 제안/명시적 채택을 구분한다. 친구 `decisions` grant는 좁은 목록에서 상태만 공개하고 사유·메모·출처는 숨긴다. 구 테이블/함수와 `#tasks` 안의 구 판단 상세 소비자는 아직 남아 있어 물리 종료 전환은 완료가 아니다. 격리 DB 37파일/519검증, unit 19파일/96검증, OAuth/토큰 MCP 계약, Chromium 35건, 빌드·인코딩·가이드 검사를 통과했다. 일반 로컬/운영 미적용.
- 점검 문맥 전환 진행(2026-09-23): `get_daily_context` MCP 도구를 저장형 `app_create_daily_context` 대신 읽기 전용 `app_get_daily_context`로 연결한다. 현재 자산·원칙·비공개 보유 메모·열린 할 일과 최근 점검/판단 활동을 조합하며 문맥 행을 만들지 않는다. 구 저장형 문맥 RPC/테이블은 구 브리핑 저장과 DB 테스트가 아직 사용하므로 물리 종료 전 별도 차단·교체가 필요하다. 격리 DB 37파일/521검증, OAuth/토큰 MCP 계약, Chromium 35건, unit 19파일/96검증, 빌드·인코딩·가이드 검사 통과. 일반 로컬/운영 미적용.

## 구현 방식

관련 DB/API·MCP/UI·가이드·검증을 수직 슬라이스로 연결하고 슬라이스마다 커밋한다. 일반 코드 구현/배포는 이 티켓 작성에 포함하지 않는다. 미정 세부 기술 선택은 위 범위 안에서 구현자가 근거를 기록해 확정한다. 제품 기능 축소 범위를 추가로 넓히면 먼저 영향과 대안을 명시한다.
