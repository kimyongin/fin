# [공통 UX] 목록 아이콘 액션·마크다운 읽기·모바일 스크롤 안정화

상태: 설계 완료 · 구현 전 · 2026-09-28
GitHub: https://github.com/kimyongin/fin/issues/167

## 목적과 근거

모바일 목록 스크롤 중 편집 모달이 열리는 실수를 없애고, 활동을 읽는 목적과 수정하는 목적을 분명히 구분한다. 모든 도달 가능한 목록에 같은 아이콘·터치·복귀 기준을 적용하고 활동 목록의 가로 넘침을 해결한다.

코드 조사에서 AssetsPage의 자산 행, StrategyPage의 배분 제외 행, TimelineEntry의 활동/원칙 내용 영역이 큰 button이다. ActivityNarrative는 기본적으로 원문을 표시하고, MarkdownContent는 단순 제목·목록·강조·링크만 처리하여 표/코드/중첩 목록이 부족하다. 터치 오인식의 실제 이벤트 원인과 넘침의 정확한 부모 요소는 구현 시 모바일 재현으로 확정한다. 넓은 클릭 영역이 있다는 사실만으로 브라우저 결함을 단정하지 않는다.

정본: [목록 가이드](../design/list-interaction-guidelines.md), [모달](../design/modal-guidelines.md), [타이포그래피](../design/typography-guidelines.md), [타임라인](../design/timeline-guidelines.md). 기존 #119/#123/#140의 행 전체 클릭/읽기·편집 일괄 통합 요구는 이 티켓의 명시적 읽기 경로에 한해 대체한다. 편집 폼의 직접 편집·단일 저장과 2차 확인 전용 규칙은 유지한다.

## 화면별 적용표

아래는 구현 예정이며 완료 표가 아니다. 구현자는 각 행에 적용/검증/예외 증거를 추가한다.

| 목록 | 목표 동작 |
| --- | --- |
| 활동 할 일·날짜별 기록 | 행/제목 클릭 제거. 오른쪽 문서·연필 아이콘. 설명/본문을 읽기에서는 마크다운, 편집에서는 원문으로 표시. 완료·이번 완료·중단은 기존 명시적 버튼 유지 |
| 활동 검색 결과·연결된 항목 | 일반 목록과 같은 읽기/편집 진입. 검색 근거·점수·필터·페이지·스크롤 유지. #162 미구현 맥락 확장을 이 작업에 포함하지 않음 |
| 자산 종목·0보유 목록 | 행 클릭 제거, 소유자는 연필로 기존 직접 편집 상세 진입. 공유는 문서 아이콘으로 읽기 상세. 기존 종목/보유/평가 정보와 계좌별 편집 유지 |
| 배분 제외 보유 목록 | 자산 목록과 동일한 아이콘으로 해당 자산 상세 진입 |
| 배분 태그별 목표 목록 | 기존 목표 인라인 입력 유지. 불필요한 상세 모달/연필을 추가하지 않음. 숫자·버튼·제목 넘침 확인 |
| 원칙 변경 이력 | 행 클릭 제거. 문서로 당시 본문 읽기, 권한이 있으면 연필로 해당 이력 정정 진입. 현재 원칙 새 변경과 과거 행 정정을 구분. 최신 원칙은 이미 본문이 보이므로 읽기 중복 버튼 없음 |
| 설정의 친구·열람자·계좌 관련 목록 | 본문 클릭으로 편집/이동하지 않음. 기존 보기 진입은 문서 아이콘, 편집이 실제 제공되는 곳만 연필. 연결 해제 등 독립 행동과 권한 유지 |
| 피드백 목록 | 이미 보이는 본문을 위해 새 읽기 모달을 만들지 않음. 본인 수정은 연필, 삭제/관리자 처리 권한과 기존 직접 편집 유지 |
| 태그 관리·참조 자동완성·프로필/메뉴 목록 | 선택 컨트롤이라는 명시적 예외. 기존 선택/전환을 유지하며 강제로 읽기/편집 버튼을 추가하지 않음 |
| 표 편집 | 셀 직접 편집과 내부 가로 스크롤 유지. 일반 조회 목록으로 확장하지 않음 |

## 최소 구현 계약

- 문서/연필은 목록 항목의 읽기/편집 전용이며 작고 중립적인 동일 스타일을 사용한다. 44×44px 터치 영역, 접근성 이름(예: `기록 읽기: 투자 심리`, `기록 편집: 투자 심리`), 키보드 초점을 제공한다. 아이콘 버튼을 행 button 안에 중첩하지 않는다.
- 활동 읽기는 제목·날짜·일정/태그·관련 종목/할 일과 본문을 현재 권한에 따라 표시한다. 빈 본문, 삭제된 연결, 오류/로딩도 읽기 상태에서 처리한다. 읽기에는 저장/완료 부작용이 없다.
- 읽기 → 편집은 같은 1차 모달 전환이다. 저장하면 새 내용을 읽기에 반영하고 취소는 원래 읽기로 복귀한다. 목록의 편집으로 직접 들어왔으면 종료 시 목록으로 복귀한다. 미저장 보호는 기존 ConfirmDialog를 재사용한다.
- 기존 MarkdownContent를 공통 소비 지점으로 유지한다. 표·코드·중첩 목록을 지원할 때 자체 정규식 파서를 계속 확장하기보다 기존 의존성과 호환되는 검증된 React 렌더러 도입 비용을 비교한다. raw HTML 실행·위험 URL·원치 않는 외부 이미지 요청을 차단하고 원문을 변경하지 않는다. 원칙의 기존 렌더링도 회귀 검증한다.
- 일반 목록 미리보기는 원문의 마크다운 기호를 그대로 늘어놓지 않고 짧은 일반 텍스트로 표시한다. 본문 저장/태그/티커/검색 점수/완료 상태는 바꾸지 않는다.
- 기존 목적별 조회·저장 HTTP API와 서버 권한을 재사용한다. DB migration·MCP schema 변경·새 저장 모델은 필요 없다. 웹 표현만 바뀌므로 MCP 계약에 영향 없음으로 기록한다.

## 수직 슬라이스

1. **S1 활동 읽기·편집:** 실제 저장된 마크다운 기록과 할 일을 모바일에서 스크롤 → 문서로 읽기 → 연필로 수정 → 저장/재조회한다. 공통 아이콘/마크다운/모달 전환은 이 소비 흐름에 필요한 만큼만 만든다. 검색 결과까지 같은 계약을 적용한다.
2. **S2 자산·배분·원칙:** 행 클릭 제거와 목적별 아이콘 적용, 인라인 목표 예외 유지, 원칙 읽기/정정과 자산 소유자·공유 읽기를 확인한다.
3. **S3 나머지 목록·회귀:** 설정·피드백·관리/선택 목록을 적용표로 대조하고 모든 넘침·복귀·스크롤 경로를 검증한다. 도달하지 않는 옛 화면은 다시 활성화하지 않는다.

## 인수 조건

- [ ] 내용·태그·버튼 위에서 시작한 세로 드래그와 빠른 스크롤, 손가락을 뗀 직후에 의도하지 않은 모달/완료/중단이 발생하지 않는다. 의도적 탭·Enter/Space는 정상 실행된다.
- [ ] 모든 적용표 행에 구현·검증 또는 의도적 예외 근거가 있다. 행·제목에 숨은 편집 진입과 중첩 button이 없다.
- [ ] 활동 목록·검색 결과에서 문서와 연필이 구분되고 읽기에는 쓰기 요청이 없다. 읽기/편집 전환, 저장 성공·실패·취소·미저장 폐기·늦은 응답을 확인한다.
- [ ] 제목/목록/인용/표/코드/긴 링크·한글·일반 텍스트가 읽기 쉽고 원문이 보존된다. HTML/위험 링크가 실행되지 않으며 원칙의 기존 마크다운도 깨지지 않는다.
- [ ] 360/390/768/1024/1440px 및 200% 확대에서 긴 제목·태그·URL·큰 금액·여러 액션으로 페이지가 가로를 넘지 않는다. 표/코드만 내부 가로 스크롤한다. 모바일 버튼 영역은 44px 이상이며 실제 computed style을 확인한다.
- [ ] 필터·날짜 그룹·더 보기·검색 결과·스크롤·호출 버튼 초점이 복원된다. 친구 화면은 읽기만 가능하고 같은 티커/다른 소유자의 내용이 섞이지 않는다.
- [ ] 완료/이번 완료/중단·금융 저장 확인·이력 정정 등 기존 의미와 단일 저장이 유지된다. 읽기에서 편집을 누를 때 2차 편집 모달이 생기지 않는다.
- [ ] 관련 UI/마크다운 테스트와 단위·빌드·인코딩·문서 검사를 통과하고 viewport·실기기 여부·미검증 항목을 기록한다. 모바일 자동 테스트와 실제 휴대폰 터치 확인은 구분한다.

## 인계

설계 단계에서는 문서·티켓만 작성한다. Sol 구현 시작점은 S1이며, 앱 코드·DB·배포 변경은 아직 하지 않았다. 운영 배포와 실제 모바일 확인은 구현 완료와 별도 기록한다.
