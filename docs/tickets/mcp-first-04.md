# [MCP-first] 출처 있는 뉴스·일일 브리핑·판단 결과 저장과 조회

## 구현 인계 확정 사항 (2026-09-20)

- 필독: [ADR-0002](https://github.com/kimyongin/fin/blob/master/docs/adr/0002-cost-basis-reconciliation-and-sharing.md), [ADR-0003](https://github.com/kimyongin/fin/blob/master/docs/adr/0003-extensible-feature-sharing.md), [구현 계약 초안](https://github.com/kimyongin/fin/blob/master/docs/design/implementation-contract-draft.md).
- 공유 대상 브리핑·판단·할 일은 각각 독립 read 기능 키다. 연결된 비공개 근거/원칙을 자동 포함하지 않는다. 새 연구 근거를 기존 공유 뉴스에 자동 삽입하지 않는다.
- 문서화는 구현/배포/보안 검증 완료가 아니다. 미검증 DDL·정밀도·상태 전이는 해당 티켓의 첫 작업으로 남기며 완료 체크를 앞당기지 않는다.

## 기존 자료와 신규 판단의 정리
- 뉴스 사실/해석 CRUD와 원문은 재사용한다. 뉴스는 연결된 근거 및 자료 보관함으로 조회하며 기존 직접 편집도 유지한다.
- 활동 기록은 데이터 변경 감사이다. 활동 이벤트를 이름만 바꿔 판단 기록으로 쓰거나 과거 뉴스 의견을 사용자 채택 결정으로 승격하지 않는다.
- 기존 전략의 규칙 기반 배분 계산은 저장된 모델 의견/사용자 판단과 별개다. 후보 계산만으로 판단·할 일을 만들지 않는다.
- 기존 뉴스 편집이 이미 저장된 판단의 근거를 소급 변경하지 않도록 원문/버전 참조를 #44 계약에 포함한다.
- 구현 단위: A 공통 스키마·참조/권한 기반 → B 뉴스 확장·브리핑·판단·할 일의 저장/조회 → C 재시도·부분 실패·동시성.
- A는 #44 및 #43 버전 계약에 의존한다. #34와 B는 A 이후 병행 가능하며 #34 완료를 A의 선행 조건으로 두지 않는다.
- [ ] 기존 뉴스 CRUD/국가 필터/의견 및 활동 전후 값/CSV를 보존하고 새 관계를 조회한다.

## 판단 기록과 할 일 저장 구현
- #44 계약에 따라 판단의 상황/질문, 선택지, 출처, 적용 원칙 버전, 의견/결정, 이유, 불확실성, 재검토 조건을 저장한다.
- 모델 작성 제안은 사용자 명시적 채택 후 결정이 된다. 과거 판단 변경은 대체 관계와 이유를 보존한다.
- 조사·점검할 일과 실행할 일을 구분하고 판단·보유 이유·근거와 연결한다. 조사할 일은 선행 결정 없이 생성 가능하다.
- 매일 브리핑 생성만으로 동일 판단이나 할 일을 복제하지 않는다. 결정/할 일 연결 저장 실패 시 재시도로 중복 없이 완성한다.
- [ ] “유지하고 다음 실적 때 재검토” 요청으로 유지 결정과 조사할 일이 연결되고 실제 거래는 생성되지 않는다.
- [ ] 사용자 채택 없는 분석, 실행 없는 유지 결정, 조사 결과로 새 결정 생성, 기존 결정 대체를 검증한다.

## 연속 점검 저장 구현 — #44 계약 적용
- #44가 정의한 점검 실행/조사 범위/사건과 출처/검토 질문/판단 관계의 마이그레이션·RPC·목적 중심 MCP 쓰기를 이 티켓에서 구현한다.
- 읽기용 브리핑과 구조화 기록을 안정적 ID로 연결하고 소유자·기준 버전·작성 주체를 검증한다.
- 초안/부분 확정/전체 확정과 요청 재시도를 구분한다. 근거가 저장된 성공 범위만 다음 점검 기준으로 반영한다.
- 질문 답과 근거, 해결/재개/보류/종료 이력을 기록한다. 분석 의견이 사용자 결정이나 매매로 승격되지 않게 한다.
- 사건 정정/대체·출처 추가는 과거 근거와 연결한다. 단순 URL 일치만으로 사건을 자동 병합하지 않는다.
- [ ] 두 대화의 동시 저장, 오래된 실행의 늦은 도착, 일부 실패 후 재시도에도 최신 상태·과거 이력이 유지된다.
- [ ] 기존 비구조적 데이터와 사용자 메모는 보존하고 허구의 조사 범위나 완료 상태를 생성하지 않는다.
- [ ] 변경된 DB 모델을 supabase/schema/OVERVIEW.md에 반영한다.

## 제안 근거와 투자 기준 버전 — #43 연계
- 분석 의견에 적용한 사용자 기준의 항목/버전과 해석 근거, 충돌·정보 부족을 저장한다.
- 과거 브리핑은 당시 기준을 참조해 현재 원칙이 바뀌어도 과거 제안 이유를 복원할 수 있게 한다.
- 분석 의견, 사용자가 채택한 결정, 완료 매매를 구분하고 브리핑 저장으로 투자 기준을 변경하지 않는다.
- [ ] 유지/추가 매수 검토/축소·매도 검토/판단 보류 의견에 적용 기준과 불확실성이 연결된다.
- [ ] 최종 완료 전에 #43 기준 변경 전후 브리핑을 조회해 당시 근거가 보존되는지 검증한다.

## 일일 브리핑 저장 계약 보완
- 기본 저장 단위는 headline, 상태(추가 행동 없음/확인 필요/자료 부족), 중요 변화 최대 3개, 보유 이유 영향, 할 일 0~3개, 출처, 불확실성, 사용한 잔고/판단 버전이다.
- 할 일에는 관찰/자료 확인/기록 보완/판단 재검토 유형과 선택적 기한을 둔다. 자동 주문은 포함하지 않는다.
- “점검하고 저장해줘”는 분석과 저장을 한 흐름에서 처리한다. 읽기 요청에는 무단 저장하지 않고, 저장 실패 시 대화의 결과를 유지하며 재시도 가능하게 한다.
- 브리핑 저장은 “브리핑 작성 완료”이며 사용자가 읽었거나 실제 잔고를 확인했다는 의미가 아니다. 기존 “점검 완료” 표기는 이 의미로 제한한다.
- 같은 날 재생성은 버전/기준시각을 구분하고 최신 본문과 과거 판단을 연결한다.
- 미해결 항목의 안정적인 ID와 사용자 완료/보류 상태를 보존해 재생성만으로 새 할 일이 생기지 않게 한다.
- #41 보유 이유는 사용자 채택 전에는 제안 상태이며 자동 변경하지 않는다.
- 전체 뉴스·장문 보고서 저장을 매일의 필수 비용으로 만들지 않는다. 간단한 브리핑과 관련 출처 저장만으로 완료할 수 있다.

### 추가 완료 조건
- [ ] 분석 성공·저장 실패, 저장 성공·응답 유실 후 재시도, 동일 날짜 재생성을 검증한다.
- [ ] #32의 4개 예시가 동일 저장 형식으로 표현되며 앱에서도 같은 결론을 보여준다.

## 사용자 시나리오

## 범위
- 기존 news_facts/news_fact_annotations와 app_save_news_fact 계열을 우선 재사용한다.
- 기존 daily_reports/rebalance_suggestions 구조·현행 사용 여부를 확인하고 브리핑/판단 저장 모델을 정한다.
- save_news_research, save_daily_briefing 및 필요한 조회 계약을 구현한다. 독립 record_investment_decision 도구는 실제 사용 흐름상 필요할 때만 분리한다.
- 뉴스 출처 URL/제목/발행시각(불명일 때 unknown)/확인시각, 사실·해석·불확실성·관련 종목을 구분한다.
- 브리핑은 사용자/대상 날짜/시간대/분석 기준시각/관련 원본 레코드/모델 작성 여부를 포함한다.
- “관찰/유지/검토” 판단과 근거·재검토 조건을 보존하고 제안을 완료 거래로 저장하지 않는다.
- 중복 저장·재생성 정책, 수정 이력, 요청 idempotency를 정의한다.
- URL/필수 필드/형식 검증과 사실의 진실성 검증은 다르다. 서버가 기사의 진실성을 보장한다고 표시하지 않는다.

## 완료 조건
- [ ] ChatGPT에서 명시적으로 저장 요청한 결과가 OAuth 사용자 계정에 저장되고 다시 조회된다.
- [ ] 동일 요청 재전송으로 중복 뉴스/브리핑이 생기지 않는다.
- [ ] 출처 없는 뉴스는 거부하거나 명시적 개인 의견 유형으로 분리한다.
- [ ] 저장된 날짜와 최신 자료 시점이 구분되고 부분 실패 시 재시도가 가능하다.
- [ ] 브리핑 저장 이후에만 브리핑 작성 완료를 기록한다. 열람/잔고 확인 상태는 별도이며 저장으로 갱신하지 않는다.
