# [자산 UX] 종목·보유·평가 3열 헤더와 목록 정보 위계 정돈

2026-09-24 · 로컬 구현·자동 검증 완료 · 운영 전 · P2

GitHub: https://github.com/kimyongin/fin/issues/134

## 목적과 기존 구현

보유 목록에서 무엇을 보유하고, 어떤 가격에 얼마나 샀으며, 현재 가치와 가격 수익률이 얼마인지 빠르게 읽는다. #129에서 연결한 계산과 태그 보조 텍스트를 재사용하고 목록의 배치만 정돈한다.

현재 `src/features/assets/AssetsPage.jsx`는 헤더 없이 데스크톱에서 종목/수량/평균가·현재가/평가를 4열로 표시한다. 모바일은 종목·평가 아래에 수량·가격을 별도 행으로 표시한다. 숫자의 의미와 정렬 기준을 쉽게 파악하도록 모바일·PC 모두 `종목 | 보유 | 평가` 3열로 통일한다.

## 목표 화면

| 종목 | 보유 | 평가 |
| --- | ---: | ---: |
| **삼성전자** | **10주** | **800,000원** |
| 005930 · 국내주식 | 평균가 70,000원 | **+14.3%** |
| | 현재가 80,000원 | |

- 목록 위에 `종목 / 보유 / 평가` 헤더를 한 번 표시하고 행과 동일한 열 너비·정렬을 적용한다. 보유에는 평균가도, 평가에는 수익률도 포함되므로 `보유량 / 평가액`보다 넓은 의미의 이름을 사용한다.
- 종목: 이름을 주 정보, 코드·태그를 작은 일반 텍스트로 표시한다. 태그 칩을 다시 도입하지 않는다. 전체 계좌 조회의 복수 계좌 수 안내는 보조 정보로 유지한다.
- 보유: 수량을 주 정보로, `평균가`와 `현재가`를 각각 라벨이 있는 보조 줄로 표시한다. 수량의 소수 정밀도와 자산에 맞는 단위를 유지한다. 모든 유형에 임의로 `주`를 붙이지 않는다.
- 평가: 평가금액을 주 정보로, 평균가 대비 가격 수익률을 아래에 표시한다. 숫자는 오른쪽 정렬하고 양수/음수 부호와 기존 색을 함께 사용한다. 각 행의 `평균가 대비` 반복 문구는 제거한다.
- 목록 아래에 `수익률은 평균가 대비 현재가 기준이며 수수료·세금·배당·환율 변동은 반영하지 않습니다.`를 한 번 안내한다. 보조 안내는 고정 footer가 아니라 목록의 일부다.
- 개별 시세 기준일은 상세에서 확인한다. 오래되거나 누락된 시세·환율은 목록에서도 기존 상태 안내를 유지한다. 상단의 최신 시세 기준일을 모든 종목의 기준일로 설명하지 않는다.

## 모바일과 접근성

- 모바일에서도 3열을 유지하고 종목에 가장 넓은 공간을 우선 배정한다. 숫자 열은 필요한 폭을 확보하며 긴 종목명·코드·태그는 줄바꿈한다. 가격과 금액은 통화 단위가 잘리지 않도록 처리한다.
- 작은 화면에서는 셀 여백·간격을 조정하고 긴 외화/원화 환산 금액은 같은 셀 안에서 의미 단위로 줄바꿈한다. 값 생략·임의 금액 축약·가로 스크롤·12px 미만 글자 축소로 해결하지 않는다. 보조 줄은 12px 이상, 주요 정보는 기존 가독성 수준을 유지한다.
- 헤더와 행의 숫자 정렬을 일치시킨다. 행 선택으로 기존 상세를 열고 키보드 및 최소 44px 조작 영역을 유지한다. 시각적인 열 제목뿐 아니라 읽기 순서·접근성 이름에서도 수량/가격/평가금액/수익률 의미가 구분되어야 한다.
- 빈 목록·검색 결과 없음에는 불필요한 숫자 헤더와 수익률 안내를 반복하지 않는다.

## 계산·예외·작업 경계

- `PositionValue`, 기존 가격 포맷과 `usePortfolioDerivedData`의 평균가/현재가/priceChangePercent를 재사용한다. 전체 계좌는 종목 합산, 계좌 선택은 해당 계좌 값이라는 기존 계약을 유지한다.
- 원화·외화 평가금액과 기존 환산 표시를 보존한다. 가격 수익률을 원화 총손익이나 전일 등락률로 바꾸지 않는다.
- 평균가/현재가 누락 또는 평균가 0이면 수익률은 `—`다. 평가 불가·부분 누락·오래된 시세 상태를 숨기거나 0%로 대체하지 않는다.
- 현금은 보유 칸에 `현금성`, 직접평가형은 `평가형`과 기존 매입금액을 표시한다. 두 유형에 주식용 수량/평균가/현재가/가격 수익률을 추가하지 않고 평가는 기존 금액을 표시한다.
- 계좌 선택·검색·추가·표 편집·상세 편집·공유 읽기를 유지한다. DB/API/MCP와 저장 데이터는 변경하지 않는다. 일반 테이블 프레임워크나 신규 모달은 만들지 않는다.
- #129의 계산·누락값·공유 조건은 유지한다. 모바일 별도 숫자 행과 목록 내 개별 시세 기준일 반복 요구는 이 티켓의 3열/상세 기준일 방식으로 대체한다. #129의 기존 구현 및 검증 이력은 유지한다.

## 구현·검증 기록 (2026-09-24)

- `AssetsPage.jsx` 목록을 모바일·PC 공통 3열로 바꾸고 헤더와 행에 동일한 그리드 폭을 사용한다. 종목명/코드·태그, 수량/평균가·현재가, 평가금액/가격 수익률을 각 열 안에서 읽는다. 외화 원금액과 원화 환산액은 같은 평가 칸의 별도 줄로 표시한다.
- 현금성·직접평가형은 기존 의미를 유지하고, 시장형의 누락·오래된 시세 상태와 수익률 `—`도 유지한다. 개별 시세 기준일은 기존 상세에서 확인한다. 검색 결과가 없으면 헤더와 수익률 안내를 숨긴다.
- `npm test` 102개, `npm run build`, `npm run check:encoding` 통과. 격리 `.e2e` DB 575개와 OAuth MCP 계약/준비도 검사 및 `e2e/asset-list-columns.spec.js` 통과. E2E에서 360/390/768/1024/1440px의 헤더·행 정렬, 긴 이름·외화 셀 넘침, 시세 없는 종목, 현금·직접평가형, 검색 결과 없음, 계좌 선택과 상세 진입을 확인했다.
- 음수·0 수익률, 더 큰 외화 금액, 공유 사용자 화면, 실제 기기 키보드·스크린리더는 이번 자동 검증에서 확인하지 않았다. 운영 배포도 별개다.
