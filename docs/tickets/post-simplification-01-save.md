# [후속 정리] 활동·할 일과 태그의 원자 저장 및 재시도 안정화

우선순위: P1 · 상태: 로컬 구현·검증 완료, 운영 미적용 · 2026-09-23
관련: #87, #88, #82, #49 · 기준 코드: 8cb943f

## 문제와 근거

src/features/lifecycle/LifecyclePage.jsx:135의 saveGeneralAction은 본문 생성 후 태그를 별도 RPC로 저장한다. 태그 실패 뒤 재시도할 때 새 idempotency key로 본문을 다시 생성한다. 현재 함수에 태그 실패를 주입한 검사에서 재시도 후 본문 2건이 생성됐다. 이는 실제 DB/브라우저 재현 결과는 아니다.

## 범위와 최소 계약

- 태그를 선택한 활동/할 일 신규 등록을 하나의 목적별 서버 트랜잭션으로 처리한다. 기존 app_create_activity / app_save_general_task와 태그 연결 경로를 조사하고 최소 확장 위치를 확정한다.
- 한 제출 시도의 입력과 요청 키를 함께 보관한다. 응답 유실 시 같은 입력/키로 재시도하고, 성공 후 화면 갱신 실패를 저장 실패와 구분한다.
- 새 제출과 입력 수정 시 키 교체, 미확인 결과 처리 규칙을 구현 전에 이 티켓에 기록한다. 기존 요청 영수증을 재사용하고 범용 명령 엔진이나 새 이력 테이블을 만들지 않는다.
- 기존 태그 개별 편집 경로와 태그 소유권, 재시도 응답의 버전/태그 정합성을 유지한다.
- 앱·MCP가 동일한 원자 저장 계약을 사용하게 한다. 공개 입력이 달라지면 도구 schema/description/가이드/계약 검사를 함께 갱신한다.

## 구현·검증 기록

- `20260923090453_atomic_tagged_creation.sql`의 두 목적별 래퍼가 기존 생성·태그 RPC를 한 트랜잭션으로 묶는다. 태그 배열은 원 생성 receipt 요청에도 포함되어 같은 키로 다른 태그를 제출하면 거부한다. 새 테이블이나 영수증은 만들지 않았다.
- 웹은 입력과 종류의 fingerprint에 요청 키를 묶어 실패/미확인 재시도에 보존하고 입력 변경 때 새 키를 쓴다. OAuth MCP는 신규 생성에서 선택 태그를 함께 전달하며 편집/연결 후속에서는 기존 경로를 유지한다. 가이드와 도구 설명을 갱신했다.
- 분리 E2E: DB 37파일/510건, OAuth·토큰 MCP 계약, Chromium 35건 통과. Vitest 19파일/94건, OAuth Edge Deno check, 워크플로 가이드 및 인코딩 검사 통과.
- 실제 응답 유실을 일으킨 브라우저 조작 및 UI 실패/재시도 전용 시나리오는 아직 검증하지 않았다. 운영 DB/Edge/Pages 미적용.
