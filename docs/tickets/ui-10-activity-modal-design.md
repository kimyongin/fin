# [UI/UX] 활동 모달을 계좌·보유 추가의 폼 디자인에 맞춰 정돈

2026-09-24 · P2 · 로컬 구현 및 자동 검증. 사용자 지정 참조는 자산의 계좌 추가·보유 추가 모달이다. 운영 배포·실기기 평가는 별개다.

GitHub: https://github.com/kimyongin/fin/issues/117

후속 사용자 결정 [#123](./ui-16-modal-inline-edit.md): 현재 대상의 직접 편집·단일 저장을 모든 모달에 적용한다. 아래 읽기/편집 모드 및 태그 별도 저장 유지 요구는 대체되었다. 이 문서의 구현/검증은 당시 스타일 작업 결과이며 #123 완료 증거가 아니다.

추가 사용자 결정: [모달 디자인 가이드](../design/modal-guidelines.md)를 모든 모달의 공통 기준으로 확정했다. AGENTS/디자인 원칙/컴포넌트 문서에 연결했다. 아래 활동 모달 적용과 함께 실제 진입 가능한 전체 모달을 대조하고, 공통 스타일 불일치를 소비 화면별로 수정한다. 데이터 계약 변경이 필요한 별도 문제는 범위와 근거를 기록한다. 문서화만으로 전체 모달 적용 완료를 표시하지 않는다.

## 목적과 확인한 차이

활동 등록·기록 읽기/편집을 자산 모달과 같은 앱의 경험으로 정돈한다. 작은 화면에서 필수 입력을 쉽게 찾고, 선택 입력 때문에 긴 폼을 먼저 훑지 않아도 되게 한다.

- 참조: `src/features/modals/EditorModals.jsx`의 `AccountEditorModal`, `HoldingEditorModal`. 공통 `ModalShell`과 `ModalActions`를 사용한다.
- 자산 폼은 필드 사이 gap-4, 라벨/입력 사이 gap-2, 강조된 작은 라벨, rounded-2xl 입력, px-3/py-3 여백, 일관된 포커스 테두리를 사용한다. 보유 폼은 관련된 짧은 입력을 넓은 화면에서 두 열로 배치한다.
- 활동의 `GeneralActionModal`/`ActivityDetailModal`은 같은 shell을 쓰지만 rounded-xl·py-2 입력, 다른 라벨/버튼, 긴 세로 배치와 독자 footer를 사용한다. 추가 화면에는 출처·태그 생성/관리까지 한 번에 노출된다.
- `GeneralTaskDetail`도 반복 종료 및 안내를 본문 카드에 배치한다. 읽기 정보와 조작 영역의 정리가 필요하다.
- 최근 반응형 모달 전환은 이미 구현돼 있다. 이번 범위는 내부 폼·읽기 레이아웃·액션의 시각적 통일이다.

## 화면별 구성

### 활동 추가

1. 제목 입력: 할 일 또는 기록 제목(#116 용어).
2. 본문 입력: 확인할 때 또는 기록 내용. 전체 폭으로 배치한다.
3. 기존 매일 반복/이미 했음 옵션을 한 줄로 묶되 좁으면 자연스럽게 줄바꿈한다. 별도 모드 탭을 추가하지 않는다.
4. 할 일은 예정일 또는 반복 시작일 하나만 표시한다. 기록은 수행일·활동 종류를 넓은 화면에서 두 열, 좁은 화면에서 한 열로 표시한다.
5. 판단 종류를 선택한 경우 필요한 판단 입력만 이어서 표시한다. 사용자 채택 시 필요한 선택/이유를 숨겨서 저장을 막지 않는다.
6. 조사 범위·출처는 기본 접힌 ‘출처 및 조사 범위’로, 태그는 기본 접힌 ‘태그’로 제공한다. 선택한 태그가 있으면 닫힌 상태에서도 이름 요약을 표시한다. 태그 생성·이름 변경·삭제는 기존 기능을 해당 영역 안에서 유지한다.
7. footer에 닫기/저장. 모바일은 충분한 폭의 같은 행, PC는 오른쪽 정렬한다. 닫기는 공통 미저장 확인 경로를 사용한다.

### 기록 상세·편집

- #115의 ‘관련 할 일 → 기록 내용’을 읽기 본문으로 적용하고 #116 용어를 사용한다. 후속 할 일 입력과 목록은 다시 넣지 않는다.
- 읽을 때는 제목·종류·수행일 → 관련 할 일의 작은 요약 → 결과·결론·메모·출처 순서로 배치한다. 읽기 내용을 비활성 입력칸으로 표시하지 않는다.
- 편집할 때 제목과 본문은 전체 폭, 수행일·종류는 반응형 두 열로 정리한다. 자동 생성 기록은 서버가 허용하는 필드만 편집한다.
- 모든 블록을 테두리 카드로 둘러싸지 않는다. 관련 할 일은 약한 배경으로 구별하고, 기록의 각 본문은 라벨·간격 중심으로 나눈다. 빈 읽기 항목은 생략한다.
- 본문에 흩어진 저장/취소/삭제 버튼은 footer에 둔다. 읽기에서는 수정, 편집에서는 취소/저장, 삭제 가능한 기록만 별도의 위험 행동을 제공한다. 태그 저장이 별도 동작인 현재 계약은 명확하게 표시하며 디자인 통일을 이유로 저장을 암묵적으로 합치지 않는다.

### 할 일 상세

- 제목·일정·반복·확인할 내용을 같은 라벨/간격 규칙으로 표시한다.
- 반복 종료는 일반 정보와 분리하여 footer의 보조/위험 행동으로 둔다. 종료 확인은 같은 모달 안에서 제공한다.
- 설명은 현재 항목 이해에 필요한 짧은 문구만 남긴다. 이 티켓 때문에 새로운 할 일 편집 기능이나 상태를 만들지 않는다.

## 공통 디자인·구현 규칙

- 자산 참조 폼의 입력 모서리, 배경, 테두리, 내부 여백, 라벨 굵기와 간격, 오류 박스, 포커스 표시를 적용한다. 긴 한국어 라벨은 과한 자간 때문에 잘리지 않도록 확인한다.
- input/select는 최소 44px 높이, textarea는 읽기/입력에 충분한 높이, 모든 필드는 min-width:0과 가용 폭을 따른다. 종류 선택은 한 개이므로 기존 select를 유지할 수 있다. 검색의 복수 종류 칩과 혼동하지 않는다.
- 공통 ModalShell의 640px 미만 전체 화면/이상 최대 2xl 중앙 모달, 헤더·본문·footer 구조를 유지한다. 좁은 폼을 억지로 두 열로 만들지 않는다.
- `ModalActions`를 가능한 등록/편집 footer에 재사용한다. 편집 취소 등 실제 의미 차이가 있으면 최소 label/callback 보완만 한다. 조회 화면에 불필요한 저장 버튼을 만들지 않는다.
- 선택 영역 접기는 입력값을 지우지 않는다. 검증 오류가 있는 영역은 열고 해당 입력으로 안내한다. 숨겨진 필드 때문에 저장 불가 이유를 찾지 못하는 상태를 방지한다. 종류 전환 시 보이는 필드만 검증하는 기존 계약을 보존한다.
- 접힌 영역은 키보드 포커스가 들어가지 않게 구현하고, 확대/축소·resize·저장 실패에도 초안을 유지한다. 에러는 모달 내부 해당 영역에서 보인다.
- 스타일 공통화는 자산과 활동에서 실제 중복되는 최소 class/표현만 추출한다. 범용 폼 엔진이나 새 모달 시스템을 만들지 않는다. 자산 모달의 기존 디자인을 함께 전면 개편하지 않는다.

## 선행·연계

- #115 활동 상세 기능 축소와 #116 용어 합의를 최종 화면에 적용한다. 구현은 #115·#116을 먼저 반영하거나 같은 작업에서 통합하여 한 번만 배치한다.
- #114 원칙 타임라인은 독립이다.
- DB·저장/MCP 계약 변경은 이 티켓의 목적이 아니다. #115에 속한 계약 변경과 구분한다. 구현 결과의 실제 공통 규칙만 component-system/screen-structure에 기록한다.

## 완료 기준

- [x] 공통 가이드의 전체 모달 목록을 실제 진입 경로와 대조하고 적용/수정 필요/의도적 예외를 기록한다. 스타일·배치 차이를 수정하고 필요한 기능별 저장 의미는 유지한다.

- [x] 계좌 추가·보유 추가와 활동 추가·기록 편집을 나란히 비교해 라벨/입력/간격/버튼/오류 표현이 일관된다.
- [ ] 간단한 할 일·기록은 필수 입력과 저장을 바로 찾을 수 있고, 선택 입력은 필요할 때 펼친다.
- [ ] 관련 할 일·기록 읽기, 태그/출처 편집, 판단 조건부 입력, 반복 날짜 하나 표시가 자연스럽다.
- [ ] 미저장 닫기·편집 취소·저장 중 잠금·오류 후 초안 유지·접힘 영역 오류 안내를 관련 기존 시나리오로 검증한다.
- [ ] 360/390/768/1024/1440px에서 가로 넘침·하단 버튼 겹침·불필요한 이중 스크롤이 없다. 주요 버튼/키보드/포커스와 확대를 확인한다.
- [x] 모바일/PC 참조 모달과 개선 모달의 캡처를 비교해 실제 결과를 기록한다. 실기기 가상 키보드와 스크린리더 미검증은 구분한다.
- [ ] 관련 UI 회귀·빌드·인코딩 검증 결과, 문서 변경 및 배포 여부를 기록한다.

| 진입 화면 | 로컬 적용/유지 판단 |
| --- | --- |
| 계좌·종목·보유·종목 태그 추가/수정 | 기존 `ModalShell`/`ModalActions`와 필드 배치가 참조 기준. 별도 데이터 변경 없음. |

| 종목 상세 | 보유 계좌가 길어질 수 있는 조회 전용 드로어. 본문에 개별 보유 조작, 저장 footer 없음. |
| 보유 메모·매매 기록·잔고 맞추기 | 공통 폼 입력·footer·초안 보호 적용. 매매와 보정은 미리보기→확정이라는 금융 쓰기 단위를 유지. |

| 활동 추가·기록 상세·할 일 상세 | 계좌/보유 참조 스타일을 적용하고 선택 출처·태그를 접었다. 관련 할 일/기록을 인라인으로 보여주며 저장/수정/삭제/반복 종료를 footer에 정리. |
| 판단·점검 상세 | 조회 전용. 판단은 긴 근거 읽기를 위한 드로어, 점검은 중앙 모달이며 저장 footer 없음. |
| 원칙 추가/수정·배분 설정 | 라벨·입력·footer·초안 보호를 공통 규칙에 맞춤. 원칙 적용 종료는 별도 위험 행동으로 유지. |

기존 모달의 별도 overlay를 새로 만들지 않았다. `ActivityTagPicker`의 입력 이름과 44px 조작 영역을 정돈했다. 로컬 자동 검증은 360/390/768/1024/1440px의 가로 넘침, 모달 열기/닫기·키보드 포커스·초안 보호·저장 실패/재시도·금융 미리보기 흐름을 포함한다. `e2e/modal-visual.spec.js`의 390/1024px 참조 계좌·활동 추가 캡처를 직접 비교해 입력 모서리·간격, 모바일 전체 화면과 PC 중앙 배치, 분리된 하단 액션이 일치함을 확인했다. 활동의 짧은 설명·옵션·접힌 태그는 기능상 차이다. 실기기 가상 키보드·스크린리더·운영 배포는 미검증이다.
