# [공통 UX] 태그 라벨 간격 통일과 선택 시 레이아웃 이동 제거

2026-09-26 · Astra 설계 · Sol 로컬 구현. 운영 배포 전.

GitHub: https://github.com/kimyongin/fin/issues/143

## 목적

자산 대표 태그와 활동 태그를 같은 간격으로 읽고, 태그를 선택·해제해도 라벨과 첫 칩 행이 움직이지 않게 한다. #140/#141 구현 뒤 사용자 화면에서 확인된 간격 회귀를 수정한다. 기준은 [태그 가이드](../design/tag-guidelines.md)와 [모달 가이드](../design/modal-guidelines.md)다.

## 실제 원인

- `src/components/TagChip.jsx`의 `SingleTagPicker`는 `fieldset.grid.gap-2` 아래 `legend`를 둔다. legend의 특수 레이아웃에 grid gap만 의존하여 라벨과 목록 사이 8px이 실제로 보장되지 않는다.
- `ActivityTagPicker.jsx`는 선택 시에만 라벨 옆에 `선택 N개 / 선택 초기화`를 추가한다. 44px 버튼이 기존 20px 라벨 행을 늘려 첫 칩 행이 내려간다.
- `ActionTimeline.jsx`의 태그 필터도 선택 시 별도 개수/초기화 행이 생긴다. 공통 규칙 적용 시 이 소비자도 정리한다.

## 목표 표현

```text
대표 태그 또는 활동 태그
          ↓ 8px
[태그 A] [태그 B(선택 색)] [태그 C]  선택 해제
```

1. 표시 라벨은 공통 label 역할(14/20·600)이며 첫 칩 영역까지 8px이다. 모달/페이지의 기본 필드 간격 16px과 구분한다.
2. `선택 N개`는 제거한다. 선택 상태는 각 칩의 테두리·배경색과 `aria-pressed`로 표시한다. 2026-09-26 사용자 후속 결정에 따라 체크 표시는 두지 않는다.
3. `선택 해제`는 선택한 값이 있을 때만 모든 태그 **뒤에** 보조 텍스트 버튼으로 둔다. 단일 선택은 값 하나를 비우고 다중 선택은 모두 비운다. 최소 44px 조작 영역을 유지한다. 라벨 옆이나 목록 위에 별도 행을 추가하지 않는다.
4. 공간이 부족하면 해제 버튼이 마지막 줄로 넘어가는 것은 허용한다. 라벨과 첫 칩의 간격 및 앞선 칩의 순서는 변하지 않아야 한다. 해제 버튼 자리를 위해 항상 빈 44px 라벨 행을 만들지 않는다.
5. fieldset/legend의 그룹 의미는 유지한다. 예: sr-only legend + 일반 flow의 시각 라벨 또는 명시적인 목록 여백. `gap-2`가 있으니 맞다고 판단하지 말고 실제 bounding box를 검증한다.
6. 태그 선택 전후 칩 너비가 변하거나 텍스트가 한쪽으로 치우치지 않게 한다. 체크 표시와 숨겨진 아이콘 공간을 모두 제거하고 텍스트를 가운데 둔다. 고정 너비 태그/잘린 이름/새 선택 엔진은 도입하지 않는다.
7. 활동 필터의 태그 OR/모두 포함 의미는 유지한다. 모두 포함 옵션은 기존 조건대로 칩 **아래**에 두고 라벨 행 높이에 영향을 주지 않는다. 해제 시 tagIds와 tagMatch 초기화는 기존 동작을 유지한다.

## 구현 범위와 경계

- `TagChip.jsx`/`SingleTagPicker`, `ActivityTagPicker.jsx`, `ActionTimeline.jsx`, 필요한 공통 CSS. 실제 중복되는 라벨/목록 배치만 공유한다.
- 자산 상세/종목 편집의 단일 선택, 활동 추가/할 일 상세/기록 상세의 다중 선택, 활동 목록 태그 필터를 대조한다. 태그 관리의 사전 편집·자산 목록 텍스트·배분 제목은 역할을 그대로 유지한다.
- 단일/다중 선택, 태그 ID·순서, 부모 저장, 미저장 보호, 권한은 유지한다. DB/API/MCP 변경 없음.
- #141의 라벨 행 오른쪽 개수·초기화 계약과 #140의 태그 관련 불충분한 간격 검증을 이 명세로 보완/대체한다.

## 인수 조건

- [x] 같은 폭에서 자산/활동 라벨 아래 실제 8px 간격을 확인한다.
- [x] 선택 전후 라벨/첫 칩 간격을 유지한다. 칩 순서는 고정하고 아이콘 자리 없이 선택 전후 칩 너비를 유지한다.
- [x] 360/390/768/1024/1440px에서 짧은/긴 이름과 줄바꿈, 마지막 해제 버튼을 확인한다. 고정 높이로 잘리는 내용이 없다.
- [x] 단일 선택·복수 선택·해제 후 저장/재조회, 필터 OR/모두 포함, 공유 읽기 동작을 기존 대표 테스트로 확인한다.
- [ ] 키보드 그룹 이름·선택 상태·초점과 44px 조작 영역을 유지한다. 스크린리더/실기기 미검증 여부는 별도 기록한다.
- [x] 선택 전후 캡처와 실제 좌표를 비교하고 인코딩·관련 회귀 검증을 통과한다.

## 인계

`TagChip`/단일 선택기, 활동 다중 선택기, 활동 목록 필터에 같은 구조를 적용했다. 시각 라벨 다음 목록에 명시적 8px 여백을 주고 선택 개수는 없앴다. `선택 해제`는 칩들의 마지막에 둔다. 사용자 후속 확인에 따라 조작 칩의 체크 표시와 미선택 상태의 빈 아이콘 공간을 제거하고 텍스트를 가운데 정렬했다. 데이터·API·MCP 계약은 바꾸지 않았다.

격리 E2E의 `modal-visual.spec.js`가 360/390/768/1024/1440px에서 짧은/긴 태그, 대표 태그·활동 태그의 라벨/첫 칩 간격, 1개·여러 개 선택과 전체 해제, 가로 넘침을 검증했고 각 폭의 선택 전후 화면을 `test-results`에 캡처했다. `activity.spec.js`의 태그 저장·필터 OR/AND·반응형 상세 회귀, DB 태그/공유 검증도 통과했다. 격리 DB 580개, `npm test` 102개, `npm run build` 및 인코딩 검사를 통과했다. 스크린리더·실기기, 운영 배포는 별도 확인이 필요하다. 기존 무관한 작업 트리는 보존했다.

후속 체크 제거 검증: 같은 5개 폭에서 자산·활동 조작 칩 내부에 체크용 `span`이 없고, 선택 전후 칩 너비가 동일하며 `aria-pressed`가 선택 상태를 전달하는 것을 확인했다. 선택된 360px 화면 캡처에서도 태그명이 가운데에 있고 오른쪽으로 밀리지 않는다. `npm test` 102개와 `npm run build`를 다시 통과했다.
