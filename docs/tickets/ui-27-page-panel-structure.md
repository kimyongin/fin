# [공통 UX] 네 탭 상단 카드의 제목·행동·본문 구조 통일

2026-09-26 · 로컬 구현 및 자동 검증 완료 · 운영 배포 전 · P2

GitHub: https://github.com/kimyongin/fin/issues/138

## 목적과 문제

자산·배분·활동·원칙을 오가도 같은 위치에서 화면 목적과 관련 행동을 찾는다. #136/#137의 배치 방향을 이어받되 카드의 색·여백만 공통화한 구현을 보완한다. 카드 높이나 정보량을 같게 만드는 작업은 아니다.

현재 `PageControls.jsx`의 `pagePanelClass`/`pagePanelFilterClass`는 외형만 공유한다. `AssetsPage`는 작은 라벨과 평가액 묶음, `StrategyPage`는 굵은 제목, `ActionTimeline`은 작은 회색 문맥, `PrincipleJournal`은 제목 다음 행의 날짜/수정 버튼을 사용한다. 그 결과 제목 역할·버튼 기준선·구획 경계가 다르다. 가로 넘침 검사만으로 이 문제를 검증할 수 없다.

## 확정 화면 계약

공통 순서: 제목과 행동 → 선택적 보조 정보 → 선택적 핵심 수치 → 구분선과 선택적 필터/문서 본문. 없는 구획과 여백은 생략한다.

| 탭 | 제목 | 상단 행동 | 아래 구획 |
| --- | --- | --- | --- |
| 자산 | 보유 자산 | 가격 갱신 · 보유 추가 · 계좌 추가 · 표 편집 | 배분과 같은 크기의 한 줄 평가액 → 구분선 → 계좌/검색/대표 태그. 시세 기준일은 목록 안내로 이동 |
| 배분 | 태그별 배분 | 태그 관리 | 전체 계좌 기준·확인 가능한 평가액. 현재/목표 목록은 카드 밖에 유지 |
| 활동 | 할 일과 기록 | 태그 관리 · 활동 추가 | 구분선 → 검색/기록 기간/태그. 기간 적용 설명은 날짜 입력 가까이에 배치 |
| 원칙 | 현재 원칙 | 수정 또는 빈 상태의 원칙 작성 | 적용 일시 → 구분선 → 현재 마크다운 또는 빈 상태 안내 |

- 원칙의 기존 수정 버튼을 제목 행으로 옮긴다. 버튼과 제목을 추가로 중복하지 않는다. 본문의 마크다운은 사용자 데이터이므로 내용·제목을 임의로 삭제하지 않는다.
- 자산은 평가 범위와 금액을 한 줄 보조 정보로 표시한다. 중복되는 종목 수·큰 금액 블록·상단 시세 날짜는 제거하되 필터 범위와 계산 의미는 유지한다.
- 활동의 기간 설명은 `기록에만 적용 · 미완료 할 일은 기간과 무관`처럼 날짜 구획에서 읽힌다. 활동 통계·소개 문단을 추가하지 않는다.

## 고정 시각 규칙

- 제목: 18px/600/28px, 기본 글자색. 네 화면 모두 같은 역할 클래스를 사용한다. 접근성 h1은 페이지당 하나를 유지하고 같은 제목을 시각적으로 반복하지 않는다.
- 보조 정보: 14px/400/20px, 보조색. 자산 평가액은 배분의 평가액과 같은 한 줄 스타일로 표시한다.
- 상단 행동: 동일한 테두리 버튼, 최소 높이 44px, 모서리 12px, 좌우 padding 16px, 버튼 사이 8px. 상단의 활동 추가만 주황색인 예외를 없앤다. 편집 모달의 확정/저장 강조색은 유지한다.
- 넓은 화면: 제목과 행동 묶음은 첫 행에 배치하고 세로 중심을 맞춘다. 버튼을 수치 묶음이나 날짜 행에 정렬하지 않는다. 제목 아래 설명은 8px 간격으로 붙인다.
- 제목과 버튼이 함께 들어가지 않으면 행동 묶음 전체가 다음 행으로 내려가 왼쪽부터 줄바꿈한다. 중간 폭에서도 제목을 찌그러뜨리거나 가로 스크롤하지 않는다. 순서는 제목 → 행동 → 보조 정보 → 수치 → 하단 구획이다.
- 카드 padding 16px/640px 이상 24px, radius 16px, 주요 구획 간격 16px, 보조 정보 간격 8px, 필터 행 간격 12px. 하단 구획이 있을 때만 그 위에 얇은 구분선 하나를 둔다. 배분의 빈 구분선은 만들지 않는다.
- 검색·날짜·계좌 입력의 높이·테두리·배경·모서리도 같은 기본 스타일을 적용한다. 태그 칩과 의미별 선택 방식은 기존 가이드를 따른다.
- 공유 읽기 상태는 공통 제목 옆 보조 상태로 표시하고, 편집 권한이 없는 행동은 숨긴다. 숨긴 버튼 자리에 빈 영역을 남기지 않는다.

## 구현 범위와 재사용

`src/components/`에 작은 상단 카드 컴포넌트를 두고 제목/행동/보조 정보/수치/하단 구획의 실제 DOM·스타일을 소유한다. 기존 `PageControls`에 두거나 별도 파일로 추출할지는 Sol이 결정한다. 단순히 CSS 문자열만 추가하고 각 페이지가 헤더를 다시 조립하는 구현은 완료로 보지 않는다.

컴포넌트는 표시용 React 내용만 받고 조회·계산·저장·권한 판정·필터 상태를 소유하지 않는다. 페이지별 설정 엔진, 새 저장소/API/MCP 변경은 필요 없다. 기존 공통 버튼·입력 스타일이 있으면 재사용한다. 전역 버튼 CSS와 Tailwind 레이어 충돌이 있었으므로 클래스 이름만 확인하지 말고 브라우저의 실제 적용값을 확인한다.

변경 대상: `AssetsPage.jsx`, `StrategyPage.jsx`, `ActionTimeline.jsx`, `PrincipleJournal.jsx`, `PageControls.jsx` 및 필요한 공통 스타일. `page-panel-guidelines.md`가 정본이며 #136/#137의 충돌하는 헤더 배치 문장은 본 티켓으로 대체한다. 해당 티켓의 저장·필터·프로필 기능은 중복 구현하지 않는다.

## 현재 상태

`PagePanel`을 `src/components/PageControls.jsx`에 추가하고 자산·배분·활동·원칙의 상단 카드를 연결했다. 후속 사용자 캡처 피드백으로 제목/버튼의 세로 중심을 맞추고 설명 간격을 8px로 줄였다. 자산 상단은 평가액 한 줄과 품질 경고만 남기고, 시세 기준일을 목록의 수익률 안내로 옮겼다. 단순 표시 컴포넌트이며 DB/API/MCP는 변경하지 않았다. `npm test` 100개, `npm run build`, `npm run check:encoding`, 격리 E2E의 DB 558개와 MCP 계약 및 브라우저 8개가 통과했다. 별도 실행의 네비게이션 회귀 14개도 통과했다. 운영 배포·실기기 검증은 하지 않았다. 작업 시작 전부터 광범위한 미커밋 변경이 있었으므로 이 슬라이스는 커밋·푸시하지 않았다. GitHub #138에는 로컬 구현/검증 내용을 댓글로 동기화하고 운영·실기기 후속 때문에 열린 상태를 유지했다.

후속 캡처 피드백 검증: 제목/버튼의 실제 세로 중심(768/1024/1440px)과 제목/설명 간격(최대 8px), 자산 큰 수치 블록·상단 시세 문구 제거를 `e2e/page-panel.spec.js`에서 확인했다. `e2e/asset-filters.spec.js`에서 조회 결과 평가액의 필터 연동과 목록 하단 날짜를 확인했다. 390/1024px 비교 캡처도 다시 열어 배분/자산의 평가액 글자 역할과 컴팩트해진 높이를 확인했다. 해당 두 E2E 파일 3개 통과, 격리 DB 558개·MCP 계약·단위 100개·빌드·인코딩 통과. 실기기·극단 데이터 검증과 운영 배포는 여전히 남는다.

2026-09-26 후속 사용자 피드백: 네 카드의 나열된 행동을 오른쪽 위 작업 메뉴로 모으고, 아이콘과 열린 목록을 푸터 햄버거와 같은 스타일로 수정했다. 행동 순서·권한·비활성 조건은 유지한다. 배분의 태그 관리 모달은 메뉴를 닫아도 살아 있도록 포털에 놓았다. 브라우저에서 자산의 계좌 추가와 배분 태그 관리 모달의 열기·닫기를 확인했고, `e2e/page-panel.spec.js` 3개·단위 100개·빌드·인코딩은 통과했다. 관련 넓은 회귀는 50개 통과, 7개 실패였으며 이 중 6개는 과거 화면 구조를 가리키는 테스트 셀렉터 수정 후 재실행에서 통과했다. 남은 1개도 `기록` 제목의 부분 일치 셀렉터를 정확 일치로 고쳤지만 아직 재실행하지 않았다. 운영 배포·실기기 검증은 하지 않았다.
