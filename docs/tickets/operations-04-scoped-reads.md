# [운영 개선] 대상별 조회와 공유 응답 필드 명시

우선순위: P2 · 규모: 중 · 상태: 진행 전
상위: #40 · 연관: #45/#46/#47 · 비동기 상태 격리 이후 통합 권장

## 근거와 발생 조건
- `src/features/review/data.js:34`: 최근 판단 50개에서 브리핑을 필터링한 뒤 최대 10개 상세를 추가 조회한다. 연결 판단이 범위 밖이면 실제 과제가 누락된다.
- 공유 문맥은 항상 []를 반환해 미지원 관계를 과제 없음처럼 표시한다.
- tradeData.js/TradeEntryModal.jsx는 전체 최근 거래 50개를 받은 뒤 종목으로 필터링한다.
- `supabase/migrations/202609210016_shared_review_dtos.sql:37`: 공유 판단 상세가 to_jsonb(d)에서 일부 열만 제외한다. 새 민감 필드가 자동 공개될 수 있다.

## 최소 변경 범위
- 브리핑→판단→과제의 명시적 관계를 서버에서 필터링한 뒤 제한한다. 대상별 읽기 API로 N+1 상세 조회를 줄인다.
- 과제의 현재 상태와 순서 기준을 명시한다. 관련성만으로 긴급 과제나 미완료라고 단정하지 않는다.
- 거래 조회에 종목/필요 계좌 조건과 안정적인 페이지 커서를 추가하고 기존 MCP 호출 호환을 유지한다.
- 없음/권한 없음/조회 실패를 구분한다. 공유 관계 노출은 기존 grant와 공개 계약 안에서만 제공한다.
- 공유 상세는 허용 필드를 명시적으로 구성한다. 개인 기준 snapshot·내부 이력·비공개 연결은 계속 제외한다.

## 인수 조건
- [ ] 관련 판단이 최근 50개 밖에 있어도 브리핑 과제가 조회된다. 표시 제한은 대상 필터 이후 적용된다.
- [ ] 50개 초과 거래에서 선택 종목/계좌 조회와 페이지 이동에 누락·중복이 없다.
- [ ] 소유자/허용 친구/철회/무관 사용자 및 부분 grant 조합을 테스트한다.
- [ ] 연결 ID·건수·비공개 상세가 권한 밖으로 노출되지 않는다.
- [ ] 공유 응답 키 집합을 계약 테스트하며 내부 필드 추가가 자동 공개되지 않는다.
- [ ] 기존 API와 MCP 호출 호환, 오늘→과제→판단 및 기록 취소 진입을 회귀 검증한다.
