# [MCP-first] 종목별 보유 이유·재검토 조건과 판단 이력

## 구현 인계 확정 사항 (2026-09-20)

- 필독: [ADR-0002](https://github.com/kimyongin/fin/blob/master/docs/adr/0002-cost-basis-reconciliation-and-sharing.md), [ADR-0003](https://github.com/kimyongin/fin/blob/master/docs/adr/0003-extensible-feature-sharing.md), [구현 계약 초안](https://github.com/kimyongin/fin/blob/master/docs/design/implementation-contract-draft.md).
- 보유 이유는 별도 기능 키 holding_theses로 기본 비공개다. 향후 명시적 기능 공유를 지원할 구조를 사용하며 기존 메모/공유 전략과 자동 통합하지 않는다.
- 문서화는 구현/배포/보안 검증 완료가 아니다. 미검증 DDL·정밀도·상태 전이는 해당 티켓의 첫 작업으로 남기며 완료 체크를 앞당기지 않는다.

## 기존 자산 화면과의 연결 경계
- 기존 종목/계좌별 카드와 메모는 유지하며 보유 이유/재검토 조건은 선택적 상세 진입으로 연결한다. 카드 전체를 분석 본문으로 대체하지 않는다.
- 기존 note의 저장 경로와 새 보유 가설을 구분하고 앱/MCP에서 같은 ID와 버전을 읽는다.

## 보유 이유와 판단 기록 구분
- 보유 이유는 현재 유효한 투자 가설이다. #44 판단 기록은 이 가설을 채택/유지/변경한 이유와 당시 선택지를 담는다.
- 보유 이유에 관련 판단 ID/버전을 선택적으로 연결하고 같은 내용을 별개의 확정 결정으로 중복 생성하지 않는다.
- 원칙 변경이나 모델 분석만으로 보유 이유를 자동 변경하지 않는다.

## 검토 질문 데이터와 연결 — #44
- 보유 이유의 재검토 조건은 #44 검토 질문과 ID로 연결한다. 별개의 중복 할 일 목록을 만들지 않는다.
- 질문의 답/근거가 생겨도 사용자가 확정한 보유 이유를 자동 변경하지 않는다. 채택된 변경에는 이전 이유/질문/근거 관계를 남긴다.
- [ ] 이유 수정·전량 매도·재매수 시 기존 질문을 유지/보류/종료할 정책을 명시하고 과거 이력을 보존한다.

## 사용자 전체 기준과의 관계 — #43 연계
- #43은 사용자 전체 투자 목적·성향과 공통 원칙을, 이 티켓은 종목/계좌별 보유 이유를 관리한다.
- 종목별 이유가 공통 금지사항/한도와 충돌하면 충돌로 제시하고 자동 재정의하지 않는다.
- [ ] 일일 분석에 두 기준의 출처가 구분되고 서로의 저장 내용을 덮어쓰지 않는지 검증한다.

## 선행 작업
- #32 제품 계약, #33 OAuth MCP 계약

## 사용자 가치
“이 종목을 왜 가지고 있고 언제 다시 생각해야 하는지”를 기억해 일일 브리핑의 해석 기준으로 사용한다.

## 설계
- 사용자+종목을 기본 범위로 보유 이유, 투자 기간(선택), 재검토 조건(선택), 다음 점검일(선택)을 저장한다. 계좌별 목적이 다르면 계좌별 재정의가 가능하도록 범위를 명시한다.
- 기존 instrument/holding note는 보존한다. 기존 메모를 자동으로 확정된 보유 이유로 해석하거나 덮어쓰지 않는다.
- 사용자가 말한 이유와 ChatGPT가 제안한 가설을 구분한다. 명시적 저장 요청/수락이 있을 때 사용자 판단으로 기록한다.
- 도구는 save_holding_thesis(가칭), 앱은 종목 상세의 선택 입력으로 같은 저장 경로를 사용한다. 분석/온보딩을 입력 완료까지 막지 않는다.
- 수정 시 이전 판단과 유효시각을 보존한다. 전량 매도 후에는 이전 보유 목적을 자동으로 새 매수에 적용하지 않는다.
- 조건은 우선 자유 텍스트와 점검 날짜로 시작한다. 정량 조건 자동 판정은 신뢰 가능한 입력을 확보한 지원 유형만 수행하고 그 외에는 미평가로 반환한다.
- 일일 브리핑에는 사용자가 기록한 이유, 해당 이유에 영향을 줄 근거, 재검토 시점을 연결한다. 관련 근거를 못 찾았다는 것과 이유가 검증되었다는 것을 구분한다.
- 개인 판단은 기본 소유자 전용. 기존 친구 공유에 자동 포함하지 않는다.
- 스키마 변경 시 supabase/schema/OVERVIEW.md를 갱신한다.

## 완료 조건
- [ ] “장기 적립용이야. 실적 발표 후 다시 보자”를 최소 입력으로 저장·수정·조회한다.
- [ ] 보유 이유가 없어도 아침 점검을 완료하며 임의로 이유를 생성하지 않는다.
- [ ] 같은 종목의 계좌별 목적과 과거 보유 이력을 혼동하지 않는다.
- [ ] 모호한 “나중에”를 임의 날짜로 바꾸지 않고, 확정 날짜는 사용자 시간대로 처리한다.
- [ ] #34 문맥, #35 브리핑, #36 종목 상세에서 동일한 판단 버전과 관계를 사용한다.
