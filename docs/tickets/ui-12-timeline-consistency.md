# [UI/UX] 활동·원칙 타임라인 디자인 통일

2026-09-24 · P2 · 설계 완료, 구현 전.

GitHub: https://github.com/kimyongin/fin/issues/119

## 목적과 현재 차이

동일한 시간순 이력인데 화면마다 읽기 구조와 조작이 달라 사용자가 다시 익혀야 한다. 공통 [타임라인 가이드](../design/timeline-guidelines.md)를 정본으로 삼고 두 화면에 적용한다.

- `src/features/lifecycle/ActionTimeline.jsx`: 날짜별 패널·헤더 접기·건수·더 보기를 제공한다.
- `src/features/activity/ActivityEventViewer.jsx`: 시간 열/점/제목/종류·출처 배지와 결과·결론·변경 필드·CSV 조작이 섞여 있다. 모바일/넓은 화면 배치도 원칙과 다르다.
- `src/features/strategy/PrincipleJournal.jsx`: 단일 세로선 안에 날짜·분류·본문·이전 내용 펼침을 배치한다. 날짜별 패널/접기가 없고 본문을 반복한다.
- #118은 원칙을 마크다운으로 바꾸고 변경 메모 중심 목록/선택 시점 본문 상세를 정의한다. 이 티켓은 그 계약의 공통 표현을 담당한다.

## To-Be

후속 [#122](./activity-15-tags-and-references.md)에 따라 활동 종류 배지와 종류별 표시 유지 요구는 태그·본문·명시적 참조로 대체한다. 이 티켓은 표현 통일을 담당하며 종류 제거/공유 변경은 #122에서 수행한다. 통합 구현 시 제거 예정 종류 UI를 새 공통 컴포넌트의 필수 계약으로 만들지 않는다.

두 화면 모두 섹션 제목 → 접을 수 있는 날짜별 카드 → 시각·점·대표 텍스트·필요한 배지 → 더 보기로 통일한다. 활동의 대표 텍스트는 기록 제목, 원칙은 변경 메모다. 목록에서 핵심만 읽고 항목을 눌러 상세를 연다. 선/점·간격·글자·카드·반응형·초점·상태 표현은 가이드를 따른다.

할 일과 현재 원칙은 기존 독립 섹션으로 유지한다. 활동 검색 결과를 시간순으로 강제하지 않는다. 활동의 태그 검색과 공유 계약은 #122에서 변경하며, 이 티켓은 활동과 원칙의 표현을 통일한다.

## 구현 범위

1. 활동/원칙의 실제 표시 코드를 기준으로 날짜 그룹과 항목 표현만 작은 공통 컴포넌트로 추출한다. 도메인별 controller와 데이터 어댑터를 유지한다. 별도 디자인 시스템 프레임워크는 만들지 않는다.
2. 활동의 날짜 카드와 기록 행을 가이드에 맞춘다. 긴 결과/결론·필드별 변경 전후 값·일괄 편집 CSV가 상세에 실제 제공되는지 먼저 확인한다. 목록에서 옮길 기능은 기록 상세에서 사용 가능하게 연결한 뒤 제거하며 기능을 조용히 삭제하지 않는다. 공통 ActivityEventViewer의 다른 소비자도 조사해 영향 범위를 기록한다.
3. 원칙은 #118의 변경 메모와 해당 행 본문 상세를 사용한다. 날짜 카드·접기·항목·상태·더 보기만 공통 표현에 연결한다. 긴 원칙 본문이나 previous 비교를 되살리지 않는다.
4. 표시 날짜/시각을 기존 업무 시간대에 맞추고 도메인별 발생/적용 시각을 구별한다. API가 제공하는 안정 정렬과 커서를 유지한다. 같은 날짜의 페이지 연결·중복 방지·접힘 상태를 점검한다.
5. 상세 닫기/키보드 초점/스크롤·검색 조건 복원, 더 보기 실패/재시도, 데이터 없는 날짜 표현을 두 화면에서 일치시킨다. 소유자/공유 화면에서 허용된 상세만 연다.
6. 가이드와 실제 구현을 연결하고 화면 구조/컴포넌트 문서·티켓에 적용 결과와 예외를 기록한다. 새 타임라인 작업 시 이 가이드를 찾을 수 있도록 개발 진입 문서에서 연결한다.

## 의존 관계와 진행 순서

#118의 변경 메모 저장·조회와 원칙 상세 계약을 먼저 구현하거나 같은 수직 슬라이스에서 연결한다. 그 이후 이 티켓으로 공통 표현을 적용한다. #118이 끝나기 전에 이전 원칙 펼침 UI를 먼저 공통화하지 않는다. #114의 타임라인 표현은 #118/본 가이드가 대체하되 기존 이력 데이터는 유지한다. #117의 ModalShell 기준을 재사용한다.

## 완료 기준

- [ ] 활동과 원칙에 날짜 카드·시각·선/점·타이포·간격·상세 진입·더 보기·상태 표현이 같은 규칙으로 적용된다.
- [ ] 활동 제목/태그/짧은 요약, 원칙 날짜/변경 메모로 빠르게 훑을 수 있고 긴 본문은 상세에서 손실 없이 읽는다. 메모 없는 과거 원칙도 자연스럽게 표시한다.
- [ ] 기존 활동의 변경 전후 값과 해당되는 CSV 기능에 도달할 수 있다. 할 일 완료·활동 필터/검색·태그·공유 접근이 유지된다.
- [ ] 같은 날 다수 항목/같은 시각/자정 부근/다른 기기 시간대/날짜가 이어지는 다음 페이지를 확인한다. 날짜 중복·누락·순서 역전·접힘 초기화가 없다.
- [ ] 더 보기 실패 후 재시도, 상세 닫기, 창 크기 변경에서 기존 목록과 조작 상태가 유지된다.
- [ ] 360/390/768/1024/1440px에서 두 화면을 같은 조건으로 비교한다. 긴 제목·메모·URL·다수 태그·기록 없음·오류를 확인한다.
- [ ] 44px 조작 영역·키보드 Enter/Space·초점 복귀·aria-expanded·하단 탭 겹침·가로 넘침을 검증한다.
- [ ] 관련 사용자 흐름 E2E, 빌드·인코딩을 수행하고 실제 viewport/상태/상호작용과 실기기 미검증 범위를 남긴다.
- [ ] 적용한 공통 컴포넌트와 소비자, 의도적인 차이 및 이유를 가이드/티켓에 기록한다. 문서 작성과 구현/배포 완료를 구분한다.

현재는 가이드 및 티켓 작성만 완료했으며 제품 코드·DB·배포는 변경하지 않았다.
