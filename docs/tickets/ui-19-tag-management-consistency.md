# [공통 UX] 2차 모달 용도 제한과 배분·활동 태그 관리 통일

2026-09-24 · Astra 설계 후 Sol 로컬 구현. 운영 배포 전.

GitHub: https://github.com/kimyongin/fin/issues/127

2026-09-26 후속 [활동 태그 검색 간소화](./ui-30-activity-tags-without-search.md)가 아래 활동 추가/상세/관리창의 태그 이름 검색 요구를 대체한다. 활동 목록의 태그 필터·자산 관리 검색과 이 티켓의 기존 구현/검증 기록은 유지한다.

후속 UX: [#128](./ui-20-tag-chip-guidelines.md)과 [태그 가이드](../design/tag-guidelines.md)가 목록 배치·초기 선택·편집 위치를 대체한다. 아래 로컬 구현·검증은 당시 동작의 기록이며 새 칩 UX의 완료 증거가 아니다. 저장·권한·관리 위치와 남은 운영/실기기 검증은 유지한다.

상위 기준: [모달 가이드](../design/modal-guidelines.md), [디자인 원칙](../design/PRINCIPLES.md), [단순성](../engineering/SIMPLICITY.md). 연계: #121 배분, #123 직접 편집, #125 기록 입력, #126 확인 계층.

## 목적

사용자는 태그 목록을 정리하는 일과 현재 기록에 태그를 붙이는 일을 구분할 수 있어야 한다. 배분·활동에서 같은 관리 흐름을 제공하고, 상세 편집 중 태그 이름/삭제 관리 때문에 폼이 커지거나 다른 편집 모달로 이동하지 않게 한다. 2차 모달은 짧은 사용자 의사 확인에만 사용한다.

## To-Be 사용자 흐름

### 배분 / 활동 페이지

- 각 페이지 보조 도구에 `태그 관리` 버튼을 둔다. 배분에서는 `자산 태그 관리`, 활동에서는 `활동 태그 관리`라는 제목의 1차 모달을 연다. 페이지 제목·주요 버튼·필터 배치는 기존 공통 규칙을 따른다.
- 두 관리창은 동일한 구조다. #128에서 태그 검색 → 가로 줄바꿈 칩 목록 → + 새 태그 → 선택 시 목록 아래 입력 영역으로 보완한다. 초기 미선택에는 닫기만, 추가/수정에는 닫기와 추가/저장을 둔다. 선택 태그의 삭제는 입력 영역의 보조 위험 버튼이다.
- 태그를 선택하면 같은 본문에 이름이 바로 편집 가능하게 보인다. 새 태그는 명시적으로 눌렀을 때 입력 영역을 비운다. 별도 수정 버튼·별도 편집창·접기·세 번째 단계를 만들지 않는다. 목록과 입력 영역을 유지하고 모바일은 한 열 안에서 칩을 줄바꿈한다.
- 편집 대상은 한 번에 태그 하나다. `저장`은 현재 선택한 태그만 저장하며 전체 목록 일괄 저장으로 오해되지 않게 입력 영역에 대상 이름을 표시한다. 저장 후 관리창은 유지하고 저장한 행을 선택 상태로 둔다. 닫기로 이전 저장이 취소되는 것처럼 표현하지 않는다.
- 다른 태그 선택/새 태그 진입/닫기에 미저장 변경이 있으면 하나의 2차 의사 확인으로 보호한다. 계속 편집하면 기존 입력·선택 유지, 버리기를 확정하면 요청한 이동을 실행한다. 자동 저장은 없다.
- 삭제는 2차 확인 하나에 대상과 영향, 버려질 미저장 변경을 함께 설명한다. 취소하면 입력 유지, 성공하면 해당 행 제거 및 선택 해제. 다른 태그를 자동 삭제하거나 태그가 붙어 있던 자산/기록/할 일을 삭제하지 않는다.
- 오류는 현재 입력 영역 또는 해당 확인창에 표시한다. 저장 성공 후 새로고침 실패는 저장 실패와 구분해 조회만 재시도하며, 성공한 쓰기를 반복하지 않는다.
- 태그 목록이 길면 검색을 제공하고 #128에서 모달 본문 스크롤 하나로 정리한다. 빈 목록·검색 결과 없음·긴 이름·읽기 실패를 구분한다. 활동에는 원래 없는 정렬 순서 입력을 새로 만들지 않는다. 자산 태그의 기존 순서 필드는 유지한다.

### 활동 추가 / 기록 상세 / 할 일 상세

- 태그 검색과 선택된 태그 칩, 선택/해제만 남긴다. 체크박스 대신 선택 상태가 드러나는 버튼/칩과 접근성 상태를 사용한다. 선택 영역은 접지 않는다.
- 태그 생성·이름 변경·삭제 및 관리창 진입 버튼은 상세에서 제거한다. 상세 위에 다른 편집창을 여는 경로를 만들지 않는다. 검색 결과가 없을 때만 활동 페이지의 `태그 관리` 위치를 짧게 안내한다.
- 선택/해제는 상세 초안만 바꾸고, 기록/할 일의 `저장`에서 다른 필드와 함께 기존 원자 저장 API로 반영한다. 상세 취소는 태그 연결 초안도 버린다.
- 새 태그가 필요하면 현재 내용을 저장하거나 닫은 뒤 활동 페이지에서 태그를 만들고 다시 선택한다. 관리창에서 태그를 생성했다고 특정 기록/할 일에 자동 연결하지 않는다.
- 자산 상세의 기존 단일 대표 태그 선택은 유지한다. 활동은 복수 태그다. 관리 방식 통일이 선택 개수나 저장소 통합을 뜻하지 않는다.

## 저장·연결과 변경 영향

- 현재 태그 저장소와 API를 재사용한다. 신규 테이블, 태그 공통 DB, 범용 CRUD 엔진, 일괄 저장 API는 이 작업에 필요하지 않다.
- 자산 태그: 기존 `app_save_tag`, `app_delete_tag`와 포트폴리오 재조회. 활동 태그: `fetchActivityTags`, `saveActivityTag`, `deleteActivityTag` 및 기존 사용자/버전/멱등성 처리. 활동 태그는 실패한 동일 요청의 재시도 키를 유지한다. 자산 태그의 일반 실패는 초안을 유지해 다시 시도할 수 있게 하되, 태그를 위해 별도 멱등 저장 구조를 만들지 않는다.
- 태그 이름 변경은 같은 ID를 유지하고 관련 표시·검색 필터를 갱신한다. 삭제 시 연결 해제와 영향받는 배분 목표를 확인 문구에 명시한다. 구 버킷 해제 문구는 제거한다. 실제 FK/RPC 삭제 영향은 구현 시작 시 해당 코드만 확인하고 테스트에 반영한다.
- 배분 목표는 태그 ID로 초안을 보존한다. 이름/순서 변경은 비율에 영향이 없다. 추가 태그는 목표 0으로 시작하고 삭제 태그만 초안/목표 목록에서 제거한다. 다른 비율을 임의로 재조정하지 않는다. 저장된 목표의 비교 기준도 최신 서버 값으로 갱신하되 다른 대상의 동시 목표 변경을 조용히 덮어쓰지 않는다. 합계가 100%가 아니면 기존 안내·저장 제한으로 사용자가 조정한다.
- 활동 태그 변경은 목록·상세·검색 칩을 갱신한다. 삭제된 태그 ID는 검색 선택에서도 제거한다. 태그 갱신이 기록/할 일의 다른 필드 초안을 덮어쓰지 않는다.
- 공유 사용자는 태그 이름을 읽을 수 있어도 관리/저장 버튼과 쓰기 권한이 생기지 않는다. 두 태그 영역의 기존 소유권/공유 경계를 보존한다.
- MCP의 태그 관리/선택 계약은 그대로다. 웹 위치가 적힌 가이드만 확인하고 낡은 설명이 있으면 갱신한다. 의미 변경이 없다면 검토 결과를 남긴다.

## 구현 범위와 순서

1. 배분 태그 관리 한 흐름을 완성한다. 기존 `ModalShell`/`ConfirmDialog`와 태그 액션을 재사용하고, 별도 `TagEditorModal` 진입을 같은 본문 편집으로 대체한다. 실제 저장·삭제·재조회·목표 초안 보존을 검증한다.
2. 활동 페이지에 같은 관리 흐름을 적용한다. 목록/선택/입력/액션 표현 중 두 소비자가 공유하는 최소 부분만 추출하고, 서로 다른 API/권한/후처리는 각 기능에 둔다. 공통 태그 프레임워크를 선행 구현하지 않는다.
3. `ActivityTagPicker`를 선택 전용으로 줄이고 `GeneralActionModal`, `ActivityDetailModal`, `GeneralTaskDetail`, 검색 필터 연결 및 기존 E2E를 갱신한다. 도달 가능한 옛 편집 경로와 관련 코드만 제거한다.
4. #126의 남은 검증 상태를 유지하면서 이번 규칙의 실제 적용·검증을 기록한다. 기존 #121/#123/#125 티켓 전체를 다시 구현하거나 자동 완료 처리하지 않는다.

## 완료 기준

- [x] 배분·활동 모두 페이지→태그 관리 한 모달에서 검색·추가·편집·저장·삭제를 수행한다. 일반 속성 편집용 2차 모달이나 관리창 닫기→편집창 재열기 경로가 없다.
- [x] 2차는 삭제·초안 폐기 등의 의사 확인에만 쓰인다. 변경 사유 예외가 일반 편집으로 확대되지 않는다.
- [x] 활동 추가/기록/할 일 상세에 태그 사전 CRUD가 없고 선택/해제만 본문과 함께 저장된다. 선택 칩은 `aria-pressed`와 키보드 버튼으로 표현한다.
- [x] 이름 변경·삭제가 모든 표시와 필터에 반영되고, 관련 원본 데이터와 다른 초안은 유지된다. 자산 태그 삭제/추가 뒤 목표 목록과 합계/충돌 검증이 실제 서버와 맞는다.
- [x] 조회 실패, 저장 실패/동일 요청 재시도, 저장 후 조회 실패, 미저장 대상 전환/닫기, 삭제 취소·실패를 검증한다. 공유 읽기 전용 경계를 확인한다. 자산 태그는 일반 실패 후 초안 보존·재시도를 확인하며 결과불명 응답의 자동 복구는 요구하지 않는다.
- [x] 360/390/768/1024/1440px에서 긴 이름·많은 태그·빈값·오류·footer와 스크롤/포커스를 검증한다. 미검증 실기기 범위를 명시한다.
- [x] 관련 테스트·빌드·인코딩·diff 검사와 최신 문서를 갱신한다. DB/MCP 의미가 그대로여서 migration/도구를 추가하지 않았다.

## 이전 설계와의 관계

#126은 확인 계층의 기반이며 이 티켓은 용도 제한과 태그 관리 소비 흐름을 보완한다. #125의 ‘태그를 한 곳에서 편집’은 기록에 붙일 태그 선택에 적용하고 태그 사전 편집을 상세에 유지하라는 의미로 읽지 않는다. #123의 단일 저장은 현재 선택한 대상에 적용한다. 태그 목록 전체를 한 원자 쓰기로 확장하지 않는다.

## 로컬 구현과 검증

- `TagManagerModal` 한 본문에서 목록/검색/새 태그/선택 태그 편집을 제공한다. 배분은 `AssetViewToolbar`, 활동은 `LifecyclePage`의 페이지 도구에서 연다. `ModalShell`의 미저장 닫기와 `ConfirmDialog`의 태그 삭제·대상 전환 확인을 사용한다. 브라우저 뒤로가기도 기존 상세 이력 보호를 재사용한다.
- 자산 태그는 기존 `app_save_tag`/`app_delete_tag`, 활동 태그는 기존 버전·멱등성 있는 `app_save_activity_tag`/`app_delete_activity_tag`를 사용한다. 두 영역의 조회/후처리는 각 페이지에 둔다. 구 `TagEditorModal`과 연결 액션·상태는 제거했다.
- 활동 추가·기록·할 일 상세의 `ActivityTagPicker`는 기존 태그 선택만 한다. 연결 변경은 기존 기록/할 일 저장에 포함된다. 이름 변경/삭제는 활동 목록·필터를 다시 읽는다. 초기 태그 조회 실패/진행 중에는 빈 목록으로 오인해 관리창을 열지 않도록 버튼을 비활성화하고 페이지의 재시도를 사용한다.
- 배분은 태그 변경 뒤 서버 목표와 태그를 다시 읽고 ID별 입력 초안을 유지한다. 서버의 다른 목표 값이 함께 바뀌었다면 목표 저장을 막고 최신 목표를 명시적으로 불러오게 한다. 목표가 있는 태그 삭제는 기존 DB 보호 트리거가 거부한다.
- `npm test`: 102개 통과. `npm run build`, `npm run check:encoding`, `git diff --check`, `npm run check:workflow-guides` 통과. 격리 E2E의 DB 542개·MCP 계약과 활동/탐색 브라우저 28개가 통과했다. 추가 배분 태그 관리자 360/390/768/1024/1440px, 미저장 대상 전환, 삭제 취소, 목표 초안 보존, 이름 변경·실제 삭제 후 목표 목록 갱신 테스트는 별도 재검증했다. 뒤이은 RPC 어댑터 위치 정리는 동일 인자를 확인하는 단위 테스트와 빌드로 확인했다.
- MCP 태그 도구의 입출력·의미는 바뀌지 않았다. `docs/design/contracts/agent/tool-descriptions.md`와 워크플로우 가이드에서 웹 태그 관리창 위치를 지시하지 않아 설명 변경이 불필요했다. 문서만 갱신했고 운영 DB·함수·웹 배포는 수행하지 않았다.
- 후속 로컬 검증: 양수 목표의 태그 삭제는 서버가 거부하고 확인창·원본 태그가 유지된다. 외부에서 목표를 바꾼 뒤 태그를 갱신하면, 초안이 깨끗할 때는 최신 목표가 반영되고 초안이 있으면 값을 보존하며 충돌을 알리고 명시적 재조회 전에는 저장을 막는다. 이 과정에서 발견한 무초안 재조회 누락을 수정했다.
- 활동 태그는 첫 쓰기 실패 후 같은 멱등 키로 재시도하고, 쓰기 성공 뒤 조회 실패 시 읽기만 재시도해 한 행만 남는다. 자산 태그도 서버에 도달하기 전 실패한 쓰기의 초안 보존·재시도·중복 행 없음을 확인했다. 빈 태그 목록과 조회 오류, 미저장 전환/닫기, 삭제 취소/서버 거부를 구분했다. 공유 사용자는 배분·활동의 태그 관리 버튼이 없고 소유자 데이터만 조회한다. 공유 전환 중 제거된 `setTagModal` 호출로 화면이 멈추는 버그도 수정했다.
- 활동 태그 관리자에서 360/390/768/1024/1440px, 긴 이름 12개, 내부 목록 스크롤, 검색 결과 없음, footer 표시, Escape 취소/초안·포커스 유지를 브라우저 자동화로 확인했다. 실제 모바일 가상 키보드·safe-area와 스크린리더 발화는 실기기에서 아직 확인하지 않았다.
- 검증 실행: 단위 102개, 격리 DB 542개, MCP 계약, 관련 브라우저 41개 중 최초 40개 통과 후 발견 버그 수정; 실패 흐름과 동시 목표 재검증 2개 및 자산 재시도·활동 스크롤/키보드 각 1개 통과. `npm run build`, `npm run check:encoding`, `npm run check:workflow-guides`, `git diff --check` 통과. 모든 E2E 초기화는 격리 `.e2e`만 대상으로 했다.
- 단순성 결정: 자산 태그의 `app_save_tag`는 이름의 소유자별 고유 제약은 있지만 멱등 키가 없다. 서버 쓰기 성공 후 응답만 유실되면 같은 이름으로 다시 저장할 때 중복 행 대신 이름 충돌 오류가 보일 수 있다. 발생 가능성과 태그의 위험도를 고려해 이 예외를 #127의 완료 조건에서 제외한다. 이 경우 페이지를 새로고침하여 실제 반영 여부를 확인할 수 있다. 별도 receipt·자동 복구·신규 migration은 만들지 않는다. Supabase RPC 경계 확인과 격리 DB/E2E 검증 결과를 그대로 유지한다.
- 아직 하지 않은 일: 운영 배포 및 실제 모바일 키보드·safe-area·스크린리더 평가. 로컬 자동 검증 완료와 구분한다.

## 실기기 확인 절차 (운영/테스트 빌드 적용 후)

1. 휴대폰에서 배분과 활동의 `태그 관리`를 각각 열어 긴 태그가 있는 목록을 스크롤한다. 헤더와 하단 `닫기 / 저장`이 보이고 배경 페이지가 함께 움직이지 않는지 확인한다.
2. 태그명을 편집하며 가상 키보드를 열고 닫는다. 입력과 저장 버튼이 가려지지 않고 화면 아래 안전 영역에 걸치지 않는지 확인한다.
3. 미저장 상태에서 닫기·다른 태그 선택을 시도한다. 확인창에서 `계속 편집`을 누르면 입력과 초점이 유지되고, `변경 버리기`에서만 사라지는지 확인한다.
4. VoiceOver 또는 TalkBack에서 대화상자 제목, 태그 목록의 선택 상태, 입력 라벨, 오류와 확인 버튼을 순서대로 읽고 조작할 수 있는지 확인한다. 실제 기기·OS·브라우저와 결과를 이 티켓에 기록한다.
