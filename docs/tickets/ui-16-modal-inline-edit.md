# [공통 UX] 모든 상세 모달의 직접 편집·단일 저장 적용

2026-09-24 · 할 일 상세 수직 슬라이스 진행 중, 전수 적용 전.

GitHub: https://github.com/kimyongin/fin/issues/123

기록 추가/상세의 후속 UI와 종목 참조 전환은 [#125](./activity-16-record-editor-simplification.md)를 따른다. 태그는 접기 없이 하나의 표시/편집 영역을 사용하고 종목·할 일은 검색 결과에서 바로 선택한다. 관련 할 일 요약과 선택기를 중복 표시하지 않는다. 직접 편집·원자 저장은 유지하며 아직 새 설계 구현 전이다.

자산 후속 설계는 [#124](./ui-17-asset-detail-simplification.md)를 따른다. 자산 메모·필드를 줄이고 접기를 없애며 보유값 저장 직전에만 작은 사유 확인창을 제공한다. 배경 상세는 초안을 보존한 비활성 상태이며 활성 dialog/포커스 트랩은 하나다. 이 확인창은 속성 편집 모달 왕복 금지의 명시적 예외이며 다른 모달에 의무 사유 입력을 확대하지 않는다.

## 결정과 범위

사용자는 #120의 ‘상세에서 바로 속성을 편집하고 한 번에 저장’을 모든 모달의 공통 원칙으로 확정했다. [모달 디자인 가이드](../design/modal-guidelines.md)의 해당 규칙이 정본이다. #117 당시 별도 읽기/편집 모드·태그 별도 저장 유지 요구를 대체한다. 과거 구현/검증 기록은 당시 결과로 보존한다.

편집 권한이 있는 현재 대상의 상세는 모든 수정 가능 속성을 같은 본문에서 바로 편집하고 하단 저장 하나로 반영한다. 미저장 상태를 하나로 관리하며 같은 대상의 태그 선택도 포함한다. 다른 업무 행동과 실제 읽기 전용 대상은 가이드의 명시적 구분을 따른다. 현재 요청 범위는 문서/티켓 정리이며 제품 코드 변경은 하지 않았다.

## 적용 책임

| 범위 | 담당과 적용 |
| --- | --- |
| 자산 종목/보유 상세·메모 | #120이 직접 편집·원자 저장·단일 shell 금융 단계를 구현 |
| 활동 기록 | #122 새 본문/태그/참조를 기준으로 이 티켓에서 별도 편집 모드·태그 저장을 제거. 필요 저장 계약은 #122와 한 번만 구현 |
| 할 일 상세 | 기존 수정 가능한 제목/일정/본문/태그를 직접 편집. 완료/다시 열기/반복 종료는 별도 업무 행동 유지 |
| 원칙 | #118의 현재 원칙 편집에 적용. 과거 원칙 본문은 읽기 전용이며 복원/과거 편집을 추가하지 않음 |
| 계좌·보유·종목·태그 등록/수정 | 기존 직접 입력 폼을 재사용하고 빠진 초안/통합 저장/닫기 규칙 점검 |
| 배분 | #121에서 별도 설정 모달 자체가 제거되므로 구 모달을 다시 정돈하지 않음 |
| 나머지 실제 진입 모달 | 공유/조회/계산/피드백/연결 등 실제 경로를 조사해 직접 편집 적용 또는 읽기 전용/별도 행동의 이유 기록 |

## 구현 방식

1. 실제 진입 경로와 각 모달의 수정 가능 속성·읽기 전용 값·별도 업무 행동·쓰기 API를 목록화한다. 사라질 종류별 활동 모달과 배분 설정은 #121/#122에 따라 제거 대상으로 분류한다.
2. #118/#120/#122 소비자와 중복 개발을 피하며 순차 적용한다. 공통 ModalShell/ModalActions를 재사용하고 폼/저장 단위는 기능이 소유한다. 먼저 전 화면용 범용 폼/명령 프레임워크를 만들지 않는다.
3. 제목/본문/태그 등 같은 대상 변경이 한 번에 성공하도록 기존 원자 API를 재사용하거나 목적별 API를 최소 보완한다. 중간 실패에 일부만 저장되는 경로를 없앤다. 신규 API가 필요하면 해당 기능 티켓에 계약·인증·검증·배포 변경을 기록한다.
4. 수정 권한이 없는 사용자/과거 이력/파생값은 읽기 전용이다. 관련 할 일의 요약처럼 참조한 다른 대상을 무조건 현재 기록의 저장 범위에 넣지 않는다. 다른 대상 편집은 동일 shell 전환 또는 원래 화면의 직접 편집으로 연결한다.
5. 저장 후 재조회 실패·닫기·초안이 있는 상태의 별도 행동·뒤로가기·resize에 일관된 동작을 적용한다. 등록 성공 후 닫기와 상세 저장 후 유지의 차이는 가이드에 따른다.

## 완료 기준

- [ ] 도달 가능한 모든 모달의 적용/읽기 전용/별도 행동/퇴역 목록과 근거를 기록했다. 자산만 바꾸고 전체 완료라고 표시하지 않는다.
- [ ] 현재 대상의 편집 가능 속성을 수정 버튼이나 다른 모달 없이 편집하고, 태그 선택까지 한 번 저장한다.
- [ ] 같은 대상의 다중 필드 쓰기가 원자적이며 일부 저장 실패·중복 클릭·응답 유실·재조회 실패를 검증했다.
- [ ] 기본 동선에 읽기→편집 모드 전환이 없고 실제 읽기 전용 정보는 일반 텍스트로 표시한다. 저장 후 상세는 유지된다.
- [ ] 별도 확정/삭제/참조 이동/미저장 확인을 포함해 활성 dialog가 하나이고 초안·초점·복귀 맥락을 보존한다.
- [ ] 각 소비자에서 360/390/768/1024/1440px, 긴 내용/오류/권한 없음/초안/키보드/하단 버튼을 검증하고 실제 범위를 기록한다.
- [ ] 해당 API·MCP 교차 회귀와 E2E·빌드·인코딩을 검증한다. 전수 적용 현황과 아직 미구현/미검증인 경로를 가이드/티켓에 반영한다.

운영 배포·실기기 검증은 로컬 구현과 별도 상태로 기록한다.

## 구현 기록 (할 일 상세)

- `app_get_general_task`의 소유자 응답에 현재 태그를 포함했다. 공유 사용자의 상세는 기존 좁은 읽기 모델을 유지한다.
- `app_save_general_task_detail`은 기존 할 일 필드 저장과 태그 저장을 같은 DB 트랜잭션으로 연결한다. 복합 응답의 idempotency receipt를 재사용하므로 응답 유실 후 같은 요청을 다시 보내도 중복 업데이트하지 않는다. 태그 검증 실패는 필드 업데이트와 활동 기록까지 함께 롤백한다. 기존 `app_save_general_task`와 MCP 계약은 유지한다.
- 할 일 상세에서 제목·확인할 때·예정일/매일 반복·태그를 초안으로 직접 편집하고 하단 저장 하나로 반영한다. 별도 반복 종료는 그대로 업무 행동이며, 미저장 초안 중에는 실행하지 않는다. 친구의 상세는 읽기 전용이다.
- 자산 상세 및 나머지 모달 전수 적용은 완료하지 않았다. 이 중간 상태를 #123 완료/운영 배포로 표시하지 않는다.

## 구현 기록 (활동 기록 상세)

- 기존 기록 상세의 `수정` 모드와 `태그 저장` 별도 버튼을 제거했다. 소유자는 서버에서 허용된 본문/날짜 필드를 바로 편집하고 태그와 함께 하단 `저장` 하나로 반영한다. 공유 사용자는 계속 읽기 전용이다.
- `app_save_activity_detail`은 기존 필드·태그 검증 함수를 재사용하는 하나의 트랜잭션이다. 필드만/태그만/둘 다 변경을 구분해 불필요한 쓰기를 줄이고, 복합 응답의 멱등 영수증을 남긴다. 태그 검증 실패 시 필드 변경도 롤백한다. #122가 내부 활동 모델을 바꾸면 이 목적별 조합 API도 같은 저장 계약으로 갱신한다.
- 이 단계는 기존 서버의 `editable_fields` 제한을 유지한다. 자동 기록을 포함한 전체 편집 권한 변화와 보유 참조/공유 단순화는 #122에서 처리한다. 자산 상세와 나머지 모달 전수 적용은 여전히 미완료다.
- 검증: 격리 `.e2e`에 두 목적별 migration을 적용하고 기존 DB 564개, OAuth/토큰 MCP 계약, 할 일 상세 저장·태그 오류 롤백, 활동 상세 저장·태그 오류 롤백을 통과했다. 활동 브라우저 전체 16개 중 새 UI에 맞추기 전에는 1개가 태그 관리 버튼의 모호한 선택자로 실패했고, 해당 행을 특정하도록 수정한 표적 재실행은 통과했다. 단위 106개·빌드·인코딩·워크플로우 가이드 검사 통과. 일반 로컬/운영 DB에는 적용하지 않았고, 실제 모바일·친구 공유 화면 전수 검증은 남아 있다.

## 2026-09-24 후속 대조

- #120 자산 상세는 종목/계좌별 보유/메모/태그를 한 초안에서 원자 저장한다. 매매·확인·보유 삭제는 같은 자리에 전환하는 별도 업무 행동이다. 상세에서 다른 편집 모달을 겹쳐 띄우지 않는다.
- #122 활동 상세는 구 판단/점검 별도 진입을 제거하고 본문·날짜·태그·할 일/보유 연결을 직접 편집해 한 번 저장한다. 자동 기록도 본문/연결을 편집할 수 있지만 금융 영수증·할 일 회차 상태는 변경하지 않는다. 활동 추가는 등록 폼이므로 별도 수정 모드가 없다.
- 할 일 상세는 기존 제목·일정·확인할 때·태그 단일 저장을 유지한다. 완료·반복 종료는 업무 행동으로 분리한다. 원칙은 현재 Markdown 편집/변경 메모, 과거는 읽기 전용이다. 표 편집은 기존 전체화면 예외다.
- 계좌·보유·종목·태그 편집 폼과 자산 태그 관리 목록은 현재 단일 shell을 사용하지만 긴 내용·실제 모바일 키보드·초점/복귀 맥락의 전수 검증이 남았다. 사용되지 않는 `HoldingReasonModal`은 진입 경로가 없어 후속 정리 후보이며 완료 범위에 넣지 않았다.
- 로컬 단위/DB/MCP/활동·자산 브라우저 경로는 검사했으나 모든 모달의 오류·응답 유실·모든 viewport 조합과 운영/실기기 검증은 끝나지 않았다. 따라서 #123 전체 완료로 표시하지 않는다.

## 2026-09-24 도달 경로 재점검 및 일반 로컬 적용

`src/`의 `ModalShell` 호출과 실제 import/진입 경로를 다시 대조했다. 상세에서 다른 dialog를 쌓는 활성 경로는 없으며, 더 이상 import되지 않는 `HoldingReasonModal`은 삭제했다. 모달마다 별도 저장 프레임워크를 만들지 않았다.
