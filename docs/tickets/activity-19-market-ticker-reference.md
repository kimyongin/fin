# [활동] 관련 시장 종목을 등록 ID 대신 티커로 연결

상태: 구현 중 · 2026-09-27
GitHub: https://github.com/kimyongin/fin/issues/166

## 목적

보유·등록 여부와 무관하게 시장 종목을 조사하고 기록한다. 자산 목록에서 종목을 삭제해도 기록의 대상은 남아야 한다. 예금·현금성·평가형 자산은 관련 종목으로 연결하지 않고 활동 태그와 본문으로 표현한다.

현재는 `activity_events.instrument_id`를 저장하며 같은 소유자의 등록 종목만 연결할 수 있다. FK의 `ON DELETE SET NULL` 때문에 종목 삭제 시 연결이 사라진다. 할 일의 `subject.instrument_id`와 검색 필터도 ID 기반이다. 이 티켓은 활동 참조 계약만 바꾸며 자산 테이블의 PK·보유 연결·금융 쓰기 대상을 티커로 바꾸지 않는다.

## 최소 계약

- 기록은 선택적 `instrument_ticker` 하나를 정본으로 저장한다. 종목 테이블 FK를 요구하지 않으며 ID와 티커를 영구 이중 관리하지 않는다. 기존 할 일의 종목 참조도 `subject.instrument_ticker`로 맞춰 같은 필터로 찾는다. 별도 관계/종목 카탈로그 테이블이나 복수 종목 기능은 만들지 않는다.
- 저장값은 기존 시세 공급자와 호환되는 정규화 티커다. 공백 제거·영문 대문자화, 국내 코드의 선행 0과 `.KS`/`.KQ`, 종목 클래스 구두점을 보존한다. 숫자 코드만으로 거래소를 추측하거나 이름을 티커로 저장하지 않는다. 정확한 길이·허용 문자·오류 예시는 구현 첫 단계에 기존 자산 티커 규칙과 대조해 확정한다.
- 등록되지 않은 티커도 명시적으로 입력해 저장할 수 있다. 형식 검사는 상장·실재 확인을 보장하지 않는다. 후보 밖 입력을 자동 확정하지 않고 사용자가 티커를 확인해서 연결한다. 자동 종목 등록·시세 조회/갱신은 하지 않는다.
- 현재 소유자의 등록된 `market` 종목이면 이름을 부가 표시한다. 없으면 티커만 표시하고 오류/끊어진 연결로 취급하지 않는다. 다른 사용자의 종목명·메모·보유를 가져오지 않는다. 예금·평가형 자산은 후보에서 제외하고 내부 생성 코드를 시장 티커로 제안하지 않는다.
- 종목 삭제·재등록과 이름 변경은 저장 티커를 바꾸지 않는다. 실제 시장 티커 변경도 과거 기록을 자동 재작성하지 않는다. 필요할 때 소유자가 기록을 수정한다. 상장 이력·티커 별칭/재사용 판별 엔진은 범위 밖이다.
- 생성/편집/조회/검색의 웹 HTTP와 OAuth MCP 계약을 함께 전환한다. 수정에서 필드 생략은 유지, `null`은 해제다. 기존 태그 원자 저장·할 일 연결·반복 회차·검색 근거/커서 계약은 보존한다.
- 자동 금융 기록은 대상이 시장 종목일 때 티커를 남긴다. 비시장 자산 기록은 종목 참조 없이 기존 읽을 수 있는 제목·본문·선택 태그를 유지한다. 금융 실행은 기존 holding ID·소유권·멱등성·원자성을 그대로 사용하며 기록의 티커 변경이 금융값에 영향을 주지 않는다.
- 티커 필터는 정확한 정규화 값으로 비교한다. 본문에 티커가 등장한 결과와 명시적 연결 결과를 구분한다. 같은 티커라도 소유권과 승인된 전체 공유 경계를 먼저 적용한다. 티커는 접근 권한이 아니다.

## 기존 데이터와 배포

- 시장 종목 ID 참조는 소유자 일치 확인 후 티커로 이관한다. 본문·태그·task_id·시각·금융 receipt는 보존한다. 과거 이미 끊어진 참조는 추측해서 복원하지 않는다.
- 비시장 연결은 해제하되 기존 대상 이름/내부 코드를 잃지 않게 본문에 짧은 관련 자산 문구를 중복 없이 보존한다. 기존 본문을 덮어쓰거나 자산 태그를 활동 태그로 자동 복제하지 않는다. 할 일은 설명에 동일하게 보존한다. 변환 전후 건수와 예외를 기록한다.
- 추가 migration으로 이관한다. 기존 migration 수정·운영 초기화는 하지 않는다. 서버 전환 → Edge/MCP → 웹 → 구 참조 종료의 호환 순서를 구현 기록에 명시한다. 필요한 짧은 구 ID 입력 adapter는 owner 검증 후 티커로 변환하고 종료 조건을 정한다. 양쪽 입력 충돌은 거부한다. 영구 이중 쓰기는 하지 않는다.
- 이관 검증과 사용처 전환 후 활동 `instrument_id` FK/트리거와 할 일의 구 subject 키, ID 검색 분기를 제거한다. 원본 관계 백업과 부분 배포 실패 복구 방법을 배포 전에 확인한다.

## 구현 순서와 분담

1. 실제 쓰기/조회/자동 기록/검색 사용처를 조사하고 정규화·구 입력 호환 계약을 고정한다.
2. 미등록 티커 기록 저장 → 웹/HTTP/MCP 재조회·수정·해제·종목 삭제 후 유지까지 첫 수직 슬라이스로 검증한다. 기존 모달 입력을 재사용한다.
3. 기존 할 일·자동 금융 기록·검색·공유·데이터 이관을 연결하고 구 참조를 종료한다.
4. #163은 이 계약을 소비하는 검색창 자동완성/필터 UX를 맡는다. 후보는 현재 보는 사용자의 등록 시장 종목 + 접근 가능한 할 일/기록의 저장 티커를 중복 제거한 목록이다. 미등록·삭제된 종목은 티커 일부로 찾을 수 있고 이름을 모르면 이름을 만들어내지 않는다. 외부 전 종목 이름 자동완성은 별도 요구 전까지 추가하지 않는다.
5. MCP 도구 schema/description·workflow guide·review manifest, API 계약·스키마 색인·관련 테스트를 갱신한다. #162 연결 맥락과 #164 에이전트 검증은 이 티커 계약을 사용한다.

## 2026-09-27 로컬 구현·검증

- 첫 수직 슬라이스로 DB `instrument_ticker` 저장/기존 시장 참조 이관, 수동 기록 생성·편집·상세 읽기, 기본/혼합 검색, 등록 시장 종목 후보와 티커 직접 입력, 웹 HTTP/OAuth MCP 계약을 연결했다. 기존 ID RPC는 배포 호환을 위해 남아 있으며 새 웹/OAuth 경로는 티커 RPC를 사용한다.
- 시장/비시장 자동 기록은 기존 금융 대상 ID를 유지하고 새 기록의 시장 티커는 트리거로 채운다. 일반 할 일의 `subject.instrument_ticker`는 저장 시 정규화한다. 과거 시장 task/event 참조를 티커로 이관하고, 비시장 기록의 읽을 수 있는 문구는 보존한다.
- 로컬 일반 DB에 쓰지 않도록 migration과 새 pgTAP 19개를 한 트랜잭션에서 실행해 모두 통과하고 롤백했다. 등록 재시도, 같은 값 저장, 수정·해제, 할 일 작성, 금융 기록의 티커 채움, 허용된 친구 읽기와 비인가 사용자 차단도 포함한다. `npm test` 25파일/127개, `npm run build`, 6개 Edge 진입점의 `npx deno check`가 통과했다. workflow guide review manifest도 새 계약으로 갱신해 검사가 통과했다.
- 이관 전 형식의 시장 할 일 ID와 비시장 기록 본문을 트랜잭션에 넣은 뒤 migration을 적용하고, 시장 티커·비시장 자산명 보존을 확인한 후 롤백했다. 운영 데이터 이관 건수와 예외는 운영 적용 전 별도로 확인한다.
- 격리 E2E 실행기의 migration 동기화는 현재 작업 트리의 기존 미추적 `.e2e` migration 파일을 덮어쓰므로 실행하지 않았다. 실제 웹 로그인·OAuth MCP 호출, 공유/화면 폭/200% 확대, 운영 DB 이관·배포는 미검증이다.
- 후속 구현에서 구 ID 입력/검색/상세 함수와 컬럼·트리거의 종료 시점 및 비시장 할 일의 긴 설명 예외를 확인해야 한다. #163의 검색창 자동완성과 미등록 티커 후보 통합은 별도 티켓이다. 새 migration을 운영에 적용하기 전 현재 운영 schema 상태와 중간 버전 클라이언트의 호환을 다시 검증한다.
