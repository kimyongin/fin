# [MCP-first] 실제 잔고 확인 시점·범위 기록과 상태 표시

## 자산 유형 및 입력 흐름과의 경계
- 시장형의 수량/평균가 확인과 평가형·현금성의 실제 입력 필드 확인 범위를 구분한다. 지원하지 않는 확인 유형은 명시한다.
- 값 없는 확인, 보정, 매매의 UI 의미를 #36/#38과 공유한다. 잔고 확인용 대형 화면으로 기존 자산 조회를 대체하지 않는다.

## 선행 작업
- #32 제품 계약, #33 OAuth MCP 계약
- #37/#38에서 제공할 거래/보정 버전 계약과 통합하되, 읽기 파일럿용 확인 기능은 먼저 구현할 수 있다.

## 사용자 가치
앱 계산의 정확성과 실제 증권사 잔고 확인 여부를 구분하고, 차이가 나도 쉽게 현재 기준을 다시 맞춘다.

## 설계
- “증권사 잔고와 확인했어”라는 사용자의 명시적 동작으로 확인 이벤트를 기록한다.
- 확인 대상은 계좌/보유 항목 및 수량·평균가 필드를 명시하고 해당 스냅샷/버전과 confirmed_at을 보존한다. 수량만 확인한 경우 평균가까지 확인되었다고 표시하지 않는다.
- 브리핑 조회/저장, 시세 동기화, 매매 입력은 잔고 확인일을 갱신하지 않는다.
- 앱에서 동일 잔고 확인(값 변경 없음)과 잔고 보정(값 변경 있음)을 구분한다. MCP도 같은 의미로 동작한다.
- 확인 후 거래가 들어오면 “마지막 확인 이후 거래 반영”으로 표시한다. 일부 계좌 확인을 전체 확인으로 승격하지 않는다.
- 앱/도구에 마지막 실제 확인, 마지막 매매 입력, 시세 기준시각, 브리핑 생성시각을 별도 필드로 제공한다.
- “미확인”과 “오래 확인하지 않음”을 실제 불일치와 구분한다. 근거 없는 신뢰도 점수나 반복적인 빨간 경고를 만들지 않는다.
- 일일 점검은 확인을 강요하지 않는다. 사용자가 불일치를 알렸을 때 보정 흐름으로 연결한다.
- 확인 도중 버전 변경을 검증하고 중복 요청을 안전하게 처리한다. 타 사용자 데이터 확인은 금지한다.

## 완료 조건
- [ ] 단일 항목/계좌 일부/전체 확인의 표시가 실제 범위와 일치한다.
- [ ] 가격 갱신·브리핑 저장 후에도 마지막 잔고 확인일이 유지된다.
- [ ] 확인 이후 매매·보정·동시 편집 상태를 오해 없이 표시한다.
- [ ] 확인하지 않은 계정도 브리핑 이용이 가능하며 필요한 한계만 간결히 표시한다.
- [ ] 기존 데이터에 확인 날짜를 임의로 채우지 않는다.
