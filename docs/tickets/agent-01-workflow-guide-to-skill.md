## 목적과 범위

사용자가 “포트폴리오에서 ~ 해줘”라고 요청하거나 Portfolio 플러그인을 선택한 상태에서, 가이드·태그·검색 순서를 반복 지시하지 않아도 필요한 현재값과 저장 지식을 찾아 활용하게 한다. 재사용할 새 결론은 사용자가 기록을 먼저 요청하지 않아도 초안으로 제안하고 동의 후 저장한다. `get_workflow_guide`의 모든 topic을 스킬로 이관하고 가이드 도구·중복 prompt/resource·전용 유지 체계를 제거한다.

Portfolio를 지정하지 않은 일반 질문에서 플러그인이 자동 선택되는지는 인수 조건이 아니다. 자연어로 Portfolio를 지정한 요청과 UI에서 플러그인을 선택한 요청은 각각 확인하며, 한 경로의 성공을 다른 경로의 성공으로 간주하지 않는다.

플러그인에는 `portfolio` 진입 스킬 하나와 여섯 참조(지식 검토, 자산, 원칙, 활동, 피드백, 공유)를 둔다. 현재 스킬과 중복 진입점으로 함께 배포하지 않는다. 도구의 스키마/효과/복구 설명과 서버의 권한·원자성·중복 쓰기 방지는 유지한다. 새 DB·새 가이드 API·대화 엔진은 만들지 않는다.

## S1 — 자연어 검토부터 승인된 기록까지

소비 시나리오: “포트폴리오에서 지금 배분을 바꿔야 할지 검토해줘” → 필요한 현재값·저장 지식 자발적 조회 → 근거 답변 → 새 판단의 기록 초안 → 동의 → 단일 활동 저장·재조회. DB/UI 변경은 없다.

- [x] `plugins/portfolio/skills/portfolio/`에 한 진입점과 참조 구성을 구현하고 구 활성 진입점을 대체한다. 실제 도구 입력은 현재 schema를 사용하며 스킬에서 가이드 호출을 요구하지 않는다.
- [x] 기존 이론/뉴스/결정, 태그 보완·원문 검토·당시 근거 보존, 쓰기 동의와 자동 기록 중복 방지 계약을 이관한다.
- [x] 정본의 기존 `portfolio-knowledge-review` 문단별 통합표에 따라 공통/판단/기록 조작 지침을 배치한다. 구 스킬을 통째로 중복 복사하지 않고 가이드 조회·20개 예상·무조건 태그 조회를 정리한다. 자발적 초안 제안이 구 가이드의 “요청 시 저장” 때문에 사라지지 않아야 한다.
- [x] 활동·종목 메모·원칙·할 일·배분·제품 피드백의 저장 대상 선택표를 검증한다. 투자 판단 스킬을 통합했다는 이유로 모든 요청을 일반 활동 저장으로 보내지 않는다.
- [ ] Portfolio를 자연어로 지정하거나 UI에서 선택한 요청에서 조회→답변→자발적 초안→승인 후 저장/거절을 검증한다. 태그·검색 도구·기록 요청을 미리 알려주지 않는다. 단순 잔고·앱 개발 문의에서 과잉 적용을 확인한다.
- [x] 스킬 본문·참조를 웹·모바일에 전달할 수 있는지 검증 결과 또는 미검증 사유를 기록한다. 파일 작성만으로 사용자 흐름 완료를 선언하지 않는다.

## S2 — 관리 작업 이관과 서버 제거

소비 시나리오: 원칙 편집, 실제 체결 기록/잔고 보정, 할 일·회고, 피드백·공유. 정본 문서의 11개 topic 매핑과 시나리오 표를 사용한다.

- [x] 나머지 주제의 비자명한 순서·경계·복구를 참조에 이관하고 폐기된 도구·공유·보유 참조 안내를 바로잡는다. 필요한 도구별 계약은 description에 보완한다.
- [x] `workflow-guides.ts`, 가이드 도구 schema/handler/group/enum과 시작 검사, 호출 권고를 제거한다.
- [x] OAuth 일일 검토 prompt/resource와 관련 capability·handler·렌더러를 제거한다. 다른 실제 소비 기능이 없는지 확인한다. 제거한 tools/call은 `-32602`, prompt/resource 메서드는 `-32601`이며 부수 효과가 없다.
- [x] 가이드 전용 source digest/review manifest/검사 스크립트/npm 명령과 CI gate를 제거한다. seed·MCP/unit 테스트에서 가이드 존재를 기대하던 부분을 실제 도구/스킬 전달 및 제거 계약 검증으로 바꾼다.
- [x] 현재 개발 규칙·PRD·계약 문서·배포 안내를 새 책임에 맞춘다. 과거 검증 기록과 ZIP은 이력으로 보존한다. 매 변경마다 스킬 digest를 승인하는 새 체계는 만들지 않는다.
- [x] 인코딩·diff·스킬 형식/파일 링크/패키지 포함, 관련 unit·Edge type·OAuth 인증/도구 발견/오류·실제 저장/재조회·복구·권한·빌드 검사를 수행한다.

## S3 — 한 플러그인 배포와 종료 확인

- [x] 현재 앱 ID와 내부 플러그인 이름을 유지해 더 높은 버전의 단일 ZIP을 만든다. 버전·해시·서버 커밋과 직전 정상 패키지를 기록한다. 별도 Portfolio 항목을 만들지 않는다.
- [ ] [배포 절차](../engineering/chatgpt-plugin-deployment.md)를 따라 승인된 범위에서 기존 플러그인을 갱신하고 웹·모바일 스킬/참조 전달과 대표 작업을 확인한다. 실패하면 서버 제거 배포를 보류한다.
- [ ] 승인된 OAuth Edge 배포 후 새 세션/메타데이터 갱신에서 가이드와 prompt/resource가 없고 실제 도메인 도구가 작동함을 확인한다. 서버와 플러그인의 일시 공존을 최종 완료로 보고하지 않는다.
- [ ] 웹·모바일 각각 Portfolio를 지정한 독립 대화 두 건으로 투자 검토를 반복하고, 기록 초안·동의 후 저장은 별도 사례로 확인한다. 자연어 지정과 UI 선택의 결과를 구분해 기록한다.
- [ ] 스킬 선택 증거·참조 읽기·앱 호출·쓰기 승인·저장 결과를 구별해 기록한다. 확인할 수 없는 증거는 미확인으로 표시한다. 운영 금융값에 임의 시험 쓰기를 하지 않는다.
- [ ] 제거 후 회귀 시 서버 복구→필요한 이전 패키지 내용을 높은 버전으로 재배포하는 순서를 확인하고 실제 수행 여부를 남긴다.

### 남은 인수 조건과 다음 작업

웹에서 자동·명시 선택 대화를 실행했다. 화면에 도구 표시가 없었다. 운영 OAuth Edge 로그에 같은 시간대 ChatGPT 클라이언트 요청이 있었으나 사용자의 다른 ChatGPT 대화에서 발생했을 가능성을 배제할 수 없다. 세 시험 대화의 앱 호출·도구 이름·스킬 참조 읽기는 미확인이다. 세 대화 모두 새로 저장할 가치가 있는 결론인지 불명확해 기록 초안 누락만으로 행동 실패를 단정하지 않는다. 로컬 정적 검사와 도구 회귀 성공은 모델 행동 검증이 아니다. 이 환경에서는 실제 모바일 ChatGPT를 조작할 수 없으므로 S1 행동 평가와 S3를 미완료로 둔다.

웹 행동 미확인의 원인을 조사하고, 스킬/앱 호출이 실제로 확인되는 새 독립 대화 두 건을 재시험한다. 그 뒤 초안 동의/거절과 실제 모바일 참조 전달을 확인한다. 서버 제거 배포는 아래 사용자 지시에 따라 이 검증보다 먼저 진행했다. 운영 복구는 수행하지 않았다.
