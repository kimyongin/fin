# 제품과 구현의 단순성 원칙

2026-09-23 · 승인된 방향 · ADR-0008과 함께 적용.

이 앱은 현재 자산을 쉽게 관리하고 다음 판단을 이어가는 기록장이다. ChatGPT는 조사·해석·설명하고 Portfolio는 기억·계산·검증한다. 사용자가 관리할 개념과 개발자가 유지할 구조를 함께 줄인다.

## 기본 원칙

1. 실제 사용자 시나리오부터 최소 저장 구조를 정한다. 기존 코드가 있다는 이유만으로 기능·테이블을 유지하지 않는다.
2. 현재값을 기본으로 한다. 일반 내용은 같은 행에서 편집한다. 불변성·revision·수정 이력·상태 전이·스냅샷은 구체적인 사용 목적이 있을 때만 둔다.
3. 메모로 충분하면 기존 메모를 사용한다. 조사·판단·점검·회고는 활동의 내용과 결과로 표현한다. 같은 내용을 별도 도메인과 활동 양쪽 정본으로 관리하지 않는다.
4. 할 일은 예정과 반복, 활동은 수행과 결과다. 사전 등록 여부와 관계없이 하나의 활동 화면에서 읽는다. 자동 자산 변경 기록을 사용자가 다시 작성하지 않는다.
5. 독립 조회·권한·수명·무결성이 필요한 데이터만 별도 테이블로 분리한다. 부모와 함께 읽고 쓰는 짧은 출처·조사 범위 배열은 검증된 JSON으로 충분할 수 있다. 모든 도메인을 범용 payload 테이블로 합치지는 않는다.
6. 단순화에는 저가치 기능의 축소도 포함한다. 과거 잔고 재생, 모든 수정 복원, 자동 체결 진행률 같은 기능을 보존하기 위해 새 구조를 추가하지 않는다.
7. 이력 보존과 이력 시스템 운영은 다르다. 기존 데이터는 이관·읽기 가능한 보관으로 보존하되 새 쓰기·호환 API를 무기한 유지하지 않는다.
8. 버전·이력·멱등성을 구분한다. 일반 텍스트의 의무 변경 사유/버전 왕복을 없앤다. 오래된 자산값 덮어쓰기와 매수 중복은 서버에서 방지한다. updated_at을 쓰는 것도 충돌 검사이므로 이름만 바꿔 단순화했다고 하지 않는다.
9. 인증·사용자 격리·명시적 공유·정밀 계산·원자 저장은 유지한다. 민감한 메모를 공개 필드로 옮기면서 공유 범위를 확대하지 않는다.
10. 테이블만 합치고 기존 API·상태·복제 데이터를 그대로 두는 변경은 완료가 아니다. 웹/MCP/가이드/테스트/문서를 함께 줄인다.
11. 수직 슬라이스로 구현한다. 첫 소비자가 없는 공통 프레임워크를 만들지 않는다. 공통 중복 요청 처리도 실제 쓰기 두 곳에서 재사용되는 최소 범위만 만든다.
12. 현재 개발 지침은 한 곳에서 명확히 읽히게 한다. 과거 결정은 이력으로 보관하고 최신 규칙에 누적해서 섞지 않는다.

## 설계·리뷰 질문

원칙은 목적이 확인된 이력 예외다. 같은 테이블에 안정 원칙 ID와 적용 시작 시각·종료 여부를 가진 변경 행을 쌓아 당시 원칙을 조회한다. 일반 메모처럼 덮어쓰거나 종료 시 과거 행을 삭제하지 않는다. 별도 이력 테이블이나 모든 도메인에 적용하는 버전 엔진은 만들지 않는다.

현재 제품의 확정 예: 오류 보유값은 증권사 값을 보고 직접 보정하며 매매 되돌리기를 만들지 않는다. 반복을 멈추면 전체 종료/삭제하고 필요 시 새로 등록한다. 활동 삭제는 잔고나 할 일 상태를 되돌리지 않는다. 원칙은 한 행에 하나씩 저장한다. 세부 수정 이력은 내보내기로 보존할 수 있으며 앱의 과거 상태 복원 기능은 요구하지 않는다.

새 테이블/상태/도구/이력을 추가하거나 유지할 때 티켓에 다음을 짧게 답한다.

- 어떤 사용자 행동에 필요한가? 기존 메모/활동/원칙으로 부족한 이유는?
- 없애면 정확히 어떤 기능을 잃는가? 그 기능이 현재 필요한가?
- 데이터 정본은 어디인가? 편집 시 함께 바꾸는 곳은 몇 개인가?
- 보존 데이터·공유 권한·중복 쓰기에 어떤 영향이 있는가?
- 제거할 기존 테이블/API/분기와 실제 검증은 무엇인가?

테이블 수 자체를 목표치로 강제하지 않는다. 전후 테이블·공개 도구·변경 경로 수와 대표 사용자 흐름을 비교해 복잡도가 줄었음을 확인한다.
