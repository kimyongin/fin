# ChatGPT Portfolio 플러그인 배포

2026-09-30 기준 개인용 ChatGPT 플러그인의 업로드 절차다. 공개 플러그인 디렉터리 제출이나 DB·Edge Function·Pages 배포 절차가 아니다. 서버 계약과 제품 에이전트 행동은 각각 해당 코드·[검증 인계](../design/contracts/agent/portfolio-knowledge-skill-plan.md)에서 확인한다.

| 항목 | 현재 값 |
| --- | --- |
| 패키지 원본 | `plugins/portfolio/` |
| 플러그인 상세 | [포트폴리오](https://chatgpt.com/plugins/plugin_asdk_app_6aba7f7d0ccc8191b9f51834a40e6548) |
| 내부 플러그인 이름 | `dev-6aba7f7d0ccc8191b9f51834a40e6548` |
| 표시 이름 | 플러그인과 앱 모두 `포트폴리오` |
| 참조하는 앱 ID | `asdk_app_6aba7f7d0ccc8191b9f51834a40e6548` |
| 현재 업로드 버전 | `1.1.5` |
| 마지막 업로드 파일 | `artifacts/portfolio-unified-1.1.5.zip` |

ChatGPT에 MCP 앱을 만들면 앱만 담은 플러그인 항목도 생성된다. 여기에 스킬을 추가할 때 **기존 앱 플러그인의 새 버전으로 업로드**한다. 새 개인용 플러그인을 별도로 추가하면 설치 목록에 Portfolio가 두 번 보인다. 앱 연결과 플러그인 설치는 별개 상태이며, 플러그인 ZIP은 `.app.json`으로 이미 만든 앱 ID를 참조한다. 이 ZIP은 현재 GitHub Pages CI가 올려 주지 않으며 ChatGPT에서 별도로 업로드한다. ZIP만 바꾼다고 Supabase의 MCP 서버 코드나 OAuth 앱 연결이 배포되지는 않는다. MCP 도구 계약을 바꾼 릴리스는 [기존 서버 배포 Runbook](./deployment.md)과 해당 전환 계약의 순서를 따른다. 이번 가이드 제거는 새 스킬의 웹·모바일 전달을 먼저 확인한 뒤 OAuth Edge를 배포한다.

## 새 버전 준비

1. 현재 플러그인 상세의 **플러그인 ZIP 다운로드**로 설치된 구성의 내부 `name`과 앱 ID를 확인한다. 같은 플러그인을 갱신할 때는 내부 `name`을 유지한다. `displayName`은 앱과 동일하게 `포트폴리오`로 둘 수 있다. 앱 이름을 설정에서 편집하면 플러그인 상세가 앱 기본 설명·버전 1.0.0으로 돌아갈 수 있으므로 기존 스킬·설명·프롬프트를 담은 새 버전을 같은 플러그인에 다시 올린다.
2. `plugins/portfolio/.codex-plugin/plugin.json`의 `version`을 올리고 필요한 스킬을 `plugins/portfolio/skills/`에서 수정한다. `.app.json`이 현재 앱 ID를 가리키는지 확인한다. 앱을 삭제 후 다시 만들었다면 새 앱 ID와 새 앱 플러그인을 기준으로 패키지를 준비한다. 이전 앱 ID를 그대로 두지 않는다.
3. `plugins/portfolio/`의 **내용**을 ZIP 루트에 담는다. 현재 패키지의 구성은 `.codex-plugin/plugin.json`, `.app.json`, `skills/portfolio/SKILL.md`와 `skills/portfolio/references/`의 참고 문서 7개다. 구 지식 검토 진입점을 함께 넣지 않는다. 별도 `mcp.json`이나 두 번째 앱 전용 플러그인을 만들지 않는다.
4. ZIP 무결성, manifest의 내부 이름·버전·표시 이름, 앱 ID, 스킬·참고 문서의 포함과 상대 링크를 검사한다. `npm test`로 플러그인 연결·도구 참조를 검증한다. 텍스트를 바꿨다면 `npm run check:encoding`과 `git diff --check`도 통과시킨다. 이전 정상 ZIP과 새 ZIP을 혼동하지 않도록 파일명에 버전을 넣고 해시를 배포 기록에 남긴다.

## ChatGPT에 반영하고 확인

1. 정확한 ZIP 파일과 대상 플러그인, 앱 접근 범위를 확인한 뒤 해당 작업의 사용자 승인 규칙에 따라 업로드한다. 이미 만든 [Portfolio 플러그인](https://chatgpt.com/plugins/plugin_asdk_app_6aba7f7d0ccc8191b9f51834a40e6548)의 **추가 작업 → 새 버전 업로드**를 사용한다. `플러그인 압축 파일 업로드`로 새 항목을 만들지 않는다.
2. **새 버전 업로드 메뉴는 파일 선택 창이 아니라 업로드 대화 상자를 연다.** 대화 상자에서 **파일 선택**을 별도로 누른다. 브라우저 자동화에서는 파일 선택을 누르기 *전에* `filechooser` 이벤트 대기를 시작하고, 이벤트가 오면 준비한 ZIP의 절대 경로를 `setFiles`에 전달한다. 2026-09-30 인앱 브라우저에서는 `추가 작업`·`새 버전 업로드`·`파일 선택`에 각각 Enter를 누르는 방법으로 성공했다. 메뉴 직후 파일 선택 이벤트가 없다는 이유로 업로드 불가라고 판단하지 않는다. 이벤트가 없으면 현재 대화 상자와 버튼 상태를 다시 확인한다.
3. **`업로드 중…`은 완료가 아니다.** `새 버전이 업로드되었습니다` 메시지와 상세 화면에 바뀐 버전을 확인한다. 파일 선택 뒤 반영까지 몇 초 걸릴 수 있다. 완료 화면의 `플러그인 보기`가 창을 닫지 않으면 상세 화면을 새로고침해 버전을 확인한다.
4. 상세 화면에서 새 버전, 앱 1개, 스킬 1개, 연결 계정을 확인한다. 설치 목록에 Portfolio가 한 항목인지 확인한다. 구형 시험용 플러그인이 중복 설치돼 있다면 새 항목의 동작을 확인한 뒤 그 시험용 항목만 설치 해제한다. 앱 자체나 연결 계정을 삭제하지 않는다.
5. 웹의 독립적인 새 대화에서 “포트폴리오에서 ~ 해줘”라는 자연어 지정과 UI의 Portfolio 선택을 각각 시험한다. 지정하지 않은 일반 질문의 자동 플러그인 선택은 필수 조건이 아니다. 태그·검색 방법을 지정하지 않아도 필요한 활동을 찾아 활용하는지, 실제 조회 근거와 저장 금지 준수를 확인한다. 자발적 기록 초안과 동의 후 저장은 별도 시나리오로 검증한다. 운영 금융 데이터에 시험 기록을 임의로 추가하지 않는다.
6. 모바일 요구는 실제 ChatGPT 모바일에서 플러그인 노출, 연결 계정, 자동 조회, 근거 표시를 확인해 별도로 기록한다. 웹 성공이나 `Desktop only` 표기 부재로 모바일 통과를 선언하지 않는다.

인앱 브라우저에서 업로드 대화 상자가 열린 뒤의 파일 선택 순서는 다음과 같다. `zipPath`는 검증한 패키지의 절대 경로다.

```js
const chooserPromise = tab.playwright.waitForEvent("filechooser", { timeoutMs: 10000 });
await tab.playwright.getByRole("button", { name: "파일 선택" }).press("Enter");
const chooser = await chooserPromise;
await chooser.setFiles(zipPath);
```

업로드와 설치 성공은 패키지 배포 완료이고, 자동 조회·기록 제안의 제품 동작 완료는 별도 판정이다. 각 배포에는 ZIP 경로·SHA-256, 내부 이름·버전·앱 ID, 대상 플러그인 링크, 설치/연결 상태, 웹·모바일 검증 결과, 미검증 항목과 직전 정상 패키지를 남긴다.

## 실패 시 복구

앱 기반 플러그인은 Plugin Creator 편집 도구가 지원하지 않는다고 응답할 수 있다. 이 경우 기존 상세 화면의 새 버전 업로드를 사용한다. 2026-09-29에는 상세 정보가 앱 기본 버전 1.0.0을 표시하고 다운로드 ZIP도 앱 manifest 두 개만 포함했지만 스킬 상세에는 업로드한 스킬이 남아 있었다. 다운로드 ZIP이나 버전 표시 하나만으로 스킬 소실을 단정하지 말고 실제 스킬 본문과 배포 원본을 함께 확인한다.

- **업로드 거부:** 설치된 버전과 앱 연결 상태를 먼저 확인한다. 내부 이름·버전·ZIP 루트·앱 ID를 대조해 새 패키지를 만든다. 실패한 업로드를 성공으로 기록하지 않는다.
- **중복 항목:** 앱이 만든 플러그인에 스킬이 포함됐는지 확인한 뒤 별도 시험용 플러그인만 설치 해제한다. 이름이 같다는 이유로 앱이 만든 항목을 삭제하지 않는다.
- **동작 회귀:** 마지막 정상 ZIP의 내용을 기준으로 더 높은 버전의 복구 패키지를 만들어 같은 플러그인에 업로드하고 재검증한다. 이 복구 경로는 아직 실제 수행하지 않았다. 서버 계약 문제라면 플러그인만 되돌려 해결됐다고 가정하지 않는다.
- **앱 삭제·연결 해제:** ZIP의 앱 참조는 연결을 복원하지 않는다. 앱을 새로 만들고 필요한 OAuth 연결을 다시 확인한 뒤 새 앱 ID를 참조하는 패키지를 그 앱의 플러그인에 올린다.
