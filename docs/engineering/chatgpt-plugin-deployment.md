# ChatGPT Portfolio 플러그인 배포

2026-09-30 · 현재 운영 경로는 Plugin Creator로 편집하는 개인용 standalone 플러그인이다. 아래 과거 앱 기반 업로드 기록은 현재 절차와 구분한다. DB·Edge Function·Pages 배포는 [서버 배포 Runbook](./deployment.md)의 별도 작업이다.

## 현재 대상과 원본

| 항목 | 현재 값 |
| --- | --- |
| 내부 패키지 이름 | `portfolio-workflow` — 업데이트에서 유지 |
| 표시 이름 | `포트폴리오` |
| 현재 패키지 버전 | `1.2.3` |
| 편집 가능한 manifest | `plugins/portfolio-workflow/plugin.json` |
| 제품 스킬 정본 | `plugins/portfolio/skills/portfolio` |
| 기존 앱 참조 정본 | `plugins/portfolio/.app.json` |
| 패키징 명령 | `python scripts/package-portfolio-workflow.py` |
| 생성 ZIP | `artifacts/portfolio-workflow-<version>.zip` |
| 편집·업로드 | Plugin Creator의 source 조회와 guarded update |
| 구성 | 앱 참조 1개, 스킬 1개, 참고 문서 8개, 계산 스크립트 1개 |

기존 앱과 연결 계정을 재사용한다. 계정의 정확한 backend plugin ID와 현재 release ID는 Plugin Creator 조회 결과에서 확인하고 그대로 사용한다. 표시 이름, 앱 ID, URL slug를 backend ID로 대체하지 않는다. 비공개 계정 식별자·시험 대화 링크·계정 화면은 공개 저장소에 넣지 않는다.

## 수정하고 업데이트하기

1. 지정된 `portfolio-workflow`의 `get_plugin_files`로 현재 파일·scope·현재 release ID를 먼저 읽는다. 필요한 manifest·스킬·참고 문서를 확인한다. 동명 항목이 있으면 ID와 구성으로 대상이 맞는지 확인한다.
2. 제품 지침은 스킬 정본에서 수정한다. 플러그인 표시 이름·설명·버전은 편집 가능한 root manifest에서 수정한다. 내부 이름, 앱 연결, audience, 기본 프롬프트의 값·형식·순서를 보존한다.
3. root manifest 버전을 올리고 패키징 명령을 실행한다. 실행기는 기존 앱 참조와 스킬을 복사해 단일 폴더 ZIP을 만들고 compatibility manifest를 동기화한다. 스킬 복사본을 별도 정본으로 관리하지 않는다. 구 `plugins/portfolio/.codex-plugin/plugin.json`은 기존 앱 기반 배포의 호환 자료이며 현재 업데이트 대상이 아니다.
4. ZIP 무결성·버전·앱 참조·단일 스킬·참고 링크·계산 스크립트 포함을 확인한다. `npm test`, 필요한 계산 검사, `npm run check:encoding`, `git diff --check`를 변경 범위에 맞춰 실행한다. 환경 제약은 직접 수행한 대체 확인과 구분해 기록한다.
5. `update_plugin`에 검증한 ZIP 절대 경로, 확인한 backend ID, 조회한 `expected_release_id`를 전달한다. 성공 응답의 버전과 release를 확인한다. 충돌 시 최신 원본을 다시 읽고 변경을 조정한다. 새 release ID만 끼워 넣어 오래된 패키지를 재시도하지 않는다.
6. source를 다시 읽어 변경 내용과 보존 항목을 검증한다. 설치 화면의 이름·버전·앱 1개·스킬 1개·기존 계정 연결은 host 검증으로 별도 확인한다. 지침 시험은 새 대화에서 한다.

파일 업데이트는 overlay이므로 ZIP에서 빠진 파일이 삭제되지 않는다. skill/file 삭제가 필요하면 이 제한을 명시하고 지원되는 삭제 경로를 확인한다. 업데이트할 때 새 플러그인을 반복 생성하지 않는다.

## 도구와 브라우저 역할

- Plugin Creator: 현재 standalone 플러그인의 source 조회, 지침·metadata 편집, 계정 업데이트.
- Plugin Management: 사용자가 지정한 구형·시험용 플러그인의 설치 해제. 정확한 항목을 대상으로 한다. 기존 앱 기반 canonical 항목의 설치 해제는 앱 연결도 끊을 수 있으므로 단순 중복 스킬 정리 방법으로 사용하지 않는다. standalone 항목의 설치 해제와 앱 연결 제거를 구분한다.
- 브라우저: 설치 화면·새 대화의 실제 동작 시험 또는 지원 도구로 수행할 수 없는 명시적 UI 작업. Creator가 처리하는 업로드를 임의로 브라우저 업로드로 바꾸지 않는다.
- 앱 기반 canonical 플러그인의 Creator 편집 거부는 현재 standalone 플러그인에도 적용되는 제약이 아니다. 구 항목을 웹으로 업데이트하는 절차는 현재 기본 경로가 아니다.
- 플러그인 삭제와 설치 해제, 앱 삭제·연결 해제는 서로 다르다. 영구 삭제만 지원되는 경우 되돌릴 수 없다는 점과 의존 관계를 확인한다.

## 검증과 복구

독립적인 새 대화에서 명시적으로 플러그인을 선택해 실제 조회와 응답을 확인한다. 저장 금지 요청은 쓰기 없이 시험하고, 실제 금융값 변경이나 임시 활동 저장은 별도로 승인된 시나리오에서만 수행한다. source 조회 성공, 계정 릴리스 저장 성공, 설치 화면 확인, 실제 동작 성공은 서로 다른 증거다. 모바일과 일반 질문의 자동 선택은 웹 명시 선택 시험과 구분한다.

동작 회귀가 있으면 직전 정상 source를 기반으로 더 높은 버전의 복구 패키지를 만들어 같은 plugin ID에 업데이트하고 검증한다. 서버 오류는 플러그인만 바꿔 해결됐다고 가정하지 않는다. 서버·DB 변경은 해당 원본과 별도 배포 절차를 사용한다.

전체 Portfolio 스킬을 기존 앱을 참조하는 standalone 플러그인으로 옮겼다.
