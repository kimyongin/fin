# ADR-0001 — MCP-first 책임 분리와 기존 앱 재구성

상태: Accepted (제품·책임 경계만 확정; 상세 스키마/배포 구현은 미완료)
결정일: 2026-09-20

## 배경

기존 앱은 다중 계좌·태그·자산 유형·표 편집과 전략 계산에 강점이 있다. 일일 판단의 연속성을 추가하면서 전체 화면을 새로 만든 시안은 익숙한 자산 관리의 장점을 잃었다. 반대로 모든 기존 화면을 고정한 채 기능만 추가하면 기준 설정·분석·감사 기록이 겹친다.
사용자는 ChatGPT에서 직접 조사·분석한 결과를 OAuth MCP로 저장하고 모바일에서도 사용하려 한다. 별도 skill 설치나 앱 심사를 필수로 하는 배포는 원하지 않는다.

## 결정

1. ChatGPT가 조사·해석·설명을 전담하고 Portfolio가 저장·계산·구조/권한 검증을 전담한다. 서버 내 LLM과 자동/예약 분석은 현재 도입하지 않는다. 사용자 요청이 분석 시작점이다.
2. OAuth MCP를 기본 연동으로 사용한다. 도구 설명·짧은 server instructions·필요한 작업 가이드로 사용 가능하게 하고 prompts/resources/별도 skill 지원을 필수 전제로 두지 않는다.
3. 유용한 자산 작업 방식과 데이터는 유지하되 전략은 원칙·운용 계획과 배분 점검으로 재구성한다. 뉴스는 근거 자료, 활동은 감사 내역으로 재배치한다. 기존 테마와 컴포넌트를 사용한다.
4. 규칙 계산, 모델 제안, 사용자 채택 결정, 계획, 실제 체결을 분리한다. 계획 변경으로 잔고를 바꾸지 않는다. 원칙·근거 버전과 질문 ID로 점검을 이어간다.
5. 앱과 MCP는 같은 계산·저장 의미를 따른다. 초기 등록/대량 편집, 보정, 실제 매매, 실제 잔고 확인을 구분한다. 기존 메모를 확정 보유 이유로 자동 변환하지 않는다.
6. 새 개인 기준·판단은 기본 비공개로 설계하고 기존 공유 필드와 분리한다. 기존 공유 변경은 명시적 정책과 검증이 필요하다. 인증 사용자 격리는 UI뿐 아니라 서버 계약에서 강제한다.

## 검토한 대안과 제외 이유

| 대안 | 제외 이유 |
| --- | --- |
| 독립적인 새 자산 UI로 전면 재작성 | 복수 계좌/태그/표 편집의 익숙한 흐름을 불필요하게 변경 |
| 기존 화면은 모두 고정하고 기능만 추가 | 전략·뉴스·판단의 책임 중복과 복잡성이 커짐 |
| 앱 서버에서 뉴스 수집·LLM 분석까지 수행 | 현재 역할 분담·운영 범위를 넘고 별도 비용/운영이 필요 |
| skill 설치나 MCP prompts/resources를 필수로 요구 | 목표 웹/모바일 환경에서의 가용성을 전제할 수 없음 |
| 활동 로그를 판단 기록으로 재사용 | ‘무엇이 바뀌었나’와 ‘왜 결정했나’의 의미가 다름 |

## 결과와 비용

- 기존 UI·계산을 재사용할 수 있지만 계산 공통화·버전 참조·기존 편집과 원장의 통합이 필요하다.
- MCP 지침만으로 모델 행동을 보장하지 않는다. 권한·버전·상태 전이·중복 방지는 서버에서 검증한다.
- 새 화면과 옛 URL 대응, 자료/활동의 위치 변경, 필드별 공유 정책 및 회귀 검증이 구현 범위에 포함된다.
- 부분 실패·동시 분석·과거 자료 정정은 관계와 이력으로 처리한다. 자유 텍스트 파싱에만 의존하지 않는다.

## 확정하지 않은 사항

정확한 DB 스키마·RPC·반올림·과거 거래 재계산·누락 환율/분모·공개 필드 목록·최종 UI 배치는 이 ADR로 결정하지 않는다. #32/#43/#44 등의 계약 산출물로 확정한다.
웹 실험에서 prompt/resource 미노출이라는 관찰은 모든 클라이언트의 영구적 미지원 증명이 아니다. 모바일/배포 상태는 실제 검증한다.

## 변경 규칙

책임 분리·저장 의미·공개 범위를 바꾸면 새 ADR에서 이 결정을 대체하는 부분과 이유를 기록하고 PRD/티켓을 맞춘다. 단순 문구·간격 변경에 ADR을 강제하지 않는다.
