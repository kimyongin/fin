# ADR-0004 — 도메인 저장 유지와 최소 공통 변경 규약

2026-09-23 후속: [ADR-0008](../adr/0008-minimal-portfolio-storage.md)과 저장 단순화 #86~#91이 충돌하는 저장/이력/기능 유지 요구를 대체한다. 기존 구현·검증 증거와 미검증 외부 게이트는 보존하며 새 구현은 docs/START-HERE.md에서 시작한다.

상태: Accepted (사용자 합의 반영, 2026-09-21). 구현·배포 검증 완료를 뜻하지 않는다.

## 결정과 대체 범위

도메인별 테이블/제약은 유지하고 반복되는 안전 처리만 공통 규약으로 통일한다. 모든 데이터를 type+payload 테이블에 넣거나 범용 CRUD/명령 실행 엔진을 만들지 않는다. 기존 기술 초안의 일괄 head/revisions, 서명 문맥 왕복, 전역 버전 차단, 사건 revision 엔진 요구를 아래 내용으로 대체한다. ADR-0001~0003의 제품·공유·원가 정책은 유지한다.

## 공통 변경 규약

입력은 operation, idempotency_key(중복 쓰기 방지가 필요한 작업), target_id(대상 변경), expected_version(충돌 위험이 있는 현재값 변경), 도메인별 검증된 payload로 구성한다. 이것은 내부 처리 규약이지 새 범용 execute API나 범용 데이터 모델이 아니다. 목적별 API를 유지하고 owner는 인증에서 결정한다.

인증/입력 검증 → 동일 요청의 기존 성공 확인 → 소유권/필요 버전 검사 → 도메인 규칙 → 변경·감사·성공 receipt의 DB 원자 저장을 일관되게 적용한다. 작은 helper와 명시적 RPC부터 구현한다. 읽기/신규 추가에 불필요한 expected_version을 강제하지 않는다. 실제 체결 취소를 일반 DELETE로 처리하지 않는다.

## 버전·이력 최소화

| 대상 | 필요한 보존/검사 | 하지 않을 것 |
| --- | --- | --- |
| 전략/개인 기준 | 현재 행 version + 중요한 변경 이력, 분석/판단 당시 snapshot | 모든 객체에 head/revision 쌍 강제 |
| 보유 이유 | 현재값/version, 명시적 변경 이력·당시 snapshot | 과거 거래 정정에 따른 전체 보유 구간 자동 복원 엔진 |
| 판단 | 결정 레코드, 상태 변경 이력, 후속 결정의 replaces_id, 당시 근거 snapshot | 상태 전이마다 본문 전체 revision 복제 |
| 조사 task | 현재값/version, 답/근거·상태 변경 이력 | 모든 제목/표시 변경을 별도 revision 모델로 승격 |
| 브리핑 | 분석 입력·결과 한 레코드, 정정은 새 레코드+supersedes_id | 1:1 review_run/briefing_revision 분리 |
| 근거 | 불변 출처/요약 기록, 정정은 새 기록+supersedes_id | 별도 사건 head/revision·병합/분리 엔진 선구현 |
| 잔고/체결 | 대상별 버전, 정밀 계산, 절대 기준점, 취소 이력 | 안전 규칙 축소, 불완전 원장으로 현재값 덮어쓰기 |

충돌 방지 version과 사용자에게 필요한 변경 이력은 별개다. 원칙의 과거 변경·판단 근거 보존 요구는 삭제하지 않고 현재 행+변경 이력/소비 시점 snapshot으로 충족한다. JSON은 snapshot/상세 내용에 쓰되 FK·소유권·핵심 계산 필드를 숨기지 않는다.

## 문맥·조사 단순화

- get_daily_context는 서버 소유 임시 context snapshot을 만들고 context_id를 반환한다. 분석/열람/잔고확인 업무 기록을 만드는 것은 아니다. ‘조회는 아무 DB 쓰기도 하지 않는다’는 이전 기술 제약을 대체한다. read-only hint 등 프로토콜 메타데이터는 실제 부수 효과에 맞춰 #33에서 검증한다.
- snapshot은 불변이며 owner/생성시각/만료/대상 범위를 포함한다. 저장 시 서버 원본을 브리핑에 복사하고, 임시 context 삭제가 과거 브리핑을 잃게 하지 않는다. ID를 알아도 타인 접근 금지, 만료면 재조회. 이미 성공한 요청 재시도는 context 만료보다 먼저 성공 receipt를 조회한다.
- 서명·압축·키 회전·큰 문맥 왕복은 도입하지 않는다. 임시 context의 크기·TTL·사용자별 생성 제한·정리 주기와 반복 조회 비용은 첫 기능에서 측정/검증해 확정한다. 임시 저장은 일반 활동 기록/공유 목록에 노출하지 않는다.
- 전역 holdings/metadata/prices 카운터 도입을 첫 기능 선행으로 요구하지 않는다. 체결은 대상 잔고, 질문은 대상 질문 및 실제 변경 의미에 필요한 의존값을 검사한다. 가격 갱신만으로 조사 답 저장을 막지 않는다. 분석은 당시 시각과 알려진 변경을 표시하며 완전한 최신성 검증을 주장하지 않는다.
- 대상별 조사 기록·미확인 구간·열린 질문은 유지한다. 첫 버전은 미해결 구간을 보수적으로 다시 조사하며 반복 조사를 허용한다. 완료구간의 일반 합집합/차집합 엔진은 후순위. 새 성공 기록으로 실패를 닫을 때 같은 대상·명시된 범위 충족을 검사하고 max 날짜만으로 미확인을 지우지 않는다.

## 후순위와 유지할 안전장치

사건 엔진은 기존 근거/판단/task ID 연결로 반복 조사와 정정을 먼저 처리한 뒤 필요성이 확인되면 도입한다. 전량 매도 후 이전 보유 이유는 미적용/재확인으로 두고 자동 재활성화하지 않는다. 과거 수정은 관련 이유를 재확인 필요로 표시하며 자동 복원하지 않는다.

공통 UI·서버 폴더 전체 선구현, 가이드 전용 도구는 선행조건이 아니다. 모달 접근성/입력 보호, 인증·공유·참조 검사, 체결 중복 방지, numeric 계산, 원자성, 절대 보정 정책은 그대로 유지한다.

첫 slice: 서버 context 조회 → 단일 briefing+근거/조사 범위 저장 → 재조회 → 읽기 화면. 이력 UI·질문 변경·체결은 관련 slice에서 통합한다. 후순위는 기능의 자동 완료 판정이나 데이터 보존 요구 삭제를 뜻하지 않는다.
