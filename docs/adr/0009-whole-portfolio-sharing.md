# ADR-0009 — 포트폴리오 전체 읽기 공유

상태: Accepted · 2026-09-26 · #145 로컬 구현, 운영 전환 전. #146 후속 UX는 설계 단계.

## 결정

사용자는 항목별 공개 설정을 제거하고 전체 공개, 설정의 `공유 하기 / 공유 받기` 흐름을 요청했다. 자산·배분·활동(할 일/기록)·원칙(현재와 변경 이력)을 하나의 읽기 전용 포트폴리오로 공유한다. 비밀번호로 검증된 기존 친구/게스트 대상이며 익명 인터넷 공개나 수정 권한을 의미하지 않는다.

접근 조건은 본인 또는 `전체 공유 ON + 유효한 친구/게스트 관계`다. 기능별 허용/거부 설정과 정책 버전 저장소를 제거한다. 기존 `profiles.sharing_enabled`와 관계 검증을 사용하고, 조회별 사용자 콘텐츠 allowlist와 쓰기 소유권 검사는 유지한다. 필요하면 기존 읽기 함수의 기능 키는 지원 리소스 확인용 얇은 호환 인자로 남기되 개별 정책 상태를 두지 않는다.

공유에 포함하는 콘텐츠는 계좌/종목/보유·일반 메모·태그·시세, 배분 목표/현황, 할 일·기록·연결 상세, 원칙의 본문·변경 메모·일시·과거 본문이다. 비밀번호/해시·세션·연결 토큰·친구 목록·설정·제품 피드백·내부 실행 JSON/영수증/임베딩은 제외한다. UI 전체를 그대로 공유하거나 원본 DB 행의 모든 컬럼을 반환하지 않는다. MCP 인증 사용자의 본인 데이터 접근은 그대로다.

## 전환과 구현

기존 공개 범위가 확대되므로 기존 공유를 OFF로 전환하고 새 범위를 명시한 화면에서 사용자가 다시 ON한다. 접속 정보/친구 연결/사용자 콘텐츠는 보존한다. 구 클라이언트가 예전 의미로 ON할 수 없도록 새 ON API는 전체 범위 의도를 명시적으로 받는다. 별도 동의 이력/버전 테이블은 만들지 않는다. 기존 비밀번호·친구/게스트 수명 정책은 바꾸지 않는다.

`공유 하기`는 이름·비밀번호·공유 여부를 하나의 초안으로 편집하고 `저장하기`로 함께 반영한다. `공유 받기`는 이름/비밀번호로 연결하고 목록에서 보기/해제를 제공한다. 이 UX는 [#146](../tickets/ui-34-sharing-form-and-viewers.md)이 #145의 토글 즉시 저장을 대체한 후속 결정이다. 전체 권한·전환 계약은 [#145](../tickets/ui-33-sharing-settings-autosave.md)를 따른다.

소유자는 자신의 설정에서 자신을 연결한 로그인 친구의 공개 이름·아이콘·최근 웹 열람 시각만 조회한다. 기존 friendships에 마지막 시각 하나를 추가하며 일반 공유 콘텐츠에는 관계 목록을 포함하지 않는다. 익명 게스트를 식별하거나 방문 이력/실시간 접속 상태를 만들지 않는다. 연결/열람 안내와 성공한 웹 조회 후의 제한적인 갱신 계약은 #146을 따른다.

ADR-0003의 기능별 정책 확장/권한 묶음, ADR-0008 및 #122의 개별 활동 공유 유지, #118/#132의 원칙 owner-only 읽기 요구를 이 범위에서 대체한다. 사용자 격리·서버 권한 검증·원칙 쓰기/이력 의미·금융 원자성은 유지한다. 이번 결정은 운영 DB 변경이나 배포를 즉시 실행하라는 지시가 아니다.
