# ADR-0003 — 단순한 설정 화면과 기능별 공유 권한 구조

상태: Accepted (설계 방향) · 2026-09-20

## 배경과 결정

사용자는 복잡한 권한 설정을 피하되 기능별 상세 공유 설정으로 확장할 수 있는 구조를 요청했다.
따라서 사용자에게 보이는 설정의 복잡도와 내부 권한 단위를 분리한다. 공유 boolean 하나를 모든 API의 권한 근거로 사용하지 않는다.

- 내부 권한은 안정적인 기능 키와 허용 동작으로 구분한다. 첫 버전 동작은 read만 지원한다. 공유는 편집 권한을 주지 않는다.
- 설정 UI는 권한 묶음(preset)을 제공할 수 있다. preset은 기능별 권한을 일괄 변경하는 편의 기능일 뿐 서버의 별도 우회 권한이 아니다.
- 현재 제안 UI는 기존 공유에 더해 ‘투자 점검 기록도 공유’ 설정이다. 활성화할 때 briefing/decision/task 읽기를 함께 설정하며 개인 기준/보유 이유/비공개 근거는 포함하지 않는다. UI 문구·초기 범위는 검토안이며 실제 공개 전에 범위를 명시한다.
- 이후 상세 설정은 같은 기능별 권한을 개별 편집한다. 사용자별 예외·개별 문서·필드별 권한 엔진을 지금 구현하지 않는다.
- 앞선 ‘민감한 개인 기준은 항상 비공개’ 제안은 영구 제한으로 채택하지 않는다. 기본 비공개로 두고 향후 별도 명시적 설정으로 허용할 수 있도록 키를 분리한다.

## 최소 권한 계약

논리 키는 `owner + audience + feature + action`이다. audience는 서버가 기존 친구/뷰어 접근 관계로 확인하는 공유 대상 집합이다. 임의 클라이언트 입력으로 대상 집합을 인정하지 않는다.
첫 버전에는 기존 공유 대상 집합에 대한 공통 정책만 제공한다. audience 식별 경계를 두어 미래에 친구별 정책을 추가할 수 있지만 현재 친구별 override, 상속, deny 우선순위는 만들지 않는다.

기능 예시: `assets`, `strategy`, `news`, `activity`, `briefings`, `decisions`, `tasks`, `investment_profile`, `holding_theses`, `research_evidence`.
이는 메뉴가 아니라 데이터 경계다. 개인 기준과 기존 공유 전략을 동일한 ‘원칙 메뉴’ 권한으로 합치지 않는다. 정확한 필드 allowlist는 #43/#44에서 정의한다.

권한 판단은 ‘기존 소유자 접근 관계 유효 AND 해당 기능 read 허용’이다. 미등록 기능·누락 정책은 deny다. 기존 데이터의 공유는 이관 시 명시적으로 현재 허용 기능에만 매핑하며 신규 기능을 wildcard로 자동 허용하지 않는다.
상세 설정이 서로 다르면 UI는 ‘사용자 설정’ 상태로 표시하고 화면을 열었다는 이유만으로 preset을 재적용하지 않는다.
묶음 변경은 정책 버전/CAS로 원자 적용한다. 향후 추가되는 기능은 기존 preset을 켠 사용자에게도 자동 공개하지 않는다.

## 보안 및 연동

- 동일 권한 resolver를 API/RPC·목록·상세·검색·내보내기에 적용하고 RLS/서버 필터로 직접 접근도 차단한다. UI 숨김만으로 보호하지 않는다.
- 공개한 판단의 연결 대상은 별도 기능 권한을 확인한다. 비공개 원칙의 ID·제목·본문을 관계를 통해 반환하지 않는다. 본문 자체에 개인정보가 있을 수 있으므로 공유 미리보기에서 실제 내용을 보여준다.
- 활동·CSV의 신규 민감 payload는 원래 기능 허용 범위로 필터링한다. activity read가 모든 개인정보 읽기를 뜻하지 않는다.
- 권한 철회·친구 제거·뷰어 만료 시 다음 요청부터 차단한다. 캐시는 owner/audience/policy version에 맞춰 격리·무효화한다. 이미 복사된 내용의 회수는 보장하지 않는다.
- MCP 자기 포트폴리오 접근은 앱 친구 공유와 별도다. 공유 설정이 MCP의 타 사용자 조회 허용으로 자동 확대되지 않는다.

## 후속 작업과 비목표

#43/#44는 키·필드·저장/평가 계약, #36은 단순 UI와 공개 미리보기, #39는 기능별 권한·직접 호출·철회 회귀를 담당한다.
DB 테이블명·마이그레이션은 아직 확정/실행하지 않았다. 첫 버전에 범용 RBAC, 역할 편집기, 친구별 예외, 레코드/필드별 ACL은 도입하지 않는다.
