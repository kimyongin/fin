# ADR-0008 — 현재값·활동 중심의 최소 저장 구조

상태: Accepted (방향과 축소 범위) · 2026-09-23. 구현·이관·배포 전.
정확한 DDL/API와 운영 이관 결과는 첫 계약 티켓 및 각 수직 슬라이스에서 확정한다.

## 배경

여러 번의 화면 통합 뒤에도 판단/보유 이유/자료/브리핑/리포트의 개별 원본과 이력·관계·영수증이 남았다. 사용자 요구는 현재 보유값과 메모, 원칙, 할 일과 활동을 쉽게 관리하는 것이다. 회계 원장과 모든 과거 상태 복원은 목적이 아니다.

## 결정

[단순성 원칙](../engineering/SIMPLICITY.md)을 개발·리뷰 기본으로 삼고 [재설계](../design/minimal-portfolio.md)를 적용한다.

- 계좌·종목·보유·가격·카테고리 배분 기반은 유지한다.
- 보유 이유는 기존 보유 메모로, 종목 공통 설명은 종목 메모로 관리한다.
- 판단·자료·점검·회고의 새 정본은 편집 가능한 활동이다. 작은 출처/범위/기간 정보는 해당 활동에 둔다.
- 할 일은 한 모델/공통 상태로 운영한다. 일반/조사/실행별 상태 엔진과 자동 체결 진행률은 축소한다. 매일 반복은 유지한다.
- 서술형 개인 기준·운영 규칙은 공통 원칙으로 관리하고 계산 가능한 목표 비중은 유지한다.
- 매매는 현재 보유값 계산과 활동 저장, 보정은 절대값 수정과 활동 저장이다. 과거 기록 편집으로 현재 잔고를 자동 재생하지 않는다. 수수료·세금 제외 체결가 평균 정책은 유지한다.
- 일반 편집의 불변·의무 이력·별도 revision과 상시 문맥 저장을 제거하는 방향으로 전환한다.
- 자동 금융 사실의 일반 텍스트 편집은 차단한다. 정밀 계산·원자성·중복 방지·자산 충돌 검사는 유지한다.
- 모든 기존 이력은 이관 또는 읽기 가능한 보관으로 보존한다. 개인정보의 기존 비공개 경계를 축소하지 않는다.

## 대체와 한계

원칙 이력 예외: 당시 어떤 원칙을 사용했는지 조회하기 위해 같은 원칙 테이블에 변경마다 새 행을 추가한다. 안정 원칙 ID·적용 시작 시각·종료 여부로 현재/과거 조회를 제공한다. 종류별 최신 한 건으로 묶지 않으며 원칙별 마지막 행을 선택한 뒤 종료 여부를 적용한다. 아래 일반 이력 축소 방침보다 이 예외가 우선한다. 별도 이력 테이블·버전 번호·다른 데이터의 과거 상태 복원은 추가하지 않는다.

추가 확정: 활동은 최소 분류를 자동 지정한다. 기록 삭제는 보유값/할 일 상태를 되돌리지 않으며 할 일 삭제도 기존 수행 기록을 지우지 않는다. 반복은 오늘 완료와 전체 종료/삭제만 구별하고 일시정지·재개 기능을 두지 않는다. 원칙은 한 행에 하나씩 저장한다. 최신 매매를 포함한 되돌리기는 제외하고 증권사 현재값으로 보정한다. 세부 과거 수정 과정은 백업/내보내기로 보존하며 복원 UI/API는 만들지 않는다.

ADR-0002의 과거 거래 취소/기준점 이후 재생, ADR-0004의 도메인별 의무 이력, ADR-0005~0007의 판단·보유 이유·리포트 별도 정본과 금융 원장 유지 요구 중 충돌 부분을 대체한다. ADR-0001의 역할 분리와 ADR-0003의 기능별 공유 확장성은 유지한다.

기존 이력 보존은 기존 테이블/API 영구 운영을 뜻하지 않는다. 반대로 새 설계 승인만으로 실제 테이블 삭제·운영 배포가 완료되거나 승인된 것은 아니다. 운영 적용 범위와 백업/복구는 릴리스 티켓에서 명시한다. 과거 티켓의 로컬 완료 증거와 미검증 외부 게이트는 유지한다.

2026-09-23 최종 후속 결정: 사용자는 기존 투자 데이터 전체를 삭제해도 된다고 명시했다. 구 데이터의 이관·과거 조회·기존 세션 호환을 이유로 별도 테이블/API/화면을 남기지 않는다. 인증·다중 사용자 격리·새 공유 설정 기능의 구조는 유지하되, 기존 투자 기록과 구 공유 대상 행은 폐기 가능하다. 이는 운영 DB 즉시 삭제/배포 지시와는 구분한다. 기존 이력 보존을 요구한 위 문장은 이 결정으로 대체한다.
