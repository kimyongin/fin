# 종류별 자산 처리 모델

## 상태

- 완료
- 원격 DB에 `202607180008`부터 `202607180011`까지 적용 완료

## 목표

자산 종류에 따라 입력값, 저장값, 평가 계산, 자산 화면의 지표를 다르게 처리한다. 평균 단가가 사용자에게 의미 없는 평가형 투자에 평균 단가와 현재가를 억지로 입력하거나 표시하지 않는다.

## 종류

| 값 | 화면 이름 | 예시 | 평가 방식 |
| --- | --- | --- | --- |
| `market` | 시장형 투자 | 주식, ETF, 미국 장기채 ETF | 수량 x 현재가. 평균 매수가와 현재가를 비교한다. |
| `valuation` | 평가형 투자 | 유진 단기채, 퇴직연금 공모펀드 | 매입금액과 평가금액을 직접 저장한다. 보유 좌수는 선택 정보다. |
| `cash` | 현금 | KRW, USD, JPY 잔고 | 평가금액 하나를 통화별로 원화 환산한다. |
| `fx` | 내부 환율 | USDKRW=X, JPYKRW=X | 사용자가 보유 자산으로 만들지 않는다. |

전략 태그는 종류와 별개다. 예를 들어 미국 장기채 ETF는 `market`이면서 `장기채` 태그를, 유진 단기채는 `valuation`이면서 `단기채` 태그를 사용한다.

## 현재 문제

- `holdings`가 `quantity`, `avg_price`만 저장한다.
- 모든 평가금액을 `quantity x latest_price`로 계산한다.
- 일반 편집, 표 편집, CSV 병합, 저장 RPC가 평균 단가를 필수로 요구한다.
- 퇴직연금 CSV처럼 티커와 평균 단가가 없는 평가형 상품을 정확히 반영할 수 없다.

## 데이터 모델

- `instruments.instrument_type` 제약을 `market`, `valuation`, `cash`, `fx`로 변경한다.
- `holdings.purchase_amount`, `holdings.valuation_amount`를 추가한다.
- `quantity`, `avg_price`는 평가형과 현금에서 사용하지 않는다.
- 기존 `investment`는 `market`으로 이전한다.
- 평가형 상품은 거래소 티커가 없어도 저장 가능해야 한다. 화면에서 티커를 요구하지 않고 내부 식별자를 생성한다.

## 구현 범위

1. DB와 RPC
   - `app_save_holding`, `app_bulk_save_portfolio_rows`, 포트폴리오 조회 RPC를 종류별 입력과 반환값에 맞춘다.
   - MCP 보유 조회·저장 도구도 매입금액과 평가금액을 지원한다.
   - 시장 가격 동기화 대상에서 `valuation`, `cash`를 제외한다.
   - 활동 기록의 before/after 데이터에 새 금액 필드를 포함한다.

2. 계산과 표시
   - 시장형: 평가금액, 평균가, 현재가, 수익률을 계산한다.
   - 평가형: 매입금액, 평가금액, 평가손익, 수익률을 계산한다.
   - 현금: 잔액과 원화 환산액만 계산한다.
   - 계좌, 태그, 전략 버킷 합계는 세 종류의 원화 평가금액을 합산한다.

3. 입력 화면
   - 종목 편집에서 세 사용자 종류를 선택한다.
   - 보유 수정 모달은 선택한 종류에 맞는 필드만 표시하고 검증한다.
   - 표 편집은 공통 열과 종류별 값 열을 함께 제공하며, 해당하지 않는 셀은 입력하지 않는다.

4. CSV 병합
   - 결과 파일은 `종류`, `매입금액`, `평가금액`을 포함한다.
   - 시장형만 평균 매수가를 출력한다.
   - DC와 IRP의 공모펀드는 매입금액·평가금액을 평가형 값으로 가져온다.

## 완료 기준

- 유진 단기채를 `평가형 투자`로 저장할 때 평균 매수가와 현재가 입력 없이 저장된다.
- 시장형 ETF는 기존 평균 매수가·현재가·차트 경험을 유지한다.
- 현금은 평균 매수가와 수익률을 표시하지 않는다.
- 표 편집 CSV 붙여넣기 후 종류별 변경값을 검토하고 저장할 수 있다.
- 전략의 평가금액과 리밸런싱 기준 금액이 세 종류 모두에서 정확히 합산된다.
- 활동 기록, 친구 읽기 전용 화면, MCP 읽기·수정 경로가 새 데이터 필드를 누락하지 않는다.
- DB 마이그레이션 적용, 인코딩 검사, 테스트, 프로덕션 빌드가 모두 통과한다.
